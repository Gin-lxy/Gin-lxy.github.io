## 0. 一句话结论

Motus 针对"理解、世界建模与控制被拆分在多个独立模型中、且动作专家难以利用无动作标签的异构视频数据"这一具身智能问题，提出用 MoT（Mixture-of-Transformers）三专家架构加 UniDiffuser 式调度器统一五种建模模式，并用光流学出的潜动作（latent action）让动作专家能在大规模无标注数据上预训练。论文在 RoboTwin 2.0 仿真（50 任务平均成功率 88.66%/87.02%）与两个真机平台上报告了相对 π0.5 与 X-VLA 的提升，证据支持"这套统一建模与预训练配方在本论文测试范围内有效"，但各核心组件的独立贡献未被实验隔离。

## 1. 论文具体想解决什么问题？

**研究背景与具体任务。** 一个通用具身智能体（embodied agent）需要同时具备场景理解、指令理解、未来预测与动作生成能力。论文把这类能力形式化为五个概率分布（§3）：视觉-语言-动作模型（vision-language-action model, VLA，由当前观测与指令直接出动作）、世界模型（world model, WM，由观测与动作预测未来观测）、逆动力学模型（inverse dynamics model, IDM，由观测序列反推动作）、视频生成模型（video generation model, VGM，由观测与指令生成未来视频）、以及视频-动作联合预测（video-action joint prediction，同时生成未来视频与动作）。这里动作以动作分块（action chunking）形式预测，即一次输出未来 $k$ 步动作，以缓解逐步推理的延迟与误差累积。

**现有方法通常如何处理。** 主流做法是按需选边：VLA 类工作（π0.5、X-VLA 等，§2.1）用视觉-语言模型学静态策略，只出动作、不建模未来；世界模型与视频生成类工作（如 ViDAR）先生成未来视频、再间接推动作，但不含语言理解式的策略头；$\mathcal{F}_1$ 把 VLA 与 IDM 结合，显式想象未来观测并输出动作，是"半统一"；最完整的统一原型是 UWM，把五种分布塞进一个扩散骨干（§1、§2.1）。数据侧，现有方法或给通用骨干注入本体特化信息、或把不同本体强行投影到高维动作向量，本质上仍依赖有标注的机器人轨迹（§3 挑战 2）。

**现有方法在哪些条件下表现不好。** 论文给出两类条件（§3）：其一，任务需要"理解 + 想象 + 控制"协同的长程操作时，割裂的模型各自只覆盖一块能力，无法互相借力；其二，当数据里存在大量无动作标签的视频（互联网视频、第一人称人类视频）时，现有方法全被"动作标签墙"挡住——控制信号跨本体不可复用，动作专家拿不到这些数据。论文还断言 UWM 这类统一原型"从头训练或先验有限"，缺 VLM 理解先验或缺 VGM 物理先验，泛化受限。

**作者发现了什么新的现象、瓶颈或被忽略的问题。** 严格说，本文没有报告新的实证现象，其"发现"是架构级与数据级的论证：(1) 现有模型格局把本应统一的系统拆成五个独立任务，而统一的关键障碍是"如何在保住各自预训练先验的前提下共享参数"（§1 挑战 1）；(2) 动作专家之所以不能像视频/语言模型那样预训练，是因为缺少一个可跨本体、可在无标注像素上监督的"动作表示"（§3 挑战 2）。论文把第二点转化为一个可操作的观察：光流是像素级的运动表达、天然跨本体共享，可以充当动作的替身。

**支撑这一问题判断的证据。** 动机证据主要是两份基线成绩与结构分析：RoboTwin 2.0 上 π0.5 平均成功率 42.98%（论文 Table 2）、真机 AC-One 上 π0.5 平均部分成功率 14.79%（论文 Table 3），用"现成最强开源模型也做不好"来支撑"割裂建模不够用"；架构分析（$\mathcal{F}_1$ 与 UWM 的能力缺口）来自论文对相关工作的引用与推断。论文没有报告"独立模型为何失败的机理实验"。

**作者认为问题产生的原因。** 两点归因（§3）：(1) 统一多模态生成能力本身很难——直接把 token 拼接进单骨干会丢掉 VLM/VGM 的预训练先验，从头训练又要付出不可行的数据与算力；(2) 动作空间碎片化加上视频缺动作标注，导致动作专家没有"预训练入口"，只能从小规模标注轨迹学起。

**论文要验证的核心假设。** 把理解、生成、控制统一在一个模型中，并让动作专家通过光流潜动作在大规模异构数据上预训练，能提升下游机器人操作任务的泛化表现（摘要与 §1 贡献列表）。注意这是一个复合假设：统一架构与潜动作预训练被捆绑验证，论文没有设计能单独检验每一半的实验。

**问题拆分（早已存在 / 新观察 / 实际解决）。** 早已存在的一般问题：跨本体动作空间不一致、视频无动作标签、统一世界模型原型（UWM）及其局限。本文提出的新观察：光流潜动作可以充当跨本体、跨标注形态的"动作替身"，并可用少量动作标签锚定到真实控制分布（§4.2）。本文实际要解决的具体子问题：在单一可训练系统中同时容纳五个分布且保住双方预训练先验（挑战 1）；给动作专家构造可在无标注数据上监督的潜动作接口（挑战 2）。论文自己没有把这三个层次明确区分——"现象观察"与"解决方案"在 §1 与 §3 中被混在一起叙述。

## 2. 创新点是什么？

本文的真增量不是单点算法，而是把"统一世界模型"从理论原型推进成了一个可训练、可切换五种模式的工程系统：三个现成预训练模型（Wan 2.2 5B 视频生成、Qwen3-VL-2B 理解、自建动作专家）通过共享注意力拼成一个网络，用一个时间步调度器统一训练与推理，再用光流潜动作补上动作专家的预训练入口，配以三阶段训练和六层数据金字塔。逐项看：

1. **MoT 三专家架构 + Tri-model Joint Attention（三模型联合注意力）。** 每个专家保留自己的 Transformer 组件（FFN、归一化），仅把多头自注意力层拼接共享，实现跨模态特征融合且不互相覆盖功能。与最接近的 UWM 的差异是结构性的：UWM 把观测 token 与动作 token 拼接后送进同一条 $N$ 层流水线，本文则保留三个独立专家、复用各自的预训练权重（§4.1）。对应挑战 1；其收益证据见 §4.2（整体成绩）与 §4.3（注意：无组件级消融）。
2. **UniDiffuser 式调度器与五种推理模式。** 训练时给视频与动作分别采样整流流时间步与噪声尺度，使模型同时建模边缘、条件与联合分布；推理时通过固定或扰动某一分支的噪声状态，在 VLA / 世界模型 / IDM / VGM / 联合预测之间切换，而无需重训或改网络（§4.1、附录 §7.1 的算法 2–6）。这属于"已有调度思想（UniDiffuser）的跨领域新组合"；对应挑战 1；五种模式各自的表现证据见 §4.2 与 §4.3，但强弱不均。
3. **光流潜动作（latent action）与弱监督对齐。** 用 DPFlow 计算光流、转成 RGB 后由 DC-AE（深度压缩自编码器）重建，编码结果经轻量投影得到 14 维向量，与典型机器人动作维度对齐；训练时 90% 无标注数据做自监督重建、10% 有标注轨迹（含 Curobo 随机采样生成的任务无关数据）做弱动作监督（§4.2）。与 LAOM 等潜动作工作的差异在于表示介质换成光流、且嵌入在一个统一多模态模型里；对应挑战 2；阶段消融（论文 Fig. 6 / 图 5）显示第二阶段预训练带来约 5–6 个百分点提升，但无法单独归因。
4. **三阶段训练管线 + 六层数据金字塔。** Stage 1 只训 VGM（多机器人轨迹 + 人类视频）、Stage 2 冻结 VLM 训练三专家（引入潜动作与任务无关数据）、Stage 3 在目标机器人数据上 SFT（监督微调）；六层金字塔按质量与相关性给数据分层并映射到阶段（论文 Table 1、论文 Fig. 4）。这属于数据工程与训练流程的新配方；对应挑战 2；证据即论文 Fig. 6 的阶段消融与真机 from-scratch 对照（§4.2）。

## 3. 作者如何解决？

**直觉。** 从头训练一个"什么都会"的统一大模型不现实（对齐好的多模态数据不够、算力也不够），所以 Motus 的策略是"拼"：把三个已经很强的专家（视频生成、视觉语言理解、动作）用共享注意力焊接起来，让信息在三者之间流动；同时解决最弱环——动作专家没有大规模预训练数据——的办法是不直接学动作，而是先学"像素里看得见的运动"：光流就是动作在画面上的投影，把光流压缩成一个低维向量（潜动作），就能让没有动作标签的视频也变成动作专家的监督信号。论文的赌注是：这样得到的运动先验比单靠机器人轨迹训出的策略更泛化。

**输入与总框架。** 任务输入是当前观测帧 $\bm{o}_t$（真机上还有本体感知 $\bm{p}_t$，联合位置控制下它与动作同空间）、语言指令 $\ell$，输出是未来 $k$ 步动作块（真机部署）或未来视频帧（世界模型 / 视频生成用途）。模型本体是三个专家（论文 Fig. 1 / 图 1）：生成专家直接用 Wan 2.2 5B 视频基础模型，理解专家取 Qwen3-VL-2B 最后一层对应 token 的输出，动作专家是深度与 Wan 相同的 30 层 Transformer（隐层 1024、24 个注意力头、约 641.5M 参数；理解专家约 253.5M，总规模约 8B，论文 Table 11）。

![图 1：Motus 三专家架构与 Tri-model Joint Attention](/images/dailypaper/2026-10-15/2512.13030v2_fig1_architecture.png)

**图 1**（论文 Fig. 1）：Motus 的整体架构。底部左侧是视频生成分支（Video Encoder → Video Gen. Model 的 QKV/AdaLN → Video Decoder），中间是动作专家分支（Action Encoder/Decoder），右侧是理解专家（冻结的 Pre-trained VLM，输入语言指令）——三条分支各自保留 FFN 与归一化层，只在中间的 Tri-model Joint Attention 层交汇：三个专家的多头自注意力被拼接共享，用一个注意力学到三类 token 的跨模态关联，因此视频生成能"看到"语言意图、动作预测能"看到"未来画面与场景语义，而各分支的专用能力又不会被对方冲掉。注意两个分支各自注入整流流（rectified flow）时间步 $\tau_v$、$\tau_a$，这是下文调度器切换模式的接口；动作解码器的输出既可以是真实动作 $a_t\ldots a_{t+k}$（有标注数据），也可以是潜动作 $z_t\ldots z_{t+k}$（无标注视频），这正是潜动作打通大规模预训练的通道。

**训练目标：视频与动作各自流匹配。** 训练时对动作块与未来视频块分别采样时间步 $\tau_a$、$\tau_o$ 和高斯噪声，用整流流目标回归速度场，两部分损失直接相加，即

$$l^{\theta}=\big\|v_a^{\theta}-(\epsilon_a-\bm{a}_{t+1:t+k})\big\|_2^2+\big\|v_o^{\theta}-(\epsilon_o-\bm{o}_{t+1:t+k})\big\|_2^2 .$$

视频与动作各用各自的时间步与噪声尺度，这一"异质时间步"设计就是 UniDiffuser 式调度器：训练时它让模型同时见过"视频任意噪声 + 动作任意噪声"的各类组合，因而同时建模了边缘分布与条件分布；推理时只需把某个分支固定在"纯噪声"或"干净"状态，就得到不同的建模模式（§4.1、附录 §7.1 算法 2–6）。五种模式的配置是固定流程、不是模型学出来的：VLA 模式把视频分支一直保持纯噪声、只去噪动作；IDM 模式反过来固定干净观测、去噪动作；世界模型模式固定真值动作、去噪视频；VGM 模式固定纯噪声动作、去噪视频；联合预测模式则两条分支一起去噪。每步推理用 10 步整流流采样（论文 Table 11）。

**动作密集、视频稀疏。** 一个直接的问题是 token 失衡：动作块是 48 步 @30Hz（约 1.6 秒），若视频也按同等帧率提供，视频 token 数会远超动作 token，Tri-model Joint Attention 会倒向视频预测、动作能力被稀释。论文的策略是降采样视频：视频只用 8 帧 @5Hz，恰好是动作帧率的六分之一，两个模态 token 数保持平衡（§4.1，论文 Fig. 2 / 图 2）。

![图 2：动作密集、视频稀疏预测的时间轴](/images/dailypaper/2026-10-15/2512.13030v2_fig2_action_dense.png)

**图 2**（论文 Fig. 2）：Action-Dense Video-Sparse Prediction 的示意。沿时间轴看，粉色的动作（Sampled Actions）以 30Hz 密集采样 48 步，橙色的视频帧（Sampled Frames）则被下采样到同一时间窗内只有 8 帧——同一个 1.6 秒窗口里，动作提供高频控制信号，视频只提供低频"剧情推进"信号。这样做同时缓解三个问题：训练/推理变快、避免冗余的相邻帧预测、并让联合注意力里的两种 token 数量可比，模型不会因视频 token 占多数而丧失动作精度（§4.1 原文列出这三点动机）。

**潜动作：把光流变成 14 维的"伪动作"。** 为了让无动作标签的数据（人类第一人称视频、多机器人轨迹等）也能监督动作专家，Motus 用运动表示充当动作的替身（论文 Fig. 3 / 图 3）：先用 DPFlow 计算相邻帧的稠密光流并转成 RGB 图；再用一个预训练 DC-AE 重建光流图，把光流压缩到 4 个 512 维 token；接着用一个轻量编码器把 4×512 特征投影成 14 维向量——维度刻意对齐典型机器人动作空间（如 Aloha 双臂 14 维关节动作）。训练 VAE 时混合 90% 无标注数据做自监督光流重建、10% 有标注轨迹做弱动作监督，其中有标注部分还包含按 AnyPos 方式用 Curobo 随机采样目标机器人动作空间生成的任务无关图像-动作对（§4.2）。总损失为重建项、动作对齐项与 KL 正则之和：

$$\mathcal{L}=\mathcal{L}_{\text{recon}}+\lambda_a\,\|\bm{a}_{\text{real}}-\bm{a}_{\text{pred}}\|^{2}+\beta\,\mathcal{L}_{\text{KL}} .$$

其中第一项最小化光流重建误差，第二项把潜动作拉向真实动作分布（$\lambda_a=1.0$），第三项约束潜空间（$\beta=10^{-6}$，论文 Table 11；这条管线的完整数据流见 图 3）。论文的论证逻辑是：维度对应 + 少量真实动作弱监督，共同把潜动作分布锚定到真实控制分布上，于是"视频里学到的运动先验"能自然映射为"可执行的机器人控制"（§4.2）。注意哪些是模型学的、哪些是固定流程：光流由 DPFlow 固定计算、Curobo 采数据是离线流程；被训练的是 DC-AE 潜空间与投影器，被"当作动作"喂给动作专家的 $z$ 则直接替换标注 $a$（论文 Fig. 1 中动作解码目标的"$a$ 或 $z$"）。

![图 3：潜动作 VAE——光流经 DC-AE 编码为潜动作再重建](/images/dailypaper/2026-10-15/2512.13030v2_fig3_latent_action_vae.png)

**图 3**（论文 Fig. 3）：Latent Action VAE 的数据流。一段机器人视频经 DPFlow 变为彩色光流图（颜色编码运动方向、深浅编码速度），光流图被 DC-AE 编码成 4×512 的 token，再投影为 14 维潜动作 $z_t$——它位于编码器与解码器之间，是整条通路的瓶颈与语义核心；随后解码器与第二个 DC-AE 把 $z_t$ 复原回光流图，重建误差构成自监督信号。读者应从中理解两点：其一，潜动作是被"压出来"的低维运动量，而不是学出来的策略——它的目的在于当动作标签的替身；其二，重建-对齐联合训练使这个 14 维空间与真实关节动作空间在尺度与几何上接近，后续动作专家才能用同一套"动作块"接口同时消费真动作与潜动作。

**三阶段训练与六层数据金字塔。** 有了架构与潜动作，最后是把数据按"预训练价值"排布进训练日程（论文 Table 1、论文 Fig. 4 / 图 4）：Stage 1 只训练 VGM 专家，用第二层（第一人称人类视频）、第三层（合成数据，如 RoboTwin）与第五层（多机器人轨迹）让视频生成先"见过"真实机器人操作；Stage 2 训练全部三个专家（VLM 冻结），加入第四层任务无关数据，动作监督由潜动作提供，这一阶段把运动与交互知识灌进动作专家；Stage 3 用第六层目标机器人轨迹做 SFT，把先验适配到具体本体的动力学上。第一层（互联网网页数据）不直接训练 Motus，只体现在所复用的预训练基座（Wan 2.2、Qwen3-VL）里——论文 Table 12 列出了每层数据的具体来源与规模（如 AgiBot 728,209 条、EgoDex 230,949 条、RoboTwin 27,500 条，以及自采 in-house 2,000 条等）。

![图 4：六层具身数据金字塔](/images/dailypaper/2026-10-15/2512.13030v2_fig4_data_pyramid.png)

**图 4**（论文 Fig. 4）：具身数据金字塔的分层逻辑。塔底是数量最大、与策略最"间接"的互联网数据（Common Crawl、Wikipedia、YouTube 等），越往上数据量越小、与目标机器人任务越直接：第一人称人类视频→合成数据→任务无关数据→多机器人任务轨迹，塔尖是目标机器人自身的任务轨迹。金字塔的意义是把"异构"变成"有梯度的同构"：底部数据提供运动与交互的广度（经潜动作接口进入动作专家），塔尖数据提供目标本体的精度（经 SFT 注入）；每层数据按论文 Table 1 映射到固定训练阶段，数量随层级递减而质量递增（论文注明第三、四层的顺序有时可换）。

**训练了哪些部分（谁被更新、谁被冻结）。** Stage 1 只更新 VGM 专家（论文 Table 1 写 "Only VGM"），把 Wan 2.2 从通用视频模型改造成"机器人操作视频模型"；Stage 2 更新三个专家的全部可训练模块——动作专家的 Transformer、理解专家自带的若干 Transformer 块、VGM 专家，同时冻结 Qwen3-VL 本体（论文原文 "(VLM frozen)"，理解专家消费的是 VLM 最后一层对应 token）；Stage 3 用目标机器人数据更新全模型（潜动作接口换回真实动作监督）。三阶段均用 AdamW、批大小 256，学习率分别为 $8\times10^{-5}$、$5\times10^{-5}$、$1\text{–}5\times10^{-5}$；GPU 时数约 8,000 / 10,000 / 400 小时（论文 Table 13 的训练配置，其中 GPU 时数行与论文 Table 12 数据集明细为 v2 版新增，v1 未披露）。

**推理阶段发生了什么变化。** 训练时模型见过的都是"两分支各自带噪"的组合，推理时不再训练，而是由部署者（固定流程）决定各分支的噪声状态：真机控制通常用 VLA 模式（视频分支保持纯噪声、只给动作分支去噪）或联合预测模式（两分支同时去噪）；需要"想象未来"时用世界模型模式（给定动作、去噪视频）；需要造数据或可视化时用 VGM 模式。无论哪种模式，采样都是 10 步整流流（论文 Table 11），输出 48 步动作块交给底层控制器，或输出 8 帧视频。哪些行为由模型决定、哪些由固定流程控制：模式选择、时间步与噪声配置、数据分层映射、光流计算（DPFlow）与任务无关数据采样（Curobo）都是固定流程；专家内部的特征融合、潜动作编码、两种模态的去噪轨迹则全部由模型学得。

## 4. 解决得怎么样？

#### 4.1 实验设置

- **仿真主战场：RoboTwin 2.0。** 50 个双臂操作任务，多任务联合训练：每任务 50 条 clean 演示 + 500 条强随机化演示（共 2,500 + 25,000 条），随机化包括随机背景、杂乱桌面、桌面高度扰动与随机光照；所有模型都从各自预训练检查点出发、统一微调 40k 步，每任务测 100 次取成功率（§5.2）。基线：π0.5、X-VLA（论文 Table 2），附录论文 Table 14 追加 GO-1 及自身变体 from-scratch（w/o Pretrain）与 Stage 1。
- **真机平台与任务：AC-One 与 Agilex-Aloha-2。** AC-One（9 个任务）：折毛巾、用咖啡机煮咖啡、从饮水机接水、把方块放进盘子（含 OOD 变体）、用磨豆机磨咖啡豆、用水壶倒水浇花、按指令触摸键盘、把面包放进烤箱——覆盖空间理解、可变形物体操作、精密流体控制、视觉理解与长程规划五类能力；Aloha（5 个任务）：折毛巾、接水、倒水浇花、触摸键盘、把面包放进烤箱。每任务仅用 100 条轨迹训练，同平台所有任务联合训一个模型、再逐任务评测；基线 π0.5 与 from-scratch 对照（§5.3）。
- **评价指标：** 仿真用二值成功率（100 次试验）；真机用部分成功率（partial success rate）——把任务拆成子目标并赋分（例如把面包放进烤箱拆为开门 0.2、抓面包 0.4、放入 0.6、关门 0.8、按旋钮 1.0 五个子目标），按完成度累计得分，满分只在整体成功时给出（§5.3、论文 Table 4–5）。折毛巾每种毛巾评 4 次、抓方块每种方块评 5 次（§8.3）。
- **附录补充基准：** LIBERO-Long（10 个长程语言条件操作任务，与 π0、GR00T-N1、UniVLA、OpenVLA-OFT、X-VLA 对比）、VLABench（In Distribution 与 Cross Category 两个 track × 3 个任务、以 π0.5 官方实现为基线）；五种推理模式的能力验证（世界模型生成质量 FID/FVD/SSIM/LPIPS/PSNR；IDM 模式对两个专门训练的基线比动作 MSE；VLA 与联合预测模式的成功率对比）。
- **公平性范围：** 仿真上"同数据 + 同 40k 微调步数"是明确的（§5.2 原文强调）；但预训练侧预算不齐——Motus 使用本论文自建的三阶段预训练（约 1.84 万 GPU 小时 + 约 100 万条轨迹/视频数据），π0.5/X-VLA 的预训练成本与数据论文均未报告，二者不可比；LIBERO-Long 与 VLABench 上 Motus 的微调数据/步数也未与基线对齐披露。
- **主实验、消融、附录各自回答的问题：** 主实验回答"统一模型+预训练是否比现有模型强"（论文 Table 2、3）；消融（论文 Fig. 6）回答"哪个训练阶段贡献了多少"；附录回答"五个模式各自是否可用、数据集与训练细节是什么"（论文 Table 6–16）。

#### 4.2 关键结果

- **RoboTwin 2.0 平均成功率（§5.2，论文 Table 2）：** Motus 88.66%（Clean）/ 87.02%（Randomized），X-VLA 72.80 / 72.84（差 +15.9 / +14.2 个百分点），π0.5 42.98 / 43.84（差 +45.7 / +43.2 个百分点）。附录论文 Table 14 中 GO-1 仅 37.8 / 36.2。摘要的"+15% 超 X-VLA、+45% 超 π0.5"即由此而来（绝对百分点）。仓库 README 的 87.02% 与此一致。
- **训练阶段消融（§5.4，论文 Fig. 6 / 图 5）：** Randomized 场景 77.00 → 81.86 → 87.02，Clean 场景 77.56 → 82.26 → 88.66（from-scratch → Stage 1 → Stage 2）。即"视频预训练"与"潜动作统一预训练"各贡献约 5–6 个百分点，且叠加后才有最终成绩。

![图 5：训练阶段消融柱状图](/images/dailypaper/2026-10-15/2512.13030v2_fig5_ablation.png)

**图 5**（论文 Fig. 6）：RoboTwin 2.0 随机化多任务设置下的阶段消融。两组柱分别对应 Randomized 与 Clean 场景，每组的三个柱子依次是 from-scratch（w/o pretrain）、仅 Stage 1 预训练、Stage 2 完整预训练（即最终 Motus）；虚线箭头标出从 from-scratch 到最终的累计增益（+10.02 / +11.10 个百分点）。读者应读出两条信息：预训练在这个数据受限的设置里是主要收益来源（比模型结构差异重要），且两个阶段的作用可以叠加而非互相替代——这也是论文"大规模预训练对机器人策略有效"主张的最直接证据。

- **真机部分成功率（§5.3，论文 Table 3）：** AC-One 平均 63.22% vs π0.5 14.79%（+48.4 个百分点）、from-scratch 25.86%；Aloha 平均 59.30% vs π0.5 48.60%（+10.7 个百分点）、from-scratch 26.60%。摘要"+11~48%"即这两个平台的提升区间。
- **提升很小或没有提升处：** LIBERO-Long 上 Motus 97.6 与 X-VLA 97.6 完全打平（附录论文 Table 9，论文原文 "matching the best reported performance"；同表其余基线为 π0 85.2、GR00T-N1 90.6、UniVLA 94.0、OpenVLA-OFT 94.5）；VLABench 平均仅 +0.05 / +0.03（In Distribution 0.48 vs π0.5 0.43，Cross Category 0.25 vs 0.22，论文 Table 10），且 Select Fruit 任务两个 track 都低于 π0.5（0.33 < 0.42，0.20 < 0.36），说明"统一模型全面领先"在个别任务上不成立。
- **平均值的掩盖与任务级回退：** 论文 Table 14 的 50 个任务中，Motus 有约 31 个任务至少在一项同条件对比中低于 X-VLA 或 Stage 1 的对应数字；其中多数差距仅 1–4 个百分点（单次 100 次试验下难以与噪声区分），但少数回退明显：Move Can Pot（Clean）34% vs X-VLA 89%、Stage 1 56%；Adjust Bottle（Clean）89% vs X-VLA 100%；Handover Mic（Rand.）63% vs Stage 1 88%；Stack Blocks Three（Clean）91% vs Stage 1 99%。平均优势真实存在，但"全面更好"不成立。
- **真机反例：** Aloha 平台的 Put Bread into Oven，Motus 34% 低于 π0.5 的 36%（论文 Table 3），与 §5.3 原文"outperforms the baseline across all tasks on both robotic arms"的表述矛盾。
- **统计信息与真机可视化：** 所有结果均为单次运行汇报；仿真每任务 100 次试验、真机部分任务每类只评 4–5 次（§8.3），无方差、置信区间或显著性检验（论文未报告）；九个真机任务的执行过程可视化见 图 6。

![图 6：两个真机平台上的九类任务执行过程](/images/dailypaper/2026-10-15/2512.13030v2_fig6_realworld_demos.png)

**图 6**（论文 Fig. 8）：Motus 在 AC-One 与 Agilex-Aloha-2 上的真机执行过程逐帧展示，覆盖九个任务（从上到下：用咖啡机煮咖啡、按指令敲键盘、磨咖啡豆、把方块放进盘子、倒水浇花、从饮水机接水、放方块、把面包放进烤箱、折毛巾）。这张图说明的是任务清单与执行形态——每个任务由语言指令定义、多帧序列展示双臂协同与长程子目标的推进——读者应把它当作"方法在真实机器人物理系统上闭环运行"的存在性证据，而不是成功率证据；成功率数字在论文 Table 3 中。

**子任务分解暴露的另一面。** 论文 Table 4 与 Table 5 给出两个任务的部分分细节：AC-One 的 Put Bread into Oven，Motus 42% vs π0.5 12%，但 from-scratch（无预训练）也有 40%——这个任务上预训练几乎没带来增量；Aloha 的 Get Water from Water Dispenser 则相反，Motus 96% vs π0.5 62%、from-scratch 仅 8%，预训练增益明显。两个例子并排看，真机上的预训练收益高度依赖任务，与仿真里阶段消融的稳定增益形成对照，提示真机结果的不确定性可能不小。

#### 4.3 机制证据

- **消融只隔离了"训练阶段"，没有隔离"机制"。** 论文 Fig. 6 / 图 5 的三个条目（from-scratch / Stage 1 / Stage 2）同时改变了三件事：是否用多机器人+人类视频微调 VGM、是否引入潜动作监督、以及训练数据量与训练步数。因此 +5 个百分点的"Stage 2 增益"不能直接归因给潜动作，也可能来自更多数据与更长训练。
- **对 §2 创新点的逐一核对：** (1) MoT + Tri-model Joint Attention——论文没有"把 UWM 式单骨干在同一数据上训练"的对照，无法证明"共享注意力比拼接 token 好"；只有跨论文的间接比较。(2) 调度器与五模式——论文 Table 8 给出 VLA 模式 83.90 与联合预测模式 87.02（RoboTwin Randomized），说明联合去噪比单去动作好；但没有调度器变体（如统一时间步）的消融。(3) 潜动作——唯一的间接证据是阶段消融（上述混淆）与 IDM 模式的 MSE 0.014 vs 专门训练基线 ResNet18+MLP 0.044 / DINOv2+MLP 0.122（附录论文 Table 7，仅 100 个 RoboTwin 样本）；没有"不用潜动作、只用有标注数据"的同预算对照。(4) 三阶段配方——Stage 消融即是其证据，但如上所述无法拆细。
- **"统一未损害各能力"的部分证据是成立的：** IDM 模式 MSE 低于两个专门模型、VLA 模式与联合模式都可用、世界模型能出图，这些至少说明多模式切换在推理上真实可运行（附录 §7.2）。但世界模型模式只有画质指标（FID 11.209、FVD 61.2、SSIM 0.866、LPIPS 0.0636、PSNR 25.07，论文 Table 6），论文没有与任何其它视频生成模型对照，也没有"用世界模型改善下游控制"的实验。
- **替代解释未被排除：** 与 π0.5 / X-VLA / GO-1 的对比中，Motus 的预训练数据规模（约 100 万条轨迹 + 23 万条人类视频）与算力（约 1.84 万 GPU 小时）明显大于常规 VLA 训练投入，论文没有做"同数据同预算下与 UWM 式单骨干对比"的实验，因此"统一架构 + 潜动作带来增益"与"数据/算力更多带来增益"两种解释在现有证据下无法分开。

#### 4.4 成本与适用范围

- **模型与训练成本（论文 Table 11、Table 13）：** 总参数约 8B（Wan 2.2 5B + Qwen3-VL 2.13B + 动作专家 641.5M + 理解专家 253.5M）；三阶段训练 GPU 时数约 8,000 / 10,000 / 400 小时（合计约 1.84 万 GPU 小时，论文未报告 GPU 型号）。"GPU Hours"行与数据集明细表（Table 12）为 v2 相对 v1 新增的披露，v1→v2 其余差异仅为编号与元数据，主结果数字无变化。
- **推理配置：** 动作块 48 步 @30Hz、视频 8 帧 @5Hz、整流流采样 10 步、Logit Normal 采样策略（论文 Table 11）。**推理时延、FPS、显存占用论文均未报告**；官方仓库给出推理显存 >24GB（预编码 T5 时）或约 41GB、训练 >80GB 的环境说明，但仓库属论文发布后更新的材料，本报告不作为论文事实采用。
- **数据与外部依赖：** 训练数据 8 个来源与规模见论文 Table 12（AgiBot 728,209、EgoDex 230,949、RoboTwin 27,500、RDT 6,083、RoboMind 两套共 16,861、任务无关数据 1,000、in-house 目标机器人数据 2,000）；其中 in-house 数据未公开。方法直接依赖外部模型与工具：Wan 2.2、Qwen3-VL-2B、DPFlow、DC-AE、Curobo。人工标注方面：真机每任务 100 条遥操作轨迹，论文未报告标注工时。存储复杂度论文未报告。
- **改善与未解决：** 改善的是仿真平均成功率（+15.9pp 超 X-VLA）与两个真机平台的平均部分成功率；未解决的是组件级因果归因、推理时延与部署成本、以及统计稳定性（无多次运行与置信区间）。
- **结论适用边界：** 桌面双臂操作任务（RoboTwin 2.0 / AC-One / Agilex-Aloha-2）、Aloha 风格关节动作空间与动作分块推理；LIBERO-Long 只打平、VLABench 只微弱领先，说明"统一模型全面优于现有方法"不成立，适用性应限定在论文测试的这些基准与平台上。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：三个核心机制（MoT 结构、调度器、潜动作）都没有组件级消融，收益无法归因

- **原文依据**：§5.4 的消融只有 from-scratch / Stage 1 / Stage 2 三档（论文 Fig. 6）；没有"UWM 式单骨干同数据训练""无潜动作预训练""统一时间步调度"等对照，论文也未报告各组件的移除实验。
- **为什么重要**：它决定创新性主张（统一起作用、潜动作起作用）是否被证实，还是只证明了"更多预训练 + 更多数据有用"。
- **当前能够得出的判断**：论文观察到了现象（完整配方有效），但没有充分验证因果解释；Stage 2 的增益至少被"数据量/训练步数"混杂。
- **如何验证或补强**：最小组件消融应为"去掉潜动作、Stage 2 仅用有标注数据、同数据同步数"与"单骨干拼接 vs MoT"两组对照，并在相同预训练预算下与 UWM 比较。
- **严重程度**：主要问题

#### 质疑："+45% 超过 π0.5"取自最弱基线，且基线适配细节未披露

- **原文依据**：摘要与 §5.2 的 +45% 以 π0.5 为对象（RoboTwin 平均 42.98%），而 X-VLA 为 72.80%，两个基线相差 30 个百分点；论文未说明 π0.5 在 RoboTwin 上的微调配置、数据配比与是否经过最优调参。
- **为什么重要**：核心宣传数字的对照对象可疑，若 π0.5 适配不充分，+45% 是假性差距；反之若适配充分，需要解释为何 π0.5 在此基准上远弱于同代方法。
- **当前能够得出的判断**：RoboTwin 上"Motus > X-VLA ≈ +15pp"更可信；"+45% 超 π0.5"证据不足，存在基线欠调的可能。
- **如何验证或补强**：公开两个基线的 RoboTwin 训练配方、调参预算与复现日志；补一个作者自调的 π0.5/X-VLA 上界。
- **严重程度**：主要问题

#### 质疑：真机实验的"部分成功率"是自定义加权指标，样本少且无统计稳定性

- **原文依据**：§5.3 与论文 Table 3–5、Table 15–16：子任务分值（0.2/0.4/0.5/0.8/1.0 等）由作者定义；Aloha 的 Put Bread into Oven Motus 34% < π0.5 36%，与 §5.3"所有任务超过基线"矛盾；毛巾每类评 4 次、方块每类评 5 次（§8.3）。
- **为什么重要**：真机 +11~48% 是摘要级结论之一；自定义部分分权重可能系统性放大或缩小差距，小样本下的 4–5 个百分点差异无统计意义。
- **当前能够得出的判断**：AC-One 的大幅提升（14.79→63.22）方向可信但幅度受基线极低与任务构成影响；Aloha 上的差距（+10.7pp）在无置信区间时只能算弱证据。
- **如何验证或补强**：对每个真机任务做多次独立评测并给出置信区间，部分分权重做敏感性分析，或改用二值成功率复测。
- **严重程度**：主要问题

#### 质疑：五种"统一模式"中只有一部分能力有实验支撑，世界模型与联合预测的验证明显偏弱

- **原文依据**：论文 Table 6 的世界模型只有画质指标且无对照模型；论文 Table 7 的 IDM 只有 100 个样本的动作 MSE；联合预测模式除成功率外仅有可视化（论文 Fig. 12）；摘要声称五模式可切换"且统一建模显著有益"，但支持"有益"的实验实际只有论文 Table 8 一个数字（VLA 83.90 vs 联合 87.02）。
- **为什么重要**：本文的核心卖点是"五合一"，若多数模式只有存在性验证，卖点会退化为"一个成功的 VLA + 若干未验证的附加能力"。
- **当前能够得出的判断**：多模式推理在工程上可运行（有视频与指标产出），但"统一建模使各能力互相增强"未被充分证明。
- **如何验证或补强**：为世界模型补下游用途（如模型预测控制、失败检测）对照；扩大 IDM 评测样本；报告各模式在同一基准上的完整对比表。
- **严重程度**：次要问题

#### 质疑：外部依赖与私有数据披露不足，影响复现边界

- **原文依据**：训练依赖 Wan 2.2、Qwen3-VL、DPFlow、DC-AE、Curobo 等外部组件（§4.1–§4.2）；论文 Table 12 中 in-house 目标机器人数据 2,000 条与真机实验数据未公开；论文未报告 GPU 型号、训练总成本换算、真机遥操作数据采集协议细节；论文给出的项目页 https://motus-robotics.github.io/motus 在本报告读取时返回 404。
- **为什么重要**：可复现性是机器人基础模型类工作被质疑的首要维度；私有数据与未披露的采集/配置会限制第三方复现与成本评估。
- **当前能够得出的判断**：代码与检查点开源（Apache-2.0）提高了复现上限，但 Stage 3 与真机结果依赖非公开数据，第三方无法完整复现真机数字。
- **如何验证或补强**：公开 in-house 数据或其采集脚本、目标平台配置与评测协议；在公开数据上提供完整训练配方与成本表。
- **严重程度**：次要问题

## 6. 审稿式总评

> 作者发现具身智能的功能被割裂在理解、世界建模与控制的独立模型中，且动作专家无法利用无动作标签的异构视频数据，因此提出 Motus：用 MoT 三专家共享注意力统一五个建模分布，用 UniDiffuser 式调度器支持推理时的模式切换，并通过光流潜动作让动作专家在大规模无标注数据上完成预训练，配合三阶段训练与六层数据金字塔实现。实验在 RoboTwin 2.0（50 任务）与两个真机平台上表明，统一配方相对 π0.5 与 X-VLA 获得平均成功率上的一致提升；其中阶段消融（论文 Fig. 6）与真机 from-scratch 对照证据较强，但"MoT 结构、调度器、潜动作各自为何有效"仍缺少充分支持，且任务级统计（多次重复、置信区间）、基线适配细节与推理成本均未报告。本文最有价值的部分是把统一世界模型从原型做成了可运行、有开源检查点的完整工程配方（含数据分层与潜动作接口），最大的审稿风险是组件消融缺失导致的因果归因不明与"最弱基线"修辞。

- **问题定义清晰度**：强——五个分布的形式化（§1、§3）与两大挑战的拆分明确，任务边界（桌面双臂操作）清楚。
- **创新性证据**：中——架构与调度器均为已有组件的新组合，缺少与 UWM 式单骨干等的直接对照来支撑"统一结构更优"的声明。
- **方法可信度**：中——架构、损失与训练流程描述完整且可运行（有开源实现），但 14 维潜动作、六分之一降采样等关键设计选择缺少定量依据。
- **实验支持力度**：中——仿真 50 任务 + 两个真机平台的规模在同类工作中可观，但组件消融、统计稳定性与基线公平性存在缺口。
- **可复现性**：中——代码与检查点开源（Apache-2.0），但 in-house 数据未公开、GPU 型号与真机采集细节未报告、项目页链接失效。
- **综合阅读价值**：高——统一世界模型方向的完整工程配方、六层数据金字塔的组织方式与潜动作作为"动作专家预训练入口"的思路，对研究机器人基础模型与数据工程的读者有直接参考价值。
