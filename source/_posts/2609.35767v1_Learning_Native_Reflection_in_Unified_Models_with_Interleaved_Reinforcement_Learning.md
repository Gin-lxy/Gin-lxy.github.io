## 0. 一句话结论

UMM-Reflection 把统一多模态模型 BAGEL 的"看图—写诊断—改图"多轮反思整条轨迹做一个轨迹级 RL：同一初始图采样 $K=16$ 条兄弟轨迹共享一个组归一化优势，同时更新语言（反思文本）与 flow（图像编辑）两个头，推理时不再需要 verifier。在作者自建评测协议（512×512、instruction-voice prompt、每题 1 张图）下，GenEval 宏平均从 SFT 的 0.72 提升到 0.84（摘要称 +12.05 点），并迁移到未参与训练的 WISE（+10.97）、OneIG-Bench（+3.48）、T2I-CompBench++（+4.63）；效果证据（配对检验、消融）较完整，但机制主张("RL 只是选择 SFT 分布中已有的成功修复")以分布与探针证据为主，且全部主结果来自作者自建协议与单图评测，外部可比性与统计稳定性有限。

## 1. 论文具体想解决什么问题？

**研究背景与任务。** 统一多模态模型（同一网络里做理解与生成，如 BAGEL）能看自己的图也能重画它，原则上可以像语言模型做自我修正那样，对一幅有错误的生成图执行"检查—诊断—修订—再看"的闭环（§1）。作者把这个闭环称为 native reflection（原生反射）。难点在于：一次修订到底有没有用，只有渲染完成之后才知道，所以反思文本与图像生成必须作为一个整体来学，而不是先训文本、再训渲染器。

**现有方法及其局限。** 作者把已有路线归为两类（§1、§2）：

1. 对"单次渲染"做 RL：T2I-R1、ReasonGen-R1 对文本计划与单张图做 GRPO，UniRL 用模型对自己成图的回答当奖励——模型从不回去修改渲染结果；Flow-GRPO、DanceGRPO 等把组相对优化带到 flow 生成器，但策略仍是一次 prompt→image。
2. 监督模仿多轮"推理—编辑"轨迹：Idea2Img、Thinking with Generated Images、MINT、Uni-CoT、IRG、ThinkMorph、UniT 等让模型看中间图后继续生成，但主要靠模仿合成轨迹训练。"模仿能带来冷启动，但不能保证一次反思带来有效修正"（§2，作者主张）。

**作者发现的新现象（本文核心观察）。** SFT 并不是什么都没学会：16 条 SFT rollout 里，78% 的失败训练图存在至少一条正确修复（Fig. 1、Appendix I），且 95.48% 的 SFT 轨迹遵守协议格式（Table 8）；但单条 SFT 轨迹只修复 20.59% 的初始错误图（Table 8）。也就是说，模型"会做"，但"不能可靠地做对"——存在一个从"产生有用修复"到"稳定选择有用修复"的缺口。同时作者报告：只优化渲染器、或只优化循环里的一个头，都只能拿到一小部分收益（§5，Table 3）。

**作者对原因的假设。** 模仿学习优化的是"与示范的匹配"，而不是"哪条反思能带来更好的图像"；且一次反思的价值要在渲染之后、甚至后续轮次之后才显现，所以信用必须跨轮、并且同时流向诊断文本与渲染动作（§1）。naive 加入 RL（只训 renderer 或单头）无法提供这样的信用（§5 的三组对照）。

**要验证的核心假设。** 把整条反思轨迹作为优化单元、让兄弟轨迹共享同一张初始图、用轨迹级优势同时更新文本头与 flow 头，能否把"SFT 会做但不稳"变成"稳定做对"，且推理时不依赖 verifier、不依赖外部 critic 与 best-of-$K$ 选择。

需要区分的是：文本自纠正需要在线 RL 而非仅提示这一一般性结论在 SCoRe 等文本工作里已存在；本文的新观察是"统一模型的图像反思里也存在同样的冷启动—可靠性缺口"，并给出了量化（20.59% vs 64.94%）。

## 2. 创新点是什么？

**一句话概括真正增量。** 本文把一个 GRPO 风格、但作用对象是"整条多轮反思轨迹"的 RL 配方落进单个统一模型内部：共享初始图的 $K$ 条兄弟轨迹让组内比较的对象从"初始图运气"变成"反思策略"；一条轨迹级优势不经逐轮归一化，同时更新反思 token 与 flow 转场，从而绕开逐轮信用分配的组合爆炸（$K^N$ 条展开，$16^3=4{,}096$，§3.4），并用分级奖励让"部分修复"也能被奖励（Appendix C）。训练期用冻结 verifier 打分，推理期完全去掉。

逐项分析：

**(1) 共享初始图的全轨迹 RL（shared-root sampling，§3.4）。** 每个请求只采样一张初始图并从计算图中 detach，然后从同一像素出发采样 $K=16$ 条完整轨迹，各自跑到 done 或修复上限。与 T2I-R1/ReasonGen-R1 的"单轮 GRPO"不同，策略包含多轮相互依赖的图像状态；与 SCoRe 式文本多轮 RL 不同，动作空间里包含图像生成（flow head）；与 Flow-GRPO 相比，渲染转场被放进"首次生成不算损失、只算反思轮"的多轮轨迹中。这属于新设定下的组合式创新：GRPO、Flow-GRPO 的 SDE 采样、共享根设计都各有出处，但"把二者嵌进图像反思闭环 + 轨迹级单一优势"是新的。

**(2) 单一优势、双通道更新（Text–flow coordination，§3.4）。** 关键设计是文本与 flow 两个通道共享同一条轨迹优势 $A_i$，不分别归一化：一条反思带来更好的图，则写诊断的 token 与随后执行渲染的转场一起被强化，模型由此学到"哪类反思对应哪类视觉结果"。论文报告的证据是：冻结 flow 头只训文本头得 78，冻结文本头只训 flow 头只有 73（接近 SFT），联合训练 84（Table 3）。

**(3) 分级奖励与防早停（Eq. 1、Appendix C）。** 二值 GenEval 评分下，六个家族中五个在"部分修复"时 $\Delta_t=0$，progress 项会失效；所以作者只对失败区域分级：通过则 $q=1$，否则 $q=\min(\tfrac12 f,\,0.5^-)$（$f$ 为家族内约束满足比例），并在打分服务侧用 fail-closed 规则保证"通过/不通过判定不被改变"。论文报告 200 对图像检查无一违规，非零分数图像占比从 21% 升到 100%（Appendix C）。此外轨迹奖励对"过早 done"施加 $-0.5$ 惩罚；Appendix P 的对照显示：给"正确 done"发奖金会把最终准确率从 82 拉到 79（策略在 116 个最终失败里对 112 个错误图直接宣布 done）。

**(4) 冷启动数据构造（§3.2–3.3）。** 用 GPT-5.5 当 critic、Qwen-Image 渲染初图、Qwen-Image-Edit 执行编辑，生成 29,529 条被接受的轨迹：one-shot 9,000 条、natural-repair 8,645 条、planned-progression 11,884 条；BAGEL 不参与数据生成，避免把自身失败模式蒸馏回监督。这一条更多是工程流程与数据构造贡献，端到端依赖外部模型。

**与最接近工作对照后可确认的差异：** 相对单轮 RL：跨轮信用 + 修改自己的图；相对外部 critic 管线（Idea2Img/ReflectionFlow 等）：两个角色是同一策略、推理无 critic；相对模仿式多轮统一模型：有结果驱动 RL 且消融显示 best-of-4、多编辑预算、单纯 SFT 都达不到同等水平（Table 3）。至于"首次在统一模型上做多轮反思 RL"这一说法，根据本文的 related work 与实验对比，只能确认作者声称的差异；是否构成首次提出，还需要更完整的文献检索。

## 3. 作者如何解决？

**直觉。** 如果同一个网络既能看懂图又能画图，就让它在每一轮里先"看当前图 → 写出哪里不对 → 给出修改指令 → 重画"，并只把"最终图更好/更差"这一个结果信号回传给整条轨迹上的所有动作。多做几轮、多试几条，只要比较的是"从同一张图出发的不同反思策略"，就能学出"哪类诊断值得写"。关键在于两个角色用同一组参数、共享同一个优势，从而绕开"每一轮都要单独估计信用"的难题。

**按运行流程展开（§3.1–3.4）。**

1. **输入**：请求 $c$。模型先自己生成初始图 $x_0$，并在 RL 中把 $x_0$ 从计算图 detach——初始文生图不直接接收策略梯度（脚注 1：BAGEL 本身不支持单次前向的交错生成，作者用外部 controller 把每轮的反思与图像作为新 turn 回灌，以执行交错协议）。
2. **每一轮**：模型观察请求、文本—图像历史、当前图 $x_t$，输出结构化反思 $u_t\sim\pi_\theta^{\text{text}}(\cdot\mid c,x_{\le t},u_{<t})$，动作 $a_t\in\{\text{edit},\text{done}\}$；edit 附带自然语言修正指令 $e_t$，随后同一模型渲染 $x_{t+1}\sim\pi_\theta^{\text{flow}}(\cdot\mid c,x_t,e_t)$；done 则返回当前图。协议最多三轮修复（§3.1）。反思为带标签字段的文本（[CURRENT_ROUND]、[SOURCE_IMAGE]、[SCORE]、[THINKING]、[ACTION]、[EDIT]），其中 [SCORE] 是模型自评、不是外部奖励，verifier 分数从不进入策略观测（Appendix B；完整推理系统提示词见 Appendix R）。
3. **训练分三段。** 第一段是外部模型造轨迹（§3.2）。第二段 SFT 冷启动：$\mathcal{L}_{\text{SFT}}=\mathcal{L}_{\text{AR}}+\lambda_{\text{img}}\mathcal{L}_{\text{FM}}$，从 base BAGEL 出发训练一个 epoch；167,363 条训练行分三种视图——controller 行监督完整反思文本、transition 行监督每次编辑（编辑图像收 flow-matching 损失）、verifier 行看部分轨迹只监督下一条反思；28 层 MoT 的两个 expert 分支可训，ViT/VAE、文本嵌入、词表投影冻结（Appendix B）。第三段全轨迹 RL：每个 update 取 2 个 root、每个 root $K=16$ 条兄弟轨迹；冻结 verifier 给每张图打分级分 $q_t$，轨迹奖励为

   $$R(\tau)=q_T+\alpha\sum_t[\Delta_t]_+ + \beta\, S_{\text{multi}}(\tau) - \lambda\sum_t[-\Delta_t]_+ - p\,\mathbf{1}[\text{premature done}],$$

   其中 $\Delta_t=q_{t+1}-q_t$，$S_{\text{multi}}(\tau)=\sum_t[\Delta_t]_+ - \max(\{[\Delta_t]_+\}_t\cup\{0\})$，超参 $\alpha=\beta=0.3$、$\lambda=p=0.5$（Eq. 1–2）。组内归一化后每条轨迹拿一个优势

   $$A_i=\operatorname{clip}\!\left(\frac{R(\tau_i)-\mu_R}{\max(\sigma_R,0.1)},\,-1,\,1\right),$$

   两个通道共用它做 clipped surrogate $J_c$（对冻结 SFT 参考的 KL 惩罚、text/flow 各自的 clip 与 KL 系数；flow 用 Flow-GRPO 的 SDE 采样器，每次修复训两个连续随机转场），ε 分别为 0.2/0.1（§3.4、Table 4）。
4. **推理**：只有统一模型运行——无 verifier、无 best-of-$K$、无外部 critic；50 步去噪、512×512、最多 3 次修复，每个 prompt 返回 1 张图（§4.1、Appendix A）。

## 4. 解决得怎么样？

#### 4.1 实验设置

- **任务与数据**（§4.1、Appendix A）：GenEval（全部 553 条官方 prompt，未过滤）、WISE（1,000 条）、OneIG-Bench（695 条 alignment prompt / 共生成 1,120 条）、T2I-CompBench++（2,400 条，8 类）。RL 训练只用 3,000 条 GenEval 风格 prompt 池（取自 Flow-GRPO 发布数据的六家族配额，与官方评测 prompt 无复用、无重复；另有 270 条与训练 UID 不相交的 dev 集）。
- **基础模型**：BAGEL（28 层 mixture-of-transformers），所有臂同一 backbone；RL 从 reflection-SFT checkpoint 出发，训练与评测统一在 512×512（BAGEL 原生 1024×1024；作者解释低分辨率是为了让整轨迹采样可行）。
- **基线**（§4.1、§5、Appendix N）：Base（单次生成）、reflection SFT（多轮无 RL，RL 的直接 parent）、直接 T2I-RL（Flow-GRPO 从官方 Base 训 1,000 updates、无修复）、Self-Agentic（未训练的 Base 被强制走三轮 inspect-and-edit）、Best-of-4（用 T2I-RL 渲染器出 4 张图，用 Base 或 RL 的理解通路选 1 张，同 4 图预算）、外部 GPT-5.5 critic 管线。
- **指标与统计**：GenEval 六家族宏平均（0–100 与 0–1 两套都报告）；WISE 官方加权聚合（GPT-4o judge）；OneIG question-dependent alignment（Qwen2.5-VL-7B scorer）；CompBench 八类均值（类别专用 scorer）。配对比较用 McNemar 精确检验，分布分析用按 prompt 分层 bootstrap 区间（1,000–5,000 次）。评测协议自建：instruction-voice prompt、每题 1 张图、≤3 次修复、50 步去噪，各臂一致。
- **消融/分析回答什么**：Table 3 回答"每个组件是否必需"（组件叠加、训练长度、单头冻结、同预算 Best-of-4、奖励项移除）；§6 与 Appendix F–J 回答"模型内部变了什么"；Appendix P 回答"停止行为如何被奖励塑形"；Appendix N 回答"外部 critic 是否更强"。

#### 4.2 关键结果

只列支撑主要结论的关键数字（均注明位置）：

- **GenEval 主结果**（Table 1，553 prompts，512²，宏平均 0–1）：BAGEL-Base 0.71、reflection SFT 0.72、UMM-Reflection **0.84**；摘要口径相对 SFT +12.05 点（prompt-micro 版本见 Table 8：71.07 → 83.91）。增益集中在需要"改构图"的家族：position +42.00（0.47→0.89）、color binding +14.00、counting +10.00；**single object 是唯一回退**（1.00→0.95，Table 10）。
- **配对统计**（§4.2、Table 9）：最终图上 RL 对 SFT 为 109 胜 38 负（$p<10^{-8}$，McNemar）；仅初始图是 48–32（$p=0.09$，无显著差异）——增益来自反思轮而非更好的第一张图。
- **条件修复率**（Table 8）：单条轨迹修复初始错误图的比例从 SFT 的 20.59% 升到 64.94%；同时 **damage 率（把本来正确的图改坏）从 6.53% 升到 8.77%**。
- **迁移**（Table 2，native 0–1）：WISE 0.55→0.74；OneIG 0.80→0.83（SFT 0.79 反而低于 Base）；CompBench 0.49→0.55。相对 SFT 的增幅为 +10.97/+3.48/+4.63 点（摘要），三个 benchmark 都未参与训练。
- **测试时扩展**（§4.3、Fig. 4）：SFT 三轮只加约 +2 点且第一轮后变平；RL 第一轮就 +9 点且到第三轮仍在涨；各臂初始图准确率几乎相同（70–73），说明差距来自多轮修正。
- **消融**（Table 3，宏平均 0–100）：直接 T2I-RL 76（单次生成变强但不会修复；WISE 上 0.54 vs Base 0.55 不迁移，§1、Table 11；该对照设置见 Appendix A.1）；Self-Agentic 未训练循环 77；SFT 72；**联合 RL 84**；只训 flow 头 73；只训文本头 78；同 4 图预算 Best-of-4 为 80（两种选择器，配对 McNemar $p\le0.04$）；去掉多轮进步项 $\beta=0$ 为 79（且初始图准确率从 73 掉到 63）；只训 500 updates 已有 82。在"四次 Base 独立采样全部失败"的 62 个 prompt 上，RL 反射恢复 60%（SFT 12%）。
- **外部对照**（Appendix N）：GPT-5.5 critic 管线 GenEval 0.79、修复率 27.6%（45/163），且 GPT-5.5 对 67/163 张错误初图一次编辑都不发；UMM-Reflection 为 0.84 / 64.9%，推理时无外部模型。

**没有提升的部分（如实列出）**：counting 家族停在 67.5（Appendix Q 显示该家族训练奖励 1,000 updates 内始终平坦，作者归因于"计数需要精确、学到的增删/改色/移位编辑还无法可靠改变数量"，并把它列为下一步训练目标）；WISE/OneIG/CompBench 的增幅比 in-domain 小一个量级；single object 家族小幅回退。

#### 4.3 机制证据

**主张**：RL 没有给模型新能力，而是在 SFT 已能产生的修订中"选择"那些能落到正确区域的路径。支撑证据分四组（§6、Appendix F–J）：

1. **兄弟覆盖率 vs 单条成功率**（Appendix I，Table 7）：RL 训练早期（策略≈SFT），16 条 rollout 中已存在正确修复的 root 占 77.6%，而单条轨迹成功率仅 22.7%；训练后 pass@1 升到 70.1%，pass@16 只升到 97.1%。即"可修复性"分布基本已存在，RL 主要抬高单次命中率。
2. **骨干自身的正确性读出几乎不变**（§6.2、Appendix F，Fig. 5、Table 5）：理解流 depth-20 的 "passes the verifier" 线性探针 AUC 在 Base/SFT/RL 下为 0.804/0.807/0.815（冻结 DINO/CLIP 特征只有 0.55）；但初始失败图落入该读出"稠密通过区"的比例在 RL 下从 34% 升到 62%，SFT 只从 36% 到 42%；在编辑次数匹配（同为 3 次编辑）的 153 个 prompt 上，RL 的 DINO 首末图距离 0.28 vs SFT 0.11（配对差 0.17，95% CI [0.13,0.21]），R0→R3 精确增益 −3.3（SFT）vs +16.3（RL）（+19.6 [11.1,28.1]）。

   ![Fig. 5：失败图像在被复现的骨干自身"通过 verifier"读出面（理解流 depth-20 × 生成流 depth-8）上的分布移动，RL 的 R0→R3 与 SFT 的 R0→R3 对比](/images/dailypaper/2026-09-29/2609.35767_fig5.svg)

   Fig. 5 是"选择而非新增能力"这一主张最核心的图：每个点是一张初始失败的图，坐标是两条线性探针的输出（理解流 depth 20 与生成流 depth 8，即两流各自 AUC 峰值所在深度；探针按 prompt 分组五折交叉验证，报告留出 AUC）；绿色实线等高线是 verifier 通过的参考图、红色虚线是失败的参考图（相当于骨干眼中"对/错"的坐标系）；橙色（RL）与蓝色（SFT）等高线分别是两种策略在 R0 与 R3 的图像分布。读法是配对看：左两格是 RL 从 R0 到 R3、进入稠密通过区的比例 34%→62%；右两格是 SFT 的 36%→42%。它说明 RL 的 R3 分布直接落在 SFT 分布已经偶尔够到的同一通过区里——RL 没有打开新区域，而是把轨迹移了过去；这就是"RL 提取 SFT 宽分布中的正确切片"这一措辞的来源。
3. **换指令的准因果实验**（Appendix J）：固定图像、RL 渲染器与噪声，只替换编辑指令——RL 策略写的指令修复 48.4%，原始请求指令 20.5%，SFT 策略的指令 21.4%，规则化穷举所有 GenEval 约束的指令 27.6%；RL−规则 +20.8 点（95% 状态 bootstrap [13.6,27.9]）。这直接说明"改进写在文本里"的部分确实可迁移、可执行。
4. **视觉通路稳定**（Appendix G/H）：SFT 与 RL 对 VAE key 的注意力图中位相关 0.98（ViT 超 0.99）；第三轮时对历史各图（$x_0$、第一修订、当前图）的注意力分配在 SFT 与 RL 下几乎相同——模型读它自己的整段视觉历史，RL 没有改变这一点。

**如何解读这组证据（审稿人视角）**：这是"效果 + 分布/探针相关性 + 一个准因果换指令实验"的组合，比只报性能更有力；但探针与 pass@16 统计都在训练提示与训练 verifier 内测得，"选择而非新增能力"的强主张仍无法完全排除奖励工程带来的分布偏移（详见 §5 质疑 3）。论文没有做"限制候选集后 RL 还能否增益"这类直接因果隔离。

#### 4.4 成本与适用范围

- **训练成本**（Appendix A、Table 4）：RL 在 2 节点 × 8 张 NVIDIA H100 80GB（16 GPU、FSDP hybrid-sharded）上跑 1,000 updates 约 33 小时（中位 118 秒/update）；每个 update 渲染 2 roots × 16 siblings × 最多 4 张图。训练与评测都在 512×512（BAGEL 原生 1024×1024），作者明说降分辨率是为了让整轨迹采样可行。
- **推理成本**：推理时无 verifier、无外部模型、无 best-of-$K$；但 RL 平均编辑数 3.00（Table 3，几乎总用满 3 次修复预算），即每个 prompt 最多生成 4 张图，相对 Base 的单张是约 4 倍图像生成开销。**论文未报告推理时延、显存或单题 wall-clock 成本。**
- **数据/外部依赖**：SFT 冷启动的 29,529 条轨迹依赖 GPT-5.5、Qwen-Image、Qwen-Image-Edit（§3.2），其生成成本与接受标准未量化；RL 的奖励依赖与 GenEval 同源的冻结检测器（Appendix C）。
- **验证范围**：核心结论建立在 BAGEL 一个骨干、GenEval 六家族式组合约束、512² 评测之上；迁移结论覆盖 WISE/OneIG/CompBench 三个 benchmark（增益更小但方向一致）。论文**未验证**：更高分辨率、其他统一模型骨干、GenEval 约束之外的能力（如文字渲染、人物一致性）、以及推理期成本与延迟的可行性；counting 家族仍无改善。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：评测协议是作者自建的（512²、instruction-voice、每题 1 图），与公开榜单/原生协议不可直接比较，"超过 SFT +12 点"的外部意义有限

- **原文依据**：Appendix A 明确"所有臂在 512×512、50 步、≤3 repairs 下评测；BAGEL 原生 1024×1024"；§4.1 说明用 instruction-voice prompt；Table 1 标注 "BAGEL reports 0.82 under its native protocol [8], whereas the local rows use our protocol"（本地 Base 只有 0.71）；Table 1/2 参照行大多标 † 或 "published settings differ"。
- **为什么重要**：论文的核心卖点是反思循环的价值，但低分辨率会放大/缩小错误分布（更多细节类错误被移除），自建 prompt 口吻也会改变模型行为；外部读者无法把 0.84 与榜单上的 GenEval 分数对齐。
- **当前能够得出的判断**：内部对照（Base/SFT/RL 同协议）是公平的，作者也自觉区分了 "controlled comparisons" 与 published 参考值；但绝对数值与跨论文比较不能成立，工程上也未证明 1024² 或其他口吻下同样有效。
- **如何验证或补强**：在 BAGEL 原生 1024² 与原生 GenEval 协议下复评同一 checkpoint；或在另一套 prompt 口吻下复现 Δ；报告分辨率敏感性。
- **严重程度**：主要问题。

#### 质疑：奖励与评测同源——训练奖励直接由 GenEval 风格检测器/阈值构成，训练池又是 GenEval 六家族，in-domain 增益可能是"对评测器过拟合"

- **原文依据**：Appendix C 的分级奖励逐家族用 GenEval 官方检测器与阈值（object 0.3、counting 0.9）计算 $q$；§4.1/Appendix A 说明 RL prompt 池就是 GenEval 六家族（每家族固定配额）；相对地，外部 benchmark 增益为 +10.97/+3.48/+4.63（摘要），比 GenEval 的 +12.05 小一个量级（OneIG 只有 +3.48）。
- **为什么重要**：如果增益主要来自"学会满足检测器"，那它不是一般的图像修复能力；迁移结果（WISE 由 GPT-4o 打分、OneIG 由 Qwen2.5-VL 打分）是当前唯一的反过拟合证据，但那些 judge 也是自动模型，且论文没有人类评测。
- **当前能够得出的判断**：存在真实迁移、且 fail-closed 设计保证评分不改变通过/不通过判定；但论文既没有检验"训练奖励上升而独立质量不升"的反例，也没有量化检测器盲区。reward hacking 风险未被排除。
- **如何验证或补强**：引入与训练检测器不同构的评测（人类偏好、LLM 裁判、其他视觉检查器）；做"替换训练 verifier（如换用另一组检测器）后增益是否保持"的消融；报告训练奖励与留出质量曲线的相关性。
- **严重程度**：主要问题。

#### 质疑："RL 只是选择 SFT 分布中已有的成功修复"这一机制主张以分布/相关性证据为主，缺因果隔离，且在训练分布内测得

- **原文依据**：Fig. 5、Table 5 的探针与分布统计、Table 7 的 pass@1/pass@16 都基于 553 条 GenEval 轨迹与训练 verifier；探针 AUC 在三个 checkpoint 间只差 0.011（0.804→0.815）；Appendix J 是唯一准因果实验（换指令），但它只测"文本通道"，未隔离"渲染器分布"与"采样选择"的作用。
- **为什么重要**：这一主张直接决定论文的理论贡献定位（"选择"而非"学会新能力"）。若实际上 RL 也扩展了可行修复集合（比如更长编辑序列中的新组合），用"选择"解释会低估方法、也误导后续研究。
- **当前能够得出的判断**：证据方向一致地支持"选择"解释（pass@16 只从 78% 到 97%、探针不变、指令换装可迁移），但"候选集限制后 RL 仍增益"的对照缺失；且 β=0 消融显示初始图准确率可从 73 崩到 63（共享权重漂移），说明"初始图不受 RL 影响"的说法需要限定为"无直接轨迹损失"。
- **如何验证或补强**：给 RL 策略的候选动作加约束（如只允许 SFT 采样中出现过的编辑指令类型）看增益是否消失；对渲染器做冻结对照（已有 flow-only 行）并结合采样噪声固定；对"选择"假说做 pre-registered 预测（如按 SFT 分布密度分层报告增益）。
- **严重程度**：主要问题。

#### 质疑：SFT 起点的价值没有被隔离——未训练的 Base 加外部循环（77）甚至高于 SFT（72），且缺少"Base 直接做轨迹 RL（跳过 SFT）"的对照

- **原文依据**：Table 3 中 Self-Agentic（未训练 Base 强制三轮 inspect-and-edit）71→77（+5，repair 27.6%），而 reflection SFT 70→72（+2，repair 20.6%）；表内"direct RL → reflection SFT → trajectory RL（500 updates）"两行说明任务顺序有影响（74→81 vs 71→82），但没有 Base→轨迹 RL 的臂；§3.3 只解释 SFT 提供"一致接口"。
- **为什么重要**：如果 SFT 只是提供协议格式、甚至一度把性能做差（72<77），那么"必须先 SFT 再 RL"的设计选择、以及 SFT 数据构造（GPT-5.5/Qwen-Image 蒸馏）的必要性都值得质疑；这也影响方法的复现成本（省掉蒸馏管线可大幅降低成本）。
- **当前能够得出的判断**：论文显示了 SFT 对接口与"有意义的修订"的作用，且最终 RL 获益远超前两者；但 SFT 的净贡献与最优起点顺序未被隔离，作者也未讨论"72<77"这一现象。
- **如何验证或补强**：增加"Base + 协议提示 → 直接轨迹 RL"与"SFT 只学格式（无图像 loss）→ 轨迹 RL"两个对照；报告跳过蒸馏数据规模后的性能曲线。
- **严重程度**：主要问题。

#### 质疑：关键结果缺统计稳定性披露，damage 上升与失败案例被淡化，成本未完整报告

- **原文依据**：Appendix A 明确 "Evaluated outputs per prompt and arm: 1"（每题 1 张图、单一 checkpoint）；摘要与结论只给点估计（+12.05 等），没有多 seed/多次运行的方差；damage 从 SFT 6.53% 升到 8.77%（Table 8）未做显著性检验，只在正文一句带过；失败案例仅 Appendix O 的 Fig. 19 两例；推理延迟、SFT 蒸馏成本均未报告。
- **为什么重要**：单图评测 + RL 采样噪声使 ±1–2 点的差异不可解释；damage 上升意味着反思循环有时会把对的图改坏，这是部署关注点；闭源/外部模型依赖（GPT-5.5、Qwen-Image）影响复现。
- **当前能够得出的判断**：主结论（+10 点量级）远大于噪声风险，配对 McNemar 与 bootstrap 区间也覆盖了部分比较；但细粒度结论（如 500 vs 1,000 updates 的 82→84）缺少方差支撑，damage 上升未被正面讨论。
- **如何验证或补强**：主表报告多种子均值与区间；对 damage 做配对检验；公开蒸馏数据的构造统计（接受/重试率、成本）；报告推理期每题的图像生成数与延迟。
- **严重程度**：次要问题。

## 6. 审稿式总评

作者发现统一多模态模型在模仿式 SFT 之后已经"会改图但不稳定"（单条轨迹修复率 20.59%，而 78% 的失败图存在正确修复的兄弟样本），因此提出 UMM-Reflection：从同一张 detach 的初始图采样 $K=16$ 条完整反思轨迹，用一条组归一化的轨迹级优势同时更新文本头与 flow 头，配合分级奖励与防早停项，且推理期不需要 verifier。实验在 BAGEL、512×512 自建协议下表明：GenEval +12 点量级、三个外部 benchmark 有更小但稳定的迁移，消融支持"共享根 + 双头联合 + 分级奖励"的必要性，"RL 选择已有修复路径"的解释由探针、pass@k 与换指令实验交叉支撑；其中效果证据（内部对照、配对统计、指令替换的准因果实验）较强，但"选择而非新增能力"仍是基于训练分布内的分布证据、奖励与评测同源带来的过拟合风险、以及 SFT 起点价值未被隔离，这三点缺少充分支持。本文最有价值的部分是把"多轮反思 + 结果驱动 RL + 统一模型单策略"的工程与评测框架完整地立了起来，并给出了机制分析的范式；最大的审稿风险是评测协议与奖励的同源性使外部可比性与泛化结论无法完全令人信服。

- **问题定义清晰度**：强
- **创新性证据**：中
- **方法可信度**：中
- **实验支持力度**：中
- **可复现性**：中（代码/权重/数据集合已公开，但依赖 GPT-5.5、Qwen-Image 等外部/闭源模型与 16×H100 训练资源）
- **综合阅读价值**：高
