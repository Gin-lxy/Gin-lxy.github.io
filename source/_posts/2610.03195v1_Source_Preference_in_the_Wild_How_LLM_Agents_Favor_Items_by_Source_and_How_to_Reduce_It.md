## 0. 一句话结论

本文研究 LLM agent 在端到端网络搜索中是否按"来源"（URL 的 registrable domain）系统性偏好条目，并用"要求满足度匹配 + 位置循环轮转 + Bradley–Terry 评分"把这种偏好量化，进一步用隐藏/互换来源信息的受控实验、DPO 训练实验和推断时干预来定位其来源与缓解路径。在论文报告的三个域（Shopping、Accommodation、Scholar）与 12 个模型上，证据较强地支持"显式来源信息本身会影响选择"；但"野外偏好幅度可全部归因于来源身份"与"现实模型的偏好由训练数据中的来源–满足度关联造成"两条更强的因果表述，目前证据只能支持"在受控设置下能够发生"，尚不足以支持"现实成因即如此"。

## 1. 论文具体想解决什么问题？

研究背景与任务：LLM agent 正从"提供信息"转向"替用户做决定"——决定展示哪些商品、推荐哪家酒店、引用哪篇论文（§1）。当 agent 对来自某些来源（site 或 service，定义为条目 URL 的 registrable domain）的条目表现出偏好——即便不同来源的条目同等满足用户请求——用户的可见范围会被收窄，被回避来源即使提供更好的条目也可能失去曝光；若 agent 的选择反馈进后续训练，偏好还可能自我强化（§1，作者提出的动机，属作者主张）。

现有方法的处理与失效条件：已有工作在受控设置中把语义相同的内容挂到不同来源上，证明模型存在来源偏好（如 Khan et al. 2026 报告学术、新闻、购物域的来源偏好；Blankenstein et al. 2026 显示功能等同的工具也存在 provider 与位置相关的选择偏差）；但真实端到端搜索中，每个来源提供自己的一组条目，内容质量与请求满足度天然不同，展示位置也不同。此时只看"选择率"无法区分"偏好该来源"与"其条目更好或位置更有利"（§1、§3）。

本文发现的新现象与支撑证据：（1）在控制要求满足集合（requirement-matched）与展示位置后，12 个模型在三个域中每一个都同时偏爱某些来源、回避另一些，且模型间方向高度一致（§4.1）；(2）偏好可压过满足度：少满足一个 requirement 的条目来自 preferred source 时被选择率中位数 68%，而反方向仅 2%（§4.2，Fig. 3）；（3）显式来源信息（URL、标题/正文中的来源名）本身影响选择——隐藏减弱偏好、恢复增强、互换改变选择（§5）；（4）训练中把来源与"更好条目"反复配对可以让来源成为满足度的 shortcut（§6.1，DPO 实验）；(5）内容缺少请求所需信息时，agent 用关于来源的先验知识填补（§7，Appendix K 给出真实推理片段）。

作者认为问题产生的原因：来源被当作"该来源条目更可能满足请求"的捷径信号（作者援引 shortcut learning 文献 §6.1）；缺失信息触发对来源的刻板先验（§7）。核心待验证假设为三条：端到端搜索中存在可测量的来源偏好；显式来源身份本身（而非其条目差异）影响选择；该依赖可由训练中的来源–满足度关联产生，并可通过补全信息或改写系统提示减轻。

区分三类：领域一般问题——LLM 的顺序/位置偏差与上下文线索敏感性早已被研究（Appendix A）；本文新观察——端到端搜索（agent 自行检索、条目内容各不相同）中的来源偏好、inversion 率与其跨模型一致性；本文实际解决的子问题——给出可比的来源偏好度量并隔离"来源身份"的因果贡献，以及两条缓解路径的可行性验证。需要强调：论文观察到了偏好现象并做了因果隔离实验，但对现实中 12 个模型的偏好"为何形成"没有直接验证（Appendix I 的 Interpretation 明确承认这一点）。

## 2. 创新点是什么？

真正的技术增量可以概括为：把"来源偏好"从人工构造的受控问答搬到端到端检索—选择流程中，构造了一套在同满足度、同位置下比较来源的度量（requirement-matched pairs + 循环位置轮转 + Davidson 扩展的 Bradley–Terry 模型 + 请求级聚类 bootstrap 与 FDR 控制），并配合三组干预（来源信息隐藏/恢复、内容固定的来源身份互换、合成来源的 DPO 训练）把"来源身份影响选择"这一命题从相关性推进到受控因果证据，最后测试了缺失信息场景下的缓解手段。逐项分析：

1. 端到端搜索中的来源偏好度量与 inversion 指标。新增了什么：以 LLM judge 判定每个条目的要求满足向量 $q$，仅把"满足同一 $q$"且来自不同来源的条目配对（requirement-matched pair），每条结果列表做全部 $L$ 个循环轮转（每个轮转单独运行，构成循环拉丁方），逐位置比较选择结果 $D_c=Y_c-Y'_c\in\{-1,0,1\}$；用 Davidson 扩展的 Bradley–Terry 模型联合估计每个来源评分 $\beta_s$ 与 tie 参数 $\nu$，偏好分定义为

$$\tau_{s}=\mathbb{E}\left[D\mid\beta_{s},\beta_{\mathrm{opp}}\right]=\frac{\exp(\beta_{s})-1}{\exp(\beta_{s})+1+\nu\exp(\beta_{s}/2)}$$

（Eq. 1），并用请求级聚类 bootstrap（$B=10{,}000$）加 FDR 5% 把来源分类为 Source+/0/−（§3，§E）。与最接近的已有方法（Khan et al. 2026 的语义相同内容+不同来源提示）的差异：条目由 agent 自己通过真实搜索获得、内容与满足度各异，匹配与位置控制针对的就是这种"野外"噪声。这一差异属于研究场景迁移 + 测量方法的组合式创新；论文用 Table E.2 报告 BT 单评分拟合的相关 r=0.54–0.76、加权平均绝对残差 0.02–0.06 来支撑该度量的可用性。

2. 来源身份的因果隔离实验。新增了什么：条件重放（Hidden：URL 隐藏且标题/正文中的来源名替换为 "the website"；URL-only：恢复 URL；Original：原样）逐级恢复显式来源信息（§5.1、Table 2、Appendix G）；以及内容与位置严格平衡的互换实验——同一对 requirement-matched 条目，标题/正文中的来源线索被擦除、来源身份只出现在 url 字段，来源赋值（原样/互换）× 展示顺序（两种）共 4 臂，统计 $T_+-T_-$（§5.2、Table 3、§H）。与已有工作的差异：不是比较不同条目的选择率，而是在内容与位置固定下只改变"显示的来源身份"。移除该设计的后果：仅凭 §4 的观测数据无法区分"来源身份"与"该来源条目未被判定的其他差异"（论文 §5 开篇自己指出了这一替代解释）。

3. 训练机制实验（合成来源 DPO）。新增了什么：用三对虚构来源（Kelto–Varnis、Temnuki–Dalnuki、Roveki–Tavumi），在 DPO 偏好对中让 target 来源以 50%/80%/20% 的比例标记"更好满足请求"的条目（Balanced/Aligned/Reversed），推断时用满足度相同的条目对测量 target 的选择率（§6.1、Table 4、§J）；以及用同样方法对既有 Amazon 偏好做 rebalancing/reversal（§6.2、Table 5）。这回答了"来源偏好能否被训练数据制造/削弱"的可行性问题；无法回答"现实现有偏好是否由此产生"。

4. 缺失信息下的缓解实验。新增了什么：在两候选（Source+ vs Source−）设置中，比较 Same Price（把缺失价格以相同值补进两条内容）、General 系统提示（"来源 URL 与价格无关"）、Designate 系统提示（"通常 {Source−零售商} 提供低价"）对 Source+ 选择率的影响（§7、Table 6）。结果模式清晰：补信息有效、否认关联无效、反向植入先验有效（§7.1、§7.2）。

几点对照规范"不得自动视为创新"的检查：论文的主实验未被更大模型/换数据集替代；DPO、LLM judge、Tavily、Bradley–Terry 均为现成组件，本文贡献在其组合与实验设计而非新算法。关于原创边界：根据本文的 related work 和实验对比，只能确认作者声称的差异（把来源偏好研究延伸到端到端搜索并做来源身份隔离实验）；是否构成首次提出，还需要更完整的文献检索。

## 3. 作者如何解决？

直觉：要把"偏好来源"这个模糊说法变成可检验的命题，需要构造"除来源外尽量相同"的对比。作者的策略是两层控制——第一层在观测数据里，把满足度相同、位置相同、只差来源的条目配对比较（回答"偏好是否存在、有多大"）；第二层在干预实验里，把来源信息本身当作被操纵的变量（回答"是不是来源身份在起作用"），最后分别从训练侧与推断侧测试偏好的生成与消除路径。

运行流程（按论文实际管线）：

1. 输入与检索：每个请求交给一个遵循共享系统提示的 ReAct 风格 agent（§2、§B）。agent 只能执行 `search[<query>]` 与 `select[<n1,n2,...>]`（可含"返回搜索页"），不能打开网页；结果页由 Tavily Search API 返回，每条含 title、content snippet、URL（按 Tavily 顺序展示、不重排，平均每条搜索 8.83 个结果）；每 episode 最多 5 个环境动作（最多 3 次搜索）。三个域共 4,822 个请求：WebShop 1,500、HotelQuEST 786（214 原始 + 572 地理位置替换变体）、ScholarGym 2,536（§C、Table C.1）。
2. 要求满足度判定：Shopping 用 WebShop 结构化要求；Accommodation/Scholar 用 LLM 从请求中抽取可核验条件（完整提示词见 §D）。逐要求的判定由 source-blind 的 LLM judge（Qwen3.8-27B）完成，judge 只看到 title 与 content（URL 与来源名被移除）；人类标注抽样验证 375/375/100 条，人在环一致性：人类–人类 $\alpha$ 0.67–0.72，人类–LLM $\alpha$ 0.65–0.75（§2、§D、Table D.1）。
3. 来源偏好测量：同一结果列表内，把满足同一要求集合 $q$ 的条目两两配对；对长度 $L$ 的列表做全部 $L$ 个循环轮转、每个轮转单独运行，使每个条目在每个位置恰好出现一次；对每个位置 $p$，用"条目 $i$ 置于 $p$ 的那次运行"与"条目 $j$ 置于 $p$ 的那次运行"构成一次比较，得分 $D_c$（仅 $i$ 选中为 1，仅 $j$ 选中为 −1，其余为 0，其中包括"都没选"与"都选"两类 tie）；随后拟合 BT+Davidson 模型得到来源评分 $\beta_s$，按 Eq. 1 换算出与平均来源的期望选择差 $\tau_s$（百分比点），并用请求级 cluster bootstrap 检验显著性、在模型×域内做 FDR 5% 控制，得到 Source+/Source−/Source0 标签（§3、§E）。少于 15 个匹配对的来源被合并为一个共享评分的 pooled opponent。
4. 关键图：![论文总览：上排为端到端 agent 设置（请求→ReAct 检索与选择→source-blind 要求满足度判定），下排为偏好测量流程（匹配比较与位置轮转→Bradley–Terry 评分→来源分类规则）（原论文 Figure 1）](/images/dailypaper/2026-10-05/2610.03195_fig1.png)

   这张图把全文两半工作串起来：上半部分的三个面板对应"agent 如何自己检索并选择条目"，强调判定器看不到来源（source-blind），这是后续所有比较的可信前提；下半部分的第 4 面板展示循环轮转如何让同一对条目在每个位置都被公平比较（把位置从混淆变量变成受控变量），第 5 面板给出 $\tau_s$ 的直觉解释（相对平均来源的期望选择差），第 6 面板给出按显著性把来源分为 Source+/0/− 的规则——注意 Source0 表示"证据不足"而不是"偏好为零"。没有这套位置与满足度的双重控制，"选择率差"就无法解释为来源偏好。

5. 受控实验一（隐藏/恢复来源信息）：冻结 agent 的自然轨迹（用户指令、查询、条目、此前 assistant 轮次不变、不再发起新搜索），仅在最终结果页上做三种可见性变换：Hidden（删 URL 字段、条目自身标题/snippet 中的来源名替换为 "the website"）、URL-only（在 Hidden 基础上恢复 URL 行）、Original（原样）；对变换后的页面重新做全部循环轮转评估，逐条件重新估计 $\tau_s$ 并保持 §4 的来源分类标签固定（§5.1、§G）。预期的检验逻辑：若偏好源于来源身份，隐藏应使其减弱、恢复应使其增强。
6. 受控实验二（来源身份互换）：对每个模型×域，取同请求、不同来源、满足判定向量完全相同（逐位相等，而非仅总分相同）的条目对；两个条目的标题/snippet 中来源线索先被替换为 "the website"，来源身份只能通过 url 字段显示；每对做 4 次展示（原样/互换 × 两种顺序），比较 $T_+$（显示为 Source+ 身份时的选择率）与 $T_-$，差值 $T_+-T_-$ 在内容与位置都平衡时期望为 0（§5.2、§H）。
7. 训练侧实验：对 Qwen3.5-9B、Llama-3.1-8B-Instruct、Tulu-3-8B-SFT 用冻结的 WebShop 搜索结果构造 DPO 偏好对——chosen 是"更好满足请求"的条目对应的选择动作，rejected 是另一个；训练数据中 target 来源被分配给 chosen 的比例在 Balanced/Aligned/Reversed 条件分别为 50%/80%/20%，每条对子在两种顺序下渲染（10,000 条训练样例），标签本身只由满足度决定（§6.1、§J，Table J.1：LoRA、5,000 updates、有效 batch 8、lr $5\times10^{-6}$、单卡、bf16）。评估时不采样：对两个合法动作分别求条件对数概率，比较大小得到选择率（Eq. 3）；评估对子的满足向量完全相等，因此差异只能来自来源。
8. 推断侧实验（缺失信息）：在两候选（Source+ vs Source−，来源身份仅出现在 url 字段）中，系统给缺失价格要求的情形设计三种干预：补上相同的价格（Same Price）；系统提示声明"来源 URL 与价格无关"（General）；系统提示植入"通常 {Source−零售商} 提供低价"（Designate）（§7）。

模型决定什么、流程固定什么：检索查询由 agent 决定（系统提示要求只写关键词），候选集由 Tavily 返回、顺序固定；选择子集由 agent 决定并立即结束 episode；而满足度判定、配对规则、轮转设计、bootstrap 与显著性、DPO 数据构造与评估的打分方式全部由固定流程控制。是否训练：主干实验（§4、§5、§7）不训练 agent，只做推理与重放；§6 为 3 个开放模型各做 LoRA-DPO 训练（Gemini 因推理成本被排除在 §5.1 之外，§G）。输出：每个来源的 $\tau_s$ 与分类标签、inversion 率、来源互换下的选择率差、DPO 前后的 target 选择率，以及各干预下 Source+ 选择率的变化（pp）。

（教学简化示例，非论文实验）把测量逻辑示意为：两个条目 A、B 都满足"防水、蓝色"但 A 来自 X 站、B 来自 Y 站；只有当"把 A、B 轮流放到每个展示位置后，A 被选中的次数系统性更高"时，$\tau_X>0$ 才成立——而不是"X 的条目恰好排在前面"。

## 4. 解决得怎么样？

#### 4.1 实验设置

任务与数据：三个真实选择任务域——Shopping（WebShop 前 1,500 个目标）、Accommodation（HotelQuEST 全部 214 条 + 572 条地理位置替换变体）、Scholar（ScholarGym 全部 2,536 条查询），共 4,822 个请求；只用其请求，条目集合由 live 搜索动态构造（§2、§C）。

基础模型（12 个 agent 模型，共享同一系统提示）：GPT-5.4-nano、GPT-5.6-Luna、Gemini-3.7-Flash、GLM-5.3-Flash、DeepSeek-v4-Flash-0731、Llama-4-Maverick、Llama-4-Scout、Llama-3.1-8B-Instruct、Tulu-3-8B、Qwen3.5-27B、Qwen3-30B-A3B、Qwen2.5-32B-Instruct（§2）。DPO 实验另用 Qwen3.5-9B、Llama-3.1-8B-Instruct、Tulu-3-8B-SFT（§6.1）；§7 的干预实验只取其中 5 个模型（§7、Table 6）。

基线/对照：inversion 分析用中性来源对 $Inv_{0,0}$ 作基线（§4.2）；来源互换实验的零假设是内容与位置平衡下 $T_+-T_-=0$（§5.2）；DPO 用 pre-DPO（$n=0$）与 Balanced 条件作对照（§6.1）；§7 用无干预的 Base 选择率作对照。值得注意的是：论文未与任何已有的去偏/公平性方法（如提示去偏、重排序去偏）作对比，Table 3/4/5/6 的对照都是本文自建的。

指标：偏好分 $\tau_s$（pp，Eq. 1）；inversion 率 $Inv_{\ell,m}$（少满足者被选中的比例，Eq. 2）；来源互换差值 $T_+-T_-$（pp）；target-source 选择率（%）；干预变化（pp）。公平性预算：所有比较复用同一次搜索轨迹与共享提示；位置通过轮转/顺序平衡控制；解码温度 0（GPT-5.6-Luna 为 1）、seed 4242（支持的模型），但作者声明 API 模型无法保证完全确定性（§B）；swap 与 DPO 实验对内容和顺序做了严格交叉平衡。

各实验回答的问题：§4 回答"偏好是否存在、多大、模型间是否一致"；§5 回答"来源身份本身是否影响选择"；§6 回答"训练能否制造/削弱偏好"；§7 回答"缺失信息与提示能否减轻偏好"；§E–§F 提供估计细节、拟合检查、全量逐模型结果；§I 提供"偏好分与平均满足度正相关"的描述性证据。

#### 4.2 关键结果

偏好普遍存在且模型间方向一致（§4.1，Table 1、Fig. 2）：12 个模型在三个域各自都同时存在 Source+ 与 Source−。Table 1 报告的 144 个模型–来源组合中 110 个被分类为 Source+ 或 Source−，两类的中位偏好分分别为 +15 与 −18 pp。对 12 个高频来源中的 10 个，没有任何模型偏爱另一模型回避的来源（例外是 Amazon 与 eBay，均由 GPT-5.4-nano 给出相反标签，§4.1、Table F.4）。同类来源间也不一致：12/12 模型偏好 Walmart 但仅 2 个偏好同为综合零售的 Target；10 个偏好 Booking.com 而半数回避 Expedia。Fig. 2 把范围扩到每域 20 个高频来源：32 个被多数模型标为 Source+/− 的来源中 27 个在所有模型上 $\tau_s$ 同号；Scholar 中 Source+ 占 14/17，Shopping（6/8）与 Accommodation（6/7）中 Source− 占多数。![按搜索出现频率排序的每域前 20 来源的平均偏好分：点=模型均值，横杠=跨模型范围，颜色=多数标签；Shopping/Accommodation 以 Source−（蓝）为主，Scholar 以 Source+（红）为主（原论文 Figure 2）](/images/dailypaper/2026-10-05/2610.03195_fig2.png) 该图支撑"偏好不是零散噪声而是跨模型的共同结构"这一关键判断，也是 Table 1 之外覆盖面最广的证据。

偏好可压过满足度（§4.2，Fig. 3）：把满足 set 只差一个 requirement 的两个条目配对，inversion 率 $Inv_{+,-}$（少满足者来自 preferred source）的中位数是 68%，反向 $Inv_{-,+}$ 的中位数仅 2%，中性对 $Inv_{0,0}$ 中位数 19%；该顺序在全部模型×域组合中成立（Table F.5 给出各单元数值与 95% bootstrap CI；每单元"仅选一个"的比较数中位数约 2,000）。![inversion 率：蓝=少满足者来自 dispreferred 而更优者来自 preferred（接近 0），灰=双中性来源（中间），红=少满足者来自 preferred（多数远超 50% 虚线）；虚线为 50%（原论文 Figure 3）](/images/dailypaper/2026-10-05/2610.03195_fig3.png) 图中也可见不可忽视的例外与不确定性：Gemini-3.7-Flash 在 Shopping 的 $Inv_{+,-}$ 仅 97%（85–100，仅 39 次比较）、在 Scholar 为 48%（42–53，5,063 次比较，接近 50%）；GPT-5.4-nano 在 Shopping 为 54%（46–62）；Accommodation 中 Gemini 因只标出 2 个 Source+ 来源而没有 $(+,-)$ 对（Table F.5 注）。即"偏好压过满足度"的强度在不同模型×域上差异明显。把两侧分别与中性来源配对（Table F.6、Fig. F.1）：在每个域中多数模型满足 $Inv_{0,-}>Inv_{+,0}$，作者据此认为 dispreferred 侧的效应更大（§4.2）。

来源身份本身影响选择（§5）。隐藏→恢复实验（§5.1，Fig. 4）：恢复显式来源信息（Hidden→Original）使 Source+ 的 $\tau$ 平均升高 5.8 pp、Source− 降低 5.9 pp（跨模型等权平均）；其中大部分升幅在恢复 URL 一步（Hidden→URL-only）就出现——11 个模型中有 9 个在该步完成全部差距扩张的 80% 以上（Gemini 因成本被排除，§G）。![来源信息可见性三档（Hidden→URL-only→Original）下的偏好分 τ：左图 Source+ 单调升高、右图 Source− 单调降低，且大部分变化发生在恢复 URL 一步（原论文 Figure 4）](/images/dailypaper/2026-10-05/2610.03195_fig4.png) 该图的两个面板互为镜像，说明"显示来源"同时放大正负偏好；但它本身只证明"可见性影响偏好强度"，不能证明同一内容的被选概率会随所挂来源变化——后者由互换实验回答。

互换实验（§5.2，Table 3、Table H.1）：在内容与位置完全平衡的 4 臂设计下，12 个模型×3 域的 $T_+-T_-$ 全部为正，且每个模型至少在一个域上 $p<0.01$。Shopping 的效应最大（+19.2 到 +64.7 pp；如 Llama-4-Maverick +64.7、Tulu-3-8B +58.7、Llama-3.1-8B-It +43.7，Table 3）；Accommodation 最小（+2.5 到 +24.1pp，其中 Llama-4-Scout +2.5、Llama-3.1-8B-It +4.1、Gemini +13.3 不显著）；Scholar 居中（+8.8 到 +21.4pp）。对应 Table H.1 的 $T_+$ 显示率 51.2%–82.4%。

训练可制造与削弱偏好（§6，Tables 4–5）：在合成来源上，DPO 前 target 选择率 49.8–51.0%；Balanced（50% 关联）后仍 49.4–51.0%；Aligned（80% 关联）升至 70.1–75.1%；Reversed（20%）降至 24.5–28.5%（± 为三对合成来源间的样本标准差，0.1–2.3pp）。对现实来源：Amazon vs eBay/Etsy/AliExpress 在 DPO 前选择率为 53.7–62.7%；Balanced 后回到 49.7–51.9%，Aligned 后升到 78.0–82.5%，Reversed 后降到 17.7–25.3%。

缺失信息与提示（§7，Table 6）：Base 下 Source+ 条目的选择率为 68.8%（GPT-5.4-nano）、83.9%（Llama-3.1-8B-It）、87.6%（Tulu-3-8B）、95.7%（Llama-4-Maverick）、96.4%（Qwen3.5-27B）。Same Price 在所有 5 个模型上下降（−2.8 到 −28.3pp）；General 提示几乎不变（−1.1 到 +1.3pp）；Designate 在全部模型上下降（−7.4 到 −22.5pp）。

上述结果中"提升小/无效/缺失"的部分：Accommodation 的互换效应普遍只有几个 pp 且部分不显著（Table 3）；Gemini 的 Accommodation 单元没有 $(+,-)$ 对、Shopping 单元比较数仅 39（Table F.5）；Fig. 3 个别单元 bootstrap CI 很宽（如 Accommodation GPT-5.4-nano 的 $Inv_{+,-}$=72%，CI 56–84，n=380）；Table 3 的显著性为未校正 p 值（Table H.1 注明 unadjusted）；所有条件每个（请求, 条件, 顺序）只评估一次，论文未报告多 seed 方差——Table 4/5 的 ± 只覆盖合成来源对间的离散度。

#### 4.3 机制证据

论文把"有效"与"为什么有效"分开做了部分工作。支持机制的证据：（1）互换实验在内容与位置固定下改变来源身份仍改变选择，排除了"条目内容差异"和"位置效应"两个主要替代解释——这是三个实验里最干净的一环（§5.2、§H）；（2）DPO 实验显示"来源–被偏好"的关联率可以单调地制造偏好（50/80/20% → ~50/74/26%，Table 4），且对现实来源的既有偏好也能被 rebalancing 拉回 50% 附近（Table 5），格式与位置被严格平衡（§J），排除了"只是学会了位置选择"的解释；（3）§7 的 Same Price 干预有效而 General 声明无效、Designate 有效，与"缺失信息触发来源先验填充"的假设一致，且 Appendix K 给出 agent 真实的推理文本（如"Result 2 … is from Walmart (more likely to have under-$50 pricing)"、"Home Depot, which is more likely to provide a clear price under $350"）作为定性佐证。

尚不能确立因果的部分：（1）Appendix I 的"来源平均满足度越高、偏好分越高"是描述性相关（top-20 截止下 Pearson r=.778/.598/.677，33 个模型×域全部为正），但论文自己声明该分析"does not establish what their training data contained or why their existing preferences arose"，且相关性随来源数截止（10→30）而变化（Shopping r 从 .823 降到 .577，Accommodation 从 .705 降到 .465，Scholar 反向从 .494 升到 .705），未校正 τ 估计误差与请求重复（§I）。![偏好分 τ 与来源平均请求满足度的散点关系：三行对应每模型每域取前 10/20/30 个高频来源，三列对应三个域；每点为一个模型–来源观测，各面板内为正相关但强度随来源截止数变化（原论文 Figure I.1）](/images/dailypaper/2026-10-05/2610.03195_fig5.png) 这张图是"训练关联假说"的动机证据：它显示现实中"平均更满足请求的来源"也确实更被偏好，因此模型若在训练中见过类似关系，就可能把它学成对来源的捷径——但如作者所言，这仍是相关，不能替代对训练数据的直接审计。（2）§4 的野外偏好中，除来源身份外的其他系统性差异（同一 requirement 向量下 snippet 的信息量、措辞、品牌线索）无法从该设计排除；§5.1 的"恢复 URL 后偏好增强"也与此一致——但隐藏条件下偏好并未消失，2% vs 68% 的 inversion 差距中究竟有多少来自"显示的来源身份"、多少来自与来源相关的未测量内容特征，swap 实验给出的是下界性的证据。（3）DPO 证明的是"可以产生"，不是"现实中就是这样产生的"；12 个受测闭源/开放模型的偏好在训练侧的具体来源（预训练数据、RLHF、蒸馏等）论文未报告也无法从现有实验推断。

#### 4.4 成本与适用范围

训练成本：§J 报告了 DPO 的全部设置（LoRA rank 16、5,000 optimizer updates、有效 batch 8、lr $5\times10^{-6}$、cosine 5% warmup、bf16、单卡训练），但未报告 wall-clock、GPU 小时数或费用；每个 run 用一张 GPU（§J）。推理成本与时延：论文未报告 token 消耗、每次选择的时延或总调用量；仅报告交互预算（每 episode ≤5 个动作、最多 3 次搜索，§B）。人工标注：人类标注者完成 375（Shopping）/375（Accommodation）/100（Scholar）条目的逐要求判定用于 judge 验证（§D），标注成本与薪酬未报告。外部依赖：检索依赖 Tavily Search API；判定依赖 Qwen3.8-27B（部署方式未报告）；GPT-5.4-nano/5.6-Luna 经 OpenAI API、DeepSeek/Gemini/Llama-4/GLM 经 OpenRouter，部分模型用本地 vLLM（§H）——闭源服务依赖明显。存储/系统复杂度：论文未报告。

改善了什么：给出了首个（就本文覆盖范围而言）端到端搜索场景下的来源偏好量化证据，并在受控设置中确立了"显示来源身份→选择变化"的因果链，同时示范了两条可操作性有限的缓解路径。仍未解决：Same Price 的对策现实不可得（信息缺失正是因为拿不到）；Designate 需要预先知道哪个来源是 dispreferred，且作者自述只是"counteracts the preference rather than removing its cause"（§7.2）；General 型声明无效说明"告知模型忽略来源"不是可行手段；论文没有评估这些干预对用户最终效用（买到的东西是否更好）的影响——只测了选择率的移动；跨域/跨时点/跨语言的普适性也未经检验（单一搜索 API 快照、三个英文请求集）。适用边界：结论限定在 2026 年报告时点的 12 个模型、三个域、Tavily 检索环境与受控的 WebShop/ScholarGym 请求集合内。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：野外偏好幅度（68% vs 2%）不能完全归因于"来源身份"，互换实验的效应量与之不匹配

- **原文依据**：§4.2 / Fig. 3 / Table F.5 报告 inversion 差距巨大（中位数 68% vs 2%）；而把来源身份隔离到只剩 URL 字段的互换实验（§5.2 / Table 3）在 Accommodation 域只得到 +2.5 到 +24.1pp、多个单元不显著（Table H.1 中 Scout 51.2%、Llama-3.1 52.0%、Gemini 56.7%（n=15）），显著小于观测层面的差距。requirement-matched 的匹配基于 LLM judge 判定的满足向量（§2、§D），同一向量并不保证 title/snippet 的其他质量维度（信息量、表述）在来源间可比。
- **为什么重要**：这直接影响全文核心定量主张的归因：如果 68/2 大部分来自与来源相关的内容差异而非"看到 URL 就改变主意"，那么"来源偏好让用户拿到更差条目"的叙述需要下调；反之如果野外主要靠标题/正文中的来源名（swap 实验擦除了它们、只留 URL），swap 实验则低估了效应。论文没有做"标题/正文保留来源名"的版本，两种可能的误差方向都未被排除。
- **当前能够得出的判断**：可以确认"显示来源身份能因果地改变选择"（swap 实验设计干净），不能确认观测到的 inversion 幅度全部由来源身份驱动；幅度归因存在混杂（未测量的内容质量差异），且 swap 与野外显示方式不同（来源只出现在 URL 字段）。
- **如何验证或补强**：增加一个"来源信息出现在标题/正文中"的互换变体；对 requirement-matched 对做人类盲评内容质量以审计残余差异；报告 inversion 率随"来源身份可见性"（Hidden/URL-only/Original）的变化——论文已有 Hidden 条件的数据收集管线（§G），把 Eq. 2 直接套用到三档可见性即可给出幅度归因的上/下界。
- **严重程度**：主要问题

#### 质疑：机制链"训练可产生偏好"被写成了近乎"现实偏好就是这样产生的"

- **原文依据**：§6.1 的 DPO 实验只在 3 个开放模型上、用合成来源证明"来源–满足度关联可以制造偏好"；Appendix I 的相关分析是描述性且作者自认不构成归因（"this analysis does not establish what their training data contained or why their existing preferences arose"），相关强度还随来源截止数剧烈变化（r 在 Shopping .823→.577、Scholar .494→.705）；§4 发现的 12 个模型偏好（含多个闭源模型）没有任何训练端证据。
- **为什么重要**：这关系到"本文解释了来源偏好的成因"这一创新表述的边界。目前证据支持的命题是"这是一种可能的产生机制"，而不是"这是现实模型中偏好的实际来源"；摘要与 §1 的措辞（"We test two routes to this preference"）比实验结果可支持的范围更宽。
- **当前能够得出的判断**：受控机制实验的设计与结果扎实（Balanced/Aligned/Reversed 单调、对现实来源同样有效、位置严格平衡），但仅覆盖"can"；现实成因当前材料无法确认。
- **如何验证或补强**：对训练数据可审计的开放模型（如论文用的 Qwen3.5-9B、Llama-3.1、Tulu-3）检查预训练/SFT 数据中来源与质量的关联统计，并检验该统计量能否预测 §4 测得的 $\tau_s$；或对同一模型家族、不同数据配比的检查点做横断比较。
- **严重程度**：主要问题

#### 质疑：缓解实验的可用性与外部效度不足，且缺少与已有去偏方法的对比

- **原文依据**：§7 的干预只在 5 个模型、WebShop 单一域的两候选设置上测试；Same Price 的对策在现实中不可得（作者自己在 §7.2 指出"in practice it is missing because it is unavailable"）；Designate 需要预先知道哪个来源是 dispreferred 且"counteracts the preference rather than removing its cause"（§7.2）；General 声明近乎无效（−1.1 到 +1.3pp）。全文没有任何与已有公平性/去偏方法（如提示去偏、重排序、曝光配额）的对比实验。
- **为什么重要**：论文在 §1 与 §8 把"reducing source preference"作为核心贡献之一（也是应用动机：防止曝光集中与自我强化）。如果可用手段仅剩"注入反向先验"，其现实价值与伦理中立性都要打折扣——Designate 本质上是把另一种来源刻板印象注入 agent，而不是让选择回归内容本身。
- **当前能够得出的判断**：干预实验支持"选择可以被系统提示移动"这一机理性结论，但可用性结论（可部署的缓解方案）证据不足；与已有方法的相对收益完全未知（论文未报告）。
- **如何验证或补强**：在更多域/模型上重复干预；补齐与现有去偏基线的对照；测试不依赖"已知 dispreferred 列表"的提示形式（如强制逐要求核对内容、隐藏来源与要求核对的组合）；并评估干预对用户效用（选中条目的满足度）的实际影响，而不只是选择率移动。
- **严重程度**：主要问题

#### 质疑：测量链条对 LLM judge 与单维评分的依赖，以及显著性报告的稳健性细节

- **原文依据**：满足度由 LLM judge（Qwen3.8-27B）判定，人类验证仅覆盖 375/375/100 条且验证集是"agent 选中的结果"样本（§D）；BT 模型用单一 $\beta_s$ 概括来源，拟合相关仅 r=0.54–0.76（Table E.2）；§5.2 互换实验使用的来源标签取自全量数据的在样本估计（"not estimated out of fold"，§H）；Table H.1 的显著性注明 unadjusted；所有评估每个条件只跑一次、无多 seed 方差，API 模型输出被作者自己声明不能保证确定（§B）；大量来源因出现次数不足被合并或更保守地标为 Source0（§E：1,376 个在 >5% bootstrap 重复中缺席的来源里 1,373 个为 Source0）。
- **为什么重要**：$\tau_s$ 与 inversion 率都是下游统计量，judge 的错误会以非随机方式（如对某些来源的 snippet 风格更易判错）传导；样本内标签可能轻微高估 swap 效应；单 run 与未校正 p 值削弱结论的可复制性预期。
- **当前能够得出的判断**：论文在估计层面比同类工作更规范（聚类 bootstrap、FDR、penalty 敏感性分析、轮转控制），判断为"方法负责但仍有残余风险"；这些细节更可能影响幅度而非方向。
- **如何验证或补强**：对 judge 做规模更大、分层于来源的验证（含未选中条目）；swap 标签改用交叉拟合（out-of-fold）；报告多 seed/多时点的复跑方差；对 Table 3/6 做多重比较校正。
- **严重程度**：次要问题

#### 质疑："更家族内更新的模型偏好更强"等跨模型概括存在混杂，且黑盒模型不可审计

- **原文依据**：§4.1 第三点称 Qwen 与 Llama 家族内更新模型平均 $|\tau_s|$ 更大；但这些模型在规模、训练数据、后训练流程上同时变化，论文未隔离变量；受测的多数模型（GPT、Gemini、GLM、DeepSeek、Llama-4）为闭源或无法审计训练数据的版本，具体 checkpoint 与日期部分来自未来版本号命名（如 GPT-5.4-nano、Gemini-3.7-Flash），可复现性依赖服务端快照。
- **为什么重要**：跨模型比较（谁偏好更强、哪些来源被共同偏爱）是 §4 的主要叙事之一；如果"更新模型更强"来自规模/数据配比而非"版本更新"本身，该观察的解读会变；此外所有偏好都绑定在特定服务时点，外部复现难以对齐。
- **当前能够得出的判断**：论文只做了描述性陈述（"exhibit stronger"），没有因果声明，属于证据强度有限的观察；对方向一致性（多数模型同号）的证据不受此影响，因为那是同批时点内的比较。
- **如何验证或补强**：在固定规模、固定数据配方下做受控缩放/版本对比；公开或标明各服务模型的确切快照版本与访问日期。
- **严重程度**：次要问题

## 6. 审稿式总评

> 作者发现 LLM agent 在端到端网络搜索中对"来源"存在系统性偏好——在控制要求满足度与展示位置后，12 个模型在三个域都同时偏爱与回避特定来源，且少满足一个要求的条目来自 preferred source 时被选率中位数达 68%、反方向仅 2%——因此提出用 Bradley–Terry 评分量化来源偏好、并用隐藏/恢复/互换来源信息的受控实验、合成来源 DPO 训练与缺失信息干预来隔离其作用与缓解路径。实验在 4,822 个请求、12 个模型、三个域的条件下表明：来源身份本身能因果地改变选择（互换实验全正、多数显著），训练关联可以制造或拉回偏好（合成与 Amazon 对照），补全缺失信息与反向先验提示可以减轻偏好；其中"来源身份影响选择"的因果证据较强，但"野外偏好幅度完全由来源身份驱动"与"现实偏好由训练关联产生"仍缺少充分支持。本文最有价值的部分是把一个模糊的公平性担忧做成可重复测量的研究工具，并用多层控制实验把观测、因果与机制分开检验；最大的审稿风险是核心幅度数字（68% vs 2%）的归因依赖 LLM judge 判定的满足度匹配，而来源身份被单独隔离时测得的效应明显更小，以及缓解方案的现实可用性有限。

- **问题定义清晰度**：强。把"来源偏好"与"条目质量/位置"的混淆在 §1–§3 中拆解得很清楚（选择率不足够的原因、匹配与位置控制的设计动机），并给出了边界明确的子问题分解（§1、§3）。
- **创新性证据**：中。度量、因果隔离与训练实验的组合是扎实增量，组件多为现成方法的组合；"首次在端到端搜索中量化来源偏好"的边界依赖本文 related work 的对比，机制链只到"can"（§2、§6.1、§I）。
- **方法可信度**：中。位置轮转、内容固定互换、DPO 关联率三档、聚类 bootstrap+FDR 等设计严谨，接近效应的归因与 judge 依赖仍留残余风险（§3、§5.2、§E、Table E.2）。
- **实验支持力度**：中。覆盖 12 模型×3 域、多样干预且披露了完整提示词；但单一搜索 API 时点、单 run 无多 seed 方差、部分单元样本量小（Gemini 39 次比较）、缓解实验仅 5 模型单域、无既有去偏基线（§B、§D、§7、Table F.5、Table H.1）。
- **可复现性**：中。agent 提示、判定提示、DPO 超参、解码设置与顺序平衡细节均完整给出；但训练数据/代码"将在发表时发布"（当前未发布）、若干服务依赖闭源 API 且输出非确定（§B、§J、Reproducibility statement）。
- **综合阅读价值**：高。对"agent 推荐公平性"与"评测方法论"两个方向都提供了可直接复用的测量工具与实验范式，且对自身证据边界较诚实（§4.2 的例外、§7.2 的局限、§I 的描述性声明）。
