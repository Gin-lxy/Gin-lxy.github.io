## 0. 一句话结论

论文指出自动 harness 优化（AHO）只顾"如何根据反馈更新 harness"，却把"用哪些训练场景产生反馈"在优化前固定，于是把训练场景选择表述为自动课程学习问题，用"失败模式臂 + LLM 学习进度打分 + 自适应 Pull/Draw 探索"的非平稳多臂老虎机实现。在 GAIA2（测试集 300 题）与 Terminal-Bench 2.0（测试集 40 题）上，同一优化器 AutoSaddler、同一 rollout 预算下，测试 Pass@1 分别比固定乱序课程高 4.4 / 7.5 个百分点（59.8 / 80.0），消融显示三个课程组件缺一不可。结论的边界是：证据来自 gpt-5.5 单模型、TB2 仅一次优化运行且测试集仅 40 题，尚未排除优化随机性与评估噪声的贡献，外推到其他模型/优化器/任务分布时证据不足。

## 1. 论文具体想解决什么问题？

**领域一般问题（已有文献的共同设定）。** LLM Agent 的能力不只取决于模型权重，还取决于外部 harness——如何提示 agent、能用哪些工具、运行时如何被控制、监控与纠错（§1）。自动 harness 优化（AHO）因此成为一条独立路线：执行训练场景→从执行轨迹诊断缺陷→打补丁更新 prompt、工具接口或控制逻辑（§2）。按论文 §2 的归类，search-based 方法（如 Meta-Harness、HARBOR）在 harness 实现空间上做演化/贝叶斯搜索，learning-based 方法（如 AutoSaddler）把外部 harness 状态当作"被学习的对象"、用训练 mini-batch 的 rollout 反馈反复更新（不更新权重），GEPA 介于两者之间。这些方法的共同点是：**优化机制（怎么更新）是被研究的对象，而训练场景集合 X_t（拿什么产生反馈）是预先固定的**——要么整训练集，要么优化开始前排好的 mini-batch 顺序（§1、§3，Eq.5 之前的形式化）。

**本文新观察（相对上述一般设定）。** 作者指出：随 harness 演化，训练场景的价值会变化，固定顺序造成两类错配——(i) 未解决的失败可能仍值得优化，却被固定调度"翻篇"；已修复的失败却继续消耗预算；(ii) "重访已知失败"与"评估未见场景"的相对价值本身随时间变化，固定调度无法调节这个平衡（§1）。支撑该判断的证据是一条现象性观察：在固定顺序优化下，训练中观察到的许多失败在最终 harness 中仍未解决（§1 的交叉引用在 HTML 中渲染为 "(3(b))"，对应 Fig. 3(b) 的 failure-to-success 转换率曲线；Appendix G 的 tnxtee 案例也展示了同类现象）。

**作者认为的原因与核心假设。** 作者把原因归为"反馈来源的选择"缺少自适应机制，并援引课程学习/环境设计文献（Graves et al. 2017；Matiisen et al. 2017；POET 等）说明"改变呈现给学习者的数据/任务/环境可以改善学习"（§1）。核心假设由此可表述为：**在固定优化器 O 与固定 rollout 预算 K 下，把 X_t 的选择建模为与 harness 共同演化的课程策略 π，能产出比固定课程更好的最终 harness**（形式化为 §3 的 Eq.5–6：π* = argmax_π E[J(θ̂_π)]）。

**本文实际解决的具体子问题。** 只处理"离线、learning-based AHO"中的课程策略设计，且**刻意不动优化器本身**（§3 明确"hold the optimizer O and its candidate-evaluation procedure fixed"）；在线/测试时适配、权重与 harness 联合优化均不在范围内。

**需要留意的地方。** 论文观察到"固定顺序下失败残留"这一现象，并给出失败模式案例层面的机制解释，但**没有做单独的因果实验**证明失败残留主要由"顺序固定"造成（而不是预算总量、优化器 patch 质量、任务难度分布造成）；作者用"同预算、只改课程"的对照设计间接支持这一归因。

## 2. 创新点是什么？

**一句话概括技术增量：** 把 AHO 中"选哪些训练场景"单列为可学习的课程维度，用一个**臂集合在线增长的**非平稳多臂老虎机来建模——臂不是预定义的任务分组，而是执行后诊断出来的"失败模式"（同一底层缺陷可跨场景复用），臂的优先级由 LLM 按"严重度/可修复性/泛化面/副作用风险"四轴打分并 softmax 采样，另有一个 LLM 控制器在"重访已知臂（Pull）"和"探索未见场景（Draw）"之间做二值决策。相对已有工作，这三个模块都是**新增机制**，但其"课程学习/bandit 选择训练目标"的框架本身是经典思想的迁移。

**(1) 失败模式臂（Failure-Pattern Extractor，§4、Eq.7、Appendix A/B/K 图 14）。**
- 新增了什么：把每个失败先独立抽象为"症状候选" c_t(e)=g_ext(e, δ_t(e))（此阶段不看已有臂集合，作者称是为避免锚定偏差），再对现有臂做三路归一化 A_{t+1}=g_norm(A_t, {c_t(e)})：命中已有原子模式则链接、属于多个模式的组合则多重标注、否则新建臂（Appendix K 图 14）。每个臂维护模式描述、支持场景集 S(a)、以及观察到的 harness/trace/诊断证据；选臂后从 S(a) 采样下一批场景。
- 与最接近方法的差异：AutoSaddler/GEPA 用固定 mini-batch；"类别臂/场景臂"是预先定义的粒度（类别=GAIA2 的任务类别，场景=单题）。失败模式臂是**在线产生、跨场景复用的中间粒度**。
- 证据：替换臂表示（课程程序不变）后，类别臂在 GAIA2/TB2 降 3.0/10.8 pp，场景臂降 3.6/6.7 pp（Table 1 消融行）；机制侧证据是失败命中率（一次迭代采样的 mini-batch 至少含一个未解决失败的场景所占比例）失败模式臂 52.9%/60.4%，高于类别臂 36.4%/30.5%、场景臂 17.6%/36.6%（Appendix G、Fig. 8）。案例研究（tnxtee、4bytkx）展示同一臂被重访后对失败补丁做二次修正（Appendix G 图 6/7）。
- 移除后会怎样：如上，退化为类别/场景粒度，TB2 上损失最大（-10.8 pp）。

**(2) 自适应臂优先级（Arm Prioritizer，§4、Eq.8–10、Appendix K 图 15）。**
- 新增了什么：用 LLM 会话对每个已实例化臂估计"学习进度"分数 φ_t(a)∈[0,1]，输入是当前 harness、臂的完整拉取历史（patch 意图、dev 集影响、逐场景反思）与四种因素；prompt 里明确 φ=(severity+fixability+breadth+(1−side_effect))/4，再按 q_t(a) ∝ exp(φ_t(a)/τ_sel) 采样（τ_sel=0.15，Appendix A）。分数每次选臂时基于最新历史重算，允许优先级随 harness 演化。
- 与最接近方法的差异：这是把课程学习里的"学习进度优先"（Graves et al. 2017 等）搬到 harness 优化，但论文强调 AHO 中目标没有直接 loss 信号，只能由 LLM 从证据推断（§2）。
- 证据：去掉它（所有臂同分）后 GAIA2/TB2 降 4.5/7.5 pp（Table 1）；替换为 EMA 失败残留率打分（TSCL 风格，η=0.1）得 56.7%（比 ActiveSaddler 低 3.1 pp，Appendix D Table 5）；机制侧，Fig. 3(a) 显示拉取概率质量持续在臂间转移；Fig. 11/12（Appendix I）显示成功率高的臂仅占 26.2% 概率质量（均匀分配下应为 68.6%，即 0.38×），含未解决场景的 11 个臂占 73.8%（2.35×），同模式在新场景中复现会使臂概率回升（P8 +4.8 pp、P10 +9.4 pp）。
- 移除后会怎样：见上，且 Fig. 3(b) 的失败→成功转换率下降。

**(3) 自适应探索控制（Exploration Controller，§4、Eq.11、Appendix K 图 16）。**
- 新增了什么：每一步用一个 LLM 会话在 {unseen, arm} 间做二值决策（无固定公式/阈值，prompt 明确禁止机械地用 |A_t|、|U_t| 等单一统计量决策）；边界条件固定（臂集空→unseen；未seen池空→arm）。另外增加了"回归再发现"规则：所有训练场景探索完且所有臂访问过后，先前成功且未实例化为臂的场景重新进入 unseen 池，若此时失败则照常走抽取流程，从而在不全量重跑的情况下发现回归。
- 与最接近方法的差异：Task-CoEvolve/HarnessLens 在**评估侧**（候选修改已提出之后）选验证任务；ActiveSaddler 在**训练侧**、贯穿整个优化过程决定证据来源（§2 明确这一区分）。
- 证据：替换为"每 5 次迭代探索一次"的固定调度后 GAIA2/TB2 降 4.5/8.3 pp（Table 1）；替换为 UCB-AIR 计数规则（α=0.6）得 55.6%，仅比固定调度高 0.3 pp、比 ActiveSaddler 低 4.2 pp（Appendix D Table 5）。机制侧：GAIA2 上 Draw 率从前半段 44% 降到后半段 20%；Pull 决策时未解决臂数是 Draw 时的 2.0×（GAIA2：1.62 vs 0.81）与 6.9×（TB2：0.76 vs 0.11），固定调度则接近 1（0.8×/1.3×）（§5.3 RQ3、Appendix J、Fig. 13）。
- 移除后会怎样：见上。

**(4) 问题表述本身（§1、§3、Eq.5–6）。** 把"哪些训练场景产生反馈"从固定超参提升为可学习的课程策略，是本文明面上的概念贡献。按规范需要说明：根据本文 related work 和实验对比，只能确认作者声称的差异（训练侧、贯穿优化、目标动态实例化）；同期最接近的 CoEvolve（权重侧生成任务）、Task-CoEvolve/HarnessLens（评估侧选任务）没有同台实验对比，"是否首次提出"还需要更完整的文献检索。

**不算创新的部分：** 没有新模型、新数据集或新评测指标；AutoSaddler 优化器、GAIA2/TB2 基准、GitHub Copilot SDK（GC-SDK）都是现成组件；Pattern Registry + 命令行接口（Table 2）是必要但偏工程的基础设施。论文的"三条 contribution"（§1 末）与上述 (1)(2)(3)(4) 对应。

## 3. 作者如何解决？

**直觉。** 优化一次 harness 的预算大约只够执行 3 个场景（Appendix A：每轮 ≤3 个场景），所以"下一轮拿什么场景去练"本身就是稀缺资源分配问题。既然失败是诊断出来的、且同一缺陷会跨场景复发，那么**把"尚未修好的缺陷"而不是"题目"当作优化目标**，在"再练一遍已知缺陷（Pull）"和"测一批没见过的场景找新缺陷（Draw）"之间动态取舍，就能把预算花在边际收益最高的地方。

**运行流程（§4 Workflow Overview、Appendix B Algorithm 1/2）。**
- 输入：初始 harness H_0（GAIA2 用默认 ReAct agent，TB2 用 Terminus 2）、训练集 D_train、dev 集 D_dev、rollout 预算 K=10(|D_train|+|D_dev|)（GAIA2 1400、TB2 490）、固定优化器 O、臂选择温度 τ_sel=0.15。
- 每轮迭代：
  1. **探索决策**（模型决定，Eq.11）：d_t=g_explore(H_t, A_t, U_t, I_<t)∈{unseen, arm}；边界条件与"回归再发现"由固定流程处理（Algorithm 1 第 7–18 行）。
  2. **选批**：若 Draw，从未见池 U_t 无放回采样 X_t 并从 U_t 移除；若 Pull，Arm Prioritizer 对每个臂用 LLM 打分（Eq.8），softmax（Eq.9）后采样臂 a_t（Eq.10），再从该臂支持场景集采样 X_t。
  3. **执行与更新**（固定流程，优化器决定如何改 harness）：H_t 在 X_t 上执行得到 E_t，交给 O。以 AutoSaddler 实例化（Algorithm 2）为例：诊断失败→生成结构化 patch→在 X_t 上复跑候选 H'_t→若本批改善则额外在 D_dev 上评估→Reflection 记录 fixed/regressed/still-failing/still-passing 并更新 EvoDAG→Evolve 得到 H_{t+1}。**所有任务级执行（包括为评估候选 harness 的执行）都计入预算 K**（Appendix B）。
  4. **失败模式抽取**（模型决定 + 固定流程）：F_t=补丁前失败 ∪ 补丁后仍失败/新失败，两阶段抽取与归一化（Eq.7），更新臂集合与支持场景集。
  5. 循环至预算耗尽；按 dev 集性能选出最终 harness（dev 只用于选择与回归检查，test 留作最终评估）。
- **哪些由模型决定、哪些是固定流程**：三个课程决策（抽取/打分/探索）由 GC-SDK 的 LLM 会话完成；诊断、补丁、候选评估、预算计数、边界规则、软max采样规则是固定流程。整个方法**不训练任何权重**（training-free 的外部状态优化：被优化的 θ 是 prompts/工具接口/控制逻辑）。
- 输出：一份优化后的 harness（可执行、可迁移到任何被该 harness 包裹的模型上——实现上以 worktree/commit 形式管理，见 Appendix K 中出现的 `git diff`、`evo-dag` 等命令）。

**关键公式与设计假设。** Eq.7 的"先抽取后归一化"假设：症状抽取不锚定已有臂，能减少归并偏差；但这也意味着臂集合的正确性完全依赖 LLM 的标签一致性（Appendix K 用 link/compose/new 三路判定，并给出"不过度合并/不过度拆分"的指令）。Eq.8–10 假设：臂的价值可由四个可读因素线性平均后作为"学习进度"代理；τ_sel 控制探索强度，论文取 0.15（偏贪心）。Eq.11 假设：探索/利用的取舍靠 LLM 对全上下文的整体判断，没有显式的不确定性估计。

**教学简化示例（非论文实验）：** 假设某 agent 在三个不同场景里都失败——"没打电话确认就直接订餐厅"、"没核对同名联系人就发会议邀请"、"没澄清日期歧义就改日程"。场景不同，但底层缺陷是同一个"歧义未澄清即执行写操作"，失败模式臂会把三条失败归入一个臂；下次 Pull 时抽到的可能是第四个同类场景，而不是重复其中任何一题。论文真实的对应例子是 GAIA2 的 tnxtee（Appendix G 图 6）：agent 发出的活动开始时间确认邮件缺少结尾语和真实姓名署名，这条失败被抽成臂；第 3 轮的补丁加的 executor hook 只对单行草稿生效、未触发；因为臂仍然存在，第 5 轮把触发条件扩展到多行回复后才修好——若无该臂，这一失败会被别的成功场景掩盖。

## 4. 解决得怎么样？

### 4.1 实验设置

- **基准与基础 harness**：GAIA2（模拟手机环境的通用助理任务，默认 ReAct agent 为 base harness）与 Terminal-Bench 2.0（89 个终端任务：系统管理/机器学习/网络安全，Terminus 2 为 base harness）（§5.1）。
- **数据划分**（Table 3）：GAIA2 按 Universe（人格）做 OOD 划分，train=Universe 29（75 题）、dev=Universe 30（65 题）、test=Universe 21/22/27（107+112+81=300 题）；TB2 无自然分组，随机划分 30/19/40。
- **模型与预算**：任务 agent 与优化器都用 gpt-5.5（推理强度：任务 agent=medium，GC-SDK 优化器会话=xhigh）；预算 K=10(|D_train|+|D_dev|)，即 GAIA2 1400 次 rollout、TB2 490 次；每轮最多 3 个场景；τ_sel=0.15（§5.1、Appendix A）。
- **基线**：GEPA、Meta-Harness、AutoSaddler（无显式课程）；另加两种"按基础 harness 在训练集上 5 次评估的准确率排序"的固定 easy-to-hard 课程（类别级、场景级）；手工 harness Terminus-KIRA 仅作参考行（TB2 表内）。
- **指标与协议**：test Pass@1，3 次测试执行取均值 ± 标准差；最终 harness 按 dev 性能选择（§5.1）。
- **各实验回答什么**：主表（Table 1）回答"课程自适应是否有效"；RQ1–RQ3 消融（Table 1 消融行 + Appendix G/I/J）回答三个组件各自的作用；Appendix C 回答优化随机性下的稳健性（GAIA2 二次运行）；Appendix D 对比非 LLM 替代策略；Appendix E 回答"换优化器是否仍有效"（GEPA）；Appendix F 回答成本。

### 4.2 关键结果

- **主结果（Table 1）**：GAIA2 test Pass@1 = **59.8 ± 1.0**，对比 AutoSaddler 55.4 ± 1.2（+4.4 pp，论文 §5.2 称其为"固定随机洗牌场景顺序"）、类别顺序 55.9 ± 1.3、场景顺序 55.7 ± 1.2、GEPA 54.2 ± 2.2、Meta-Harness 54.2 ± 1.2、默认 agent 53.6 ± 1.1。TB2 = **80.0 ± 2.5**，对比 AutoSaddler 72.5 ± 0.0（+7.5 pp）、场景顺序 73.3 ± 1.4、类别顺序 70.8 ± 1.4、Meta-Harness 66.7 ± 5.2、GEPA 65.8 ± 5.2、手工 Terminus-KIRA 69.2 ± 3.8、Terminus 2 64.2 ± 2.9。
- **提升不均匀**：GAIA2 上固定类别课程（55.9）本就略高于 AutoSaddler（55.4），说明"固定课程差"并非普遍成立；主要差距出现在 TB2（类别顺序比 AutoSaddler 低 1.7 pp）。TB2 上 AutoSaddler 的 3 次测试执行方差为 0（72.5 ± 0.0），提示 40 题测试集对 harness 差异的分辨力可能有限。
- **消融（Table 1，括号为相对 ActiveSaddler 的降幅）**：类别臂 56.8 ± 0.8（−3.0）/ 69.2 ± 2.9（−10.8）；场景臂 56.2 ± 0.2（−3.6）/ 73.3 ± 3.8（−6.7）；去 Arm Prioritizer 55.3 ± 2.1（−4.5）/ 72.5 ± 2.5（−7.5）；去 Exploration Controller 55.3 ± 0.9（−4.5）/ 71.7 ± 1.4（−8.3）。四个消融变体在 GAIA2 上都落到 AutoSaddler 水平（≈55.3–56.8），没有出现"部分收益"，说明论文没有报告组件间的收益分解。
- **稳健性与迁移**：GAIA2 第二次独立优化运行得 61.6 ± 2.9（首次 59.8 ± 1.0），两次均超过全部固定课程基线 3.9–4.4 / 5.0–5.7 pp（Appendix C，Table 4）。把课程层套到 GEPA 上：GAIA2 平均 54.2%→57.2%（+3.0 pp；Universe 21/22/27 分别 56.4→58.6、50.0→54.2、57.2→59.7，Appendix E，Table 6）。TB2 未报告第二次优化运行。
- **替代策略**：EMA 打分 56.7%（−3.1）、UCB-AIR 探索 55.6%（−4.2）（Appendix D，Table 5）。
- **机制指标的失败侧**：类别臂/场景臂并非无效（场景臂在 TB2 达 73.3，甚至高于 AutoSaddler），论文用命中率与案例来解释失败模式臂为何更优（见 4.3）。
- **成本（Appendix F，Table 7/8）**：优化器侧每个 patch 的开销，GAIA2 上 ActiveSaddler $11.44 / 1581 s / 142.2 次 LLM 调用，对比 AutoSaddler $7.87 / 943 s / 95.4 次；TB2 为 $11.37 vs $6.77。单次任务 rollout 成本各方法相当（GAIA2 ≈15–19 次调用、200–232 s）。端到端（优化器+任务执行）成本-精度（Fig. 5、§5.2）：GAIA2 达到 dev 58.5% 需 $298，AutoSaddler 需 $1360、类别顺序 $673、场景顺序 $1698 且只到 56.9%；TB2 达到 78.9% 需 $128，AutoSaddler $220、场景顺序 $363、类别顺序 $548 且只到 73.7%。

![Figure 1：优化效率（上：GAIA2，下：Terminal-Bench 2.0）](/images/dailypaper/2026-10-02/2610.00906_fig1.png)
- **Fig. 1（上）**是主结果的效率视角：纵轴为"best-so-far dev 准确率"，横轴为累计执行的任务场景数（即预算消耗）。看点是 ActiveSaddler（青色）在相同预算下阶梯式上升更早、更高——GAIA2 在约 900 个场景内达到 63% 左右的最佳 dev 准确率，而 AutoSaddler（深蓝）与两种难度排序（紫/红）到 1400 个场景仍在 55–58% 区间；灰色虚线是一条参考水平线（与基线水平相当）。**(下)** 的 TB2 曲线形态相同（ActiveSaddler 在约 180 个场景内升到 84%，其余方法到 490 个场景预算耗尽时仍在 65–79%）。这张图回答"同样的执行预算花在哪里更值"，也解释了为什么论文要用端到端成本曲线（Fig. 5）补一刀。

### 4.3 机制证据

- **只说明"有效"的部分**：Table 1 的消融证明三个组件与最终 test Pass@1 有因果关联（在同预算下移除即下降），这是较强的"有效性"证据。
- **说明"为什么有效"的部分**：Fig. 8 的失败命中率（52.9/60.4 vs 36.4/30.5 与 17.6/36.6）说明失败模式臂把更多轮次花在"当前 harness 仍失败"的场景上；Fig. 11/12 说明打分会随证据重分配概率质量（成功臂 0.38× 均匀份额、未解决臂 2.35×；34 次拉取选中 19/35 个臂，中位优先级排名第 3，62% 来自前 3）；Fig. 13 说明 Pull/Draw 与未解决臂数量相关（2.0×/6.9×）。Appendix G 的两个案例（tnxtee：同一臂两次迭代才修好；4bytkx：补丁生效后又丢失、场景臂版本 10 多轮未重访）提供了机制层面的叙事。

![Figure 3：自适应臂打分的效果（上：拉取概率质量演化；下：失败→成功转换率）](/images/dailypaper/2026-10-02/2610.00906_fig3.png)
- **Fig. 3（上）**是 GAIA2 上一次运行里各失败模式臂的"拉取概率质量"堆叠图（纵轴为该臂被下一轮选中的概率）：颜色带随时间此起彼伏、没有固定在少数几个臂上，说明优先级确实随 harness 与证据变化在重新分配——这是 RQ2 的核心机制图。**(下)** 是失败→成功转换率（优化中观察到的失败场景最终被修好的比例）：ActiveSaddler 最高，其后是去掉打分器的变体与 AutoSaddler，对应 Table 1 中 −4.5/−7.5 pp 的消融结论。两张图合起来把"打分器有效"（结果）推进到"打分器通过重排优先级让更多已观察失败被修复"（机制）。

![Figure 8：不同臂表示下的失败命中率](/images/dailypaper/2026-10-02/2610.00906_fig8.png)
- **Fig. 8** 是 RQ1 的机制量化：纵轴"failure hit rate"指一次迭代采样的 mini-batch 中至少包含一个"未解决失败场景"的比例（预算同为 1400/490）。失败模式臂 52.9%/60.4% 明显高于类别臂 36.4%/30.5% 与场景臂 17.6%/36.6%，直接支撑"臂的粒度决定预算打在未解决弱点上的密度"这一解释；它也是 Table 1 中类别/场景臂消融（GAIA2 −3.0/−3.6 pp、TB2 −10.8/−6.7 pp）的机制侧证据。
- **替代解释能否排除**：(i) 预算公平性——论文把"所有任务级执行"计入 K，且各方法每轮 ≤3 场景，这一点口径清楚；但**优化器侧 LLM 开销不计入 K**（ActiveSaddler 每 patch 多 ~50% 花费与更多调用），所以"更好课程"与"每轮更强的优化器计算"没有被完全解耦；Appendix F 的端到端曲线（同花费下仍更优）是对该质疑的部分回应，但并非等价计算量的对照实验。(ii) 评估侧选择效应——最终 harness 由 dev 选择、test 独立报告，主表不受 dev 过拟合直接影响；但 TB2 单次运行 + 40 题的组合使 test 数字本身噪声较大。(iii) 打分机制——没有独立校准实验（例如 LLM 分数与"后续实际是否修好/带来多少 test/dev 提升"的相关性），"为什么有效"的解释有相当部分来自 LLM 自己在 prompt 里的 rationale 与作者的案例阅读，属于**相关性证据**而非因果证明。

### 4.4 成本与适用范围

- **已报告的成本**：优化器侧时间/美元/LLM 调用/token（Table 7）、每次 rollout 成本（Table 8）、端到端成本-精度曲线（Fig. 5）；patch 的生成/拒绝/接受计数（GAIA2：37 生成/18 拒绝/19 接受；TB2：35/17/18）。

- **依赖**：gpt-5.5 与 GitHub Copilot SDK（GC-SDK）、GAIA2 模拟环境与 TB2 终端环境、以 worktree/git/EvoDAG 为中心的工程栈（Appendix K 可见 `evo-dag`、`git diff`、`.claude/skills/<name>/SKILL.md` 等要求）；SKILL.md 声称放在匿名仓库，但 HTML 版可复现性声明中找不到链接。项目页（本次核对）给出代码链接 https://github.com/microsoft/AutoSaddler/tree/feat/activesaddler 。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：主要结论的统计稳健性不足——TB2 只有一次优化运行、测试集仅 40 题、无显著性检验

- **原文依据**：Table 1（TB2 Test-Split (40)，ActiveSaddler 80.0 ± 2.5 vs AutoSaddler 72.5 ± 0.0）；Appendix C 只对 GAIA2 做了两次独立优化运行，TB2 无对应实验；全文报告的是 3 次测试执行的标准差，没有优化运行间方差、置信区间或显著性检验；TB2 上 AutoSaddler 的 std=0.0 提示 40 题上 3 次重复执行可能高度相同。
- **为什么重要**：+7.5 pp 在 40 题上约等于 3 道题，若优化运行间波动与 GAIA2 观察到的量级（Run1 59.8、Run2 61.6，差 1.8 pp）相当或更大，则 TB2 的最大卖点可能落在噪声范围内；这直接影响结论范围与"超过手工 harness（Terminus-KIRA 69.2）"这类论断。
- **当前能够得出的判断**：TB2 的结果是单次运行的观测，不能确认可复现；GAIA2 上两次运行一致更支持该基准的结论。
- **如何验证或补强**：TB2 上补 3–5 次独立优化运行并报告跨运行方差；报告配对显著性检验（如按题配对）；用更大测试集或多次采样降低评估噪声。
- **严重程度**：主要问题。

#### 质疑：课程收益与额外优化器计算未完全解耦，"同预算"只对任务 rollout 成立

- **原文依据**：Appendix B 明确所有任务级执行计入 K，但 Appendix F Table 7 显示 ActiveSaddler 每个 patch 的成本 $11.44 / 142.2 次 LLM 调用 vs AutoSaddler $7.87 / 95.4（GAIA2），TB2 $11.37 vs $6.77；Table 1 中四个消融变体全部落到 AutoSaddler 水平，没有"部分组件带来部分收益"的证据。
- **为什么重要**：若收益的一部分来自"每轮更强的诊断/打分计算"，则"自适应课程"这一归因被稀释；消融中三组件缺一不可也可能是共同的实现依赖（如都依赖 Pattern Registry 的质量）而非独立机制。
- **当前能够得出的判断**：论文用端到端成本-精度曲线（Fig. 5）给出了"同花费下仍更优"的反证，但没有"等优化器 LLM 调用数""等 wall-clock"的对照实验；组件间独立性未被隔离。
- **如何验证或补强**：在固定优化器侧 token/调用预算下重跑；做 2×2 组件组合（仅抽取、仅打分、仅探索）的收益分解；报告不改变课程内容、只增加打分调用次数的对照。
- **严重程度**：主要问题。

#### 质疑：课程决策依赖同一 LLM 黑箱，缺少判分校准与独立验证

- **原文依据**：三个课程决策（失败抽取、臂打分、探索决策）都由 GC-SDK LLM 会话完成；φ 由 severity/fixability/breadth/side-effect 四轴取平均（Appendix K 图 15），但四轴没有与人评或后续真实收益做过相关性/校准分析；"为什么有效"的解释主要来自 Fig. 3(b)、Fig. 8、Fig. 11–13 的统计与案例，属于相关性证据；所有环节共用同一模型（gpt-5.5）与同一系统栈，存在自我确认风险。
- **为什么重要**：若判分与"实际学习进度"脱钩，方法退化为昂贵的随机课程；论文也承认 AHO 中"诊断出的缺陷没有直接 loss 信号"，这让校准问题更关键。此外，跨模型（不同 LLM 打分会否一致）完全未验证。
- **当前能够得出的判断**：现有证据支持"该实现整体有效"，不足以支持"四因素打分确实是有效的学习进度估计"这一更强的机制主张。
- **如何验证或补强**：报告 LLM 分数与后续实际 dev 提升的相关性；做打分模型的替换实验（不同厂商模型）；人工评估抽取的失败模式的一致性（标注者间一致性）。
- **严重程度**：主要问题。

#### 质疑：基线强度与固定课程的构造细节影响公平性判断

- **原文依据**：Table 1 的"AutoSaddler"行未标注其默认场景顺序；§5.2 把对照描述为"fixed randomly shuffled scenario order"，但 AutoSaddler 原论文的默认设定是否即随机洗牌、洗牌种子是否多次平均，未在本文报告；固定课程由 base harness 在训练集上 5 次评估的类别/场景准确率排序得到（§5.1），该难度信号本身噪声大且未报告排序稳定性；同期任务选择/课程类方法（CoEvolve、Task-CoEvolve、HarnessLens）只在 related work 讨论、未同台实验。
- **为什么重要**："课程学习 vs 固定顺序"的结论强度取决于固定顺序的强度；若 AutoSaddler 默认顺序本就是一个较弱的调度，+4.4/+7.5 pp 的解读需要更谨慎。
- **当前能够得出的判断**：可确认比较对象是"同一优化器的固定随机洗牌顺序"与两种难度排序；无法确认这些顺序是否为该优化器的最优固定调度（未报告种子平均或多顺序对照）。
- **如何验证或补强**：报告多种随机顺序的均值±方差作为基线；给出按种子平均的 AutoSaddler 曲线；加入"最简单的非课程强基线"（如按最近失败频率轮转）。
- **严重程度**：次要问题（因论文仍报告了难度排序与 GEPA/EMA/UCB 等多重对照）。

#### 质疑：结论外推范围窄，且"自动 harness 超过手工 harness"未被分析

- **原文依据**：仅 2 个基准、1 个主模型（gpt-5.5）、1 个主优化器（ActiveSaddler-on-AutoSaddler，另有 GEPA 变体但只在 GAIA2，Appendix E）；TB2 上自动优化结果（80.0）明显超过手工 Terminus-KIRA（69.2）与 Terminus 2（64.2），作者未讨论"40 题测试集 + 自动 harness 反超手工"可能的评估设定问题（例如测试集与训练分布重叠、环境不稳定）；GAIA2 的 test 由 3 个 held-out universe 组成，OOD 设计较好但仍属同一模拟器。
- **为什么重要**：结论若被读成"课程学习普遍提升 agent harness"，超出了证据覆盖；读者需要明确边界是"该模型、该优化器、这两个基准、离线设定"。
- **当前能够得出的判断**：结论仅在这两个基准、gpt-5.5、离线 AHO 设定下成立；更多模型/优化器/环境的证据缺失。
- **如何验证或补强**：在其他模型族（开源模型、不同规模）与其他基准（如 SWE-bench 类长程任务）上复现；报告 TB2 测试任务的来源与潜在污染检查。
- **严重程度**：次要问题。

## 6. 审稿式总评

> 作者发现自动 harness 优化把"用哪些训练场景产生反馈"在优化前固定死，会让未解决的失败被过早放弃、已修复的问题继续占用预算，因此把训练场景选择表述为自动课程学习问题，提出 ActiveSaddler：以在线实例化的失败模式为臂的非平稳 bandit，配合 LLM 四轴打分与自适应的 Pull/Draw 探索，让课程与 harness 共同演化。实验在 GAIA2 与 Terminal-Bench 2.0 上、同一 AutoSaddler 优化器与同一 rollout 预算下表明，测试 Pass@1 分别比固定乱序课程高 4.4 与 7.5 个百分点（59.8 / 80.0），消融显示三个课程组件缺一不可，并且失败模式臂在"失败命中率"这一机制指标上明显优于类别/场景臂，端到端成本-精度也更好；其中"失败模式臂 + 失败命中率 + 案例重访"这条证据链较强，但 TB2 仅一次优化运行、测试集仅 40 题、无显著性检验，且课程收益与额外优化器计算没有完全解耦，LLM 打分也缺少校准与跨模型验证。本文最有价值的部分是把"反馈来源"单列为可优化维度并给出一个可运行、可消融、成本可核算的完整系统；最大的审稿风险是主要增益建立在少量运行与单一模型栈上，跨设置的可复现性尚未证明。

- **问题定义清晰度**：强。§3 用 Eq.1–6 把 harness 优化与课程选择分开形式化，明确冻结优化器只改 X_t，边界（离线、learning-based、固定预算）写得很清楚。
- **创新性证据**：中。失败模式臂是有实质内容的机制并被消融与机制指标支持，但整体框架是经典课程学习/bandit 思想的迁移，最接近的同期方法未同台对比，"首次提出"需更完整检索。
