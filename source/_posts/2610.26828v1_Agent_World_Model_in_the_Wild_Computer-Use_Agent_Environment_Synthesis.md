## 0. 一句话结论

WildAWM 用开源模型把一个“个人电脑”拆成可逐日合成、可重置、可验证的 GUI/MCP/CLI 世界，再用五道执行式质量门筛出 341 个跨界面长时程任务；在两个 Qwen 模型、8 个分布外（out-of-distribution, OOD）基准上确实观察到平均 +8.21 与 +10.58 个百分点的提升，但其中有多少来自合成世界本身、多少来自对 GLM-5.2 教师轨迹的监督微调（supervised fine-tuning, SFT）蒸馏，当前实验还不足以完全分开。

## 1. 论文具体想解决什么问题？

这篇论文要解决的不是“怎样让模型更会点鼠标”，而是“训练通用计算机使用智能体（computer-use agents, CUAs）所需的环境从哪里来”。论文开篇把当前趋势概括为：LLM 智能体正从“向人类数据学习”转向“在与世界交互中学习”，因此环境供给成为关键瓶颈（§1）。真实世界训练有三类麻烦：状态难以重置、在线服务会随时间变化、探索动作可能产生真实后果；手工搭建环境虽然可控、可验证，但成本高、难扩展；于是合成环境成为一条看起来可行的中间路线（§1）。

CUAs 的特殊性在于，它们在一个完整的个人电脑上工作：可以操作图形用户界面（graphical user interface, GUI），可以调用模型上下文协议（model context protocol, MCP）服务，也可以在命令行界面（command-line interface, CLI）里写脚本、读写本地文件。一个任务可能同时需要这三种接口，因此“选哪个接口、如何在接口之间传递状态”本身就是能力的一部分（§1）。但现有合成管线通常只覆盖一种交互方式：有的做浏览器环境，有的做工具调用，有的做终端工作流；已有的 CUA 合成工作又大多以 GUI 为中心（Table 1、§2）。这些环境往往是单应用、单接口、浅状态的：任务不需要跨应用协调，也不依赖前几天的历史记录。

论文把这种差距归纳为三个反复出现的问题：任务是否可解（solvability）、任务是否足够难（difficulty）、验证器是否可靠（verifier reliability）。作者认为，现有方法常见的隐含假设是“前沿模型能解，所以任务有效”，但前沿模型也会犯错；反过来，如果所有模型都解不出，也不能证明任务可解。验证器如果过于严格或过于宽松，就会把失败轨迹当成成功，或者把合理解法判错（§1、§3.2）。这三件事共同决定了合成数据能不能用于强化学习。

这里需要区分三层问题。第一层是领域早已存在的一般问题：可执行环境稀缺、仿真到现实的迁移、可验证奖励的设计。第二层是本文提出的新观察或新框架：真实计算机使用是“跨接口、带历史”的，而现有合成管线是“单接口、单应用”的；作者进一步主张，质量控制的瓶颈不只是“生成更多任务”，而是“用执行证据证明任务可解、够难、验证器可靠”。第三层是本文实际解决的子问题：搭一条从人物设定（persona）到多日世界状态、再到跨智能体界面（cross-agent interface, XAI）任务和验证器的流水线，发布 341 个环境—任务对，并在 8 个 OOD 基准上训练和评测两个 Qwen 模型。需要说明的是，第二层更像基于 Table 1 和 related work 的设计判断，而不是论文通过统计测量得到的新现象；论文没有报告“现有单接口管线在跨界面任务上的失败率”这类对照数据。

作者给出的因果解释是：单应用、单接口的世界无法产生必须跨界面协调的任务；浅状态无法产生依赖历史的任务；缺少执行证据则无法判断任务难度和验证器质量。因此他们假设：用人物设定驱动多日累积世界，强制任务使用三种接口，再用多道执行式质量门过滤，就能得到“可解、够难、可验证”的训练数据；只在这些合成世界里训练，能力可以迁移到未见过的网页、claw 类和计算机使用任务；而且整个合成过程可以只用开源模型完成（§1、§3）。这条因果链的每一环都需要证据：世界设计是否真的产生跨界面行为，质量门是否真的提高数据质量，训练是否真的带来 OOD 迁移，开源合成是否与闭源合成等价。论文对后三环给了实验，但第一环和“闭源对照”仍然是薄弱处。

## 2. 创新点是什么？

真正的技术增量不是某个新基础模型，而是把“个人电脑世界”当成可合成、可验证、可重置的训练数据单元：人物设定驱动多日状态累积，三界面任务逼迫跨接口协调，执行证据而不是模型自述来过滤任务和验证器。具体可以拆成四点。

第一，**多日累积的跨界面个人电脑世界合成**。WildAWM 不是为每个任务临时拼一个应用，而是从人物设定出发，逐日生成日计划，再用共享的事件技能库把计划落地成数据库、网站和本地文件的确定性增量，形成可重放的 world state（世界状态）$W(c,d)$（§3.1）。与 Table 1 中的 AWM、WebArena-Infinity、Gym-Anything、TMax、Synth. Computers、CUA-Gym、CUA-Universe 相比，差异在于同一个世界同时暴露 GUI、MCP 和 CLI，并且状态跨天累积；这更接近“集成的组合”，而不是单点算法发明。证据指向 §4.2 的环境规模/多样性统计与 §4.3 的行为分析。

第二，**五道执行式质量门与反事实探测**。每条任务由 18 个模型—运行框架组合跑 6 条轨迹，再用程序化验证器、LLM 裁判和 agent 裁判三层判断，最后过“裁判一致性、初始不满足、任务可解、任务难度、反事实探测”五道门（§3.2）。与常见的启发式过滤或“强模型能解即可”相比，这套协议把“可解性、难度、验证器可靠性”拆成可执行检查；其中反事实探测利用 LLM 的谄媚（sycophancy）倾向，故意给出相反结论，看裁判是否仍能坚持证据。证据指向 §4.2 的 Table 7 与 §4.3 的机制讨论。

第三，**全开源合成与 341 个环境—任务对**。合成侧使用 GLM-5.2、DeepSeek-V4-Flash、MiniMax-M3 三个开源模型，不依赖专有前沿模型；最终发布 341 个环境—任务对、640 个世界状态和 83 个可复用的世界合成技能（Table 1、Table 2、Table 4）。与依赖 Opus、GPT 系列做合成的管线相比，这降低了复现门槛，也让“开源模型能否合成高质量环境”成为一个可检验的主张。证据指向 §4.2 的合成质量统计与 §4.4 的成本/适用范围。

第四，**面向长时程 CUA 的训练配方**。先用 GLM-5.2 的成功轨迹做 SFT 冷启动，再用 GRPO 做在线强化学习（reinforcement learning, RL），奖励由“任务是否完成”与“验证器检查清单的部分分”组成，并加入格式惩罚、自适应 rollout 和跨上下文压缩的分段训练（§3.3、Appendix A.5、A.6）。与原始 GRPO 相比，这些改动分别针对长时程稀疏奖励、零方差组和上下文压缩导致的因果链断裂；属于已有组件（GRPO、DAPO 式自适应采样、分段损失）的组合与工程化。证据指向 §4.2 的 Table 8 与 §4.3 的行为分析。

这些点大多不是从零发明：人物设定、技能库、程序化验证器、GRPO、DAPO 都不是本文首创。根据论文的 Table 1 和 related work，只能确认作者声称的差异；是否构成“首次提出”，还需要更完整的文献检索。

## 3. 作者如何解决？

### 3.1 整体数据流：从人物设定到可训练的三元组

WildAWM 的输入不是一个现成数据集，而是一套生成配置：人物设定生成器、15 个来自 WebHarbor 的镜像网站、8 个 MCP 服务、一个共享的事件技能库，以及本地文件系统。输出是 $\{\text{task},\text{environment},\text{verifier}\}$ 三元组，以及在这些三元组上训练出来的策略模型（§3、论文 Fig. 1）。这里的“world model”不是学习式的动力学预测模型，而是一个可执行、可重置、可验证的个人电脑世界及其状态；这是读这篇论文时首先要避免的误解。

图 1 给出整条流水线。它把两个合成阶段串成一条数据流：人物设定先展开成多日计划，日计划被编码智能体落地成可重放的世界状态；世界状态再被任务生成器改写成必须跨 GUI、MCP、CLI 的任务，任务与验证器经过多智能体执行和多层裁判，最后通过质量门进入训练。读者应从中理解的是：环境不是任务的背景板，而是任务的“初始状态 + 可验证的状态变化”；验证器不是事后的字符串匹配，而是从初始状态到最终状态的差异检查。

![图 1：WildAWM 的两阶段合成与训练数据流](/images/dailypaper/2026-10-22/wildawm_fig1.png)

**图 1**（论文 Fig. 1）：整条管线由世界合成、XAI 任务合成和在线 RL 三部分组成。世界合成侧从人物设定出发，逐日生成日计划，再由编码智能体把计划实现为网站、MCP 服务和本地文件的状态增量，形成可重放的 $W(c,d)$；任务合成侧从某个世界状态出发，先探索环境、提出候选任务，再生成任务说明、评分细则和程序化验证器，随后让多个模型—运行框架组合执行任务，用程序化验证器、LLM 裁判和 agent 裁判交叉判断，最后经过五道质量门决定接受或退回修改；被接受的三元组进入 SFT/RL，验证器直接充当奖励函数。图中的关键数据流是“世界状态 → 任务 → 轨迹 → 判定 → 门控 → 训练”，而不是单向的“生成任务再人工检查”。

哪些环节由模型决定、哪些由固定流程控制，可以用一张表概括：

| 环节 | 模型决定的部分 | 固定流程或硬规则 |
| --- | --- | --- |
| 人物设定与日计划 | GLM-5.2 在系统提示（constitution）下写职业、联系人、故事线、日计划 | 多样性裁判、与前一天状态连续、至少一个“图像决定性”故事线 |
| 世界落地 | 编码智能体写 `delta.sh` 和确定性 Python 子脚本 | 两次重放内容哈希一致、声明校验、服务健康、独立 reviewer |
| 任务与验证器 | 生成器探索环境后写任务、`golden.py`、评分细则和验证脚本 | 三种接口都必须不可或缺、任务不超过 300 词、$V=\prod_i v_i$、自检循环 |
| 质量门 | 18 个模型—运行框架组合执行，LLM 裁判与 agent 裁判给判定 | 五道门的阈值固定；每轮最多两次修复；失败原因回灌技能库 |
| RL | 策略模型生成每一步动作 | 奖励公式、优势归一化、裁剪范围、最大轮数、超时固定 |

### 3.2 世界合成：把“个人电脑生活”做成可重放的状态

世界合成的第一步是人物设定。生成器是一个使用 GLM-5.2、跑在 OpenCode 里的编码智能体；它被要求先检查 15 个 WebHarbor 镜像站的真实目录和现有 MCP 应用索引，确保人物提到的商品、课程、酒店确实存在，而不是凭空编造（Appendix A.3）。每个人物包含职业、至少 3 个具名联系人、常用网站、4 到 8 个 MCP 服务、2 到 5 条跨天故事线，其中至少一条是“图像决定性”的：某个选择只能靠看图片决定，不能靠文字检索（Appendix A.3）。候选人物会经过一个 LLM 多样性裁判，如果和已接受人物共享同一职业与生活领域、同一套核心工具/网站使用模式、或同一条叙事弧，就被退回并附上相似性反馈，最多修改两次（Appendix A.3、Table 11）。

第二步是逐日规划。日计划器在计划第 $d$ 天之前，必须读取真实的前一天状态 $W(c,d-1)$，包括数据库、工作区文件和网站历史，然后写出当天的活动、MCP 事件、GUI 操作和涉及的本地文件；计划里还带一个“覆盖压力”直方图，统计前几天各应用、各网站的使用次数，用来鼓励跨天分散接口使用（Appendix A.3）。这一步的设计意图很直接：如果每天只重复同一个应用，世界虽然变大，但任务会趋同；连续性则保证后面生成的任务可以依赖“昨天发生的事”。

第三步是技能增强的落地。生成器先把日计划里的活动与共享技能库匹配。一个事件技能不是一句提示词，而是一份可执行规格：涉及哪些接口、要产生哪些状态变化、跨记录/文件的 consistency 约束是什么、前置条件是什么、后续可能触发什么（§3.1、Appendix C）。论文给的例子是订机票：同一个确认号要同时出现在 Google Flights 的订单、确认邮件、私信、日历事件和本地笔记里，技能会检查消息顺序、日历占位符、标签 ID 等一致性（Table 17）。如果日计划出现技能库没有覆盖的活动，生成器就新写一个技能；如果缺少某个 MCP 服务，就实现对应的数据库 schema 和后端，并把它加入共享库，供后续人物和天数复用（§3.1）。最终世界合成技能库有 83 个技能（Table 2）。

第四步是把计划变成确定性的状态增量。这里用的是一个“god-mode”编码智能体：它运行在已经启动的世界实例里，能访问 MCP 服务、WebHarbor 数据库和文件系统，产出一个 `delta.sh` 以及若干确定性 Python 子脚本；脚本在 Hermes 式的隔离环境里对第 $d-1$ 天状态重放，必须每次得到完全相同的第 $d$ 天状态（Appendix A.3）。确定性靠几条硬约束保证：时间戳必须是冻结的字面量，不能用 `datetime.now()`；ID 必须由 `MAX(id)+1` 推导，不能随机；插入必须幂等；密码必须使用人物 `accounts.json` 里的固定盐哈希（Table 11）。世界验收还有五层：静态 lint、两次重放的内容哈希一致、`produces.json` 声明校验、真实启动后的登录/页面/服务健康检查、以及一个运行在宿主侧、与实现者隔离的 reviewer agent（Appendix A.3）。这些设计不是为了“好看”，而是因为 RL 需要反复 reset 到同一个初始状态；如果世界每次重放都不同，奖励和 credit assignment 就失去意义。

世界合成的输出是累积状态 $W(c,d)$。论文报告了 36 个人物、640 个世界状态、平均每个人物 17.8 个状态；最终日平均有 171.6K 条数据库记录、50.1 个本地文件、59.3 MiB 的世界状态；每天平均触及 3.97 个网站/服务和 5.31 个 MCP 服务（Table 2）。15 个镜像网站和 8 个 MCP 服务是共享的应用层，但每个人物的可变状态是隔离的（Appendix A.3）。这解释了为什么后面的任务可以要求“读取前天私信里的批准，再去网站下单，最后写本地笔记”：这些信息确实分布在同一个世界的不同接口里。

### 3.3 XAI 任务合成：用执行证据而不是模型自述来筛任务

任务合成的输入是一个具体的世界状态 $W_0=W(c,d)$。生成器先在这个活的世界里探索，最多提出 4 个候选任务草图；每个草图必须满足三个条件：完成它必须同时用到 CLI、MCP 和 Web GUI，而且三者都不可或缺；必须要求解题者写并运行一个脚本或命令行程序，处理真实用户可见的源文件或 MCP 导出，并且这个计算结果要驱动后续的 MCP 或 Web 决策；任务要对 assigned difficulty 来说是长时程的（§3.2、Appendix A.4）。草图还要经过多样性门：与已接受任务、以及并发 worker 正在开发的任务比较，如果核心动作和涉及的对象相同，就视为近重复；不同措辞不算不同（Appendix A.4、Table 12）。这一步的目的是防止 341 个任务变成“同一类购物任务换 341 个商品名”。

被选中的草图会展开成七个工件：`task.md`（给解题者看的第一人称请求，最多 300 词）、`reason.md`（出题理由，内部）、`meta.json`（结构化元数据，内部）、`golden.py`（参考解法，用来产生“忠实解题者”的可观察状态）、`rubrics.md`（评分细则）、`verify.skill.md`（验证技能说明）、以及若干确定性验证脚本（Appendix A.4）。这里有一条重要的“保密纪律”：`task.md` 是公开的，`reason.md` 和 `meta.json` 是管线内部的，避免把答案、图像真值或验证器细节泄漏给解题者（Appendix A.4、Table 12）。验证器最终把任务成功定义为所有二元检查都通过：

$$V(W_0,W,a)=\prod_{i=1}^{N}v_i(W_0,W,a)$$

其中 $W_0$ 是初始世界状态，$W$ 是最终世界状态，$a$ 是智能体的最终回答，$v_i\in\{0,1\}$ 是第 $i$ 条检查（§3.2）。这个乘积形式意味着“全对才算成功”，但单条检查的分数可以用于 RL 的部分信用；这是后面奖励设计的基础。

接下来是执行与判断。每条任务收集 6 条轨迹，其中 3 条带提示、3 条不带提示；执行者来自 18 个模型—运行框架组合：3 个开源模型（GLM-5.2、DeepSeek-V4-Flash、MiniMax-M3）× 6 个运行框架（OpenCode、Codex、Claude Code 三个编码智能体，以及 Nanobot、OpenClaw、Hermes Agent 三个 claw 类智能体）（§3.2）。这里的 claw agents 是论文对以 OpenClaw 一类运行框架为载体的智能体的称呼，论文没有给出更正式的定义。每条轨迹随后经过三层判断：程序化验证器 $V$ 直接读最终世界状态；LLM 裁判读任务、评分细则和机器抽取的证据摘要，给出 completed/failed/world_imperfect 三分类；agent 裁判用 OpenCode 多轮检查初始和最终世界快照，能看文件、数据库和图片（§3.2、Appendix A.4）。三层判断的分工是：程序化检查便宜、确定但可能 brittle；LLM 裁判能理解语义意图；agent 裁判能主动查证，但最贵，所以只在合成期使用，最终的奖励函数仍是程序化验证器。

五道质量门是这套方法的核心。它们不是简单的“分数阈值”，而是分别针对不同的失败模式：

- **裁判一致性（Judge Consistency）**：对每条轨迹 $j$，要求程序化验证器、LLM 裁判、agent 裁判三者的判定完全一致，即 $V(W_0,W_j,a_j)=V_{\text{LLM}}^{(j)}=V_{\text{agent}}^{(j)}$。如果不一致，就把证据退回生成器，修改评分细则或验证脚本（§3.2）。这道门防的是“验证器和裁判对任务意图理解不同”。
- **初始不满足（Initial Unsatisfaction）**：要求 $V(W_0,W_0,\varnothing)=0$，也就是在智能体什么都不做时，任务不能已经被判定完成（§3.2）。这道门防的是“初始世界状态已经满足目标”，否则任务没有意义。
- **任务可解（Task Solvability）**：要求至少有一条轨迹成功，而且每条成功轨迹都确实使用了任务声明需要的所有接口（§3.2）。这道门防的是“裁判都同意，但所有 agent 都失败”的不可解任务；仅靠裁判一致性不能证明可解。
- **任务难度（Task Difficulty）**：只看 3 条不带提示的轨迹，令 $k=\sum_{j\in\mathcal{U}}V(W_0,W_j,a_j)$；$k\le 1$ 标为 hard，$k=2$ 标为 medium，$k=3$ 标为“太容易”，退回生成器加难度（§3.2）。这道门用经验成功率而不是主观难度标签来校准。
- **反事实探测（Counterfactual Probe）**：对一条轨迹的判定 $V$，告诉 agent 裁判“独立审计认为正确答案是 $1-V$”，要求它重新调查；如果它坚持原判且不修改验证脚本，则通过；如果它屈服、修改脚本，则失败（§3.2）。这道门利用 LLM 的谄媚倾向，测试裁判的判定是否稳定。Appendix A.4 把它拆成两阶段：先做一次不给预期的盲判，再进入“gaslight”阶段；如果裁判改脚本，系统会通过文件 diff 检测并回滚。

图 2 展示了候选任务在这五道门里的漏斗。它想说明的不是“每一门都砍掉固定比例”，而是“候选从草图到可用任务要经过多次退回和重写”：多样性门之后还剩 2,551 个候选，初始不满足门后 642 个，最终接受 341 个；大量候选在可解性、难度和反事实探测上被退回。读者应从中理解：341 不是“生成出来就收下”的数量，而是经过执行证据筛选后的结果。

**图 2**（论文 Fig. 2）：漏斗从多样性门开始，逐层经过初始不满足、裁判一致性、任务可解、任务难度和反事实探测，最终留下 341 个接受任务；每一层都标注了首次直接通过的比例和经过反馈修改后通过的比例，以及被拒绝的数量。它反映的是合成管线的“筛选—反馈—重写”循环：候选不是一次性判定，失败者会带着诊断证据回到生成器，最多修改两轮；被接受的任务进入多样性池，失败的教训则被写进生成器的演化技能库。图中最重要的读法是“接受率”而不是单层通过率：2,551 个草图最终只有 341 个任务，说明质量控制是实质性的，而不是形式上的。

一个具体案例可以帮助理解任务形态。论文 Table 3 的任务要求一位音视频技术员为运动酒吧的显示墙锁定机架电涌保护器：先在 MCP 私信里确认老板已经批准，再用 CLI 写脚本把机架库存、物料清单和 APC 规格书三个异构来源做连接和排序，输出候选清单；然后到 Amazon 店铺登录，把排名第一的电涌保护器加入购物车；其中两个候选在列表规格上完全相同，只能靠商品图片的白色机身和数字显示面板来区分；最后写本地补货笔记，并给安装同事发私信。接口流是 MCP → CLI → GUI → CLI → MCP，共 5 个子任务，最后的 GUI 写入又回到 CLI 和 MCP，所以无法在单一接口内完成（Table 3、§3.2）。这个例子说明“图像决定性”不是装饰：它把任务从“文本检索 + 排序”变成了必须看图的 GUI 操作。

### 3.4 训练：先学格式与跨界面习惯，再用 RL 补长时程

341 个任务被随机分成 100 个 SFT 任务、208 个 RL 任务和 33 个域内验证任务（§4）。训练分两阶段。

第一阶段是 SFT 冷启动。作者发现 XAI 任务对基础 Qwen 模型太难：Qwen3.6-35B-A3B 在域内只有 5.7 pass@1、18.4 pass@4；Qwen3.5-4B 只有 0.38 pass@1、1.5 pass@4；大多数 GRPO 组会得到相同奖励，产生零方差、浪费 rollout（Appendix A.5）。因此他们先用 GLM-5.2 在 100 个 SFT 任务上各收集 4 条轨迹，只保留成功的轨迹，并且每个任务最多保留 1 条，以平衡任务间的数据量；然后把轨迹转成 Qwen 的对话模板，只在 assistant token 上计算损失，训练 3 个 epoch（Appendix A.5）。如果轨迹在推理时发生上下文压缩，就按压缩边界切成因果段，超过 102,400 token 的段会被删掉（Appendix A.5、A.6）。这一步学到的不仅是任务格式，还有教师的跨界面行为习惯；后文的行为分析会显示，SFT 后接口切换率明显上升。

第二阶段是 GRPO。对任务 $\tau$ 的第 $j$ 条轨迹，如果发生格式错误（例如工具调用无法解析、工具名不存在、输出为空、推理块标签错误），则 $e_j=1$，奖励固定为 $-1$；否则奖励为：

$$r_j=\min\left\{1,\; V(W_0,W_j,a_j)+\frac{0.1}{N}\sum_{i=1}^{N}v_i(W_0,W_j,a_j)\right\}$$

其中 $N$ 是检查清单的条目数，$V$ 是全对才为 1 的任务成功指示，第二项是部分信用，权重 0.1（§3.3）。这个设计的直觉是：长时程任务的成功信号很稀疏，如果只用 0/1，很多轨迹组没有梯度；用检查清单的部分分可以提供更密的信号，但成功仍然拿满分 1，避免“部分完成”压过“真正完成”。格式错误单独给 -1，是为了让模型先学会可解析的动作格式，尤其是 GUI 动作必须被正确解析才能作用到界面上。

GRPO 的另一个问题是零方差组。小模型在早期经常所有 rollout 都拿 0，或者都格式失败，组内奖励没有差异，优势为 0。作者借鉴 DAPO 做了自适应 rollout：每个任务维护一个 rollout 乘数 $\kappa_\tau$，初始为 1、上限为 3；当任务被采样时，先发 $G=4$ 条基础 rollout，再按 8 条一组追加，直到组内出现至少两种不同奖励，或者达到上限（Appendix A.5）。如果一个任务的 4 条基础 rollout 全成功，就标记为 mastered 并取消未完成的多余 rollout；如果池子里只有格式失败，就标记为 ready 并从中随机抽一组；如果到达上限仍无差异，就标记为 exhausted 并从该步丢弃（Appendix A.5）。优势按池内奖励标准化；如果池内标准差为 0 且全部是格式失败，则给每条轨迹 $-K^{-1/2}$ 的优势，专门提供格式学习信号；其他零方差情况优势为 0（§3.3）。这套机制的目的是把 rollout 计算花在“能产生梯度”的任务上，而不是平均地撒在所有任务上。

第三个细节是跨上下文压缩的分段训练。OpenCode 在上下文接近窗口上限时会自动压缩：把早期轮次总结成紧凑表示，然后让智能体在新鲜前缀上继续。这让 rollout 可以很长，但也让轨迹不再是一条单一的因果序列。论文把两次压缩之间的连续步骤定义为一个 segment（段），每个段共享一个基础前缀；标准做法是把每一步当成独立样本，分别用自己的完整 harness 上下文计算损失，这需要 $T_j$ 次前向、重复编码大量重叠前缀，也丢掉了同一上下文窗口内步骤之间的自回归依赖；分段做法则把同一段内的步骤放在一起，按段计算损失，既减少前向次数，又保持段内的因果结构，并用轨迹级归一化保证压缩频繁的轨迹和压缩少的轨迹得到相同的总梯度权重（Appendix A.6、论文 Fig. 7）。论文给的例子是：一条 9 步、在第 5 步发生一次压缩的轨迹，按 per-step 是 9 个样本，按 segment-wise 只有 3 个样本（Appendix A.6）。这是工程效率与训练—推理对齐的结合，不是新的 RL 目标。

训练超参数方面：两个模型都用 Adam，峰值学习率 $5\times10^{-6}$，10% warmup 后余弦衰减，权重衰减 0.01，全局 batch size 8，SFT 3 个 epoch；RL 最多 64 步，每步 8 个任务，$G=4$，学习率 $1\times10^{-6}$ 常数，裁剪范围 0.2/0.28，熵系数 0.001，不做 KL 惩罚，每条 rollout 最多 256 轮、30 分钟，上下文 102,400 token；训练时冻结 MoE 路由器和视觉编码器，其余参数都训练（Table 13、Appendix A.5）。硬件是 8 张 NVIDIA B200，合成和训练共用（§4）。

### 3.5 推理：同一个运行框架，模型自己选接口

推理阶段没有额外的训练或微调。所有评测都使用 OpenCode（v1.17.7）作为智能体运行框架；模型可以自主使用原生文件工具、shell、MCP 服务、浏览器工具和桌面工具，系统提示要求它根据操作所需能力选择接口，而不是按固定优先级（Appendix A.2）。GUI 访问有两条路径：Playwright 提供导航、点击、输入、选择、取文本/属性等浏览器自动化；Browser-use CLI 提供无头 Chromium 的命令行控制；桌面基准还额外提供截图、可访问性树、点击、输入、滚动、键盘/鼠标原语和 guest 内执行工具（Appendix A.2）。对于本身不支持多模态输入的策略模型，系统提供一个 vision 工具，把图片路径转成由 Qwen3.6-35B-A3B 生成的文字描述（Appendix A.2）。推理时上下文窗口 100K token，自动压缩；大多数基准最多 256 轮，OSWorld 2.0 和 ALE 允许 512 轮；温度 1.0、top-p 0.95、top-k 20，推理强度设为 high（Appendix A.2）。智能体完成后写一个标记文件并停止。

这个推理协议的设计意图是让训练和评测尽可能一致：训练时的 rollout 也用同一个 OpenCode 运行框架、同一套工具和系统提示（Appendix A.5）。最终输出是最终世界状态、智能体的回答，以及验证器给出的分数；在域内验证集上，论文用 pass@k 的无偏估计和更严格的 pass^k（所有 k 次都成功）来报告（Appendix A.1）。这也解释了为什么训练后的模型在 OOD 基准上可以直接用同一套 harness 评测，而不需要为每个基准换一套动作空间。

## 4. 解决得怎么样？

### 4.1 实验设置

论文把 341 个任务随机分成 100 个 SFT、208 个 RL 和 33 个域内验证任务（§4）。OOD 评测覆盖 8 个基准，分三类：

| 类别 | 基准 | 任务数 | 报告指标 |
| --- | --- | --- | --- |
| Web agent | Online-Mind2Web（O2W） | 300（全量） | pass rate |
| Web agent | WebArena（WA） | 226（812 的子集） | pass rate |
| Claw agent | QwenClawBench（QCB） | 100（全量） | mean score |
| Claw agent | ClawEval（CLE） | 300（全量） | pass rate（分数 ≥0.75） |
| Computer-use | CUA-Gym（CUG） | 200（10,910 的子集） | mean score |
| Computer-use | OSWorld-Verified（OSV） | 99（330 的分层 30%） | mean score |

| Computer-use | Agents’ Last Exam（ALE） | 99（Linux 子集） | mean score |

这些数字来自 Table 9 和 Appendix A.1。需要强调的是，WA、CUG、OSV 都不是全量：WA 只用了 5 个自托管站点，CUG 从 10,910 个任务里随机抽 200 个，OSV 是 330 个任务的分层 30% 样本；O2W 还会排除被 reCAPTCHA 或其他访问限制阻塞的网站（Appendix A.1）。这些选择是为了评测效率，但会影响与全量结果的直接可比性。

被训练的两个模型是 Qwen3.6-35B-A3B 和 Qwen3.5-4B；对比对象包括 GPT-6-Astra、GPT-5.6-Sol、GPT-5.5、Claude Opus 5、Claude Opus 4.8、GLM-5.2，以及 prior work 报告的 OpenForgeRL 和 CUA-Gym 数字（§4、Table 5）。所有主结果都使用 OpenCode 运行框架，带 GUI（点击、输入）和 MCP（例如 Playwright）工具，推理强度 high；最大轮数 256，OS-2 和 ALE 为 512；上下文 100K，自动压缩；需要 LLM 裁判的基准统一用 GPT-5.5（§4、Appendix A.1）。开源模型在合成和评测中都做了 NVFP4 量化，以降低推理成本（Appendix A.1）。训练用 8 张 B200，SFT 3 个 epoch，RL 最多 64 步，每步 8 个任务、$G=4$（§4、Table 13）。

主实验回答“只在合成世界训练能否迁移到 8 个 OOD 基准”；§5.1 回答“合成环境是否够大、够多样，任务是否可解、够难，验证器是否可靠”；Table 7 回答“每道质量门是否有贡献”；Table 8 回答“RL 配方各部分是否有贡献”；§5.4 和 Appendix B 回答“行为上发生了什么变化”。这套实验组合比只报主结果的论文更完整，但每个问题都只回答了一部分，后文会逐一拆开。

### 4.2 关键结果

先看主结果。Table 5 显示，Qwen3.6-35B-A3B 的平均分从 42.84 提升到 53.42（+10.58），Qwen3.5-4B 从 21.83 提升到 30.04（+8.21）；8 个基准全部有提升（§4）。35B 的提升主要集中在 CLE（38.00→54.67，+16.67）、OSV（33.16→49.22，+16.06）、WA（53.54→67.26，+13.72）和 CUG（53.73→65.95，+12.22）；4B 的提升集中在 O2W（26.39→45.65，+19.26）、CUG（21.39→37.35，+15.96）、CLE（26.67→36.67，+10.00）和 WA（30.09→39.82，+9.73）。这些数字说明“合成世界训练”不是只对某一个基准有效。

但平均值掩盖了差异。4B 在 OS-2 上只从 0.87 提升到 1.03（+0.16），在 ALE 上从 7.00 到 8.96（+1.96）；35B 在 ALE 上从 23.57 到 26.31（+2.74），在 QCB 上从 57.86 到 61.44（+3.58）。这些低绝对值/低增益的基准，恰好是更长时程、更接近真实桌面的任务，说明方法在“离合成世界较远”的任务上仍然吃力。另一个容易被忽略的点是：4B 在 O2W 上的增益（+19.26）比 35B（+11.17）更大，所以“模型越大收益越大”只在平均意义上成立，不是每个基准都成立。

与前沿模型相比，35B 的平均 53.42 仍然低于 GLM-5.2 的 63.21、Opus-4.8 的 68.86、Opus-5 的 70.83 和 GPT-6-Astra 的 73.11；论文的说法是“缩小差距”，不是“追平”。具体地，它在 WebArena 上达到 67.26，与 GLM-5.2 完全相同；在 O2W 上达到 80.77，高于 GPT-5.5 的 72.22（§4、Table 5）。这两处是论文重点强调的“局部追平/超过”，但读者要注意：WebArena 的 67.26 是一个两位小数完全相同的点估计，论文没有报告方差，不能据此推断“等同于 GLM-5.2”。

合成质量方面，论文报告 WildAWM 的环境状态中位数为 52.4K token，而 CUA-Gym 的任务特定注入状态只有 1.1K token；尽管规模大得多，WildAWM 的 Vendi 分数在所有采样规模上都更高，最近邻余弦距离为 0.25，对比 CUA-Gym 的 0.20（§5.1、图 3，论文 Fig. 3）。Vendi 分数越高表示多样性越好，最近邻距离越大表示冗余越低。任务侧，24 个模型—运行框架组合中，每个任务至少被一个 agent 解出；只用合成时的三个开源模型也能解出超过 95% 的任务；带提示时，每个任务至少被三个模型中的一个解出，51.5% 的任务被三个模型全部解出（§5.1、图 3）。验证器方面，程序化验证器与 GLM-5.2 agent judge 的一致率为 95%，Cohen's κ 为 0.90（Table 6）；与 GPT-5.6-Sol 和 Opus-5 的一致性略低（κ 分别为 0.83 和 0.84），但仍在较高水平。

![图 3：环境多样性、任务可解性与验证器一致性](/images/dailypaper/2026-10-22/wildawm_fig3.png)

**图 3**（论文 Fig. 3）：这张图把“环境是否够多样”和“任务是否可解”放在同一组证据里。环境侧比较 WildAWM 与 CUA-Gym 的 Vendi 分数随采样环境数的变化，并给出最近邻余弦距离；任务侧统计每个任务被多少比例的异构 agent 解出，以及带提示时三个开源模型累计解出的任务比例。它支持的结论是：WildAWM 的环境状态更大、更不冗余，同时任务不是“难到没人能解”，而是至少存在一条可执行的成功路径；带提示时的高覆盖率进一步说明失败主要来自能力/探索，而不是环境本身不可解。读者也要注意：这里的“可解”是相对于这 24 个配置而言，不是对人类或任意 agent 的绝对保证。

难度方面，论文在 WildAWM-val 上报告 GPT-6-Astra 的 pass@1 为 59.85%，GLM-5.2 为 37.88%，Opus-5 为 54.55%；训练后的 WildAWM-35B-A3B 为 35.98%，WildAWM-4B 为 27.65%（图 4，论文 Fig. 4a）。GPT-6-Astra 在 8 次尝试后仍有 27.3% 的任务失败，pass@8 为 72.7%；GLM-5.2 的 pass@8 为 63.6%，Qwen3.6-35B-A3B 为 45.5%，Qwen3.5-4B 为 6.1%（论文 Fig. 4b、§5.1）。任务池的 rarefaction 曲线显示，341 个任务覆盖 134 个领域、91 种任务类型，接受率约 53%，曲线没有明显饱和，平均成对余弦距离保持稳定（论文 Fig. 4c、§5.1）。这里的 53% 是从初始不满足门之后的 642 个候选算起（341/642），不是从 2,551 个草图算起。

![图 4：WildAWM 验证集上的难度、测试时扩展与任务池饱和](/images/dailypaper/2026-10-22/wildawm_fig4.png)

**图 4**（论文 Fig. 4）：这张图回答两个问题——“任务对前沿模型是否仍然难”和“继续合成是否会饱和”。它把模型规模与 WildAWM-val 的 pass rate 对齐，显示 GPT-6-Astra 约 60%、训练后的 35B 约 36%、4B 约 28%；同时给出 pass@k 与更严格的 pass^k 随尝试次数的变化，说明增加测试时尝试能提高至少一次成功的概率，但“每次都成功”的概率下降得很快；任务池的 rarefaction 曲线则按领域和任务类型统计，随着接受任务增加仍在上升，尚未看到平台。读者应理解：这套任务不是“前沿模型随手就能解”的简单集合，但“难”与“可训练”是两件事，后者还要看 RL 是否能把成功率推上去。

消融实验分两组。Table 7 在 Qwen3.5-4B 上每次去掉一道质量门，重新合成 SFT 数据并训练：完整方案平均 31.86；去掉初始不满足 24.08（-7.78），去掉裁判一致性 22.56（-9.30），去掉任务可解 29.26（-2.60），去掉任务难度 26.37（-5.49），去掉反事实探测 27.91（-3.95）。域内验证集的差异更明显：完整 21.59，去掉初始不满足只剩 3.05，去掉裁判一致性 3.79，去掉任务难度 7.58，去掉反事实探测 13.64（Table 7）。论文据此说五道门互补，移除任意一道平均下降 2.60–9.30 分（§5.2）。

但 Table 7 也有不均匀的地方：去掉任务可解门后，O2W 反而从 38.49 升到 44.87；去掉反事实探测后，OSV 从 17.17 升到 24.09；代价是域内验证集大幅下降（15.91 和 13.64）。这说明这些门的作用不是“每个基准都涨”，而是“平均和域内数据质量更好”；也说明只报平均值会掩盖门与基准之间的交互。Table 8 在 35B 上做 RL 消融：完整 53.42；去掉格式奖励 52.18（-1.24），去掉检查清单部分分 51.17（-2.25），去掉 SFT 冷启动 48.11（-5.31）。SFT 冷启动是最大的单一因素，这一点对后文的“教师蒸馏”质疑很关键。论文正文还说去掉格式奖励后 CLE 的 pass rate 更高（61.00 vs 54.67），但“平均分没有相应提高”，给出的数字是 69.89 vs 69.45；这里 69.89 实际上高于 69.45，文字与数字互相矛盾，至少是笔误或表述错误（§5.3、Table 8）。

### 4.3 机制证据

Table 5 证明“训练后在 8 个基准上更好”，但不自动证明“是 WildAWM 的哪个设计导致更好”。论文为此提供了三类机制证据：合成质量（环境多样性、任务可解性、验证器一致性）、质量门/RL 消融、以及策略行为分析。下面把每个创新点对应的证据和缺口拆开。

| 设计 | 论文给出的支持证据 | 仍然缺少的隔离实验 |
| --- | --- | --- |
| 多日、跨 GUI/MCP/CLI 的世界 | 环境规模 52.4K vs 1.1K token、Vendi 更高、最近邻距离 0.25 vs 0.20（§5.1、论文 Fig. 3）；任务平均 3.1 次接口切换、74.5%  revisit 旧接口（§3.2）；SFT 后接口切换率 18.4%→24.7%（§5.4） | 没有“单接口世界”“无历史世界”“去掉 MCP 或 CLI”的同预算对照；无法判断跨界面设计本身贡献了多少，还是只是提供了更多样的数据 |
| 五道执行式质量门 | Table 7 逐门移除，平均下降 2.60–9.30；域内验证集下降更明显 | 去掉门会改变数据量和难度分布，没有控制“任务数量/训练 token 相同”；只在一个 4B 模型上做；没有人类真值验证门判定的正确性 |
| 全开源合成 | Table 1 的集成差异；论文 Fig. 3/4 的合成质量；代码、数据、模型公开 | 没有“同一管线换用专有模型做生成器”的对照，无法证明开源模型与闭源模型在合成质量上等价，只能证明“开源模型也能做出可用的结果” |
| RL 配方（SFT 冷启动、部分分、格式惩罚、自适应 rollout、分段训练） | Table 8 的 RL 消融；论文 Fig. 5 的难度四分位、接口切换、step budget；Table 14 的行为统计 | 没有自适应 rollout 和分段训练的单独消融；没有 reward hacking 分析；SFT 冷启动是最大因素，教师蒸馏与 RL 的贡献没有完全分开 |

行为分析提供了更细的线索。论文把 OOD 任务按“前沿模型解题率”分成四个难度四分位，WildAWM 在第二、第三四分位分别提升约 +19.9 和 +12.2 分，在最难四分位只有 +0.3 分；在最难四分位，base 和四个变体只解出 4–7 个任务，而 GPT-6-Astra 解出 18 个（§5.4、图 5，论文 Fig. 5、Appendix B）。这说明收益集中在“教师够得着”的中等难度任务，真正超出教师能力的任务没有被合成数据拯救。接口切换率从 base 的 18.4% 升到 SFT 后的 24.7%、RL 后的 25.5%，接近 GLM-5.2 的 26.3%；而 RFT（用 base 自己的成功轨迹）和 +RL（不做 SFT 直接 RL）分别只有 15.8% 和 15.7%（§5.4、Table 14）。这强烈暗示跨界面行为主要来自教师轨迹的 SFT，而不是 RL 自己探索出来的。长时程方面，SFT 和 WildAWM 在 40 步内解出的比例接近（34.9% vs 36.8%），但在 40–120 步之间 SFT 只多解 9.7 分，WildAWM 多解 17.0 分；+RL 也能多解 15.2 分，但起点更低，120 步内只到 47.2%，低于 WildAWM 的 53.7%（§5.4、论文 Fig. 5）。这组证据支持“SFT 学跨界面习惯，RL 补长时程”的解释，但它仍然是行为相关性，不是对因果机制的隔离。

![图 5：训练变体的难度四分位收益、接口切换与 step budget](/images/dailypaper/2026-10-22/wildawm_fig5.png)

**图 5**（论文 Fig. 5）：这张图是行为层面的机制证据。它按前沿模型的解题率把 OOD 任务分成四个难度四分位，比较 base、RFT、SFT、无 SFT 的 RL、完整 WildAWM 和 GLM-5.2 相对 base 的提升；同时统计连续工具调用在 GUI、CLI、MCP 等接口族之间切换的比例，以及在不同 step budget 内解出的任务比例。读者应看到三条线：收益集中在教师能解的中等难度；跨界面切换率在 SFT 后跳升、在只做 RFT/RL 时反而下降；RL 的主要作用是把 40–120 步的长时程任务解出来，而不是把最容易的任务再刷高。它也暴露了方法的边界：最难四分位几乎没有提升。

从机制证据的角度看，论文能排除一部分替代解释：所有主结果使用同一个 OpenCode harness，训练和评测工具一致；Table 8 的 SFT 消融说明 RL 不是唯一因素；RFT 和 +RL 说明“只要在 WildAWM 数据上微调”并不够，教师的跨界面轨迹有独立作用；8 个基准覆盖三类任务，降低了“只对一个基准过拟合”的可能。但它不能排除另外几个替代解释：教师蒸馏（SFT 的贡献最大）、训练 token/rollout 预算（WildAWM 的轨迹更长、工具调用更多）、基准污染（公开基准可能出现在预训练数据中）、单次运行噪声（没有 seeds/CI）、以及评测子集选择。换句话说，证据支持“这套数据+配方在报告条件下有效”，但还没有把“合成世界”从“教师轨迹”和“更多长轨迹计算”中分离出来。

### 4.4 成本与适用范围

合成成本方面，Table 4 给出每个任务的平均值：生成器输入 69.8M token、输出 1.1M token，2.5 轮修订（P90 为 5 轮）；一次任务执行平均 80 次 LLM 调用、81 次工具调用，输入 4.1M token、输出 20.6K token；平均访问 1.1 个 GUI 网站、连接 2.4 个 MCP 服务、处理 5.0 个本地文件。合成使用 18 个模型—运行框架组合、每条任务 6 条 rollout，失败候选还要多轮修复；最终从 2,551 个草图得到 341 个任务。论文只报告了“合成和训练共用 8 张 B200”，没有报告总 GPU-hours、美元成本、墙钟时间或人工小时（§4、Table 4）。因此无法判断“每个可用任务”的真实成本，也无法与手工环境或其他合成管线做性价比比较。

训练成本方面，SFT 在 100 个任务上训练 3 个 epoch，RL 最多 64 步、每步 8 个任务、$G=4$，每条 rollout 最多 30 分钟、256 轮；同样没有总 GPU-hours。推理成本方面，评测最多 256/512 轮、100K 上下文、自动压缩，O2W 还依赖 live websites；这些都会影响可复现性和成本。论文没有报告失败率、超时率（除了 Appendix B 提到 CUG/OSV/WA 上 5.5% 的 episode 在 120 步前超时）、重试率或人工审核成本。

任务分布也影响“可扩展”的含义。图 6 把 341 个任务按人物设定和 day index 展开：前六个人物贡献 178 个任务，其余 30 个各 2–14 个，640 个世界状态中只有 246 个承载任务，262 个任务来自 day 0–13。这说明合成尝试集中在最早开发的六个人物上，绝对数量不能直接当作有效多样性。

![图 6：341 个任务在人物设定与天数上的分布](/images/dailypaper/2026-10-22/wildawm_fig6.png)

**图 6**（论文 Fig. 6）：这张图展示 341 个接受任务在 36 个人物设定和 day index 上的分布。前六个人物贡献了 178 个任务，其余 30 个人物各贡献 2–14 个；任务数随“当天有世界状态的人物数”变化，Pearson $r=0.90$；640 个世界状态中只有 246 个承载了至少一个接受任务，262 个任务来自 day 0–13。它说明语料的绝对数量（341）不等于有效多样性：任务集中在少数人物和前两周的世界状态上。论文在 Appendix A.3 主动解释了原因——前六个人物是最早合成、用来开发和测试任务管线的，因此有更多合成尝试；这不是隐瞒，但正文没有把它作为限制展开。

适用范围方面，这套方法目前覆盖的是英文、单人、个人电脑、三种接口、36 个人物、341 个任务、两个 Qwen 规模；没有多用户/企业环境、非英文 locale、真实机器部署、安全/隐私红队、长期运行或对抗用户。论文的动机是“真实世界 RL 有安全风险”，但没有评估合成世界是否真的降低了这些风险；它证明的是“在合成世界里训练能迁移到一些 OOD 基准”，不是“合成世界可以替代真实世界训练”。仍未解决的问题包括：最难四分位没有提升；OS-2/ALE 的绝对分数很低；RL 在域内验证集上没有超过 SFT（37.3→36.0）；验证器没有人类真值；成本与失败率不透明；Table 2 的“World size growth 30.9 KiB”与“World state size 59.3 MiB”在 17.8 个状态下难以自洽，论文没有解释这个单位/口径问题。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：OOD 提升可能主要来自对 GLM-5.2 教师轨迹的 SFT 蒸馏，而非 WildAWM 世界本身

- **原文依据**：§4 与 Appendix A.5 的 SFT 设置是 100 个任务、每任务 4 条 GLM-5.2 rollout、只保留成功轨迹、每任务最多 1 条；Table 8 去掉 SFT 冷启动后平均从 53.42 降到 48.11（-5.31），是所有 RL 消融中最大的；Table 14 的域内 pass@1 在 SFT 后为 37.3、教师为 37.9、RL 后为 36.0；§5.4 明确说跨界面行为“inherited from the teacher”，接口切换率从 18.4% 升到 24.7% 主要发生在 SFT 后。
- **为什么重要**：论文的中心主张是“在合成世界中训练能泛化到未见任务”。如果大部分收益来自模仿更强的教师，那么贡献更像是“用 WildAWM 任务收集教师轨迹”，而不是“合成世界提供了独特的学习信号”；这会影响创新归属、341 个任务的价值判断，以及后续研究应该优先复制哪一部分。
- **当前能够得出的判断**：现有证据支持“WildAWM 的 SFT+RL 数据有效”，但不足以把“世界合成”与“教师蒸馏”分开。RFT（+73 个净任务）和 +RL（无 SFT）提供了部分对照，说明并非全部来自教师；但仍缺少“在另一个环境里收集同等规模 GLM-5.2 轨迹”的 SFT 对照。审稿人判断：主要混杂因素未被完全排除。
- **如何验证或补强**：增加三个对照：(1) 用同样 token/轨迹预算，在 CUA-Gym、WebArena 或手工环境中收集 GLM-5.2 成功轨迹做 SFT；(2) 只用 WildAWM 任务、但把任务迁移到别的环境做 SFT/RL；(3) 从更强的 base 直接 RL，不用教师 SFT。报告每组的增益/成本比，才能判断“世界”本身的边际价值。
- **严重程度**：主要问题。

#### 质疑：验证器可靠性是用模型裁判“自证”，缺少人类真值；反事实探测可能奖励固执而非正确

- **原文依据**：§3.2 的三级判断全部由模型完成：程序化验证器、GLM-5.2 LLM 裁判、OpenCode agent 裁判；Table 6 的 95% 一致率与 κ=0.90 是相对 GLM-5.2 agent judge 和 judge majority，不是相对人类；只抽样 100 条 rollout；Appendix A.4 的反事实探测在“独立审计认为相反”时要求裁判坚持原判，若改脚本则失败。
- **为什么重要**：验证器同时是质量门的裁决器和 RL 的奖励函数；如果验证器本身有系统性偏差，任务可解性、难度和训练信号会一起偏。论文把 verifier reliability 列为三大挑战之一，这是方法可信度的核心，也是“用执行证据代替模型自述”这一卖点能否成立的关键。
- **当前能够得出的判断**：现有证据说明多个 LLM 裁判之间高度一致，且程序化验证器与它们一致；这支持“内部一致性/稳定性”，但不能证明“与真实完成情况一致”。反事实探测是巧妙的谄媚压力测试，但一个“无论证据如何都坚持原判”的裁判也会通过，因此它测试的是抗压性，不是正确性。审稿人判断：验证器的 ground truth 仍无法确认。
- **如何验证或补强**：分层抽取 100–200 条 rollout（覆盖 hard/medium、三种接口、成功/失败），由人类标注完成与否，报告验证器的 precision、recall、F1 和 κ；加入“故意错误但自信”的裁判作为反事实探测的阴性对照；用 reward hacking 策略（例如只改文件、不完成语义）测试验证器是否被绕过；公开验证脚本与失败案例。
- **严重程度**：主要问题。

#### 质疑：33 个验证任务和高度集中的人物分布，支撑不了“60% of 341”与“可扩展”的强表述

- **原文依据**：Appendix A.1 的 WildAWM-val 只有 33 个任务 × 8 条 rollout；论文 Fig. 4 的标题明确写“Performance on WildAWM validation set”，图中 GPT-6-Astra 为 59.85%；摘要却说“341 ... GPT-6-Astra solving only 60% of them”；Appendix A.3 和 Table 10 显示前六个人物贡献 178/341 个任务，后 30 个各 2–14 个，246/640 个世界状态承载任务，262 个任务来自 day 0–13；没有置信区间或多种子。
- **为什么重要**：60% 是论文最醒目的难度卖点，“可扩展”是第二个卖点；如果 60% 只是 33 个任务上的点估计，其抽样误差约为 ±17 个百分点（二项分布粗略估算），“341 个中的 60%”的措辞会高估精度。任务集中在少数人物，也会让“134 个领域、91 种任务类型”的多样性看起来比实际有效多样性更强。
- **当前能够得出的判断**：33 个任务是 341 个的随机子集，59.85% 可以作为总体估计，但精度有限；作者在 Appendix A.3 主动披露了集中度，说明并非隐瞒，但正文没有把它作为限制讨论。审稿人判断：结论方向可信，“60% of 341”与“scalable”的表述被夸大。
- **如何验证或补强**：在全部 341 个任务上评测 GPT-6-Astra（至少 3 个种子），报告 bootstrap 置信区间；按人物/领域分层报告；留出整个人物做 OOD 测试；报告每个人物的 unique task type 数，而不只是总数；给出 accepted tasks 随 compute 的 scaling curve 及成本。
- **严重程度**：主要问题。

#### 质疑：跨基准平均分的公平性与可复现性不足，单次运行和子集选择可能放大或掩盖差异

- **原文依据**：Table 9 使用 WebArena 226/812、OSWorld-Verified 99/330、CUA-Gym 200/10,910 等子集；Appendix A.1 对 O2W 排除 reCAPTCHA 阻塞网站、用 GPT-5.5 做裁判、对开源模型做 NVFP4 量化；主结果和消融没有 seeds、置信区间或显著性检验；Table 5 的 † 参考数字来自不同 harness（OpenForgeRL 用 OpenClaw、CUA-Gym 用 R-GUI）；§5.3 称去掉格式奖励后 CLE 平均分没有提高，但给出的 69.89 高于 WildAWM 的 69.45，文字与数字矛盾。
- **为什么重要**：论文的核心结论是“平均 +8.21/+10.58，缩小与前沿差距”；平均值混合了 pass rate 和 mean score、不同子集、不同裁判与量化设置，单次运行的噪声可能大于 4B 模型在 OS-2/ALE 上的 +0.16/+1.96。CLE 的 69.89 vs 69.45 矛盾至少说明结果表述需要校对，读者无法判断哪个数字是最终结论。
- **当前能够得出的判断**：主比较在使用同一 OpenCode harness、同一评测协议方面比很多论文更克制；但“可复现”仍不足：没有 seeds/CI、子集和 live website 漂移、闭源裁判、† 基线不可直接比。审稿人判断：结论方向大概率成立，但具体数字的稳健性无法确认；CLE 句子是报告错误或笔误，需修正。
- **如何验证或补强**：公开逐任务结果与运行日志；主结果和 Table 7/8 各跑 3 个种子，报告均值±标准差或 bootstrap CI；对子集做功效分析，或补全 WebArena/OSWorld 全量；统一裁判版本与量化设置；修正 CLE 的表述并同时给出 pass rate 与 mean score 两套结果。
- **严重程度**：次要问题（但影响可复现性评分）。

#### 质疑：合成成本、失败率与适用范围报告不足，“全开源”和“可扩展”的边界被淡化

- **原文依据**：Table 4 给出每任务平均 69.8M 生成器输入 token、1.1M 输出、2.5 轮修订、80 次 LLM 调用/81 次工具调用；§4 只用一句“8 NVIDIA B200 GPUs for both synthesis and training”；没有总 GPU-hours、美元成本、人工小时、失败类型分布；Appendix A.1 仍用 GPT-5.5 做裁判、O2W 依赖 live websites；Table 2 的“World size growth 30.9 KiB”与“World state size 59.3 MiB”在 17.8 个状态下难以自洽，论文未解释；实验只覆盖英文个人电脑世界、36 个人物、两个 Qwen 规模，没有安全/隐私/真实部署评估。
- **为什么重要**：“scalable”是标题级主张；如果每个接受任务需要大量 rollout、裁判调用和人工设计的 constitution，341 个任务的成本可能并不低。安全动机（真实世界 RL 有风险）也没有对应的安全评估，读者无法判断合成世界是否真的降低了风险。Table 2 的单位不一致会影响对世界规模的判断，也会让复现者难以核对资源需求。
- **当前能够得出的判断**：论文报告了细粒度的 per-task token 统计和硬件配置，这是加分项；但没有总成本/失败率，无法验证“可扩展”的经济性。适用范围是“英文、单人、个人电脑、三接口、两个 Qwen 规模”；不能外推到多用户、企业环境、非英文或真实机器。Table 2 的数字问题更像统计口径/单位错误，需作者澄清。
- **如何验证或补强**：报告总合成成本（GPU-hours、API 费用、人工小时）与每个接受任务的成本；给出候选被拒原因分类与比例；做小规模 scaling law（成本 vs 接受任务数/质量）；补非英文、多用户、安全红队实验；澄清 Table 2 的单位。
- **严重程度**：次要问题。

## 6. 审稿式总评

> 作者发现通用计算机使用智能体的训练受限于“单应用、单接口、浅状态”的合成环境，因此提出 WildAWM：用开源模型从人物设定出发逐日合成带 GUI、MCP、CLI 的个人电脑世界，再用五道执行式质量门筛出可解、够难、验证器可靠的任务。实验在 8 个 OOD 基准、两个 Qwen 规模上表明，只在合成世界训练可以带来平均 +8.21/+10.58 的提升；其中“环境更大更多样”“每个任务至少有一个 agent 能解”“质量门消融有贡献”这几项证据较强，但“提升有多少来自合成世界而非教师蒸馏”“验证器是否与人类真值一致”“60% 的难度估计有多精确”仍缺少充分支持。本文最有价值的部分是把环境合成、任务生成、验证器质量控制和长时程 RL 串成一条可复现的工程链路，并公开了 341 个环境—任务对；最大的审稿风险是教师蒸馏混杂与验证器自证。

- **问题定义清晰度**：强。论文把 CUA 环境合成的三个具体挑战（可解性、难度、验证器可靠性）说得很清楚，Table 1 的定位也能让读者一眼看出与 AWM、CUA-Gym、CUA-Universe 等工作的差异。
- **创新性证据**：中。多日跨界面世界、五道质量门、全开源合成、RL 配方都是实质性的集成创新，但组件大多是已有思想的组合；缺少“单接口世界”“专有模型生成器”“同等教师轨迹预算”的对照，因此“新在哪里”有一部分仍靠作者叙述。
- **方法可信度**：中。确定性重放、五层世界验收、三层裁判和反事实探测设计得很细，工程可信度高；但验证器没有人类真值，反事实探测可能奖励固执，质量门的效果也只在 4B 模型上做了消融。
- **实验支持力度**：中。8 个基准、2 个规模、门控/RL 消融和行为分析构成了较完整的证据链，主结果方向可信；但 33 个任务的验证集、单次运行、无置信区间、子集与量化设置差异，使具体数字的稳健性不足。
- **可复现性**：中。代码、数据、模型、项目页均公开，Appendix 给了大量提示词和超参数；但评测仍依赖 GPT-5.5 裁判、live websites 和未报告的总计算成本，缺少 seeds/CI，完整复现主结果的门槛不低。
- **综合阅读价值**：高。即使不完全接受其结论，这篇论文对“如何设计可执行、可验证的智能体环境”和“如何用执行证据做质量控制”给出了可复用的工程模板，适合作为 CUA 数据合成方向的参考。
