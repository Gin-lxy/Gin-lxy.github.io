## 0. 一句话结论

AREX-2 把"同一任务上的多轮迭代改进过程"本身做成训练数据：在以机器学习工程（GitHub 仓库）与算法编程（在线评测）为源的、带可执行评分函数的环境中，让 teacher agent 在小时级预算、数百次工具调用下反复提交与修订，再以"整条轨迹按最终成绩筛选、失败轮保留在上下文中、只对推进性决策计算 loss"的方式模仿学习到 Qwen3.8-27B。论文报告的 MLE-bench Lite（81.8）与 Frontier-CS（70.7）结果领先于其列出的开源模型，四个 deep research 基准（BrowseComp 84.0、HLE 文本子集 52.6、GAIA 92.2、DeepSearchQA 93.8）超过同组旧配方模型且未新增研究类训练数据，分数随测试时轮数预算继续上升。但跨域迁移这一核心主张缺少"同基础模型、同 harness、仅旧配方数据"的直接对照，训练数据规模、teacher 模型与全部训练超参未报告，因此现有证据只支持"在这套评测设置下的六项基准上有效"，不足以支持"普遍提升了 Agent 的自改进能力"。

## 1. 论文具体想解决什么问题？

- **背景与任务**：LLM agent 处理困难任务（训练一条 pipeline、写一个受评分函数约束的程序、回答一个研究问题）通常依赖"尝试—测量—修订"的循环。作者把循环的一次完整迭代称为一个 round，并指出：现有系统中这个循环主要实现在 scaffold/harness 里——由外部框架决定何时重试、保留什么，模型只被要求一次产出一个尝试（§1；引 AIDE、AlphaEvolve、AI Scientist 等工作）。本文要把这个循环"搬进模型内部"。
- **作者对 self-improvement 的定义**：在单任务内的 test-time scaling——给定同一任务更多轮数，agent 能靠自己的判断把分数变得更高（§1）。形式化上（§2.1，Eq. 1–5）：轨迹为 $\tau=(y_0,f_0,y_1,f_1,\ldots,y_n,f_n)$，$s_t=\max_{k\le t}S(y_k)$ 为前 $t$ 轮的最好分数，第 $t$ 轮的期望增益为 $r_t=\mathbb{E}_{\pi_\theta}[s_t-s_{t-1}]$，总改进为

  $$\mathbb{E}[s_T]-s_0=\sum_{t=1}^{T} r_t .$$

  作者进一步定义有效轮数 $T^{\ast}=|\{t\le T: r_t>\epsilon\}|$ 与平均增益 $\bar r$，使总改进约等于 $\bar r\,T^{\ast}$（误差至多 $\epsilon T$）：reflection 决定 $\bar r$（一轮值多少），long-horizon execution 决定 $T^{\ast}$（能保持多少轮有效）。二者合称 long-horizon reflection。
- **现有做法的不足（作者主张）**：当前 agent 训练数据是"单次尝试 + verifier 过滤"构建的——给出任务、模型产出解、verifier 判 pass/fail、保留通过的解（§1；引 SWE-Gym、SWE-smith、R2E-Gym），其思想源头是 STaR/ReST 一类"在自己的成功输出上微调"。这种数据只展示"正确解长什么样"，不展示"一个解是如何被改进的"；中间尝试、收到的反馈、随后的修订全被丢弃；而且立即通过的样本最易收集，长程改进过程最先丢失。作者由此断言：agent 在一个问题上工作数小时、测量并反复修订、最终远超起点的轨迹，在训练数据中"几乎不存在"。
- **哪些条件不好**：论文没有用实验刻画已有系统在何种条件下失效（无对照实验），而是从数据构造方式给出机理论证。这属于**作者主张**：论文未提供任何对现有训练数据集的长程轨迹占比统计。
- **新的现象与被忽略的问题**：作者认为瓶颈不是单次求解能力，而是模型缺少两类行为——用反馈改进（reflection）和在多轮中维持有效改进（long-horizon execution）；并认为这两者是"元技能（meta-skill）"，与领域无关（§1、§2.1 末段）。
- **核心假设**：long-horizon reflection 是与领域无关的元技能，可以在"适合监督"的领域学会，并迁移到别的领域。据此选择两个训练域：机器学习工程与算法编程，理由有三（§1）：反馈无歧义（验证分数或评测判决直接说明修改是否有效）、存在持续改进空间（从 baseline 到调优集成、从暴力到近最优，长轨迹被奖励）、素材丰富（GitHub 与在线评测题目）。
- **最终要验证的假设**（§3 开篇）：这种长程改进轨迹 (1) 能在源域产生强表现；(2) 学到的能力能扩展到 deep research；(3) 训练后的 agent 能把额外的测试时计算转化为继续进步。

区分层次：test-time scaling 与 agent 训练数据过滤是领域早已存在的一般问题；"长程改进轨迹在现有数据中缺失"是本文提出的观察，但只有论证没有测量；本文实际解决的子问题是——**给出一种可执行的构数据流程，并用一次具体训练验证它在这六个基准上的收益**。

## 2. 创新点是什么？

一段话概括：真正的技术增量不在模型或算法结构，而在**训练数据的构造与监督方式**。论文把"多轮改进"作为一等公民：先用 teacher model 把现成代码源编译成带评分函数的环境，用大预算跑出含失败与回退的长轨迹，再在轨迹级筛选（只看最终成绩与过程合规）与 step 级打标（只对推进性决策算 loss）的约束下做模仿学习；同时把 deep research 数据保持不变，以便把后者上的增益解释为跨域迁移。

逐项分析：

**创新点 1：环境与轨迹的构造管线（核心贡献，§2.2–2.3）**

- 新增机制：环境定义为二元组 $e=(\sigma,S)$（任务 + 评分函数）。对仓库源，teacher 读代码、识别其度量、写出"提高该指标"的任务、在 agent 不可见的 held-out split 上计算分数的评分脚本、以及装好仓库和数据的 sandbox；对评测题目源，任务即题面，sandbox 提供编译器与样例，$S$ 为隐藏测试给分——凡评测允许就给 graded 分数（如通过测试比例、相对已知最优的启发式质量），而不是二值判定，因为二值判定只说"没成功"，graded 分数让每一轮都携带信息（§2.2）。
- 环境准入是两条执行检查：源自带的 reference 解（仓库自身模型或评测的 accepted submission）必须能在 $S$ 下运行并得分（证明环境可用）；一个简单 baseline（原仓库或直白的第一版程序）必须显著低于 reference（证明有改进空间）。过不了第二条就丢弃。
- 轨迹由 teacher agent 在三条设计条件下产生（§2.3）：**更多轮数**（预算为小时级、每任务数百次工具调用，且明确告知 agent 预算，使其先立 baseline、早轮测量、后轮按测量结果修订）；**operational knowledge**（环境如何工作的知识——仓库暴露哪些 API、数据加载器期待什么、约束下允许什么优化——任务陈述不给出，agent 通过读源码与文档、检索代码依赖的论文与库、跑小实验获得；其中一部分以 skills 形式预置：general skills 提前从 ML 仓库与常见实践整理，task-specific skills 由围绕任务的检索构建且排除任务本身的材料）；**反馈进循环**（每轮以提交结束，agent 在决定下一步之前先看到分数与环境报告，在此发生 reflection：对照预期、保留或回退、形成下一个假设；掉分的轮次不删除，因为"对失败的反应"正是要学的东西）。
- 与最接近已有方法的差异：STaR/ReST 保留成功输出；SWE-Gym/SWE-smith/R2E-Gym 用 verifier 过滤单次尝试；AIDE/AlphaEvolve 把循环放在 scaffold。AREX-2 的差异是把"过程"整体保留下来当作监督对象。
- 不可替代性证据：**部分**。§3.3.3 的 stage-wise ablation（Fig. 6）显示 skills、轮数与训练各自有贡献，但没有"用同样多轮轨迹、但改回单轮/成功轮筛选"或"不做 loss masking"的对照，因此该设计中最有辨识度的两点（保留失败轮、只对推进决策算 loss）都缺少孤立消融——这是分析者（审稿人判断），不是论文报告。

**创新点 2：轨迹级筛选 + step 级 loss masking 的监督方式（§2.4）**

- 轨迹整条保留或丢弃，条件有二：最终成绩高（最好提交达到"相对 reference 设定的阈值"——论文未报告具体阈值）且过程合规（transcript 符合 user-assistant-tool 格式、每次工具调用都有 observation、以良构状态终止、未违规如从 held-out split 重建答案或泄露凭证）；**对单轮不作要求**，因此保留的轨迹可以包含失败运行、回退与放弃的路线。
- 监督粒度：整条轨迹作为 context 保留，按 step（一次决策 + 到下一个 observation 前发出的动作）分组，loss 只加在"使解前进"的决策上——诊断失败、修复、换策略、跑下一个实验、提交更好的解；无进展的 step（重复 polling、返回无新 observation 的调用、近似重复的轮次）、系统消息、环境报告、检索文档都不算 loss。这样失败本身留在 context 里，模型学到的是"失败之后怎么反应"。
- 与"直接对全轨迹做 SFT"的差别在于避免模仿失败轮本身。原文没有给出对照实验证明这一细节的收益；"无进展 step"的判定规则只给了启发式举例，判定算法、命中比例、对被 mask 掉的 token 占比均未报告。

**创新点 3：跨域迁移主张（把 deep research 的增益读作 transfer，§2.4 末、§3.2）**

- 做法：新增两个域的长程轨迹 + 原 AREX 配方（Lu et al., 2026）中不变的 deep research 数据，微调 Qwen3.8-27B。作者称"新轨迹是相对上一版配方的唯一差别"（**作者主张**），因此 deep research 上的增益"不来自新的研究类数据"。
- 但 AREX-2 的基础模型是 Qwen3.8-27B，而旧对照 AREX (4B)/AREX (122B) 的基础模型、数据与训练细节均未报告，论文也未提供"Qwen3.8-27B + 仅旧配方数据"这一控制组 → 无法确认迁移增益的归因（详见 §5 质疑一）。
- 另外，训练轨迹中含"检索论文与库"这类行为，因此 deep research 的增益也可能部分来自"检索技能"而非抽象的长程反思——论文未区分这两种解释（审稿人判断）。

**创新边界**：根据本文的 related work 与实验对比，只能确认作者声称的差异——环境合成、拒绝采样式筛选、loss masking 都是已有组件的重新组合与明确化；论文没有声称某个组件"首次提出"，也没有与同代的 RL 式自改进训练方法（如工具调用 RL、SWE agent RL）做直接比较。是否构成"首次把长程改进轨迹用于迁移训练"，还需要更完整的文献检索。

## 3. 作者如何解决？

**直觉**：如果一个模型只见过"正确的最终解"，它学不到"如何从错误走向正确"。因此作者构造的数据展示的是"工作过程"：一个强 agent 在一个能立刻打分的环境里，花数小时、几百次工具调用，反复测量与修订；把这一整段过程（含失败）喂给模型，但只在"推动分数前进"的决策上算 loss。为了让这种昂贵的监督物有所值，数据源要选在"改进了多少马上就能知道"的领域；作者赌的是学到的东西（如何用反馈、如何补齐环境知识、失败后如何继续）不绑定具体领域。

按运行流程展开（Fig. 3）：

![AREX-2 总览：环境构建、轨迹构造与自改进模型三个阶段](/images/dailypaper/2026-10-01/2609.38288_fig3.png)

图中三栏对应论文的三段流程。左栏"Constructing Environments"：从 GitHub 仓库与在线评测两类源出发，teacher model 分析源、构造环境并执行验证，只有通过验证的保留（绿色 Valid Environment），否则丢弃（红色 Discard）——这一步保证每条环境既有可运行的评分函数、又有可证明的改进空间。中栏"Constructing Trajectories"：LLM agent 在环境内"提交解—看反馈—改进策略—反思修订"循环多轮，途中按需查询 operational knowledge（read/acquire/experiment），并搜索外部资料；全部过程（含失败）落入下方数据库成为训练数据。右栏"Self-Improving Model"：用这些轨迹训练出模型后，测试时依然是"尝试—反馈—反思—改进"的多轮循环，作者期望的形态是分数随轮数上升（右下小图）。三栏共同回答的因果链是：**环境保证反馈可信 → 轨迹记录改进过程 → 训练把过程内化为模型行为**。

具体步骤：

1. **输入**：GitHub 仓库（ML 工程任务源）与在线评测题（算法编程源）。仓库有代码和数据但没有"任务"，评测题有题面和测试但没有可迭代 sandbox，两者都还不是环境。
2. **环境构造与准入**（§2.2）：teacher model 产出任务、held-out 评分脚本、sandbox；两条执行检查（reference 能得分、简单 baseline 显著更低）决定准入。
3. **轨迹生成**（§2.3）：teacher agent 在大轮数预算下运行，三条设计条件如上；skills 文档放进其上下文，使其强到足以产出"值得模仿"的轨迹。
4. **轨迹筛选**（§2.4）：整条按"最终成绩 + 过程合规"取舍，单轮不作要求。
5. **监督构造**（§2.4）：全轨迹留作 context；loss 只加在推进性决策上。**教学简化示例**（非论文实验）：假设某轮 agent 把学习率改大导致验证分数从 0.80 掉到 0.72，下一轮它读日志、把改动回退并换成数据增强，分数升到 0.83。AREX-2 的监督会把"掉分"这一步保留在上下文但不计算 loss，而把"读日志诊断→回退→换策略"这些决策算作 loss 目标；这**不是**论文中的真实样本，只用于说明筛选粒度。
6. **训练**（§2.4）：在"新轨迹 + 原 AREX deep research 数据（不变）"的混合上模仿学习（fine-tune）Qwen3.8-27B 得到 AREX-2。**论文未报告**是否使用 RL、训练数据量、混合比例、epoch、学习率与算力。
7. **推理阶段**（§3.1、§3.3）：coding 域使用"our optimized harness"；deep research 用双层递归研究流程——inner loop 收集证据并产出临时答案，outer loop 依据模型自身置信度与轨迹状态决定接受、精炼或重启；非 coding 评测最多 300 次 inner turns、总 1500 turns。

模型自主决定的部分：何时提交、改什么、是否回退、自评置信度、是否重启。固定流程控制的部分：sandbox 与评分脚本、预算与时间上限、格式与合规检查、loss masking 规则。

## 4. 解决得怎么样？

### 4.1 实验设置

- **任务与基准（§3.1）**：六项基准覆盖四类能力——Frontier-CS（算法编程，Agent Track，188 题，开放性问题、graded 分数）、MLE-bench Lite（端到端 ML 工程）；BrowseComp、HLE、GAIA、DeepSearchQA（deep research 与通用 agent 推理）。
- **指标**：DeepSearchQA 报 F1，MLE-Lite 报 Any Medal（获得奖牌的竞赛占比，三次种子平均），其余报 accuracy；HLE 用文本子集（Table 2 注：带 * 者为全量 HLE 结果）。
- **协议**：非 coding 基准沿用 AREX 协议（inner turns ≤ 300、总 turns ≤ 1500）；Frontier-CS 用官方 Agent Track，每任务 5 小时；MLE-Lite 用 OpenMLE 协议，每任务 12 小时。MLE-Lite 上 AREX-2 在**上下文带 skills** 的条件下评测（§3.1）。
- **基线来源混杂**：Table 1 注说明 Frontier-CS 上带 * 的结果（DeepSeek-V4-Pro/Flash、Kimi-K2.7-Code、GLM-5.3-Flash）由作者复现，MLE-Lite 各模型结果"由 OpenMLE 复现并报告"；闭源模型数字来自各自公开报告。Table 2 中 AREX(122B)/AREX(4B) 为同组旧配方模型，是最关键对照。
- **主实验 / 消融分工**：§3.2（Table 1–2）回答"强不强"；§3.3.1–3.3.2（Fig. 4–5）回答"是否把更多预算转化为更好解"；§3.3.3（Fig. 6）回答"skills、训练、轮数各贡献多少"。**论文无附录**，没有额外的补充实验。

### 4.2 关键结果

### 4.3 机制证据

![Frontier-CS 上带反馈的轮次/时间扩展：best-so-far 分数随时间变化](/images/dailypaper/2026-10-01/2609.38288_fig4.svg)

Fig. 4（§3.3.1，188 题、每题 5 小时、每轮提交后能看到分数与评测反馈）：AREX-2 在 1 小时达到 54.4、2 小时 65.9、5 小时 70.7；DeepSeek-V4-Pro 在 2 小时后停在 44.7，DeepSeek-V4-Flash 在 3 小时后停在 39.1。第 2–5 小时 AREX-2 仍增 4.8 分，其中最后一小时增 2.2 分。图例还给出了其基础模型 Qwen3.8-27B 的曲线（5 小时 39.6）与 Kimi-K2.7-Code 54.7、GLM-5.3-Flash 50.4——虽然正文没有展开，图上其实包含了一个"同 harness 下基础模型 vs 训练后模型"的对照，这比正文的表述更有信息量。作者据此主张 AREX-2 的优势来自持续改进而非好的开局，对应 $T^{\ast}$ 更长。

Fig. 5（§3.3.2，未随文下载，按原文曲线核对）：在训练中未加入任何研究类轨迹的 BrowseComp 上，评测全程不给正确答案反馈，AREX-2 的精度随平均轮数从 64.8（47 turns）升到 84.0（143 turns）；同流程下的 AREX (122B) 在约 140 turns 时精度约 71.5，落后 12 分以上，且其最终精度 82.5 被 AREX-2 用不到一半的轮数超越；作者称每轮增益约为对方三倍，对应更大的 $\bar r$。这条曲线是全文最强的"无外部正确性信号也能靠自身判断继续改进"证据。

![MLE-bench Lite 上的阶段式消融阶梯](/images/dailypaper/2026-10-01/2609.38288_fig6.svg)

Fig. 6（§3.3.3）是唯一把方法拆开的实验，五级阶梯全部在 MLE-bench Lite 上：

| 阶段 | 模型 | skills | 轮数 | Any Medal |
| --- | --- | --- | --- | --- |
| M0 | 基础模型 Qwen3.8-27B | 无 | 基础 | 28.8 |
| M1 | 基础模型 | +general skills | 基础 | 41.2 |
| M2 | 基础模型 | +task-specific skills | 更多 | 68.2 |
| M3 | AREX-2 | 同 M2 | 同 M0/M1 | 75.8 |
| M4 | AREX-2 | 同 M2 | 同 M2 | 81.8 |

它支持三条观察（§3.3.3）：operational knowledge 有效（不训练也能从 28.8 升到 68.2）；训练在 skills 之外仍有增益（M2→M4 同 skills 同轮数差 13.6；轮数更少时 M3 也比 M2 高 7.6）；训练后的模型能把更多轮数变成继续提升（M3→M4 +6.0）。

**机制证据的边界**：以上实验说明"方法有效"以及"skills / 训练 / 轮数各自有贡献"，但没有说明"为什么有效"的细节——失败轮保留与 loss masking 这一最独特的设计没有任何隔离对照；$\bar r$ 与 $T^{\ast}$ 是从聚合曲线反推的解释，不是直接测量；也没有排除"更强的 harness / 更长预算 / 更多 skills 篇幅"等替代解释（除 M2–M4 的轮数控制外）。论文没有报告任何"移除某个组件后掉多少分"的单因素消融。

### 4.4 成本与适用范围

论文实际报告的成本：

- **评测成本**：MLE-Lite 每任务最多 12 小时、Frontier-CS 每任务 5 小时、deep research 评测总轮数上限 1500（§3.1），属于高预算 agent 评测。
- **数据生成成本**（定性）：每条轨迹"小时级、每任务数百次工具调用"，且需要能胜任的 teacher agent 与预置 skills；**论文未报告**环境数量、轨迹条数、token 数、teacher 模型身份与数据生成总算力。
- **训练成本**：**论文未报告**（数据规模、混合比例、epoch、学习率、算力均无）。
- **人工标注**：论文未提及使用人工标注，也未说明过程合规检查（如"未从 held-out 重建答案"）由规则、模型还是人工完成（论文未报告）。
- **外部依赖**：评测在六个公开基准环境内进行；仓库构建依赖 GitHub 与在线评测平台的素材；teacher 是否为闭源模型未说明。
- **公开物**（官方项目页 github.com/VectorSpaceLab/AREX-2，论文首页所指）：发布评测代码与数据集配置，模型发布于 HF 集合 BAAI/AREX-2；训练轨迹未发布，且明确把 benchmark 文件、模型输出、凭证与运行产物排除在仓库之外。数据侧不可复现。

**适用范围**：结论适用于"有可执行评分函数、且评测环境允许长时间多轮迭代"的场景（本论文的六个基准）；对短轮次交互、无可验证反馈或不允许外部工具的任务，论文没有提供证据。仍未解决的问题包括：与最强系统在 BrowseComp/HLE 上的差距、GAIA 未领先小模型、MLE-Lite 比较中 skills 条件的公平性、以及跨域迁移缺少直接对照。

## 5. 最容易受到审稿人质疑的地方

#### 质疑一：跨域迁移（核心主张）缺少同基础模型、同配方的直接对照

- **原文依据**：§2.4 称"新轨迹是相对上一版配方的唯一差别"，§3.2 与 Table 2 用 AREX-2 超过 AREX (4B)/AREX (122B) 作为迁移证据；但论文未报告旧 AREX 的基础模型、数据构成与 harness，也没有"Qwen3.8-27B + 仅旧配方数据"这一控制组。
- **为什么重要**：这是论文最主要的科学主张（long-horizon reflection 是 domain-agnostic meta-skill）的直接证据；若无法排除基础模型换代与 harness 差异，就无法确认 deep research 的增益来自新轨迹数据。
- **当前能够得出的判断**：存在混杂因素，证据不足。作者对该差异的因果归因尚不能成立。
- **如何验证或补强**：在同基础模型、同 harness、同数据量下比较"旧配方数据"与"旧配方 + 新轨迹"；并附基础模型在相同双层研究流程下的分数。
- **严重程度**：主要问题。

#### 质疑二：训练数据与 teacher 的关键信息全部缺失，方法不可复现、数据质量不可评估

- **原文依据**：§2.2–2.4 只给流程不给量——环境数、轨迹数、筛选阈值（"相对 reference 设定的阈值"）、skill 文档的篇幅与来源、训练数据混合比、超参与算力均未报告；PDF 无附录（12 页）。"无进展 step"的判定只举了启发式例子（重复 polling、无新 observation、近似重复轮次），未给规则细节与命中比例。
- **为什么重要**：影响可复现性，也影响对"数据是本文最强卖点"这一说法的可信度——读者无法判断数据规模效应、无法判断 loss masking 实际屏蔽了多少 token。
- **当前能够得出的判断**：当前材料无法确认；项目页确认只公开评测代码与数据集配置，训练轨迹不公开。
- **如何验证或补强**：给出数据统计表（环境数/轨迹数/轮数分布/失败轮占比/mask 比例）、阈值敏感性分析、teacher 模型说明与最小可复现的数据样本。
- **严重程度**：主要问题。

#### 质疑三：MLE-Lite 的对比公平性——带 skills 的评测与混合来源的基线

- **原文依据**：§3.1 与 Table 1 注明确说明 AREX-2 在 MLE-Lite 上"上下文带 skills"评测，且各基线数字"由 OpenMLE 复现并报告"；Fig. 6 显示仅靠 skills + 更多轮数，基础模型不训练即可从 28.8 升到 68.2。Frontier-CS 一侧则注明部分基线由作者复现、闭源数字取自公开来源，且 AREX-2 "runs with our optimized harness"（§3.3.1）。
- **为什么重要**：直接影响实验结果的可比性——领先幅度（+8.1 / +16.0）是在何种统一条件（相同时间预算、相同 skills 配额、相同 harness）下取得的，论文未逐项交代。
- **当前能够得出的判断**：论文对 skills 的作用做了披露并给出消融（这是优点），但不足以确认与基线的评测条件完全对等；属于部分披露下的公平性风险。
- **如何验证或补强**：报告无 skills 条件下 AREX-2 的成绩；公开各基线的轮数/时间预算与是否使用外部知识文档；在同一 harness 下重跑全部对照。
- **严重程度**：主要问题。

#### 质疑四：$\bar r$ 与 $T^{\ast}$ 是解释，不是测量；"刷分曲线"缺少机制层面的直接证据

- **原文依据**：§2.1 的 Eq. 1–5 定义了这两者，但 §3.3.1–3.3.2 度量的是时间/turn 与聚合分数曲线，"What it verifies"段落把曲线形状读作"有效视界长""每轮增益约三倍"；无逐轮 $r_t$ 统计、无失败轮后恢复率、无对 scaffold 依赖程度的检验（BrowseComp 场景本身由双层循环 scaffold 驱动）。
- **为什么重要**：这决定论文的机制解释是"有相关性"还是"有因果"；也决定"long-horizon reflection 被学会"与"更长预算下 scaffold 更好用"能否区分。
- **当前能够得出的判断**：相关性证据；机制解释未被直接验证。
- **如何验证或补强**：按轮统计 $r_t$ 的分布与失败轮后的恢复概率；更换 scaffold 复现扩展曲线；用同预算的单轮 best-of-n 对照。
- **严重程度**：次要问题。

#### 质疑五：结果缺少统计稳定性信息，且高预算单次评测的重复性未知

- **原文依据**：Table 1–2 中只有 MLE-Lite 说明为三次种子平均；Frontier-CS 188 题、BrowseComp、GAIA、HLE、DeepSearchQA 均未报告方差、置信区间或多次运行；HLE 一列混用文本子集与全量结果（带 * 标注）；MLE-Lite 的 12 小时、Frontier-CS 的 5 小时预算使重复评测成本很高。
- **为什么重要**：影响结论的可信区间，尤其是 DeepSearchQA 上 0.4 分、GAIA 上 4.9 分这类小差距的解释力。
- **当前能够得出的判断**：论文未报告，无法确认稳定性；按公开信息也无法估计评测的随机性。
- **如何验证或补强**：报告多次运行的标准差与显著性检验（至少对关键对照）；对 HLE 统一使用同一口径重评。
- **严重程度**：次要问题。

## 6. 审稿式总评

> 作者发现 agent 的"改进循环"大多留在 scaffold 里、训练数据只记录单次成功解，因此提出把长程改进过程本身做成监督数据：在带可执行评分函数的 ML 工程与算法编程环境中，用大预算 agent 生成含失败与回退的多轮轨迹，按最终成绩整条筛选，只对推进性决策计算 loss，并混入不变的 deep research 数据训练 Qwen3.8-27B，得到 AREX-2。实验在六个基准、四类能力的条件下表明：源域成绩领先（MLE-Lite 81.8、Frontier-CS 70.7），扩展曲线在带反馈与不带反馈两种设置下都持续上升，阶段消融给出 skills/训练/轮数各自的贡献；其中"轮数继续提升"这一现象与消融的阶梯证据较强，但"跨域迁移由长程反思元技能带来"这一核心因果主张仍缺少同基础模型、同配方的直接对照，训练数据与 teacher 信息也未披露。本文最有价值的部分是明确的问题形式化、可操作的数据配方与诚实的 skills 消融；最大的审稿风险是把一次高预算评测下的领先结果解释为普遍的自改进能力。

简短判断（各项依据见前文）：

- **问题定义清晰度**：强。§2.1 给出 self-improvement 的可用定义与分解（$\bar r$、$T^{\ast}$），并将其与"循环在 scaffold 内"的现状明确区分；边界（单任务内 test-time scaling）界定清楚。
- **创新性证据**：中。增量是"已有组件的新组合 + 问题形式化"，两个最有辨识度的设计（失败轮保留、loss masking）无隔离消融；related work 中对同代 RL 自改进训练方法未做比较。
- **方法可信度**：中。流程自洽、各环节动机清楚，但 data/teacher/超参缺失使数据质量与规模效应无法评估。
- **实验支持力度**：中。六个基准 + 两种扩展曲线 + 阶段消融覆盖面不错，且图上包含基础模型对照；但混合来源基线、带 skills 的比较与缺少方差削弱了关键幅度的解释力。
- **可复现性**：中。模型与评测代码、数据集配置公开（官方项目页），评测协议与预算写明；但训练数据、teacher、超参与阈值未报告，训练侧不可复现。
- **综合阅读价值**：中。对做 agent 数据构造与长程训练的读者有直接参考价值；作为"迁移性"科学结论的证据尚不完整。
