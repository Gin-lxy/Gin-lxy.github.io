## 0. 一句话结论

Harness VLA 把冻结的预训练 VLA（视觉-语言-动作模型，Vision-Language-Action model）降格为一个"可重试的接触密集原语"，与一组小而固定的解析式原语（grounding/staging/transport/navigation/release）一起交给带双层记忆的 LLM 智能体规划器编排，从而在不微调 VLA 的前提下把预训练策略推广到指令重定向、位置交换等部署扰动场景；论文在四个仿真基准上报告了相对冻结 VLA 与所引最强先验基线的大幅提升（LIBERO-Pro +38.6 个百分点、RoboCasa365 +27.1 个百分点、RoboTwin C2R 58.4%，作者主张），但"提升来自分层编排设计"的因果归因仍掺杂测试时预算与闭源规划器主干两个主要混杂因素，且正文与表格存在数字口径不一致，证据强度需要打折。

## 1. 论文具体想解决什么问题

**研究背景与具体任务**。机器人操作（robotic manipulation）的长期目标是让系统按自由形式的自然语言指令在变化的物体、布局与形态下可靠执行任务。当前有两条对立路线（§1）：端到端 VLA 模型直接从机器人轨迹学习接触密集（contact-rich）的视觉运动控制；LLM 编程智能体（coding agent）用语言模型推理去组合显式的感知与控制 API（application programming interface，应用程序接口）。本文的具体任务设定是语言条件操作（language-conditioned manipulation）：环境 $\mathcal{E}$ 在每个时刻暴露观测 $o_t=(I_t^{\text{rgb}}, I_t^{\text{d}}, q_t)$（agent 视角 RGB 图、对齐的度量深度图、机器人本体感知（proprioception）状态），任务由自然语言描述 $\ell$ 与仅在回合结束时给出的稀疏成功信号、二值完成谓词（completion predicate）$\mathcal{G}$ 定义（§2.1）。

**现有做法在哪些条件下表现不好**。作者的主张是两条路线各自把错误的组件放到了过大的职责上（§1）。端到端 VLA 擅长局部的图像条件接触（抓取不规则物体、在紧凑公差下放置、操作对解析控制器脆弱的固定装置），但在偏离训练轨迹分布（trajectory distribution）的部署扰动（deployment perturbations）下急剧退化——语义重定向（semantic retargeting）、目标重绑定（goal re-binding）、物体布局移动、把短技能组合成长流程时，策略可能重复熟悉的训练期行为，而一次不稳定的接触失败即可毁掉整个单体（monolithic）回合（§1）。论文给出的量化证据是 LIBERO-Pro 上的对照（Table 3，PDF p8）：冻结的多种 VLA 在指令重定向（T）/位置交换（S）扰动的八个评测格上大面积崩溃——OpenVLA、NORA 均 0.0%，$\pi_{0}$ 0.3%，$\pi_{0.5}$ 11.0%，作者评测的 $\pi_{\mathrm{RLinf}}$ 50.0%；此前最强已报告基线 RATS 也只有 43.8%。另一侧，解析式原语（analytic primitives，基于运动学/模型的确定性控制器，如逆运动学（inverse kinematics, IK）搬运、腕部旋转、底座移动、夹爪开合与释放）难以处理不规则抓取、受限放置与铰接物体（articulated object）交互，而编程智能体类系统在操作领域往往仍靠扩技能库（skill library）来补能力（§1、§5）。

**作者发现/强调的现象**。论文把部署扰动刻画成"超出冻结 VLA 轨迹分布的空间"，并用 Figure 3 的终端帧对比说明冻结策略的行为对语言条件化很弱：在任务描述重定向而视觉场景几乎不变的 Object-Pro 用例中，$\pi_{\mathrm{RLinf}}$ 重复标准行为而不跟随新指令；在布局交换的 Goal-Pro 用例中，它仍把物体移向训练时的区域（§3.3，Fig. 3，PDF p10）。需要说明：这一"VLA 对扰动脆弱"的现象在领域内早已存在（LIBERO-Pro 等工作本身就在测量），本文的新观察是把该现象归因于"职责分配错误"，并据此提出分解方案；该归因是作者的解释框架，论文没有对"单体架构为何失败"做机制性的因果实验（审稿人判断）。

**作者认为的原因与核心假设**。原因：单体 VLA 被迫在一个策略内同时承担语言接地、长程组合与底层控制，超出了它的训练分布；而编程智能体一侧又试图用手写/自动生成的 API 覆盖物理细腻交互（§1）。核心假设：保持原语库固定且小，让智能体学习"何时、如何"编排它——把语义重定位（semantic re-grounding）、非接触执行与 VLA 再摆位（re-staging）提升到规划器层，冻结 VLA 只负责局部接触密集阶段；这样无需微调即可扩展预训练 VLA 的轨迹分布（§1、§2.3，Fig. 2）。

## 2. 创新点是什么

一句话概括：本文的技术增量不是新模型或新训练方法，而是一套"把冻结 VLA 暴露为单一原语、把编排交给带双层记忆的 LLM 智能体、并保持原语库固定"的系统性框架（training-free 的智能体层 + 一个仅做 SFT 的 VLA 后端），并配套一组机制分析（调用预算曲线、完成归因、原语使用统计）来支撑"分工有效"的主张。其组件（harness、记忆、原语组合、code-as-policies 思想）在既有工作中都有原型，本文属于"已有范式在机器人操作上的新组合与系统性实现"，原创边界主要落在"冻结 VLA 作为可重试原语 + 双记忆学习原语操作范围"这一设计（审稿人判断；论文 Related Work 只对比了各条线的代表工作，是否首次提出还需更完整文献检索）。

逐项分析：

1. **VLA-作为-原语的抽象与固定小原语库（§2.3，Table 1，PDF pp. 5–6）**。新增机制：原语库 $\mathcal{P}$ 是规划器唯一可调用的动作接口，含 6 个解析式原语（move_to、move_pose、rotate_wrist、rotate_pitch、set_gripper、release；RoboCasa365 另加 navigate_to、move_base）与 1 个学习原语 vla_act；vla_act 绑定各基准的冻结 VLA，由规划器给出任务条件提示与早退谓词 $\tau$，执行动作块（action chunk）直到 $\tau$ 满足或块预算耗尽。与最接近已有方法（Code as Policies、ProgPrompt、RATS、Cap-X 等）的差异：不合成可执行代码、不扩技能库，而是发出结构化 JSON 原语调用并在闭环中逐次重建参数；与 ASPIRE（自动扩张技能库）方向正相反（§5）。对应问题：单体 VLA 被迫承担全部职责。证据：$\pi_{\mathrm{RLinf}}$ 冻结权重不变、仅换编排方式后在 LIBERO-Pro 从 50.0% 提到 82.4%（Table 3），说明该抽象确实能在不改模型的前提下改变行为分布；"原语库必须固定"本身没有被直接消融，论文用 ASPIRE 式扩张留作未来工作（§6，审稿人判断）。

2. **双层记忆与"学习原语操作范围"的自举流程（§2.2、附录 A）**。新增机制：仅在单个参考种子 $s_0$ 上做智能体探索（探索期可用 reset、宽裕墙钟预算），把成功轨迹序列化为"空间坐标替换为符号化感知查询"的 JSONL 过程记忆（Task Specific Memory（任务特定记忆）的 procedural trace + 语义审计 JSON），并把可复用的成功规则（success rules）与失败模型（failure models，如空抓取、假成功）沉淀到跨任务的 Global Memory（全局记忆）；部署期禁用 reset、缩短预算，检索记忆并按当前 RGB-D 重新接地（re-ground）。与最接近工作（Voyager 的持久记忆、SWE-agent/OpenHands 的 harness）的差异：把记忆机制与 VLA 后备的接触原语结合到物理操作（§5 作者自述的空白点）。证据：附录 A 给出记忆文件格式与"结合结构、不重放字面坐标"的规则；Table 5 的零样本对照（去掉记忆后 Goal-S 从 87.0% 掉到 31.0%）间接显示记忆的贡献。该记忆设计如何对应问题：把"每任务一次成功探索"变成可迁移的结构先验，降低对 VLA 泛化的要求。

3. **机制分析套件（§3.3，Fig. 4/6，Table 19/20）**。新增内容：调用上限曲线（Fig. 4）把"允许的最大 vla_act 调用数 $k$"与累计成功率联立，用受控的调用预算探针检验"稀疏但可重试的调用"有效性；完成归因（Fig. 6）统计成功回合由解析式还是 VLA 触发最终完成谓词；使用统计（Table 19/20）给出各环境下原语类别配比（LIBERO 解析式 84.2%、vla_act 15.8%；RoboCasa365 vla_act 35.3%；RoboTwin C2R vla_act 47.4%）。与"只报总成功率"的一般工作相比，这组分析把"分工假设"变成可检验的中间量。局限见 §4.3 与 §5：这些证据部分是描述性的，未把"再摆位质量"与"重试次数"分离。

**什么不算创新**（审稿人判断）：没有新模型架构、没有针对 VLA 的强化学习或偏好优化（§6 明确列为未来工作）；VLA 后端（$\pi_{0.5}$-SFT 检查点、RLDX-1）与解析控制器都复用现成组件；Flash Mode 是把成功序列编译成任务卡（task card）的重放工程（附录 G），属工程改进；"更强 LLM 规划器带来更好结果"（附录 H）是观测到的相关性，不构成本文方法性创新。

## 3. 作者如何解决

**直觉说明**。把一次长程操作想成"搬运路线 + 若干接触关口"：路线（去哪、以什么姿态接近、搬到哪里、何时松手）用确定性运动学原语就能可靠完成；真正需要"手感"的只有抓取、放置、按压、拧龙头这类接触密集关口，而这些恰恰是预训练 VLA 表现最好的局部能力。于是论文的解法不是让 VLA 变强，而是让它"少干活"：规划器负责理解语言、在当前场景里重新定位目标、把机器人摆到 VLA 熟悉的局部观测/触碰位姿，然后调用冻结 VLA 做一小段接触动作，观察结果，必要时再次摆位重试。

**按实际运行流程展开**（§2、附录 A/E）：

1. 输入：任务描述 $\ell$、RGB-D 观测、机器人状态（本体感知 + 末端执行器（end-effector）位姿与夹爪状态）。规划器看不到仿真器的特权信息（物体真值位姿、控制器内部量），只能通过 RGB 图像语义识别 + 在预计算世界图上索引像素来获得度量定位（附录 E.2 的感知隔离规则）。
2. 执行循环：规划器 $\Pi$（Codex 或 Claude Code）每回合只写一条 JSON 原语调用到 command.json；环境 worker 执行直到该原语的后置条件（post-condition）满足或内部预算耗尽，写回 state_NN.json、log_NN.json、新观测与同步标志；规划器读取新证据后再决定下一动作（文件中介的 Read-Eval-Print Loop（REPL，读取-求值-打印循环），附录 A，Table 8）。循环直到完成谓词满足或步数预算耗尽（§2.1）。
3. 谁来决策、谁来固定流程：规划器决定原语选择、参数绑定（目标坐标来自当轮感知/记忆）、vla_act 的提示与调用时机，以及是否重试或换策略；固定流程控制 JSON 序列化、原语内部执行、后置条件、预算与审计文件写入。二者边界明确——原语库在评测前冻结，规划器不能发明新原语（§2.3）。
4. 两个阶段（§2.2）：探索自举（bootstrapping）阶段在单个参考种子（seed $s_0$）上让智能体自由尝试摆位顺序、预接触位姿、vla_act 调用时机与早退阈值，成功后把经验写成任务特定记忆（含"把具体坐标参数化为符号感知查询"的 JSONL）与全局记忆；严格部署阶段禁用 reset、压缩预算，检索并动态重接地记忆轨迹来求解新种子/扰动。
5. 是否需要训练：框架本身无训练；唯一训练环节是 RoboTwin 后端 LingBot-VLA 的监督微调（supervised fine-tuning, SFT）（附录 D.3，Table 15：AdamW、学习率 $1\times 10^{-4}$、全局 batch 256、chunk size 50、flow steps 10、FSDP2、bf16/fp32 混合精度），此后冻结；LIBERO/LIBERO-Pro 用 RLinf 发布的 pi05_libero130_fullshot $\pi_{0.5}$-SFT 检查点（记 $\pi_{\mathrm{RLinf}}$，完全冻结），RoboCasa365 用官方 RLDX-1 检查点（冻结）。
6. 推理阶段的变化：策略参数零变化，变化全在外部——多轮文件往返、记忆检索与重接地、解析原语的对位与再摆位、可重试的 vla_act 调用；Flash Mode（§4.1）进一步把成功序列编译成任务卡，用 VLM（vision-language model，视觉-语言模型）定位锚点后按序重放，无需在线规划（重接地公式见附录 G 的 $\Delta\mathbf{x}_i=\mathbf{x}^{\text{ref}}_i-\mathbf{a}^{\text{ref}}_{j(i)}$、$\mathbf{x}^{\text{run}}_i=\widehat{\mathbf{a}}_{j(i)}+\Delta\mathbf{x}_i$，Eq. (1)）。
7. 输出：每个回合的审计 JSON 与命令 JSONL；基准成功信号决定分数（附录 C）。真实双 Franka（附录 F 之外的第 4 节）用同一分工：Codex(GPT-5.5) 调用冻结的 $\pi_{0.5}$ 桌面清理策略做抓取/交接/放置，解析原语负责预接触摆位、自由空间搬运与转向，人工负责 reset 与成功判定（§4.2）。

## 4. 解决得怎么样

#### 4.1 实验设置

- **基准与规模**（附录 C，Tables 10–14）：LIBERO 四套件（Spatial/Object/Goal/LIBERO-10）各 10 任务 × 10 个留出种子 = 400 回合；LIBERO-Pro 八格（四族 × 指令重定向 T / 位置交换 S）各 10 任务 × 10 种子 = 800 回合；RoboCasa365 target50（Atomic-Seen 18 + Composite-Seen 16 + Composite-Unseen 16 任务）× 每任务 5 个留出种子 = 250 回合；RoboTwin C2R 50 任务 × 5 个随机化种子 = 250 回合。主协议共 1,700 个报告回合，另有 Flash Mode 对比的 800 回合独立批次（Table 7）与零样本/真实世界补充实验。所有基准的成功都由各自的二值完成谓词判定（附录 C 开头）。

#### 4.4 成本与适用范围

- **训练成本**：框架无训练；唯一训练为 LingBot-VLA 在 RoboTwin 轨迹上的 SFT 后训练（Table 15 给出超参：lr $1\times 10^{-4}$、全局 batch 256、chunk 50、flow steps 10、FSDP2 混合精度）；GPU 数、训练时长、数据规模论文未报告。三个冻结 VLA 中，$\pi_{\mathrm{RLinf}}$ 与 RLDX-1 为外部发布检查点；LingBot-VLA 检查点是否公开论文未报告。
- **推理/运行成本**（Table 7，附录 G）：每个原语一次文件往返；Table 7 的计时显示 Codex 高推理档平均规划耗时 529.23 秒/回合、无推理档 344.17 秒、Flash 源轨迹工具耗时 56.17 秒（三者口径不同，论文声明不构成端到端加速证据）。规划器的 token 用量、API 调用次数与金额论文未报告。自举阶段的尝试次数与墙钟时长论文未报告（只说"宽裕预算 + 可用 reset"）。
- **外部依赖**：三个闭源规划器主干（GPT-5.5、Opus-4.7、GPT-6 Astra）；Flash 重放依赖 VLM 定位锚点；仿真侧依赖 Robosuite/MuJoCo 内置求解器与各基准环境；真实侧两台双 Franka（base + wrist 相机 + RealSense D455 度量定位，§4.2）。
- **人工与存储**：真实世界的场景重置与成功判定由操作员完成（"human in the loop"，§4.2）；记忆为 JSON/JSONL 文本文件、审计与日志逐回合落盘（Table 8），存储成本低但回合数×文件数的系统复杂度在真实部署中需要工程化。
- **已改善/未解决**：改善——冻结 VLA 在扰动基准上的成功率大幅抬升（LIBERO-Pro 50.0→82.4，Table 3）、零样本指令重定向能力保留（79.0%，Table 5）、单一 harness 跨三个体系可移植；未解决——开放环的规划器-VLA 反馈（§6 自述）、无语义细粒度描述导致的高杂乱长程任务受限、Composite-Unseen 仍低、真实世界无量化成功率、规划器换代即改变结果的稳健性问题。
- **适用边界**：结论限定于四个基准的仿真设置与本文使用的基础模型/规划器版本；不能外推为"通用提升了机器人操作能力"或"任意 VLA + 任意 LLM 都可靠"；真实世界结论为定性演示级别。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：冻结 VLA 基线与逐基线对照没有获得与 Harness 相同的测试时预算与重试机会，"分层编排有效"与"更多尝试有效"仍纠缠

- **原文依据**：§2.2 明示两个阶段不对称——自举期有 reset 与宽裕墙钟，部署期禁用 reset 但 Harness 仍可在一回合内多次调用 vla_act、观察、再摆位重试（Key Finding 2）；Table 3 的对照 $\pi_{\mathrm{RLinf}}$ 是单次整体执行 50.0%，Harness 82.4%；Fig. 4 显示把调用上限放宽本身就能改变成功率；RATS/Cap-X 等最强先验的数字取自其原论文协议，未在本文同预算下重跑（Table 3 表注）；论文自己也承认 Table 7 的计时口径不同、不构成加速证据，说明作者对预算口径敏感，但主表没有等预算对照。
- **为什么重要**：它直接决定核心因果主张的成色——增益若主要来自"允许更多次已摆位尝试 + 记忆先验"，则启示是"重试机制与预算管理"而非"VLA 应当只做接触原语"这一更一般的架构结论；也影响与 RATS 等竞争方法的公平比较。
- **当前能够得出的判断**：存在混杂因素但未被完全排除。有利证据：Fig. 4(a) 中 $k$=1（仅一次规划器选择的调用）已 52%>50%，说明"选对时机调用一次"本身有增益；Table 5 零样本下仍有 31.0/79.0，说明离开记忆也不为零。不利证据：没有"给冻结 VLA 同等重试/复位预算"或"给 RATS/Cap-X 同协议重跑"的对照，无法量化预算贡献占比。
- **如何验证或补强**：(a) 给冻结 VLA 基线配一个最简单的重试/复位封装（同等最大调用数与尝试数）作为"等预算单体基线"；(b) 在本文协议下重跑 RATS/Cap-X 并匹配预算与主干；(c) 报告自举探索的实际尝试次数、墙钟与 token 消耗，使"测试时算力"可对齐。
- **严重程度**：主要问题。

#### 质疑：结果高度依赖闭源规划器主干（LIBERO-Pro 72.1 → 82.4 → 92.63），"可靠性与鲁棒性"结论的稳健性和可复现性受限

- **原文依据**：同一 harness 下仅换规划器：LIBERO-Pro 上 Codex(GPT-5.5) 72.1、CC(Opus-4.7) 82.4、Codex(GPT-6 Astra，低推理档) 92.63（Table 3、Table 21）；RoboCasa365 上依次为 57.2、48.8、59.20（Table 4、Table 22）；§3.3 仅以 "without loss of generality" 论证 CC 的代表性，未报告同一主干下方差或重复运行；三个主干全部是闭源服务；正文未报告主表 Codex(GPT-5.5) 的推理档位与提示/温度配置。

## 6. 审稿式总评

> 作者发现：端到端 VLA 的强项在局部接触密集控制，但部署扰动（语义重定向、目标重绑定、布局变化、不稳定接触）会把它打出训练轨迹分布，而编程智能体一侧又把物理接触交给不擅长它的解析 API（§1、Table 3 的冻结策略崩溃与 Fig. 3 的行为证据）；因此提出 Harness VLA——保持原语库固定且小，把冻结 VLA 暴露为单一可重试原语 vla_act，由带任务特定记忆与全局记忆的 LLM 规划器学习"何时、在哪个局部区域、以什么前置状态"调用它，其余交给解析原语（§2、Fig. 1/2）；通过文件中介 REPL 的回合循环与"自举-严格部署"两阶段实现，无 VLA 微调（§2.2、附录 A）。实验在 4 个基准共 1,700 个主协议回合、外加零样本、Flash 与真实定性条件下表明：同一冻结 VLA 在扰动基准上大幅抬升（LIBERO-Pro 50.0→82.4，RoboCasa365 30.0→57.2，RoboTwin C2R 50.4→58.4，Table 3/4/6），其中"选对时机调用 VLA"的调用预算证据较强（Fig. 4(a)：1 次调用即 52%>50%）、记忆贡献有半隔离证据（Table 5：位置交换 87.0→31.0），但增益归因仍缺少等预算对照与分机制消融，且结果随闭源规划器换代大幅摆动（72.1/82.4/92.63，Table 3/21），正文与表格存在数字不一致（质疑四）。本文最有价值的部分是"冻结模型 + 智能体编排"的实证范式与可移植的双记忆原语框架——它给出一条不训模型、靠 harness 工程扩展 VLA 有效工作范围的清晰路线；最大的审稿风险是：核心因果主张（分层编排带来增益）与测试时预算、闭源规划器能力两个混杂因素纠缠，使其"可靠、state-of-the-art 鲁棒"的强表述目前只能按"在论文报告的主干与协议下成立"来理解。

- **问题定义清晰度**：强（两条路线各自的错配讲得清楚，任务形式化（§2.1）、原语接口（Table 1）、评测协议（附录 C）与记忆格式（附录 A）均明确给出）。
- **创新性证据**：中（"冻结 VLA 作为可重试接触原语 + 双记忆学习操作范围"是真实的系统增量，且用 ASPIRE/RATS/Cap-X 等正面对比了定位；但组件均为已有范式的新组合，无同协议重跑的最近邻基线，"首次"边界无法仅凭本文确认）。
- **方法可信度**：中（框架描述完整、提示全文公开、perception 隔离规则明确；但 $\tau$/容差与自举过程未报告、依赖三个闭源主干、开放环反馈为自述局限）。
- **实验支持力度**：中（四个基准 + 零样本 + Flash + 真实演示的覆盖面强，关键效果量级大且两版数字一致；但无方差/显著性、跨协议基线混杂、两处数字口径不一致、机制证据部分为描述性）。
- **可复现性**：中（代码仓库公开且为 Apache-2.0 许可、提示与协议全文给出；但主结果依赖三个闭源规划器与特定冻结检查点，LingBot-VLA 检查点可用性未报告，Token/成本口径缺失）。
- **综合阅读价值**：高（把"何时该不该让 VLA 干活"这一被广泛讨论的直觉做成了可度量的系统与机制分析，"冻结模型 + harness 工程"的路线对做机器人学习、智能体与系统集成的读者都有直接参考价值；但引用其数字时需带上质疑四的口径提示）。
