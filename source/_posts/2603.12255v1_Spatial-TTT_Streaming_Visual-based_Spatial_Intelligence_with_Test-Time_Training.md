## 0. 一句话结论

论文把测试时训练（test-time training, TTT）引入多模态大语言模型（multimodal large language model, MLLM）：让模型在推理过程中用在线更新的快速权重（fast weights）充当长视频流的空间证据记忆，在 VSI-Bench、MindCube-Tiny、VSI-SUPER 三个视频空间基准上取得平均分最好的结果（如 VSI-Bench 平均 64.4，Table 1）。结论边界：三个基准均为单次评测、无显著性检验；"提升来自 TTT 空间记忆"这一点没有经过"同数据、同训练流程、换回标准注意力"的对照隔离；效率结论成立于论文报告的测速条件（352×480 输入、理论 TFLOPs）。

## 1. 论文具体想解决什么问题？

**背景与任务。** 空间智能（spatial intelligence）要求模型从连续的视觉观测流中持续地维护、更新并推理 3D 空间证据——相机在移动、物体被遮挡、视角不断变化，空间线索散布在成千上万帧中（§1）。本文的具体任务是流式空间理解：给一段长时程第一视角视频流和若干空间问题（物体计数、绝对/相对距离、房间大小、相对方向、路线规划、出现顺序等），模型要在不把全部帧塞进上下文窗口的前提下累计证据并作答。

**现有方法为何不够。** 通用 MLLM 在 2D 理解上表现很强，但缺乏 3D 几何先验，在需要精确空间对齐的任务上明显退化；已有的空间增强路线（向输入注入几何线索、扩充 3D 空间问答数据、SFT 与 RL 微调）仍局限于单张图片或 16/32 帧的短片段，无法扩展到实际场景中的长时程视频流（§1、§2.1）。直接拉长输入序列会遇到注意力的二次复杂度；激进的时间下采样又会把精确 3D 推理所需的细节丢掉（§1）。论文在实验结果里给出了这一瓶颈的直接证据：Qwen3-VL-2B 与 Cambrian-S-7B 在超过 120 分钟的视频上发生显存不足（out-of-memory, OOM），按评测协议记为 0 分（§4.3、Table 3）。

**作者提出的新角度。** 摘要明确给出问题定位：核心挑战不是更长的上下文窗口，而是空间信息如何被选择、组织并随时间保留。此前 TTT 已在语言建模与自回归视频扩散中显示"推理时更新快权重可以高效记忆长内容"（§2.2），作者据此假设：让 MLLM 的一部分参数变成随视频流在线更新的快权重（被描述为紧凑的非线性记忆），比冻结参数的长上下文方案更适合近乎无限的观测流（§1）。作者同时指出两个具体障碍：常规 TTT 的 Q/K/V 由逐点线性映射生成，忽略视觉 token 间的邻域结构，记忆更新缺乏空间连贯性（§3.2）；现有空间数据集的监督稀疏且局部——一道题往往只覆盖场景的一小块、答案只是一个选项或整数，无法教会模型"如何更新快权重"（§3.3）。

**核心假设。** 用稠密场景描述训练出的快权重更新动力学，能在长视频流上保留全局 3D 证据，从而提升流式空间理解，且计算与内存随流长近似线性增长。需要区分三层：MLLM 空间能力不足是领域早已存在的问题；"把 TTT 记忆搬进 MLLM 并做三处空间化改造（混合锚层架构、空间预测卷积、稠密监督）"是本文的新工作；实际解决的子问题是长时程视频上的空间问答与持续计数/回忆。论文的整体方案与工作方式见图 1。

## 2. 创新点是什么？

一句话总括：实质增量是把已有的 TTT 序列建模思路（大块更新与 Muon 优化器来自 LaCT，快权重记忆此前用于语言建模与新视角合成）移植到多模态大模型的空间理解任务，并做了三处空间化适配——混合锚层架构保住预训练能力、向 Q/K/V 注入时空归纳偏置、用稠密场景描述提供适配 TTT 动力学的监督信号。

1. **TTT 快权重作为流式空间记忆 + 混合 3:1 架构。** 每四个注意力层中三层替换为 TTT 层，保留下来的锚层维持预训练的跨模态对齐；TTT 层把长程时序依赖压缩进在线更新的快权重（§3.2）。与 TTT-E2E 等纯 TTT 序列模型不同，这里的额外约束是不能破坏一个预训练 MLLM；消融显示去掉锚层后 VSI-Bench 平均分从 64.4 掉到 53.9（Table 4、§4.4）。架构与分层安排见 §3 与图 2。

2. **大块更新 + 与 TTT 并行的滑动窗口注意力（sliding window attention, SWA）。** 以约等于多帧画面的 2648 个 token 为一块（chunk）做一次快权重更新，提高并行度；因果约束下当前块在更新时不能看到自身，块内 token 无法互看，于是并行保留一个共享 Q/K/V 的 SWA 分支来补足块内时空连续性（§3.2）。这是相对常规小 chunk TTT 的设计改动，属于已有组件的重新组合；支持证据见 §4.2 的效率分析与 §4.3。

3. **空间预测机制。** 对 TTT 分支的 Q/K/V 施加 Dirac 初始化的逐通道 3D 时空卷积，把逐点映射改成邻域映射，让快权重学习时空上下文之间的预测关系而非孤立 token 的映射（§3.2）。这是本文特有、最接近新机制的组件；移除后平均分从 64.4 掉到 62.1，数值类问题下降更大（Table 4、§4.4）。

4. **稠密场景描述数据 + 两阶段渐进训练。** 从 SceneVerse 标注构造约 16k 条稠密场景描述（全局语境、物体与计数、物体关系），先用它训练快权重更新动力学（滑动窗口从 5600 退火到块大小 2648），再用大规模空间问答数据微调流式推理能力（§3.3、§3.4、附录 A.1）。相对只做稀疏问答微调的做法，这属于数据构造与训练流程的差异；移除后平均分降到 61.3（Table 4、§4.4）。

## 3. 作者如何解决？

**直觉。** 关键改写是：模型不再是"先看完整段视频、再一次性回答"，而是把视频流按块送入，一边看一边把空间证据写进一组随时可改的参数（快权重），问题到来时再从这组参数里读出记忆作答。整体流程见图 1。

![图 1：流式分块更新快权重的总体思路](/images/dailypaper/2026-10-16/2603.12255v1_fig1_teaser.png)
**图 1**（论文 Fig. 1）：这张图展示 Spatial-TTT 的工作方式：快权重从初始化状态出发，随视频流按块依次被"续写"——每到一个新块就把它编码进记忆，形成"初始化—按块更新—应用状态回答"的循环，最终使模型具备相对距离、物体计数、路线规划等八类空间能力。示例部分把该机制放在一个机器人导航问答上：多个块依次更新空间状态，模型从累积出的整体状态图给出动作序列。读者应理解两点：记忆不是把帧存起来，而是以固定规模参数的形式被逐步重构；更新与作答发生在同一条流式过程内，这正是 TTT 与"把全部帧放进上下文"的本质区别。

**（1）输入与输出。** 输入是空间视频流加空间问题文本，输出是答案文本（整数、选项字母或短语）。评测时 VSI-SUPER 视频按 1 fps 采样；训练第一阶段每例均匀采 32 帧，第二阶段用 64–128 帧（§4.1）。模型以 Qwen3-VL-2B-Instruct 初始化，沿用其视觉编码器与解码器主干（§4.1）。

**（2）混合 TTT 架构（创新点 1 的展开）。** 在解码器的 L 层中，每四层里三层替换为 TTT 层（75%），留一层标准自注意力作锚层（anchor layer），由锚层保持对整个上下文的完整注意力，保住预训练模型的语义推理能力；TTT 层则把长程依赖压进快权重，使显存随流长呈亚线性增长（§3.2）。工程上有两个保真设计：TTT 层不新建 QKV 投影矩阵、直接共享原注意力层的投影；额外只加轻量的可学习 scale-and-shift 作用在投影后的 q、k 上，且门控投影零初始化、scale 初始为 1、shift 初始为 0，使训练起点与原全注意力模型行为一致（§4.1）。这样设计的原因在消融中有体现：纯 TTT 架构大幅掉点（Table 4），说明保留锚层不是可选项。组件连接与数据流见图 2。

![图 2：混合 TTT 架构与层内数据流](/images/dailypaper/2026-10-16/2603.12255v1_fig2_architecture.png)
**图 2**（论文 Fig. 2）：这张图给出从"视频帧 + 问题"到"答案"的完整数据流。视觉 token 与文本 token 进入解码器堆叠后，按"每四层含一个全注意力锚层、三个 TTT 层"的节奏逐层传递，锚层负责全上下文语义，TTT 层负责把历史压进快权重。单个 TTT 层内部是一进两分支：共享 QKV 之后，一个分支做窗口注意力，另一个分支先经 Rescale & Shift 与 3D 时空卷积做邻域聚合，再"切块进入分块更新循环"——每块内先应用当前快权重产出输出、再用该块的 key/value 执行一次带正交化与归一化的快权重更新，最后与窗口注意力分支输出相加。读者应重点理解：长程信息只以快权重的参数形式跨块传递，而块内细节由窗口注意力兜底，两个分支在每一层持续协同。

**（3）层内并行两分支：TTT 与 SWA（创新点 2 的展开）。** 常规 TTT 用小 chunk（如 16 或 64 个 token）频繁更新，对视觉数据并行度差、还会在块边界割裂帧内空间结构；本文把块大小放大到 b=2648 个 token、约对齐多帧画面，块即更新单元（§3.2、§4.1）。但大块带来一个因果约束问题：为防止信息泄漏，当前块在更新快权重时不能与自身交互，块内 token 间的时空连续性就无人负责。解法是在每个 TTT 层内并排放一个 SWA 分支，与 TTT 共享 Q/K/V（TTT 分支的 q、k 被 scale/shift 调制），窗口 w 不小于块大小 b，从而完整覆盖块内下三角的因果结构。层输出是两支路之和：

$$o_t = \mathrm{WindowAttn}\big(q_t,\, K_{[t-w:t]},\, V_{[t-w:t]}\big) + f_{W_t}(q_t)$$

其中窗口初始化 w=5600（足以覆盖整个序列）、在第一阶段的两个 epoch 内线性退火到 2648，第二阶段固定 w=b（§3.4、§4.1）。退火的作用是让 TTT 分支逐步接管跨块信息传播，而不是一直依赖大窗口。

**（4）TTT 分支内部：先应用、再更新，优化器换成 Muon（创新点 1、2 的展开）。** 快权重网络 f_W 是无偏置 SwiGLU-MLP，由三个权重矩阵构成，论文将其称为可学习快权重（§3.2 的式 4）：快权重的初始状态在训练中学习，推理时被在线改写。每个块的处理顺序是：先用当前快权重处理块内 query 得到输出（apply），再对块内 key/value 计算自监督损失并做一步更新（update）。一般 TTT 的更新是朴素的梯度下降：

$$W_t \leftarrow W_{t-1} - \eta\, \nabla_W \mathcal{L}\big(f_{W_{t-1}}(k_t),\, v_t\big)$$

本文改用 Muon 更新规则：先累积动量并做正交化梯度（Newton–Schulz 迭代），再更新并用 L2Norm 归一化以保持权重幅度（§3.2 的式 6–7，沿自 LaCT 的做法）。作者给出的理由是提升在线更新的稳定性与有效性；论文未报告 Muon 与普通梯度下降的对照消融（论文未报告）。

**（5）空间预测机制（创新点 3 的展开）。** 在常规 TTT 中，Q/K/V 由逐点线性投影生成，忽略视觉 token 的邻域结构；而快权重必须把整块压成紧凑记忆来表示 3D 结构，孤立 token 的变换迫使它从零学空间模式，压缩更难、记忆更无序。本文的处理是把视觉 token 重排成时空网格，对 Q/K/V 分别做核大小 3×3×3 的逐通道时空卷积做邻域聚合，卷积核以 Dirac delta 初始化以保证起点等价于恒等映射（§3.2、§4.1）。效果是快权重不再学"孤立 token 之间的预测"，而是学"时空上下文之间的预测映射"，论文称其从而隐式捕获几何对应与时间连续性（作者主张，见 §4.3 对机制证据的核查）。

**（6）稠密监督与两阶段训练（创新点 4 的展开）。** 阶段一用一个约 16k 样本的稠密场景描述数据集（3.6k 条 ScanNet、12.5k 条 ARKitScenes，从 SceneVerse 的物体中心 3D 场景图派生）：模型收到空间视频流后要生成一段连贯的场景走查，内容分三类——全局语境（场景类型与功能）、物体与计数（类别与精确数量）、物体关系（布局与成对关系），从而给快权重更新动力学提供覆盖整场景的梯度信号（§3.3、附录 A.1）。阶段二用约 250 万条开源空间数据加约 50 万条自采数据做持续微调，任务覆盖相对方向/距离估计、空间计数、路线规划、房间大小估计等；窗口与块大小固定为 w=b，TTT 层完全聚焦跨块空间信息聚合（§3.4、§4.1、附录 A.1）。注意论文对第二阶段数据量的表述不一致：§3.4 写"2M spatial VQA samples"，§4.1 写"3M"，附录 A.1 写"约 2.5M 开源 + 约 0.5M 自采"（审稿人判断，属披露瑕疵，见 §5）。训练超参：预训练主干学习率 1e-6、TTT 新增参数 1e-5，warmup 1k 步加余弦调度；论文给出两组学习率意味着主干参数处于可训练状态，但未逐模块报告冻结清单，也未报告第二阶段的训练步数（论文未报告）。

**（7）推理阶段发生的变化与输出。** 推理采用双 KV 缓存实现恒定内存的流式处理：一是固定长度 w 的窗口 KV 缓存，负责 SWA 的局部上下文，超出窗口后丢弃最早条目；二是 TTT 待处理 KV 缓存，从空开始累积 key-value，攒满一块 b 就执行一次快权重更新随后清空（§3.4）。因此部署期的"训练"只发生在快权重这一子集参数上，主干参数不再变化。哪些由模型决定、哪些固定：固定的有块大小 2648、窗口退火日程、更新节奏（每块恰好一次）、Muon/L2Norm 规则与 Dirac 初始化；由数据驱动决定的是快权重与 scale/shift 的内容及最终答案。最终输出是答案文本。

## 4. 解决得怎么样？

#### 4.1 实验设置

**任务与基准。** 三类视频空间评测：VSI-Bench（5000+ 问答、288 段 ScanNet/ScanNet++/ARKitScenes 室内视频；数值题用平均相对准确率 Mean Relative Accuracy（MRA）、多选题用准确率 Accuracy（ACC），平均分为跨任务宏平均；题面形式见图 3）；MindCube-Tiny（1050 题，含 600 道 Among、250 道 Around、200 道 Rotation；多视角图像组加视角变换推理；形式见图 4）；VSI-SUPER-Recall（VSR，选择题 ACC）与 VSI-SUPER-Count（VSC，持续计数，MRA）（10–120 分钟第一视角视频、按 1 fps 采样；形式见图 5）。

**基础模型与配置。** 以 Qwen3-VL-2B-Instruct 初始化；TTT 层按 3:1 替换注意力层；块大小 2648、窗口 5600 退火至 2648；3D 卷积核 3×3×3；学习率 1e-6（主干）/1e-5（TTT 新参数）（§4.1）。

**基线。** 闭源模型（GPT-5、Gemini-2.5-pro、Gemini-3-pro、Seed-2.0、Grok-4、Kimi-K2.5）；开源通用模型（LongVA-7B、LLaVA-OneVision-72B、LLaVA-Video-72B、InternVL3-2B/8B、Qwen2.5-VL-3B/7B、Qwen3-VL-2B/8B）；开源空间智能模型（MindCube-3B、SpatialLadder-3B、SpaceR-7B、ViLaSR-7B、VST-3B/7B-SFT、Cambrian-S-3B、Spatial-MLLM-4B）；长视频模型（MovieChat、Flash-VStream，仅 VSI-SUPER）。另有 Human 与 Random Choice 参考线（§4.1）。

**公平性与协议。** 基线均为现成模型或官方权重，训练数据与推理预算未与本文对齐；VSI-SUPER 上所有模型统一按 1 fps 采样；OOM 者记 0（Table 3 说明）。全部结果为单次评测，论文未报告重复运行、置信区间或显著性检验（论文未报告）。

**实验分工。** 主实验回答三基准表现（§4.2、§4.3）；消融回答三个组件各自的贡献（Table 4，完整分项见附录 Table 7）；Table 5 回答效率随输入长度的扩展性；附录给出评测提示模板（Table 6）、单层伪代码（Algorithm 1）与定性示例（论文 Fig. 3–6）。

#### 4.2 关键结果

**VSI-Bench（Table 1，§4.2）。** Spatial-TTT-2B 平均分 64.4，高于最强开源空间模型 VST-7B-SFT 的 60.6、最强闭源 Gemini-3-pro 的 56.0 与 GPT-5 的 55.0，论文据此宣称"尽管只有 2B 规模仍超过闭源与开源基线"。分项上真正领先的是绝对距离（47.8，次高 Qwen3-VL-8B 47.0）与相对方向（73.0，次高 Cambrian-S-3B 61.9）。同样需要记录的是未领先的单项：物体计数 70.8（VST-7B-SFT 72.0）、物体大小 71.7（Qwen3-VL-8B 76.3）、房间大小 65.9（VST-7B-SFT 68.3）、相对距离 61.8（Cambrian-S-3B 64.8，GPT-5 63.7）、路线规划 47.4（Gemini-3-pro 61.9、Kimi-K2.5 52.1）、出现顺序 77.0（Cambrian-S-3B 78.8）——平均分领先并不等于逐项领先。原文称模型的优势项包括 Route Plan，该说法只相对开源空间模型成立，对 Gemini-3-pro 并不成立（审稿人判断）。VSI-Bench 的题面与流式评测形式见图 3。

![图 3：VSI-Bench 流式空间问答示例](/images/dailypaper/2026-10-16/2603.12255v1_fig3_vsibench_examples.png)
**图 3**（论文 Fig. 3）：这张图展示 VSI-Bench 如何把流式观测转化为对空间记忆的考验：视频帧以流式输入，问题在观测结束后提出，因此计数类题目必须跨块对已见实例去重累计，房间大小与出现顺序则要求把不同时刻的观测联系起来；作答同时覆盖数值估计与多选两种计分形式，对应 Table 1 中的计数、房间大小、出现顺序等分项。读者应理解其评测机制与本文方法的联系：这些题的答案无法从任何单帧读出，只有持续维护跨块的空间状态才能作答，这正对应 TTT 快权重被设计承担的职责。

**MindCube-Tiny（Table 2，§4.2）。** 平均 ACC 76.2，超过最强闭源基线 Gemini-3-pro 的 63.9（+12.3 个百分点）与最强开源空间模型 MindCube-3B 的 51.7（+24.5 个百分点）；分项中最优的是 Around 89.8 与 Among 74.0，但 Rotation 子集 55.5 明显低于 GPT-5 的 94.5。原文写"在 ACROSS 和 AMONG 两个子集表现最好"，表中并不存在 ACROSS 子集、实际最优为 Around 与 Among，疑为笔误（审稿人判断）。该基准的多视角问法见图 4。

**图 4**（论文 Fig. 6）：这张图解释 MindCube 的评测机制：同一物体只以少量视角的图像给出，问题要求模型站在指定视角做空间判断（例如"以某张图的朝向站在此处，背后是什么"），正确作答依赖在视角之间建立一致的 3D 心理模型，而不能靠记住画面本身。这类题与 VSI-Bench 的长视频记忆互补：它考的是视角变化与遮挡下的几何推理能力，对应 Table 2 的 Rotation、Around、Among 三个子集，其中本文方法在 Around 与 Among 领先、在 Rotation 落后。读者应理解本文的混合架构与空间预测卷积不仅服务长序列压缩，也承担跨视角几何一致性的建模。

**VSI-SUPER（Table 3，§4.3）。** 持续计数（VSC）上 Spatial-TTT 在全部四个时长档大幅领先：31.8/45.6/36.2/38.4（10/30/60/120 分钟），而所有基线不超过 0.8。长时程回忆（VSR）上则只是"competitive"：10 分钟 38.3 与 Cambrian-S-7B 的 38.3 持平，30 分钟 35.0 持平，60 分钟 28.3 与 Qwen3-VL-2B 持平，120 分钟 30.0 领先——但该档位领先的直接原因是 Qwen3-VL-2B 与 Cambrian-S-7B 因 OOM 被记 0（Table 3 说明，审稿人判断）。另外 VSC 的 10 分钟档 31.8 低于其 30 分钟档 45.6，呈非单调。持续计数任务的机制与代表例题见图 5。

![图 5：VSI-SUPER 持续计数示例](/images/dailypaper/2026-10-16/2603.12255v1_fig5_vsisuper_count.png)
**图 5**（论文 Fig. 5）：这张图解释 VSI-SUPER-Count 的持续计数机制：相机在室内持续移动（视频可长达 120 分钟、按 1 fps 采样），同类物体反复进入与离开视野，模型必须跨时间段、跨视角对已计数的实例去重，最终给出整段视频中不同实例的总数。计数对空间记忆的要求最苛刻——任何一次遗忘都造成多计或少计，且答案无法从结尾几帧读出。它与 Table 3 的 VSC 结果直接对应：本文方法在四档时长上取得 31.8–45.6 的成绩，而全部基线不超过 0.8，说明这类"边看边维护计数状态"的任务最能体现快权重随流更新的价值。

**消融（Table 4，完整分项见附录 Table 7；§4.4）。** 完整模型 VSI-Bench 平均 64.4（数值 64.0、多选 64.8）。替换空间预测卷积为恒等映射后降到 62.1（数值类降幅更大：64.0→60.7）；去掉稠密场景描述数据降到 61.3；去掉锚层变成纯 TTT 架构降幅最大，降到 53.9（多选 64.8→52.4）。

**效率（Table 5，§4.4）。** 随输入帧数增加，Spatial-TTT 的每次前向理论 TFLOPs 与峰值显存近似线性增长：128/256/512/1024 帧分别为 74.3/156.2/341.9/799.4 TFLOPs 与 6.2/7.0/8.4/11.9 GB；对照 Qwen3-VL-2B 为 75.9/179.9/473.9/1403.1 TFLOPs 与 6.2/8.3/12.6/21.2 GB，Spatial-MLLM-4B 在 512 帧即 OOM。1024 帧时相比 Qwen3-VL-2B 约减少 43%（论文表述为"over 40%"）。

**负面与小提升信息汇总。** VSR 相对最强基线无净提升（10–60 分钟持平）；VSC 时长档间非单调；VSI-Bench 六个单项不及特定基线；MindCube 的 Rotation 子集大幅落后 GPT-5；以上所有数字均无方差、置信区间或显著性检验；论文未报告失败案例分析（论文未报告）。

#### 4.3 机制证据

论文的实验能较好回答"方法是否有效"，但对"为什么有效"是三组强度不一的证据。

对创新点 4（稠密数据）与创新点 3（空间预测卷积）：Table 4 的"移除即掉点"（61.3 与 62.1）是直接的组件消融，支持二者对最终成绩有贡献；但"w/o Dense Data"移除的是整个第一阶段，混合了数据量与训练流程两个变量，不是隔离对照。

对创新点 1（混合架构）："w/o Hybrid Arch"的 53.9 是全文最强的消融信号，证明自注意力锚层不可替代。但它说明的是"必须保留一些全注意力"这一训练稳定性事实，而非"TTT 快权重在长序列上有效"——VSI-Bench 本身是短片段任务，该消融并不构成对长流记忆机制的验证。长序列上的机制证据只能来自 VSI-SUPER，而其最长档位（120 分钟）的领先受 OOM 记 0 规则影响，VSR 上也无净提升。换言之：论文声称的核心机制（快权重随时间累积空间证据）在长时程场景下缺少干净的对照实验，效率侧证据（Table 5 的近似线性扩展、双 KV 缓存的恒定内存设计）反而更接近因果无混杂的机制证据，因为它直接测量层替换带来的计算路径变化。

对创新点 2（大块 + SWA + Muon）：论文未报告块大小、窗口大小、Muon 与普通梯度下降的敏感性或对照消融（论文未报告）；SWA 的必要性只有"因果约束"这一设计论证，没有实验验证。

替代解释方面：本文在 2B 主干上使用约 300 万条空间问答加 1.6 万条稠密描述做两阶段训练，而基线多为现成模型；缺少"相同数据、相同训练流程、把 TTT 层换回标准注意力"的对照，意味着成绩提升目前不能排除来自数据规模与微调流程本身。此外论文没有对快权重内容做任何探测或可视化分析，"快权重捕获几何对应与时间连续性"仍是作者主张（§3.2），未被直接验证。

#### 4.4 成本与适用范围

**训练成本。** 论文未报告 GPU 型号、卡数、训练总时长与 batch size（论文未报告）；只报告学习率、warmup 步数与余弦调度、第一阶段窗口退火历时两个 epoch，第二阶段的训练步数未报告。

**推理成本。** 报告了理论 TFLOPs 与峰值显存随帧数的变化（Table 5），但未报告墙钟时延或吞吐（论文未报告）；每块一次 Muon 更新（含 Newton–Schulz 正交化）位于推理路径内，其开销占比未单独报告。相比 Qwen3-VL-2B，1024 帧时计算与显存各降约 43%，且差距随长度拉大。

**数据与依赖。** 第一阶段 16k 稠密描述从 SceneVerse 公开标注派生（非新采集）；第二阶段约 250 万条公开数据（VSI-590K、VLM-3R、InternSpatial、ViCA 等）加约 50 万条自采数据——自采部分由 ScanNet 重建派生，含房间范围与质心（alpha-shape 估计）、物体有向包围盒、40 类室内语义标签与 2D 语义投影（附录 A.1）；人工标注成本未报告，数据与模型是否开源未报告（论文未报告）。外部依赖为开源的 Qwen3-VL-2B 与 Muon 优化器，无闭源服务依赖。

**未解决与适用边界。** 论文未报告失败案例与局限性分析；VSR 未净超最强基线；Rotation 子集弱；所有评测为单次运行。改善的问题：长视频空间计数（VSC）与短片段空间问答（VSI-Bench 平均、MindCube）。尚未解决的：长时程"回忆顺序"类任务的净提升、超过 1024 帧的显存/质量边界、开放域视频与真机具身场景——论文结论应限定在室内场景（ScanNet/ARKitScenes 系）的视频空间问答范围内。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：缺少同数据同流程的非 TTT 对照，SOTA 提升无法归因到 TTT 记忆机制

- **原文依据**：模型在 2B 主干上用约 300 万条空间问答加 16k 稠密描述做两阶段训练（§4.1、附录 A.1），基线均为现成模型且训练数据未对齐；唯一的架构消融是"纯 TTT"（Table 4，53.9），并未提供"同数据、同流程、把 TTT 层换回标准注意力"的对照。
- **为什么重要**：这直接决定"TTT 快权重带来长程空间记忆"这一核心立论。若换成普通注意力加同样的数据微调也能到 64 左右，则本文的机制叙事需要整体收缩为"数据与训练配方有效"。
- **当前能够得出的判断**：现有证据支持"方法有效"，但无法把增益隔离给 TTT；在短序列基准（VSI-Bench）上尤其如此。
- **如何验证或补强**：训练一个参数规模、数据、步数完全一致的全注意力对照（可在训练帧数内用滑动窗口注意力近似长上下文），并在 VSI-SUPER 上比较；同时报告两者的训练成本。
- **严重程度**：主要问题

#### 质疑：长序列优势受"OOM 记 0"记分规则影响，VSR 实际无净提升

- **原文依据**：Table 3 说明 Qwen3-VL-2B 与 Cambrian-S-7B 在 80GB GPU 上超过 120 分钟即 OOM、成绩记 0；VSR 上 Spatial-TTT 与 Cambrian-S-7B 在 10/30 分钟完全持平（38.3/35.0）、60 分钟与 Qwen3-VL-2B 持平（28.3），唯一领先的 120 分钟档正是对手记 0 的档位（§4.3）。
- **为什么重要**：论文"随视频变长保持稳定"的核心卖点（摘要、§4.3）部分建立在对手因工程原因拿 0 分之上；若基线采用其官方支持的抽帧或滑窗策略，对比结论可能变化。
- **当前能够得出的判断**：VSC 上的领先（31.8–45.6 vs ≤0.8）是真实的大幅优势；VSR 上"稳定优于基线"的结论证据不足，应降格为"与最强基线持平、且内存可持续"。
- **如何验证或补强**：在显存受限条件下对基线使用官方的长视频推理配置（抽帧、滑窗、量化）；报告各模型在不同时长下的实际显存占用曲线，把"能力差异"与"工程上限差异"分开。
- **严重程度**：主要问题

#### 质疑：快权重"捕获几何对应"缺机制验证，Muon、块大小、窗口等关键设计无消融

- **原文依据**：§3.2 称空间预测机制让快权重"隐式捕获几何对应与时间连续性"；全文没有任何对快权重内容的探测、可视化或分析；Muon 更新被采纳但无与普通梯度下降的对比，块大小 2648、窗口 5600→2648、卷积核 3×3×3 均无敏感性实验（Table 4 只有组件级消融，论文未报告上述项目）。
- **为什么重要**：机制主张是论文标题级卖点（"Test-Time Training"与"空间记忆"）；只有端到端成绩无法排除快权重只是充当某种隐式位置编码或缓存。
- **当前能够得出的判断**：组件有贡献（移除掉点），但贡献是否通过论文声称的机制发生无法确认；Muon 等沿用设计在新任务上的收益大小未知。
- **如何验证或补强**：对快权重做探针实验（例如线性探测其是否编码物体位置/朝向）、按块分析记忆内容的演化；补充 Muon vs 朴素梯度下降、块大小与窗口的敏感性曲线。
- **严重程度**：主要问题

#### 质疑：训练与数据披露不足以复现，数据规模表述前后不一致

- **原文依据**：第二阶段的样本量在 §3.4（2M）、§4.1（3M）、附录 A.1（约 2.5M + 约 0.5M）三处表述不一致；GPU 型号/卡数/总时长、batch size、第二阶段训练步数均未报告（§4.1）；截至 2026-10-16 未发现公开代码仓库，数据与权重是否开源未报告。
- **为什么重要**：混合 TTT 架构的实现细节（层替换方式、共享投影、Dirac 初始化的卷积、Muon 超参）繁多，缺代码与数据披露时，复现成本极高；数据规模不一致直接影响对训练预算的判断。
- **当前能够得出的判断**：方法描述总体具体（超参、伪代码、提示模板都有），但复现所需的关键工程信息缺口明显；数据规模表述应视为笔误级别的不一致，而非实质矛盾。
- **如何验证或补强**：开源训练代码与数据构建脚本；在版本更新中修正数据规模表述并补充训练成本表（GPU 时）。
- **严重程度**：次要问题

#### 质疑："超越闭源与开源基线"与"Route Plan 有优势"的表述超出表内证据

- **原文依据**：摘要称取得 state-of-the-art；§4.2 称多选任务（含 Route Plan）有强优势，但 Table 1 中 Route Plan 为 47.4，低于 Gemini-3-pro 的 61.9、Kimi-K2.5 的 52.1 与 GPT-5 的 50.2；六个单项各有更高基线；MindCube 的 Rotation 子集 55.5 远低于 GPT-5 的 94.5（Table 1、Table 2，§4.2）。
- **为什么重要**：结论的范围表述影响读者对"全面领先"的判断；按平均分宣称 SOTA 与按分项宣称优势是两种强度不同的主张。
- **当前能够得出的判断**：平均分领先（VSI-Bench 64.4、MindCube 76.2、VSC 全面领先）成立；"逐项优势"的表述与表内证据不符，属结论超范围。
- **如何验证或补强**：在正文明确分项胜负并在摘要限定"平均分最优"；对 Route Plan 等落后分项给出失败案例分析。
- **严重程度**：次要问题

## 6. 审稿式总评

作者把流式空间理解的核心困难定位为"空间信息如何被选择、组织与保留"而非上下文长度，因此提出把 TTT 快权重作为 MLLM 的在线空间记忆，通过混合锚层架构、大块更新并行滑窗注意力、空间预测卷积与稠密场景描述监督实现。实验在 VSI-Bench、MindCube-Tiny、VSI-SUPER 三类基准上表明：2B 模型取得三项平均最优与持续计数的大幅领先，效率随输入长度近似线性扩展；其中组件消融（尤其是锚层必要性与稠密监督）与效率分析证据较强，但"提升归因于 TTT 机制"缺少同数据同流程的对照，"快权重记住 3D 结构"没有任何直接探查，长时程优势还部分依赖对手 OOM 记 0 的记分规则。本文最有价值的部分是把测试时训练系统地引入多模态空间智能并给出可用的工程配方；最大的审稿风险是核心机制未被隔离验证、复现材料缺位。

- **问题定义清晰度**：强——"流式空间理解"的缺口与"非更长上下文"的定位明确，且有基线 OOM 与稀疏监督两类证据支撑（§1、§4.3）。
- **创新性证据**：中——增量清晰（TTT 入 MLLM + 空间预测卷积 + 稠密监督），但大块更新与 Muon 沿用 LaCT、混合架构是已知组合思路；SOTA 数字支持效果，归因未隔离（§2、§4.3）。
