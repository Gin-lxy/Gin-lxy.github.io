## 0. 一句话结论

EvoDuet 把“用 LLM 做进化搜索时的联网检索”从一次性的工具调用改造成与解演化同步的**双层优化**：外层照常进化候选程序，内层用“假设证据评分”（预测每篇文档单独能把当前父解改到多少分）来进化搜索查询，并由“知识缺口”门控决定查新、复用旧文档还是干脆不查。在作者报告的 21 个 SimpleTES 优化任务上，它把 OpenEvolve 的跨任务平均最优 NDG 从 74.1% 提到 78.0%（GPT-5.6-Luna）和从 61.3% 提到 82.3%（Gemini-3.8-Flash），并在 8 个任务上超过公开最优程序分数——但这一结论的边界是：主要数字是 4 次运行取最优（best-of-4）、无显著性检验；最接近的公开对照 DeepEvolve 未在同等模型与预算下重跑；Qwen3.5-9B 上作者自己报告为负增益（N=1 时 −14.4%），因此“普遍提升科学发现能力”的表述不被这些实验支持。

## 1. 论文具体想解决什么问题？

**研究背景与任务。** LLM 驱动的进化搜索（FunSearch、AlphaEvolve、OpenEvolve 等）在“评估器能打分、但最优解无法直接计算”的优化任务上寻找新解:每轮由 LLM 作为变异算子提出候选，评估器打分，高分候选进入种群作为下一轮父解（§2.1 给出了形式化定义:任务 $\tau=(I,x_0,\mathcal{E})$，评价函数 $\mathcal{E}$ 确定且可验证）。

**现有方法如何处理。** 多数 scaffold 只跑单一的“解循环”（solution loop）；一些方法在其外套更多循环，作者称之为 Loop Packing（Fig. 1），例如 EvoX 加了一个在停滞时改写搜索策略的 strategy loop。关键问题是:迄今所有被“打包”的循环都只消费两种知识来源——本次运行的进化历史和 LLM 的参数化知识。作者主张这样的搜索是**闭的（closed）**，当进展需要模型不具备的外部知识（如某个新版本库的用法）时就会停滞（§1）。

**现有方法在什么条件下表现不好**（本文的初步分析，§2，均为原文事实）:

1. 把每个迭代都“喂”上任务相关的有用文档（oracle documents）平均有效，但不是自动有效:31 个任务上平均 NDG 提升 Qwen3.5-9B +10.3%、GPT-5.6-Luna +4.0%（Fig. 3a）；同时在 8 个（Qwen）和 4 个（Luna）任务上把 NDG 拉低超过 1%，Rosetta 上分别降 9.0% 与 23.3%（§2.3，Fig. 3c）。
2. 模型需要“探索的余地”:在 Sums/Diffs 上，oracle 文档在每迭代生成 1 个候选时无效（14.8% vs 15.4%），到每迭代 8 个候选时才把 NDG 从 25.8% 提到 40.7%（§2.3，Fig. 4a）。
3. 查询必须随解演化:在 Denoising 上，让 LLM 在解循环里自己写查询（joint-level 搜索），100 次迭代中 99 次调用工具、产生 185 条查询，但返回的 URL 有 88.1% 是重复页面，第 50 次迭代后不再改进；EvoDuet 用 201 条查询拿到 248 个不同 URL（重复率 62.4%），同口径 held-out NDG 为 84.5% vs 27.7%（§2.3，Fig. 4b–4d）。

**作者认为的原因（作者主张）。** 闭搜索的根源不是缺少一次搜索，而是“检索内容与当前解的状态脱钩”:同一批页面在解变化后已无信息增量；同时模型即使拿到文档，也需要足够的并行探索机会才能把文档用起来。由此推出本文要验证的核心假设:**若把“问什么”当作以任务评估函数为目标的内层优化问题、并让检索决策由模型自评的知识缺口触发，URL 更多样、进展更持续、发现更多**。

**问题的归类。** “LLM 进化搜索会停滞”是领域早已存在的一般问题；“oracle 文档收益不均、联合式搜索重复返回同一批页面并停滞”是本文的新观察（单任务、单模型轨迹级证据）；本文实际解决的子问题是:**在模型参数固定、无法训练检索策略的前提下，如何让检索与解的演化共同前进**。需要说明的是:第 1 条与第 2 条是跨 31 个任务的统计观察，第 3 条（重复页面导致停滞）主要来自 Denoising 一条 100 迭代轨迹的对照，论文观察到现象并给出了解释，但该因果解释的证据面窄（见 §5 质疑 3）。

## 2. 创新点是什么？

**一段话概括真正的技术增量:** EvoDuet 把 web 搜索从“解循环里可选的工具调用”升级为**与解循环共享同一目标函数的第二层优化问题**（Eq. 1），并用“假设证据评分”（hypothetical evidence scoring，$\hat{s}_t(d)=\mathcal{M}_\theta(\tilde{c}_{t}^{r-1},\mathcal{E}(x_t),d)$）把不可观测的内层目标 $\mathcal{E}(x_{t+1}(q))$ 变成可计算的代理，从而在**不生成、不评估任何候选解**的前提下优化查询、对文档排名；再配一个三态知识缺口门控（no-op / look-up / retrieve）与一个把“文档 + 实测结果”写回的搜索数据库，构成闭环。整个方法 training-free，模型参数全程冻结（§3）。

**创新点 1:双层公式与“假设证据评分”代理（§3.1，Eq. 1；§3.4）。**
- 新增机制:内层目标用 LLM 预测“仅用文档 $d$ 改进父解后评估器会给的分”，据此排序文档、指导下一轮查询；每篇文档在内层只评分一次并缓存复用。
- 与最接近方法的差异:DeepEvolve 顺序耦合“先深研、再改代码”，joint-level 在写代码时顺手搜索，两者都**不按任务目标给查询或文档打分**（§B.5）；EvoX 进化的是搜索**策略**（仍是闭搜索）。EvoDuet 是第一个（作者主张）把“查询质量”定义为“其文档导出的候选解分数”的方法。
- 类型判定:属于已有组件（LLM 做预测器、进化循环、web 搜索工具）的**新组合 + 新的目标函数设计**，不是全新理论。
- 对应问题:直接回应“查询必须随解演化”。
- 证据:Table 1(c) 四路对照（Molecule / Burgers / CP n=26），Table 2 joint-level 43.2% vs bi-level 84.5%（Denoising）；Table 6 的 R/J 预算消融说明内层轮数与查询数不是越多越好（R=5 掉到 34.28%）。
- 移除后变化:去掉内层退化为 joint-level 或 no-search，Table 2 中两个任务分别从 84.5%/76.0% 掉到 43.2%/42.9% 与 0.0%/14.8%（GPT-5.6-Luna）。

**创新点 2:知识缺口三态门控（§3.3，Eq. 3）。**
- 新增机制:每次迭代先由一次模型调用输出知识状态 $K_t$（区分“已有知识 / 此前检索与实验的发现 / 关于当前解的未解问题”）与决策 $g_t\in\{\text{no-op},\text{look-up},\text{retrieve}\}$；look-up 直接复用 $\mathcal{D}_s$ 中存储文档的正文，不发起新搜索。
- 差异:EvoX 用“进度停滞”启发式触发；joint-level 基线几乎每轮强制搜索（99/100 迭代）。对随机门控与停滞启发式的对照见 Table 1(b)。
- 类型:研究思想层面的改动（何时检索由模型自评缺口决定），非模块堆叠。
- 证据:Table 1(b) knowledge gap 84.5%/100.0%，heuristic 60.6%/99.5%，random 58.5%/93.9%（Denoising / Erdős，GPT-5.6-Luna）。注意该对照只覆盖 2 个任务。
- 移除后变化:换成随机或停滞启发式即上表数字。

**创新点 3:搜索数据库与“文档—结果”回写闭环 + 门控并行生成（§3.2，Eq. 2；§B.1）。**
- 机制:每次 retrieve/look-up 迭代把保留文档、预测分、父/子实测分与评估器反馈写入 $\mathcal{D}_s$，后续 gate 与查询构造共享最近 10 条记录的快照；同时把候选生成数绑定到门控（retrieve/look-up 时 $N_t=N$，no-op 时 $N_t=1$，只把最优合法候选交给选择策略 $\phi$）。
- 差异与类型:并行生成借自本文 §2.3 的观察（属于经验设计）；把“实测结果”反向灌入检索层是本文特有的耦合。

**创新点 4（辅助）:可审计的行为分析协议（§5.1；Appendix E.1）。**
- 六类行为 flag（method transfer、cross-domain transfer、live documentation lookup、target-informed reconstruction、public artifact reuse、evidence-inspired over-reach）加两类 artifact 检查（直接抄代码 19 次迭代、0.2%；数值复制 59 次迭代、0.7%，其中仅 1 个 run 的最终最优程序保留了复制的解）。对“检索是否真的被用上”给出可核查口径，这在同类工作中少见，也是论文自我证伪的一部分。

**关于原创边界（审稿人判断）。** 方法的关键组件均有出处:OpenEvolve 提供 scaffold，population state descriptor 明确沿用 EvoX（§3.4 原文 “Following EvoX”），Tavily 提供搜索，oracle 文档由 Claude Code 生成（§C.2）。根据本文 related work 与实验对比，只能确认作者声称的差异（双层 vs 顺序/联合耦合、按预测分排序文档）；是否“首次提出”还需要更完整的文献检索。

## 3. 作者如何解决？

**直觉说明。** 与其每次迭代都盲目搜索、或永远不搜索，EvoDuet 把“该不该查、查什么”拆成三步模型自评:先说清“我现在缺什么知识”（gate），如果判断要查，就在内层反复“写查询→执行搜索→预测每篇文档单独能让候选解涨多少分→留下最有希望的几篇并更新知识状态”，最后外层拿着这几篇文档并行生成候选解、真实评估，并把“哪篇文档最终带来多少分”写回数据库，供以后的 gate 和查询参考。整个过程不动模型参数:改进来自推理时的流程与检索行为，而不是训练。

**运行流程（Algorithm 1 与 Algorithm 2，均为原文事实）。**

1. **输入**:任务 $(I,x_0,\mathcal{E})$、scaffold 的选择策略 $\phi$、外层迭代数 $T$、候选数 $N$、检索预算 $(R,J,M,D,K)$。OpenEvolve 提供人口库 $\mathcal{D}_e$ 与 $\phi$。
2. **每次外层迭代** $t$:$\phi$ 从 $\mathcal{D}_e$ 选出父解 $x_t$ 与进化历史 $\mathcal{H}_t$，组成上下文 $c_t=[\mathcal{H}_t;x_t]$（Algorithm 1 第 5 行）。
3. **门控**:一次模型调用 $(K_t,g_t)=\textsc{Gate}_{\mathcal{M}_\theta}(c_t,\mathcal{D}_s)$（Algorithm 1 第 6 行；Eq. 3）。gate 在人口分析之前运行，no-op 与 look-up 不需要额外的分析调用（§B.2）。
   - no-op:$\mathcal{S}_t=\varnothing$，$N_t=1$，不搜索；
   - look-up:gate 直接给出 $\mathcal{D}_s$ 中的文档 id，其正文进入解 prompt，不搜索，$N_t=N$；
   - retrieve:进入内层（Algorithm 2）。
4. **内层（仅 retrieve 时）**:固定父解、其分数、进化历史与人口状态描述子 $A_t$（由确定性统计经一次模型调用转为“事实性观察”，沿用 EvoX 的提示词，§3.4 / §B.3），在 $R=3$ 轮里做四件事:（1）查询构造:每轮 $J=1$ 条查询，模型输出查询文本（≤500 字符）、关键词、目标来源类型、预期发现方向与理由；（2）web 搜索:每个不同查询通过 Tavily（advanced search depth）取回至多 $M=5$ 篇，与上轮保留文档去重合并成池 $\mathcal{P}_r$；（3）假设证据评分:一次模型调用对所有未评分文档给出“用该文档单独改进父解后的评估分”预测 $\hat{s}_t(d)$；（4）知识状态更新:同一次调用用新文档更新 $K_t^r$，然后按预测分保留 Top-$D=3$ 篇。全部 $R$ 轮跑满、无提前停止（§B.3）。
5. **外层生成**:从同一 prompt 并行采样 $N_t$ 个候选（Eq. 2），逐个评估，只把**最优合法候选**交给 $\phi$（若全部失败走 scaffold 的重试策略）。
6. **回写**:把本轮执行的查询、保留文档与预测分、文档 id、父/子实测分与评估器反馈写入 $\mathcal{D}_s$（每个预测只假设单文档，而候选实际使用整个保留集，因此实测结果属于“整次尝试”，中间轮没有单独结果；失败的评估结果记为未知，§B.1）。
7. **输出**:预算内评估分最优的解。

**哪些由模型决定、哪些是固定流程。** 模型决定:门控决策、知识状态文本、查询文本、文档评分、候选解本身。固定流程决定:轮数 $R$、每轮查询数 $J$、每查询文档数 $M$、保留数 $D$、TopD 选择与平局规则、去重规则、预算常量（temperature 0.7、top-p 0.95、medium reasoning effort、≤32,768 输出 token，§B.4）。

**是否需要训练。** 不需要，模型参数全程固定；论文把“训练证据选择与实现能力”留作 future work（Appendix F、G）。方法依赖的外部组件（论文直接使用、非本文提出）:OpenEvolve scaffold、EvoX 的人口状态提示词、Tavily 搜索、GPT-5.6-Luna / Gemini-3.8-Flash / Qwen3.5-9B 等闭源或外部模型。

**成本瓶颈（原文事实）:** 每迭代检索相关模型调用上限:no-op 1 次、look-up 1 次、retrieve ≤ $RJ+R+2=8$ 次（$R=3,J=1$），web 搜索 ≤ $RJ=3$ 次；此外每次检索迭代生成 $N$ 个候选（no-op 只生成 1 个）（§B.4）。这就是该方法在调用预算上的额外开销。

图 5（Figure 5，evoduet_method_overview）是理解方法主干的图:左栏 “Inner Loop: Query Optimization” 画出内层的四步循环（query construction → web search → evidence evaluation → knowledge state 更新，最多 R 轮），并给出 Swap Reduction 的真实片段（dSABRE 的指数深度加权被写进 SWAP 打分器并保留到最终程序）；中栏 “Knowledge-Gap Retrieval Gating” 是中枢，显示 Search DB（snapshot）如何被 gate/查询/评分共享，以及三种决策如何路由到 no-op/look-up/retrieve 对应的外层行为；右栏 “Outer Loop: Solution Optimization” 画出 N 路并行生成、只保留最优合法子代、评估结果回写 Search DB 的闭环，以及 “Up to T iterations” 的整体循环。三个面板缺一不可:左栏是查询怎么进化，中栏是何时检索/复用的决策与记忆，右栏是解怎么用文档前进并把实测结果反哺检索。

**教学简化示例（该例是本文分析者构造，不是论文实验）。** 把进化搜索想成修改一篇论文稿:父解是当前稿子，“文档”是检索到的参考资料。假设证据评分 $=\;$“如果我只拿这一份资料改稿，评审大概会给多少分”——模型不动笔、先给每份资料估个分，按估分决定把哪几份资料摆上桌，再让真正改稿的那一步使用它们。由此可以直觉理解两点设计动机:（1）为什么内层可以不生成程序就优化查询（预测代替真实评估）；（2）为什么“预测有用”仍可能改坏稿子（预测有 20% 落空，见 §4.3）。

## 4. 解决得怎么样？

### 4.1 实验设置

- **任务（§2.2，Table 3）:** 两套共 31 个任务——10 个“简单科学优化”任务（Pressure Vessel、SINDy、Batch Reactor、LABS-27、LJ-13、Chwirut2、Perovskites、SRSD、GuacaMol、Summit）用于第 2 节的动机实验；21 个取自 SimpleTES 的任务（量子编译 Swap Reduction ×1；航天动力学 Cassini、Galileo、Mariner 10、Rosetta、Voyager 2 ×5；科学算法 Denoising ×1；AI foundations Domain Mixture、U Shape、LR & BSZ、Parallel ×4；算法工程 AHC039、AHC058 ×2；数学 Erdős、AC1–AC3、CP n=26/32、Hadamard、Sums/Diffs ×8）用于主实验。Molecule 与 Burgers 只出现在 Table 1(c)/§B.5 的耦合方式对照里，Appendix C 的任务清单没有这两个任务的描述，其来源与评估细节论文未报告。
- **模型与 scaffold:** 主实验用 GPT-5.6-Luna、Gemini-3.8-Flash、Qwen3.5-9B 作为冻结的 $\mathcal{M}_\theta$，scaffold 为 OpenEvolve；Table 1(d) 另测 Top-$K$ 与 EvoX；Rosetta 的一条轨迹用了 GPT-5.6-Sol（Table 13）。
- **基线:** OpenEvolve（无搜索 / 每迭代给 oracle 文档）；joint-level（Tavily 在解循环内使用）；DeepEvolve（顺序耦合，**使用其已发表分数**）；随机门控与停滞启发式门控（Table 1(b)）。
- **指标:** Normalized Discovery Gain（NDG，§2.2）:$\mathrm{NDG}=\frac{\mathcal{E}(x_{\mathrm{best}})-\mathcal{E}(x_{0})}{\mathcal{E}(x_{\mathrm{SOTA}})-\mathcal{E}(x_{0})}\times 100$，以 SimpleTES 发布的最优程序为 SOTA 锚；另报告任务原生分数与美元成本。
- **预算与种子:** 每个条件 4 个随机种子；主图（Fig. 6）报告**4 次运行中的最优 NDG**；简单任务跑 20 迭代、其余跑 100 迭代（§D.1）；推理参数见 §B.4。
- **各实验回答什么:** 主实验（Fig. 6、Tables 7–10）比 21 任务上的总体 NDG 与逐组增益；消融回答“门控设计”（Table 1(b)）、“耦合方式”（Table 1(c)、Table 2）、“内层预算”（Table 6）、“跨 scaffold”（Table 1(d)）；分析与审计（Fig. 8、Fig. 16、Appendix E、I、K）回答“检索是如何被使用的、什么时候失败”。

### 4.2 关键结果

以下均为原文事实（除注明作者主张处），格式为:指标 / 任务 / 比较对象 / 条件 / 位置。

- **总体 NDG（best-of-4 的跨任务平均，N=1）:** GPT-5.6-Luna 74.1%→78.0%（+3.9%）；Gemini-3.8-Flash 61.3%→82.3%（+21.0%）；Qwen3.5-9B 反向，N=1 下降 14.4%，N=8 仍比 OpenEvolve 低 4.7%（§4，Fig. 6a）。
- **并行扩展（8 个任务，N=1→8→16）:** GPT-5.6-Luna 平均 NDG 89.6%→95.7%，Gemini-3.8-Flash 84.5%→89.6%，单调上升（§4，Fig. 7）。
- **超越/追平公开最优（Table 1(a)、Table 13）:** 11 个任务的最终最优程序——8 个超过 SimpleTES 参考、3 个在 $10^{-9}$ 内追平（Appendix K 开头）。典型:Swap Reduction（Q20）14,835 vs 15,186 SWAPs；Rosetta $\Delta v$ 1.396424 vs 1.552968 km/s（低 10.1%，§I.7）；Denoising 0.722906 vs 0.722690；Erdős 0.380859 vs 0.380868。需注意量级:Voyager 2 的“超越”只有 3.430214→3.430206，Domain mix 与 Parallel 的增益在 $10^{-4}$ 量级；且其中两个最优程序保留了对公开成果的复用（下条）。11 个 run 的成本区间 11.93–161.33 美元、均值 45.56 美元（§4）。
- **公开成果复用（原文事实，作者主动披露）:** Erdős 行依赖运行时下载公开 witness（§I.5:“its result depends on access to the published artifact”）；Rosetta 最优程序保留了公开 GTOPX 数值种子（§I.7）。§4 明确只有 11 个 SOTA 结果中的 2 个在最优程序中复用了公开 artifact。
- **增益分布（Fig. 6c，126 个任务×模型×候选数组合）:** OpenEvolve 基线 NDG 越高增益越小（Pearson $r=-0.41$）；基线 ≥80% 的 75 个比较中位增益 0.0%；5–20% 区间中位增益 −5.4%（即此区间 EvoDuet 平均反而更差）；基线 <5% 的 10 例中 5 例被抬到 >5%，这 5 例中位增益 +71.8%（§4）。
- **分组结果:** 数学任务在六种模型/预算设置中的五种有提升、平均 +7.1%；算法工程（AHC039/AHC058）六种设置平均 −1.6%，Limitations 承认在该类任务上“不一致地变差”（§4，Fig. 6b；Appendix F）。
- **门控对照（Table 1(b)，Denoising / Erdős）:** knowledge gap 84.5%/100.0% > heuristic 60.6%/99.5% > random 58.5%/93.9%。
- **耦合方式对照（Table 1(c)，Molecule / Burgers / CP n=26）:** EvoDuet 0.8524/0.7846/2.635983；OpenEvolve 0.8496/0.6937/2.635983；joint-level 0.8474/0.6919/2.635980；DeepEvolve（已发表分数）0.8149/0.6666/2.581971。Molecule 与 CP n=26 上的差距很小甚至持平。
- **跨 scaffold（Table 1(d)）:** Sums/Diffs 与 Denoising 上，EvoDuet 分别给 OpenEvolve +23.5%/+84.5%、Top-$K$ +46.7%/+63.6%、EvoX +55.1%/+37.8%（GPT-5.6-Luna）。
- **内层预算消融（Table 6，Denoising，GPT-5.6-Luna）:** $R=1$ 58.35%、$R=3$（默认）81.77%、$R=5$ 34.28%；$J=1$ 81.77%、$J=3$（$k=3$）80.15%、$J=3$（$k=5$）71.86%、$J=5$（$k=3$）57.30%——“更多检索不是更好，两个方向都不是”。
- **不足与负面结果:** Qwen3.5-9B 全场景负增长；Rosetta 上 oracle 文档反而伤害两个模型（§2.3）；Table 4/5 显示同一条件不同种子的方差很大（例:Qwen 的 Swap Reduction 19,802±353，Rosetta 5.0725±1.649）；主结果 Figure 6 只有 best-of-4，**论文未报告**主对比的标准差、置信区间或显著性检验（对照组 Table 4/5 反而报告了 mean±std——口径不统一是本文的一个表述瑕疵）。
- 一处小的交叉引用错误（审稿人判断，供核对）:§2.3 在描述 Sums/Diffs 的 N=8 NDG 提升（25.8%→40.7%）时标注 Figure 4(b)，但按图题该结果属于 Figure 4(a)（4(b) 是累计查询数）。

### 4.3 机制证据

- **代理信号是否可信（支持）:** 4,324 次检索上，假设证据评分与所选候选的实测分 Spearman $\rho=+0.86$；21 个任务全部为正、中位 +0.74（§5.1，Fig. 8a）。这支持“预测分可当内层代理”的用法，但作者没有报告与“无预测的随机排序文档”这一关键对照（见质疑 3）。
- **“promising 文档 ⇒ 改进”是相关性（作者自己标注）:** 当 retrieve 保留至少一篇预测优于父解的文档时，选中候选超越父解的比率 67.1%、刷新 run 最优 14.1%，对比 no-op 的 52.1%/9.6%；look-up 为 61.2%/10.1%；但 36.5% 的检索根本拿不到 promising 文档，此时的改进率只有 38.3%（§5.1，Fig. 8b）。Fig. 16 的题注明说:因为 gate 自己选择文档暴露，这些是**观测性（observational）比较**，不能当作因果。
- **反例与边界（重要）:** 20% 预测“有用”的检索产出了更差的子代；82 个 Luna run 中 29 个出现超过自身总增益 10% 的倒退（§E.1.2；Galileo 案例:预测 0.63701、实际 0.37713，$\Delta v$ 从 1.926 升到 3.873 km/s，§I.6）。跨域迁移的 13 个 flag 运行中也有“检索了但从未采用”的例子（Anscombe 变换在 3 个 Denoising 运行中未进入任何候选；二次剩余初始化出现在 10 个子代但不在最优程序里，§I.2）。因此：**行为 flag ≠ 成功使用证据**，论文自己给出了这条限制。
- **失败机制分析:** Qwen 在文档迭代上的评估失败率 12.4%（无文档 9.2%），超越父解仅 27.7%（Luna 41.1%、Gemini 31.8%）；50 个抽样修订中 26% 未使用或误用文档方法——6% 未用、20% 实现错误（§4、§E.3，Table 11）；该抽样由 Codex（LLM）判读、样本仅 50 个（分母 2,980），比例本身**无法从当前材料独立验证**。
- **能否排除替代解释:** 部分。Table 6 说明内层预算不是单调越多越好，支持“机制而非算力”的方向；但主结果没有与 OpenEvolve 做“调用预算/检索次数对齐”的对照，也没有把“额外模型调用带来的收益”与“检索内容带来的收益”分离（见质疑 3）。

### 4.4 成本与适用范围

- **报告的成本:** Table 1(a) 给出 11 个最优程序的运行成本（11.93–161.33 美元，均值 45.56 美元）；Table 1(e) 的 Denoising 帕累托图（见下方第四张配图）显示:EvoDuet 以约 38.45 美元达到 100.27% NDG，SimpleTES 以估计 API 等价成本 265.39 美元达到 100%，即 **6.9× 成本降低**；更低成本处还有 10.73 美元/86.31% 与极便宜端点（0.58 美元处的 OpenEvolve 基线，88.35% 量级）的参考点（§5.2，Table 1(e)）。
- **论文未报告:** 全 21 任务的平均总成本、每任务 token 消耗、wall-clock 时延、Tavily 单独费用、与 OpenEvolve 的同 token/同调用数对照；除了 Denoising 之外的逐任务成本模型。凡此均不能从当前材料估算。
- **依赖与系统复杂度:** 闭源模型 API（GPT-5.6-Luna、Gemini-3.8-Flash）、外部检索服务 Tavily、以及“检索内容来自公开网页”的可靠性问题（Ethics/G 节讨论了错误来源与夸大新颖性的风险，建议来源归属、独立验证和人工监督，§H）。

第四张配图（对应原文 Table 1(e) 的 Denoising 帕累托面板，非论文中编号为 Figure 4 的那张图）是对“检索开销是否值得”的直接回答:横轴为美元成本（对数刻度）、纵轴为 held-out NDG。右上两个大点分别是 SimpleTES（100.00%，$265.39）与 EvoDuet（100.27%，$38.45，星标），标注 “6.9× cheaper”；左侧更低成本的点（如 $0.58 附近约 88%、$10.73 约 86%）是 OpenEvolve 基线或低成本变体，标注 “+11.92%” 的箭头表示在相近成本档位上 EvoDuet 相对基线多出的 NDG。这张图是论文“成本效率”主张的唯一直接证据，且注意 SimpleTES 的成本是**估计的** API 等价成本，不是其真实运行账单。

- **哪些问题改善、哪些未解决:** 改善的是“检索何时发生、查什么、查到的证据怎么被记住”这一层，以及在部分解决的中间地带任务（基线 NDG 5–80% 区间）上的发现速度与上限；未解决的是弱后端模型无法受益（Qwen）、算法工程类任务变差、以及证据被误实现（20%）的问题。结论适用范围应限定为:**能自行实现检索到的技术方案的前沿模型 + 有明确可验证评估器、且基线尚未饱和的优化任务**。

## 5. 最容易受到审稿人质疑的地方

#### 质疑 1:主结果用 best-of-4 且无方差或显著性检验，GPT-5.6-Luna 的 +3.9% 无法与种子噪声区分

- **原文依据:** Fig. 6 题注“we report the best NDG across four runs”（§4）；同一批实验在附表里报告了很大的种子方差（Table 4 中 Qwen 的 Rosetta 5.0725±1.649、Swap Reduction 19,802±353，Table 5 同）。Qwen 的 −14.4%/−4.7% 与 GPT-5.6-Luna 的 +3.9% 都被同一口径（best-of-4）放大或缩小。
- **为什么重要:** “EvoDuet improves discovery”的总体结论主要靠跨任务平均值支撑；best-of-4 在“选最优”的过程中会系统性高估所有方法，但对高方差方法更有利，也没有给出任何一个统计检验。若 +3.9% 落入噪声，则摘要中“74.1%→78.0%”与“Qwen 不受益”的对比叙事都会被削弱。
- **当前能够得出的判断:** 证据不足。可确认的是 Gemini-3.8-Flash 的 +21.0% 远大于报告过的种子波动量级，方向可信；GPT-5.6-Luna 的 +3.9% 无法确认。
- **如何验证或补强:** 主对比改用与附表一致的 mean±std 口径；按 (任务, 种子) 配对做 per-task 差异检验（如 Wilcoxon 符号秩）与 bootstrap 置信区间；增加种子数；报告 best-of-4 与 mean 两条曲线。
- **严重程度:** 主要问题。

#### 质疑 2:最接近的公开对照 DeepEvolve 未在同模型、同预算下重跑，比较不公平

- **原文依据:** §B.5 明说“DeepEvolve was not rerun with the same model or search budget”，其分数取自论文已发表值且低于本文自建的 OpenEvolve 基线（Table 1(c) 0.8149/0.6666 vs 0.8496/0.6937）；joint-level 基线也是作者自建，其“每迭代至少一次、最多三轮”的 Tavily 预算同样由本文设定（§B.5）。
- **为什么重要:** 论文的核心创新声明是“双层耦合优于顺序耦合”，但唯一的顺序耦合代表（DeepEvolve）是用它自己的模型和预算在同任务上的历史成绩；三种耦合方式从未在统一模型、统一种子、统一搜索次数下对比。这直接关系到创新性证据与结论范围。
- **当前能够得出的判断:** 结论只能限定为“在本实现条件下优于本文实现的两个变体与一个跨文献比较”。比较存在模型、预算、实现三重混杂。
- **如何验证或补强:** 用 GPT-5.6-Luna + Tavily 按 DeepEvolve 的流程（先深研后改码）重跑；或至少在统一 scaffold 上实现“顺序检索”变体并匹配总调用预算。
- **严重程度:** 主要问题。

#### 质疑 3:检索带来的额外预算未被控制，机制证据是观测性的——“查询进化有效”尚未与“多花算力更有效”分离

- **原文依据:** §B.4 调用预算表:retrieve 迭代额外 ≤8 次 LLM 调用 + 3 次搜索（no-op 只有 1 次调用），而主对比（Fig. 6）没有给出同等总调用预算的 OpenEvolve 对照；机制证据本身被作者标注为 observational（Fig. 16 题注）；promising 文档与改进率的 67.1% vs 52.1% 属于相关性；§5.1 的结论句式（“suggest that hypothetical evidence scoring helps identify...”）是作者主张而非常规实验确证。此外论文没有报告“把保留文档替换为随机文档但保持同等调用与搜索次数”的对照。
- **为什么重要:** 若不控制预算，增益可能来自“更多 token、更多候选、更多评估机会”，而非双层共同进化这一机制；这直接决定创新点 1、2 是否成立。
- **当前能够得出的判断:** 存在混杂变量；Table 6 与 Table 2 能排除“单纯把内层拉长”的解释，但不能排除“总预算更高”的解释。
- **如何验证或补强:** 加入预算对齐的 OpenEvolve（同 LLM 调用数与搜索次数）；加入“检索到文档但随机排序/随机保留”“promising 文档置换成不相关文档”的安慰剂对照；报告每任务的 token 与调用统计。
- **严重程度:** 主要问题。

#### 质疑 4:部分“超越 SOTA”的结果依赖复用公开成果，新颖性声明需要逐项限定

- **原文依据:** §I.5:Erdős 的 Table 1(a) 最优程序保留运行时下载公开 witness，“its result depends on access to the published artifact”；§I.7:Rosetta 最优程序保留公开 GTOPX 数值种子；§4 自述 11 个 SOTA 结果中 2 个如此；§E.1.1 的 artifact 检查还发现 4 个 run 嵌入公开数值（3 个 Rosetta 轨迹/飞越日期、1 个 AC2 构造），其中仅 1 个 run 的最优程序保留复制内容。
- **为什么重要:** “超越公开最优分数”是本文最醒目的成果，但如果最优程序包含下载的公开解或公开数值，成绩的部分来源是“整合 + 局部优化”，而不是独立发现；对“科学发现”的卖点与来源公平性都是直接压力。另外 Swap Reduction 的优势被作者注明“specific to Q20”（§I.1），不宜外推。
- **当前能够得出的判断:** 作者披露质量高（Appendix E/K 逐案记录），这对可信度是加分；但主表未逐行标注哪些结果含公开 artifact，读者无法从 Table 1(a) 直接判断每个“超越”的独立程度。当前材料可以确认复用事实存在，具体哪些行受影响需查 Appendix K 源码。
- **如何验证或补强:** 在 Table 1(a) 每行标注“是否含下载/公开数值”；给出“禁用网络下载与公开数值”的对照运行分数；对每个超越行报告不含 artifact 时的最优分。
- **严重程度:** 主要问题（对发现性声明），因披露充分可视为中等偏上。

#### 质疑 5:指标口径与适用范围——NDG 的锚与平均方式会放大结论，跨 scaffold 声明依据太窄

- **原文依据:** NDG 以 SimpleTES 发布的程序为 SOTA 锚（§2.2），锚较弱时 NDG 可超 100%（Denoising 100.27%，Table 1(e)），锚较强时天花板效应明显（GPT-5.6-Luna 基线在 16/31 任务上已达 ≥95%，§2.3）；Fig. 6c 显示基线 5–20% 区间中位增益为负（−5.4%），平均 NDG 由任务构成决定；跨 scaffold 结论（Table 1(d)）只基于 Sums/Diffs 与 Denoising 两个任务，而且 “+84.5%” 这类数字在此任务上的上限受锚定义影响。
- **为什么重要:** 若读者把 “74.1→78.0” 理解为“普遍能力提升”，会高估方法；正确的读法是“在 21 个混合任务集合上的平均，且分布高度不均”。“跨 scaffold 通用”也超出了两个任务所能支持的证据量。
- **当前能够得出的判断:** 结论被平均口径放大；跨 scaffold 声明证据不足，应限制为“在测试的两个任务上可与其他 scaffold 叠加”。
- **如何验证或补强:** 报告 per-task win/loss/tie 计数与分层汇总（按基线 NDG 分箱）；在 Top-$K$/EvoX 上扩展到更多任务（尤其未饱和任务）；对 NDG 锚给出敏感性分析（如用更强锚重算）。
- **严重程度:** 次要问题。

## 6. 审稿式总评

> 作者发现 LLM 进化搜索的“闭搜索”会在需要外部知识时停滞，且把搜索工具简单地塞进解循环会反复返回同一批页面（88.1% 重复 URL、50 迭代后停滞），因此提出 EvoDuet:用知识缺口门控决定查新/复用/不查，用“假设证据评分”在不生成程序的前提下优化查询，并把文档-结果对回写数据库形成闭环。实验在 21 个任务、3 个模型、两个候选预算上表明:前沿模型总体 NDG 提升（Gemini-3.8-Flash +21.0% 证据较强，GPT-5.6-Luna +3.9% 证据弱），8 个任务超过公开最优分数、3 个追平，Denoising 上以约 1/6.9 成本达到同等水平；其中门控与耦合方式的对照消融、内层预算消融、以及行为审计（含公开 artifact 的主动披露）证据较扎实，但 best-of-4 无显著性、DeepEvolve 未同条件重跑、检索预算未对齐，使“机制本身有效”仍缺少充分支持。本文最有价值的部分是把“检索”提升为一个以评估函数为目标的显式优化层，并配套了少见的可审计实验协议；最大的审稿风险是主结果的选择性口径（best-of-4）与对照公平性。

- **问题定义清晰度:** 强。把“闭搜索”与“查询不随解演化”两个瓶颈用 oracle 与 joint-level 两组实验分开论证，问题界定与实验设计一致（§1–§2）。
- **创新性证据:** 中。双层形式化 + 预测式文档评分是真实增量，但组件多来自已有工作（EvoX 状态描述子、OpenEvolve、Tavily），且最接近的公开对照未同条件比较，“首次”边界无法确认（§3、§B.5、§6）。
- **方法可信度:** 中。伪码、预算表、提示词模板、11 份程序源码齐备，机制表述清楚；但内层代理的有效性只给了相关性证据，机制归因受观测性数据限制（§4.3）。
- **实验支持力度:** 中。21 任务 × 3 模型 × 2 预算 + 多类消融 + 行为审计覆盖面可观，且诚实报告负结果；但 best-of-4、无显著性检验、最强对照未重跑、部分最优程序依赖公开 artifact（§4.2、§5）。
- **可复现性:** 中。论文提供完整 prompt（Appendix J）、推理参数与调用预算（§B.4）、轨迹与程序源码（Appendix I/K）；但依赖闭源模型（GPT-5.6-Luna / Gemini-3.8-Flash）与 Tavily 服务，模型侧不可独立复现，Qwen 分析中的 26% 抽样判读由 LLM 完成。
- **综合阅读价值:** 高。对做 LLM Agent、检索增强推理与自动科学发现的读者，“知识缺口门控 + 预测式证据评分 + 结果回写”是可直接迁移的设计模式；对做评测的读者，Appendix E/I 的行为审计与 artifact 检查提供了好的负面样本清单。
