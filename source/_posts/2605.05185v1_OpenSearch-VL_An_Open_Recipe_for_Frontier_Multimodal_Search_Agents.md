## 0. 一句话结论

这篇论文针对“顶级多模态搜索智能体的训练数据、流程与配方不公开、难以复现”的问题，给出一套完全开放的配方：用 Wikipedia 超链接图合成防捷径的多跳 VQA 数据、搭建含视觉修复与检索的七件工具环境、再用带“致命步感知”的多轮 GRPO 训练。论文报告在 7 个知识密集型基准上，8B、30B-A3B、32B 三个规模相对同底座智能体基线平均分别提升 14.6、13.8、15.7 分，证据足以支持“该配方在同底座对比下有效”；但训练池与 LiveVQA、FVQA 两个评测集存在来源重叠且未报告去重、实验无方差、评测与训练复用同一家族 judge（大模型评判员），使“与商业闭源模型可比”这一结论的强度受限。

## 1. 论文具体想解决什么问题？

**背景与任务。** 多模态深搜（multimodal deep search）要求多模态大模型（MLLM）从“被动看图”变成会主动搜索证据、核验事实的智能体：给定图像 I₀ 与问题 q，模型交替输出推理与工具调用，读回观测，最终给出答案（§1、§2）。这一方向的头部系统（Seed、Kimi、Gemini 等）大多闭源，开源侧虽有 MMSearch-R1、WebWatcher、DeepEyes、SenseNova-MARS 等，但训练数据、轨迹合成流程与训练细节披露不足（§1、§6.1）。

**现有方法通常在哪些条件下表现不好。** 论文给出三类瓶颈（§1）：其一，高质量训练数据是核心瓶颈，缺少数据就无法系统研究“哪些数据属性对智能体搜索行为是必需的”；其二，真实图像常有模糊、低分辨率、透视畸变、密集文字等情况，检索本身不能修复坏掉的视觉证据，而多数多模态搜索智能体只做检索，“先修复视觉再检索”没有一起解决（§1、§6.2）；其三，长程工具调用中一次畸形调用、超时或重复失败会级联毁掉整条轨迹——直接丢弃浪费了失败前的有效推理，照单全收又会把失败后的无意义 token 变成噪声梯度（§1、§4.2、§6.3）。

**本文的新观察与主张。** 论文主张两个被忽略的问题：(i) 若问句中保留实体名、或图像锚定在答案实体附近，智能体会退化为“一步检索”捷径（one-step retrieval collapse），图像沦为装饰，多跳能力无从学起（§3.1）；(ii) 组归一化（group normalization）会让低于组均值的失败轨迹把“失败前的正确推理”一起惩罚掉（§4.2、附录 B.2）。这两个现象论文主要用单例反事实分析（附录 D.3：把 Australia_Zoo 的锚点换成答案实体的照片、或跳过模糊改写，任务都塌缩成一次反查/一次文本搜索）与引用前人工作（Geng et al. 2025；Huang et al. 2026）来支撑，**没有给出捷径命中率、过滤前后样本比例等量化证据**——即观察到了现象并用构造性论证解释，但没有实测因果。

**论文实际解决的具体子问题。** 区分为三块：(1) 造出“必须用工具、且必须多跳”的训练数据；(2) 提供一个覆盖“视觉修复 + 检索 + 定位解析”的工具环境，并让智能体在多轮交互中管理好图像/文本混合上下文；(3) 在多轮 RL 中给失败轨迹设计合理的信用分配（credit assignment）方式。核心假设是：数据质量、工具多样性、失败感知训练三件事独立有效，合起来即可复现接近头部的搜索智能体。

## 2. 创新点是什么？

真正的技术增量是“把三件彼此独立的事拼成一条可复现流水线，并在第三件上提出了新的做法”：数据侧是既有思路（多跳采题、实体模糊化、图像锚定）的系统化组合加两个新设计（锚点固定在路径起点而非答案实体、两阶段难度过滤）；训练侧的致命步感知 GRPO 是本文最有新意的算法改动。逐项如下。

**创新 1：防捷径的多跳 VQA 合成流水线。** 在 Wikipedia 超链接图上采样长度 2–4 的受限随机游走，给路径节点标注“锚点/桥接/答案”三种功能角色，再从远到近把桥接实体改写成不含实体名（non-leakage，不泄露）的模糊描述，最后把锚点替换成图像指代（source-anchor visual grounding，源锚视觉锚定）。与最接近的 WebWatcher、Skywork-R1V4 式构造相比，差异是**图像锚在推理链的起点而非答案实体**，使图像成为“承重结构”，单次反查无法解题（§3.1；证据指向 §4.2 表 3(a)：去掉锚定与模糊改写平均掉 11.5 与 10.3 分）。

**创新 2：覆盖视觉修复的七件工具环境。** 统一文本搜索、图像搜索、锐化、超分辨率、透视矫正、裁剪、OCR 七件工具，检索与视觉修复共享同一接口，并在数据合成、RL 采样与推理三处复用（§1、§2、表 1）。与“检索为主”的既有智能体的差异在于它先把坏图修好再检索；证据指向 §4.2 表 3(a)（去掉仅占 10% 的退化增强子集平均掉 1.3 分，作用存在但不大）。

**创新 3：多轮致命步感知 GRPO。** 引入“致命步”（fatal step：连续 K=3 次工具执行错误即判定轨迹致命）：掩掉致命步之后的全部 token，并对致命轨迹的优势（advantage）做单侧裁剪（one-sided clamping）max(r̃ᵢ, 0)——组归一化分数仍按全组计算以保持统计无偏，但致命轨迹的负优势不再惩罚其有效前缀。与 Vision-DeepResearch 的硬掩码（hard-masking，整条丢弃）相比，差异是“保留正梯度、不给负梯度”；证据指向 §4.2 表 3(b)（平均 71.8 对硬掩码 67.7，相对 Vanilla GRPO 的增益 +4.2 对 +0.1）。

**创新 4：全开放交付。** 承诺并实际发布数据（SearchVL-SFT-36k、SearchVL-RL-8k）、三个规模的模型检查点与训练代码（Apache-2.0）。这属于交付层面的贡献，不构成算法创新，也没有消融可测，但它是论文标题中 “Open Recipe” 的实质内容（§1、§6、§7）。

## 3. 作者如何解决？

直觉上，这篇论文把“会不会搜”拆成三件可控的事：**先造出只有多跳搜索才能解的题**（否则模型学的是“一步反查”），**再给它能修图也能搜网的手**（否则坏图直接卡死），**最后在训练时教它别因工具报错而学坏**（否则失败轨迹的梯度会污染正确推理）。三者分别对应数据、环境、优化三个层面，缺少任何一环，末端的强化学习都会学到错误行为。

### 3.1 输入与形式化

输入是一张图 I₀ 和一个问题 q。智能体在第 l 步的条件历史为 h_l =（I_l, q, a_{<l}, o_{<l}），即“累积的图像集合 + 原问题 + 此前的动作序列 + 此前的观测序列”；动作遵循 ReAct（Yao et al., 2022）的“先想后做”约定，写成 a_l = [z_l, c_l]，z_l 是一段推理（论文用 `<think>` 块），c_l 是一次工具调用（`<tool_call>` 块）；最后一步只输出答案（`<response>` 块）。整套交互被记录为轨迹 τ = {(h₀,a₀,o₀), …, (h_L, a_L)}（§2）。这个形式化把“多模态上下文”显式定义成 I_l 与观测序列两部分，是后面所有设计的基础。

### 3.2 数据构造：从 Wikipedia 图到防捷径 VQA

流水线分三阶段（§3、附录 D）。**第一段是路径采样与规范化出题**：把英文 Wikipedia 当成有向图，从种子页面出发做长度 h∈{2,3,4}（概率 0.4/0.4/0.2）的受限随机游走，跳过消歧页、列表页、非条目命名空间、重定向与“枢纽节点”（hub node：入度超过 10,000 的页面，约占 0.03%）；路径上 v₀ 是锚点（视觉入口）、中间节点是桥接实体、v_h 是答案节点，答案 a 从 v_h 的词条中抽取（要求 6 token 以内的短答案），再由 GPT-4o 生成一句规范化问句 q_t（附录 D.1、D.2 给出了 Australia_Zoo → Steve_Irwin → Terri_Irwin 的完整例子，最终答案是 “20 November 2009”）。**第二段是模糊实体改写**：从离锚点最远的桥接实体开始逐个把实体名替换成属性/关系描述，每次替换必须同时满足三个不变式——答案不变、在评判器世界知识下唯一指向该实体、问句中不出现路径上任何实体的别名；为避免模板化，还会间歇对答案做混淆改写。**第三段是锚点视觉锚定**：从 Wikimedia Commons 取锚点的代表性图片，用 CLIP 相似度筛选（阈值 0.28；例子中得 0.34），把问句里的锚点提及替换成“图中的人/图中的动物园”这类视觉指代表达（visual referring expression），得到最终的 (I, q, a)。之后再做自动质检（掩蔽、唯一性、视觉相关性、非平凡性四项）。

随后是合并与过滤（§3.2）：把 Wikipedia 合成样本与 LiveVQA、FVQA、WebQA 三个开源多模态语料合并，用一个冻结的 Qwen3-VL-32B 做两阶段难度过滤——先删“不用工具就能答对”的样本，再删“一次 ImageSearch 就能答对”的样本，确保保留下来的题真的需要“先看图定位、再走文本关系链”。此外随机抽 10% 的样本做受控退化（模糊、降采样、透视畸变），并用对应的修复工具（Sharpen、SuperResolution、PerspectiveCorrect）配对，专门训练“先修图再检索”的行为。

第三阶段是轨迹合成（§3.3）：对每个样本用 Claude Opus 4.6 作为专家模型在真实环境里自由调用工具，独立采样 K=5 条多轮 ReAct 轨迹，再走两级拒绝采样——先按答案正确性剔除（GPT-4o 评判），再由 GPT-5.4 过程级评判器按“工具使用、推理与观测的逻辑一致性、是否有无效重复”审查。两级级联后得到 36,592 条专家轨迹，平均每条 6.3 次工具调用，即 SFT 语料 SearchVL-SFT-36k。图 1 给出了整条流水线的组件与数据流。

![图 1：数据构造流水线总览](/images/dailypaper/2026-10-15/2605.05185v1_fig1_data_curation_pipeline.png)

**图 1**（论文 Fig. 1）：整张图回答“训练数据从哪来、每一步解决什么问题”。上半部分是 VQA 合成的闭环：从 Wikipedia 图上的受限随机游走开始（明确列出跳过消歧页/列表页/环/枢纽节点的约束），把路径转成规范问句后进入模糊改写，右侧强调“答案不变、唯一性、不泄露”三不变式与“图像锚定到路径起点”的取舍，随后经质检汇入多跳 VQA 池。下半部分说明路线分岔：一条走“分级过滤”（先剔除不用工具、再剔除一次图像搜索可解的样本），另一条是抽 10% 做退化—修复配对，最终筛选后的题集进入专家轨迹合成，由拒绝采样产出 36k 条轨迹。读者应从中理解的关键是：数据质量不是靠规模，而是靠“约束采题 + 三不变式改写 + 两阶段难度过滤”三道闸门共同保证的，而图像的锚点位置决定了题目是否真的多跳。

小结：这三道闸门把“必须多跳”与“必须看图”从数据属性变成出题阶段的硬约束，而不是事后筛选——为后面在真实环境里学习工具调用提供了干净的分布基础。

### 3.3 工具环境：七件工具与多模态上下文管理

**工具是固定流程执行的部分，模型只决定“调用哪个、传什么参数”。** 环境按工具族确定性路由观测：视觉工具（除 OCR 外）返回图像观测，检索工具与 OCR 返回文本观测（§2）。七件工具分三类（表 1、附录 F）：检索类的 TextSearch 实际是三段流水线（Serper 检索 top-k URL → JINA Reader 抓取正文转 Markdown → Qwen3-32B 生成每篇 2–4 句“面向查询”的摘要），输出是带标题与 URL 的摘要列表；ImageSearch 走 Polaris Lens 反查相似图与实体；增强类是本地确定性算子（OpenCV 非锐化掩蔽、EDSR 超分、Canny 四边形检测 + 四点透视变换），坏权重或找不到四边形时优雅退化返回原图；注意力解析类的 Crop 按 (x, y, w, h) 切出子图写盘，OCR 走远端 PaddleX 输出带版面标签与阅读顺序的结构化文本块（表 1、附录 F）。系统提示还用“工作流配方”把组合用法写死：读不清的文档 `perspective_correct → sharpen → layout_parsing`，密集图表先 `crop` 再解析，先 `image_search` 后**必须**跟一次 `text_search`（附录 E）。这些是提示与固定流程约束，模型不被允许自行发明工具。

**多模态上下文如何组织、保留、复用（用户关注点）。** 论文对这一点有几处明确设计，值得逐条说清。第一，**观测分流**：图像观测直接注入视觉主干（visual backbone），天然不经过 token 级损失；文本观测（检索结果与 OCR 解析）以 token 形式进入上下文，但被生成掩码排除在损失之外（§2、§4.1）。第二，**上下文单调增长、无淘汰机制**：论文明确写出“主动视觉上下文随步骤单调增长”，I_l = {I₀} ∪ {o_k : k < l 且 o_k 是图像观测}，即所有历史图像都保留在上下文里，论文没有提出任何图像裁剪、摘要或淘汰策略（§2）。第三，**跨轮复用靠图像句柄**：系统提示规定初始图是 img_1，每次工具输出依次产生 img_2、img_3…，并要求“始终对最新的最佳版本操作”；因此上一轮 Crop 出的子图可以被下一轮 ImageSearch 直接引用（附录 E）。第四，**文本侧的压缩发生在工具内部**：检索结果不是原始网页，而是查询聚焦的 2–4 句摘要，OCR 输出结构化块，这是“工具内压缩”而非“上下文内裁剪”。第五，**实现层适配**：作者为 Qwen3-VL 写了图文打包（packing）与“变长视觉观测的图像 token 重对齐”例程，使视觉工具产出的图像能原样被策略消费，SFT 阶段图像分辨率上限设为 262,144 像素（约 512×512）（附录 C、表 4）。论文用一个真实推理轨迹（论文 Fig. 9）展示这条回路：模型先裁剪路牌 → 用裁剪图做图像搜索识别出 Kessock Bridge → 用文本搜索核验通车年份 1982，随后立即给出答案；图 2 即该轨迹。

![图 2：多轮工具调用的真实轨迹](/images/dailypaper/2026-10-15/2605.05185v1_fig9_case_study.png)

**图 2**（论文 Fig. 9）：这张案例图展示一次完整的多轮搜索如何在混合上下文中推进。轨迹从一张桥梁照片与原问题开始，模型的每一步都遵循“先写 think 再发 tool_call，等到观测回来再决定下一步”的节奏：先把路牌区域裁剪出来（工具返回一个新的图像句柄），再把这张裁剪图交给图像搜索换取文字线索，再用文字搜索定位到具体网页摘要，最终在证据收敛时输出答案。读者应关注的机制点是：工具返回的既有图像也有文本，它们都被追加进同一段持续增长的上下文，而图像句柄让上一轮的视觉产物能作为下一轮工具的输入参与检索——这正是“多模态上下文管理”在本文中的具体形态。需要指出，这是定性展示而非量化证据，论文没有给出上下文长度、图像 token 数或“保留全部图像 vs 只留最新一张”的对照实验。

小结：工具环境由两部分组成——七件工具提供确定性的执行能力，系统提示用“工作流配方”约束组合方式；而多模态上下文的管理没有独立记忆模块，完全依赖“观测追加 + 图像句柄”这一朴素机制。

### 3.4 训练一：SFT 冷启动

SFT（supervised fine-tuning，监督微调）用 36,592 条专家轨迹做多轮工具交错的全参数微调，损失只覆盖模型自己生成的 token：把每步动作拆成推理 z_l 与工具调用 c_l 两段分别取对数似然求和，而工具观测 o_l 只作为上下文条件、不进损失（这一点沿用 Search-R1 的检索 token 掩码策略；§4.1 式 8）。训练配置为 LlamaFactory 扩展的多轮数据集整理器、DeepSpeed ZeRO-3、8B 全量微调含视觉塔与多模态投影器、序列上限 32k token、学习率 2×10⁻⁵、8 个 epoch、有效批大小 256（附录 C.1、表 4）。SFT 的目的是先让模型学会“说该说的话、调该调的接口”，为后续 RL 提供稳定初始化。

### 3.5 训练二：多轮致命步感知 GRPO

RL 阶段用 GRPO（Group Relative Policy Optimization，组相对策略优化）的搜索增强版做在线探索，但对环境、奖励与优势估计都做了改动（§4.2、附录 A、B）。

**采样与奖励。** 对每个提示（I₀, q）采样一组 G 条多轮轨迹（8B 用 G=8，30B-A3B 用 G=16；表 5），每条轨迹的奖励是三项乘积：格式分 r_fmt 作为乘法门 × 准确率分与查询质量分的加权和：

r(τ) = r_fmt(τ) · [α · r_acc(τ) + (1 − α) · r_query(τ)]，α = 0.8

其中 r_fmt 是确定性结构检查（每步必须是 `<think>` 紧跟 `<tool_call>`，末步必须是 `<response>`，结构违规或触发工具执行错误即该步得 0），它作为乘法门会把结构崩坏轨迹的总分压到近零；r_acc 是终局的二值正确性（GPT-4o LLM-as-Judge，被判致命而提前截断的轨迹确定性地记 0）；r_query 是过程分（GPT-5.4 评判，0 到 1），按四个维度打分：查询与问题的语义相关性、跨轮查询的逻辑推进、检索内容的信噪比、图像与文本检索的跨模态互补性——对致命轨迹，评判只看致命步之前的有效前缀（§4.2）。查询质量分的作用是对冲终局奖励在长程任务上的稀疏性。

**失败处理：致命步检测、掩码与单侧裁剪。** 环境把工具执行错误（超时、载荷畸形、参数解析失败）确定性记为一次错误，连续 3 次错误即判定轨迹在第 fᵢ 步进入致命状态；没有触发则 fᵢ = Lᵢ+1（附录 B.1，K=3 的取法是保守的，允许模型先自我纠正）。随后训练掩码在原“生成 token 掩码”上再乘一个指示函数，把致命步之后的全部 token 清零，使梯度只经过有效前缀；同时所有轨迹（含致命）仍参与组均值与标准差的计算，以保持组统计无偏。最后对致命轨迹做单侧裁剪：

Âᵢ = r̃ᵢ（非致命）；Âᵢ = max(r̃ᵢ, 0)（致命）

直觉是：致命轨迹若本来比组均值好（r̃ᵢ > 0），就只在有效前缀上被正向强化；若低于组均值，也**不给负梯度**，避免把失败前的正确推理一起打压。附录 B.2 给出了形式化命题——在该方案下，致命轨迹的有效前缀梯度与搜索增强 GRPO 在非负优势下的一致，而硬掩码的梯度为 0，因此新方案“弱占优”；作者也诚实披露该裁剪会给组内带来一个非负的偏置 b_G ≥ 0（因为把负的致命优势映射成 0），并用 10,000 个组的聚合分布说明 91.8% 的致命轨迹落在负侧、只有 8.2% 被保留，且被保留者的分布与非致命的右峰重叠（论文 Fig. 5，见本报告 §4.3 图 6）。图 3 给出该训练流水线的整体结构。

![图 3：多轮致命步感知 GRPO 训练流水线](/images/dailypaper/2026-10-15/2605.05185v1_fig2_rl_training_pipeline.png)

**图 3**（论文 Fig. 2）：该图把 RL 阶段拆成“采样—评分—归一化—更新”四段。左侧策略模型在真实环境中对同一提示采样一组轨迹，轨迹内部是 think/tool_call/observation 的交错结构；中间三个评分器并行工作，分别产生准确率、格式与查询质量三个信号，合成轨迹级奖励；右侧先按是否触发连续工具错误把轨迹标成非致命/致命，再做组内归一化与优势计算——非致命轨迹保号，致命轨迹用单侧裁剪把负值归零。图下部的两个小面板说明判定逻辑：孤立的单次工具报错可恢复、轨迹仍算非致命，只有连续错误级联才被判致命，此时有效前缀保留梯度而失败之后的 token 被掩掉。读者应理解的核心是：本文的 RL 改动集中在“哪些 token 参与梯度”和“失败轨迹的优势怎么算”两处，而非改动 GRPO 的采样或目标函数主干。

小结：这一改动的效果集中在训练动力学层面——它改变的是“哪些 token 参与梯度”与“失败轨迹的优势如何计算”，GRPO 的采样与目标主干保持不变。

### 3.6 推理阶段与输出

推理阶段不需要任何新增模块：模型仍以附录 E 的系统提示与同一套工具运行“想—调—看”循环，证据足够时输出 `<response>` 结束（同一份系统提示同时用于推理与 SFT 数据收集）。RL 带来的变化是行为层面的：论文的训练曲线显示致命步感知方案让模型维持更长的工具调用轮数并获得更高批次准确率（§5.2；论文 Fig. 3，见 §4.2 图 4）；评测时不再使用任何训练期评判器参与决策，最终答案用与 VDR 基准一致协议的 GPT-4o 评判器与参考答案比对，指标为 Pass@1（§5、附录 E）。数据侧还有一个细节：RL 的 8K 样本从 §3.2 过滤后的 VQA 池中随机抽取，论文明确保证它们与 SFT 轨迹所用的样本不相交（§5）。

## 4. 解决得怎么样？

#### 4.1 实验设置

评测覆盖 7 个知识密集型基准：SimpleVQA、VDR、MMSearch、LiveVQA、BrowseComp-VL、FVQA、InfoSeek，范围是视觉实体识别、网页证据检索、多跳推理与长尾问答（§5）。底座为 Qwen3-VL-8B-Instruct、Qwen3-VL-30B-A3B-Instruct、Qwen3-VL-32B-Instruct 三个变体；基线分三类：直接推理（GPT-4o、GPT-5、Gemini-2.5-Flash/Pro、Claude-4-Sonnet、Claude-3.7-Sonnet、Qwen3-VL 各规模）、RAG 工作流（Retrieval-Augmented Generation，检索增强生成：一次性把检索结果塞进上下文）、智能体工作流（MMSearch-R1-7B、Visual-ARFT-7B、DeepMMSearch-R1-7B、DeepEyes-v2-7B、WebWatcher-7B/32B、SenseNova-MARS-8B、Qwen3-VL 各规模）。指标为 Pass@1，正确性由 GPT-4o 评判器按 VDR-Bench 协议裁定（表 2、附录 E 的评测提示）。训练数据为 36K SFT 轨迹与 8K RL 样本（后者与前者不相交），全部训练在 Nvidia H20 上完成：智能体 SFT 在 256 张 H20 上，8B 约 2 天、30B-A3B 约 4 天；随后的致命步感知 GRPO 约 200 个优化步、在 64 张 H20 上跑 10 天（§5）。消融在 8B 上做，分两组：表 3(a) 拆数据流水线四个部件，表 3(b) 拆 RL 配方四个层级，都只在 SimpleVQA、InfoSeek、FVQA 三个基准上评测；附录主要回答实现细节（SFT/RL 超参、系统提示、工具规范、路径采样与运行示例、案例研究）。

#### 4.2 关键结果

**主结果（表 2）。** 与同底座智能体基线相比：8B 平均从 42.0 提升到 56.6（+14.6），超过此前最强的开源 8B 智能体 SenseNova-MARS-8B（52.7）3.9 分；30B-A3B 从 47.8 到 61.6（+13.8），其中 VDR 20.2→33.5（+13.3）、MMSearch 44.2→68.7（+24.5）、FVQA 63.0→73.2（+10.2）、InfoSeek 56.2→72.4（+16.2）；32B 从 48.0 到 63.7（+15.7）。32B 的 63.7 分同时高于 GPT-5 的 RAG 工作流（53.6）与 Gemini-2.5-Pro 的直接推理（46.0），这是论文“与商业模型可比”主张的主要依据。值得注意的是 8B 版本（56.6）本身已超过 30B-A3B 的智能体基线（47.8），说明该配方在同底座上的增益不依赖模型规模。

**提升较小或未超越的部分。** BrowseComp-VL 上三个规模（37.6 / 41.1 / 43.8）全部低于 GPT-5 的直接推理（48.6）与 RAG（54.9）——这是唯一一个对所有开源对比均出现“被商业模型压制”的基准，论文正文并未点出这一反例。VDR 上 8B 版本（20.8）只比 SenseNova-MARS-8B（19.4）高 1.4 分；LiveVQA 上 30B-A3B 相对基线的提升（62.0→67.4，+5.4）反而小于 8B 的（50.6→59.6，+9.0），说明提升幅度并不随模型规模单调增长。**论文未报告任何方差、置信区间或显著性检验**（Limitations 中承认“为大规模评测报告多种子误差棒成本过高”），因此 1–3 分区间的比较无法判断是否超过噪声。

**消融结果（表 3）。** 数据侧：完整流水线在三个基准上平均 64.6 分，去掉源锚视觉锚定降 11.5 分（53.1）、去掉模糊实体改写降 10.3 分（54.3）、去掉分级过滤降 8.2 分（56.4）、去掉退化增强子集只降 1.3 分（63.3）；作者据此把前三者解释为“防捷径与保难度”的核心，把增强子集解释为“主要提升鲁棒性而非核心增益”。RL 侧（均为 8B、同一 SFT 初始化）：Vanilla GRPO 把平均从 64.6 提升到 67.6；换用 Vision-DeepResearch 的硬掩码几乎不变（67.7，+0.1）；只用致命掩码则到 69.1（+1.5）；叠加单侧裁剪的完整方法到 71.8（+4.2），在三基准上均为最优。需要指出，硬掩码并非在所有单指标上都无益：它在 InfoSeek 上比 vanilla GRPO 高 1.4 分（67.9 对 66.5），但在 SimpleVQA 和 FVQA 上各低 0.5 分（68.3 对 68.8；66.9 对 67.4），“几乎无增益”的结论建立在平均值之上。图 4 的训练动态进一步支撑致命步感知方案的行为差异。

![图 4：RL 阶段训练动态（轮数与批次准确率）](/images/dailypaper/2026-10-15/2605.05185v1_fig3_training_dynamics.png)

**图 4**（论文 Fig. 3）：这幅双面板曲线图记录 RL 训练过程中模型行为的变化，左轴关注每条 rollout 平均经过多少个工具调用轮次，右轴关注批级准确率，三条曲线分别对应硬掩码、vanilla GRPO 与本文的致命步感知方案。随着训练推进，三种方案准确率都在上升，但本文方案的曲线在后期稳定在更高位置，且工具调用轮数长期维持在更高水平而没有像另外两条那样回落——作者据此论证该方案“鼓励有效的持续探索，而不是过早压制困难轨迹”。读者应理解的是：这条证据展示的是训练过程的行为相关性（更长的轨迹伴随更高的准确率），它支持“裁剪保留了有益的探索信号”这一解释，但本身不能排除“更长轨迹只是副作用”的可能。

#### 4.3 机制证据

**对 §2 每个创新点逐一核对。** 创新 1（防捷径数据流水线）：有直接消融，四个组件（锚定、模糊改写、过滤、增强子集）都做了移除实验，且方向一致（表 3(a)），是本论文机制证据最扎实的一项；但其“防捷径”的因果解释仍依赖附录 D.3 的单例反事实分析与设计论证，论文未报告过滤前后捷径命中率的实测统计。创新 2（七件工具环境）：证据最弱——只测了退化增强子集的移除（-1.3），从未单独移除 Crop、OCR、ImageSearch 等组件，“工具的多样性是否必要”在实验上未被隔离；且增强子集消融在三个基准上的降幅都不超过 2.1 分，提示“视觉修复”对总分贡献有限。创新 3（致命步感知 GRPO）：证据最强——表 3(b) 的四个层级把“丢弃整条（硬掩码）”“只掩码”“掩码 + 单侧裁剪”逐级隔离，显示增益主要来自掩码（+1.5）与裁剪（+2.7），且图 4 的训练动态与图 5、图 6 的分布统计从不同侧面吻合。创新 4（全开放交付）：无消融可测，属交付层面。**多模态上下文管理（用户关注点）**：论文没有针对“上下文如何组织/保留”做任何对照实验——没有“保留全部历史图像 vs 只保留最新一张 vs 淘汰无关图像”的比较，也没有图像 token 数或上下文长度随轮次的统计，因此“多模态上下文管理比较有用”在本文中只是设计与定性展示（论文 Fig. 9 的案例轨迹显示裁剪图被后续图像搜索、再被文本搜索接力复用），缺乏针对性证据。

**机制证据本身的两张图。** 图 5 用两个难度不同的 rollout 组说明单侧裁剪在“组均值较低”时保留部分致命轨迹的有效前缀（Âᵢ > 0，只对前缀给正梯度），在“组均值较高”时退化为硬掩码（Âᵢ = 0）。

**图 5**（论文 Fig. 4）：该图对比两种组内情形，解释裁剪函数如何随组难度改变行为。上排两组柱状图把同一提示下的 16 条 rollout 按奖励排序，蓝色为非致命、砖红为致命，虚线是组均值，柱体外框标记致命轨迹的裁剪结果；下排的色带示意一条代表性致命轨迹的 token 级处理：深绿段是被保留梯度的有效前缀，浅灰段是被掩掉的失败后 token。读者应读出两条规则：当组均值较低、部分致命轨迹反而高于均值时，模型只强化它们失败前的推理（前缀保号、失败之后掩掉）；当组均值较高、所有致命轨迹都远低于均值时，裁剪把它们全部归零，等于退化为“整条丢弃之外、但前缀也不惩罚”的硬掩码，从而避免用负梯度破坏可能是正确的推理。

#### 4.4 成本与适用范围

**论文报告的成本。** 训练：SFT 在 256 张 H20 上约 2 天（8B）、4 天（30B-A3B）；RL 在 64 张 H20 上约 200 个优化步、约 10 天；32B 的 SFT 或 RL 成本**论文未报告**。数据合成：每个样本用 Claude Opus 4.6 采样 5 条轨迹，再经 GPT-4o 答案判定与 GPT-5.4 过程判定两级拒绝采样，最终保留 36,592 条、平均 6.3 次工具调用；被拒绝的原始 rollout 总数与 API 花费**论文未报告**。推理侧：论文未报告推理时延、评测时的 token 消耗或工具调用次数（只给出训练配置上限：RL 的响应长度上限 70,000 token、提示上限 4,096 token，SFT 序列上限 32,000 token，SFT 图像上限 262,144 像素）。人工标注为零（全自动流水线，但依赖人工设计的提示与评分 rubric）。外部依赖包括 Claude Opus 4.6、GPT-4o、GPT-5.4、Serper、JINA Reader、Polaris Lens 与 PaddleX OCR；论文在 Limitations 中自认这些外部服务带来版本依赖、抓取失败、排序漂移与摘要幻觉，会推高奖励方差，且“精确数值复现”受此限制。

**得到改善与仍未解决的问题。** 得到改善的是：同底座下的多跳搜索准确率（7 个基准一致提升）、长程工具调用的鲁棒性（训练曲线更稳定）、以及研究透明度（数据、代码、模型均已公开，仓库为 Apache-2.0，模型与两个数据集已上线 Hugging Face）；仍未解决的是：奖励评判只覆盖文本查询、忽略 Crop 等中间视觉操作（Limitations 自认）、外部工具环境不可控、以及缺少方差与失败案例分析。结论的适用范围应限定为：Qwen3-VL 系列底座、7 个知识密集型问答/搜索基准、以及论文所述的英文网页检索场景；不能外推为“普遍提升智能体能力”。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：训练数据池与 LiveVQA、FVQA 两个评测集来源重叠，论文未说明如何避免评测样本泄漏

- **原文依据**：§3.2 明确把 LiveVQA、FVQA、WebQA 三个开源语料与 Wikipedia 合成样本合并为 VQA 池；§5 的 Datasets 段落说明 RL 的 8K 样本“从 §3.2 过滤后的 VQA 池中随机抽取”，只承诺“与 SFT 轨迹所用样本不相交”；而 §5 的评测基准列表同样包含 LiveVQA 与 FVQA（表 2）。
- **为什么重要**：这直接决定表 2 中两列最大提升的可信度——32B 在 LiveVQA 上相对同底座基线提升 25.0 分、8B 在 FVQA 上提升 12.8 分，若训练池包含评测样本（或同一图像/实体的近似样本），这些增益部分来自记忆而非能力。
- **当前能够得出的判断**：无法确认是否真的泄漏——论文可能使用了这两个数据集的官方 train split，但没有披露划分方式、也没有报告训练样本与评测样本的去重统计。属于证据不足而非已被证伪。
- **如何验证或补强**：披露 LiveVQA/FVQA/WebQA 的 split 与过滤规则，给出训练池与评测集按问答对、图像哈希与实体名的交集统计，或在剔除重叠样本后重新评测并报告差异。
- **严重程度**：主要问题（若重叠被证实，则升级为致命问题）

#### 质疑：32B 规模的训练路径与三个规模的成本披露不完整，“配方可扩展”缺少对称证据

- **原文依据**：附录 C.2 开篇写明表 5 覆盖“我们做 RL 微调的两个变体：8B 密集与 30B-A3B MoE”，即 32B 的 RL 配置没有被报告；§5 的实现细节只给出 8B 与 30B-A3B 的 SFT 时长，未提 32B 的训练成本。而主表（表 2）把 32B 的 63.7 分（多项第一）作为核心卖点。
- **为什么重要**：若 32B 只做 SFT，则三个规模并非同一条“配方”，§5.1“训练配方从 8B 有效扩展到 32B”的结论混入了训练路径差异；读者也无法评估复现 32B 结果所需的预算。
- **当前能够得出的判断**：论文未报告 32B 是否经 RL 训练、用何种配置；无法确认。
- **如何验证或补强**：补充 32B 的完整训练阶段与超参表（或明确声明其为 SFT-only），并给出三个规模的训练成本对照。
- **严重程度**：主要问题

#### 质疑：全部主结果无方差，且评测与训练复用同一 GPT-4o 评判体系

- **原文依据**：表 2 为单点数字，无置信区间或多种子报告（Limitations 承认未提供误差棒）；RL 的 r_acc 由 GPT-4o 按 LLM-as-Judge 计算（§4.2），基准评测同样由 GPT-4o 判定（§5、附录 E 中的论文 Fig. 10），且两者提示结构几乎相同。
- **为什么重要**：其一，8B 与 SenseNova-MARS-8B 的差距只有 3.9 分，无方差时无法排除噪声；其二，训练奖励与评测裁决同族同源，模型可能学到“更容易被该评判器判对”的回答风格，而论文 Fig. 10 的判定标准是“报告任何位置包含正确答案即算正确”，这会系统性偏好啰嗦的深研报告式回答。
- **当前能够得出的判断**：存在评估独立性风险与混杂因素，论文未提供可排除的证据。
- **如何验证或补强**：多轮随机种子评测并报告区间；用异构评判器（不同模型或人工）交叉复评；报告开放答案评测中评判器与人工的一致性。
- **严重程度**：主要问题

#### 质疑：消融覆盖窄、单指标反例被平均掩盖，关键超参无敏感性分析

- **原文依据**：表 3(a) 与 3(b) 均只在 8B 与 3 个基准上完成；表 3(b) 中硬掩码在 SimpleVQA（68.3 对 68.8）与 FVQA（66.9 对 67.4）上低于 vanilla GRPO，正文只写“几乎没有增益（67.6→67.7）”；七件工具中从未做单件移除实验；“连续 3 次错误算致命”（K=3）与奖励权重 α=0.8 均无敏感性分析。
- **为什么重要**：这影响“每个组件都必要”这一结论的证据强度——例如硬掩码在小样本基准上的表现提示对照差异可能处于噪声量级，而 3 基准平均不足以支撑“整个流水线的每个阶段都重要”。
- **当前能够得出的判断**：部分结论依赖均值；对于工具环境与超参，论文未报告可隔离变量的实验。
- **如何验证或补强**：在全部 7 个基准与多种子上重跑消融；对 K、α 与采样组大小 G 做敏感性扫描；补充单件工具移除与“有工具但无视觉修复”的对照。
- **严重程度**：主要问题

#### 质疑：实现细节的表述不一致（评判器型号、工具命名、训练步数口径）

- **原文依据**：r_query 的评判模型在 §4.2 为“GPT-5.4”，在图 11 的图注中却写作“GPT-4o judge prompt”，Limitations 又称复合奖励“依赖专有 GPT-4o 评判器”，三处不一致；论文表 1 的“OCR”在系统提示（附录 E）与代码仓库中名为 `layout_parsing`，仓库 README 列出的工具集为 10 件（多出 web_search、visit、python_interpreter），与论文表 1 的 7 件对不上；§5 称 RL 阶段“约 200 个优化步”，而表 5 给 8B 配置的是“Total Epochs 100”（8K 样本、批 256 时百个 epoch 远多于 200 步），两种口径无法直接换算。
- **为什么重要**：奖励定义的准确性直接影响结果解释；工具与步数的口径差异会妨碍复现与外部核验。
- **当前能够得出的判断**：这些是论文、图注与代码实现之间的表述不一致，难以从论文单独判断以哪个为准。
- **如何验证或补强**：以公开代码仓库为准核对评判器版本与步数统计口径，并统一论文、图注与仓库的表述。
- **严重程度**：次要问题

## 6. 审稿式总评

> 作者发现顶级多模态搜索智能体难以复现的根因在数据、工具与长程 RL 三处，因此提出一条完全开放的配方：用 Wikipedia 多跳采题加模糊改写与源锚图像锚定合成防捷径数据，用七件工具统一视觉修复与检索，并用致命步感知 GRPO 掩掉失败后的 token、单侧裁剪保留有效前缀的梯度。实验在 7 个知识密集型基准、三个 Qwen3-VL 规模上表明同底座平均提升 13.8–15.7 分，并在部分基准追平商业闭源模型；其中 RL 失败处理与数据流水线的消融证据较强，但训练池与 LiveVQA/FVQA 评测集的重叠风险、无方差报告、评测与训练共用评判器以及 32B 训练路径未披露，仍缺少充分支持。本文最有价值的部分是把“数据—工具—训练”的完整配方连同数据、代码与模型一起开放，让多模态深搜从黑盒走向可复现；最大的审稿风险是评测公平性（数据重叠与评判器复用）与结论边界（32B 的规模外推）。

- **问题定义清晰度**：强。数据、工具、长程 RL 三类瓶颈在 §1 有明确定位，且分别对应 §3 的流水线与 §4.2 的两组消融；虽然“捷径坍塌”的因果论证主要靠构造性推理，问题本身的界定是清楚且可操作的。
- **创新性证据**：中。模糊改写参考 Skywork-R1V4、掩码继承 Search-R1、硬掩码对照取自 Vision-DeepResearch，本文的组合与致命步掩码 + 单侧裁剪（含附录 B.2 的形式化占优命题）是真实增量，但数据侧创新更接近“系统化设计与工程组合”，且论文没有给出与这些前作在数据构造上的定量对比。
- **方法可信度**：中。算法推导完整，作者还主动披露裁剪带来的非负偏置 b_G ≥ 0 并说明其影响，这是不错的学术姿态；但奖励依赖专有评判器且型号描述自相矛盾、关键超参无敏感性分析，削弱了方法的可核验性。
- **实验支持力度**：中。7 个基准、3 个规模、两类消融在同类工作中属于中上；然而无方差、消融覆盖窄（8B + 3 基准）、存在训练/评测来源重叠风险，且未超越商业模型的 BrowseComp-VL 反例未被正文讨论，因此结论强度受限。
- **可复现性**：中。数据（SearchVL-SFT-36k / SearchVL-RL-8k）、三个模型检查点与代码均已公开，仓库为 Apache-2.0 且在论文发布后仍在更新（最后推送 2026-07-30，晚于论文提交），RL 超参表给得相当细；但训练与评测依赖多个外部 API（Serper、PaddleX、Claude/GPT 评判器），论文自认精确数值复现困难，32B 训练配置也缺失。
- **综合阅读价值**：高。对想理解“多模态工具调用智能体如何被完整训练出来”的读者，这篇论文提供了罕见端到端的配方细节（数据构造、工具规范、提示、RL 目标与实现坑），其失败处理思路（致命步掩码 + 单侧裁剪）可以直接迁移到其它长程工具调用任务；阅读时应重点核对其消融覆盖与评测公平性两处的边界。
