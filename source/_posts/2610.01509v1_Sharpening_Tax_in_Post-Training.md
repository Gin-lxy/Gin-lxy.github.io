## 0. 一句话结论

论文把"RL 后训练是扩展能力还是锐化原有行为"的争论搬到多轮工具调用类 agentic 任务上：在 14 组开源 base/post-trained checkpoint 对 × 3 个基准（BFCL v4 多轮、WebShop、ACEBench，42 个组合、每任务 128 次 rollout）上，后训练模型赢在 pass@1，但在大预算下常被"仅加轻量 harness 的 base 模型"在 pass@K（解覆盖率）上反超，作者把这一代价归因于后训练将每任务成功率分布"双峰化"（推向总解出/总解不出两个极端），并把它压缩为一个可诊断标量 Sharpening Tax（K=128 时 42 个组合中 36 个为正）。为解决它，作者提出 PTGS（按题自适应采样温度的 Bayesian sampler），在 Qwen2.5-7B-Instruct 的两个网格世界 RL 环境（Sokoban、FrozenLake，PPO/GRPO，5 个随机种子）中同时提升 pass@1 与 pass@128、并减小税。边界：诊断部分证据面广但为观测性（后训练配方未公开，因果解释只由带强假设的数理模型支持）；缓解部分仅一个 7B 模型、两个玩具环境、均值对比未做显著性检验，"PTGS 可推广到一般 agentic RL"当前证据不足。

## 1. 论文具体想解决什么问题？

**领域一般问题。** "RL 后训练（RLVR 等）究竟是创造了新能力，还是只是在放大 base 模型已有的高奖励行为（distribution sharpening）"是当前争论焦点：一方报告 RL 模型在 pass@K（大 K）上输给 base 模型，认为后训练以解覆盖率为代价换取 pass@1；另一方认为能力边界可以真正扩展（延长训练、grokking 等），也有人把差异归因于训练数据/任务分布（§7 Related Work 概括了这两派争论）。

**现有方法的局限（作者给出的动机）。** 该争论的证据几乎全部来自数学与代码任务，作者指出两个问题：(1) 预训练对数学/代码的曝光极大，base 模型可能本就编码了大量候选解法；(2) 这类评测往往只检查最终答案，运气好的错误推理也能得分，会虚高 pass@K（§1，引 Skalse et al. 2022；Wen et al. 2026）。因此现有结论未必能迁移到 agentic 任务。

**本文的新观察。** 作者主张 agentic 任务（多轮工具调用、场景化接口、环境反馈、长程一致性）是检验"锐化假说"的 stress test，因为这类行为在预训练数据中稀少、通常被认为要靠后训练获得（§1）。在此基础上给出三个观察：其一，只加一个"数据集无关、模型无关"的轻量 harness，预训练 base 模型就能执行 agentic 任务，并在测试时预算足够大时在 pass@K 上反超其后训练版本（Fig. 2）；其二，反超所需预算 k* 随模型规模缩小，WebShop 上 4B 的 k* > 128 而 31B 约 3（Fig. 3，§3）；其三，后训练把每任务成功率分布推向两个极端——总是解出或从不解出，中间"给算力就能解出"的区域大幅塌缩（Fig. 4 与 §3 正文；gemma-4-31B 在 WebShop 上中间类别从 87.6% 降到 30.0%，总是解出从 0.0% 升到 26.0%，总是失败从 12.4% 升到 44.0%）。

**支撑证据。** 14 组 base/post-trained 对（Gemma-4、Ministral-3、Qwen2.5、Qwen3.5 四族，3B–35B，Table 1）× 三个过程性（process-centric）基准，每任务 128 次 rollout（§A.1、Table 3）；三基准都按环境状态判定成功，不易被"幸运最终答案"刷分（§A.1）。harness 的作用有消融：8 个 base 模型中 6 个在没有 harness 时 BFCL 得分为 0，加 harness 后平均 pass@1 从 5.6% 升到 15.6%、pass@32 从 15.2% 升到 49.1%（§3 正文汇总，per-model 见 Appendix Table 2）；同一 harness 会损害后训练模型（平均 pass@1 42.8→16.3%），故作者对后训练模型保留各自默认脚手架（§3、§A.3）。

**作者认为的原因。** 分布锐化（sharpening）：后训练把概率质量集中到少数高奖励行为模式，代价是解覆盖率。作者用 Theorem 2 给出一个理想化模型：若后训练以比例 λ 独立地把每任务成功率坍缩到 0 或 1，则原始税 Tax_A(K)=λ·A_Base(K) 恒非负且成比例（§6）。

**核心假设。** (i) 准确率—覆盖率张力可迁移到 agentic 领域且普遍存在；(ii) 该代价可用单一标量刻画、可用少量 rollout 预测，并与其他评测指标相关；(iii) 其中一部分覆盖率损失并非不可避免，通过改变 RL 训练时的 rollout 采样（按题调温）可以兼得 pass@1 与 pass@K。

**必须区分的是：** 论文观测到了"双峰化"现象并有跨模型证据，但因果解释（是 RL/SFT/DPO 中的哪一环节、以什么机制造成）没有被验证——checkpoint 的预训练/后训练数据与配方均未公开，作者在 §9 Limitations 中明确承认这是"observational rather than interventional"，需要可控数据配方实验才能给出因果结论。Theorem 2 是一个建模结果而非对真实训练过程的验证。

## 2. 创新点是什么？

**一段话概括：** 本文的技术增量有三块：一个把 base 模型当作"覆盖率锚点"、用 pass@K 曲线面积差与校准化差额刻画的诊断标量（Sharpening Tax），一套把该诊断落到 14 模型 × 3 基准 × 128 rollout 的 agentic 评测协议（含让 base 模型能当 agent 的轻量 harness），以及一个不改动 RL 算法本体、只按每题目难度在线自适应 rollout 温度的 Bayesian sampler（PTGS，附三个小定理解释其机制）。其中诊断思路有较好的可解释性与可预测性验证（ρ=0.85），但构造本身是标准 pass@k 估计量的重加权；PTGS 是采样侧已有思路（温度调度/自适应采样）的一个干净实例化，实证范围很小。

逐项分析：

1. **Sharpening Tax（诊断标量，§4, Eq. (1)–(3)）**
   - 新增什么：A(K)=Σ_{k=1}^{K-1}[pass@K−pass@k]（pass@K 天花板下的面积，Eq. (1)）；S(K)=A(K)/[(K−1)(1−pass@1)]（用准确率余量校准并归一到 [0,1]，Eq. (2)）；Tax_X(K)=X_Base(K)−X_Post(K)（Eq. (3)）。Proposition 1 给 A(K) 一个概率解释：A(K)=E[(H−1)·1{H≤K}]，即"首次成功前的期望失败次数"，S(K) 是它在首试失败任务上、归一到 [0,1] 的版本（§6）；Corollary 4 把税分解为"天花板差"与"预算平均覆盖率差"（Eq. (8)，Appendix B.2）。附录 D.1 的 42 组合汇总表显示，后训练模型对其自身天花板的达成比例 C̄/C 在所有组合中都高于 base。
   - 与最接近已有方法的具体差异：pass@k 无偏估计量（Chen et al. 2021）与重复采样扩展曲线（Brown et al. 2024）都是既有工具，以往工作要么肉眼比较曲线形状、要么只看端点指标（pass@K、pass^K）。本文的差异是把整条曲线的"重试价值"归一成一个标量并以 base 模型为锚（差分化），并验证其可预测性。
   - 属于哪类：指标设计层面的新组合/工程改进，不是新学习原理；作者也承认这一节的价值在"把可视化变成可观测量"（§7）。
   - 对应什么问题：让"锐化税"可以在不同模型/基准/预算间比较，并支持预算受限场景下的早期估计。
   - 证据：Tax_S(8)（8 次 rollout、半数任务上估计）能预测留出半数任务上的 Tax_S(32)，Spearman ρ=0.85；Tax_S(8) 与一致性差 Δpass^8 正相关；在三个预测目标（Tax_S(32)、Δpass@32、Δpass^32）上，它是唯一三个都强显著的早期预测子（Fig. 6 三面板，§4）。
   - 移除后会怎样：没有消融实验（这是指标而非可移除模块），但可对照的是：若只看端点指标，就无法区分"K=8 就饱和"与"K=128 仍在爬升"这两种非常不同的策略，例子见 §4 中 Fig. 5 的两类税形状（Tax_A 随预算近似单调上升，Tax_S 可升可降）。

2. **agentic 领域的评测协议与新经验事实（§3）**
   - 新增什么：一套轻量、无任务泄漏的 harness（系统提示 + Python 函数签名形式的工具目录 + 让模型用 JSON 写 `tool_call` 块的指令 + `### User/Assistant/Tool Output` 分节 + stop 序列防自造环境回复，§A.3），使没有 chat template 的 base checkpoint 能以 completion 接口进入标准 benchmark runner；以及由此得到的经验事实：base 模型 + harness 是"合格的 agent"，且 crossover 预算随规模减小（Fig. 2、Fig. 3）。
   - 与最接近已有方法差异：此前 coverage 分析几乎只在数学/代码域做，且不涉及 base 模型的工具调用适配。这是把已有争论换到新领域做（新的经验研究，而非新算法）。
   - 证据：harness 消融（§A.3 Table 2）显示它对 base 必要（6/8 得 0→非 0），对后训练模型平均有害（BFCL 平均 pass@1 42.8→16.3%），说明"base 能工作"确实依赖这个适配层，且论文主比较中该层的方向性偏差（若存在）是保守的（harness 若给后训练模型反而更差）。
   - 不可替代性：harness 的增益极大（gemma-4-31B BFCL 上 pass@32 从 0.0% 到 86.5%），但它本身是"让 base 能答题"的前提而非性能技巧。

3. **PTGS（训练期 sampler，§5, Eq. (4), Algorithm 1）**
   - 新增什么：对每个 prompt 维护带遗忘因子 γ 的成功/失败计数 (s̃_x,f̃_x)，构造成以目标成功率 p̃ 为中心的 Beta 先验（总质量 2），用 Thompson sampling 抽后验成功率 p̂_x，再经映射 T_x=τ^{h(p̂_x)}（h 分段：难题升温、易题降温，T_x∈[1/τ,τ]）决定该组 rollout 的温度；RL 更新规则不改，log-prob 用同温度计算以保持 on-policy（§5、§A.5、Algorithm 1）。
   - 与最接近已有方法的具体差异：采样侧已有工作做全局温度调度、rollout 内调度或估计幂分布（§7 引 Yang et al. 2025；Liao et al. 2025；Dang et al. 2026；Karan and Du 2026）；PTGS 的差异是"每题一个 Beta-Binomial 后验 + 按题目难度自适应"，且不侵入 RL 目标函数。
   - 属于哪类：已有组件（温度采样、Beta-Binomial 后验、Thompson sampling、组采样）在 RL 训练循环中的新组合，理论上是干净的，但每一块组件都是成熟的。
   - 对应什么问题：直接针对 §1 观察到的"中间成功率任务被推向两极"，让难题保持在中段（重试仍能翻盘），易题更确定。
   - 证据：§5 的 PTGS 结果表显示在 PPO 与 GRPO、Sokoban 与 FrozenLake 四组对照中，加 PTGS 后 pass@1 与 pass@128 同时提高、Tax_S 均下降（细节见 §4.2）；E.3 的固定温度/截断解码消融（Table 7、8）表明这不是"全局调温"或"截断分布"的等价物；Theorem 3 给机制解释（见 §3）；Appendix F.1/F.2 显示难度估计与真实成功率相关（Pearson 0.81/0.71）、高熵不是单纯来自更高温度。
   - 移除后会怎样：Table 7、8 就是"移除 PTGS 换成固定 T∈{0.5,…,1.5} 或 top-p/top-k/min-p"的对照：在 Sokoban 上固定的高温提高 pass@1 也提高税（T=1.5 时 Tax_S=0.102，比默认的 0.094 更高）；在两种环境里没有任何固定温度能同时达到 PTGS 的 pass@1 与 pass@128。

4. **理论结果（§6, Appendix B）**
   - Proposition 1（税的语义）、Corollary 4（税的天花板/饱和分解）、Theorem 2（双峰化按比例收税）、Theorem 3（升温难 prompt 会增加"含成功的组"与"混合组"的概率，改善 PPO/GRPO 的学习信号）、Proposition 5（冷却已掌握 prompt 会把混合组转为全成功组）。证明完整（Appendix B），但均为理想化模型下的结论（如 Thm 2 假设任务独立地坍缩到 {0,1}；Thm 3 假设升温确实提高成功率 p′>p，这一点由 Fig. 39 的经验结果支持）。

**原创边界说明：** 根据本文 related work 与实验对比，只能确认作者声称的差异（agentic 域首个系统性 coverage 分析；PTGS 与已有采样侧方法在机制与对照上的区别）。是否构成"首次提出"需要更完整的文献检索；此外"用 pass@k 验证 RL 是否只做锐化"这一研究路线本身已有 Yu et al. 2025、Zhao et al. 2025 等先行工作，本文是其中的新成员而非开创。

## 3. 作者如何解决？

**直觉。** 如果后训练只是把策略变得更"确定"（高奖励行为概率更高、其余压平），那么当用户愿意为一个任务采样很多次时，这种确定性就要付费：原 base 策略里"偶尔蒙对"的行为在重试预算下能累积成解出，而后训练后的策略要么一次就中、要么永远不中，重试不再产生新信息。于是：(a) 把"重试还能带来多少成功"量化成税；(b) 在 RL 训练时，把"总是失败"的难题加热（保持探索），把"已经会做"的易题降温（固化成功），让重试的价值在训练中保留下来。

**按实际运行流程展开：**

1. **输入（诊断部分，§3–§4）。** 每个基准的任务集（BFCL v4 multi_turn_base 200 任务、WebShop 前 500 条指令、ACEBench 770 任务子集，§A.1）+ 14 组 base/post-trained checkpoint（Table 1）。采样配置对所有模型统一（BFCL temp 0.4，WebShop/ACEBench temp 0.7，top-p 0.95，N=128 rollouts/task，Table 3）；后训练模型关闭 thinking mode（并用 Fig. 9 消融说明该选择不改变结论）。全部模型用 vLLM 0.19.0 服务（§A.2）。
2. **关键步骤（诊断）。** base 模型经 harness 适配（A.3，见 §2）；两种策略在相同任务集上各采样 N=128。对每任务统计成功数 c_i，计算 pass@1/pass@k/pass^k（§2，无偏估计量），先看曲线交叉（Fig. 2），再看每任务成功率的分布形状（Fig. 4：总是解出 / 给算力能解出 / 总是失败三类），最后计算税的两种版本（Eq. (1)–(3)）并做配对任务 bootstrap 置信区间（1000 次重采样，重采样任务而非 rollout，§A.4）。
3. **由什么组件执行。** 全部是固定流程（采样→统计→bootstrap），无模型决策；附录 A.6 给出 tax 计算的伪代码（accumulative product 实现避免组合数数值问题）。
4. **PTGS（训练部分，§5、Algorithm 1）。** 输入：任务池 D、组大小 n、目标成功率 p̃、温度跨度 τ、遗忘因子 γ。对每个训练步：(i) 取任务批；(ii) 对每个 prompt 由 (s̃,f̃) 与先验构造 Beta(2p̃+s̃, 2(1−p̃)+f̃)，Thompson 采样得 p̂_x；(iii) 计算 T_x=τ^{h(p̂_x)}（式 (4)；h 对难题取 (p̃−p)/p̃、易题取 (p̃−p)/(1−p̃)，故 T 的取值在 [1/τ,τ]，且过三点 T(0)=τ·T_ref、T(p̃)=T_ref、T(1)=T_ref/τ，§A.5）；(iv) 以 T_x 生成 n=16 条 rollout（组内所有 turn 用同一温度），统计成功数 s_x；(v) 以 γ=0.95 折扣更新计数；(vi) 用原 RL 规则更新（PPO/GRPO 均不改）。哪些由模型决定：只有 rollout 文本；温度、更新、过滤全是固定流程。
5. **训练哪些部分。** 只微调策略（以及 PPO 的 critic）：Qwen2.5-7B-Instruct，在 RAGEN 框架中训练 PPO 与 GRPO 各 200 步（每步 8 任务 × 16 rollout；AdamW，actor lr 1e-6，DAPO 式 clip 0.2/0.28，无 KL 惩罚，minibatch 32，含 RAGEN 的 reward-variance filter 保留方差最高 90% 的组，§A.5）。PTGS 超参：PPO 用 τ=1.5（T_x∈[0.667,1.5]）、p̃ 从 0.25 线性升到 0.5；GRPO 按验证集选参（Sokoban τ=1.4、FrozenLake τ=1.2，§A.5）。
6. **推理阶段发生什么变化。** 训练完成后评测时 PTGS 被移除（§5 末）：每个 checkpoint 在 64 个未见任务上以 T=0.5 采样 128 条，报告 pass@k 与 Tax_S(128)（对照该环境的 base 模型一次共享评测）。附录 E.4 另做了"推理期 PTGS"变体（先采 pilot，再由后验定温度采解答，不训练），在 FrozenLake 上优于全局温度曲线，在 Sokoban 上只有少数配置略优（64 个任务里差 1–2 个任务）。
7. **最终输出。** 一个诊断结论（税的存在性、大小、可预测性、路由应用）与一个训练方法（PTGS）。

**关键公式与设计假设。**
- 诊断：A(K)=Σ_{k=1}^{K−1}[pass@K−pass@k]（Eq. (1)）；S(K)=A(K)/[(K−1)(1−pass@1)]（Eq. (2)，要求 1−pass@1>0）；Tax_X=X_Base−X_Post（Eq. (3)）。Proposition 1 的解释：只有"首试失败、但在预算内某次成功"的任务贡献 A，且首成越晚贡献越大——因此税为正 = 后训练的成就不再依赖重试（Appendix B.2 进一步分解为"天花板损失"与"饱和加速"两种效应）。
- PTGS：T_x=τ^{h(p̂_x)}（Eq. (4)）；Theorem 3 给出 I_n(p)=1−(1−p)^n（组内至少一次成功）与 J_n(p)=1−p^n−(1−p)^n（混合组）随 p 的单调性：加热难题使两者都变多（p′≤1/2 时），这正是 PPO（需要成功样本才能强化）与 GRPO（需要混合组才有非零优势）所需的学习信号；已掌握题降温则由 Prop 5 保证混合组转化为全成功组而非全失败组。
- 设计假设：rollout 在给定任务下条件独立（§2、§6 均声明）；训练时自适应采样可在不改变 RL 目标的前提下塑造最终策略（引 Schaul et al. 2015；Nath et al. 2025，§5）。

(1)/(5)，该任务对 A(4) 的贡献 a₄(0.25)=Σ_{k=1}^{3}[(1−p)^k−(1−p)^4]=(0.75−0.316)+(0.5625−0.316)+(0.4219−0.316)≈0.785，等于"首次成功前的期望失败次数"。若后训练把它锐化到 p=1（总解出）或 p=0（永不），该贡献都变成 0——而 p=1 时 pass@1 反而升到 1，这正是"税为正但看起来更好"的最小例子。

## 4. 解决得怎么样？

### 4.1 实验设置

- **诊断（§3–§4）**：14 对 checkpoint（Gemma-4 E4B/12B/26B-A4B/31B；Ministral-3 3B/8B/14B；Qwen2.5 3B/7B/14B/32B；Qwen3.5 4B/9B/35B-A3B，其中两个 MoE 约 4B/3B 激活）见表 Table 1；三基准各 N=128 rollouts/任务（BFCL 200 任务、WebShop 500、ACEBench 770，见 Appendix D.1 汇总表）；同基准内 base 与 post 共享任务、温度、seed 与步数预算（Table 3）；报告配对任务 bootstrap 95% 区间（§A.4）。基线即"同族 post-trained 模型"与"base+harness"互为对照；另含 thinking mode 消融（Fig. 9）、harness 双向消融（Table 2）、按规模分组的聚合（§C.1）、全局温度对照（§C.4、Fig. 24）。
- **PTGS（§5、§A.5）**：Qwen2.5-7B-Instruct 在 RAGEN 的 Sokoban（6×6、1 箱、shaped reward）与 FrozenLake（4×4 slippery，0.8/0.1/0.1 转移）上训练；PPO 与 GRPO 各有无 PTGS 两版；5 个随机种子取均值；200 步训练；评测用 64 个未见任务 × 128 rollout @ T=0.5（无 PTGS）。消融：固定训练温度 T∈{0.5,0.7,1.0,1.3,1.5}（Table 7）、top-p/top-k/min-p 截断解码（Table 8）、τ∈{1.2,…,1.5}（Fig. 35）、推理期 PTGS（Fig. 36）、高温度 PPO 对照（Fig. 40）。
- **基线公平性**：RL 基线与原论文同在 RAGEN/StarPO 设置下（同样本、同预算、同 filter）；主要区别仅是 rollout 温度与相应 log-prob 温度（§A.5）。主实验与消融、附录实验分别回答："现象是否存在/多广"（§3–4）、"税的诊断价值"（Fig. 6、Fig. 32）、"方法是否有效/为什么有效"（§5 结果表、Table 7、8、Fig. 33–34、39–42）。

### 4.2 关键结果

以下数字均核对指标、对象、条件与原文位置：

1. **交叉反超（覆盖率）**：gemma-4-31B 在 WebShop 上 base 的 pass@128=87.6% 对 post 56.0%（§3 正文"over 85% vs 56%"，对应 Appendix D.1 汇总表该行 C_B=0.876、C_P=0.560）；同模型 ACEBench 为 94.2% 对 91.4%、BFCL 为 90.5% 对 83.5%（Appendix D.1 汇总表）。
2. **并非处处如此**：小 backbone 上后训练扩大了覆盖率（Ministral-3-3B WebShop base 32.6% vs post 68.8%，Qwen2.5-7B BFCL base 22.0% vs post 60.0%，Appendix D.1 汇总表）；聚合上"最大 backbone 组"的均值曲线在 k≈22 被 base 反超，"最小 backbone 组"在 128 内从不被反超（§C.1，Fig. 10）。
3. **双峰化**：gemma-4-31B 在 WebShop 上"给算力能解出"的任务占比 87.6%→30.0%，总是解出 0.0%→26.0%，总是失败 12.4%→44.0%（§3、Fig. 4、Table 4）。例外：小 backbone 在 BFCL 上后训练把任务从"总是失败"提升到中间类别（§C.1、Table 4）。
4. **税的普遍性**：Tax_S(128)>0 出现在 42 个组合中的 36 个（§4 正文）；负值共 6 个，多为最小 backbone 在 BFCL 的情形（Ministral-3-3B −0.027、Qwen2.5-3B −0.023、Qwen2.5-7B −0.044，即"后训练修补了 base 的工具调用格式"），另有 Qwen3.5-4B/35B-A3B 在 ACEBench（−0.005/−0.026）与 Ministral-3-3B 在 WebShop（−0.003）（Appendix D.1 汇总表）。最大 backbone 组的税几乎处处为正（§4、Fig. 5），Tax_A 对最大 checkpoint（如 gemma-4-31B）最大；Tax_S 的最大值出现在 Gemma 族（26B-A4B 在 WebShop +0.105、12B 在 WebShop +0.092，Appendix D.1 汇总表）。
5. **可预测性**：Tax_S(8)（8 rollouts、半任务估计）预测留出任务上的 Tax_S(32)，ρ=0.85；Tax_S(8) 与一致性差 Δpass⁸ 正相关；Fig. 6 右图中它是唯一对三个目标都强显著的早期预测子（§4）。
6. **路由应用（附录 D.4）**：用 32 条 pilot rollout 估计的 Tax_S 逐任务在 base/post 间路由，pass@128 在六个面板中的五个超过纯 post 策略，最多 +13.6 分（WebShop、最大 backbone 组；唯一例外在 1.1 分内），且每个面板都超过均匀随机路由、接近 oracle 路由（Fig. 32）。
7. **PTGS 主结果（§5 结果表，5 种子均值）**：
   - Sokoban：PPO pass@1 46.5→61.1、pass@128 55.0→69.7、Tax_S 0.094→0.081；GRPO 36.5→39.1、55.3→72.5、0.081→0.025；base 为 20.7/76.6（无税概念）。注意 PPO+PTGS 的 pass@128 仍低于 base 的 76.6，即 PTGS 减小而非消除税。
   - FrozenLake：PPO 63.7→65.0、74.1→80.0、0.039→0.020；GRPO 63.4→67.3、77.8→81.2、0.029→0.028；base 26.3/89.1（覆盖率仍高于所有 RL 结果）。
8. **不是"全局调温"或"截断解码"（附录 E.3）**：Sokoban 上固定 T=1.5 的 PPO 得到 57.4±11.6 / 64.4±11.1，低于 PTGS 的 61.1±8.6 / 69.7±9.7，且其 Tax_S=0.102±0.017 高于默认温度；FrozenLake 上任何固定温度都无法同时达到 PTGS 的水平（如 T=0.7：63.7±7.1 / 70.3±4.9 对 PTGS 65.0±3.2 / 80.0±8.3）；各类截断解码相对祖先采样大多在 ±2 分内，无一致增益（Table 7、8）。
9. **提升小/无显著性的地方**：FrozenLake 上 GRPO+PTGS 的税 0.029→0.028 基本持平；§5 结果表只报均值不报方差；Table 7 中 PTGS 的税区间与多数基线重叠（Sokoban 0.081±0.039 对默认 0.094±0.016、T=1.5 的 0.102±0.017），因此"收更少的税"在多数环境中未达统计显著，主要增益来自 pass@1/pass@128 的均值提升。此外 FrozenLake 上 PTGS 的 pass^128（一致性）低于默认（42.5 对 50.9，区间重叠，Table 7）。
10. **失败/反例案例**：§C.4 报告全局升温并非单调有效，gemma-4-31B-it（锐化最重）对升温几乎无响应；E.4 的推理期 PTGS 在 Sokoban 上仅两个配置在 pass@1 与 pass@128 两个指标上同时超过所有固定温度，且优势只有 64 个任务中的 1–2 个任务（Fig. 36）。

### 4.3 机制证据

- **"有效"层面**：跨 14 模型 42 组合的税测量本身较扎实（配对 bootstrap、同任务同预算、含 thinking-mode 与 harness 消融排除部分替代解释）；PTGS 的主效果有 5 种子均值与 PPO 的 ±95% CI 支持。
- **"为什么有效"层面**：Theorem 2 只说明"在假设的坍缩模型下税必然非负且成比例"；Theorem 3 说明"若升温提高成功率，则含成功组与混合组都更频繁"，其前提 p′>p 由经验证据支持而非证明——Fig. 39 显示 PTGS 训练中"零成功组"占比在大部分训练步低于固定温度 PPO；F.1 显示后验难度估计与真实成功率相关（Pearson 0.81 Sokoban / 0.71 FrozenLake，且系统性低估约 0.1）；F.2 用"PPO 全局升温到 1.3/1.5"的对照说明 PTGS 的高熵不能由更高温度解释（FrozenLake 上 T=1.5 达到相似熵但需要比 PTGS 平均温度高约 60% 的采样温度），且全局高温不带来对应的覆盖率提升。F.3 的案例研究（Fig. 41–42）显示 PPO 在 5 次运行中有 4 次丢失的个别任务，PTGS 多数运行能解出——这是存在性证据，不是统计性证据。
- **能否排除替代解释**：可以排除"仅仅因为温度更高/解码截断不同/thinking mode 开启/评测端点噪声"等一部分解释；**不能**排除的包括：不同 checkpoint 的后训练数据配比差异（观测性设定，§9 承认）、harness 对 base 的增益带来的能力归属模糊、以及"覆盖率损失其实是偏好对齐而非能力丢失"的替代解读——论文没有设计实验去区分"策略真的忘了怎么解"与"策略只是压低了解出的概率"（例如在 token 级比较 base/post 在同一 prompt 下的分布，或做能力探测），Theorem 2 的"p 被替换为 0/1"是这一不可区分性的直接体现。另外，"税=能力的净损失"的解读需要依赖 pass@K 作为能力代理，而 pass@K 衡量的是"重试可恢复的成功"，本身混合了能力与行为倾向。

### 4.4 成本与适用范围

- **训练成本**：PTGS 不改变 RL 更新、无额外计算开销（§5："does not require any changes to RL update itself nor bring computational overhead"）；PTGS 训练本身 200 步 × 128 trajectories/步 × 2 环境 × 2 算法 × 5 种子。但**论文未报告**任何 GPU 型号/小时数/费用。
- **评测成本**：诊断部分需要 14 对模型 × 3 基准 × 3 种任务量级 × 128 rollouts × 2 种策略的大规模推理，是本文最重的开销，**论文未报告**其具体算力或时延。
- **推理时延/token**：诊断不引入推理侧开销（只是统计已有 rollout）；PTGS 训练期修改采样温度不增加 token 数；推理期 PTGS 变体（E.4）把预算拆成 pilot 与解答两段，pilot 的预算开销为半预算（B=256 时 m=n=128）。
- **外部依赖**：全部为开源权重 + vLLM + RAGEN，无闭源 API；无人工标注需求；需存储 14 对模型的本地产出。
- **可复现性材料**：超参与流程在 Appendix A 报告较细（含伪代码）；官方 GitHub 仓库存在，但 README 声明它是"minimal working examples for understanding the project; it is not a reproduction package"，benchmark 检出、模型服务环境与 RL 训练基础设施留给读者（仓库提供 metrics 与 PTGS 的 numpy 最小实现与测试）。复现论文的主实验需要自建大规模推理设施。
- **适用范围与未解决**：结论适用于"文本、二值成功信号、K≤128、开源 checkpoint、评测性分析"的范围；作者指出 open-ended 生成、多模态/VLA、不同后训练类型（RL vs SFT vs on-policy distillation）的税差异、以及"何时/如何"出现锐化的因果问题均未解决（§9）；PTGS 只验证于两个网格世界环境。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：PTGS 的结论建立在单一 7B instruct 模型与两个玩具网格环境上，与诊断部分的大规模证据完全不成比例，"平衡采样效率与覆盖率"的普适性主张缺乏支撑。

- **原文依据**：§5 与 Appendix A.5——所有 PTGS 实验仅用 Qwen2.5-7B-Instruct，在 Sokoban（6×6）与 FrozenLake（4×4）上训练，任务池 200/环境、评测 64 个未见任务；而诊断部分覆盖 14 个模型、3 个真实 agentic 基准、42 个组合。作者在 §9 列举的局限（多模态、open-ended 等）并未明确点名这一"缓解侧实验规模远小于诊断侧"的问题。
- **为什么重要**：PTGS 是论文三大贡献之一，其声称解决的问题（后训练锐化）在主实验域（BFCL/WebShop/ACEBench）完全未被验证；网格世界与真实工具调用任务在动作空间、horizon、奖励结构上差异巨大。
- **当前能够得出的判断**：在论文报告的两个环境下有效；跨域/跨规模外推当前证据不足。属于结论范围被隐含放大的风险。
- **如何验证或补强**：在 BFCL/WebShop 上以 1.5B–32B 多规模模型训练 RL（或对已有后训练流程加 PTGS），报告税与 pass@K；至少在第三个环境与另一个模型族上复现 §5 结果表。
- **严重程度**：主要问题。

#### 质疑："PTGS 收更少的税"在统计上不稳健，主表不报告方差，"税下降"的多数区间与基线重叠，部分依赖检查点选择。

- **原文依据**：§5 结果表只有 5 种子均值（如 Sokoban PPO 税 0.094→0.081、FrozenLake GRPO 税 0.029→0.028），无区间；Appendix Table 7 的 CIs 显示 0.081±0.039（PTGS）对 0.094±0.016（默认）、0.102±0.017（T=1.5）均重叠，FrozenLake 为 0.020±0.047 对 0.039±0.026，同样重叠；GRPO 使用"训练中验证成功率最高的 checkpoint"（记为 †，§A.5），而 PPO 用最终 checkpoint——两种选择规则并存于同一主表。
- **为什么重要**：这是方法有效性的核心指标之一（"smaller tax"写在摘要）；CI 重叠意味着该结论在多数环境下尚不能被区分于噪声，而"最高验证"选择在 5 种子下的方差本身较大（Table 7 中部分基线 pass@1 的 CI 达 ±26.8）。
- **当前能够得出的判断**：pass@1/pass@128 的提升有均值支持（且方向一致），但"税显著下降"当前证据不足；需要更多种子与配对显著性检验。
- **如何验证或补强**：对每个环境/算法报告配对种子差值的 CI 或检验；统一 checkpoint 选择规则并报告两套结果；把种子数从 5 扩大。
- **严重程度**：主要问题。

#### 质疑："锐化"作为因果机制未被验证，Sharpening Tax 测量的是"重试价值差"而非"能力差"，观测性设定下无法区分替代解释。

- **原文依据**：§9 自述"observational rather than interventional"，checkpoint 的预训练/后训练数据均未公开；Theorem 2 假设后训练"独立地"把任务成功率替换为 0/1（§6）；正文把税解释为"post-training 让成功更少依赖重试"，但观测到的负税案例（后训练修复工具调用格式，Appendix D.1 汇总表）表明该指标同样会捕捉"能力获得"，即它是"后训练净效应"而不是纯粹的"锐化"度量。
- **为什么重要**：论文的全部叙事（包括 Discussion 中"许多科学难题可能靠一次不寻常的奏效而非每次可靠的流程"）依赖"锐化=能力受窄化"的因果解读。
- **当前能够得出的判断**：机制解释是"与数据一致的一种模型"，不是被识别的因果；作者已如实标注。
- **如何验证或补强**：用完全可控的预训练/后训练数据配方（作者 §9 指出的方向）做干预实验；在同一 base 上分别做 SFT/DPO/RLVR 并比较税；或做 token 级分析区分"概率重分配"与"能力丧失"。
- **严重程度**：主要问题。

#### 质疑：缺少与最接近的"保持多样性/防熵坍缩"方法的实证对照，PTGS 的优势无法定位。

- **原文依据**：§7 提到目标侧方法（exploration bonus、entropy-collapse 缓解：Yu et al. 2025；He et al. 2025；Song et al. 2025；Gai et al. 2025；pass@k-aware 目标：Walder and Karkhanis 2025；Tajwar et al. 2026），以及采样侧方法（Yang et al. 2025；Liao et al. 2025；Dang et al. 2026；Karan and Du 2026）。但实验对照只有固定温度（Table 7）与截断解码（Table 8）；PPO 的熵系数固定 0.001、GRPO 为 0，未做熵奖励基线；没有与任何 pass@k-aware 目标或 KL 正则的对比。
- **为什么重要**：审稿人需要知道"按题 Bayesian 调温"相比"简单加大熵奖励/加大 KL/全局温度调度"是否值得其复杂度；E.3 部分回答了"不是全局温度"，但未回答与目标侧方法的差别。
- **当前能够得出的判断**：在论文选择的对照内 PTGS 占优；相对更主流多样性方法的相对优势无法评估。
- **如何验证或补强**：加 entropy-coefficient 扫描（如 0.001→0.01→0.05）与 pass@k-aware 目标基线，同预算同种子比较 pass@1/pass@128/税。
- **严重程度**：主要问题。

#### 质疑：base 与 post-trained 的比较协议不对称，base 的"最佳可能表现"无上界，harness 增益之大使"能力归属"模糊。

- **原文依据**：base 模型配 harness、post-trained 模型用各自默认脚手架（§A.3 的 asymmetric scaffolding）；同一 harness 会显著损害 post-trained 模型（平均 pass@1 42.8→16.3%，Table 2）；harness 对 base 的增益极大（gemma-4-31B 在 BFCL 的 pass@32 从 0.0% 到 86.5%；6/8 个 base 模型无 harness 时 BFCL 得 0）。"w/o harness" 的 base 对照是人工构造的（借用其 post-trained 版本的 chat template），并非 base 的部署形态。
- **为什么重要**：主结论"base 在覆盖率上反超"是相对于"base+本文 harness"这一特定配置；harness 本身是外部脚手架，其好坏直接放大或压缩 base 的 pass@K 曲线。偏差方向对主结论是有利的（论文显示若给 post-trained 加 harness 会更差，所以不对称比较是保守的），但这只说明交叉反超不是 harness 强加给 post-trained 的伪结论，不能说明 base 的能力边界在更优 harness 下不会更高——反过来也不能说明 base 在更差 harness 下还有此现象，总之能力归属是可操作的变量。
- **当前能够得出的判断**：交叉现象在"轻量 harness"下成立且方向性偏差保守，但"base 模型的覆盖率"没有脱离脚手架定义的绝对含义；论文未做 harness 强度的扫描（除有/无二值）。
- **如何验证或补强**：扫描 harness 质量（few-shot、更强解析、不同模板）对 crossover 点的影响，并给出 base 表现的 harness 敏感性区间；或在显式训练 base 使用模板后再公平比较。
- **严重程度**：次要问题（方向保守，但影响结论的解释口径）。

## 6. 审稿式总评

> 作者发现：在 agentic 任务上，只配轻量 harness 的预训练 base 模型在足够测试时预算下常能在 pass@K 上反超其后训练版本，后训练把每任务成功率分布推向"总是解出/从不解出"两个极端，以采样效率与一致性换取解覆盖率。因此提出以 base 为锚的 Sharpening Tax 把这一代价量化（42 个模型—基准组合中 36 个在 K=128 为正、可由 8 次 rollout 预测、ρ=0.85，并能用于 per-task 路由），再提出 PTGS 用 Beta-Binomial 后验按题目难度自适应 rollout 温度。实验表明：诊断部分在 14 个开源模型对、3 个过程性 agentic 基准上证据较强且含 thinking-mode/harness 消融；机制部分有 Theorem 2/3 的形式化与难度估计、零成功组、高熵归因等分析支持"与锐化模型一致"，但因果识别缺失（配方未公开、观测性设定，作者自认）；缓解部分在 Qwen2.5-7B 的两个网格世界中同时提升 pass@1 与 pass@128 并（在均值上）减小税，然而只有 5 种子、主表无区间、税差与基线 CI 重叠、且完全未在主基准上验证。本文最有价值的部分是"把测试时扩展曲线变成可诊断、可预测、可路由的标量"这一视角与跨 42 组合的经验证据；最大的审稿风险是把仅在两个玩具环境验证的 PTGS 表述为对后训练锐化的通用解法。

- **问题定义清晰度**：强。研究问题（后训练是扩展还是锐化）表述明确、边界清楚，且把已有争论的域限制（数学/代码）作为切入理由；指标定义、实验协议与结论适用范围在正文与附录中均有交代。
- **创新性证据**：中。诊断指标是标准 pass@k 估计量的面积/差值重加权，PTGS 是成熟组件（温度采样、Beta 后验、Thompson sampling、组采样）的新组合；原创性主要落在"agentic 域的系统性经验研究 + 可预测诊断 + 干净的自适应采样实例化"，论文未声称更深的理论突破，相关工作的差异有讨论但未做实证对照。
- **方法可信度**：中。诊断协议严谨（同任务同预算、配对 bootstrap、多重消融），理论证明完整但依赖理想化假设；PTGS 的方法本身简洁、可插拔、无额外开销，但效果证据方差大、部分区间重叠。
- **实验支持力度**：中（诊断强、缓解弱）。诊断侧的 42 组合 + 路由 + 可预测性分析足以支撑"税普遍存在且可诊断"；缓解侧仅一个模型、两个环境、5 种子，且未报告显著性，支撑"在报告条件下 PTGS 同时改善准确率与覆盖率"这一有边界的结论，而不支撑更一般的"可平衡"主张。
- **可复现性**：中。模型、基准、超参、伪代码、评测协议齐全（附录 A）；官方仓库提供最小实现但自述非复现包；主实验的算力规模与成本未报告，完整复现需要自建大规模推理与 RL 训练设施。
- **综合阅读价值**：高。对关心"RL 后训练是否真的提升能力上限""测试时扩展与后训练的关系""多轮 agent 的评测协议"的读者，本文提供了概念工具（税）、可复用的诊断代码与一套跨模型的证据；同时它把未验证部分（因果、通用缓解、成本）标注得相对诚实，适合作为该争论的入门与批判性阅读材料。
