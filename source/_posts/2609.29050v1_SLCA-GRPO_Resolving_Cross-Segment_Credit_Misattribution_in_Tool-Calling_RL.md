## 1. 作者发现了什么问题？

### 背景与任务

LLM 从"聊天"走向"做事"，核心能力是通过外部工具规划并执行动作。SFT 能提供不错的初始化，但作者指出它依赖对固定模式的模仿，在 Model Context Protocol（MCP）这类规模大、变动频繁的工具命名空间下很脆弱（§1），因此需要 on-policy RL 做后训练。本文研究的正是**工具调用 agent 的 RL 后训练**：给定一条用户指令和一组工具 schema，策略要产出"推理 + 结构化工具调用"的动作链，并在最后给用户一段自然语言答复。

工具调用与纯推理任务的关键差别在于：它的轨迹天然被外部可验证的边界切开。论文把一条 rollout 写成

$$y=\big[y_{\mathrm{tool}}\oplus y_{\mathrm{sum}}\big]$$

其中 $y_{\mathrm{tool}}$ 是操作段（穿插结构化工具调用的推理轨迹），$y_{\mathrm{sum}}$ 是面向用户的总结段（§3.1）。作者把这种结构叫 **Heterogeneous Rollouts（非同质 rollout）**。

### 已有方法具体哪里做得不好

主流的 GRPO 会把**一个轨迹级的标量 advantage 广播给所有 token**；即使引入了过程奖励模型（PRM），信号也是先被加总成 $R_{\text{total}}=R_{\mathrm{tool}}+R_{\mathrm{sum}}$ 再做 advantage 估计（§1）。作者把这一结构性缺陷命名为 **Global Signal Conflation**，它导致本文的核心概念：**Cross-Segment Credit Misattribution（跨段信用错配）**——总结段的奖励波动会混进工具 token 的 advantage 里。

作者同时指出已有缓解手段都没有堵住这条通路（§1、§2.2）：

- 时间轴方法 VinePPO、GiGPO、SPO 解决的是"步与步之间"的 credit，但仍然保留 $R_{\text{total}}$；
- ToolPO 加了局部工具奖励，但其 advantage 形式是 $A_{\mathrm{tool}}=A_{\text{global}}+\lambda\cdot A_{\text{tool\_local}}$、$A_{\mathrm{sum}}=A_{\text{global}}$（App. C.4），总结奖励仍作为 $A_{\text{global}}$ 的一部分进入工具 token；
- RLTR 干脆把 planner 和 summarizer 拆成两段流水线，代价是放弃统一 backbone（还额外引入 planner 专用 SFT 与冻结 summarizer）。

![已有方法与 SLCA 的机制对比](/images/dailypaper/2026-09-28/2609.29050_fig2.png)

*原文图 4（Figure 4，App. A 开头）。左：标准 GRPO 用 $R_{\text{total}}$ 产生统一 advantage 并广播到全部 token，总结段的噪声因此泄漏进工具 token 的梯度（图中写的正是 "Noisy leakage from summary rewards into tool gradients"）；右：SLCA 让工具段与总结段各自计算 advantage，用"墙"一样的结构切断跨段路径。该图是全文问题诊断的骨架。*

### 关键现象与证据

作者给出的证据分三类，需要注意其中哪些是"案例"、哪些是"训练统计"：

1. **冲突情形（sign-conflict）的存在。** 工具调用低效或失败、但总结写得正确时，混合 advantage 可能为正，错误的工具行为被强化；反过来，正确的工具轨迹配上错误的总结时，正确的工具使用被惩罚。论文首页给出两个具体诊断案例（未编号的 Diagnostic cases 图）：一个"多余的工具调用 + 正确的交付总结"，一个"正确的退款证据 + 错误的退款总结"；App. D.4 的图 9 则给出带完整奖励分解的版本（下文 §2 会展开）。
2. **训练轨迹层面的证据。** 标准 GRPO 在训练中稳定到更长的轨迹上，却没有对应的成功率提升（图 2(b)）。作者据此提出"performative execution"的解释：模型在靠**拉长轨迹去迎合总结奖励**，而不是提高工具调用精度（§4.2）。
3. **梯度诊断。** 训练中梯度 $L_2$ 范数出现高频尖峰（图 5、表 5），但 3B 上工具/总结两个梯度方向的余弦相似度全程接近 0（区间 $[-0.03,0.08]$，App. B）。作者据此判断不稳定的来源更可能是被指派的 advantage 幅度（污染），而不是两段梯度方向冲突——因此他们把 SLCA 称为 "advantage-level firewall" 而不是 "gradient firewall"。

另外两个与解释一致的现象：3B 与 8B 上标准 GRPO 的 Summary 分数更高、但 Success 更低（§5、App. D.1）；ToolPO 在 7B 上 Summary 达 0.6054、Process 只有 0.3408（表 15）。即"一段好看"可以掩盖"另一段坏了"。

### 核心判断

作者的判断是：**问题不在于缺少稠密奖励，而在于 advantage 估计之前的信号聚合**。只要在归一化和广播时把两段混在一起，任何稠密奖励都救不了；所以要在"结构轴"上（execution vs. articulation）、在 backward 之前就阻断 summary→tool 的 advantage 通路。作者也明确了边界：SLCA 并不主张"工具调用与最终答案因果无关"，而是把它当作一次**偏差–方差权衡**（§1、App. A.2）——用执行侧的稠密奖励去更新工具决策 token，认为这是方差更低、信息也足够充分的信号；两段之间的合法因果联系（工具对 → 总结更好）通过 $R^{\mathrm{sum}}$ 中的系统性成分 $\bar{R}^{\mathrm{sum}}(y_{\mathrm{tool}})$ 保留（Assumption A.2）。

区分一下：工具调用 RL 的 credit assignment 是**已有研究问题**；本文的**新观察**是"两段非同质输出被同一标量 advantage 广播"这一结构性缺陷，以及把根因定位到 advantage 污染而非梯度方向冲突（后者是可证伪的诊断结论，见 App. B 的余弦相似度测量）。

## 2. 作者如何解决？

### 核心思路

SLCA-GRPO 把"统一策略的一次更新"拆成两条互不串扰的信用通道：**执行段的稠密过程奖励只更新工具段 token，面向用户的总结偏好奖励只更新总结段 token**。它对应前面问题的方式是直接、结构性的：既然污染来自"广播统一 advantage"，那就在 backward 之前让工具 token 的梯度对 $R^{\mathrm{sum}}$ 的偏导恒等于零（式 (4)）。实现上不需要额外采样、不需要中间状态的 rollout、不需要 value model，也不需要学习一个分段器（§3.3）。配套的两件基础设施是 **SGLS**（Schema-Guided LLM Simulator，可扩展的 schema 约束模拟器）与 **HierR**（Hierarchical Rewards，分层奖励），它们分别解决"在哪探索"和"用什么信号"。

![SLCA-GRPO 框架总览](/images/dailypaper/2026-09-28/2609.29050_fig1.png)

*原文图 1（Figure 1，§3 开头）。自上而下三段：(Top) SGLS 用 schema 约束的模拟生成交错轨迹，Policy $\pi_\theta$ 在 tool-environment interaction loop 中产出 tool trajectory tokens，最后产出 summary segment；(Middle) HierR 把反馈分成稠密执行奖励 $R^{\mathrm{tool}}$（Format / Match / Parallelism）与终局质量奖励 $R^{\mathrm{sum}}$（judge 打分的 Quality）；(Bottom) SLCA 优化层把两侧 advantage 各自归一化（$\hat{A}^{\mathrm{tool}}=\mathrm{Norm}_g(R^{\mathrm{tool}})$、$\hat{A}^{\mathrm{sum}}=\mathrm{Norm}_g(R^{\mathrm{sum}})$）后分别路由，图中打叉的连线即"不泄漏"（No Leakage）的跨段路径。这张图把"基础设施—信号—优化"三层分工画得最清楚。*

### 实际运行流程

**（1）输入与 rollout。** 输入是一条指令 $x\sim\mathcal{D}$ 和当前实例的工具 schema $\Sigma(x)$；策略 $\pi_{\theta_{\text{old}}}$ 对同一个 $x$ 采样 $G=16$ 条 rollout，每条轨迹通过与 SGLS 交互产生（Algorithm 1）。SGLS 是两阶段流水线（App. C.3）：**第一阶段是纯确定性校验**（不带 LLM）——工具名不在当前实例的可用集合里就返回硬编码错误串，必填参数缺失就返回列出缺失字段的确定性错误信息；**第二阶段只对通过校验的调用**，把工具定义 JSON 与解析后的 `<tool_call>` 载荷塞进固定模板，由一个冻结的 Qwen3-235B-A22B-Instruct（temperature 0.6）生成 mock `<tool_response>`。作者强调这个 mocker 与策略 backbone 是跨家族、跨代的（MoE vs. dense、不同 tokenizer），用来抑制隐式泄漏；它只做"模板约束下的模拟"，从不提供规划建议或奖励信号（App. C.3）。

**（2）分段（mask-based segmentation）。** 关键设计是**复用 agent loop 本来就有的 token 级掩码** $m_{i,t}\in\{0,1\}$（$1$ 表示策略生成的可学习 token，$0$ 表示环境注入的 token）。把 $m=1$ 的极大连续段记为 $\{[s_{i,k},e_{i,k})\}_{k=1}^{K_i}$，则**最后一段**是 Summary 段，**之前所有段的并集**是 Tool 段（式 (6)–(8)，App. A.1）。于是"每个带梯度的 token 都被唯一指派一个语义角色"，且不需要任何标注或学习式分段器；边界假设是轨迹以一个最终答复块收尾（$K_i=1$ 时整条轨迹视为 Summary）。作者特别声明：SLCA 切的是**结构轴**（执行 vs. 表述），不切工具段内部的时间轴（Action 1 vs. Action 2），所以它不是 VinePPO/GiGPO/SPO 的变体（§3.1）。

**（3）分段回报（HierR）。** 回报被拆成两个语义不同的部分：$R(y)=R_{\mathrm{tool}}(y_{\mathrm{tool}})+R_{\mathrm{sum}}(y_{\mathrm{sum}}\mid y_{\mathrm{tool}},o)$（§3.2），对第 $i$ 条 rollout 直接取 $R_i^{\mathrm{tool}}=S_{\text{process}}(y_{i,\mathrm{tool}})$、$R_i^{\mathrm{sum}}=S_{\mathrm{summary}}(y_{i,\mathrm{sum}}\mid y_{i,\mathrm{tool}},o_i)$（式 (1)）。其中

$$S_{\text{process}}=0.10\,S_{\text{fmt}}+0.25\,S_{\text{name}}+0.15\,S_{\text{key}}+0.20\,S_{\text{val}}+0.30\,S_{\text{par}}$$

（式 (22)，App. A.4）——格式合规 $S_{\text{fmt}}$ 数可解析且通过 schema 校验的调用块比例，工具名 $S_{\text{name}}$ 是多重集 F1，参数键 $S_{\text{key}}$ 是 Jaccard，参数值 $S_{\text{val}}$ 是宽松（大小写不敏感、可类型转换）匹配率，并行约束 $S_{\text{par}}$ 是**首轮调用个数的硬性 0/1 检查**（防止"并行塌缩"）。$R^{\mathrm{sum}}$ 用 LLM-as-a-judge：GPT-OSS-120B 冻结打分，只看工具返回值和最终答复（不看中间推理和 `<tool_call>` 内容），沿 Result Interpretation / Information Completeness / Expression Quality 三维度给 5 级分类评分，再线性映射 $(r-1)/4$ 到 $[0,1]$，解析失败一律记 0.0（App. A.5）。

还有一个容易被忽略但很关键的边角设计——**omission guard**：当 ground truth 要求调用工具、而 rollout 里连一个 `<tool_call>` 开标签都没有时，直接覆盖式地设 $R_i^{\mathrm{tool}}=0$、$R_i^{\mathrm{sum}}=R_{\text{pen}}=-0.5$（式 (21)，App. A.3）。注意这是"覆盖"而不是"加减"，且负信号**只从总结 token 走**，正好把"不查就直接答"这个行为的梯度方向压下去。作者报告一条代表性轨迹里 no-call 比例从约 10–15% 在 50 次更新内趋近于 0。

**（4）分段优势与路由（SLCA 本体）。** 两段奖励先**在组内各自归一化**：

$$\hat{A}_{i}^{\mathrm{tool}}=\frac{R_{i}^{\mathrm{tool}}-\mu_{g}^{\mathrm{tool}}}{\sigma_{g}^{\mathrm{tool}}+\epsilon_{\text{norm}}},\qquad \hat{A}_{i}^{\mathrm{sum}}=\frac{R_{i}^{\mathrm{sum}}-\mu_{g}^{\mathrm{sum}}}{\sigma_{g}^{\mathrm{sum}}+\epsilon_{\text{norm}}}$$

（式 (2)），再逐 token 路由（式 (3)，正文 HTML 中该式 MathML alttext 缺失，此处据其 annotation 还原）：

$$\hat{A}^{\text{SLCA}}_{i,t}=\begin{cases}\lambda_{\mathrm{tool}}\,\hat{A}_{i}^{\mathrm{tool}}, & t\in\mathcal{T}_{i,\mathrm{tool}},\\ \lambda_{\mathrm{sum}}\,\hat{A}_{i}^{\mathrm{sum}}, & t\in\mathcal{T}_{i,\mathrm{sum}},\\ 0, & m_{i,t}=0.\end{cases}$$

环境注入的 token 直接拿 0。两个工程细节（App. A.3）：其一是**存在性过滤**——只用"该段存在"的样本子集 $\mathcal{I}_g^s=\{j\mid g(j)=g,\ L_j^s>0\}$ 去算 $\mu_g^s,\sigma_g^s$（式 (17)、(19)），因为工具使用天然稀疏，若组里只有一条样本带工具段，naive 归一化会方差崩塌；而当有效样本数 $<2$ 时作者**显式把 advantage 置 0**（关掉这次更新），而不是回退到 $\mu=0,\sigma=1$（那会把原始分数当成 advantage 放大）。其二是**权重必须在归一化之后乘**：$\operatorname{Norm}(\lambda X)=\operatorname{Norm}(X)$（式 (20)），归一化前缩放会被 z-score 完全抵消。

**（5）优化目标。** 最终就是把 GRPO 的统一标量 advantage 换成路由后的 $\hat{A}^{\text{SLCA}}_{i,t}$，其余仍是 PPO-clip：

$$\mathcal{J}(\theta)=\mathbb{E}_{x\sim\mathcal{D},\,\{y_{i}\}\sim\pi_{\theta_{\mathrm{old}}}}\Bigg[\frac{1}{N}\sum_{i,t}m_{i,t}\cdot\min\Big(\rho_{i,t}\hat{A}^{\text{SLCA}}_{i,t},\ \text{clip}\big(\rho_{i,t},1-\epsilon_{\text{clip}},1+\epsilon_{\text{clip}}\big)\hat{A}^{\text{SLCA}}_{i,t}\Big)\Bigg]$$

（式 (5)，$N=\sum_{i,t}m_{i,t}$；逐 token KL 惩罚项为简洁略去）。实际配置：对称 clip $\epsilon_{\text{clip}}=0.2$（不用 DAPO 式非对称）、dual-clip 常数 3.0（只作用于负 advantage 且比值很大的样本）、KL 系数 0.001、学习率 $1\times10^{-6}$、1 个 RL epoch、7B 默认约 100 个策略更新步（表 6、App. C.2）。

### 为什么可能有效（作者的理论与一个教学例子）

作者的论证分三条，逻辑层次要分清：

- **定义上的隔离。** Proposition A.1：路由后工具 token 的梯度分量 $g_{\mathrm{tool}}^{\text{SLCA}}$ 在**单次更新内**不依赖 $R^{\mathrm{sum}}$，即 $\partial g_{\mathrm{tool}}^{\text{SLCA}}/\partial R^{\mathrm{sum}}=\mathbf{0}$（式 (4)、(9)）。作者自己补了一句限定：共享参数在后续优化步之间仍可能传递信息，这是 per-update 命题。
- **条件方差移除。** 假设总结奖励含一个零均值噪声 $\xi$（写作 $R^{\mathrm{sum}}=\bar{R}^{\mathrm{sum}}(y_{\mathrm{tool}})+\xi$，Assumption A.2），则在局部 score-function 估计下

$$\mathbb{E}\big[\mathbb{V}(g_{\text{STD}}\mid\mathcal{F}_{\mathrm{tool}})\big]-\mathbb{E}\big[\mathbb{V}(g_{\text{SLCA}}\mid\mathcal{F}_{\mathrm{tool}})\big]=\mathbb{E}\big[w_i^2\|U_{\mathrm{tool}}\|^2\sigma_\xi^2\big]>0$$

（式 (11)，Theorem A.3）。作者明确这是**条件**方差声明，不是无条件方差占优——剩余的系统性协方差项可能变化，所以整件事仍被框定为偏差–方差权衡。
- **冲突区间的方向保真。** 设 $\hat{A}^{\mathrm{tool}}=-\alpha$（罚）、$\hat{A}^{\mathrm{sum}}=\beta$（奖），$\alpha,\beta>0$，则标准 GRPO 的期望更新与理想下降方向 $\mathbf{d}^{*}=-\nabla\log\pi(y_{\mathrm{tool}})$ 的内积是 $(\alpha\sigma_{\mathrm{tool}}-\beta\sigma_{\mathrm{sum}})\|\nabla\|^2$；当 $\beta\sigma_{\mathrm{sum}}>\alpha\sigma_{\mathrm{tool}}$（两段原始奖励组标准差相等时退化为 $\beta>\alpha$）时**内积为负，更新方向反了，等于在强化失败**；SLCA 恒为 $+\alpha\|\nabla\|^2$，方向正确（定理/推论 A.4，App. A.2）。
- **偏差–方差权衡的另一半。** $\hat{A}^{\mathrm{sum}}$ 在组内跨不同 post-tool 状态归一化，因此不是状态条件 value，会混入"post-tool 状态差异"；但作者把它限制在总结 token 上，并指出标准 GRPO 也一样不带状态条件（MT-GRPO、GRPO-Verif 亦然），而显式按工具结果分组会把有效组大小降到 $G/C$、多工具调用场景降到 $G/C^{K}$，不现实。

**一个教学简化例子**（数字取自原文 App. A.2 与图 9，非我虚构）：任务是比较 Apple 与 Microsoft 当前股价，参考轨迹应当是一次并行 `get_stock_price` 覆盖两个 ticker。标准 GRPO 下的轨迹却先发了一次多余的 `search_company_info`，再把两次查询拆成两个串行回合，但总结写得又对又流畅（$R_{\mathrm{sum}}=1.00$）。按 HierR 权重分解：格式 1.00、键 1.00、值 1.00，工具名被多余调用稀释到 0.80，**并行分是 0.00**，加权后 $R_{\mathrm{tool}}=0.65$（低于组均值）。在统一 advantage 里，这个结构性的工具惩罚被漂亮的总结分抵消甚至反号；SLCA 则把这 $0.65$ 的惩罚只送进 $\hat{A}^{\mathrm{tool}}$——同样的初始模型，训练后给出单次并行调用，五个子奖励全部 1.00（$R_{\mathrm{tool}}=1.00$），同时 $R_{\mathrm{sum}}$ 仍保持 1.00，工具执行分提升 $+0.35$。

### 训练/推理的边界，以及哪些是现成组件

**全部改进都发生在 RL 训练阶段**的 advantage 估计与目标函数里；推理阶段没有任何额外搜索、额外 rollout 或额外解码。需要训练参数的只有策略本身（先用 Toucan 42,423 条做交叉熵 SFT，再做 RL）；SGLS 的 mocker（Qwen3-235B-A22B）与 summary judge（GPT-OSS-120B）都是**冻结的外部模型**，不参与更新；训练框架是 verl，模拟器用 vLLM 0.11.0 部署（App. C.2–C.3）。换句话说，SGLS 与 HierR 是本文搭建的基础设施（作者把它们算作贡献之一），但"统一 backbone + 分段路由"才是方法的新意；这里被模拟的"工具"不是搜索/代码执行器，而是目标业务 API，模型决定是否调用、调哪个、传什么参数、是否并行，固定流程只负责 schema 校验与返回构造。

## 3. 解决得怎么样？

### 实验条件与比较对象

三个 backbone：Qwen2.5-3B-Instruct、Qwen2.5-7B-Instruct（默认）、Qwen3-8B-Base；三个基准（§4.1）：

- **Toucan-Test**（域内，4,000 条 held-out：3,000 单轮 + 1,000 分解多轮）：指标 Name F1、ArgMatch、Process（$S_{\text{process}}$，事后计算）、Success $=\mathbb{I}[S_{\text{process}}\geq0.9]$；
- **BFCL V3**（单轮，去掉 relevance detection 子集）：测对未见 schema 的原子泛化；
- **$\tau^{2}$-Bench**（Airline / Retail / Telecom 三个双控制环境，官方 Pass1）：测需要与用户协作改状态的鲁棒性。

受控对照是 SFT+GRPO 与 SFT+SLCA-GRPO：两者共享数据划分、SFT checkpoint、SGLS endpoint、mocker 配置、解码设置、评测协议、$G=16$、1 个 RL epoch 与 HierR 定义，**唯一差别是统一 advantage 还是分段锁定 advantage**（§4.1、App. C.2）。另有 Original、SFT（在全部 74,241 条上做行为克隆，作为"数据等量"基线）、ToolPO（加性，用论文自带 outcome 协议）、RLTR（planner-summarizer 流水线，专用 planner SFT + 冻结 summarizer）四类参照。所有训练过的数字都是**三次独立 run 的 mean±std**——论文没有报告显著性检验，措辞也是"higher reported means"。

### 关键数值

- **域内 Toucan Success@0.9**（表 1/表 23）：7B 79.13% vs. GRPO 76.60%（**+2.53 pp**）；3B 76.47 vs. 74.12（+2.35 pp）；8B 79.02 vs. 76.97（+2.05 pp）。Process、Name F1 同向（7B Name F1 0.9164 vs. 0.8971）。
- **BFCL 单轮 Overall Acc**（图 3(a)/表 17）：8B 70.31±0.50 vs. GRPO 66.96±0.32（+3.35 pp），也高于 SFT 68.50±0.35；7B 69.77 vs. 68.41（+1.36 pp）；3B 63.61 vs. 63.21（+0.40 pp）。
- **$\tau^{2}$-Bench Pass1**（图 3(b)/表 18）：7B 41.02 vs. 31.87（**+9.15 pp**）；8B 44.69 vs. 34.66（+10.03 pp）；3B 35.63 vs. 34.54（+1.09 pp）。
- **与专门方法比较**：$\tau^{2}$-Bench 7B 上 SLCA 41.02，高于 ToolPO 30.44 与 RLTR 33.72；8B 上 ToolPO 44.32 vs. SLCA 44.69，只差 0.37 pp（App. D.6）。
- **效率**：图 2(b) 显示 SLCA 在三个尺度上以**更少的平均工具轮数**达到更高成功率；摘要也把"higher accuracy with reduced tool redundancy"作为卖点。SLCA 本身**零额外 rollout 成本**（不需要中间状态 rollout、不需要 value model），这是相对时间轴方法的结构性成本优势。

### 消融与分析是否支持"为什么有效"

作者为三条设计需求（路由 / 可扩展模拟 / 稠密分段反馈）各做了消融（表 2、表 23），并额外做了几组更能"证机制"的对照：

- **组件消融（7B）**：w/o SLCA → Toucan 76.60%（−2.53 pp）、$\tau^{2}$ 31.87%（−9.15 pp）；w/o SGLS → $\tau^{2}$ 36.19%（−4.83 pp），主要伤 OOD；w/o HierR → Toucan 73.44%（−5.69 pp），主要伤参数对齐与域内（表 2）。
- **支持路径 2×2 控制（表 21/22，只在 7B）**：把两段分开归一化后，只控制"哪条路径通"，四个格子分别是 both closed（SLCA）、$S\!\to\!T$ open、$T\!\to\!S$ open、both open。关闭 $S\!\to\!T$ 的主效应在 $\tau^{2}$-Bench 上是 **5.51 pp**，打开 $T\!\to\!S$ 只有 1.91 pp，交互项 3.13 pp。这是最接近机制验证的实验：它把"堵住总结→工具通路"的收益单独分离出来。但注意 matched w/o SLCA 的差距是 9.15 pp，比 5.51 pp 大——因为 w/o SLCA 同时改了归一化方式与 token 支持，作者也承认这一点，并说这些是"tested additive estimator 下的 support control effects，不是 routing-only 的因果估计"。
- **统一基线里的权重扫描（表 20）**：把统一估计器的工具/总结权重从 1:1 调到 2:1、3:1、5:1，最好的 3:1 在 $\tau^{2}$ 上 35.24%，仍明显低于 SLCA 的 41.02%，且继续加大工具权重反而掉回 32.90%——说明差距不是"权重没调好"就能补上的。
- **奖励协议互换**：换成二值执行奖励 $R_{\text{succ}}$（表 25）增益仍为正（+2.92 / +1.33 / +4.64 pp），图 10 里第 100 步 $R_{\text{succ}}$ 0.593 vs. 0.424；把响应 mocker 换成 GPT-OSS-120B（表 8）增益仍为正（+2.83 / +1.24 / +7.16 pp）。作者据此说明结果不绑定单一奖励表述。
- **总结分支消融（表 16）**：把总结段 advantage 全置零（$\hat{A}^{\mathrm{sum}}=0$，且不给 omission guard 留例外）会显著掉分（Toucan 67.54%、BFCL 61.53%、$\tau^{2}$ 29.44%），并把 no-call 率抬到 14.2%。这说明"只留工具奖励"并不成立——总结分支与拒答兜底都是必要的（论文把这一行定位为 guard 诊断，不当作"只测总结分支"的对照）。
- **稳定性诊断（表 5）**：梯度范数标准差 3B 降 25.0%、7B 13.1%、8B 2.5%（绝对值 0.209→0.156 / 0.108→0.094 / 0.320→0.312）。作者自己限定这只是一个聚合描述量、无法区分各噪声源的贡献，也只说"这些聚合结果不足以确立梯度稳定性的规模趋势"。换言之，"更稳"是伴随现象，论文并未把它当作隔离机制的证据（分析者推断）。

我的判断（分析者推断）：论文中"性能提升"是三类基准、三个尺度、三次 run 的一致观测，证据较硬；"为什么有效"一侧，**结构隔离本身（式 (4)）是定义上的恒等式**，而"隔离带来了多少收益"只有支持路径控制（5.51 pp）与统一比例扫描提供部分支持，其余（条件方差移除、方向保真）是单次更新下的理论陈述，不与实验直接一一对应。

### 代价与仍未解决的问题

- **算力与系统成本**：SFT 用 8×H20，RL 用 32×H20（4 节点）；每个 prompt 16 条 rollout；每条 rollout 都要过一次 summary judge（GPT-OSS-120B，8192 max tokens、540 s 超时、3 次重试）；SGLS 需要一台 235B MoE 的冻结 mocker（vLLM、TP=8、最多 300 并发）。所有结果都是三次 run 均值，评测成本 ×3。
- **数据与奖励的依赖**：$S_{\text{process}}$ 依赖 Toucan 的真实 MCP 教师轨迹做 gold 匹配，当同一请求存在多种合法 API 方案时可能低估替代解；Toucan 的 strict Success@0.9 **是对 $S_{\text{process}}$ 阈值化的结果，而不是独立的任务结果标签**（作者在 Limitations 里明说）。为缓解这一点，作者补做了执行型奖励实验（表 25）与 judge-free 的 BFCL / $\tau^{2}$ 评测。
- **方法假设与边界**：SLCA 假定"工具调用与自由文本之间有清晰边界"，inline code generation 之类的场景需要学习式分段；工具段内只有一个标量 $\hat{A}^{\mathrm{tool}}$，**无法区分同一段里 Action 1 正确、Action 2 失败**（时间轴问题，与 VinePPO/GiGPO/SPO 的组合未做实验）；$\hat{A}^{\mathrm{sum}}$ 保留 grouping bias。
- **仍未改善的项**：BFCL Multi-Turn 上 SLCA 在 3B 与 8B 仍低于 SFT（表 17：3B 0.0622 vs. SFT 0.0867；8B 0.1489 vs. 0.1544），作者没有把这里解释成 SLCA 的收益，只是指出 GRPO 掉得更狠（8B 0.0822）。最大规模只到 8B、且全程用 SGLS 模拟而非真实 API，作者把更大规模与真机对比列为 future work。
- **与 ToolPO 的比较要小心**：7B 上 ToolPO 的崩溃（Toucan 20.00%）发生在 LLM-judge outcome 协议下；换成 reference-rule outcome 后 ToolPO 回到 77.35 / 68.86 / 34.18，仍低于 SLCA 但接近统一 GRPO（表 9、App. C.4）。作者把它明确定位为"协议敏感性诊断"，而不是"ToolPO 一定失败"。

---

**一句话收束**：作者发现工具调用 RL 的轨迹天然分成"执行段 / 总结段"两段非同质输出，而 GRPO 类算法把单一标量 advantage 广播给所有 token，形成跨段信用错配（总结奖励污染工具 token 的更新，冲突区间甚至方向反转），因此提出 SLCA-GRPO——用掩码自动分段、HierR 分段回报、分段独立归一化与逐 token 路由在 backward 之前切断 summary→tool 通路，并配 SGLS 提供可扩展的 schema 约束探索；实验表明在三个尺度、三个基准上它相对 matched GRPO 稳定为正（7B 上 +2.53 / +1.36 / +9.15 pp）且轨迹更短，支持路径控制也给出了 5.51 pp 的部分机制性证据，但仍存在分段边界假设、工具段内时间轴 credit 未解决、$\hat{A}^{\mathrm{sum}}$ 分组偏差、多轮 BFCL 未改善以及规模只到 8B、依赖模拟器等限制。
