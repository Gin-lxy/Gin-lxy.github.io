## 0. 一句话结论

本文针对"工具调用 Agent 的 RL 后训练"这一具体场景：GRPO 类算法把整条轨迹的单一标量 advantage 广播给所有 token，使"总结段"的奖励波动进入"工具段" token 的梯度（作者命名为 Cross-Segment Credit Misattribution，跨段信用错配）。论文提出 SLCA-GRPO——复用 agent loop 自带的 token 掩码自动切出工具段与总结段，两段奖励各自组内归一化后只路由给本段 token，并用 SGLS 模拟器与 HierR 分层奖励支撑训练。在论文报告的条件（Qwen2.5-3B/7B-Instruct、Qwen3-8B-Base 三个 backbone，Toucan-Test / BFCL V3 单轮 / τ²-Bench 三个基准，与 matched GRPO 同数据同预算的三次运行均值）下，增益一致为正（7B：+2.53 / +1.36 / +9.15 pp）；但"切段隔离本身贡献多少"只有部分机制证据，3B 档与多轮 BFCL 的改善很小甚至仍不及 SFT，结论不应外推到真实 API、更大模型或其它奖励体系。

## 1. 论文具体想解决什么问题？

### 研究背景与任务

**原文事实。** LLM 从"聊天"走向"做事"，核心能力是通过外部工具规划并执行动作；SFT 能给出不错的初始化，但它依赖模仿固定模式，在 Model Context Protocol（MCP）这类规模大、变动频繁的工具命名空间下很脆弱（§1）。本文研究的正是**工具调用 agent 的 on-policy RL 后训练**：给定一条指令 $x\sim\mathcal{D}$ 和当前实例的工具 schema $\Sigma(x)$，策略要产出"推理 + 结构化工具调用"的动作链，并以一段面向用户的自然语言总结收尾（§1、§3.1）。

工具调用轨迹与纯推理任务的关键差别，是它天然被外部可验证的边界切开。论文把一条 rollout 写成

$$
y=\big[y_{\mathrm{tool}}\oplus y_{\mathrm{sum}}\big]
$$

其中 $y_{\mathrm{tool}}$ 是操作段（穿插结构化工具调用的推理轨迹），$y_{\mathrm{sum}}$ 是用户可见的总结段。作者把这种结构称为 **Heterogeneous Rollouts（非同质 rollout）**（§1、§3.1）。

### 现有方法通常怎么做、在哪些条件下失效

**原文事实（§1、§2.2、App. C.4）。** 主流 GRPO 会把一个轨迹级的标量 advantage 广播给所有 token；即使引入过程奖励模型（PRM），信号也是先被加总成 $R_{\text{total}}=R_{\mathrm{tool}}+R_{\mathrm{sum}}$ 再做 advantage 估计。作者把这一结构性缺陷命名为 **Global Signal Conflation**，并指出三类已有缓解手段都没有堵住这条通路：

- 时间轴方法 VinePPO、GiGPO、SPO 处理"步与步之间"的 credit，但仍然保留 $R_{\text{total}}$；
- ToolPO 增加局部工具奖励，但其 advantage 形式是 $A_{\mathrm{tool}}=A_{\text{global}}+\lambda\cdot A_{\text{tool\_local}}$、$A_{\mathrm{sum}}=A_{\text{global}}$，总结奖励仍以 $A_{\text{global}}$ 的一部分进入工具 token；
- RLTR 把 planner 与 summarizer 拆成两段流水线，代价是放弃统一 backbone（额外引入 planner 专用 SFT 与冻结 summarizer）。

### 作者发现了什么新现象、瓶颈或被忽略的问题

这里有三个层次，证据强度依次递减，需要分开看：

1. **冲突情形（sign-conflict）的个案诊断（作者主张 + 单例证据）。** 论文首页一张未编号的 "Diagnostic cases" 图给出两个例子：一个是"多余的工具调用 + 正确的交付总结"，另一个是"正确的退款证据 + 错误的退款总结"。在统一 advantage 下，混合后的标量可能强化错误的工具行为、或惩罚正确的工具使用（§1）。这是定性诊断，不是统计结论。
2. **训练层面的统计现象（原文事实，但解释是作者主张）。** 标准 GRPO 稳定到更长的轨迹上，却没有对应的成功率提升（Figure 2(b)、§4.2）。作者提出 "performative execution" 的解释——模型在靠拉长轨迹迎合总结奖励，而不是提高工具调用精度；原文用词是 "compatible with"，即这是与数据一致的解释，不是被验证的因果结论。
3. **梯度诊断（原文事实）。** 训练中梯度 $L_2$ 范数出现高频尖峰（Figure 5、Table 5），但 3B 上工具/总结两个梯度方向的余弦相似度全程接近 0（区间 $[-0.03,0.08]$，App. B）。作者据此判断不稳定更可能来自**被指派的 advantage 幅度**（污染），而不是两段梯度方向冲突，因此把 SLCA 称为 "advantage-level firewall" 而不是 "gradient firewall"（App. B）。

另有两个与解释一致、但同样是关联性的现象：3B 与 8B 上标准 GRPO 的 Summary 分数更高、Success 反而更低；ToolPO 在 7B 上 Summary 达 0.6054，而 Process 只有 0.3408（Table 15、App. D.1）。即"一段好看"可以掩盖"另一段坏了"。

### 作者认为问题产生的原因，与论文要验证的核心假设

**作者主张。** 问题不在于缺少稠密奖励，而在于 advantage 估计之前的信号聚合：只要在归一化与广播时把两段混在一起，任何稠密奖励都救不了。所以要在**结构轴**上、在 backward 之前阻断 summary→tool 的 advantage 通路（§1、§3.3）。

作者也明确了边界（值得注意，作者自己写得很克制）：SLCA 并不主张"工具调用与最终答案因果无关"，而是把它当作一次**偏差–方差权衡**——用执行侧的稠密奖励去更新工具决策 token，认为它方差更低、信息也足够充分；两段之间合法的因果联系（正确工具 → 更好总结）通过 $R^{\mathrm{sum}}$ 中的系统性成分 $\bar{R}^{\mathrm{sum}}(y_{\mathrm{tool}})$ 保留（§1、Assumption A.2）。

把论文要验证的东西拆成两个可检验的假设更清楚（**审稿人判断**）：

- **H1（隔离性）**：两段各自归一化并路由后，工具 token 的梯度分量对 $R^{\mathrm{sum}}$ 的偏导恒为 0。这是式 (4) 的 per-update 恒等式，本质上是定义上的。
- **H2（收益归因）**：消除这条污染通道能转化为可测的收益，且这些收益不能仅由"加性加权 + 调权重"解释。这需要控制实验，是全文最吃紧的一环（见 §4.3 与第 5 节质疑一）。

### 三类问题的区分（按规范要求）

- **领域早已存在的一般问题**：agentic RL 的信用分配与稀疏奖励，论文在 §2.2 明确以引用线承认（Williams 1992、Schulman 等、Lightman 等、ToolRL 等）。
- **本文的新观察**：把"两段非同质输出被同一标量 advantage 广播"识别为结构性失败模式，并把不稳定归因到 advantage 污染而非梯度方向冲突；后者有 App. B 的余弦相似度测量作为可证伪诊断。
- **本文实际解决的具体子问题**：在"轨迹以最终答复块收尾、段边界可由掩码确定"的设定下，让两段 reward 只更新各自 token。超出该范围的场景（无清晰边界、工具段内时间轴）论文在 §6 明确列为未解决。

一句话提醒：论文观察到了现象（冲突案例、分数错位、训练轨迹），也给出了结构性机制，但**没有**证明"这些现象在多大程度上由跨段污染造成"——这是分析者判断，不是原文结论。

## 2. 创新点是什么？

**总括。** 真正的技术增量是把 credit assignment 从**时间轴**挪到**结构轴**：不改采样、不增加 rollout、不拆模型，只改 advantage 的归一化分组与逐 token 路由；配套的 SGLS 与 HierR 是让这个路由能在大规模训练里跑起来的基础设施，而不是新的学习算法。按性质划分：结构轴路由是新提法，但构造是"分组归一化 + 路由"的组合，技术门槛不高；SGLS 与 HierR 属于已有思路（工具模拟、过程奖励、LLM judge）的工程化组合。

### 创新点一：Segment-Locked Credit Assignment（结构轴路由）

- **新增了什么**：用 rollout 自带的 token 级掩码 $m_{i,t}\in\{0,1\}$ 做**自动分段**——把 $m=1$ 的极大连续段中**最后一段**定义为 Summary 段，之前所有段的并集为 Tool 段（式 (6)–(8)，App. A.1）；两段奖励在组内**各自**归一化（式 (2)）；再逐 token 路由（式 (3)）：工具 token 只拿 $\lambda_{\mathrm{tool}}\hat{A}^{\mathrm{tool}}$，总结 token 只拿 $\lambda_{\mathrm{sum}}\hat{A}^{\mathrm{sum}}$，环境注入 token 拿 0。
- **与最接近已有方法的具体差异**：ToolPO 是加性增强（总结奖励仍进入工具 token）；RLTR 是拆流水线（放弃统一 backbone）；VinePPO/GiGPO/SPO 仍在 $R_{\text{total}}$ 上做段内步级 credit。作者声明的差异是"结构轴（execution vs. articulation）与时间轴正交"（§2.2、§3.1 Scope）。
- **是哪种创新**：新研究思想（把输出异构性当作 credit assignment 的结构变量）+ 已有组件的新组合（掩码来自 agent loop，归一化来自 GRPO）。
- **对应前面哪个问题**：直接对应 H1——污染路径是"广播统一 advantage"，那就在广播前分流。
- **原文给出的证据**：w/o SLCA（统一估计器）在 7B 上 Toucan Success 76.60 vs 79.13、τ²-Bench 31.87 vs 41.02（Table 2、Table 23）；支持路径控制（Table 21/22）给出关闭 S→T 主效应 5.51 pp（τ²）；统一奖励比例扫描（Table 20）显示把工具权重调到 3:1 最好也只有 35.24（τ²），低于 SLCA 的 41.02。
- **移除该设计会怎样**：即 w/o SLCA 行。但要注意（**作者自述，§4.3**）：这一行"changes both normalization and token support"，度量的是组合变更而非单独某个操作的贡献。

### 创新点二：HierR（分层奖励）

- **新增了什么**：把回报拆成两段语义不同的信号：$R^{\mathrm{tool}}=S_{\text{process}}$ 是稠密结构奖励，$R^{\mathrm{sum}}=S_{\mathrm{summary}}$ 是终局偏好奖励（式 (1)）。$S_{\text{process}}$ 为五项加权和（式 (22)）：

$$
S_{\text{process}}=0.10\,S_{\text{fmt}}+0.25\,S_{\text{name}}+0.15\,S_{\text{key}}+0.20\,S_{\text{val}}+0.30\,S_{\text{par}}
$$

（格式合规、工具名多重集 F1、参数键 Jaccard、参数值宽松匹配、首轮并行个数的硬 0/1 检查，式 (23)–(27)，App. A.4）。$S_{\mathrm{summary}}$ 用 LLM-as-a-judge：冻结的 GPT-OSS-120B 沿 Result Interpretation / Information Completeness / Expression Quality 三维度打 5 级分，线性映射 $(r-1)/4$ 到 $[0,1]$，解析失败一律计 0.0（App. A.5）。
- **与已有方法的差异**：过程奖励与 judge 都不是新概念（§2.2、App. A.5 的引用）；新意只在"按段定义"——执行奖励只描述工具段的结构正确性，总结奖励只描述答复质量。
- **对应前面哪个问题**：让"分段路由"有信号可分——若没有两段独立可比的标量，路由无从谈起。
- **证据**：w/o HierR 在 7B 上 Toucan Success 掉到 73.44（−5.69 pp）、τ² 34.50（Table 2），说明稠密分段反馈重要；但这与 SLCA 的增益没有完全分离。
- **设计代价**：$S_{\text{process}}$ 依赖 gold 调用做匹配，当同一请求存在多种合法 API 方案时可能低估替代解；$S_{\text{par}}$ 是硬 0/1；judge 是外部冻结模型（§6、App. A.4、A.5）。

### 创新点三：SGLS（Schema-Guided LLM Simulator，基础设施）

- **新增了什么**：两阶段模拟（App. C.3）。第一阶段是**纯确定性校验**（不调 LLM）：工具名不在当前实例可用集合就返回硬编码错误串，必填参数缺失就返回列出缺失字段的确定性错误信息；第二阶段只对通过校验的调用，把工具定义 JSON 与解析后的 `<tool_call>` 载荷塞进固定模板，由冻结的 Qwen3-235B-A22B-Instruct（temperature 0.6、max 4096 tokens）生成 mock `<tool_response>`。
- **与已有工作的差异**：用模拟器/LLM 仿真替代真实 API 是已有路线（§2.1 引用 StableToolBench、LM-emulated sandbox 等）；本文的差异是把 schema 当"控制平面"，并强调 mocker 与策略 backbone 跨家族、跨代（MoE vs. dense、不同 tokenizer、不同预训练语料）以抑制隐式泄漏；它只做模板约束的模拟，从不提供规划建议或奖励信号（App. C.3、A.6）。
- **证据与边界**：w/o SGLS 消融主要伤 OOD（7B τ² 36.19 vs 41.02），但在域内 Process 反而略高（0.8787 vs 0.8766）（Table 2、Table 23）。作者在 A.6 明确不主张原始观测分布的对齐（$D_{\mathrm{TV}}(P_{\mathrm{real}},P_{\mathrm{sim}})$ 可能为 1），只主张 schema/语义层面的一致性——这个自我限定值得肯定。

### 什么不算创新（明确排除）

- SFT 初始化、GRPO/PPO-clip 目标（式 (5)）、KL 惩罚、dual-clip、low-var KL 都是现成组件；
- token 级掩码本身来自 agent loop，不是本文发明；
- LLM-as-a-judge、过程奖励、模拟工具环境均有既有工作（论文自己引用）；
- 单纯使用更大的 backbone 或更换数据集/指标不构成创新；
- 作者声称"SLCA 与时间轴方法正交、可组合"，目前只有论述，**没有组合实验**（§2.2 末句、§6），因此这一互补性主张**当前无法确认**。

**原创边界（审稿人判断）**：根据本文的 related work 与实验对比，只能确认作者声称的差异；是否构成"首次在结构轴上做 credit assignment"，还需要更完整的文献检索。

## 3. 作者如何解决？

### 核心直觉

把"一次策略更新"拆成两条互不串扰的信用通道：**执行段的稠密过程奖励只更新工具段 token，面向用户的总结偏好只更新总结段 token**。直觉上，污染来自"广播统一 advantage"，所以只要两段各自归一化、各走各的 token，工具 token 的梯度对 $R^{\mathrm{sum}}$ 的偏导就恒等于零（式 (4)）。作者为之付出的代价是承认一个偏差：$\hat{A}^{\mathrm{sum}}$ 仍在组内跨 post-tool 状态归一化，并非状态条件价值，但这个偏差被限制在总结 token 上（App. A.2 的 Bias–Variance Trade-off 小节）。

### 实际运行流程

**（1）输入与 rollout。** 输入是指令 $x$ 与实例工具 schema $\Sigma(x)$；对同一个 $x$ 采样 $G=16$ 条 rollout，每条通过与 SGLS 交互产生（Algorithm 1）。SGLS 的两阶段流水线见上一节；作者强调校验失败的调用拿到的是确定性反馈，只有语义上成立的调用才进入 LLM mock（App. C.3）。

**（2）分段（mask-based segmentation）。** 复用 agent loop 本来就有的掩码 $m_{i,t}$：把 $m=1$ 的极大连续段记为 $\{[s_{i,k},e_{i,k})\}_{k=1}^{K_i}$（式 (6)），**最后一段**是 Summary 段（式 (7)），**之前所有段的并集**是 Tool 段（式 (8)）。于是每个带梯度的 token 都被唯一指派一个语义角色，**不需要任何标注或学习式分段器**；边界假设是轨迹以一个最终答复块收尾（$K_i=1$ 时整条轨迹视为 Summary）。作者特别声明：SLCA 切的是结构轴，不切工具段内部的时间轴（Action 1 vs. Action 2），因此它不是 VinePPO/GiGPO/SPO 的变体（§3.1 Scope）。

**（3）分段回报（HierR）。** 回报拆成 $R(y)=R_{\mathrm{tool}}(y_{\mathrm{tool}})+R_{\mathrm{sum}}(y_{\mathrm{sum}}\mid y_{\mathrm{tool}},o)$，第 $i$ 条 rollout 直接取 $R_i^{\mathrm{tool}}=S_{\text{process}}(y_{i,\mathrm{tool}})$、$R_i^{\mathrm{sum}}=S_{\mathrm{summary}}(y_{i,\mathrm{sum}}\mid y_{i,\mathrm{tool}},o_i)$（式 (1)、§3.2）。另有一个容易被忽略但很关键的边角设计——**omission guard**（式 (21)，App. A.3）：当 ground truth 要求调用工具、而 rollout 里连一个 `<tool_call>` 开标签都没有时，直接**覆盖式**地设 $R_i^{\mathrm{tool}}=0$、$R_i^{\mathrm{sum}}=R_{\text{pen}}=-0.5$。注意这是"覆盖"而不是"加减"，且负信号**只从总结 token 走**——因为在无调用轨迹里根本没有工具 token 可罚，只能借总结 token 把"不查就直接答"压下去。作者报告一条代表性轨迹里 no-call 比例从约 10–15% 在 50 次更新内趋近于 0（App. A.3）。

**（4）分段优势与路由（SLCA 本体）。** 两段奖励先**在组内各自归一化**（式 (2)）：

$$
\hat{A}_{i}^{\mathrm{tool}}=\frac{R_{i}^{\mathrm{tool}}-\mu_{g}^{\mathrm{tool}}}{\sigma_{g}^{\mathrm{tool}}+\epsilon_{\text{norm}}},\qquad \hat{A}_{i}^{\mathrm{sum}}=\frac{R_{i}^{\mathrm{sum}}-\mu_{g}^{\mathrm{sum}}}{\sigma_{g}^{\mathrm{sum}}+\epsilon_{\text{norm}}}
$$

再逐 token 路由（式 (3)）：

$$
\hat{A}^{\text{SLCA}}_{i,t}=\begin{cases}\lambda_{\mathrm{tool}}\,\hat{A}_{i}^{\mathrm{tool}}, & t\in\mathcal{T}_{i,\mathrm{tool}},\\ \lambda_{\mathrm{sum}}\,\hat{A}_{i}^{\mathrm{sum}}, & t\in\mathcal{T}_{i,\mathrm{sum}},\\ 0, & m_{i,t}=0.\end{cases}
$$

环境注入的 token 直接拿 0。两个工程细节（App. A.3）：

- **存在性过滤**：只用"该段存在"的样本子集 $\mathcal{I}_g^s=\{j\mid g(j)=g,\ L_j^s>0\}$ 计算 $\mu_g^s,\sigma_g^s$（式 (17)、(19)），因为工具使用天然稀疏，若组里只有一条样本带工具段，naive 归一化会方差崩塌；而当有效样本数 $|\mathcal{I}_g^s|<2$ 时，作者**显式把 advantage 置 0**（关掉该段这次更新），而不是回退到 $\mu=0,\sigma=1$——那会把原始分数当成 advantage 放大（式 (18) 的讨论）。
- **权重必须在归一化之后乘**：$\operatorname{Norm}(\lambda X)=\operatorname{Norm}(X)$（式 (20)），归一化前缩放会被 z-score 完全抵消。

**（5）优化目标。** 就是把 GRPO 的统一标量 advantage 换成路由后的 $\hat{A}^{\text{SLCA}}_{i,t}$，其余仍是 PPO-clip（式 (5)）：

$$
\mathcal{J}(\theta)=\mathbb{E}_{x\sim\mathcal{D},\,\{y_{i}\}\sim\pi_{\theta_{\mathrm{old}}}}\Bigg[\frac{1}{N}\sum_{i,t}m_{i,t}\cdot\min\Big(\rho_{i,t}\hat{A}^{\text{SLCA}}_{i,t},\ \text{clip}\big(\rho_{i,t},1-\epsilon_{\text{clip}},1+\epsilon_{\text{clip}}\big)\hat{A}^{\text{SLCA}}_{i,t}\Big)\Bigg]
$$

其中 $N=\sum_{i,t}m_{i,t}$，逐 token KL 惩罚项为简洁略去。实际配置：对称 clip $\epsilon_{\text{clip}}=0.2$（不用 DAPO 式非对称）、dual-clip 常数 3.0（只作用于负 advantage 且比值很大的样本）、KL 系数 0.001、学习率 $1\times10^{-6}$、1 个 RL epoch、7B 默认约 100 个策略更新步（Table 6、App. C.2）。

### 教学简化示例（非论文实验数据）

为理解"权重必须在归一化之后乘"（式 (20)），可以看一个两样本的小例子（**教学简化示例**，数字为阅读者构造）：某步内两条 rollout 的工具奖励为 1.0 与 0.6，组均值 0.8、标准差 0.2，归一化后的 advantage 是 $+1$ 与 $-1$。若先各乘权重 $\lambda=2$ 再归一化，得到 $(2.0-1.6)/0.4=+1$ 与 $(1.2-1.6)/0.4=-1$——和没乘一样。原文用 $\operatorname{Norm}(\lambda X)=\operatorname{Norm}(X)$ 把这个恒等式写出来，说明"先乘权重"在理想情况下等于没乘；只有在归一化**之后**乘 $\lambda_s$（即式 (3) 的做法）才真正改变两段之间的相对强度。

### 训练/推理的边界，以及哪些是现成组件

**全部改进都发生在 RL 训练阶段**的 advantage 估计与目标函数里；推理阶段没有额外搜索、额外 rollout 或额外解码（§3.3："changes only the scalar advantage attached to each token"）。需要训练参数的只有策略本身（先用 Toucan 42,423 条做交叉熵 SFT，再做 RL）；SGLS 的 mocker（Qwen3-235B-A22B-Instruct）与 summary judge（GPT-OSS-120B）都是**冻结的外部模型**，不参与更新（App. C.3、A.5）。训练框架是 verl，模拟器用 vLLM 0.11.0 部署（App. C.2–C.3）。换句话说：SGLS 与 HierR 是本文搭建的基础设施，**"统一 backbone + 分段路由"才是方法的新意**；被模拟的"工具"不是搜索/代码执行器，而是目标业务 API，模型决定是否调用、调哪个、传什么参数、是否并行，固定流程只负责 schema 校验与返回构造。

## 4. 解决得怎么样？

### 4.1 实验设置

**任务与数据（原文事实，§4.1、App. C.1）。** 三个评测面：

- **Toucan-1.5M（域内）**：同一数据集既做 SFT 初始化又做 RL 后训练；经多阶段过滤得到 42,423 条 SFT 样本与 31,818 条 RL 样本（21,212 条原生单轮 + 10,606 条分解多轮），评测用 4,000 条 held-out Toucan-Test（3,000 单轮 + 1,000 分解多轮）。指标：Name F1、ArgMatch、Process（$S_{\text{process}}$，事后对所有设置统一计算）、Success $=\mathbb{I}[S_{\text{process}}\geq0.9]$。
- **BFCL V3（泛化）**：主比较去掉 relevance detection 子集、只取单轮，测对未见 schema 的原子泛化；附录另报 Multi-Turn。
- **τ²-Bench（鲁棒性）**：Airline / Retail / Telecom 三个双控制环境，官方 Pass1。

**backbone 与基线（原文事实）。** 三个 backbone：Qwen2.5-3B-Instruct、Qwen2.5-7B-Instruct（默认）、Qwen3-8B-Base。六类方法：Original、SFT（在 74,241 条全量上做行为克隆，作为"数据等量"基线）、SFT+GRPO、ToolPO、RLTR（adapted）、SFT+SLCA-GRPO。

**受控变量（原文事实）。** 核心对照是 SFT+GRPO 与 SFT+SLCA-GRPO：两者共享数据划分、SFT checkpoint、SGLS endpoint、mocker 配置、解码设置、评测协议、$G=16$、1 个 RL epoch 与 HierR 定义，**唯一差别是统一 advantage 还是分段锁定 advantage**（§4.1、App. C.2）。所有训练过的数字都是**三次独立 run 的 mean±std**；论文没有报告显著性检验，措辞是"higher reported means"。

**主实验/消融/附录的分工**：主表（Table 1）回答域内与基线对比；Figure 3 回答跨分布泛化与协作鲁棒性；Table 2/23 回答三组件消融；App. D.8/D.9 回答"是不是调权重就能补上"（机制）；App. D.12/C.3 回答奖励与 mocker 替换后是否仍成立；App. D.11 回答工具空间放大（$K$ 扫到 150）。

- **域内 Toucan Success@0.9**（Table 1、Table 23）：7B 79.13 vs 76.60（**+2.53 pp**）；3B 76.47 vs 74.12（+2.35 pp）；8B 79.02 vs 76.97（+2.05 pp）。同向的还有 Process（7B 0.8766 vs 0.8667）与 Name F1（7B 0.9164 vs 0.8971）。

- **τ²-Bench Pass1**（Figure 3(b)、Table 18）：7B 41.02±1.01 vs 31.87±2.97（**+9.15 pp**）；8B 44.69±0.84 vs 34.66±2.36（+10.03 pp）；3B 35.63±0.91 vs 34.54±2.57（+1.09 pp）。

- **训练动态**（Figure 2(b)，§4.2）：SLCA 在三个尺度上以更少的平均工具轮数达到更高成功率；作者同时承认"轨迹长度差距很小"（"The gap in trajectory length is narrow"）。Figure 2(a) 的曲线是**代表性单次 run**；ToolPO-7B 在 step 40 后下降、step 80 后结构分叉（App. D.3），RLTR 因粗粒度完整性奖励变化更慢。

### 4.3 机制证据

这一节单独评估"为什么有效"，而不是"是否有效"。按证据强度排序：

1. **支持路径 2×2 控制（Table 21/22，只在 7B）——最接近机制验证的实验。** 把两段分开归一化后，只控制"哪条路径通"，四个格子是 both closed（SLCA）、$S\!\to\!T$ open、$T\!\to\!S$ open、both open。关闭 $S\!\to\!T$ 的主效应在 τ²-Bench 上是 **5.51 pp**，打开 $T\!\to\!S$ 只有 1.91 pp，交互项 3.13 pp；Toucan/BFCL 上对应只有 1.32/0.80 pp。**作者自己限定**这些是"tested additive estimator 下的 support control effects，不是 routing-only 的因果估计"。
2. **统一奖励比例扫描（Table 20）——回答"是不是权重没调好"。** 把统一估计器的工具/总结权重从 1:1 调到 2:1、3:1、5:1，τ² 最好的是 3:1 的 35.24%，仍低于 SLCA 的 41.02%，且继续加大工具权重反而掉回 32.90%。差距不能靠单一权重补上；但反过来说，**统一估计器本身也从 31.87 涨到 35.24（+3.37 pp）**，说明"重加权"确实吃掉了一部分看似属于 SLCA 的增益（审稿人判断）。
3. **定义性隔离（Proposition A.1、式 (4)）** 是恒等式：路由后工具 token 的梯度分量在**单次更新内**不依赖 $R^{\mathrm{sum}}$。作者自己补了限定——共享参数在后续优化步之间仍可能传递信息。
4. **理论分析（Theorem A.3/A.4，App. A.2）** 是**条件性**陈述：A.3 在局部 score-function 估计下证明移除一个正的噪声方差项（式 (11)），作者明确不给出完全归一化 GRPO 的闭式，也承认剩余系统性协方差项可能变化；A.4 证明冲突区间（$\hat{A}^{\mathrm{tool}}=-\alpha<0<\beta=\hat{A}^{\mathrm{sum}}$）下标准 GRPO 的更新方向可能反号（当 $\beta\sigma_{\mathrm{sum}}>\alpha\sigma_{\mathrm{tool}}$），SLCA 恒保方向，并给出 Figure 9 的具体实例。**但论文没有报告 $\sigma_{\mathrm{tool}}$ 与 $\sigma_{\mathrm{sum}}$ 的实际数值**，因此无法判断该条件在训练中出现的频率——**无法确认**。
5. **稳定性诊断（Table 5、Figure 5）**：梯度范数标准差 3B 降 25.0%、7B 13.1%、8B 2.5%（绝对值 0.209→0.156 / 0.108→0.094 / 0.320→0.312）。作者自己限定这只是聚合描述量、无法区分各噪声源贡献，只说"这些聚合结果不足以确立梯度稳定性的规模趋势"。换言之，"更稳"是伴随现象，不能算隔离机制的证据。
6. **辅助证据**：图 9 单例（见上）；no-call 率从 10–15% 在 50 步内趋近 0（App. A.3）；奖励协议换成二值 $R_{\text{succ}}$ 后增益仍为正（+2.92 / +1.33 / +4.64 pp，Table 25，Figure 10 中第 100 步 $R_{\text{succ}}$ 0.593 vs 0.424）；把 mocker 换成 GPT-OSS-120B 后仍为正（+2.83 / +1.24 / +7.16 pp，Table 8）；总结分支消融（Table 16）显示把总结段 advantage 全置零（含 guard 例外）会显著掉分（Toucan 67.54%、BFCL 61.53%、τ² 29.44%），且 no-call 率被抬到 14.2%，说明"只留工具奖励"并不成立，总结分支与拒答兜底都是必要的。

**审稿人判断**：论文中"性能提升"是三类基准、三个尺度、三次 run 的一致观测，证据较硬；"为什么有效"一侧，**结构隔离本身是定义上的**，而"隔离带来了多少收益"只有支持路径控制（5.51 pp）与比例扫描提供部分支持，其余（条件方差移除、方向保真）是单次更新下的局部理论陈述，不与实验直接一一对应。**不能把性能提升自动解释为所提机制已被验证。**

### 4.4 成本与适用范围

**论文实际报告的成本（原文事实）：**

- 训练算力：SFT 用 8×H20，RL 用 32×H20（4 节点）；RL total batch 128、mini-batch 32、$G=16$、1 个 epoch、约 100 个策略更新步（7B）（Table 6、App. C.2）。
- 外部模型依赖：SGLS 需要一个 235B MoE 的冻结 mocker（Qwen3-235B-A22B-Instruct，vLLM 0.11.0、TP=8、最多 300 并发、bfloat16）；summary judge 为 GPT-OSS-120B（8192 max tokens、540 s 超时、3 次重试，温度 0）；τ²-Bench 的官方用户模拟器是 DeepSeek-V3.2（App. C.3、A.5、Table 10、Table 12）。
- 评测成本：所有训练结果均为三次 run 均值，等于评测开销 ×3；Toucan 评测 concurrency 256、max tokens 12,288；BFCL batch 256（App. C.2、C.5）。
- **论文未报告**训练墙钟时间、GPU 小时数或经济成本（全文对 "cost" 的使用仅指真实 API 成本与工具冗余），因此绝对开销**无法确认**。作者只声称 SLCA 本身"zero additional rollout cost"（不需要中间状态 rollout、不需要 value model）与"reduced tool redundancy"，这两点是相对时间轴方法的结构性优势，不是实测成本对比。

**数据与标注依赖（原文事实）**：$S_{\text{process}}$ 依赖 Toucan 的真实 MCP 教师轨迹做 gold 匹配；Toucan 的 strict Success@0.9 是对 $S_{\text{process}}$ 阈值化的结果，不是独立的任务结果标签（作者在 §6 明说）。为缓解，作者补了执行型奖励实验（Table 25）与 judge-free 的 BFCL / τ² 评测。

**哪些问题得到改善**：跨段污染（定义上）、域内 Success/Process、τ²-Bench 的 Overall、工具轮数（轨迹更短）。**哪些仍未解决**：多轮 BFCL（3B/8B 仍低于 SFT）、3B 与部分域的收益不显著、工具段内的时间轴 credit（单一 $\hat{A}^{\mathrm{tool}}$ 无法区分 Action 1 正确而 Action 2 失败）、$\hat{A}^{\mathrm{sum}}$ 的分组偏差、inline code generation 之类的无清晰边界场景、更大规模（只到 8B）与真实 API 对比（§6）。

**结论适用边界（审稿人判断）**：只适用于"轨迹以最终答复块收尾、工具调用边界清晰、奖励由 gold 匹配 + judge 构成、工具环境由 SGLS 模拟"的范围；超出后需重新验证。

## 5. 最容易受到审稿人质疑的地方

#### 质疑一：性能增益中"切断 summary→tool 通路"贡献多少，没有被干净地分离出来

- **原文依据**：§4.3 自述 w/o SLCA "changes both normalization and token support … measures the combined estimator change rather than either operation in isolation"；Table 21/22 的支持控制给出的 $S\!\to\!T$ 关闭主效应在 τ² 上只有 5.51 pp，远小于 w/o SLCA 与 SLCA 的 9.15 pp 差距，且交互项 3.13 pp 不小；作者自己声明这些"not presented as a routing-only causal estimate"；App. D.8 显示统一估计器只调权重就能把 τ² 从 31.87 提到 35.24。
- **为什么重要**：这是论文的核心因果主张（把 Global Signal Conflation 称为 "the dominant cross-segment credit misattribution channel"，摘要语），决定创新性叙事是否成立。
- **当前能够得出的判断**：证据不足。隔离性（式 (4)）是定义上成立的；但"隔离带来多少收益"与"归一化方式/奖励权重带来多少"混在一起，支持控制是目前最干净的估计，却只在 7B 与 τ² 上给出 5.51 pp。
- **如何验证或补强**：在 3B/8B 上补做支持控制；把统一估计器与 SLCA 的差别拆成（i）归一化分组、（ii）token 支持两个因子并报告完整 2×2（论文已有设计，但只做了一格尺度）；报告两段原始奖励的组标准差以检验定理 A.4 的条件是否常见。
- **严重程度**：**主要问题**。

#### 质疑二：与 ToolPO / RLTR 的比较协议不公平，摘要的表述放大了结论

- **原文依据**：Table 1 中 ToolPO 在 7B 上 Toucan 20.00% 是其 LLM-judge outcome 协议下的结果，App. C.4 自述这是 "protocol-sensitivity diagnostic"，换成 reference-rule 后回到 77.35%；3B/8B 的 ToolPO 行只有 LLM-judge 协议（"no reference-rule runs are available for those scales"）；8B τ² 上 ToolPO 44.32 与 SLCA 44.69 相差 0.37 pp，且 Retail 域 ToolPO 更高；摘要写 "outperforms standard GRPO, ToolPO, and RLTR by +2.53 pp / +1.36 pp / +9.15 pp"，而这三个数字实际是与 matched GRPO 的差。
- **为什么重要**：影响"超过最强基线"这一主张与读者印象；不同协议的基线对比会误导后续研究者。
- **当前能够得出的判断**：**结论被夸大**。对 GRPO 的比较受控且可信；对 ToolPO/RLTR 的比较受协议与初始化影响，8B 上相对 ToolPO 的优势在统计上不成立。
- **如何验证或补强**：为 3B/8B 补 reference-rule ToolPO；给出同一预算、同一初始化、同一奖励定义下的三方对比；摘要改写为"相对 matched GRPO 的差距"。
- **严重程度**：**主要问题**。

#### 质疑三：失败模式的诊断证据以代表性单次运行与单例为主，缺少统计稳定性

- **原文依据**：Figure 2(a)/(b) 自述为 "representative single runs"；Figure 5 同为 representative single-run traces；工具/总结梯度余弦相似度只在 3B 上测量（App. B）；Figure 9 是单例（App. D.4）；主表三次 run 但没有显著性检验，3B 的 τ² +1.09 pp（std 0.0091 与 0.0257）与 BFCL +0.40 pp 接近噪声量级；"performative execution" 用 "compatible with" 表述，属解释而非验证。
- **为什么重要**：决定读者对"问题有多严重""机制是否被证实"的信任度，也决定小模型档位结论是否成立。
- **当前能够得出的判断**：现象存在但强度未定；3B 档结论**证据不足**；训练曲线层面的论证属于关联性证据。
- **如何验证或补强**：给训练曲线加多次 run 的均值与误差带；在 7B/8B 补测余弦相似度；对关键 gap 做配对检验或增加 run 数；对 performative execution 做受控实验（例如固定轨迹长度后比较成功率）。
- **严重程度**：**主要问题**。

#### 质疑四：奖励与模拟器的耦合使域内成绩存在"共同适应"风险

- **原文依据**：Toucan 评测的 Tool Simulator 与训练同为 SGLS（Table 12）；$S_{\text{process}}$ 依赖 gold 轨迹匹配、$S_{\text{par}}$ 为硬 0/1、$S_{\mathrm{summary}}$ 是 LLM judge（App. A.4/A.5）；作者自述 strict Success@0.9 是对 $S_{\text{process}}$ 的阈值化而非独立任务结果（§6）。缓解实验：execution-based $R_{\text{succ}}$（Table 25，+2.92/+1.33/+4.64 pp）、替换 mocker 为 GPT-OSS-120B（Table 8，+2.83/+1.24/+7.16 pp）、BFCL 与 τ² 使用 judge-free 指标。
- **为什么重要**：决定结论是"通用能力提升"还是"在该奖励/模拟器体系内的适配"。
- **当前能够得出的判断**：风险**被部分缓解**（跨域评测与奖励替换后增益仍为正），但域内指标与训练信号同源这一点无法排除；论文未报告独立任务结果标签。
- **如何验证或补强**：在真实 API 或第三方模拟器上端到端复评；用与训练无关的 judge/规则复评 Toucan；报告 gold 方案不唯一样本上的表现。
- **严重程度**：**次要问题**（对 OOD 结论影响较小）。

#### 质疑五：方法假设与"通用性"表述之间存在落差

- **原文依据**：§6 Limitations 自述——分段假设在 inline code generation 等无清晰边界场景失效、需学习式分段；工具段内时间轴 credit 未解决（单一 $\hat{A}^{\mathrm{tool}}$ 标量）；$\hat{A}^{\mathrm{sum}}$ 保留 grouping bias；规模只到 8B 且全程用 SGLS；与 VinePPO/GiGPO/SPO 的组合未做实验。
- **为什么重要**：影响读者对"可用于任意 tool-calling RL"的预期（标题与摘要的措辞比 Limitations 更宽）。
- **当前能够得出的判断**：作者已如实披露，问题主要在表述层面；方法边界清楚，属"作者没有解决"而非"结论错误"。
- **如何验证或补强**：补 inline-code / 学习式分段的实验；做与时间轴方法的组合实验以支持"正交"主张。
- **严重程度**：**次要问题**。

## 6. 审稿式总评

> 作者发现工具调用轨迹天然分成"执行段 / 总结段"两段非同质输出，而 GRPO 类算法把单一标量 advantage 广播给所有 token，形成跨段信用错配（总结奖励污染工具 token 的更新，冲突区间甚至方向反转），因此提出 SLCA-GRPO——用掩码自动分段、HierR 分段回报、分段独立归一化与逐 token 路由在 backward 之前切断 summary→tool 通路，并配 SGLS 提供可扩展的 schema 约束探索。实验在三个尺度、三个基准、三次运行与 matched 对照的条件下表明：相对统一 GRPO 的均值一致为正（7B 上 +2.53 / +1.36 / +9.15 pp），轨迹更短、多轮协作鲁棒性提升明显；其中"跨域增益稳健、奖励与 mocker 替换后仍成立"这一侧证据较强，但"隔离本身贡献多少"（只有 7B 支持控制的 5.51 pp）、3B 档的统计可分性、以及 8B 上相对 ToolPO 的优势仍缺少充分支持。本文最有价值的部分是把输出异构性显式当作 credit assignment 的结构变量，并给出一个零额外 rollout、不拆模型、不改推理的实现；最大的审稿风险是核心因果主张与消融证据之间的落差，以及摘要对多基线比较的表述。

**六维评分（每项依据见前文对应小节）：**

- **问题定义清晰度**：强（§1 与 §3.1 把问题限定在"广播统一 advantage"这一可操作的结构性缺陷上，式 (1)–(8) 形式化完整，Limitations 也如实收边）
- **创新性证据**：中（结构轴路由是新提法但实现为"归一化分组 + 路由"的组合；SGLS/HierR 属已有思路的工程组合；"正交可组合"无实验，见 §2）
- **方法可信度**：中（算法与超参披露充分、边角处理克制；但理论是条件性局部分析，机制归因的隔离实验不完整，见 §4.3、质疑一）
- **实验支持力度**：中（三尺度 × 三基准 × 三次 run 且方向一致；但无显著性检验、训练诊断为单次 run、基线协议不齐、部分域反向，见 §4.2、质疑二/三）
- **可复现性**：中（超参、评测协议、奖励与提示词齐备，代码与数据链接在归档日可达；但依赖两个大模型 endpoint 与自研评测系统，本次未检查代码内容，故不能评为强）
- **综合阅读价值**：高（问题具体、写作清楚、附录把负结果与协议敏感性都摊开，对做 agentic RL 与工具调用的读者直接可用；核心机制一页可懂，细节可查）
