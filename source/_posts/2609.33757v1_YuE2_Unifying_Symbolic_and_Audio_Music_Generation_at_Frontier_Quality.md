## 0. 一句话结论

论文把"先作曲、后演唱"做成一个模型内的显式生成流程：一个 3.58B 的 AR–NAR Mixture-of-Transformers 先生成可读的 ABC 乐谱（旋律+和弦），再生成 25 Hz 语义 token 与 25 Hz 声学 latent，最后由独立训练的 48 kHz 立体声 VAE 解码成整首歌；配套的 MERT2 语义 tokenizer 与 SheetSage2 转写器负责从普通录音反向构造训练监督。在作者自建的 192 条 WildSongBench 提示上，专家成对听测支持"写谱优于不写谱"（总质量 49.3% vs 34.6%）和"统一 MoT 优于同表示的 LM+DiT"（53.4% vs 35.6%），score–audio 一致性与可控编辑实验支持"谱面决策确实在音频中被实现"；但"前沿质量"的结论建立在作者自有基准、多处自研评测组件与 best-of-8 预算之上——对六家专有系统的总体偏好平均只有 48.4%（不显著），显著优势集中在音频质量（58.9%），对 Suno v6 明显落后。

## 1. 论文具体想解决什么问题？

**任务与背景。** 论文要解决的是"整首歌生成"里一个结构性割裂：符号（乐谱/MIDI）模型把旋律、和声、节奏、曲式写得可读可改，但停在记谱层面、不产出成品录音；音频生成模型直接产出成品歌，但作曲过程隐式——没有可以检查、修改的作曲中间物（§1、§7）。作者把音乐信息的层级组织成"渐进式音乐承诺（progressive musical commitment）"（Figure 2）：文本/歌词表达意图；乐谱承诺旋律、和声、节奏与曲式；演奏/音频再解决时值、发音、音色、表情与制作。核心问题陈述为：能否用单一模型在这条层级上走通，让作曲既可读可编辑、又不牺牲成品歌质量。

**现有方法怎么处理。** 音频路线（MusicLM、MusicGen、YuE、SongBloom、LeVo 2、DiffRhythm 2、HeartMuLa、Muse 等）在音频表征里隐式建模结构；符号路线（Music Transformer、SymPAC、MIDI-DDSP、BACH）生成谱面但把"唱出来"留给外部系统；"规划"路线已有先例，但粒度不足——MusiCoT 先生成量化音频–文本嵌入，ACE-Step 1.5 规划 tempo/key/时长/结构，二者都不产出"同时指定旋律、和声、节奏与曲式的可读记谱"；Seed-Music 有铅谱到歌的流水线，但闭源且实现细节有限（§7）。相对地，Qwen-Music 用参考录音的相对音高轮廓做翻唱条件，SongEcho 需要专门训练旋律条件模块（§7）。

**具体在哪些条件下不好。** 论文给出的"不好"是能力性的、不是测量出来的：(a) 想改旋律/和声/曲式时，音频模型没有可编辑的中间表示，只能靠改提示重采样；(b) 符号模型需要外部合成流程才能听成品，人声与制作的细节不在模型内；(c) 现有规划粒度不构成"可读的完整铅谱"，人和外部 agent 都不能直接读改。

**新的观察/瓶颈。** 本文真正的工程观察是：训练这种"层级式"生成器缺的是**对齐监督**——普通音乐语料没有对齐的音符、和弦、节拍与段落标注（§1、§3 开头），因此必须先从录音反向构造符号（SheetSage2）与语义（MERT2）目标。另一处观察是"乐谱可作为生成接口"：同一个 checkpoint 能以三种方式拿到 $s$（生成、用户改写、外部转写），从而统一创建、编辑与翻唱（§2.5）。

**证据与因果。** "加入显式作曲能提升成品歌质量"不是从现象测量推出的，而是通过同 checkpoint 的匹配对照来检验（§4.2）；"缺少显式作曲是质量瓶颈"这一更强因果论断论文并未证明——它证明的是专家在盲测中更偏好有 planning 的版本。这是本报告要明确区分的：**论文观察并验证的是"偏好差异"，不是"隐式作曲导致质量上限"的因果机制**。

**核心假设。** 用式 (2) 的分解 $p_\theta(s,c,z\mid y)=p_{\theta,\mathrm{AR}}(s,c\mid y)\,p_{\theta,\mathrm{NAR}}(z\mid y,s,c)$ 可以把可读作曲、语义细节与声学细节拆开又联合训练；同一模型既能出前沿质量的成品歌，又能让 $s$ 成为被人和 agent 修改的稳定接口（§2.1、Table 16）。

## 2. 创新点是什么？

**一段话概括。** 实质技术增量是把"可读铅谱"提升为生成过程的一等状态：模型先写 ABC 谱、再写语义 token、最后用流匹配生成声学 latent，三者在一个 AR–NAR MoT 骨干里联合训练（四个训练任务混合，使"有/无 planning"的对照能在同 checkpoint 内完成）；为了让这条链条能从普通录音直接训练，论文配套了 MERT2（多视图目标自监督 + 375 bit/s 语义 tokenizer）与 SheetSage2（单模型联合铅谱转写），并把同一套条件接口复用到编辑、翻唱与 agentic 编辑。单个组件多为已有思想的组合或工程改进，"显式作曲状态 + 匹配消融 + 接口复用"的整体编排是新的。

**创新点 1：符号作曲作为生成状态（§2.1–§2.2，式 (2)(3)）。** 新增机制：自回归流按 $[\texttt{ABC\_START}],s,[\texttt{ABC\_END}],[\texttt{MUSIC\_START}],c,[\texttt{MUSIC\_END}]$ 的顺序生成（式 3）；ABC 与普通文本共享 tokenizer，语义码占独立区间，类型输出掩码阻止两段互相越界；ABC 采样不加语法约束。与最接近工作（MusiCoT 的量化嵌入规划、ACE-Step 1.5 的属性规划）的具体差异是：规划物是"人类与 LLM 都能直接读改的完整铅谱"。这属于已有表示（ABC、BPE）上的**新研究思想 + 新编排**。对应问题：让作曲可读可编辑。证据：§4.2 同 checkpoint 对照（有 planning 总质量 49.3% vs 34.6%，$p=0.0070$）；§5.1 显示谱面决策在音频中确实被实现（旋律序列相似度 0.9464 vs 失配 0.2160）。移除后变化即"无 planning"任务：总质量与音乐性偏好下降。

**创新点 2：AR–NAR Mixture-of-Transformers 单骨干（§2.3，式 (4)）。** 28 层里每层配有独立的 AR/NAR 归一化、QKV/输出投影与 MLP 专家，两流共享一次注意力计算与位置方案；混合 mask 规定：离散位置对声学位置封锁、声学位置可看全部文本/谱/语义并可全序列双向互看。与最接近工作（SongBloom、LeVo 2、HeartMuLa、Qwen-Music 等的"LM + 独立 DiT"两模型）差异是：把两阶段放进同一骨干。定位：已有思想（MoT, Deng et al. 2025）在新任务上的组合与实现。证据：§4.3 受控对照中专家偏好 MoT（总质量 53.4% vs 35.6%，$p=0.0084$；架构两条件平均 55.8%，Table 22）。**局限**：Table 21 显示无 planning 条件下 MoT 优势不显著（52.6%，$p=0.3456$），即该增益并非无条件成立。

**创新点 3：从录音构造监督的两件套（§3）。**
- **MERT2**（§3.1，Figure 4）：多视图目标合成——冻结 MuQ（layer 7，1,024 维）与 Qwen2-Audio-Instruct（layer 32，1,280 维）两路特征拼接后经融合网络（2304→2048→1024）与 4 级残差向量量化（每级 16,384 码）生成"同时受两个编码器约束"的离散目标，再让新的双向 ConvNeXt–Conformer（24 层、宽 1,024）做掩码预测预训练；随后一个基础模型分叉为全歌双向分支（2-FS，服务 SheetSage2）与因果分支（服务 tokenizer）。与 MERT/MuQ/MusicFM 的差异：目标不是复制某个编码器，而是双视图共享瓶颈；并显式服务下游自回归生成。证据：MARBLE 九个任务 14/15 指标第一（MERT2-30s，Table 6）。
- **MERT2 tokenizer**（§3.3，Figure 6）：因果注意力适配 → 全歌 SFT（歌词 CTC + mel/chroma 重建） → 在第 13/14 层 Conformer 之间插入 32 维、32,768 码的 CVQ（在线锚点更新，验证集利用率 >99%），量化状态再经 14–23 层与三个头监督（"grounding before compression"）。产出 25 Hz、375 bit/s 的语义流。证据：Table 7 中 6 项探针 5 项领先（beat F1 86.38 vs LeVo 2 79.72、EnCodec 76.50），post-VQ 保留 pre-VQ 探针分数的 78.3–98.3%；例外是调性（52.20 < LeVo 2 的 61.23）。
- **SheetSage2**（§3.2，Figure 5）：先训非自回归 Prober（MERT2 + LoRA + 任务头 + CRF 结构化解码，监督混合人工标注数据集与 MIDI 渲染音频），再用它给 441,094 条录音（28,434 小时）生成统一词表与时间约定的标签；SheetSage2-AR 用冻结 MERT2-FS 主干 + 可训练 LoRA + 6 层 RoFormer 解码器，语法约束自回归输出单一时间序事件序列（时间戳量化 10 ms），再由确定性 builder 转成 ABC。与 SheetSage1/Beat This!/ChordFormer/SongFormer 的差异：单模型同时输出旋律、和弦、调、拍/重拍/拍号与结构。证据：12/15 基准–指标对第一（Table 8）；RWC-Pop 人声旋律 F1 从 62.71 升到 82.51。

**创新点 4：乐谱作为生成接口（§2.5、§5、Table 16）。** 同一 checkpoint 通过"$s$ 从哪来"区分三种操作：Create 由模型生成 $s$；Edit 把用户改写的 $\tilde{s}$ 作为固定前缀重新生成下游 $c,z$；Cover 用外部 SheetSage2 从参考录音转写 $\hat{s}$ 再以新风格渲染。**零样本翻唱无需原唱–翻唱配对训练**（§5.3，App. C "Cover supervision" 明确训练只用单条录音的对齐输入–目标）；另有 agentic editing 案例：外部 LLM agent 把用户反馈翻成 ABC/风格/歌词修改，再由 YuE2 渲染（§5.4）。定位：接口复用 + 新能力展示 + 评估设计，属工程实现改进。

**创新点 5（方法学）：四任务混合训练（§2.4，Table 14）。** 同一模型均衡混训 {完整生成、无 planning、无语义 token、直接音频} 四种任务，使"有/无 planning"与"有/无语义前缀"都能在同一个 checkpoint 下做匹配对照（无需重训）。这是 §4.2/§4.3 因果对照成立的前提条件，属于被低估但关键的实验设计贡献。

**不算创新的部分。** 3.58B 参数规模本身；ABC、BPE、RVQ、CVQ-VAE、RoFormer、流匹配、LoRA 均为既有组件；"首次"类主张仅与 related work 列出的方法比较，Seed-Music 等闭源系统的实现细节无法核对，因此**根据本文的 related work 与实验对比，只能确认作者声称的差异；是否构成首次提出需要更完整的文献检索**。

## 3. 作者如何解决？

**直觉说明。** 一首成品歌是稠密声学对象，但不必一次做完全部决定。先让模型在"低维、可读、可改"的空间里把音乐骨架定下来（哪些音、什么和弦、什么调与速度、什么曲式），再用稠密表示补足谱面写不出的表演细节（语义 token 携带演奏信息，声学 latent 携带音色与制作），最后解码成波形。这样做的直接好处是：一个中间状态同时供优化（早期承诺改善成品）、供检查（人和 LLM 都能读）、供干预（改谱=改歌）。

**运行流程（Figure 3，见 fig1）。**

1. 输入 $y$ = 文本条件（风格描述）+ 歌词。自回归（因果）流先按式 (3) 生成 ABC 乐谱 $s$：头部声明 tempo/meter/key，小节线与段落标签组织时间与曲式，和弦符号给和声，声部给旋律；ABC 不加语法约束、与文本共享 tokenizer。
2. 同一自回归流继续生成 25 Hz 语义 token $c$（MERT2 tokenizer 的码字，每 40 ms 一个 32,768 选一的 ID，375 bit/s）。
3. 声学流（NAR，双向）以 $y,s,c$ 为条件，对 25 Hz、64 维 latent $z$ 用条件流匹配预测速度场；论文给出 $z_t=(1-t)z_0+t\epsilon$，损失为 $\mathcal{L}_{\mathrm{FM}}=\frac{1}{64|\mathcal{Z}|}\sum_{i\in\mathcal{Z}}\left\|v_\theta(z_t,t,y,s,c)_i-(\epsilon_i-z_{0,i})\right\|_2^2$（式 6）。混合 mask 保证离散预测看不到声学目标、而声学帧能看全计划并互相双向通信（式 4）。
4. 独立训练的 48 kHz 立体声 VAE（Oobleck，按 Stable Audio Open 配方，1,920× 压缩、64 维瓶颈、25 Hz）解码成歌（§3.4）。
5. 三种入口共用步骤 2–4：Create 生成 $s$；Edit 把修改后的 $\tilde{s}$ 作为固定前缀；Cover 用 SheetSage2 转写参考录音得到 $\hat{s}$（§2.5、Table 16）。

**训练。** 联合目标 $\mathcal{L}=0.25\,\mathcal{L}_{\mathrm{AR}}+\mathcal{L}_{\mathrm{FM}}$（式 7），其中 $\mathcal{L}_{\mathrm{AR}}$ 只在生成段 token 与其结束标记上计算（式 5，损失权重 1:4）。三阶段：AR 预训练 60,000 步（上下文 16,384）→ 联合 AR–NAR 训练 40,000 步（24,576）→ 退火 6,000 步（24,576）；NAR 专家从 AR 专家初始化；64 张 H800、全局 batch 256、bf16、梯度裁剪 1.0（App. C，Table 15）。数据约 346,000 小时音乐（以 CC0 与合成数据为主，多数合成数据由 Tokenwave.AI 授权），整首歌打包进 24,576 位置、不跨歌切分；文本与歌词条件可分别或同时 dropout 以支持 classifier-free guidance（§2.4）。模型主配置：约 3.58B 参数、28 层、隐宽 2,048、FFN 6,144、16 个 query 头 / 8 个 KV 组 / 头宽 128、文本词表 151,643、语义词表 32,768、RMSNorm + SwiGLU（Table 13）。

**监督从哪来（§3 开头，式 8）。** 对每条训练录音 $x$：$x\xrightarrow{\text{SheetSage2}}s$，$x\xrightarrow{\mathrm{MERT2\ tokenizer}}c$，$x\xrightarrow{\mathrm{VAE}}z$，三个目标构造器离线冻结运行。这是"无需对齐乐谱就能训练"的关键：符号监督靠 SheetSage2（其自身又靠 Prober 生成的标签训练），语义监督靠 MERT2 tokenizer，声学监督靠 VAE 编码。

**模型决定 vs 固定流程。** 模型决定 $s$、$c$、$z$ 的采样（ABC 无语法约束）；固定流程包括：ABC 的序列化/解析约定、SheetSage2 的事件词表与语法约束解码、时间量化（10 ms）、VAE 编解码、以及 Edit/Cover 的"固定前缀"接口。**教学简化示例**（非论文实验）：若用户想给副歌换和弦，Edit 流程只需重写 $s$ 中副歌的和弦符号并把整份 $\tilde{s}$ 作为前缀前传，模型重新采样 $c,z$——论文 §5.2 的真实实验正是这种"局部改、整首重渲染"的设置。

**推理与开销。** AR 采样 temperature 1.0、top-$p$ 0.95、top-$k$ 100、50 token 窗口内重复惩罚 1.2；声学生成 32 步中点 ODE；声学 token 预算为源时长（秒）的 25 倍、上限 9,000，可提前终止（App. D.3）。论文未报告推理时延、显存占用与训练 wall-clock/GPU-hours（**论文未报告**），只给出 64×H800 与更新步数这类可换算但未换算的信息。

## 4. 解决得怎么样？

#### 4.1 实验设置

- **评测基准**：WildSongBench（WSB）192 条提示，覆盖 15 个风格桶，源语言 94 条中文 + 98 条英文，保留自然代码切换/多语请求；提示与歌词以各模型的原生接口输入（§4.1）。WSB 来自作者所属组织发布的 HF 数据集（脚注 4 指向 m-a-p/WildSongBench），论文没有为本基准引用第三方来源文献。
- **指标（9 项）**：SongBench（7 维，含 Musicality）与 SongEval（5 维）的 Musicality 与 Global Avg、AudioBox Aesthetics 制作质量 PQ（10 秒窗、长度加权）、MuQ-MuLan 与 AllMusicCaps 的音频–文本对齐（用不含歌词的"标准化风格描述"）、Qwen3-Omni 提示对齐 Q3O（0–5，按维度重要性加权，式 9）、音素错误率 PER（中文用带调拼音、英文用音素）。
- **基线**：公开 8 个（YuE1、SongBloom、LeVo 2、ACE-Step 1.5、HeartMuLa、DiffRhythm 2、Muse、MiniMax Music 3，其中 MM Music 3 用官方 caption rewriter）；专有 7 个（Suno v4.5/v5/v5.5/v6/v6 Wild、MiniMax Music 2.6、Mureka 9）。
- **候选预算**：标准比较每系统 2 条候选、取 PER 更低者；YuE2 与公开基线、Suno v6 系列的 PER 取 4 次 ASR 转录的最低值；YuE2 best-of-8（Bo8）从 8 条中按 SongBench Musicality → Q3O → PER 择优（§4.1、App. A.3）。SongBloom 是唯一输入例外：其公开接口不能吃文本风格提示，只能对所有条目用同一段留出的 10 秒音频。
- **人评**：Arena 导出 351 个参与者（289 个通过 X/GitHub/Hugging Face 招募的在线场次 + 62 位音乐学院背景或音频 AI 研究的付费标注者），4,439 条保留配对评价；正式报告用其中 3,602 条专家评价（2,545 前沿对比 / 636 planning 对比 / 421 架构对比），覆盖 192 条提示；隐藏系统身份、随机 A/B、每首至少听 30 秒、每批 32 题含 5 个隐藏一致性检查（≥4 正确才通过）（App. D.4）。
- **专项实验**：§4.2 planning 消融（同 checkpoint、同提示/歌词/预算/解码器；212 条保留专家评价，211 条有效判断；旋律/和弦另由 4 位听者各评 50 对、每对各 2 评，共 200 个判断/指标）；§4.3 架构对照（LM 1.7B + DiT 1.7B = 3.4B vs MoT 3.58B，训练数据量匹配，LM 与 MoT 的 AR 组件同 token 预算/batch/更新数，DiT 训 900,000 步，共享同一语义 tokenizer、VAE 与 planning；209 条保留评价）；§5.1 score–audio 一致性（384 份生成谱、768 条录音，含 Mismatched 与 Without score 两个控制）；§5.2 五类编辑（3,844 条录音，全部保留）；§5.3 翻唱（948 首 SHS100K 未见作品，每方法 3,792 条输出，无候选筛选）；§6 三个探针评测（MARBLE、375 bit/s 表示探针、铅谱转写）。

#### 4.2 关键结果

**自动指标（Table 1–2；标准 2 候选口径）。** YuE2 在公开系统中拿下 SongBench Musicality 5.9075 与 Global Avg 6.7316（次高的 LeVo 2 为 5.4590 / 6.3247）；Bo8 达 6.2666 / 6.9632，为全部评测系统（含专有）中的最高观测均值。但同一张表显示：专有系统里 Mureka 9（6.0488 / 6.9377）与 Suno v5（5.9918 / 6.8721）在 SongBench Global Avg 上高于 YuE2 的 2 候选版本——即"超过公开基线"成立、"超过所有专有系统"只在 Bo8 口径下成立。AudioBox PQ：YuE2 / Bo8 为 8.2598 / 8.2714，超过所有专有系统（最高专有 Suno v4.5 为 8.2541），且 PQ 不参与候选选择。Q3O：4.6819 / 4.7009，全场最高。MuLan 0.5068 / AMCaps 0.4054，为公开系统最高，但低于 Suno v5（0.5428 / 0.4353）。PER 0.0844，优于多数基线，但不如 MiniMax Music 3（0.0627）与 ACE-Step 1.5（0.0746）。SongEval 上 Bo8 的 Musicality/Avg（4.2506 / 4.2960）在公开系统中排第二，落后 HeartMuLa（4.5329 / 4.5519）——作者披露 HeartMuLa 用 SongEval 与 AudioBox 参与后训练筛选与 DPO（Table 2 脚注、App. A.3）。复合指数（Figure 1、App. A.4）：YuE2 / Bo8 质量指数 82.82 / 88.34（Mureka 9 以 90 居首），对齐指数 84.59 / 83.89（Suno v5 以 90 居首）；经验 Pareto 前沿 = YuE2(Bo8)、Suno v5、Mureka 9。权重敏感性：在 SongBench 权重 0.6–0.8 区间内 YuE2 均超过所有公开基线；按 2:1 加权时 Musicality 复合最高是 YuE2 (Bo8)，而 Global Avg 复合最高是 Mureka 9（App. A.4）。

**专家听测（Figure 7/12/13，Table 21–22，tie-adjusted 估计 + 双向 CR1 聚类区间）。** Bo8 对 Suno v4.5 总质量 63.4%（CI 57.7–69.1，$p=2.26\times10^{-5}$）；对 Suno v5 为 50.2%（$p=0.9402$，统计上不可分）；对 Mureka 9 为 49.0%（$p=0.8316$）；对 Suno v5.5 为 44.2%（$p=0.0518$）；对 Suno v6 为 36.1%（$p=0.0012$，Suno v6 显著更受偏好）；对 Suno v6 Wild 为 47.5%（$p=0.4883$）。六家平均（Table 22）：总质量 48.4%（$p=0.3813$，不显著）、音乐性 46.7%（$p=0.0484$，低于 50%）、音频质量 58.9%（CI 55.6–62.2，$p=1.70\times10^{-6}$）、文本对齐 47.6%（$p=0.1111$）。也就是说**"与专有系统竞争"的证据主要落在音频质量维度**，总体与音乐性对六家平均并不占优。2 候选口径的平均也类似：总质量 48.0%、音频质量 56.6%（$p=0.0105$）、文本对齐 45.7%（$p=0.0110$，显著低于均势）。

**Planning 消融（§4.2，Figure 8/14）。** 同 checkpoint、同提示/歌词/预算/解码器下，专家偏好有 melody+chord planning 的版本：总质量 49.3% vs 34.6%（其余为平局；tie-adjusted 57.3%，CI 52.1–62.6，$p=0.0070$），音乐性 45.0% vs 29.4%（$p=0.0141$），旋律 44.0% vs 29.5%，和弦 39.0% vs 21.0%（后两项各 200 个判断）。两个细节值得注意：(a) 只有旋律的 planning 对无 planning 的总质量优势为 53.7%（$p=0.2064$）**不显著**，增益主要来自加入和弦；(b) planning 对文本对齐的优势 55.5%（$p=0.0732$）不显著。

**架构消融（§4.3，Figure 10/14）。** 在两侧都用 melody-and-chord planning 时，专家偏好统一 MoT：总质量 53.4% vs 35.6%（$p=0.0084$），音频质量 48.5% vs 29.6%（$p=3.06\times10^{-4}$），人声 59.4%（$p=2.69\times10^{-5}$）、伴奏 56.7%（$p=0.0097$）；文本对齐几乎持平（34.0% vs 33.5%）。两条件平均（Table 22）：总质量 55.8%（$p=0.0050$）、音乐性 56.1%、音频质量 56.9%、人声 57.4%。**但 Table 21 中"无 planning 条件下 MoT vs LM+DiT"总质量为 52.6%（$p=0.3456$）不显著**——架构优势并非在所有条件下成立，正文未强调这一点。

**Score–audio 一致性（Table 3，§5.1）。** 对应录音的旋律/和弦序列相似度 0.9464 / 0.9246，失配录音（同提示同歌词、用另一份谱生成）仅 0.2160 / 0.2473，无谱条件 0.2055 / 0.1897；精确调性一致 0.9307（加权 0.9515）、tempo 8% 内比例 0.9869（对数误差 0.0142）、节奏起音区间 F1 0.9396、曲式内容 0.7799、段落边界 F1 0.8724。允许一个全局移调后对应音频仍为 0.9465 / 0.9245（控制 0.3152 / 0.4658），说明差距不是全局调性/音区造成的。两候选中把每份谱与正确录音配对的任务在 188 个可评提示上 100% 正确、无平局（App. D.1）。

**可控编辑（Table 4/19，§5.2）。** 局部编辑达成率：旋律音高准确率 84.17%、和弦一致 79.54%、节奏相对起音 73.43%；全局编辑：调性加权分 90.58/100、tempo Acc2 95.68%（Acc1 75.92%）。同时未编辑内容的保留度在 90.16–94.34%。SongBench 质量 6.64–6.73，与对应的未编辑对照（6.70 / 6.73）接近；PER 0.179–0.191 与未编辑 0.184 无系统性差异。节奏编辑受资格限制（只有 107 份谱可构造相邻时值交换），覆盖率 80.36%，条件达成率 91.37%；MIDI 合成对照的达成率为 94.08%，而未编辑/反向移动对照为 0（Table 18）。

**零样本翻唱（Table 5，§5.3）。** 全谱条件下 YuE2 在 8 项工作身份检索指标上全部领先两个翻唱系统：CLEWS mAP / Hit@1 = 0.647 / 71.3 vs SongEcho 0.419 / 48.4、ACE-Step 1.5 0.024 / 2.4；Discogs-VINet mAP / Hit@1 = 0.288 / 37.5 vs SongEcho 0.122 / 16.6。内部消融给出清晰的权衡：去掉和弦后 mAP 降至 0.598 / 0.179，完全去谱降至 0.006 / 0.004；而风格对齐与质量反向上升（Musicality 5.104 → 5.490 → 5.691，PQ 8.044 → 8.117 → 8.186，MuLan 0.382 → 0.417 → 0.474，Q3O 4.273 → 4.482 → 4.837）。补充指标 AllMusicCaps 上全谱 YuE2（0.302）低于 SongEcho（0.349）。

**MERT2 / tokenizer / SheetSage2（§6）。** MERT2-30s 在 MARBLE 九任务 15 项指标中 14 项超过全部外部基线（如 MTT ROC 91.91 vs PupuJEPA-Large 91.7、GTZAN 节拍 F1 91.72 vs 86.9、EmoMusic 效价 $R^2$ 80.01 vs 78.5）；MERT2-FS 为 13/15，且 15 项全部落在 MERT2-30s 的 1.87 分以内（Table 6）。375 bit/s tokenizer 在 6 项冻结探针中 5 项领先（beat F1 86.38 vs LeVo 2 79.72、EnCodec 76.50；调性一项落后 LeVo 2 的 61.23）。SheetSage2-AR 在 15 个基准–指标对中 12 个第一；RWC-Pop 人声旋律 F1 82.51（比 SheetSage1 高 19.80 分）、Rock Corpus 67.08（+17.89）、JAAH 和弦 64.50（比 ChordFormer 高 5.06 分）；未占优处包括 GTZAN 节拍（86.27 < Beat This! 89.01）、结构边界 F1@0.5s（67.96 < SongFormer 70.63）、Chords1217 和弦（83.81，略低于 ChordFormer 的 83.94 与 madmom 的 83.52）。仅用 Prober 生成标签训练的 SheetSage2-AR，在相同协议下反超标签生成器 10/15 项（Table 11）。

**提升小/未提升/负面结果的集中处：** SongEval 落后 HeartMuLa；PER 落后两个系统（Bo8 的 PER 0.0979 还比 2 候选的 0.0844 更差，说明选择规则牺牲了歌词准确率）；短窗结构边界与 GTZAN 节拍不及专用模型；调性探针不及 LeVo 2；对 Suno v6 总质量显著落后；翻唱全谱条件的风格对齐/质量分数低于放宽条件。**自动指标全部没有报告方差、置信区间或显著性检验**（人评有 CI），192 条提示的单次评测也没有重复采样报告（论文未报告）。

#### 4.3 机制证据

- §4.2/§4.3 提供的是**效果证据**（盲测偏好），本身不解释"为什么有效"。真正偏机制的是 §5.1 与 §5.3：前者用"对应 / 失配 / 无谱"三条件和全局移调鲁棒性证明音频确实实现了该谱的具体音乐内容（不是只实现了提示词），这是较强的机制证据；后者通过"去和弦 → 工作身份检索下降、风格对齐上升"给出和弦条件与工作身份之间的因果链证据（消融式证据）。
- 但"和声在音乐风格中起关键作用"这一解释，作者明确写为**与音乐专家的定性评估**（"Our qualitative assessment with music experts links this pattern to harmony's role in musical style"，§5.3、App. D.3），不是独立测量；此处应视为作者主张。
- **替代解释的排除程度**：planning 对照匹配了提示、歌词、候选预算与解码器，且无 planning 模式是训练时均衡采样的任务之一（Table 14），基本排除了"该分支欠训练"；但**没有做等算力/等生成长度匹配**——论文原文承认允许 planning 条件额外生成谱 token（§4.2）。因此"增益来自显式作曲这一机制"与"增益来自更多生成步数/更强条件"两种解释未被完全分离。架构对照匹配了训练数据量、参数规模与 AR 侧更新数，但没有论证"DiT 训 90 万步"与"AR 训相同更新数"在两种模态间是否等价。
- 评测链自身使用作者自研组件：§5 的转写由 SheetSage2 完成（并请专家校对），§5.1 的参考谱来自 YuE2 自己的生成物；§6 的探针按 MARBLE 协议但由作者实现。这些在 §4.3 记为机制证据的**采集侧依赖**，影响强度见 §5 质疑 2。

#### 4.4 成本与适用范围

- **训练**：64 张 H800、三阶段共 106,000 次更新（60k + 40k + 6k）、batch 256、bf16（App. C）；数据规模：MERT2 预训练 70 万小时、SheetSage2-AR 28.4 万小时（441,094 条录音）、YuE2 34.6 万小时。训练 wall-clock / GPU-hours / 能耗**论文未报告**。
- **推理**：**论文未报告**时延与显存；可确认的配置是 24,576 位置上下文、AR 采样参数、32 步中点 ODE、声学 token 预算 25×时长（上限 9,000）与 6 分钟生成上限（编辑实验有 32 条输出顶到上限）。3.58B 主模型之外还依赖 MERT2 tokenizer、VAE 与（Cover 模式）SheetSage2。
- **人工标注**：62 位付费专家 + 289 个在线场次；§5.1/§5.2 的转写由音乐专家校对修正；训练标注（歌词 ASR、段落、属性描述）由 Qwen3-ASR / SongFormer / Qwen3-Omni 自动完成（App. C）。
- **外部依赖**：MERT2 目标依赖冻结的 MuQ 与 Qwen2-Audio-Instruct；训练标注与 Q3O 评测都依赖 Qwen3-Omni；对比依赖 Suno/Mureka/MiniMax 等闭源服务与多个公开权重；合成数据由 Tokenwave.AI 授权（**不可公开复现**）。论文给出的开放资源包括 HF 上的 YuE2-3B、MERT2-30s、MERT2-FS、SheetSage2 检查点与 WSB 数据集（归档时未逐一核验可达性）。
- **适用范围与未解决问题**：证据覆盖 192 条 WSB 提示（中英为主、含多语）、SHS100K 的 948 首（947 首英文）翻唱、MARBLE 与若干转录基准；对实时交互、低资源语言、长于 6 分钟的作品、以及"任意流派"的外推均未验证。仍受困于：对最强专有系统（Suno v6）总体偏好落后、歌词准确率非最优、无等算力 planning 对照、训练语料不公开、评测链与作者自研组件耦合。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：头条数字 best-of-8 与所有基线口径不对等，且选择规则使用了被报告的指标本身

- **原文依据**：Abstract 与 §4.1 以 6.9632（Bo8）宣称"highest observed mean among all evaluated systems"；App. A.3 说明 Bo8 按 SongBench Musicality → Q3O → PER 选择，而 SongBench 与 Q3O 正是被报告的两个核心指标；所有基线只有 2 条候选（含专有系统只返回 2 首的接口限制）。旁证：Bo8 的 PER 反而由 0.0844 恶化到 0.0979（Table 1/2）。
- **为什么重要**：候选数不等的比较会产生选择偏差（在 8 条里按指标挑最好，等于给自己放宽了预算），"highest observed mean"的表述容易被读成同预算下的优势；这直接影响"前沿质量"这一主结论的强度与跨系统可比性。
- **当前能够得出的判断**：Bo8 数字不能与 2 候选基线直接类比；作者披露了选择规则、也注明 PQ 不参与选择（PQ 结果可视为独立旁证），但仍把 Bo8 与 2 候选系统并列于同一摘要句。按现有证据，公平可比的主结果是 2 候选口径（公开系统领先、专有系统未超）。
- **如何验证或补强**：给出所有系统的同预算全表；对 Bo8 增加留出式选择（在独立提示集上学选择规则再评测）或报告选择规则的敏感度；把"选择后指标"与"无选择平均"并排。
- **严重程度**：主要问题。

#### 质疑：评测链多处与作者自研组件同源，Q3O 存在"标注模型即评测模型"的闭环风险

- **原文依据**：WSB 由作者所属组织发布（脚注 4 指向 m-a-p/WildSongBench），正文没有为该基准引用第三方来源；训练标注方面 App. C 写明 Qwen3-Omni 负责 genre、instrumentation、mood、vocal 等属性标注，而 Q3O 的评分模型就是 Qwen3-Omni-30B-A3B-Instruct（App. A.1），App. D.3 甚至直说 "Qwen3-Omni supplies both target style annotations and Q3O judgments"；MuLan/AMCaps 用"标准化风格描述"作文本目标，其生成流程未在文中说明。§5 的 score–audio 与编辑评测用自家 SheetSage2 转写（再经专家非盲校对），App. D.1 也承认"指标是在本录音队列上开发的"。
- **为什么重要**：若条件文本与评测器同族，Q3O（YuE2 全场最高、且是 Bo8 的第二选择准则）可能反映"与标注分布对齐"而不是"与用户请求对齐"；用自研转写器给自家生成物打分，也可能高估谱–音频一致性。论文对 HeartMuLa 的评测器复用做了显式披露（Table 2 脚注），但对自身同类问题没有对等披露。
- **当前能够得出的判断**：Qwen3-Omni 同时用于训练标注与 Q3O 评分有原文依据，**其分数影响当前无法确认**；SheetSage2 作为评测分析器的循环性被失配/无谱对照部分缓解（两个控制点差距很大），但无法完全排除。
- **如何验证或补强**：用未参与数据构造的独立评测器与独立人工复核 Q3O 与谱–音频一致性；公开"标准化风格描述"的生成流程；在 WSB 之外的第三方提示集上重跑主表。
- **严重程度**：主要问题。

#### 质疑：planning 消融未做等算力匹配，"写谱更好"无法与"更多生成步数/更强条件"分离

- **原文依据**：§4.2 明确写 "This matches the candidate budget while allowing the planning condition to generate its additional score tokens"——即只匹配候选数与提示/歌词/解码器，未匹配总生成量；planning 条件多出一整段乐谱 token 的采样，并把谱面作为额外条件传给下游。
- **为什么重要**：论文的第二个卖点（式 1–2 的显式作曲假设）依赖该对照的因果解释力；若增益部分来自额外计算或"给了更长的条件"，"显式作曲"作为机制解释就被削弱，而正确的表述会变成"更强的条件+更多计算有效"。
- **当前能够得出的判断**：四任务均衡训练排除了"无 planning 分支欠训练"这一常见替代解释，§5.1 也独立证明谱面决策会落实到音频，机制链大体可信；但严格等算力对照缺失，属"证据不足"而非"结论错误"。
- **如何验证或补强**：给无 planning 条件同等的额外采样预算（多候选或更长生成长度）后再比对；增加"生成谱但不作为条件"与"给出随机谱作为条件"两个更强对照。
- **严重程度**：主要问题。

#### 质疑：MoT 优于 LM+DiT 的结论只在部分条件下显著，且两个系统的优化预算等价性未论证

- **原文依据**：Table 21 中"无 planning 的 YuE2 vs 无 planning 的 LM+DiT"总质量 52.6%（$p=0.3456$）、音频质量 54.3%（$p=0.0807）均不显著，只有"带 melody-and-chord planning"的总质量（58.9%，$p=0.0084$）与音频质量（59.5%，$p=3.06\times10^{-4}$）显著；§4.3 只说 DiT 训练 900,000 步、LM 与 MoT 的 AR 侧同 token 预算/batch/更新数，未说明如何论证 3.4B 的 LM+DiT 与 3.58B 的 MoT 得到同等调参投入、以及 900,000 步训练是否充分收敛。
- **为什么重要**：架构主张若只在一个条件下成立，就不宜写成一般性结论（"统一优于分离"）；对照公平性决定这条对抗"主流 LM+DiT 设计"的结论是否可信。
- **当前能够得出的判断**：证据方向一致（带 planning 时五个维度上都偏向 MoT，Table 21），但**条件依赖性是原文自己表格里可见的事实**，论文正文未讨论；"优化预算等价"当前无法确认。
- **如何验证或补强**：给出 LM+DiT 的学习率/token 预算扫描与收敛曲线；在两条件各重复多种子；报告 DiT 步数的消融。
- **严重程度**：中等（限制结论适用范围，不推翻主比较）。

#### 质疑：跨系统比较的输入/配置不对称，最弱的那个基线可能被"配置不当"解释掉

- **原文依据**：§4.1 与 App. A.3 披露 SongBloom 不能用文本提示（对所有条目用同一段 10 秒音频）、MiniMax Music 3 使用官方 caption rewriter 而其他系统直接吃原始提示；Table 5 中 ACE-Step 1.5 以原生 cover 模式运行（App. D.3 给出一组固定超参）后 CLEWS mAP 仅 0.024、Hit@1 2.4%——而同一系统在 Table 2 的 Q3O（4.5809）等指标上并不弱。§5.3 的翻唱队列还经多重资格过滤（1,349 候选中取 948，且 947 首英文）。
- **为什么重要**：基线若配置不当，"全胜 8 项检索指标"的说服力大打折扣；输入通路不一致也会让"提示遵循"类对比（Q3O/MuLan/AMCaps）偏向某一方。这影响实验公平性与结论范围。
- **当前能够得出的判断**：论文给出了各基线的超参与改写协议，属可复现披露；但 2% 量级的检索结果通常会被怀疑用错了接口（例如 cover 模式的源音频/条件组织），而论文没有提供调试过程或"最好配置"的佐证；翻唱队列的语言与风格覆盖也明显偏窄。这些属"存在混杂因素"。
- **如何验证或补强**：报告基线的调参尝试与最好结果、或引用官方示例的检索得分作参照；在更均衡（多语言、多风格）的翻唱队列上重测；对输入通路做一致性说明（给每个系统其官方接口允许的最有利输入）。
- **严重程度**：中等。

## 6. 审稿式总评

> 作者发现音频生成器把作曲隐式地埋在表征里、符号模型又止步于记谱，因此提出把"可读乐谱"变成生成过程的一等状态——用一个 AR–NAR MoT 骨干依次生成 ABC 谱、25 Hz 语义 token 与声学 latent，并用自研的 MERT2（多视图目标 + 375 bit/s 语义 tokenizer）与 SheetSage2（单模型全属性铅谱转写）从普通录音构造训练监督，通过四任务混合训练实现同 checkpoint 的有/无 planning 匹配对照。实验在 192 条自建 WSB 提示、948 首未见作品与若干 MARBLE/转录基准上表明：显式作曲带来显著盲测偏好（49.3% vs 34.6%）、统一 MoT 优于同表示的 LM+DiT（53.4% vs 35.6%）、谱面决策在音频中确实被实现（0.9464 vs 0.2160）、谱编辑可局部改变目标内容并保留 90% 以上未编辑内容；其中 score–audio 三条件对照与编辑/翻唱消融的证据较强，但"前沿质量"仍缺少充分支持——对六家专有系统的总体偏好平均 48.4%（不显著）、音乐性 46.7%（低于均势），显著优势集中在音频质量（58.9%），且头条数字依赖 best-of-8 与使用被报告指标的选择规则。本文最有价值的部分是"可读作曲作为生成接口"的完整闭环与配套的监督构造工程；最大的审稿风险是评测同源（自建基准 + 训练标注模型即评测模型 + 自研转写器打分）与关键消融的预算不匹配。

**六维评分（每项依据见前文对应小节）：**

- **问题定义清晰度**：强（"符号 vs 音频"的割裂与渐进承诺框架界定明确，核心问题与子问题分离清楚；仅"前沿质量"这一措辞的边界略宽于证据，见 §1、§0）。
- **创新性证据**：中（核心思想是把已有组件重新编排为"谱—语义—声学"联合状态，对照实验支撑其有效性；但缺少对最强相关工作的直接比对，"首次"边界无法确认，见 §2）。
- **方法可信度**：中（架构、数据、训练与统计披露充分，四任务设计使消融可行；但 planning 对照未等算力、评测链多处自研组件耦合，见 §3、§4.3）。
- **实验支持力度**：中（证据体量与披露细节都超过同类报告，人评有聚类 CI；但主结果混用候选预算、自动指标无不确定性报告、翻唱基线配置存疑，见 §4.2、质疑一/二/五）。
- **可复现性**：中（模型权重、部分数据集与检查点按论文所述公开，协议与超参写得较细；但训练语料含授权合成数据不可得、无训练成本报告，且链接可达性未核验，见 §4.4）。
- **综合阅读价值**：高（对"生成中间表示作为接口"这一范式、以及音乐生成的监督构造与评估方法都提供了可复用的具体做法与大量可检验的细节，见 §3、§4.3）。
