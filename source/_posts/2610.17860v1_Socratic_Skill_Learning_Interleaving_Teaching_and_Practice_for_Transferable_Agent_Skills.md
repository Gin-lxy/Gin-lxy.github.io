## 0. 一句话结论

论文研究 LLM 智能体能否在不更新权重的情况下，靠“学生实践 + 更强教育者审阅”写出可复用到同族留出任务的技能包。作者提出 Socratic Skill Learning（SSL），让目标模型始终操作环境并撰写技能包，更强模型在练习过程中只读地解释、质疑或诊断，并用 SkillTransferBench（35 族、408 例）把习得与冻结技能评测分开。Qwen 22 族/155 例主队列上，Fixed-Window SSL（固定窗口 SSL）的族宏平均效用为 0.801，高于无技能 0.723、Trace2Skill 0.761、SKILL-KD 0.751，且对后两者的 95% 族级 bootstrap（自助重采样）区间不跨零；但跨模型提升并非都显著，缺少“学生独自练习”与“苏格拉底质疑”的消融，因此证据支持“过程中教学优于事后教学”的有限结论，尚不足以证明“苏格拉底”本身或广泛迁移。

## 1. 论文具体想解决什么问题？

Agent Skills（智能体技能）是 LLM 智能体（LLM agents）的轻量扩展：把可复用知识写成 SKILL.md，必要时附带脚本、参考和资源，推理时加载，不更新权重。它可移植、可审计，但“可复用”不会自动成立：哪些步骤值得保留、在什么输入下成立、何时要改写，都需要证据。论文问的是：学习者如何从一次具体任务的实践，得到覆盖同族变体的可复用程序。

现有做法有四类：从执行轨迹蒸馏经验（Trace2Skill）、教师—学生轨迹对比蒸馏（SKILL-KD，由 consolidation agent（整合代理）提出规则补丁并在环境重跑验证）、失败后给教师反馈（SkillLearnBench 的 Teacher Feedback）、以及让更强模型直接写包（Expert Authoring（专家代写））。它们的反馈主要发生在一次尝试结束或失败之后：一次成功只证明该实例可行，不能证明过程的适用条件；失败后的反馈只能修已写规则，不能改变此前收集了哪些证据。专家代写还多一层风险：专家知识没有在学习者环境中落地，包可能不符合具体工具、路径和验证器。

作者的新观察不是又一个准确率差距，而是技能学习的“教学需求—成本”结构。对 Qwen Fixed-Window SSL 的 66 次习得运行、630 次审阅做过程分析后，作者报告：锚点分数从 0.824 升到 0.990 时，提供课程的例行审阅比例从 73.0% 降到 16.1%；平均每次审阅 token 从 74.7K 涨到 395.7K，最后一轮“沉默审阅”占审阅 token 的 85.8%（§5.3、Appendix E.3、论文 Fig. 4）。技能越成熟，固定间隔审阅越像在为越来越不需要的服务支付越来越贵的上下文。但这是 Fixed-Window 运行中的过程统计，不是因果实验；论文比较的是完整协议，所以“为什么有效”仍带有作者主张。

论文的核心假设是：在 Student 仍是唯一环境操作者和唯一 Skill 作者的前提下，把更强模型的指导插入练习过程，并让建议必须经过环境检验，会比事后教学、专家代写和轨迹蒸馏产生更好的同族留出迁移；当教学需求下降时，用未解决的学习问题选择审阅，可在保持效用时降低教育者 token。要区分三个层次：领域早已知道智能体需要可复用知识；本文新观察到教学需求随技能成熟下降、固定窗口成本随上下文上升；本文实际解决的是“谁操作、谁写作、何时教学”三个协议变量及同族留出基准上的冻结 Skill 迁移。跨任务族、跨领域迁移和“苏格拉底式提问优于直接指令”都不在已证范围内。

## 2. 创新点是什么？

技术增量可概括为：把技能习得拆成“谁操作、谁写作、何时教学”三个可实验的协议变量，并用新基准把“习得”与“冻结技能的使用”分开。它不是新模型、新强化学习目标或新表示学习算法；Socratic 提问、学生作者、技能包、固定窗口审阅大多是已有组件，新意主要在协议组合、评测构造和审阅调度。

第一，交替式教学协议。Student 在练习过程中接受 Educator 审阅，而不是等一轮轨迹结束或失败后再给反馈；Student 仍是唯一环境操作者和包作者，Educator 只读，不能替学生做题。与 Trace2Skill、SKILL-KD 的离线轨迹蒸馏相比，它把外部知识插入“证据还在收集”的时刻；与 Post-hoc Teaching（事后教学）相比，它把一次轮末审阅拆成过程中的多次审阅。证据在 §4.2 的 Table 1、Table 8 与 Table 2，以及 §4.3 的过程分析。

第二，SkillTransferBench。35 个任务族、408 个可执行案例，每族一个锚点、一份公开族规范和若干留出案例，冻结包在全新求解器会话中评测。与 SkillsBench 只测 Skill 效用、SkillLearnBench 和 EconSkills 测参数化实例上的复用相比，它用公开规范显式定义“习得范围”，再用同族留出变体测迁移。这是基准贡献而非方法模块；证据在 §3.1、§3.2、Appendix B 与 §4.2。

第三，Issue-Guided SSL（问题引导 SSL）。它把学习问题做成持久状态：每个问题带焦点、接受标准、证据、关联修订和处置，可嵌套成树，审阅只在未解决问题打开、变化或重开时触发。与 Fixed-Window SSL（固定窗口 SSL）的定期审阅相比，它改变的是“何时审阅、看多少上下文、如何关闭问题”。证据在 §4.4 的 Table 17、Table 18 与论文 Fig. 5。

## 3. 作者如何解决？

直觉是：Skill 像留给未来自己的操作手册。难的不是写出看似合理的步骤，而是知道哪一步有证据、在什么输入下成立、何时要改。SSL 让未来要用手册的人（Student）自己动手、自己写；更强的 Educator 在旁边只读地看，在关键节点提问或指出缺口；任何建议都要由 Student 在环境里试过，才能进入手册。下面按输入、循环、冻结、评测的顺序展开。

### 3.1 输入：任务族、锚点与公开规范

输入是一个任务族（task family）$f$，而不是单个任务。每族有一个可执行的锚点任务（anchor）$x_{f,0}$、一份公开的族规范（family specification）$s_f$ 和若干留出案例（held-out cases）。规范说明族内必须保持的不变量和允许变化的维度，例如 WAL 恢复族允许变化 WAL 编码、完整性检查和恢复深度（§3.1、Appendix B.1）。学生拿到的是规范、干净的锚点环境、上一轮锚点反馈和初始技能包。技能包记为 $\mathcal{K}=(M,\mathcal{R})$，$M$ 是 SKILL.md，$\mathcal{R}$ 是可选脚本、参考和资源。

SkillTransferBench 从六个源基准改造：Terminal-Bench、AgentIF-OneDay、SpreadsheetBench、CodeContests、FullStackBench、OfficeBench。构造有两条路线：抽取与适配（把兼容源案例归入同一族，统一描述、夹具和评分器）与种子扩展（从一个任务出发，先写清不变量和允许变化，再在其内编写新案例）。每例都要有可重置环境、参考解和私有测试；程序化检查验证 Docker 构建、执行测试、确认参考解通过，再由非作者专家复核（§3.2、Appendix B.3）。最终 35 族、408 例、2,807 个检查（每例 3–34 个）；主队列 22 族/155 例，轻量子集 10 族/77 例（Table 5、Appendix B.4）。

图 1 把基准构成与筛选放在同一张图：任务族按六个领域组织，族内案例数 5 到 17 不等；No-Skill 分数分布显示不少案例无技能时已有较高通过率，因此主队列用“至少两个非完美结果”筛掉过易的族；队列条显示 35 族/408 例、22 族/155 例主队列与 10 族/77 例轻量子集的嵌套关系。

**图 1**（论文 Fig. 2）：这张图解释 SkillTransferBench 的构成逻辑和评测队列的嵌套关系。任务族按领域组织，每族有多个可执行案例；主队列不是全目录，而是从中筛出“有足够留出案例、且无技能时并非全部满分”的族，轻量子集再从主队列抽取一部分供跨模型比较。它呈现“先定义族规范、再在族内变化”的设计：习得只看锚点，评测看同族留出成员，因此测到的是规范到程序的转化，而不是对某个固定案例的记忆。

这个设计控制了“同族但不同实例”的变量：所有方法共享案例和验证器，冻结包必须在全新会话重新加载，减少会话泄漏。代价是只测同族留出变体。论文没有让一个族学到的 Skill 去解另一个族，也没有在真实部署环境测；标题里的“transferable”应理解为“在同族新实例上可复用”，而非“跨任务族、跨领域可迁移”。

### 3.2 循环：学生练习，教育者审阅

SSL 把习得分成 3 轮（round）。每轮 Student 在 Docker 工作区探索锚点、调用工具、修改技能包；Fixed-Window SSL 每完成 $g=10$ 次工具调用触发一次 Educator 审阅，轮末补一次未审阅的尾部。Educator 看到最近的推理与工具结果、实时技能包、族规范、此前课程，以及 fresh solver（全新求解器）在锚点上的反馈；它可说理、质疑、诊断、建议检查，也可沉默。Student 可澄清、反驳、改编建议，然后继续探索；每次审阅最多一次 Educator 追加回复（§4.2、Appendix C.2）。一轮结束时运行时冻结技能包，用全新目标模型求解器在干净锚点跑一遍；轨迹和验证器反馈进入下一轮。三轮结束后，最终包在留出案例上评测，每例都用全新会话的求解器，只加载冻结包（§4.1、§3.3）。

组件上，Student 和 Educator 是两个独立、跨轮持续的会话，带自动上下文压缩；会话不跨族、不重复、不跨协议单元。Educator 只能列目录、读文件、搜索包，不能执行环境动作或写文件。求解器只通过原生 Skill 目录加载目标包，其他 Skill 被禁用；留出材料在习得期间不可见，私有检查只在提交后运行（Appendix C.1）。运行时用 Pi coding agent 0.81.122、TypeScript 5.9.3 和 Docker。

固定的是 3 轮、$g=10$、每次审阅最多一次追加、每轮一次锚点测试、每留出案例一个全新求解器、评分规则。模型决定的是 Student 如何探索、何时结束本轮、包里写什么、是否接受建议，以及 Educator 是否开课、课程内容、是否沉默。环境 grounding 由 Student 负责，外部知识由 Educator 提供，运行时负责隔离并保证证据可追溯。

图 2 同时画出学习—迁移回路和两种审阅策略：Educator 只读观察 Student 的最近工作与实时 Skill，Student 负责工具调用、环境实验和包写作，冻结后的包交给全新 solver；固定窗口按工具调用数触发，问题引导按未解决问题的状态变化触发。

![图 2：SSL 的教学与实践回路](/images/dailypaper/2026-10-22/socratic_fig2.png)

**图 2**（论文 Fig. 3）：这张图把“谁在做什么”画清楚。Educator 不是代写者，而是只读审阅者；Student 不是被动接收者，而是唯一环境操作者和包作者；迁移只发生在最后，只有冻结技能包进入全新求解器，Educator 和习得会话都不跟随。两种策略的差别在触发信号：固定窗口看工具调用数，问题引导看未解决问题的状态变化。这个架构把外部知识与环境证据分开，避免专家建议未经检验就变成规则，也避免学生无证据照抄专家结论。

为什么不让 Educator 直接写包？专家知识再强，也可能不符合学生环境的工具、路径和验证器；只读可保留外部视角，同时强制 Student 用执行证据决定包内容。为什么每轮做锚点测试？锚点是便宜的中间检查点，能暴露包在全新会话中的明显问题。为什么 3 轮？论文没有轮数消融，这个固定预算在 §4.4 会变成未报告的超参数风险。

训练方面，SSL 不训练任何参数：没有 SFT、RL 或奖励模型，Student 和 Educator 都是冻结 API 模型，变化的只有文本和文件。冻结包在任务族 $f$ 上的迁移效用（transfer utility）定义为

$$U_f(\mathcal{K};\pi_S)=\mathbb{E}_{x\sim\mathcal{D}_f}\left[r_f\left(\pi_S(x,\mathcal{K})\right)\right],$$

其中 $\pi_S$ 是目标求解器，$\mathcal{D}_f$ 是该族案例分布，$r_f$ 是验证器分数。推理阶段，求解器收到案例 $x$ 和冻结包 $\mathcal{K}$，在新会话完成任务；没有 Educator、锚点反馈或包修改，最终输出是提交工件或环境状态，由私有检查打分。SSL 的“学习”发生在习得阶段，部署阶段只剩“加载包、读包、按包执行”。

### 3.3 Issue-Guided：把审阅从时间表改成问题状态

Fixed-Window 的问题是审阅时间由工具调用数决定，而非“现在有没有未解决的问题”。Issue-Guided SSL 把审阅单位从时间窗改成学习问题（learning issue）。一条 Educator 课程要给出学习焦点（focus，调查什么）和接受标准（acceptance criterion，什么可观察证据算解决）。问题节点还保存证据、关联的包修订和处置状态；问题可嵌套成学习问题树（Learning-Issue Tree）：调查中出现的子问题成为子节点，关闭后回到最近的未解决祖先，已解决的兄弟分支保留（§4.3）。

Student 在每次连贯知识修改后调用 `commit_skill_revision`，声明摘要、证据、关联问题 ID 和处置。关闭方式有三种：包已改变且有验证证据（verified closure，要求一次成功的课后检查）、给出有界的适用范围证据、或有证据地拒绝建议。若新一轮 fresh-solver 锚点反馈与包矛盾，相关问题下一轮重开，已解决兄弟节点不受影响（§4.3、Appendix C.2）。审阅触发也变了：第一次修订或 10 次工具调用后做一次 bootstrap；此后只有未解决问题打开、变化或重开才请求审阅。Educator 上下文缩小到活动问题及祖先、最新修订、最近局部工作，同时保留整包只读访问；沉默会关闭当前审阅 episode。

为什么这样设计？固定窗口在技能成熟后产生大量“没有新问题、但仍要读越来越长上下文”的审阅；问题状态可把预算集中到真正未解决处，并让关闭有可观察依据。问题树保留调查层次：子问题解决后注意力回到父问题，而非推倒重来。这对应 §1 的成本观察，也在 §4.4 表现为 61.7% 的 Educator token 节省。

但有一个实现混杂：Appendix C.2 明确说，Issue-Guided 的触发条件、上下文范围和追加策略一起变，不只是“把固定窗口换成问题触发”，还同时改变 Educator 看到多少历史、是否允许追加、何时算关闭。§4.4 的成本下降不能单独归因于问题树或问题选择；Appendix H 也承认需要控制实验分离贡献。输出仍是同一个冻结包，推理阶段与 Fixed-Window 相同。

## 4. 解决得怎么样？

### 4.1 实验设置

实验围绕四个问题：RQ1 同族留出迁移；RQ2 不同专家指导组织方式在三个模型对上的表现；RQ3 教学过程；RQ4 审阅调度与成本。主队列 Qwen 22 族/155 例，轻量子集 10 族/77 例，覆盖六个领域。主队列每族每条件 3 次独立习得，每次评测全部留出案例；No Skill 用 3 次 fresh-solver 重复；DeepSeek 和 Kimi 只做 1 次（§5.1、Appendix D.3）。

模型对三组：Qwen3.7 Plus（Student/solver）+ Qwen3.7 Max（Educator 或 Expert Authoring 作者）；DeepSeek-V4-Flash-0731 + DeepSeek-V4-Pro-0813；Kimi K2.5 + Kimi K3（Appendix C.1）。三组都是“学生模型同时是部署求解器，教育者是更强外部模型”，保证评测与习得模型一致，但也意味着 Educator 能力是方法的一部分。

基线五类：No Skill 不做习得；Expert Authoring 让外部强模型探索、写包并接收多轮锚点反馈；Post-hoc Teaching 让 Student 写包，但每轮只在轨迹结束后接受一次审阅；Adapted Trace2Skill 保留并行补丁提议与合并，把电子表格前端换成任务族适配器；Adapted SKILL-KD 用作者复现的循环，从通用规则种子出发，每次访问锚点最多 3 个自适应轮，候选规则须经 fresh Student 完全成功后接受（Appendix C.3、C.3.1）。

指标是族宏平均（family-macro）Avg@3 效用：每例分数为私有检查通过比例，超时记 0；先对族内案例平均，再对族和重复平均。主队列估计量为

$$\widehat{U}=\frac{1}{3|\mathcal{F}|}\sum_{r=1}^{3}\sum_{f\in\mathcal{F}}\frac{1}{|V_f|}\sum_{v\in V_f}R_{f,v,r},$$

其中 $\mathcal{F}$ 是族集合，$V_f$ 是族留出案例，$R_{f,v,r}$ 是第 $r$ 次重复中案例 $v$ 的通过比例。辅助指标有全通过率、相对 No Skill 的迁移增益和按族重采样的 95% paired bootstrap 区间。Appendix D 给逐族结果与额外模型对，E 给教学过程，F 给成本。

公平性方面，论文报告 token，但没有对齐各方法习得预算：Expert Authoring 4.95M、Post-hoc 8.71M、Fixed-Window 6.89M、Issue-Guided 5.72M tokens/run；SKILL-KD 的 1.94M/run 是另一套口径，Trace2Skill 无共同口径（Table 8、Appendix C.3.1）。因此“SSL 更好”暂时不能排除“SSL 用了更多算力”。论文也未报告随机种子与采样设置，只说用 provider defaults（服务商默认值）（Appendix C.1）。

Qwen 主队列核心数字如下，效用为 0–1 的族宏平均，增益相对 No Skill，括号内是 95% 族级 bootstrap 区间（Table 8）：

最关键的是 Fixed-Window SSL 对 Adapted Trace2Skill 的 +3.99 pp [1.45, 6.49]、对 Adapted SKILL-KD +4.99 pp [1.79, 8.48]、对 Post-hoc +5.31 pp [2.34, 9.09]、对 Expert Authoring +7.29 pp [3.62, 11.44]（§5.1、Appendix D.1）。四个 95% 区间都不跨零。全通过率从 32.50% 升到 49.49%（Fixed）和 50.82%（Issue），增益 16.99 和 18.33 pp，区间不跨零（Appendix D.1）；但约 50% 也意味着还有一半案例没有全过。

Issue-Guided 的 0.805 只比 Fixed 的 0.801 高 0.4 pp，差异在噪声内。它真正的卖点是成本：Educator token 少 61.7%，总习得 token 少 16.9%（6.89M 降到 5.72M），每 Educator token 的迁移增益是 Fixed 的 2.75 倍（§5.4、Table 17、论文 Fig. 5）。准确说法是“效用基本不变时显著减少外部监督”，而不是“更准”。

跨模型结果要谨慎。Table 2(a) 相对 No Skill 的增益（轻量子集）为：Qwen 上 Fixed +4.1、Issue +4.5、Expert +1.1、Post-hoc −0.7；DeepSeek +3.1、+2.5、+1.2、+0.5；Kimi +8.2、+7.4、+5.8、+4.1。点估计上两个交替协议在三对中都排前两位。但 Table 13 显示 Fixed−No Skill 在 DeepSeek 上 [−4.63, +13.03]，跨零；Fixed−Expert 与 Issue−Fixed 的三对区间也全跨零。因此“三个模型对都优于专家代写”只是点估计排序；DeepSeek 和 Kimi 还各只有 1 次重复。

平均值也掩盖族间差异。Fixed 在 22 族中改进 16 族，但 Bank transaction filter 从 0.678 降到 0.593，SPARQL professors 0.706→0.680，XLSX structure 0.933→0.923；Issue 也在 ACL、Financial documents、SPARQL、SQLite、XLSX 上低于 No Skill（Table 9）。案例级看，Fixed 在 155 例中 72 升、59 不变、24 退，Issue 为 71/63/21；25 个 No-Skill 满分 ceiling（上限）案例里，Fixed 仍退 3 个、Issue 退 5 个（Table 10）。

图 3 把四种 Qwen 调度的效用与教学成本放在同一尺度：$g=5$ 和 $g=20$ 的效用都在 0.776 左右，$g=10$ 是 0.801，Issue 是 0.805；教育者 token 从 $g=5$ 的 5.33M、$g=10$ 的 2.40M、$g=20$ 的 1.26M 降到 Issue 的 0.92M；每百万教育者 token 的增益从 0.99、3.23、4.19 升到 8.91。Issue-Guided 不是简单“少审阅”，而是把审阅放在更有信息量的位置：比 $g=20$ 多花一点教育者 token 换回约 2.9 pp 效用，比 $g=10$ 少花 61.7% 教育者 token 却保持同样效用。

![图 3：不同审阅调度下的效用与教学成本](/images/dailypaper/2026-10-22/socratic_fig3.png)

**图 3**（论文 Fig. 5）：这张图比较“审阅预算怎么花”而非单一准确率。横轴分别是效用、每轮教育者 token、每百万教育者 token 换来的迁移增益；四行对应固定窗口三个间隔和问题引导。审阅越频繁，教育者 token 越多；但效用不随审阅次数单调上升，$g=5$ 和 $g=20$ 都低于 $g=10$，说明关键不是“多审”或“少审”，而是“何时审、看什么”。Issue-Guided 用更少教育者 token 达到略高效用，代价是学生承担更多调查工作。

但 $g=10$ 明显好于 $g=5$ 和 $g=20$，论文没有报告三者的置信区间或选择依据，0.801 可能带有轻度调参。

### 4.3 机制证据

作者追踪 66 次 Qwen Fixed-Window 运行、630 次审阅、254 次开场课程和 91 次追加对话（Appendix E.2）。三个主要观察：教学率随轮次下降（73.0% → 37.5% → 16.1%），锚点分数上升（0.824 → 0.986 → 0.990）；教学后学生下一次工具调用是写/编辑文件的概率比沉默后高 23.9 pp（95% CI [13.0, 36.1]），未来十次调用内包变化概率高 38.6 pp（[10.7, 57.8]）；每次审阅 token 从 74.7K 涨到 395.7K，最后一轮沉默审阅占审阅 token 的 85.8%（§5.3、Appendix E.3、Table 16）。锚点已满分的 99 个后续轮次中，包仍有 98 个变化；33 轮有新课程、66 轮没有，后者全部修改了包（Appendix E.3）。

图 4 把技能成熟、教学决策、学生行为和审阅成本串成一条链。

![图 4：教学需求、学生行为与审阅成本](/images/dailypaper/2026-10-22/socratic_fig4.png)

**图 4**（论文 Fig. 4）：这张图是机制核心。它把锚点分数与教学率放在同一时间轴，说明技能越成熟、教育者越少开课；把教学与沉默后的学生行为对比，显示写作/编辑和包修订都更可能发生；再把每轮审阅 token 拆成课程与沉默两部分，显示沉默审阅后期占绝大部分成本。它支持的解释是：教学作用发生在学生的调查和写作环节，而固定窗口成本主要花在越来越长的上下文上，不是花在有效课程上。

但这些证据是观察性的，不是因果的。Appendix E.2 明确写道“review decisions respond to the Student's ongoing work”，即教育者可能因为学生正要写、刚写错或卡住才开课，“教学导致写作”与“写作需求导致教学”方向难分。论文用 within-run 比较（18 个同时含教学与沉默决策的运行，平均差 34.3 pp）缓解，但样本很小且未随机化。案例研究（HTML-finance）中，教育者提议“用其他条目反推报告值”，学生先实现通用算术、只选中 4 个被 flag 指标中的 1 个，随后改用财务关系与反向推导，最终在留出 v14 上 4/4 通过（§5.3、Table 3、Appendix G.1）。这说明“建议需要被环境检验”，但只是 1 个挑选出的成功案例，论文没有报告失败案例或学生拒绝建议的统计。

更关键的是，过程分析没有把“包变化”与“包变好”分开。锚点满分后仍有 98/99 轮改包，作者解释为持续发展；但论文只在最后评测留出案例，没有逐轮测留出效用，因此这些修改也可能是过拟合锚点、风格漂移或无害重写。结合重复 SD 0.030–0.036，这个缺口很重要：能看到“包在动”，却看不到“包在变好”。学习问题树统计显示，177 个问题节点中 175 个在运行结束时关闭，但关闭方式里 194 次是教育者沉默、7 次验证性关闭、2 次有界关闭、0 次证据性拒绝（Table 20）。大多数“关闭”不是被证据验证，而是教育者选择不再追问。

对 §2 三个创新逐一核对：交替式教学证据最强，Fixed vs Post-hoc 的 5.31 pp 差异且 Post-hoc 更贵，排除了“多花钱”的简单解释；但缺“学生独自练习 3 轮”基线，无法排除“多轮实践 + 锚点反馈”本身的贡献。Issue-Guided 的证据主要在成本，且触发、上下文、追加策略一起变。至于“苏格拉底”本身，论文没有“提问式 vs 指令式”对照，0 次证据性拒绝说明质疑/拒绝机制几乎未被触发。因此机制证据支持“教学与写作/修订相关、固定窗口成本随上下文上升”，但不足以证明“苏格拉底式对话是有效成分”或“问题树优于更简单触发器”。

### 4.4 成本与适用范围

成本方面，论文报告 token，不是美元、时延或人力。Qwen 主队列每个习得运行：Fixed 6.89M、Issue 5.72M、Post-hoc 8.71M、Expert 4.95M；SKILL-KD 的 1.94M/run 是单独口径，Trace2Skill 没有共同口径（Table 8、Appendix C.3.1）。Fixed 的 630 次审阅消耗 158.2M Educator token，Issue 的 329 次共 60.6M；每次审阅从 251.1K 降到 184.1K，审阅次数减 47.8%，每次 token 减 26.7%，合计减 61.7%（Appendix F.1）。节省来自“少审”与“每次看得更少”，不是把审阅挪到别的角色。

图 5 把四种调度的总 token 拆成学生作者、教育者和 fresh anchor solver 三部分：$g=5$ 总 9.56M，$g=10$ 总 6.89M，$g=20$ 总 6.61M，Issue 总 5.72M；教育者部分从 $g=10$ 的 2.40M 降到 Issue 的 0.92M，学生作者部分略升。Issue-Guided 省的是“外部监督”，不是“学生劳动”；学生仍要花 token 探索和写包，这解释了为什么总成本节省（16.9%）小于教育者节省（61.7%）。

![图 5：四种调度的习得 token 分配](/images/dailypaper/2026-10-22/socratic_fig5.png)

**图 5**（论文 Fig. 7）：这张图把“总成本”拆成角色级成本，避免把教育者节省误读成总节省。每个条形是一次习得运行的平均 token，分段分别是学生作者、教育者、每轮锚点测试的 fresh solver，总长度标在条形末端。Issue-Guided 的教育者段明显缩短，但学生段没有缩短，所以总节省远小于教育者节省；$g=5$ 总成本最高，因为审阅次数最多，$g=20$ 总成本较低但效用也低。审阅调度的本质是在“外部监督”和“学生自主调查”之间重新分配工作量，而不是免费减少总计算。

跨模型上结论更复杂。DeepSeek 上 Issue-Guided 节省 63.8% 的 Educator token，但学生作者多花 5.276M，净总成本反而增加 1.101M；学生调用数从 890 增到 1216（+36.6%），其中 sqlite 族单独增加 23.8M，其余族合计节省 12.8M（Table 18、Appendix F.1）。Kimi 上节省 77.4% 的 Educator token 且学生 token 下降 0.870M，净节省 4.12M；Qwen 净节省 1.164M。也就是说，“减少外部监督”稳定，“减少总成本”模型相关；论文没有解释 DeepSeek 学生为何多花这么多。

适用范围上，结论应限定为：在六个领域、35 族（主队列 22 族/155 例）、三组模型对、3 轮习得、单锚点、同族留出变体下，过程中教学比事后教学/专家代写/两种蒸馏基线更能提升冻结包迁移效用；Issue-Guided 能在基本不降效用时减少教育者 token。它没有证明跨族、跨领域迁移或真实部署可靠性，也没有证明在更弱 Educator 或不同工具环境下仍成立；全通过率约 50%、6/22 族没有提升、部分族退步，说明技能学习还远未到可靠水平。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：缺少“学生独自练习”的消融，无法判断收益来自教学还是来自三轮实践与锚点反馈

- **原文依据**：§4.1 与 Appendix C.3 的五类对照没有“Student 自己做 3 轮、拿同样的 fresh-solver 锚点反馈、没有 Educator”的条件；No Skill 不做习得，Post-hoc 仍有一次审阅。Student 每轮都能拿到 fresh solver 的锚点轨迹和验证器反馈（Appendix C.2）。
- **为什么重要**：这是因果归因的核心。如果三轮实践加锚点反馈本身就能把 0.723 提到接近 0.801，“教学”的增量就被高估；反之协议主张才站得住。
- **当前能够得出的判断**：证据不足，存在混杂。Fixed 比 Post-hoc 高 5.31 pp 且 Post-hoc 更贵，支持“审阅时机”而非“多花 token”；但 Post-hoc 仍有 Educator，不能替代纯学生基线。
- **如何验证或补强**：加 Student-only 3 轮对照并匹配 Student 预算；再加随机/固定提示、教学但禁止改包，分离教学、写作和额外上下文的作用。
- **严重程度**：主要问题。不否定 SSL 有效，但削弱“教学是有效成分”的因果结论。

#### 质疑：基准由作者自建自评，“留出”只是同族变体，不足以支持广泛“可迁移”的主张

- **原文依据**：§3.1–§3.2 与 Appendix B 说明 35 族/408 例由作者从六个源基准改造，主队列按“至少 5 个留出案例、至少 2 个非完美 No-Skill 结果”筛选；公开规范由作者撰写，留出案例同规范构造。评测只测同族留出，无跨族/跨领域实验；2,807 个检查只由参考解验证，未报告多正确解通过率或假阴性。AI Use Statement 说明生成式 AI 参与起草与适配。
- **为什么重要**：基准与评测同源时，“迁移”更接近同分布泛化；验证器过严时，效用衡量“像参考解”而非任务成功。这影响基准的独立价值与结论范围。
- **当前能够得出的判断**：只能支持同族留出迁移；跨族、跨领域、真实部署无法确认。构造有程序化验证和专家复核，但独立性与验证器效度未建立。
- **如何验证或补强**：由独立团队构造/复核留出案例并报告标注者一致性；做跨族/跨领域迁移；用多个独立正确解测验证器，报告假阴/假阳；公开筛选前候选集。
- **严重程度**：主要问题。限制论文最强主张的适用范围。

#### 质疑：与 Trace2Skill/SKILL-KD 的算力预算不匹配，基线还是作者改写的

- **原文依据**：Table 8 报告 Qwen 主队列 Fixed 6.89M、Issue 5.72M、Expert 4.95M、Post-hoc 8.71M tokens/run；SKILL-KD 1.94M/run 是另一套审计口径，Trace2Skill 成本为“—”。Appendix C.3 说 Trace2Skill 是作者适配版，替换了电子表格前端；SKILL-KD 也是作者复现。摘要直接比较 0.801 与 0.761/0.751，未同时给预算。
- **为什么重要**：若 SSL 用了 3.5 倍于 SKILL-KD 的 token，“方法更好”可能只是“算力更多”；适配基线偏弱也不公平。
- **当前能够得出的判断**：存在混杂。Fixed 比 Post-hoc 好且更便宜，部分缓解“多花钱”解释；但对蒸馏基线没有预算对齐，不能下强结论。
- **如何验证或补强**：在相同 token/调用预算下重跑所有方法，画效用—成本曲线；用官方实现与超参数，报告适配差异；报告每个成功 Skill 的成本。
- **严重程度**：主要问题。需要预算匹配才能把“方法”与“算力”分开。

#### 质疑：“苏格拉底”核心机制没有被单独检验，有效成分可能只是“更强模型在过程中给提示”

- **原文依据**：§4.1 说 Student 可 question、test、adapt、reject 建议；但 §5.3 与 Appendix E.2 只测教学后的写作/修订概率，没有统计质疑或拒绝比例；Table 20 中证据性拒绝 0 次、验证性关闭 7 次、有界关闭 2 次、教育者沉默 194 次。没有“提问式 vs 指令式”对照，也没有“允许拒绝 vs 不允许”的消融。
- **为什么重要**：Socratic 是论文的名称与身份；若有效成分只是“更强模型在过程中给提示”，创新性应归为 interleaved feedback，而非 Socratic teaching。
- **当前能够得出的判断**：作者主张大于证据。单个成功案例不能证明质疑/拒绝机制被使用或带来收益；0 次证据性拒绝说明该机制在实践中几乎是空的。
- **如何验证或补强**：固定课程内容，只改表达方式（提问 vs 指令）；记录质疑、拒绝、改编比例及被拒建议的后续；做允许/禁止拒绝的消融。
- **严重程度**：主要问题。直接关系核心命名与理论主张。

#### 质疑：统计稳定性不足，跨模型与过程结论被点估计和观察性数据支撑

- **原文依据**：Qwen 主队列 3 次重复 SD 为 Fixed 0.030、Issue 0.036、No Skill 0.006（Table 11）；DeepSeek 和 Kimi 只有 1 次（Appendix D.3）。Table 13 中 Fixed−No Skill 在 DeepSeek 上 [−4.63, +13.03]，Fixed−Expert 与 Issue−Fixed 三对全跨零。过程分析是观察性的，Appendix E.2 承认审阅决策会响应学生工作；锚点满分后 98/99 轮改包，但没有逐轮留出评测。$g=10$ 是主条件，但 $g=5/10/20$ 比较没有置信区间。
- **为什么重要**：摘要级“三个模型对都优于专家代写/事后教学”只有点估计和 1 次重复支撑；过程主张是关联而非因果，容易高估论文。
- **当前能够得出的判断**：Qwen 主队列的关键区间不跨零，这部分较强；跨模型排序不稳，机制是关联，post-anchor 的“持续发展”无法与漂移区分。
- **如何验证或补强**：每对至少 3–5 次独立习得，报告均值/SD/最小值；用混合效应或分层 bootstrap；预注册 $g$ 或嵌套交叉验证；对教学 vs 沉默做随机化；逐轮测留出效用。
- **严重程度**：主要问题。摘要中的跨模型与机制表述需要降级。

## 6. 审稿式总评

作者发现现有技能学习把反馈放在失败后或轨迹结束后，而固定窗口审阅成本随技能成熟和上下文累积上升，因此提出 Socratic Skill Learning：目标模型始终操作环境并撰写技能包，更强模型在练习过程中只读审阅，并用问题状态选择审阅；同时构造 SkillTransferBench，把习得与冻结技能评测分开。Qwen 22 族/155 例主队列上，Fixed-Window SSL 的 0.801 高于无技能 0.723、Trace2Skill 0.761 和 SKILL-KD 0.751，且对后两者的族级区间不跨零；Issue-Guided 在效用基本不变时减少 61.7% 的 Educator token。其中，“过程中教学优于事后教学/专家代写”的主队列证据较强，基准构造与成本披露也较扎实；但跨模型显著性、学生独自练习的消融、苏格拉底机制的分离、同族留出的范围限制，仍缺少充分支持。
