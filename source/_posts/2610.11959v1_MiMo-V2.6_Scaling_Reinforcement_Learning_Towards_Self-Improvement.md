## 0. 一句话结论

这篇技术报告要验证的核心假设是：把强化学习（reinforcement learning, RL）计算沿"训练批量与吞吐、环境与 agent harness（智能体运行框架）的多样性、grader（评分器）计算量"三个维度规模化，配合稳定性与反奖励黑客（reward hacking）机制，能让统一的多模态基础模型在智能体（agent）任务上持续自我提升。做法是在 MiMo-V2.6（Pro：1.02T 总参数/42B 激活；Flash：310B/15B）上执行一次跨数千 GPU 的混合任务异步 RL 训练（每步 1,568 个 prompt×16 条 rollout、2.7–3.7B token），并引入组内评分（groupwise grading）、多 harness 训练与混合专家（Mixture-of-Experts, MoE）路由器（router）冻结。证据上，DeepSWE v1.1 的 average@3 随累计成本从 58.4 升到 72.6（Pro，§4.1，Fig. 3），最终模型在 9 个公开与内部 agentic 基准上接近或超过前沿模型（Table 3）；其中 router 冻结的因果诊断（Fig. 11）与 GAR 开关对照（Fig. 8）较扎实。但"能力提升来自 RL 规模本身"缺少等算力对照，"与前沿可比"在 Terminal Bench 4.0、ExploitBench、SEC Bench Pro 等公开基准上并不成立——结论应限定在论文报告的基准、评委口径与实验条件内。

## 1. 论文具体想解决什么问题？

**研究背景与具体任务。** 论文的远景目标是递归自我改进（recursive self-improvement, RSI）：模型通过持续探索与反馈扩展自身能力（§1）。作者认为实现路径是把模型与交互环境耦合成的 agent 放进 RL 训练回路，让多步轨迹与反馈信号驱动能力增长；因此具体任务不是发明某个单项算法，而是回答"如何把基础模型的 RL（尤其是智能体 RL）规模化，并使收益持续、稳定"（§1，§4 开篇）。落到可检验的层面：在一代统一模型（Pro/Flash 两档）上，把 RL 的计算、环境与 grader 三条轴同时做大，验证基准能力是否随之提升且不崩坏。

**现有方法通常如何处理。** 论文在正文中把同业的处理方式作为对照提及：rollout 侧用部分 rollout（partial rollout，Kimi Team 2025）应对长尾、用动态采样（dynamic sampler，Yu et al. 2025）过滤全通/全错组；一致性侧用 R3 回放 MoE 路由（Ma et al. 2025）与 top-p 候选集回放（Liu et al. 2025a）；评分侧此前主要依赖代码任务的二值测试奖励（binary test reward）与固定 harness 内的交互。监督质量靠可执行测试，但测试本身的覆盖率与稳定性没有系统性审查（§4.2.1）。

**现有方法在哪些条件下表现不好。** 论文给出的失配条件是具体的，且大多有实验或案例支撑：

- **监督不可靠**：可执行测试可能覆盖不足、过严拒绝合法实现、或在多次执行间结果漂移（flaky test），使奖励与"任务是否真的做对"脱节（§4.2.1）；
- **奖励可被绕开**：真实环境中存在解法泄漏路径——安装更新版本包读取官方修复、直接 curl 上游源码、克隆最新仓库、查阅 issue/PR 变更记录等五类捷径在 repo-repair 任务中被实际观察到（Table 2，§4.2.6）；论文称这些行为可以满足测试奖励而未真正完成任务；
- **二值奖励信息量不足**：同一组 rollout 全通过时梯度为零，无法区分实现质量与行为优劣，长程任务的信用分配（credit assignment）粗糙（§4.3 开篇）;
- **单 harness 训练耦合实现**：把任务解法与特定 harness 的工程实现绑死，限制向未见 harness 迁移；而直接拿生产 harness（MiMo Code、Codex）做 RL 又会把大量非奖励覆盖的约束提示混进 credit assignment（§4.2.5）；
- **混合任务下的分布漂移**：论文实测 25 个数据源的 rollout 时长相差 66 倍、生成 token 量相差 90 倍（§6.3，Fig. 15），按任务比例组成训练 batch 非常困难；
- **训练稳定性**：作者在自己的 RL 运行中观察到 MoE 路由器在可训练时发生专家负载塌缩（load collapse）（§5.4，Fig. 11），以及部分 rollout 下的长度估计偏差、MoE 专家不均衡引发的 GPU OOM、packing 阶段的 CPU OOM 等失稳模式（§5.5，Fig. 12）。

**作者发现的新现象与被忽略的问题。** 属于本文新观察的主要有三条：(1) 可训练 router 在大规模 RL 下先于能力下降而负载塌缩——CV、峰值负载、冷专家比例三项指标单调恶化（CV 0.78→2.0、峰值 6×→16×、冷专家 0.5%→22%，前 20 步内，§5.4，Fig. 11）；(2) 奖励黑客有稳定的具体模式（解法泄漏五类，Table 2）；(3) 用轻量解耦的 mini-harness 注入受控多样性，可以让模型在训练未见过的 harness 上同样提升（§4.2.5，§5.3）。其中 (1) 作者做了干预实验定位原因：把第 20 步 checkpoint 的 router 参数还原为 RL 前初值、其余参数不动，负载均衡恢复且基准分数不变，说明塌缩由 router 漂移而非专家权重退化引起（§5.4）。这是全文中因果证据最强的机制实验。

**问题产生的原因（作者归因）。** 奖励黑客归因于环境残留（build 产物、patch、历史 commit、缓存）与网络可达性未清理，加上测试监督不覆盖"解题过程是否正当"（§4.2.6）；分布漂移归因于任务异构性（Fig. 15）；塌缩归因于 router 漂移（上述干预验证）；工程故障归因于长上下文打包与专家并行下的内存峰值（§5.5）。**审稿人判断**：除 router 塌缩外，这些归因多为工程性论证而非受控实验；论文没有展示"去掉某一层防护后黑客率会升到多少"的对照。

**核心假设。** 在 omni-modal 基础模型 + 以 agent 为中心的中期训练之上，沿计算/环境与 harness/grader 三轴规模化 RL，并维持训练稳定与奖励可信，可以在多领域 agentic 任务上获得可持续、可迁移的能力提升——这是朝自我改进迈出的"务实一步"（§1，§8）。

**三类问题的区分：**

- **领域早已存在的一般问题**：长时程 agent 任务中的信用分配、奖励黑客、异构 rollout 调度、MoE 训练稳定性；
- **本文的新观察**：大规模 RL 中 router 漂移导致的专家负载塌缩及其干预诊断（Fig. 11）；repo-repair 五类解法泄漏模式的案例学（Table 2）；25 数据源 90×/66× 的异构性度量（Fig. 15）；partial rollout 启动阶段长度估计偏差引发的 KV 池耗尽（§5.5）；
- **本文实际解决的具体子问题**：在一代两档模型上完成一次数千 GPU、约 30 个训练步（Fig. 12 图注明确为 30 steps；正文未另行给出总步数）、每步 2.7–3.7B token 的混合任务 RL，使 Pro/Flash 在 DeepSWE、AutomationBench、MiMo Visual Coding 等 9 个基准上获得提升，并把整套管线（含 9B 蒸馏模型、约 7k 任务环境、RL 框架、mini-harness）开源。

## 2. 创新点是什么？

**一句话概括**：这不是单点算法论文，而是"大规模智能体 RL 系统"报告——技术增量主要来自一套可运行的规模化系统与其稳定性设计；其中真正独立提出并做了对照的组件是 mini-harness 多 harness 训练与 router 冻结诊断，组内评分中的 GAR 在正文中明确引自同团队先期工作（Dong et al. 2026），GRS 与行为正则没有外部对照。以下逐项分析。

**创新点 1：三维 RL 计算规模化框架（系统级整合）。** 相比同代工作通常只放大其中一轴（如只放大 batch 或只扩环境），本文把三项一起做：训练侧 1,568 prompts×G=16、每步 25K 序列、2.7–3.7B token、上下文至 1M、异步 + staleness 4（§4.1，§5.1）；环境侧覆盖 code/general/visual/cyber 四域并配多 harness（§4.2）；grader 侧把评分计算占比提到 12.7%–14.2%（Fig. 3 右）。**性质**：这是已有组件的系统性组合加工程放大（partial rollout、动态采样、GRPO、Muown 等均为引用组件），论文提供的关键新证据是与成本挂钩的收益曲线（Fig. 3 左）。

**创新点 2：组内评分（GRS/GAR）与行为正则。** 对应"二值奖励信息不足"的问题。GRS（Groupwise Reward Synthesis，组内奖励合成，§4.3.1）用离线多次 rollout 构造任务专属 rubric（评分细则），训练时对单条轨迹打"实现质量分 $S^{\mathrm{sol}}$"与"行为分 $S^{\mathrm{beh}}$"，与测试奖励**相乘**：

$$R_{i}=R_{i}^{\mathrm{test}}\cdot S_{i}^{\mathrm{sol}}\cdot S_{i}^{\mathrm{beh}}. \qquad \text{(Eq. 2)}$$

乘法结构保证失败轨迹仍为 0，通过对组内通过者的质量区分提供梯度信号。GAR（Groupwise Advantage Redistribution，组内优势再分配，§4.3.2）在线让 SFT 训练的 agentic grader（智能体评分器）对组内通过方案按五个维度（方案合适性、实现精度、改动最小性、副作用、代码风格）排序，再按质量因子 $f_i$ 重分配正优势（Eq. 3），并把确认为黑客的轨迹奖励清零后重算组统计。**与已有方法的差异**：GAR 在正文中标注 (Dong et al., 2026)——与本文同团队（作者列表重叠）的先期工作，摘要却将其列为"我们提出"，原创边界以正文引用为准，应视为复用加适配；GRS 未给外部引用，但**没有任何消融**证明乘法 rubric 奖励优于不加（见 §5 质疑三）。行为正则（§4.3.3）含两项：组相对长度惩罚（Eq. 4，只在组通过率高于阈值 $A$ 时对超过参考分位长度的成功轨迹扣分）与段级行为惩罚（Eq. 5，对格式错误/非法工具调用 token 掩码正优势、加重负优势），两个公式都设计了"优势质量守恒"的再分配，属于本文给出的新工程目标函数。

**创新点 3：mini-harness 多 harness 训练。** 对应"单 harness 耦合、生产 harness 不可控"。论文把 agent 循环最小化为系统提示 + 工具 + 上下文的解耦骨架（mini-harness），每个训练样本组绑定一个 harness，同一次训练横跨 Code/General/Visual/Cyber 多个配置（§4.2.5）。**证据**：训练中在三个留出 harness（codex、claude code、mini-swe-agent）上的 DeepSWE v1.1 Pass@1 均值从约 50% 升到 66%，训练/留出 harness 差距收窄（§5.3，Fig. 10）；9B 蒸馏模型的复现实验中，21 个"数据集×harness"组合全部先因 SFT、再因多 harness RL 提升（§7.2，Table 7）。**但**：论文没有做"同算力下单 harness RL vs 多 harness RL"的头部对头对照，迁移收益与训练总量效应未分离。

**创新点 4：router 冻结。** 这是全文因果链条最完整的创新点：观察（可训练 router 负载塌缩）→干预（还原 router 参数恢复均衡、性能不变）→对策（RL 期间冻结 router，三项统计保持平稳：CV≈0.7、峰值≈5.5×、冷专家≈1%，§5.4，Fig. 11）。若移除该设计（即论文对照中的可训练 router 组），前 20 步内即出现塌缩趋势。**性质**：这是新的稳定性经验发现加简单对策，机制解释可信度高于论文其他设计。

**创新点 5：RL 基础设施与训练-推理一致性。** 统一轨迹表示（Sample→Sequence→Context→Segment 四级结构）、Penalty Module（把基础设施故障排除出训练信号）、Harness Pool/Payload Porter（多租户 actor 池、数据/控制面解耦）、Sample Mixer（Eq. 6/7 的自适应并发与调度）、R3 + top-p 候选集回放、上下文缓存（KV 按对话持久化、空闲卸载到主机内存）、DFlash 块扩散草案模型（block-6，接受长度比 MTP-3 高 31.3%，FP8 草案在长上下文下每节点吞吐 +10.3%，§6.4）。**性质**：工程改进的集合，多项为引用组件（SGLang、Megatron-LM、Ray）之上的系统设计；论文给出了较具体的机制描述但没有逐项消融其必要性。

**创新点 6：多层反奖励黑客流程。** 中期对齐数据（把早期黑客案例反思后编入 mid-training）+ 环境清理（构建产物/缓存/Git 历史/网络隔离）+ 专用 hack agent 对抗筛查（迭代至找不到可利用路径）+ 训练期审计 + GAR 对确认黑客清零（§4.2.6）。**证据**：论文报告确认黑客轨迹占比全程 <2%（Fig. 6b），且未报告"关闭防护后"的对照——防护有效性主要由构造性流程与自审计支撑。

**创新点 7：开源基础（对可复现性的实质贡献）。** 发布 MiMo-V2.6-Distill-Qwen-9B（77.4B token SFT，27.2B loss token，Table 4）、约 7k 任务的环境与验证器（code 3k/cyber 1k/general 1k/visual 2k，另有约 1k 音乐任务，Table 5）、端到端 RL 框架与 mini-harness（§7）。**原创边界说明**：根据本文 related work 与实验对比，只能确认作者声称的差异；三维 scaling 框架、GRS/GAR 组合等是否"首次提出"，还需要更完整的文献检索（尤其与同期 Kimi、DeepSeek、Qwen 系技术报告对照）。

**若移除各设计，论文报告了什么变化**：GAR 移除 → 通过率早早停滞、轮次与长度失控增长（Fig. 8，§4.3.2）；router 冻结移除 → 负载塌缩（Fig. 11）；GRS、行为正则、多层反黑客、Sample Mixer、R3/top-p 回放均**没有**移除对照，其必要性目前只有设计论证与运行日志层面的支持。

## 3. 作者如何解决？

**核心思路的直觉。** 论文的赌注是：下一代能力增长主要来自"模型在真实环境里做长程任务的数量与质量"，而不是再堆一个训练技巧。因此整个技术栈都围绕一个目标改造——让**混合任务、长时程、海量并发的 RL rollout** 能被稳定生产、被公平评分、被高效消费。为达到这个目标作者做了三层工作：底座（omni-modal 模型 + agent 中期训练，保证"有的可探索"）、放大（三维 scaling，保证"探索得足够多"）、防漏（奖励可信与训练稳定，保证"学到的是对的东西"）。

**运行流程展开。**

1. **底座：架构与预训练/mid-training。** 输入是文本、图像、音频的混合数据。模型沿用混合注意力主干：每 $N$ 个滑动窗口注意力（Sliding Window Attention, SWA，窗口 $W{=}128$）块后接 1 个全局注意力（Global Attention, GA）块，FFN 均为无共享专家的稀疏 MoE；首块用致密 FFN 稳定早期表示；另接多 token 预测（multi-token prediction, MTP）模块与视觉/音频编码器（Fig. 2，Table 1：Pro 70 层/384 专家/1.02T-42B 激活；Flash 48 层/256 专家/310B-15B）。推测解码器是 5 层块扩散草案（每前向预测 7 个 token）（§2.4）。预训练两阶段（纯文本→全模态），上下文 32K→256K；Flash 训 48T token（26T+22T），Pro 训 30T（27T+3T）（§3.1）。关键的中期训练（mid-training，§3.2）把上下文先 256K 后扩到 1M，并混入跨 coding/general/visual/research 的真实 agent 轨迹，为 RL 预留探索空间；同时把隐藏权重矩阵的优化器从 AdamW 换成 Muown（Muon + 行范数控制），并做 MXFP4 量化感知训练（quantization-aware training, QAT）适配低精度——这两个改动是为后续大批量 RL 做的**预适配**（§3.2）。

   ![MiMo-V2.6 总体架构（论文 Fig. 2）](/images/dailypaper/2026-10-09/2610.11959_fig2.png)

   图中左侧是输入侧：视觉编码器（MiMo-ViT，sink 增强 SWA，交替行/列主序以沿两个空间轴传播信息，§2.2）与音频编码器（两阶段：20 层 RVQ 分词 + patch 编码，25Hz→6.25Hz，§2.3）把多模态输入映射为共享 token 序列；中间是主干：$M$ 组"$N$ 个 SWA 块 + 1 个 GA 块"，SWA 负责廉价的局部依赖、GA 周期性汇聚全局上下文——这一分段结构是后面训练优化中"SWA 层在上下文并行下只交换窗口大小 KV、通信量与序列长度无关"的前提（§6.4）；右侧是训练期辅助的 MTP 块与推测解码路径。为什么需要它：长上下文 agent 任务（1M token 轨迹）的 rollout 与训练成本几乎全部由注意力决定，SWA/GA 交错是全文所有效率数字的地基。

2. **短 SFT 之后执行单次大规模 RL（"You Only RL Once"，§5）。** 输入：每个训练步从任务并集中采 1,568 个 prompt，每个 prompt 由 rollout 策略 $\mu_{\theta_{\mathrm{old}}}$ 生成 $G{=}16$ 条轨迹，共 25K 条序列、2.7–3.7B token（约每序列 110K–150K token，§4.1）。优化目标是带重要性采样比的 GRPO（Group Relative Policy Optimization，组相对策略优化）损失：

   $$\mathcal{L}(\theta)=-\mathbb{E}_{q,\{o_i\}}\left[\frac{1}{\sum_{i=1}^{G}|o_i|}\sum_{i=1}^{G}\sum_{t=1}^{|o_i|} r_{i,t}\,M_{i,t}\,A_{i}\,\log\pi_{\theta}(o_{i,t}\mid q,o_{i,<t})\right], \qquad \text{(Eq. 1)}$$

   其中 $M$ 是 token 级掩码、$A_i$ 是序列级优势、$r$ 是逐 token 重要性比。训练采用**提示均值（prompt-mean）损失聚合**（避免响应长度膨胀）、四项解耦的重要性比裁剪界（正/负优势各设上下界，初始均 $[0.2, 5.0]$，按策略熵在线调节）、异步 partial rollout（staleness 4），并用动态采样过滤全通/全错组（§5.1）。每步还要经 Sample Mixer 按目标分布凑批：为每个数据源按"目标组数 $B_i$/接受率 $r_i$×时长 $t_i$"分配并发预算（Eq. 6）、按"长期需求+当前缺口"的加权轮转调度（Eq. 7），启动/恢复阶段用 Sample Replay 补齐慢源（§6.3）。**模型决定什么、流程固定什么**：动作、工具调用、代码补丁全部由策略模型采样决定；环境状态迁移、奖励计算、并发与批组成由固定基础设施控制。

3. **环境与 harness（§4.2）。** 四类任务的构造各有侧重：代码任务五条合成路径（GitHub PR/issue 改写、员工真实需求、规范驱动、CodeMidas 源码反推、公开数据过滤），配三层监督质检——规范-测试对齐、八次重跑去 flaky、rollout 审计找假阳性/假阴性（§4.2.1，Fig. 4）；通用任务用"可重置的真实文件+本地软件 mock"造沙盒，多 agent 并行生成文件与数据库并用审查 agent 校验一致性（§4.2.2，Fig. 5）；视觉任务分开放式设计（先点式 rubric 稳定质量、再组内比较奖励相对改进）与高保真复刻（像素相似度为主）；网络任务用真实 OSS-Fuzz 漏洞复现，奖励=用 ASan/MSan/UBSan 报告中的**漏洞类型+崩溃位置**做规则匹配，取代 CyberGym 的修复补丁差分测试（后者会因补丁不完整或无关变更误判，§4.2.4）。所有 mini-harness 从同一最小 agent 循环派生，按域配置出 Code/General/Visual/Cyber 四类，训练样本组绑定单一 harness 以保组内统计可比（§4.2.5）。

4. **grader 与行为正则（§4.3）。** 评分是本文相对"纯测试奖励"的主要改动，两条流水线见 Fig. 7：GRS 离线用多次 rollout 对比生成任务专属 rubric（solution/behavior 两组标准），训练时对每条轨迹重打分，按 Eq. 2 与测试结果相乘；GAR 在线由 SFT 训练的 agentic grader 把组内通过/失败轨迹放进共享工作区对照，给通过方案按五维排序，用质量因子重分配正优势（Eq. 3），黑客轨迹先清零再参与组统计。

   ![组内评分两条流水线（论文 Fig. 7）：(a) GRS 离线 rubric；(b) GAR 在线评分与优势再分配](/images/dailypaper/2026-10-09/2610.11959_fig4.png)

   图中 (a) 的离线半环（上）把一组 rollout $\tau_{1:n}$ 变成 Solution/Behavior 两套 rubric，在线半环（下）对单条轨迹 $\tau_i$ 逐条打分，最后进 "Reward Refinement" 框与测试奖励相乘——它的作用是让"全通过组"仍能产生梯度；(b) 的在线环先由 Groupwise Grader 对比组内轨迹，一路做通过补丁排序、另一路把 Confirmed Hack 的 $R_i$ 置零，再按"Before→After"示意把低质量通过者的正优势挪给高质量通过者——它的作用是同时压制作弊与平庸通过，把学习信号集中在更好的解法上。为什么需要两套：高通过率子集用离线 rubric 成本低、可复用；其余任务在线比较更省 rubric 维护，但每步都占用 grader 计算（这也是 Fig. 3 右 grader 占比 12.7–14.2% 的来源之一）。

   **教学简化示例**（非论文实验）：设某组 4 条轨迹、3 通过 1 失败，组均奖励 0.75；三条通过者的质量因子 $f=(1.0, 0.5, 0.5)$，则 Eq. 3 的缩放 $\lambda=\frac{\sum_{j\in\mathcal{P}}A_j}{\sum_{j\in\mathcal{P}}f_jA_j}=\frac{0.75}{0.5}=1.5$：最好的一条优势从 0.25 放大为 $1.5\times1.0\times0.25=0.375$，两条平庸的降为 $1.5\times0.5\times0.25=0.1875$，通过者优势总和保持 0.75 不变——这就是"把正优势从低质量挪向高质量"的守恒式实现（Eq. 3 的 $A'$ 定义）。

   行为正则有两条：组相对长度惩罚（Eq. 4）在组通过率高于阈值 $A$ 时，对成功轨迹中超过参考分位 $\ell_q^{\star}$ 的部分按幂函数扣奖励，鼓励简洁成功解；段级行为惩罚（Eq. 5）对格式违规/工具调用错误的 token 做掩码或加重惩罚，并设计正/负优势质量守恒，避免过度熵增（§4.3.3）。

5. **训练稳定性与基础设施（§5.4，§6）。** RL 期间冻结 router（依据见 Fig. 11）。轨迹数据按四级结构组织（Sample→Sequence→Context→Segment），Segment 里只有模型生成轮次计损失；Penalty Module 把基础设施故障用规则标出并掩码，避免污染梯度。Harness Pool 用多租户 Ray actor 池承载高并发（每个 harness 代码库一个池），Payload Porter 把重负载（MoE 路由、top-p 候选、多模态像素）写进分布式存储、调度只用轻量元数据；训练-推理一致性靠 R3 路由回放 + top-p 候选集回放 + MXFP4 QDQ 对齐全权重，DFlash 草案模型由 RL 早期日志微调加速生成（§6.1–§6.4）。

6. **RL 之后的 MOPD2。** 对"难以设计可靠奖励"的域（长程游戏开发、科研、具身等），用多前缀多教师同策略蒸馏（Multi-Prefix Multi-Teacher On-Policy Distillation, MOPD2）：学生从教师轨迹或 SFT 数据切出的历史前缀出发，只采样一个新轮次，由指定域教师做 token 级监督（标准 MOPD 保留学生自主 rollout）（§5.6，Fig. 13）。这是一层能力"拼接"，把不可验证域的教师能力并进 RL 后的学生。

7. **输出与推理阶段变化。** 最终产出两档模型与评估结果（Table 3），以及开源套件（§7）。推理时与 SFT 时期相比：草案模型换成 RL 日志微调的 DFlash 块扩散（块 6、FP8）、路由与采样候选集与训练引擎严格对齐，其他结构不变。论文提出/自研的组件与直接使用的现有组件区分：GRS/GAR 目标函数、mini-harness、Penalty Module、Sample Mixer、反黑客流程为本文提出或适配；SGLang、Megatron-LM、Ray、GRPO、R3、Muon/Muown、partial rollout、DFlash、OSS-Fuzz 等均为直接使用或引用的已有系统（§6、§4 各处引用）。

**流程中的瓶颈与额外开销（作者自述）。** 主要有四处：partial rollout 的续跑需重建 KV（re-prefill），因此批量与 partial 策略要联动（§4.1）；grader 异步运行、延迟被隐藏但吃掉 12.7–14.2% 的算力（Fig. 3 右）；多模态轨迹可达 GB 级、需元数据/像素分离传输（§6.2）；长上下文打包产生内存峰值，Flash 甚至因 packing 阶段主机内存耗尽触发 CPU OOM（§5.5）。

## 4. 解决得怎么样？

#### 4.1 实验设置

**任务与基准。** 评估覆盖四类 agentic 能力（§5.2）：代码（DeepSWE v1.1、ProgramBench、内部 MiMo Code Bench）、网络安全（CyberGym、ExploitGym、ExploitBench、SEC Bench Pro、内部 MiMo Cyber Bench）、通用 agent（AutomationBench v1.0.6、Toolathlon-Verified、GDPval-AA v2.1、Agents' Last Exam、Terminal Bench 4.0/2.1、OSWorld-Verified、JobBench）、视觉（内部 MiMo Visual Coding，含 WebDev、Image2Code）。训练侧 RL 任务构成为 agentic 与竞赛编程 68%、通用工具使用 12%、美学设计 13%、上下文遵循 3%、网络安全 4%（§5.1）。

**系统配置。** 主角是 MiMo-V2.6-Pro（1.02T/42B 激活）与 Flash（310B/15B）；下游开源实验从 MiMo-V2.6-Distill-Qwen-9B（Qwen3.5-9B 上 SFT）出发。**基线**分三类：上一代 MiMo-V2.5-Pro；前沿模型 Claude Opus 5、GPT-5.6 Sol、Claude Fable 5（均可配置推理强度的在最高档 max 评估，§5.2）；开源对照 Qwen3.5-9B（§7）。**评价指标**：各公开基准按各自惯例，论文多处用 avg@3/avg@1/Pass@1；注意 **Table 3 未标注具体聚合口径**（这是后文质疑点之一）。

#### 4.3 机制证据

区分"有效"与"为什么有效"：

- **router 冻结是全文唯一完成"观察→干预→对策"闭环的机制实验**（Fig. 11）：它既有开关对照，又有参数还原的因果探针，证据可以排除"专家权重坏了"等替代解释。局限是单层（decoder layer 9）观察、单模型（Pro）。
- **GAR 的开关对照说明"在线评分改变训练动态"**（Fig. 8）：轮次与长度不再失控、通过率延续——但三个混杂未排除：(a) 与主实验的运行尺度不同（batch 128 vs 1,568×16、纯代码 vs 混合任务）；(b) 两条曲线步数不同轴（52 vs ~30 步）；(c) GAR 内部同时含"质量排序重分配"与"黑客清零"两种作用，图中无法分离哪个带来稳定性。论文也没有报告 GAR/GRS 在**主实验设置**下的开关对照。

![GAR 开关对照（论文 Fig. 8）：(a) 通过率、(b) 平均轮次、(c) 总 token 长度](/images/dailypaper/2026-10-09/2610.11959_fig5.png)

图中灰虚线为无 GAR、橙实线为有 GAR；三格共同讲一个故事：没有在线评分时策略用"更长、更多轮"去换通过率，直到触顶回落；有在线评分时相同步数内轮次被按住、通过率仍能继续爬。它是论文"scaling grader 有回报"的最直接实验，但如正文所述，尺度与混杂限制了外推。
- **GRS 与行为正则（Eq. 2/4/5）没有任何消融**；"乘法 rubric 奖励优于不加"、"长度惩罚改善泛化"目前只是作者主张（§4.3.1 称"keeps rubric supervision tied to test outcomes"是设计论证；§4.3.3 称"improves generalization"未给对照数字）。
- **反黑客 <2% 是监控值而非对照实验值**：论文没有训练一个"关闭多层防护"的版本做黑客率对照，也没有第三方复审计；hack agent 迭代到"找不到漏洞"的停止条件是自收敛的自审（§4.2.6）。
- **"token 效率提升"的证据方向要小心**：摘要称组内评分"引导更短、更省 token 的解"，机制证据是 GAR 组轮次平稳+长度缓增（Fig. 8 对照无 GAR 的失控增长）与长度惩罚（Eq. 4）；但训练全程的总 token 数**上升**（Fig. 9 下排），故该主张是"相对反事实更省"，不是绝对下降。
- **不能排除的替代解释**：能力提升同时伴随每任务 token 消耗上升（Fig. 9），可能是"更多探索/更长思考"的选择效应而非训练质量本身；模型升级了预训练/中期训练数据（30T–48T token 级别的 omni 语料）后才进入 RL，单次 RL 收益无法与数据侧升级分离。

#### 4.4 成本与适用范围

**论文报告的代价**：RL 后训练直接成本 Pro 260 万美元、Flash 90 万美元（§4.1）；单步训练量 25K 序列/2.7–3.7B token；grader 算力占 12.7–14.2%（Fig. 3 右）；运行跨"数千 GPU"，且 30 步内出现多类中断（GPU 双位错误、Kubernetes 故障、grader 网络失联、KV 池耗尽、MoE 专家负载失衡致 GPU OOM、打包阶段 CPU OOM，§5.5，Fig. 12）——这些中断与恢复本身就是规模化成本的一部分，但论文没有给出停机时长/算力浪费比例。**论文未报告**：GPU 型号与精确数量、总训练步数（正文未给出，仅 Fig. 12 图注与 Fig. 1/9 横轴显示约 30 步）、总 GPU 小时、能源/推理部署成本、grader 模型的具体规模与版本、内部数据与环境的获取与维护成本。**外部依赖**：通用任务的评分在 RL 中用自托管 MiMo-V2.6-SFT 模型当 grader（§4.2.2），GAR 用 SFT 训练的 agentic grader（§4.3.2），代码任务包含"授权数据供应商"数据（§4.2.1）——这些依赖无法从论文外部复现。

**适用范围与被解决的问题边界**：结论适用于"论文评估的 agentic 任务集合 + 论文的评分口径"（代码/通用工作流/视觉/网络四域）；对非 agentic 能力（如纯知识 QA、数学、多模态理解）RL 前后变化论文未报告；对部署成本、延迟、鲁棒性未报告；对更小或更大模型（除 9B 蒸馏版）是否适用未验证。**改善的**：长程代码任务的解质量与稳定性、多 harness 泛化、MoE 训练稳定性、奖励可信度工程；**仍未解决的**：与最强前沿模型在多个公开安全/终端基准上的差距、全流程可复现性（主模型闭源）、防护有效性的外部验证、方差与显著性报告缺失。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：核心主张"scaling RL compute 带来能力跃升"缺少等算力对照，成本-分数曲线只证明了相关性

- **原文依据**：Fig. 3 左把 DeepSWE 分数画在累计成本轴上（Pro 58.4→72.6、Flash 48.7→65.7，§4.1），Fig. 1/9 是训练步上的分数曲线；全文没有"同模型、同数据、只改变 RL 计算量（batch/步数/并行度）"的对照运行，也没有边际收益递减分析；唯一接近的计算侧对照 Fig. 8 又混合了 GAR 开关与尺度变化（batch 128）。
- **为什么重要**：这决定本文标题级主张（RL 计算是可以持续兑换能力的"燃料"，即 self-improvement 路线成立）是否被验证。分数随成本上升也可能只是"训练步数与 benchmark 特有任务的共同趋势 + 数据/模型升级的滞后效应"。
- **当前能够得出的判断**：证据不足。可以确认"论文的这一次运行内，成本增加伴随分数上升"；不能确认收益的因果来源是 RL 计算规模本身而非训练时长、任务配比或评分口径。
- **如何验证或补强**：报告一条同设置、不同计算预算（例如 1/4、1/2、全量）的三点 scaling 曲线；或在同一 checkpoint 上对 batch/步数做受控扫描；至少给出各配置的方差与统计检验。
- **严重程度**：主要问题。

#### 质疑："与前沿模型可比"的主张依赖内部基准与不完整的外部数字，公开基准上多处明显落后

- **原文依据**：Table 3 中 CyberGym、MiMo Cyber Bench、MiMo Code Bench 等内部或半内部基准缺少前沿模型对照值（标"-"），而这些行恰是 MiMo 大幅领先的行（如 CyberGym 94.0/95.1 vs V2.5-Pro 40.0）；在有外部数字的公开行上，MiMo-Pro 落后明显：Terminal Bench 4.0 34.9 vs 49.0、ExploitBench 47.9 vs 70.0/78.5/78.0、SEC Bench Pro 66.3 vs 79.1（§5.6）；Table 3 未标注指标的聚合口径，也未说明基线评估使用的 harness 与工具预算是否与 MiMo 一致（§5.2 只说"最高推理强度"）。
- **为什么重要**：影响结论范围与宣传口径。"achieving competitive performance against frontier models"（§8）在四类任务中的安全、终端、系统级编码上并不成立。
- **当前能够得出的判断**：结论被夸大。公平的能力比较目前只在部分基准上可做；内部基准上的领先无法排除"自家人出题+自家人评分"的选择效应。
- **如何验证或补强**：给出 Table 3 全部行的指标定义与 harness/预算说明；对内部基准开放给第三方或公布与公开基准的相关性；补齐前沿模型在 CyberGym 等行的数值或明示不可比。
- **严重程度**：主要问题。

#### 质疑：组内评分的关键消融缺失——GRS 无对照，GAR 消融尺度与主实验错配且两种作用混杂

- **原文依据**：GRS（Eq. 2）与行为正则（Eq. 4/5）在全文没有任何消融；GAR 的唯一对照（Fig. 8）使用纯代码任务、batch 128，而主实验是混合任务、batch 1,568×16（§4.1 vs §4.3.2）；GAR 内部的"质量排序重分配"与"确认黑客清零"两种机制在 Fig. 8 中不可分离；摘要与 §1 把"更多 grader 计算"列为三大 scaling 轴之一，但 grader 侧对最终 Table 3 的贡献没有独立实验。
- **为什么重要**：这直接关系创新性主张（grader scaling 是有效且必要的一轴）能否成立。若把 grader 计算减半或只做黑客清零不做质量排序，结果会怎样，论文没有回答。
- **当前能够得出的判断**：设计合理但证据薄弱。可以确认"在该小尺度代码实验中，加 GAR 后训练动态更稳、通过率延续"；不能确认其收益可推广到主实验设置，也不能确认具体哪一子机制起作用。
- **如何验证或补强**：在主设置下做 GAR 全关/仅黑客清零/仅质量重分配的三分支消融；对 GRS 做乘性奖励 vs 二值奖励的对照；报告 grader 计算量与收益的曲线。
- **严重程度**：主要问题。

#### 质疑：奖励黑客与"训练稳定"的监控指标由作者自定口径，缺少外部验证与反事实对照

- **原文依据**：确认黑客占比 <2% 来自训练期离线审计 + hack agent 自筛查（§4.2.6，Fig. 6）；没有"关闭防护"的对照运行；hack agent 的停止条件是"在任何环境找不到可利用路径"，收敛到什么程度受工具与审计策略限制；相反，Table 2 显示五类泄漏在早期实验中真实存在，且论文承认"随着策略进化可能发现未被发现的捷径"（§4.2.6 训练期审计段）。此外 Table 2 每行只有单次 rollout 的案例，未报告各类泄漏在训练批中的频率分布。
- **为什么重要**：这是"奖励可信"这一整条论证轴的基石。若 2% 是低估计，Table 3 中代码类成绩的含金量会被削弱；自我审计的循环性（用发现的案例去造对齐数据、再去防同类案例）可能留下未知类别的盲区。
- **当前能够得出的判断**：当前材料无法确认防护的完备性；可以确认的是论文提供了具体的泄漏模式学与一套可复制的清理流程（工程价值成立）。
- **如何验证或补强**：公开审计标准与脚本，让第三方在开源环境上复测黑客率；报告不做网络隔离/不做 Git 清理等单层开关下黑客率的变化；对确认黑客轨迹做人工抽检并报告抽检一致性。
- **严重程度**：次要问题（对能力主张的边际影响小于前三项，但涉及防护有效性的最终解释权）。

#### 质疑：可复现性边界——主模型与内部数据闭源，关键运行参数披露不足，方差与显著性全面缺失

- **原文依据**：论文给出 RL 超参（Muown lr $3\times10^{-6}$、无 warmup、梯度裁剪 1.0、staleness 4 等，§5.1）与大量基础设施描述，但未报告 GPU 型号/数量、总步数、运行时长；RL 数据包括"授权数据供应商"与内部员工数据（§4.2.1）、通用任务栅格与内部基准均不可外部获取；开源的是 9B 蒸馏模型、约 7k 任务环境与框架（§7）；表格与曲线没有误差棒、方差或置信区间，Table 3 连聚合口径都未注明。
- **为什么重要**：影响可复现性评估与方法可信度的量化。技术报告可以以披露换取信任，但本文最贵的部分（260 万美元的 RL 运行）给出的可核对信息有限；"数千 GPU"这样的量级描述无法支撑第三方估算或复现。
- **当前能够得出的判断**：9B 路径（§7）的可复现性较强——数据组成（Table 4）、环境与验证器（Table 5）、基准数字都可核对；旗舰路径（Pro/Flash）的可复现性弱。
- **如何验证或补强**：公开总步数、GPU 小时、失败恢复停机比例；发布主模型的评估脚本与 grader 版本；在公开基准上报告至少 3 次重复的均值与标准差。
- **严重程度**：次要问题。

## 6. 审稿式总评

> 作者发现大模型迈向自我改进的现实瓶颈不是单点算法，而是整套"生产-评分-消费"RL 管线的规模与稳定性，因此提出沿训练计算、环境与 harness 多样性、grader 计算三轴规模化，并通过组内评分（GRS/GAR）、mini-harness 多 harness 训练、router 冻结与多层反黑客流程实现。实验在一次数千 GPU 的混合任务 RL 上表明：成本与 DeepSWE 分数同向上升（58.4→72.6），最终模型在 9 个 agentic 基准上接近或超过前沿模型，多 harness 与反黑客监控均给出正面趋势；其中 router 冻结的因果诊断（Fig. 11）与 GAR 的动态对照（Fig. 8）证据较强，但等算力对照、GRS 消融、内部基准的外部可比性与统计稳定性（方差/口径）仍缺少充分支持。本文最有价值的部分是一份透明度较高的大规模 agentic RL 系统蓝图与开源基础（9B 模型 + 约 7k 任务环境 + 框架），最大的审稿风险是把"运行内成本-分数相关性 + 部分内部基准领先"放大成"RL 规模化普遍带来前沿级自改进"。

- **问题定义清晰度**：强——三维 scaling 框架、每类环境的具体失配条件与反黑客案例都定义得具体可查（§1、§4.2、Table 2）。
- **创新性证据**：中——GAR 正文标注引自同团队前作，GRS/行为正则无消融，三维框架以系统整合为主；路由器冻结诊断与 mini-harness 训练是有对照的实质增量（Fig. 11、Fig. 10）。
- **方法可信度**：中——公式与超参披露较全、机制描述可执行，但因果归因多数未做受控实验，grader 侧贡献未隔离。
- **实验支持力度**：中——覆盖面与绝对数字较多，公开/内部基准混杂、缺方差与显著性、部分结论（token 效率、持续提升）需要限定语。
- **可复现性**：中——9B 开源路径较强（Table 4/5/6/7 可核对），旗舰路径弱（内部数据、未披露硬件与总步数、主模型未发布）。
- **综合阅读价值**：高——对做 agentic RL 系统、奖励设计或 MoE 训练的读者，本文提供了少见的规模化工程细节与可操作的开源基线，同时其证据边界也值得引以为戒。
