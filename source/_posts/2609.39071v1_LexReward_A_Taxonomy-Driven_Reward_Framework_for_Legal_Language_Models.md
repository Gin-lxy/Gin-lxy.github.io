## 0. 一句话结论

LexReward 针对中文法律大模型在偏好训练/强化学习（RL）中"奖励信号粗粒度、只盯最终答案、缺乏领域可解释性"的问题，提出把法律回答质量拆成 Style（语言风格）、Element（法律要素）、Chain（推理链）三个维度的 taxonomy，逐条写成可由规则函数或 LLM-as-a-judge 执行的 rubric 奖励，并用 rubric 分数构造偏好数据来训练分维度奖励模型 LexRM（并用于 DPO、best-of-5 选择与 GRPO）。在论文报告的 CLASE、Legal Δ、LexChain 三个中文法律基准上，rubric 奖励与 LexRM 的选择/生成指标优于随机与"五模型平均"对照，GRPO 用 LexRM 作为奖励优于结果型奖励；但全部结果均为单次报告、无方差与显著性检验，rubric 分数从未与法律专家评分做一致性验证，且 DPO 的提升弱于同文 SFT——因此主要结论的成立范围限于"论文给出的三个中文法律基准上的初步验证"，尚不能推广为法律奖励设计的普遍结论。

## 1. 论文具体想解决什么问题？

**背景与任务。** 法律 LLM 已被用于法律问答与法律推理，RL 成为改进模型推理的重要手段，而 RL 中"奖励什么"直接决定模型向哪些质量维度优化（§1）。论文要回答的不是某个单一下游任务，而是更上游的问题：**一个法律领域的奖励应该评估什么，如何把这些要求变成可计算、可解释的奖励信号**（§1："without a structured definition of legal response quality, it remains unclear what a legal reward should assess"）。

**现有方法的失效条件。** 作者把现有做法归为两类（§1）：(1) 通用奖励模型或整体式（holistic）偏好判断，领域针对性弱、可解释性差（Abstract；§2.2 将 early work 概括为从整体人类偏好学标量奖励）；(2) 结果导向奖励（outcome reward），如判决结果/罪名/法条/金额的预测正确性（Cai et al. 2025; Zhang et al. 2025 等被引工作）。作者的论点：模型可能以不完整推理得出正确结论、遗漏关键事实、引用不恰当法条、或给出流畅但法律上不可靠的解释，这些失败无法被"最终答案正确率"捕捉（§1）。

**支撑问题判断的证据。** 一部分是自己的实验：用结果奖励做 GRPO（GRPO (rule)）时，Element 与 Chain 的平均分相对 SFT 基本不动（Table 2：Element 60.62→60.86，Chain 55.99→55.29），提升"集中在最终答案，而支撑答案的维度如 Legal Basis 停滞或下降"（§5.2.2）。另一部分是法律专家参与的定性分析：专家将多模型在多个法律基准上的回答与参考答案对比，归纳错误与未满足的质量要求（§3）。

**问题的层次区分。**"RL 奖励设计困难"是领域早已存在的一般问题；本文的新观察是——对法律回答而言，仅按结果定义奖励会系统性忽略推理质量，且"法律回答质量"缺乏结构化定义；本文实际解决的子问题是：为**中文**法律场景给出一个三维 quality taxonomy，将其逐条操作化为 rubric 奖励，并用三个中文法律基准验证其训练价值。需要注意的是，论文用自身 GRPO (rule) 实验展示了"结果奖励下 grounding 维度停滞"这一现象，但对"收益来自奖励维度化"的因果解释，与"稠密模型奖励 vs 稀疏规则奖励"等替代解释混杂（详见 4.3），论文未做进一步隔离。

**核心假设。** 把法律回答质量显式分解为 Style/Element/Chain 并逐准则打分，可以同时用于(a) 直接比较候选回答质量、(b) 生成偏好数据训练更强奖励模型 LexRM、(c) 作为 RL 奖励改进策略生成质量，且优于随机/平均选择与结果型奖励。

## 2. 创新点是什么？

**真正的技术增量（一段话）。** 论文的核心贡献不是发明某个新算法组件：rubric 评测、Bradley–Terry 奖励模型、task arithmetic 模型合并（Ilharco et al. 2023）、DPO、GRPO 都是现成方法。增量在于**领域形式化 + 系统操作化 + 中文法律实例化**：用"专家知识（top-down）+ 模型错误归纳（bottom-up）"构造法律回答质量三维 taxonomy（Style 5 准则、Element 4 类、Chain 4 准则），为每个细粒度准则设计"规则函数或 LLM 裁判"的 rubric 奖励（含基于 CJO 司法文书语料的归一化尺度），再用 rubric 分数按三档差距构造跨任务成对偏好数据，训练一组中文法律奖励模型 LexRM（分维度 + 合并版），并给出 TTS 选择、DPO、GRPO 三层验证。最接近的已有工作：通用 rubric/细粒度评测（Prometheus、multi-objective RM 等，§2.2）不含法律领域定义；法律领域已有工作（Chen et al. 2026 的 SCPRM）只做特定任务（刑法知识图谱推理的 process reward，§2.2）。

**创新点逐项：**

1. **三维法律质量 taxonomy（Style/Element/Chain）。** 新增：把"高质量法律回答"分解为表达质量（词法+句法 5 项）、法律要素覆盖（subjects/facts/statutes/decisions 4 类）、推理链质量（order/completeness/correctness/non-redundancy 4 项）的显式结构（§3，Fig. 2）。与已有工作差异：通用 rubric 方法（如 Prometheus）面向一般评测，不定义什么是"法律上好的回答"；SCPRM 是任务内的过程奖励，不是跨任务质量定义。证据：Table 3 的维度消融显示"聚合分在所有三个维度上整体最优，单准则偶尔以很小差距胜出"（§5.2.3）；移除单个子准则的后果有例证（如 Element 只用 subjects 时不检查法条引用，statute prediction 明显下降，加上 statutes 后恢复，§5.2.3）。未报告整维度移除实验（论文未报告），无法从消融中直接读出每个维度的独立贡献。

2. **混合式 rubric 奖励操作化（规则 + LLM 裁判）。** 新增：按"是否依赖输入上下文"为每个准则分派评测器——Style 用与 CJO 司法文书语料校准的确定性规则函数（KL 散度、连词率偏差、句长统计距离、3–6-gram 覆盖距离，Appendix A.1，Eq. (3)–(5)、(8)–(13)），Element/Chain 用 LLM-as-a-judge、且评测时不需要参考答案（§4.1，Fig. 3）。性质：属于已有组件（规则特征 + LLM 裁判）的法律领域组合；其"可解释"卖点在于每个分数对应一个具名准则。消融：论文未报告"规则 vs LLM 评测器"替换实验（论文未报告），无法确认两类评测器各自的不可替代性。

3. **rubric 分数 → 三档偏好数据。** 新增：对每 query 用五个模型各取一条回答并打分，按三档（高分 vs 邻近次高、高分 vs 中分、中分 vs 显著低分）构造同 query 配对，全同分 query 丢弃（§4.2，Appendix B.1）；并对三个任务分别产出偏好数据（Element：2,736 实例 → 2,244 对）。证据：DPO 在三个维度均优于原版模型（Table 2）。未报告三档设计的消融与丢弃比例（论文未报告）。

4. **LexRM：中文法律奖励模型族 + 合并。** 新增：以 Qwen3-8B 为共享骨干、按维度分别用 Bradley–Terry 损失训练奖励模型（Eq. (6)，LoRA），并在测得任务向量余弦相似度很小（平均 |cos| ≤ 0.03，最大不超过 0.14）后，用 task arithmetic 合并成单一多维度模型（Eq. (7)，$\lambda_d=1$），以减少推理时跑三个骨干的开销。证据：Table 1 中 LexRM-Style/LexRM-Chain 在对应数据集上取得表内最佳、LexRM-Element 排名第二（§5.2.1）；但合并版 LexRM-Merge 在 CLASE（69.75 vs 81.75）与 LexChain（46.84 vs 50.46）上都明显低于对应专家模型（§5.2.1 亦承认）。作者"LexRM 是首个面向中文法律场景的奖励模型族"的主张无法由本文证据确认：根据本文的 related work 和实验对比，只能确认作者声称的差异；是否构成首次提出，还需要更完整的文献检索。

5. **把学习到的奖励接入 RL 并与结果奖励对照。** 新增/组合："先 SFT（用 rubric 最高分候选），再用 LexRM 做 GRPO"的两段流程，与 outcome reward 的 GRPO (rule) 对照（§5.2.2，Appendix B.2）。证据：GRPO (RM) 在三个维度均最高（Table 2），Element 平均分比 SFT 高 6.04 分且五个指标全面提升（§5.2.2）。这属于对已有 RL 流程的领域化应用，不是新优化算法；"移除后变化"的对应实验就是 GRPO (rule) 对照组。

## 3. 作者如何解决？

**直觉。** 与其让一个整体打分器判断"这条法律回答好不好"，不如先把"好"拆成可分别检查的维度：表达是否像规范司法文书（Style）、要素是否齐全准确（Element）、推理链是否有序完整且合法（Chain）。每个维度再落到具体准则后，就能为它选择一个合适的评测器：本质属性（如用词分布、句长）用确定性规则比对参照语料；需要理解题目与回答关系（如要素覆盖、推理合法）的准则交 LLM 按 rubric 打分。这样得到的分数既可以当奖励直接选回答，也可以当成"哪条更好"的监督信号去训练更平滑的奖励模型。

**按运行流程展开：**

1. **输入。** 法律问题/案件 query（来自 JEC-QA 刑法题、LexChain 民事判决、CLASE 风格题等），以及候选回答池：五个模型（Qwen3-4B、Qwen3.5-4B、Qwen3.5-9B、Llama-3.1-8B-Instruct、gemma-4-12B-it）各生成一条回答（temperature 0.8、top-p 0.95，Appendix B.2）。

2. **rubric 奖励计算（§4.1）。** 对上下文无关准则用规则评测器：$r_k(y)=\operatorname{Eval}^{\mathrm{rule}}_k(y;\theta_k,\mathcal{C})$（Eq. (1)），其中 $\mathcal{C}$ 为高质量司法文书校准语料；Style 的五个准则各算一个与参照分布的偏差并按校准尺度归一，$R_{\mathrm{Style}}(y)=-\frac{1}{|\mathcal{K}_{\mathrm{Style}}|}\sum_{k\in\mathcal{K}_{\mathrm{Style}}}\widetilde{d}_k(y)$（Eq. (5)），逐项细节在 Appendix A.1（例如词特异性用法律术语分布的 KL 散度，归一化尺度 $s_{\mathrm{ws}}=12.3071$；连词率参照值 $\rho^*_{\mathrm{conj}}=0.0191$；参照句长统计 $\mu^*=64.7,\sigma^*=45.3$；Table 4 汇总 5 个尺度）。对上下文相关准则用 LLM 裁判：$r_k(x,y)=\operatorname{Eval}^{\mathrm{LLM}}_k(x,y;\rho_k)$（Eq. (2)），Element 由裁判对 subjects/facts/statutes/decisions 四个子维度各给 0–1 分并求平均（§4.1），Chain 在任务给出既定推理步骤时用规则函数检查顺序/完整性/正确性/非冗余，否则由 LLM 裁判按同样四项打分（§4.1、A.3）。**哪些由模型决定、哪些是固定流程：** 评测器类型与准则定义是固定设计；LLM 裁判的具体判断由模型决定；规则分数完全确定。

3. **偏好数据构造（§4.2）。** 每条 query 的五个候选按对应 rubric 打分，构造三档配对（高 vs 邻近次高；高 vs 中；中 vs 显著低），得到 $(x,y^+,y^-)$ 元组集合 $\mathcal{P}_d$；全同分 query 丢弃（Appendix B.1）。教学简化示例（非论文内容）：若某 query 下五个候选按某 rubric 得分为 0.9/0.85/0.6/0.6/0.3，则示意上会形成 (0.9,0.85)、(0.9,0.6)、(0.6,0.3) 之类的配对，用来同时监督"强回答间的细差"与"跨档差距"。

4. **训练了什么。** (a) 每维度一个奖励模型 $R_{\theta_d}$，共享 Qwen3-8B 骨干，用 Bradley–Terry 损失微调（Eq. (6)）：$\mathcal{L}_{\mathrm{BT}}^{(d)}=-\mathbb{E}_{(x,y^+,y^-)\sim\mathcal{P}_d}\left[\log\sigma\left(R_{\theta_d}(x,y^+) - R_{\theta_d}(x,y^-)\right)\right]$，LoRA、2 epochs、lr $1\times10^{-7}$、batch 32、DeepSpeed ZeRO-3（Appendix B.2）。(b) 合并模型：任务向量 $\tau_d=\theta_d-\theta_0$，按 $\theta_{\mathrm{merged}}=\theta_0+\sum_{d\in\mathcal{D}}\lambda_d\tau_d,\ \lambda_d=1$ 相加（Eq. (7)）。(c) 策略：每维度先在 1,000 条 query 上用 rubric 最高分候选做 SFT，再在另 1,000 条上做 GRPO（初始自同一 SFT checkpoint）；DPO 则直接从 Qwen3-8B 初始化并用偏好数据训练（Appendix B.1/B.2）。

5. **推理阶段的变化。** 奖励模型使用时：best-of-5 选择（TTS）直接取 LexRM 打分最高的候选，不需要参考答案；策略使用 LexRM 作为 RL 奖励函数在线打分生成结果（§4.1、§5.2.2）。

## 4. 解决得怎么样？

#### 4.1 实验设置

- **任务与数据集（§5.1.1，Appendix B.1）。** Style：CLASE（4,000 训练 / 1,000 官方测试），评分器用"在模型生成的负例上选中 gold 回答"的成对准确率评估，策略用 CLASE-Mix（0–10 分）评估；Element：偏好数据取自 JEC-QA 刑法题与 LexChain 民事判决（2,736 实例 → 2,244 偏好对），评测用 Legal Δ 的 in-domain 测试集 3,000 条（法条预测/罪名预测/案例分析/金额计算各 500、刑期预测 1,000），报告 5 项指标与非加权平均；Chain：LexChain（9,550 训练 / 1,000 官方测试），采用其原生 LLM 评测（GPT-4o-2024-05-13 对判决 7 个方面打分并给总分）。
- **模型（§5.1.2）。** 所有 LLM 裁判组件用 DeepSeek-V4-Flash API；所有被训练模型（SFT/DPO/GRPO/奖励模型）用 Qwen3-8B 骨干（LoRA）；候选池为 Qwen3-4B、Qwen3.5-4B、Qwen3.5-9B、Llama-3.1-8B-Instruct、gemma-4-12B-it 五模型。
- **基线。** 选择/打分侧：Random（Style 块，50.00）、Five-model average（Element/Chain 块；论文未给出该基线的精确定义）、Skywork-Reward-V2-Llama-3.1-8B、Skywork-Reward-V2-Qwen3-8B、Lawformer、LegalBERT；RL 侧：GRPO (rule)，即 Element/Chain 用结果型奖励、Style 用与参考文本的 ROUGE（§5.2.2）。
- **公平性。** 候选池、评测集对所有方法一致；作者主张 LexRM 用的训练数据"远少于 Skywork 奖励模型"（§5.2.1，属作者主张，具体数据量论文未报告）；训练算力/成本未报告；DPO 从原版模型直接初始化，而 SFT/GRPO 是另一条独立链路（Appendix B.2），三者的比较条件并不对等。
- **各实验回答什么。** Table 1：评分器/奖励模型的选择质量（TTS）；Table 2：奖励信号是否改善下游策略（DPO 与 GRPO 对照）；Table 3：同一维度内子准则是否互补；Fig. 3/4：评测与奖励的可复现口径。

#### 4.2 关键结果

- **Style 选择（CLASE 1,000 对成对准确率，§5.2.1，Table 1 Style 列）**：LexRM-Style 81.75%，Rubric 79.00%，Skywork-Qwen 78.50%，Random 50.00%——LexRM-Style 为该列表内最佳（加粗）。
- **Element 选择（Legal Δ 3,000 条测试集，5 指标平均，§5.2.1，Table 1 Element 块）**：LexRM-Element 66.32，Skywork-Qwen 68.04（表内最佳），Rubric 60.27，Five-model average 49.63——与作者"排名第二"的描述一致（§5.2.1）。
- **Chain 选择（LexChain 1,000 条测试集，7 项总分，§5.2.1，Table 1 Chain 块）**：LexRM-Chain 50.46，Skywork-Qwen 50.19，Rubric 47.80，Five-model average 45.41——LexRM-Chain 为该列表内最佳。
- **合并模型的退化（Table 1）**：LexRM-Merge 在 CLASE 69.75（比 LexRM-Style 低 12.00）、LexChain 46.84（比 LexRM-Chain 低 3.62）、Legal Δ 平均 65.77（比 LexRM-Element 低 0.55），但在 Legal Δ 的罪名预测（CCP）单列上以 58.27 取得 Element 块内最高。论文承认"在 CLASE 与 LexChain 上低于对应专家模型"，未给出原因分析。
- **下游策略（§5.2.2，Table 2）**：GRPO (RM) 在三个维度均为该维度块内最高——Style CLASE-Mix 8.54/10（GRPO (rule) 8.43、SFT 7.32、DPO 5.21、原版 3.08）；Element 5 指标平均 66.66（GRPO (rule) 60.86、SFT 60.62、DPO 58.13、原版 57.78），作者报告其比 SFT 高 6.04 分且 5 个指标全面提升；Chain 总分 56.40（GRPO (rule) 55.29、SFT 55.99、DPO 54.47、原版 53.55）。
- **DPO 的边界（Table 2）**：DPO 相比原版模型三个维度均提升（+2.13 / +0.35 / +0.92），但在三个维度上均低于同文 SFT（7.32 / 60.62 / 55.99）；论文只报告"优于原版"，未报告 SFT→DPO 组合，也未与其他偏好数据来源对照。
- **较弱/无提升的对照**：GRPO (rule) 的 Element 平均分与 SFT 几乎持平（60.86 vs 60.62），Chain 上低于 SFT（55.29 vs 55.99），且如作者所述，其提升集中在最终答案，grounding 维度停滞或下降（如 LexChain 的 Statute 项 37.90 vs SFT 39.40，§5.2.2）。
- **维度消融（§5.2.3，Table 3）**：聚合分整体最优，但优势普遍很小——Style：Overall 79.00 vs 单准则最佳 Syntactic 77.50（+1.50）；Element：Overall 60.27 vs Statutes 59.95（+0.32）；Chain：Overall 47.80 vs Completeness 47.43（+0.37）。单准则偶尔在个别列胜出（如 Element 的 Disposition 单准则 SPP-F 79.54 略高于 Overall 79.04）。所有表格均未报告多次运行的方差、置信区间或显著性检验（论文未报告）。

#### 4.3 机制证据

- **"有效"的证据**：Table 1 的选择优势、Table 2 的下游提升、Table 3 的聚合优于单准则，三者共同支持"这些奖励信号在这三个基准上有用"。
- **"为什么有效"的证据**：最接近机制验证的是 GRPO (RM) vs GRPO (rule)——两者从**同一个**分维度 SFT checkpoint 出发、用相同数据量做 GRPO，唯一差异是奖励函数（Appendix B.2），且结果与"结果奖励无法监督推理过程"的假设方向一致（§5.2.2：outcome reward"对结论是否经由完整、正确接地推理得到不敏感"）。但该对照同时混合了多个差异：LexRM 是稠密、可微习得的模型奖励，而 rule 奖励是稀疏/启发式（Style 甚至是 ROUGE 与参考文本比较）；"收益来自奖励维度化"与"收益来自更稠密/更域内的奖励模型"在本文设计下无法分离，论文也未做相应拆解实验（本段判断属分析者判断）。
- **替代解释未排除的部分**：rubric 分数与评测基准（尤其 Chain 的 GPT-4o LLM 评测、CLASE 的合成负例）之间是否存在同源偏好（同为 LLM 判断）未做检验；偏好构造用的 JEC-QA/LexChain 与评测域（Legal Δ in-domain、LexChain 测试集）是否来源重叠论文未报告；Style 的归一化尺度直接来自校准语料，尺度选择对最终 79.00 的准确率贡献未做敏感性分析。
- **"可靠性"这一核心主张的支撑强度**：Abstract 称"rubric-based rewards reliably distinguish legal responses of different quality"，直接证据只有成对选择（CLASE 79.00 vs 50.00）与下游表现两类间接指标；rubric 分数与人类法律专家判断的相关系数、评审一致性均未报告（论文未报告），因此"能区分质量"目前是操作层面的证据，不是构念效度层面的证据。

#### 4.4 成本与适用范围

- **论文实际报告的成本项**：训练配置（LoRA、ZeRO-3、lr $1\times10^{-7}$、batch 32、2 epochs，Appendix B.2）；LLM 裁判用 DeepSeek-V4-Flash API（默认 reasoning effort、最大输入 8,192 tokens，全部输入未截断）；评测依赖 GPT-4o-mini（CLASE 主观项）与 GPT-4o-2024-05-13（LexChain）。奖励定义在 reward time 不需要参考答案，这降低了标注依赖（§4.1，Abstract）。
- **论文未报告的成本项**：GPU 型号/数量/小时数、API 调用量与费用、推理时延、存储需求、法律专家投入的人数/工时、专家评审一致性、奖励/rubric 的失败率或游戏化风险——均"论文未报告"，本文不做估算。可复现性细节上的小缺口：Style 语料的"CJO ms"中"ms"未见展开定义（Appendix A.1）。
- **改善了什么**：在三个中文法律基准上，选择质量优于随机/平均对照，生成质量优于原版模型与结果型奖励（在论文设定内）。**未解决**：跨维度合并性能明显退化且无解释；"统一多维度奖励"被作者列为开放问题（Appendix C）；跨语言/跨法系适用性未测试（Appendix C）；rubric 效度与统计稳定性缺乏证据。
- **适用边界**：结论适用于中文法律材料（CLASE、JEC-QA、LexChain、Legal Δ）与 Qwen3-8B 量级骨干；对外依赖包括闭源 API（DeepSeek-V4-Flash、GPT-4o 系列）与两个被引基准的评测协议。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：rubric 与奖励模型的"法律质量"判断从未与法律专家人工评分做一致性验证，核心构念效度缺直接证据

- **原文依据**：taxonomy 声称"with the assistance of legal experts"并由专家做自下而上的错误归纳（§3），但全文未报告专家人数、资质、标注量或一致性（Kappa 等）；Element/Chain 的实际打分由 DeepSeek-V4-Flash 单模型裁判完成（§5.1.2，Fig. 3/4）；"reliably distinguish"的支撑仅有 CLASE 成对准确率与下游基准表现（Abstract，§5.2.1）。
- **为什么重要**：论文的立论是"taxonomy 定义了真正的法律质量"，若 rubric 分数只与 LLM 裁判的偏好一致、而与法律专家判断相关性未知，则所训练的 LexRM 可能继承裁判的风格偏差（如对特定套路的偏好），"可解释的细粒度奖励"未必对应法律上正确的细粒度质量。
- **当前能够得出的判断**：证据不足。可以确认 rubric 分数在下游任务上有预测力，但无法确认其与专家法律判断的一致性；论文未做此验证。
- **如何验证或补强**：抽取不同分数档的候选回答，由多名法律从业者独立盲评，报告与 rubric/LexRM 分数的相关性与评审者间一致性；补充"针对裁判偏好构造的对抗样本（风格化但法律上错误）"的测试。
- **严重程度**：主要问题。

#### 质疑：全部关键结果均为单次运行的点估计，无方差、置信区间或显著性检验，"最佳"与"聚合最优"依赖很小的差距

- **原文依据**：Table 1–3 全部为单值，无 error bar 或重复次数说明；LexRM-Chain 对 Skywork-Qwen 的优势仅 0.27（50.46 vs 50.19，Table 1），Table 3 中聚合对单准则的优势最小仅 0.32/0.37（Element/Chain），论文以"小差距"一笔带过而未检验（§5.2.3）；生成候选用 temperature 0.8、top-p 0.95 采样（Appendix B.2），本应存在采样方差。论文未报告随机种子数。
- **为什么重要**：论文的主要声明——LexRM 达到"best overall results"（§5.2.1）、多准则"aggregation gives the best overall score"（§5.2.3）——恰好落在统计噪声可能覆盖的区间；LLM 评测（LexChain 用 GPT-4o 打分）自身也有波动。
- **当前能够得出的判断**：当前材料无法确认这些比较的统计稳定性；部分"最佳"结论可能被更大规模的重复实验推翻。
- **如何验证或补强**：多随机种子重复选择实验与训练、报告均值±方差；对表内关键比较做配对检验（如 bootstrap/置换检验）；报告评测 LLM 的重复一致性。
- **严重程度**：主要问题。

#### 质疑：DPO 的收益只与"原版模型"比较且全面低于同文 SFT，偏好数据相对于 SFT 数据的增量价值不明确

- **原文依据**：Table 2 中 DPO 三个维度均低于 SFT（5.21 vs 7.32；58.13 vs 60.62；54.47 vs 55.99），论文仅表述为"DPO improves over the vanilla model"（§5.2.2）；DPO 直接从 Qwen3-8B 初始化，而 SFT 用"rubric 最高分候选"训练（Appendix B.1/B.2）——两条链路起点与目标均不同。
- **为什么重要**：贡献三/四声称"用 rubric 奖励构造的偏好数据改善生成"，但同预算下 SFT（同样由 rubric 挑选数据）在所有维度更强，且未报告 SFT→DPO 的组合或 DPO 用其他偏好数据的对照，"偏好数据有用"的结论因此偏弱；这也影响对"偏好数据构造三档设计"这一创新点的评价。
- **当前能够得出的判断**：结论被部分夸大（"improves across all three dimensions"字面为真，但读者易误读为偏好训练优于监督方案）；驱动 DPO 提升的因素（数据筛选 vs 训练目标）无法从现有对照分离。
- **如何验证或补强**：报告 SFT→DPO 叠加结果；对比 DPO 使用 rubric 数据 vs 使用通用偏好数据（如 Skywork 数据）在同一初始化与预算下的表现；给出 DPO 的多 seed 结果。
- **严重程度**：主要问题。

#### 质疑：选择实验缺少更强基线——无池内最佳单模型、无 oracle best-of-5 上界，且"Five-model average"未给出定义

- **原文依据**：Table 1 的选择基线只有 Random（仅 Style 块，50.00）与 Five-model average（Element/Chain 块）；正文只出现名称（§5.2.1），未说明该基线如何计算（分析者推断可能指五个候选模型各自输出的平均表现，但论文未给出定义）；没有报告五模型各自的个体成绩或按 ground truth 选择的上界。
- **为什么重要**：没有个体成绩与 oracle 上界，就无法判断 LexRM 的选择是"接近天花板"还是"仍落后于简单策略（如选某一强模型）"；若某单模型本就接近 LexRM 的选择结果，框架的实用价值会被高估。
- **当前能够得出的判断**：论文未报告关键对照，现有证据不足以评估选择收益的相对大小。
- **如何验证或补强**：补充五个候选模型各自的 benchmark 分数与"按参考答案选择"的 oracle 上界；明确 Five-model average 的定义与实现；报告选择分歧案例的定性分析。
- **严重程度**：次要问题。

#### 质疑：LexRM-Merge 在 CLASE/LexChain 上显著退化但未分析原因，"低余弦相似度→可加合并"的论证缺乏因果支持

- **原文依据**：Eq. (7) 用固定 $\lambda_d=1$ 的 task arithmetic 合并，动机是任务向量两两余弦相似度小（平均 |cos| ≤ 0.03、最大 0.14，§4.2）；结果 LexRM-Merge 在 CLASE 69.75（vs 81.75）、LexChain 46.84（vs 50.46）明显变差，论文仅承认"falls below the respective expert models"（§5.2.1），未解释退化机制，也未报告 λ 权重搜索或层次分析。
- **为什么重要**：合并被宣传为"去除推理时三骨干"的实用组件（§4.2），但其代价在 2/3 维度上很大；余弦相似度只说明"参数更新方向不同"，并不能推出线性相加不会破坏各维度能力——这是对方法主张（多维度可组合）的重要反例，却未被正面处理。
- **当前能够得出的判断**：现象确凿且方向不利，原因未明；现有证据不支持合并策略的可用性，也不足以否定"维度可分"这一更弱的主张。分析者推断退化可能与某维度主导权重方向的干扰有关，但论文未验证。
- **如何验证或补强**：对 $\lambda_d$ 做网格/学习式搜索；逐层分析合并前后的打分行为；报告各维度上合并模型的分数分布与冲突样本；若合并不可行，明确限定结论为"维度专用模型"。
- **严重程度**：次要问题。

## 6. 审稿式总评

> 作者发现法律 LLM 的现有奖励（整体式判断或结果导向）无法覆盖法律回答的多维质量、结果奖励下推理接地维度停滞，因此提出 LexReward：用专家知识加错误归纳构造 Style/Element/Chain 三维质量 taxonomy，通过规则函数与 LLM 裁判把每个准则操作化为 rubric 奖励，再用 rubric 分数构造三档偏好数据，训练中文法律奖励模型族 LexRM 并接入 DPO、best-of-5 选择与 GRPO。实验在 CLASE、Legal Δ、LexChain 三个中文法律基准上表明：rubric 与 LexRM 的选择优于随机/五模型平均，GRPO 用 LexRM 作为奖励优于此前的"结果奖励"方案且 Element 平均分较 SFT 提升 6.04；其中"学习到的稠密奖励优于结果型奖励"这一对比证据相对较强（同 checkpoint 单变量对照），但"奖励维度化是收益来源"的机制解释、rubric 与法律专家判断的一致性、以及全部数字的统计稳定性仍缺少充分支持。本文最有价值的部分是把"法律回答质量"落成一套可复核、可复现的评测与训练流水线（含公开提示词与归一化细节），最大的审稿风险是效度与统计证据链的缺口——核心结论建立在单次运行的小差距之上，且从未接受法律专家评分的外部校验。

- **问题定义清晰度**：强。三维 taxonomy 把模糊的"法律回答质量"拆到可打分的叶子准则，问题陈述（§1）与设计（§3–4）对应清楚。
- **创新性证据**：中。组件（rubric、BT 奖励模型、task arithmetic、DPO/GRPO）均为现成方法，增量集中在领域形式化与操作化；"首个中文法律奖励模型族"的说法按规范只能确认为作者主张；维度消融显示互补性但幅度小。
- **方法可信度**：中。流程完整、公式与提示词披露到可复现级别；但评委 LLM 单模型、无专家一致性验证，合并模型的退化未有解释。
- **实验支持力度**：中。三个基准、三层验证（选择/DPO/GRPO）且如实报告了合并退化与结果奖励的停滞，属诚实报告；但无方差/显著性、无 oracle 上界与个体基线、DPO 对照弱于 SFT。
- **可复现性**：中。超参与评测口径详尽，提示词以英文翻译公开；但代码库链接在核查时 404，CJO 语料来源细节（"ms"）未展开，闭源 API 版本随时间漂移。
- **综合阅读价值**：中。对做法律领域对齐、奖励设计与 rubric 评测的读者有直接参考价值（尤其失败维度的如实呈现）；对一般 RLHF 读者，方法层面的新意有限，收益更在领域落地细节。
