## 0. 一句话结论

统一多模态模型（同时会生成和会理解）可以给自己挑错，但论文指出已有的自反馈训练要么用自产出做 SFT/偏好数据、要么训练"按反思修图"、要么把评估折成奖励，都没有把"纠正意见"直接蒸馏进原始 prompt 条件下的生成策略；UniEvo-VL 的做法是让同一个模型扮演两个角色——教师端看"原 prompt + 由自己 critique 合成的修正 prompt"，学生端只看原 prompt，在**学生自己采样的去噪轨迹状态**上逐状态匹配两侧的一步预测，只更新生成器 LoRA，不用修正后的图像当目标、不用奖励。证据边界：在论文报告的 GenEval/GenEval2/OCR 三个基准、Qwen-Image-2512 生成器与"Qwen3-VL 自评（加后验验证）"配置上，同一组对的直接生成分数确实全线高于 Base（如 GenEval 0.748→0.818，GenEval2 Soft-TIFA 31.92→35.07，均为 Table 2 配对口径）；但更强的头条数字（GenEval2 32.97→35.53、GenEval 0.882）来自接入外部闭源 critic（GPT-5.6-Luna）的配置，且不经验证的"自评直出"配置在 GenEval2/OCR 的 native 指标上低于 Base——因此证据支持"在特定 critic 与配方下，critique 可以被蒸馏为直出生成能力的提升"，尚不支持"模型能稳定地靠自身反馈无差别地自我进化"。

## 1. 论文具体想解决什么问题？

**研究背景与具体任务。** 现代统一多模态模型（MMM，如 GPT-4、Gemini 一系）把视觉生成与视觉理解合在同一个系统里，因此它们天然具备"给自己挑错"的能力：生成一张图，再看一眼，指出图文不符之处（§1，原文事实）。论文的任务类型属于生成侧训练（图像生成），研究对象是 flow-based 生成器（以 Qwen-Image-2512 为代表），目标是把"理解分支产生的纠正信息"转化为"生成分支在原始 prompt 下的直接提升"，而不是让模型在推理时多刷几轮反思（§1、§2）。

**现有方法如何处理。** 论文把相关做法分四类（§1、§4，原文事实）：（i）用统一模型的理解分支给自生成图像打分，构造 SFT/偏好优化数据（Han et al., 2025）；（ii）把自生成交互重构为 captioning、judgment、reflection 训练任务，给统一模型分配 proposer/solver/judge 角色（Han et al., 2026, UniCorn）；（iii）训练模型按显式 reflection 反复修图（Zhuo et al., 2025, ReflectionFlow）；（iv）把多模态评估聚合成奖励做 test-time 策略优化（Tan et al., 2026, Meta-TTRL），以及扩散侧的奖励型更新（Flow-GRPO、DiffusionNFT）与扩散 OPD 系列（DiffusionOPD、D-OPSD）。

**论文自认的缺口（概念性论证，不是实测现象）。** 作者指出：上述路线都没有把"纠正性条件（corrective conditioning）"沿生成器**自己的采样轨迹**直接蒸馏进"原始 prompt 条件策略"。一句 critique（如"补上缺失的物体"）描述的是期望的修正结果，但它本身不指定生成器在中间去噪步上应该如何改变自己的预测（§1，作者主张）。这是一个"监督形态"层面的论证：结果层面的目标（修正后的图、标量奖励）不告诉模型沿途每一步该怎么走。

**支撑问题判断的证据与原因归因。** 该缺口陈述主要靠 related work 的对比与自建系统的实验间接支持；第 2 节给出论文的解法假设——**验证比生成容易**（verification is easier than generation，引 Hübotter et al., 2026; Zhao et al., 2026，§1，作者引用）：既然模型"看懂哪里错了"比"一次画对"容易，就可以让理解分支提供特权信息（privileged information），再通过 on-policy 自蒸馏把这份"只有老师看得到的信息"压进学生参数。

**核心假设。** 把 critique 合成的修正 prompt $\widetilde{p}$ 作为**只对教师可见**的条件，配合在**学生自己访问的状态**上做逐状态（per-state）转移匹配，可以把纠正"内化"到不带修正提示的学生策略里；检验标准是：训练后**直接从原 prompt 生成**的分数提高，且这种提高不能仅由推理期套一次反思来解释（§2.3、§3.4.1，作者主张）。

**三类问题的区分（审稿人判断）。**（i）领域早已存在的一般问题：统一多模态模型的自我改进、生成-理解互相增强、自反馈数据构造，已有多条工作线（§4）；（ii）本文的"新观察"更像**新论证 + 新系统组合**：把 OPSD（on-policy self-distillation）与"自 critique 合成特权 prompt"接起来，并用"训练收益 vs 反思收益"的配对评估把内化效果从推理期纠错中分离出来——这属于设计层面的贡献，不是对某现象的首发发现；（iii）论文实际解决的具体子问题是：在 Qwen-Image-2512 + Qwen3-VL 反馈、按 GenEval / GenEval2 / OCR **分别训练**的设定下，提升各基准的直接生成分数（§3.1）。

## 2. 创新点是什么？

**一段话概括。** 技术增量可以概括为一件事：**把 critique 转写成的 revised prompt 当作 privileged condition，用同一模型（EMA 教师）在学生自己采样的去噪轨迹上，逐状态匹配"教师带修正提示的一步预测"与"学生只有原 prompt 的一步预测"**；采集端配一个"改写后重生成、再对原 prompt 复评"的 post-revision verification 过滤，评估端配一组"训练前后 × 直出/单次反思"的配对实验。这里没有新的损失族（OPSD 框架来自已有工作），也没有新的反馈来源（critique 由模型自己的理解分支产生），创新点在于这套组合把一个此前用于"合并多个独立训练专家"的机制（DiffusionOPD 式）改用于"自我纠正经验的固化"，并给出可靠性过滤与分离式评估。

**逐项分析：**

1. **Critique-conditioned on-policy self-distillation（核心机制）。** 新增的机制是训练信号的构造方式：教师 $\mathcal{M}_{\bar{\theta}}$ 是学生自己的 EMA 版本（$\bar{\theta}\leftarrow\beta\bar{\theta}+(1-\beta)\theta$，$\beta=0.999$，Appendix A.2），它唯一区别于学生的输入是**由 critique 合成、且通过后验验证**的修正 prompt $\widetilde{p}$；监督发生在学生轨迹 $\tau=\{s_0,\dots,s_T\}$ 的状态 $s_j$ 上，损失为两侧一步转移的散度（§2.3，Eq. 3）：
   $$\mathcal{L}(\theta)=\mathbb{E}_{(p,\widetilde{p},\epsilon)\sim\mathcal{A}_k,\ \tau\sim\mathcal{M}_\theta^{\mathrm{gen}}(p,\epsilon),\ s_j\sim\tau}\ D\!\left(\mathcal{M}_\theta^{\mathrm{gen}}(\mathrm{sg}[s_j],p),\ \mathrm{sg}\!\left[\mathcal{M}_{\bar{\theta}}^{\mathrm{gen}}(\mathrm{sg}[s_j],\widetilde{p})\right]\right)$$
   与最接近工作的差异（§4，原文事实）：OPD（Agarwal et al., 2024）是语言模型上的学生轨迹蒸馏、无外部特权条件；SDPO（Hübotter et al., 2026）把反馈条件的 next-token 预测蒸进语言策略；DiffusionOPD（Li et al., 2026）蒸馏的是**独立训练好的任务专用教师**；D-OPSD（Jiang et al., 2026）让自教师条件在**目标图像**上做监督学习；ReflectionFlow 只在推理期迭代精化；UniCorn 是角色化重构训练任务。本文的差异在于：特权条件来自"对自己输出的 critique 之文本转写"（不是目标图、不是独立教师），目标不依赖配对的修正图像，也不用标量奖励、不用梯度穿过 critic（§4 末尾段）。**性质判断：这是已有组件（OPSD + 自反馈采集 + EMA 自教师）的新组合 + 采集端设计，不是全新范式。**
   **原文证据与"移除会怎样"：** 论文最接近"移除该设计"的对照是 Appendix E 的 SFT 尝试——直接用"被验证接受的修正图像 $I'$"当训练目标（即去掉特权文本条件、改学图像结果），报告为"未取得生成提升、学生在训练中快速退化"（Appendix E，原文事实）。此外还有教师 EMA 衰减扫描（0.99/0.995/0.999，Appendix A.5、Fig. 5）：0.995 与 0.999 优于 0.99，主实验取 0.999。**但没有直接消融"特权条件本身"**（例如教师也只看原 prompt，或学生也看 $\widetilde{p}$），因此"特权信息导致增益"这一因果链在实验上仍是间接的（审稿人判断，详见 §5）。
2. **Post-revision verification（采集过滤）。** 新增流程步骤：合成 $\widetilde{p}$ 后不直接训练，而是用**同一噪声** $\epsilon$ 重新生成 $I'=\mathcal{M}_\theta^{\mathrm{gen}}(\widetilde{p},\epsilon)$，再拿 $I'$ 对**原始 prompt** $p$ 复评，只有第二次评估有效且接受（$a'=1$）才收录三元组 $(p,\widetilde{p},\epsilon)$；$I'$ 只用于准入判断，绝不是训练目标（§2.2、Appendix A.2，原文事实）。对应的问题：改写 prompt 不保证真的修好了原错误——Appendix D.4 的 Table 8 显示，不做验证时 GenEval2 训练曲线中途回落（如第 160 次更新较 120 次下降）、OCR 指标在噪声中波动甚至终点低于起点（原文事实），作者据此把验证定位为"训练信号可靠性的保险"（作者主张）。
3. **分离"已内化的改进"与"推理期纠错收益"的配对评估。** 对同一批 prompt/seed，训练前后各测"直接生成"与"允许一次 critique 反思"两种条件（Table 2），从而区分：训练把多少收益搬进了直出、反思在训练后还剩多少增量。这样的配对分解在同类自改进工作中不常见，是评估设计上的增量（§3.4.1，审稿人判断）。
4. **可复现接口的披露。** Appendix F 全文给出 semantic/text/quality 三个 critic 提示词与 prompt-synthesis 提示词（含 few-shot 示例与输出约束），并给出记录样例（如 "a photo of two sinks" 的计数修正、"Freedom 1776" 的文字修正，F.6–F.7），这在同类论文中披露得相当具体（原文事实）。

**原创边界说明：** 根据本文 related work 与实验对比，只能确认作者声称的上述差异；例如 OPSD 术语与流程本身沿用（Agarwal et al., 2024; Zhao et al., 2026; Fang et al., 2026; Li et al., 2026），"critique 作为特权信息蒸进直出策略"是否构成首次提出，需要更完整的文献检索才能判断（审稿人判断）。

## 3. 作者如何解决？

**直觉。** 把去噪过程想成走迷宫：学生只能看到题目（原始 prompt），老师却先看过一遍自己走错的录像、再拿到一条"纠正过的题目表述"（修正 prompt），于是老师知道在当前这个位置下一步应当往哪偏一点。UniEvo-VL 不让学生抄老师的最终答案（那不现实——老师手里有提示），而是让学生在**自己实际走过的每个位置**上，模仿"老师拿着提示时的下一步动作"，随着训练把这种"下一步往哪偏"的感觉压进学生参数。**教学简化示例（用于说明直觉，非论文实验）：这类似驾校教练坐在副驾纠正方向盘——学员最终要独立开车（原 prompt 直出），但先在"学员自己开过的那段路上"接受逐点的方向纠正，而不是事后看教练开一遍全程。** 论文选择这条路线还有一个前提：验证（看错在哪）比生成（一次做对）容易（§1，作者引用的假设）。

![UniEvo-VL 的概念循环：从理解到自进化](/images/dailypaper/2026-10-01/2609.38721_fig1.png)

**Fig. 1 解读（上图）。** 左侧 "User Intent" 是用户意图（文本指令 + 可选的视觉线索：Style/Object/Layout）；中间 "Self-Evolving Generation" 是本文要"内化"的推理期循环——Draft（按指令出草图）→ Critique（对自己的图给自然语言反馈，图中示例是"应为四只小猫而不是三只、最右一只应为灰或橙色、保持风格"）→ Refine（按反馈重生成）→ "Iterate & Self-Evolve" 回环；右上是**可选的外部 critic 分支**（对应 §3.4.2 的 GPT-5.6-Luna 实验）；右侧 "Better Generation" 列出循环想要换来的结果：正确物体计数、更高语义保真、更强属性绑定、更好画质、更符合意图。为什么需要这张图：它把"推理期多轮自纠"与"训练期把纠正固化下来"两种自改进形态并置——论文的立场是后者（让部署时不再需要循环也能受益）。

**整体流程（按实际运行顺序；主实验为"带验证"配方，Table 5）：**

1. **输入。** 训练用 prompt 流：GenEval 格式的训练元数据、GenEval2 风格的另一套组合式训练集、以及 OCR 视觉文字渲染的约 2 万条训练 prompt（§3.1、Appendix C；OCR 测试集 1,018 条）。三个任务**分别训练各自的生成器 LoRA**（§3.1，原文事实）。
2. **草稿生成（采集阶段，无梯度）。** 学生生成器以 $I=\mathcal{M}_\theta^{\mathrm{gen}}(p,\epsilon)$ 出草稿，$\epsilon$ 用记录在案的种子（§2.1，Eq. 1）。
3. **多轴 critique。** 由固定反馈管线（Qwen3-VL-8B-Thinking）沿三个镜头检查：semantic（对象身份、精确计数、属性、空间关系）、text（要求渲染的文字是否拼写/数量/清晰正确）、quality（结构畸形、构图、光影等渲染缺陷）；每个镜头要么给一条可执行的修正、要么输出固定语 "No issue on this lens."，最终只把文本结论往下传（§2.1、Appendix B、F.1–F.4）。评审输出 $(c,a)$：$a\in\{0,1\}$ 为是否可直接接受；$c$ 为纠正性反馈。$a=1$ 的草稿被跳过——没有纠正样本可用（Algorithm 1 第 9–10 行）。
4. **修正提示合成。** 对需要修正的草稿，合成模型（Qwen3-VL-8B-Instruct）把 critic 笔记合并成一条**自洽、独立可读的新 T2I prompt** $\widetilde{p}=\mathcal{M}_\theta^{\mathrm{und}}(p,c)$（Eq. 2）。论文强调合成角色：critique 往往是"对当前图的负面描述"，而生成器需要的是"期望终态的正面规格"，合成环节负责这个转写；且修订后的提示要把原需求完整重述（因为重新生成时模型看不到原图）（Appendix B、F.5）。
5. **后验验证（post-revision verification）。** 用同一 $\epsilon$ 以 $\widetilde{p}$ 重生成 $I'$，再把 $I'$ 对**原始 prompt** $p$ 复评；只有第二次评估有效且接受才把 $(p,\widetilde{p},\epsilon)$ 收入训练集 $\mathcal{A}_k$；畸形反馈、无效修订、复评未通过的修订全部丢弃（§2.2、Algorithm 1 第 12–19 行、Appendix A.2）。
6. **On-policy 自蒸馏（训练阶段）。** 对每个三元组，学生沿 $\tau=\mathrm{sg}[\mathrm{Rollout}_\theta(p,\epsilon)]$ 走一条 20 步轨迹；在选定的**高噪声步**（20 步中第 0–5 步、噪声占比 30%）上，学生条件 $p$、教师条件 $\widetilde{p}$，两侧用同一 CFG 规则（$g=4$）预测下一步潜变量 $\mu_{\theta,j}(z,p)=z+\Delta\sigma_j\,v_\theta^{(g)}(z,\sigma_j,p)$（Eq. 4–5），损失为平方 L2：$\ell_j^{\mathrm{flow}}=\frac{(\Delta\sigma_j)^2}{2d}\|\mathcal{M}_\theta^{\mathrm{gen}}(\mathrm{sg}[s_j],p)-\mathrm{sg}[\mathcal{M}_{\bar{\theta}}^{\mathrm{gen}}(\mathrm{sg}[s_j],\widetilde{p})]\|_2^2$（Eq. 6–7）。梯度只进学生 LoRA；生成、评估、合成、教师预测全部 detached；EMA 在每次优化步后更新（§2.3、Appendix A.1–A.2、Algorithm 1 第 23–32 行）。
7. **哪些由模型决定、哪些由流程固定。** 由模型决定：草稿、critique 内容、修订文本、两侧去噪预测；由固定规则决定：接受/拒绝（$a$、验证结果）、噪声步集合 $\mathcal{J}$、CFG 与调度器、EMA 更新、采集的 seed 策略（Algorithm 1；§2，原文事实）。
8. **需要训练什么。** 只训练**生成器 LoRA**（rank/alpha 16/16，学习率约 $3\times10^{-4}$，AdamW，4×H200，Table 5）；base 权重、文本编码器、VAE、critic/synthesis 组件全部冻结（§3.1、Appendix A）；每次优化步后由 EMA 产生下一个 batch 的教师（$\beta=0.999$）。
9. **推理阶段的变化。** 部署时直接用原 prompt 直出，**无任何额外模块或修订开销**；论文另给"可选一次反思"的推理形态（接受的草稿直接保留，否则修订重生成），两者分开报告，且所有评估始终以原始请求为打分对象（§3.1、Appendix A.3）。输出即一个演化后的生成器 adapter。

**关键实现细节与作者的诚实说明（值得记录的两点）：** 其一，论文在 §2.3 用 KL/JS 一类散度泛化描述 $D(\cdot,\cdot)$，但 flow 实例化实际上是**确定性转移匹配**（等价于按采样间隔平方 $(\Delta\sigma_j)^2$ 加权的速度匹配），作者明确写下 "it is not an exact stochastic-policy KL or JS divergence"（Appendix A.1，原文事实）。其二，方法要求两侧有"架构兼容的局部预测"；论文自己注明自回归架构需要另定义 next-token 分布上的损失，"our experiments validate only the flow instantiation"（Appendix A.1，原文事实）。

![UniEvo-VL 训练回路：三面板总览](/images/dailypaper/2026-10-01/2609.38721_fig2.png)

**Fig. 2 解读（上图）。** 面板 (a) "Generation and Understanding"：文本 prompt $p$ 交给 Student Policy 生成草稿，Multi-Axis Critic（Counting/Position/Color 等检查）产出 critique 与接受与否 $(c,a)$——对应 Eq. 1 的双模式接口，是"模型自己当审稿人"的部分。(b) "Corrective Conditioning and Acquisitive Experience"：critique $c$ 与原 prompt 合成 Revised Prompt $\widetilde{p}$，以同一噪声重生成 "Better Generation" $I'$，经 Post-Revision Verification 复评后才写入右侧 "Acquire Experience" 缓冲——这是防止"改写了 prompt 却没修好图"的脏样本进入训练。(c) "On-Policy Self-Distillation"：从经验缓冲取 $(p,\widetilde{p},\epsilon)$，TEACHER（EMA 自教师，条件 $\widetilde{p}$）与 STUDENT（条件 $p$）在**同一轨迹状态**上匹配一步预测（"Match Predictions at the Same Trajectory State"），产出 New Student。图底部是主损失式。为什么需要这三块并置：它准确体现了方法的三个可分离设计——谁来挑错（模型自己）、哪些经验可信（验证过滤）、怎么把"带提示的纠正"搬进"无提示的策略"（同状态转移匹配）；缺任何一块，后文对应的消融（critic 强度、验证开关、特权条件）就无从解释。

## 4. 解决得怎么样？

### 4.1 实验设置

- **任务与数据（§3.1、Appendix C，原文事实）：** GenEval（553 条 prompt，六类：单物体 80、两物体 99、计数 80、颜色 94、位置 100、属性绑定 100）；GenEval2（800 条，原子性 3–10 各 100 条，覆盖 40 物体/18 属性/9 关系的组合要求）；OCR 视觉文字渲染（沿用 Flow-GRPO 设置，约 2 万训练 prompt、1,018 测试 prompt）。训练数据来自"GenEval 格式训练元数据"与"另一套组合式训练集"（GenEval2 的评估 prompt 与训练流分开）。
- **基础模型与系统（§3.1、Table 4–5）：** 生成器 Qwen-Image-2512（flow-based，自带 Qwen2.5-VL 条件编码器，论文由此论证"用 Qwen-VL 系做理解反馈"的架构动机）；反馈管线 Qwen3-VL-8B-Thinking 做 critique、Qwen3-VL-8B-Instruct 做 prompt 合成；对照组外部 critic GPT-5.6-Luna（闭源，参数未披露）；评测 judge 为 gemini-2.5-flash（temperature 0、judge seed 42），native 指标使用官方评测器（GenEval GM scorer、GenEval2 Soft-TIFA、PaddleOCR 编辑相似度）。训练硬件 4×H200。
- **基线：** Base（Qwen-Image-2512；Table 1 的 Base 为同一预训练模型多个随机种子的平均，表注原文事实）；自身消融：不验证 / 验证、Qwen 自评 / Luna 外评、EMA 扫描（Fig. 5）；另有 Table 7 列出 SD3.5-L、HiDream-I1、Z-Image、SANA-1.5、LongCat、BAGEL 的**已报告** GenEval 分数作为横向参照（不同训练信号、非同一复现口径）。
- **指标：** native GenEval / OCR（0–1）、GenEval2 Soft-TIFA GM（0–100）、Gemini atomic accuracy（%）与整体任务评分（0–10）、HumanPref（0–10）。HumanPref 是**自动视觉偏好代理**，论文明确它不是人工研究、不是成对胜率、不与语义正确性合并（Appendix D.1，原文事实）。
- **公平性与配对：** 训练不使用任何奖励或评测分数（§3.1 "Evaluation scores provide no training reward"）；直接生成与"一次 critique"分开报告，prompt/seed 在**同一实验内**跨检查点与推理条件配对，不跨"验证/不验证"配置配对（Appendix D，原文事实）；"同等 critique 预算"下实际计算可能不同（接受的草稿不需要重生成，Appendix A.3）。
- **各实验回答什么：** 主表（Table 1）回答"各配置相对 Base 如何"；Table 2 回答"训练收益与反思收益的结构"；Table 3 回答"critic 强弱的影响"；Table 8/Fig. 3 回答"训练动力学与验证的作用"；Appendix A/C/D/F 回答配置、数据、评测与提示词细节。

### 4.2 关键结果

**主表（Table 1，§3.2；口径：GenEval/GenEval2/OCR 各含 Native、Atomic、HumanPref 三列）：**

- **带验证的 Qwen 配置在三个任务的全部列出指标上超过 Base**（§3.2 原文事实）：GenEval native 0.747→0.818、atomic 95.30→97.41、HumanPref 8.48→8.71；GenEval2 native 32.58→35.07、atomic 81.69→82.75、HumanPref 6.65→7.11；OCR native 0.771→0.790、HumanPref 9.07→9.10。
- **不带验证的 Qwen 配置是"偏科"的**：GenEval 提升明显（0.747→0.808；在 Qwen 配置内 HumanPref 最高，8.79 高于验证版的 8.71），但 GenEval2 native 低于 Base（32.58→32.37）、OCR native 与 HumanPref 都低于 Base（0.771→0.761、9.07→9.06）（Table 1 原文事实；§3.2 也明写 "unverified Qwen falls below Base on both measures"）。
- **外部 critic（GPT-5.6-Luna，不验证配置）在 GenEval 与 GenEval2 拿到最高 native 分**：0.882 与 35.53；但在 OCR 上其 native 0.775 虽高于 Base，仍低于验证版 Qwen 的 0.790，且 HumanPref（9.03）低于 Base（9.07）（Table 1 原文事实）。摘要中并排出现的两个数字即来自两个不同配置：0.747→0.808 为 Qwen 自评不验证配置；32.97→35.53 为 Luna 配置（Table 9 的配对口径：Qwen 32.86→32.37 为负）。
- **headline 的边界（审稿人判断）**："0.808" 出自论文自己判定"信号可靠性不足"的不验证配方；GenEval2 的最大提升需要外部闭源 critic。二者都不是"无外部监督的自我进化"的最干净证据。

**训练收益 vs 反思收益（Table 2，带验证配置、配对评估，§3.4.1）：**

- 训练后**直出**在全部报告指标上高于训练前（Table 2b：GenEval native 训练增益 +0.069、GenEval2 +3.15、OCR +0.021；atomic +2.00/+1.28、HumanPref +0.24/+0.58/+0.08）。
- **反思仍然有用，且与训练收益部分重叠、随任务不同**：GenEval 上反思增益从 Base 的 +0.078 降到训练后的 +0.030（atomic +2.85→+1.14、HumanPref +0.46→+0.16，Table 2b 原文事实）；GenEval2 上反思增益几乎不变（+10.60→+11.17）；OCR 基本持平（+0.014→+0.013）。
- **训练收益不能仅由"推理期套一次修订"解释**：在"两边都给一次反思"的同一协议下，训练把 native 分从 Base 的 0.826/42.52/0.783 提到 0.848/46.23/0.803（GenEval/GenEval2/OCR，Table 2a；§3.4.1 原文事实）。组合（训练+反思）在三个 native 指标上都最高，唯一例外是 GenEval HumanPref 仍以"反思版 Base"（8.92）最高。

**Critic 强弱与类目结构（Table 3，§3.4.2）：**

- GenEval 的 Gemini 组合保真评分（0–10，553 prompts）：Base 总体 8.96 → Qwen 演化后 9.57 → Luna 9.87；最大差距在 spatial：position 6.85→8.79（Qwen）→9.88（Luna），counting 7.86→9.29→9.58（原文事实）。
- GenEval2（800 prompts）的类目增益分化：两物体 +1.21（Luna） vs +0.28（Qwen）、颜色 +1.02 vs +0.37，而 position（+0.14/+0.06）与 attribute（+0.06/+0.04）几乎不动；总体 +0.22 vs +0.09（Table 3b 原文事实）。native Soft-TIFA 佐证该模式：Luna 32.97→35.53，Qwen 32.86→32.37。
- **较弱/无提升的角落（4.2 要求关注）：** GenEval2 的 position/attribute 类目；OCR 在不验证与 Luna 配置下的回落（0.761、0.775 均低于 Base 0.771 的 native；Luna HumanPref 9.03 低于 Base 9.07）；难度分层上，**Easy prompt（基线 5–10 分）在三个任务上回落 1–4 个百分点（归一化 0–100），增益集中在 Hard 子集**（Fig. 4、§3.3、Appendix D.5；Hard 子集仅 51/144/24 条，OCR 的 24 条尤其小，作者自己提醒解读要谨慎）。所有主结果**没有方差、置信区间或显著性检验**（论文未报告，见 §5 质疑 2）。

**训练动力学与验证的作用（Table 8、Fig. 3，Appendix D.4）：** 不验证的全程曲线里，GenEval 稳步升（8.958→9.573，0→200 步），GenEval2 中途回落（160 步 6.320 低于 120 步的 6.356）、OCR 上下波动且终点略低于起点（9.402→9.372）；作者据此论证后验验证是信号保险（原文事实 + 作者主张）。

### 4.3 机制证据

- **效果证据较强、机制证据是间接的（审稿人判断）。** "有效"由多任务、配对、含反思对照共同支持；但"为什么有效 = 特权纠正被内化"没有直接测量：论文没有报告例如"学生轨迹与教师预测的距离随训练收敛"、"学生对 $\widetilde{p}$ 的依赖度下降"这类过程指标，也没有对"privileged 条件本身"的直接消融（无"教师也用原 prompt"或"学生也看 $\widetilde{p}$"的对照；最接近的是失败的 SFT 尝试，Appendix E）。
- **验证机制的证据是轨迹级的：** Table 8 的不稳定 vs Table 1 验证版的全面超越，构成"过滤脏修正 → 训练更可靠"的合理证据链；但论文未报告被拒比例与增益之间的定量关系，也未区分"验证筛掉了坏样本"与"验证间接改变了样本难度分布"两种解释（审稿人判断）。
- **critic 强度的证据（Table 3）支持"judge 能力决定上限"的主张，但样本只有两个 critic**，且 Luna 配置的 HumanPref 仅在 GenEval 占优（8.97），在 GenEval2（6.86 vs 验证版 7.11）与 OCR（9.03 vs Base 9.07）都不占优；无法排除"更强 critic 带来更长/更细的修正文本"、"两套采集数据难度不同"等替代解释（论文未报告对修正文本长度、通过率、样本难度的对照分析；审稿人判断）。
- **风格混杂的线索（作者自曝 + 审稿人延伸）：** Appendix D.9 承认输出出现偏灰的配色与大面积浅色背景，**与反馈提示词设计（偏好自然光、中等对比、示例引入素色背景）相关**，且这类风格在所用 HumanPref 代理上得分更高；作者提醒"小偏置可能累积"。这意味着 HumanPref 的提升可能部分反映"输出向 critic/提示词风格偏好对齐"，而非纯画质提升（作者部分承认；审稿人判断为对 D.9 的合理延伸）。
- **不能从本论文确认的：** 增益中有多少来自"特权纠正"、多少来自"更详细 prompt 风格的一般模仿"、多少来自采集过滤改变的数据分布——论文未做能隔离这三者的实验（无法确认）。

### 4.4 成本与适用范围

- **训练成本（原文报告）：** 4×H200；仅生成器 LoRA；验证配方在 140 次更新的量级上评估（Table 7），不验证配方到 200–220 次（Fig. 6 注明主结果取 200，未选 220 的更高峰，属主动避免挑峰）。**采集开销是主要成本**：带验证时约 10–21% 的采集尝试被接受，平均每对训练样本需 5–10 次尝试；每次尝试含生成 + critique + 合成，被接受者还要重生成 + 二次 critique（Appendix A.4，原文事实）。**未报告**：wall-clock、GPU 小时数、每样本 FLOPs、不同任务的绝对训练时长。
- **推理成本：** 直出无额外开销；"一次反思"推理形态的成本约等于一次评估（+ 可能一次重生成），且接受草稿时不必重生成——论文提醒同等"反思预算"的实际计算可能不同（Appendix A.3）。HumanPref 与 Gemini 评测是离线开销，不进入部署。
- **外部依赖：** Qwen3-VL-8B（开源，critique 与合成两个角色）；**GPT-5.6-Luna（闭源外部服务）**——头部 GenEval2 数字依赖它；gemini-2.5-flash 仅用于评测。post-revision verification 需要 critic 再评一次、生成器再生成一次，属于采集管线内的额外系统复杂度。
- **人工标注：** 论文未报告任何人工标注或人工研究（HumanPref 是自动代理，Appendix D.1）。
- **适用范围与未解决项：** 论文只在 flow-based 生成器上验证（自认自回归需另定义损失与其未验证，Appendix A.1）；三个任务**分别训练独立 adapter**，"一个 checkpoint 跨任务进化"未被验证；SFT 路线失败且原因未查明（Appendix E 作者说"怀疑需要更复杂的正则与 prompt 选择"）；Easy prompt 回落、GenEval2 position/attribute 不涨、OCR 对配置敏感等不均衡仍在；"更高的自进化上限"仅由一个外部 critic 实验支持（§3.4.2，作者主张）。

## 5. 最容易受到审稿人质疑的地方

#### 质疑 1：摘要级主张跨配置拼接，且"自我进化"的最强证据依赖外部闭源 critic

- **原文依据：** 摘要写 "we build on top of the open-source Qwen-image-2512 and observe a significant performance gain from 0.747 to 0.808 on GenEval and from 32.97 to 35.53 on GenEval2 Soft-TIFA"，两个数字分别来自不同配置（Table 1：0.808 是 Qwen 自评不验证配置；32.97→35.53 是 GPT-5.6-Luna 外部 critic 配置，Table 9）；§1 加了 "in the corresponding configurations" 但摘要没有；§3.4.2 又说"更强 judge 能力的模型才能期待更高自进化上限"；摘要末句却导向 "without external supervision or guidance" 的叙事。
- **为什么重要：** 直接影响创新性主张的边界——"自进化"若在关键基准上需要外部更强模型当 critic，就与"模型靠自己的反馈进化"的卖点存在张力；且 0.808 出自论文自己判定信号不可靠（Table 8）的不验证配方。
- **当前能够得出的判断：** 证据存在但被选择性组合；"自评即可稳定全面提升"的结论超出实验覆盖（自评不验证配置在 GenEval2/OCR native 为负），属于结论范围被夸大。
- **如何验证或补强：** 摘要与引言按配置分别列数（自评/外评 × 验证/不验证），明确各自主张；补一个"同规模外部 critic 的开放模型"对照以分离"外部性"与"更强 judge 能力"；在被判定不稳定的任务上报多检查点均值而非单点。
- **严重程度：** 主要问题。

#### 质疑 2：主结果均为单次运行，无方差、置信区间或显著性检验

- **原文依据：** 主实验 run seed 为 0（Table 4）或 42（Table 5），演化模型的条目均为单次训练；Table 1 只对 Base 做了多种子平均（表注）；评测用 gemini-2.5-flash（temperature 0、judge seed 42），但论文自己承认托管模型不保证重复调用完全一致（Appendix D.1），并有 10 条无法返回的 judge 记录（Appendix D.8）。
- **为什么重要：** 若干核心增益量级很小（OCR 反思下 0.790→0.803、GenEval2 position +0.06/+0.14（0–10 分制）、HumanPref 多位小数），在"单次训练 + 单轮 LLM-judge 评测"下难以与运行波动区分；这直接决定"训练确实内化了纠正"的判断是否成立。
- **当前能够得出的判断：** 证据不足；多个结论（尤其小增益与子集对比）缺少统计稳定性支持。
- **如何验证或补强：** 每配置至少 3 个训练种子、报告均值与区间；对 judge 分数重复评测若干次并报评分离散；对关键比较做配对显著性检验（论文已有配对设计，只差统计量）。
- **严重程度：** 主要问题。

#### 质疑 3：三个任务分别训练独立 adapter，且缺少与最接近自改进方法的同条件对照

- **原文依据：** §3.1 "only generator LoRA parameters are updated, separately for GenEval, GenEval2, and OCR text rendering"，即不存在一个统一自进化的 checkpoint；Table 7 的横向对照是别的生成模型**已报告**的 GenEval 分数（SD3.5-L、BAGEL 等），并非在相同数据/预算下的复现；Related Work 中最近的 UniCorn、ReflectionFlow、SRUM、Meta-TTRL、DiffusionOPD 均未在同一 Qwen-Image-2512 设定下正面比较（最接近的"替代路线对照"是 Appendix E 失败的 SFT 尝试）。
- **为什么重要：** "自进化框架"的表述暗示通用性，但验证形态是逐基准的专用适配器；没有同条件正面对照，无法判断"query critique 蒸馏"相比"critique 重构成 SFT/奖励"等路线是否更好，只能判断它在本设置内可用。
- **当前能够得出的判断：** 结论被适度夸大（相对"框架"一词）；缺少最接近基线的直接比较，创新性证据不足。
- **如何验证或补强：** 在相同 prompt 流与算力下复现至少一个最近方法（如 UniCorn 式重构 SFT、ReflectionFlow 式三元组训练、把评估折成奖励的 Flow-GRPO 式更新）作为基线；报告"一个 adapter 连续经历三任务"的持续学习形态结果；把 Appendix E 的 SFT 失败升级为有诊断的对照（如学习率/正则/数据量扫描）。
- **严重程度：** 主要问题。

#### 质疑 4：训练数据与评测基准同源，HumanPref 存在风格混杂

- **原文依据：** 训练 prompt 取自 "GenEval-format training metadata" 与 GenEval2 风格的 "separate compositional training collection"（Appendix C）——与评测基准同族；HumanPref 为 Gemini 自动评分代理（Appendix D.1），且 Appendix D.9 自承输出出现"偏灰、浅色背景"的风格偏移，与反馈提示词的审美偏好（自然光、中等对比、素色背景示例，Appendix F）一致，而该风格在 HumanPref 上得分更高；论文未报告任何"训练格式与评测格式不同分布"的迁移实验。
- **为什么重要：** 若增益部分来自"适配评测同族 prompt 格式 + 对齐 judge/风格偏好"，而非通用生成能力或纠正内化，"自进化"叙述就存在替代解释（审稿人判断）；D.9 的风格线索使 HumanPref 的解读尤其需要打折。
- **当前能够得出的判断：** 存在混杂因素，无法从现有证据区分"能力提升"与"分布/风格适配"。
- **如何验证或补强：** 在与训练格式明显不同分布的 benchmark（如 DPG-Bench、T2I-CompBench 或真实用户 prompt 集）上评测；做风格控制实验（固定反馈提示词中的审美指令，观察 HumanPref 与 native 分数的解耦）；报告小规模人工偏好研究以校准 HumanPref。
- **严重程度：** 主要问题（对结论解释力影响大，但对"方法有效"本身不致命）。

#### 质疑 5：采集成本与复现披露不完全

- **原文依据：** 接受率 10–21%、每对样本 5–10 次尝试（Appendix A.4）——上游采集（生成 + critique + 合成 + 二次评估）是主要开销但未报 wall-clock / GPU 小时 / 失败率分布；Table 4 表注自承 "checkpoint metadata do not independently encode the full launch configuration"（GenEval 配置来自记录而非元数据可验证）；Critic 提示词含 few-shot 与风格偏好（Appendix F）属"实验干预的一部分"（作者自述）；论文未提供代码、数据或 adapter 的发布说明（全文无仓库链接，Reproducibility statement 只指向附录）；最强配置依赖闭源 GPT-5.6-Luna 与 gemini-2.5-flash。
- **为什么重要：** 可复现性与成本可比性；审稿人无法验证 GenEval 配置的完整启动参数，闭源 critic 使最关键实验不可复现。
- **当前能够得出的判断：** 配方文档详细（超同类平均），但复现链条在关键配置与外部服务上断点明确；成本被定性描述，无法折算为预算对比。
- **如何验证或补强：** 公开 config/脚本与 adapter，或至少补一份完整的启动配置清单；报告各任务 wall-clock、尝试次数分布与失败分类；对闭源 critic 用等价的开放模型复测。
- **严重程度：** 次要问题（不推翻结论，但影响采纳与复现）。

## 6. 审稿式总评

> 作者发现统一多模态模型"看得懂错在哪"与"画得对"之间存在监督形态的缺口——critique 描述目标而不规定去噪路径，因此提出 UniEvo-VL，把 critique 合成的修正 prompt 作为特权条件、由 EMA 自教师沿学生自己的采样轨迹逐状态匹配一步预测，并配后验验证过滤脏修正，只训生成器 LoRA。实验在 GenEval、GenEval2、OCR 三个基准、Qwen-Image-2512 + Qwen3-VL 的设定下表明：带验证配置的直接生成分数在全部列出指标上超过多随机种子平均的 Base，配对评估进一步显示训练收益与推理期反思收益部分重叠但不互相替代；其中"训练+反思组合最优"与"难度分层上增益集中、Easy 回落"这两组证据较扎实，但摘要级主张跨配置拼接、全部主结果为单种子、缺少与最接近自改进路线的同条件对照、HumanPref 存在风格混杂，均使"自评即可稳定自进化"的表述缺少充分支持。本文最有价值的部分是干净的组件解耦（critique 生成、验证过滤、轨迹匹配、配对评估）与诚实的负面记录（SFT 失败、不验证配方的不稳定、Easy 回落、风格偏置自曝）；最大的审稿风险是头条数字依赖外部闭源 critic 与不稳定的不验证配方，且无统计稳定性论证。

- **问题定义清晰度：** 强——缺口陈述（critique 不指定中间去噪预测如何改）具体、可检验，对相关工作的分类与差异定位清楚（§1、§4）。
- **创新性证据：** 中——组合式创新明确，但"特权条件本身"与"验证"的关键作用缺乏直接消融或同条件正面对照（§2、Appendix A.5/E、Table 7 口径限制）。
- **方法可信度：** 中——算法、超参、提示词披露充分且自曝了 KL/JS 表述与实际 L2 实现的差异；但单种子、外部闭源依赖与"档案配置不可由元数据验证"削弱可信度（Table 4–5、Appendix A.1/A.4）。
- **实验支持力度：** 中——三任务、配对评估、多配置与附录分析覆盖较全，并如实报告回落与失败；但无方差/显著性，类目分化与风格混杂未被隔离（§3、Appendix D.9）。
- **可复现性：** 中——配方与提示词文档在同类中偏详细（Appendix A/F），但论文未报告代码/检查点发布，关键实验依赖闭源服务 GPT-5.6-Luna 与 gemini-2.5-flash（全文与 Reproducibility statement 均未给出制品链接）。
- **综合阅读价值：** 高——对做统一多模态模型自改进、自蒸馏与生成后训练的研究者，这是一份把"自反馈 → 特权蒸馏 → 直出提升"讲得最清楚的工程配方之一，其负面结果与评估设计同样有参考价值。
