## 0. 一句话结论

论文面向"programmable world model"（程序维持可执行世界状态、视频模型负责渲染观察）提出 PROWBench：用 170 个程序构造的剧集、200 个相机视角、600 段同步 proxy 视频和可回放的世界记录，评测视频模型是否忠实渲染程序规约的场景结构、时间线与交互事件，并新增两个 VLM 裁判指标 ISR 与 LRA。在论文报告的这套数据与 11 个被评模型上，最稳的结论是"给实体级控制（proxy）比只给相机轨迹更能跟住轨迹与事件，但外观身份、朝向、长时程回归（Reappearance IoU 仅 0.053–0.131）与多视角身份一致性仍未解决"。边界是：ISR/LRA 等核心指标全部依赖未与人类标注校准过的 VLM 裁判，且基准构建与候选集筛选深度依赖 MiniMax-H3（它同时是被评模型并常居前列），因此涉及 MiniMax-H3 的名次只能有条件接受。

## 1. 论文具体想解决什么问题？

**研究背景与任务。** 视频世界模型（Genie、GameNGen、Matrix-Game、WorldPlay 等，§2.1）把世界状态隐含在视觉历史或 latent 里；programmable world model 路线（Code World Model、Programmable World Model，§1）反过来：由编码 agent / 可执行程序维护状态与交互规则，视频模型只负责把结构化世界状态渲染成观察。这就产生一个评测问题——**程序执行正确，不代表渲染忠实**：生成的视频可以看起来很合理，却违反某条规则或根本没画出某个指定交互（§1）。

**现有方法/基准怎么做、在哪里不够。** 现有基准覆盖视频质量（VBench、EvalCrafter）、可控性与动力学（WorldScore）、指令与物理合理性（WorldModelBench）、交互与长时程一致性（MIND、WorldMark、Omni-WorldBench、WorldArena、iWorld-Bench、WBench 等，§2.3）。作者在 Table 6.1 中把 11 个已有基准与本基准并列，逐项比较"行为规约 / 状态轨迹参考 / 任务事件参考 / 是否可回放 / 是否同步多视角 / 是否成对 proxy"六列，指出三点不足（§1，Table 6.1）：

1. 没有"可回放的实体状态与带时间戳事件记录"作参照，生成视频只能被判"是否合理"，不能对照"程序实际执行了什么"；
2. 现有基准不提供同一录制场景的成对 proxy 表示，无法在固定世界演化下分离"表示形式"的影响；
3. 同步多视角稀缺，无法区分"几何一致"与"身份/外观一致"。

**本文的新观察与支撑证据。** 最直接的一条是：全局相似度指标会把错误执行排在正确执行前面。Fig. 1 的 gate 场景里，明显更差的样例 CLIP 得 24.51，而正确实现全部 3 个事件的样例 CLIP 只有 22.29（而作者指标是 0/3 对 3/3）；§4.5 T7 进一步量化：跨方法平均 CLIP-Score 只在其均值附近波动 4.5–5.6%、motion smoothness 波动 1.5–1.6%，而 BBox IoU 波动 53–79%、ISR/LRA 波动 38–59%；Unverified-FF 中 LynnReal-Omni 的 CLIP 最低（24.2）却领先全部实体、相机与逻辑指标。另一条支撑是每个被评方法都在某些"看起来合理"的样例上系统性失败（Fig. 6 的 proxy 泄漏、Fig. 8.10 的外观互换与朝向错误）。

**作者认为的原因。** 这些基准缺少 replayable world records，所以"忠实性"不可测；同时被测系统把动作理解、状态预测、记忆、动力学与渲染误差耦合在一起（§2.3），无法定位错误出在哪一环。PROWBench 的做法是用引擎记录隔离出"渲染忠实性"这一环。

**核心假设。** （H1）以引擎记录的 proxy（几何/布局）加确定性构造的文本（事件时间线）为条件，可以把"渲染是否忠实实现程序规约"变成可自动打分的问题；（H2）这样测出来的指标能揭示 CLIP/放置类指标漏掉的差异。

**区分。** "视频模型不遵守指令/物理"是领域早已知道的一般问题；本文的新观察是评测基础设施层面的（缺可回放记录、缺成对 proxy、缺同步视角，以及现有指标测不出逻辑失败）；本文实际解决的具体子问题是"渲染忠实性"的测量，而不是改进任何视频模型或世界模型本身。

## 2. 创新点是什么？

**一段话概括。** 本文的技术增量是一个"程序→视频"的忠实性基准：用程序化世界引擎生成可回放的剧集记录（含视野外事件），从同一份状态记录渲染成对 proxy 与同步视角，并把"引擎记录"直接作为评测参照，配套两个基于 VLM 裁判的行为指标（Interaction Success Rate 评事件是否完成、Logic-Render Alignment 评时间线每段是否被画出）以及一组对照实验（表示、视角、长时程、微调）。它不是新模型、新训练方法，创新性在于**数据构造方式与评测指标的参照来源**。

逐项分析：

**创新点 1：可回放的、带视野外记录的世界记录与成对 proxy（数据构造）。** 新增的是数据引擎：世界合成（程序化地形/建筑/道路/室内、实体持久 ID、控制器显式分阶段，如搬运的 approach→grasp→lift→transport→release，§3.1）→ 每段执行产出结构化剧集记录（实体变换、关节姿态、可见性、外观变化、控制器事件、世界执行/存档/视频帧的显式时间映射）→ 控制编译把记录渲染成同步条件输入 $I_i^{v,r}=\mathcal{R}_r(G,S_i,C_i^v)$（共享几何 $G$、世界状态 $S_i$、视角 $v$ 的相机 $C_i^v$、表示 $r$，§3.1）。规模：170 个剧集、200 个视角、600 段 proxy 视频（540 段 1280×720 + 60 段 832×480；570 段 5 秒/150 帧 + 30 段 30 秒/900 帧）、30 帧率、37,500 个视角-帧观察、112,500 帧 proxy、合计 62.5 分钟（Appendix 6.1，Fig. 6.3）。与已有基准的差别（Table 6.1）：唯一同时具备"重放 + 同步视角（子集）+ 成对 proxy + 带时间戳引擎事件参照"的协议。证据：`Replay` 列中本基准为 ✓、WorldArena 为 Sim.（模拟器评测，非确认的记录状态重渲染），`Proxies` 列只有本基准为 ✓，`Views` 列仅 TriWorldBench（✓）与本基准（Subset）有值；作者据此声称这是首个把三者结合的基准——按规范只能确认其 related work 对比所支持的差异，是否"首次"仍需更完整文献检索。不可替代性证据：论文用同一批记录做了三组只有该数据构造才能做的对照（见 §4.2：成对表示研究 Table 5、proxy 组成研究 Fig. 5、多视角身份研究 Table 3）；但没有"删掉某个记录字段会怎样"的消融。

**创新点 2：两个以引擎事件为参照的自动指标（ISR / LRA）。** ISR（Eq. 1）对每个注册事件（参与者、时间窗、动作、期望终态）让 Qwen3.6-27B 看事件窗前后 8 帧（全帧+引擎定位裁剪）判断动作与终态是否都出现，只有响应有效且两者为"是"才算成功；LRA（Eq. 3）让裁判看每段时间窗的 12 帧，判断"该段规定的动作是否可见"，取通过段的比例；两者各有一个 IoU 加权变体 gISR/gLRA（Eq. 2/4）。与最接近的已有做法（CLIP 类文本对齐、VQA 打分）的差异：参照不是 prompt 语义或人工 rubric，而是引擎记录的事件；两个指标彼此也有区分度（Fig. 8.4：LingBot 2.0 把三个动作都画出来了 LRA=1.00，但漏掉第一个事件的终态 ISR=0.67）。有效性证据有三条（§4.5 T7）：与 BBox IoU 基本独立（场景内跨方法 Spearman 相关 0.05/0.06，LRA 为 0.14/0.12）；把时间线换成错配版本后，各方法 LRA 从 0.46–0.85 掉到 0.07–0.20，且匹配时间线在 68–97% 的样例上得分更高（这是作者自己做的、唯一的"响应性"对照）；跨方法方差远大于 CLIP。**局限见 §5 质疑 1**：该证据只说明指标对"时间线错配"敏感，不构成与人类判断一致性的校准。

**创新点 3：可扩展的生成框架与评测套件。** 框架把场景构建、行为控制、状态记录、渲染解耦：新增视角/表示可以复用已录剧集而不重跑控制器（§3.1）；评测套件覆盖可控性（SAM 3 检测 + 标签兼容 Hungarian 匹配的 BBox IoU/CErr）、逻辑与状态（ISR/LRA）、长时程记忆（Reappearance IoU、State Persistence）、多视角外观（Appearance Compliance/Consistency、MEt3R）与常规质量指标（MUSIQ/LAION/RAFT warp/VBench smoothness/CLIP，Appendix 7）。这里多数度量本身是现有工具的直接使用，属于组合与工程整合而非新思想；真正的设计选择是"所有度量都对着引擎记录打分"。

**创新点 4：评测协议本身（Verified-FF / Unverified-FF 等四个设置 + 枪战专项）。** 两套主赛道设置只差"外观信息来自经验证首帧还是文本"（Table 6.2），挑战赛道测长时程（10 段 30 秒）与多视角（10 个四人场景×4 视角）；另有 20 个枪战案例用于与域内模型 PWM 对比。这套协议对应的问题是"程序世界渲染"在不同信息条件下的能力边界（§3.3）。注意：首帧本身由 MiniMax-H3 生成并校验（Appendix 6.2），构成一处需要在报告内部反复说明的混杂（§5 质疑 2）。

## 3. 作者如何解决？

**直觉。** 与其让评委（人或模型）看一段视频猜"物理/常识对不对"，不如让程序先把世界跑一遍、把每个实体每一帧在哪、每个事件什么时候发生记下来，再用这份记录去渲染"代理视频"，最后检查模型的输出是否复现了记录里的可观察后果。proxy 只给几何与运动、不给外观，文本只给外观与时间线，所以"模型必须自己决定谁长什么样、朝哪边"，这也正好暴露了当前系统最不可靠的部分。

**实际运行流程（数据引擎侧）。** 输入是配置（环境、实体布局、参与者、任务控制器、随机种子、时长）→ 程序化生成场景与碰撞约束 → 控制器驱动行为（交互控制器按阶段更新手部目标与物体归属；活动/运动控制器支持动物、飞行、游泳；驾驶控制器做闭环控制），期间控制器上报动作阶段、参与实体与关系变化 → 每次执行导出剧集记录（共享场景几何、实体层级、初始条件、逐帧变换/姿态/可见性/外观变化、事件与输入轨迹、世界执行-存档-视频帧的时间映射）→ 控制编译出相机轨迹（第三人称任务轨迹；第一人称由记录的头部位姿与注视导出，第一人称视角中隐藏本体显示几何）与三种渲染表示（Coarse 3D 中性材质；CWM proxy 语义色环境 + 简化人形 mannequin；Colored-OBB 半透明彩色包围盒 + 白面标朝向）→ 最终流程导出记录、proxy 视频与文本/交互标签，并做四类校验（任务与时间线、几何穿插/接触、重放与对齐、视觉与媒体质量；Appendix 6.1–6.2）。评测侧则把记录投影成参照：实体用 SAM 3 从语义标签检测、按标签兼容的 Hungarian 匹配对到参照实体（Appendix 7），相机用 ViPE 在固定内参、遮蔽动态实体后估姿并归一化平移尺度（Eq. 6）。

**模型决定 vs 固定流程。** 文本 prompt 除"外观块"由 Qwen3.6-27B 生成外全部由确定性脚本从引擎记录生成（§6.3），并按各模型接口转换（MiniMax-H3/LynnReal-Omni 收到含控制块的原文；Seedance 2.5 转成 @Image1/@Video1 语法；C2R/相机条件世界模型被转成单段 caption 并压到 C2R 的 512 token 限制；CWM 转成它的 caption 格式，Table 6.3）。**被评模型不需要任何训练**：11 个模型按三族提供各自的原生输入（(a) 相机条件世界模型 EchoWM、SANA-WM、LingBot-World 2.0、AlayaWorld v1.1 收 RGB 首帧+相机轨迹；(b) proxy→RGB 模型 Cosmos-Transfer2.5、C2R、CWM、LynnReal-Omni、PWM 收各自的原生控制表示；(c) 视频基础模型 MiniMax-H3、Seedance 2.5 直接把彩色 OBB proxy 当参考视频，§4.1）。

**两个核心公式。** 事件成功（Eq. 1）：$\mathrm{ISR}_s=\frac{1}{|\mathcal{E}_s|}\sum_{e\in\mathcal{E}_s}\mathbf{1}[\text{valid response, action=yes, end state=yes}]$，表内按样本等权平均以免事件多的样本占权重；其 IoU 加权版 $\mathrm{gISR}_s=\mathrm{ISR}_s\cdot\mathrm{IoU}_s$（Eq. 2）把"事件完成"与"实体放对位置"乘在一起。时间线对齐（Eq. 3）：$\mathrm{LRA}_s=\frac{1}{|\mathcal{T}_s|}\sum_{\tau}\mathbf{1}[\text{该段规定动作被判可见}]$，同样有 $\mathrm{gLRA}$（Eq. 4）。外观判定（Eq. 7）：$q_o=\prod_{a\in\mathcal{A}_o}\mathbf{1}[\text{属性 }a\text{ 匹配}]$，即每个被判定属性必须全过。

这张图是理解两个新指标的关键：ISR 是"事件级"的严格判定（动作与终态都要出现，且裁判响应有效），LRA 是"时间线段级"的宽松判定（这一段规定动作是否出现）。两者在 LingBot 2.0 上分岔（LRA 1.00 / ISR 0.67），说明"画出了动作"不等于"完成了事件"，也解释了为什么论文认为单靠放置类指标与视觉质量分不够。

**教学简化示例（非论文实验）**：可以把它想成"老师给学生一段乐高搭建的慢动作录像（proxy）加一张成品照片（首帧）和一份带时间戳的施工说明（文本），然后只问：你搭出来的东西，在 0.0–0.97 秒里有没有把那扇门推过去、结束时门是不是开着的？"——本基准的 ISR/LRA 就是这两个问题的自动化版本。

## 4. 解决得怎么样？

### 4.1 实验设置

- **测试对象**：11 个模型分三族（§4.1）：(a) 相机条件世界模型 EchoWM、SANA-WM、LingBot-World 2.0、AlayaWorld v1.1（收 RGB 首帧+相机轨迹，无实体轨迹）；(b) proxy→RGB Cosmos-Transfer2.5（深度+类级分割）、C2R（coarse 3D+文本）、CWM（CWM proxy+深度+首帧+文本，由 MiniMax-H3 微调）、LynnReal-Omni（MiniMax-H3 的扩展）、PWM（彩色 OBB+首帧+文本，仅训练于枪战场景，只在枪战集评测）；(c) 基础模型 MiniMax-H3、Seedance 2.5（无适配，proxy 视频当参考）。
- **测试集**：主赛道 Verified-FF 40 对场景-相机（31 第三人称跟随、9 第一人称；首帧为经验证的 MiniMax-H3 生成图，所有接受首帧的方法拿到同一张）与 Unverified-FF 90 对（78/12；无首帧，外观由文本决定，两设置场景不相交，§3.3）；挑战赛道长时程 10 段 30 秒、多视角 10 个四人场景×4 视角；枪战专项 20 例（Table 4）。
- **对照与预算**：同一场景-相机下各方法拿各自原生接口的控制表示，"引擎渲染的 proxy"也作为诊断参照被打分（§4.2）；输出分辨率/帧率/帧数因模型而异（Table 8.1，如 C2R 832×480/16fps/81 帧、MiniMax-H3 1344×768/24fps/120 帧），长时程窗口衔接协议也不同（Seedance 2.5 额外接收上一窗末帧，§4.4）。统计用场景配对的符号检验；**论文未报告**方差、置信区间与多次运行的种子稳定性。
- **指标**：实体控制（BBox IoU↑、CErr↓）、逻辑/状态（ISR、LRA、gISR、gLRA）、记忆（Re-IoU、State Persistence）、相机（RotErr、TransErr、CamMC）、质量（Img、Aes、Warp、Smooth、CLIP）、多视角（Appearance Comp./Cons.、MEt3R）。主实验回答"各方法在这一基准上的排序与能力边界"；表示研究（Table 5）、proxy 组成研究（Fig. 5）、微调配对比较（§4.5 T4）与枪战对比回答"哪一环造成差异"。

### 4.2 关键结果

**主赛道（Table 1，5 秒片段）。** 实体控制上 proxy 条件族明显领先：Verified-FF 中 LynnReal-Omni / MiniMax-H3 / CWM 的 BBox IoU 为 0.518 / 0.494 / 0.454，而四个只收相机轨迹的世界模型只有 0.303–0.351（EchoWM 0.351 为该族最高）；Unverified-FF 中 LynnReal-Omni 0.457、MiniMax-H3 0.409，相机条件族 0.204–0.255。类别间配对符号检查：proxy 条件类在 38/40（Verified-FF）与 87/89（Unverified-FF）场景上更高，中位数 +0.14，$p<10^{-8}$（§4.5 T1）。但把"主角/其他实体"拆开：相机条件模型对主角的放置已接近 proxy 条件（0.44/0.42 对 0.46–0.54，第三人称），差距主要在非主角实体（0.26/0.20 对 0.38–0.44）——说明领先部分来自跟随相机这类隐式控制。Fig. 8.3 给出该结论的定性版本：同一场景同一首帧下，EchoWM 保住了主角（per-entity IoU 0.63）却没让对向来车驶过主角、也没保持前车距离（0.27 与 0.29），而 proxy 条件模型把两辆车都保持在参照框内（0.62–0.86）。

![论文 Fig. 8.3：实体级控制定性对比。列依次为 BBox proxy 输入、EchoWM、CWM、LynnReal-Omni、Seedance 2.5、MiniMax-H3；行为 0.5 s、2.5 s、4.5 s 三个时刻；虚线框是引擎参照框（青色=对向来车，橙色=前方车辆），半透明白面是 proxy 的朝向标记](/images/dailypaper/2026-10-02/2610.02205_fig3.png)

这张图是 T1 结论的可视化证据：它把"BBox IoU 的类间差距"落到具体实体上——只要看三种方法里那两辆虚线框车有没有被画出正确的相对运动，就能理解为什么"给实体级 proxy"比"只给相机轨迹+文本"更能守住非主角实体；同时它也是论文所谓"proxy 只提供位置/尺度/朝向、不提供外观"这一设计契约的直观示例（输入列只有彩色盒子）。

**逻辑与状态（同表）。** 交互成功率与放置并不同步：Verified-FF 中 LingBot 2.0 的 ISR 最高（0.733），但它的 BBox IoU 只有 0.327（倒数第三）；Cosmos-Transfer2.5 收到稠密深度+分割、IoU 排第四，却在两个设置里 ISR 与 LRA 都最低。LRA 在两个设置都由 LynnReal-Omni（0.832/0.852）与 Seedance 2.5（0.817/0.829）领先。用 IoU 加权后排序变化：Verified-FF 的 gISR 第一是 MiniMax-H3（0.334），LingBot 2.0 掉到第五（0.241）——论文据此强调"动作对"不等于"位置对"，未加权 ISR 需与实体控制结果合读（§4.3）。

**相机控制。** 差距远小于实体控制：Verified-FF 中多数方法旋转误差 1.7–3.4°，与在引擎渲染上跑姿态估计器的误差（1.1–2.7°）同量级，只有 AlayaWorld v1.1（9.4°）与 C2R（7.8°）明显更差；不给相机轨迹的基础模型在 CamMC 上与给轨迹的模型打平（类均值更低的比例 20/40 与 45/90，$p=1.0$，§4.5 T2）——proxy 视频本身已隐含相机。

**挑战赛道（Table 2、3）。** 长时程全体失败：30 秒上 BBox IoU 只有 0.175–0.280，回归实体的 Reappearance IoU 只有 0.053–0.131；每个方法都在前 5 秒最好（0.25–0.36）并在 10 秒后掉到 0.12–0.25，50 个方法-录制结果中 42 个低于 0.3（§4.4，Fig. 7）；乘客再入例子中，离场前 IoU 约 0.6，回归后 CWM 0.34、LynnReal-Omni 0.30、Seedance 2.5 0.17、MiniMax-H3 0.01（Fig. 8）。多视角上，几何一致性与身份一致性脱钩：C2R 的 MEt3R 点估计最低（0.397）但外观合规仅 32.2%、跨视角一致性 25.5%；而用身份色绑定实体的方法达 82–94% / 81–90%；即使最好的方法也有 10–19% 的受判视角对里出现"衣服不同的人"（§4.4）。**注意**：论文自述 State Persistence 分数只覆盖每个方法 17–21 个事件、裁判未校准，只能指示趋势不能当稳定排序；且 30 秒窗口衔接协议各方法不同，测的是"各自协议下的端到端保持"，不是孤立的内部记忆（§4.4）。

**微调与域内模型（§4.5 T4，Table 4）。** 微调收益不均匀：以 MiniMax-H3 为基座的配对比较中，CWM 在 71% 的 Unverified-FF 配对里 BBox IoU 更低（$p=10^{-4}$）、约 90% 配对成像质量更低，但 warp 误差更低（约 80%）；LynnReal-Omni 在 62% 配对里 IoU 更高（$p=0.03$）、81% 非平局配对 LRA 更高（$p=0.02$），但 warp 误差在所有配对里都更高（论文提醒 warp 低也可能只是动作幅度小，不能当无条件的时间一致性提升）。枪战集上通用模型 ISR 0.450–0.650，域内训练的 PWM 达 0.850（IoU 0.602 对 0.526），并更少出现 proxy 泄漏（Fig. 6）。

**表示研究（Table 5）与负结果。** 同一 MiniMax-H3、同首帧同种子下换 proxy 表示，布局几乎不变（IoU 0.503–0.514），事件指标差异也只来自少数场景（colored-OBB 的 ISR 0.733 最高、coarse 3D 的 LRA 0.802 最高），10 对样本上这些差异都不显著（符号检验 $p\ge 0.25$）。未验证首帧时的失败具体且可复现：外观与人物绑定会错配（人工审计 62 个多人场景，MiniMax-H3 有 12 例两人外观互换；Seedance 2.5 把快递员衣服穿到学生位置上），朝向会反（Fig. 8.10），C2R 在要求手绘风格的场景里仍渲成写实（Fig. 8.9）。**论文未报告**这些对比的方差或多次采样的稳定性；挑战赛道每组只有 10 个单元。

### 4.3 机制证据

**"有效"层面证据较整齐**：排序在两个主赛道设置高度一致（跨设置方法均值的 Spearman：BBox IoU 0.98、平移误差 0.93、CamMC 0.95、LRA 0.91，§4.5），大量结论有场景配对符号检验（$p$ 从 0.03 到 $10^{-8}$），且有基座配对的微调对照（CWM/LynnReal-Omni 对 MiniMax-H3），比"跨模型乱比"干净。**"为什么有效"层面证据不均匀**：

- 指标效度：LRA 的时间线错配对照（0.46–0.85 → 0.07–0.20）与 ISR/LRA 对 IoU 的低相关（0.05/0.06）支持"新指标测的是别的东西"；但这是作者自证，且只覆盖一种扰动（错时间线），**没有**与人类判断的一致性数据——论文自己把"裁判未与人类标注校准"写进局限（§4.5 T7）。
- 机制解释：proxy 带来更好的放置被归因于"显式实体控制 vs 文本/相机隐式控制"，证据是类别比较 + 主角/非主角分解 + Fig. 8.3 定性样例；这是相关性的分解，不能排除"proxy 模型同时接收了更多条件/更强基座"的替代解释。
- proxy 组成研究（Fig. 5）显示给 LynnReal-Omni 从"只有实体框"逐渐加地面/天空/50% 背景物体时，旋转误差从 6.89° 降到 3.31°、CamMC 从 0.243 降到 0.147，提示背景结构提供相机线索；但作者明确声明"100% 背景"参照同时换了 prompt、首帧与实体框集合，其额外收益不能只归给背景覆盖——这是一处作者自己标注的不可控对照。
- 多视角结论（几何一致 ≠ 身份一致）有 MEt3R 与外观判定的分离支撑，方向可信，但两个指标一个来自特征对齐、一个来自另一个未校准 VLM 判定，且都只在 10 个场景上。

### 4.4 成本与适用范围

**论文报告的成本**仅限于数据侧规模：170 剧集/200 视角/600 段 proxy 视频、62.5 分钟总时长、112,500 帧 proxy（Appendix 6.1）；评测侧每次判断取 8 帧（ISR）或 12 帧（LRA）。**论文未报告**：数据引擎的构建/渲染算力与人工工时、评测总调用量与费用、标注者报酬、裁判与人类对比的校准成本。人工环节存在但只被定性描述（首帧与时间采样的"documented visual inspection"、标签的"AI-assisted review"、62 个多人场景的人工审计），没有标注者数量、一致性或工作量。外部依赖重：MiniMax-H3、Seedance 2.5、Qwen3.6-27B、SAM 3、ViPE 等（多为闭源或第三方服务），复现整套数字受接口变化影响。

**发布状态与范围**：项目页与代码仓库在归档日可达，但仓库 Release Roadmap 显示 Benchmark data 与 Evaluation code 为 "Coming soon"，论文未给出独立的数据/排行榜地址——当前无法用已发布物核对任何数字。结论适用边界：11 个模型、5 秒/30 秒片段、游戏式 3D 场景（城市 64、室内 38、自然 31、竞速 12、水下 10、幻想 8、天空 7，Appendix 6.1）、三种 proxy 与各自原生接口。已改善的问题：让"渲染忠实性"可回放、可对照地测；仍未解决：长时程状态保持、实体身份-外观绑定、朝向控制、多视角身份一致——这些是论文自己列出的 open problems，而非其方法能修的东西（本基准不训练任何模型）。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：承载核心结论的两个新指标全部建立在未校准的 VLM 裁判上，测量效度无独立验证

- **原文依据**：ISR/LRA（§3.2，Eq. 1/3）与外观合规/一致性、State Persistence（Appendix 7）都由 Qwen3.6-27B 判定；§4.5 T7 自述"Interaction Success, Logic-Render Alignment and the appearance metrics rely on a VLM judge that has not yet been calibrated against human annotation"；全文唯一的人工核查是 62 个多人场景的外观互换审计与首帧"documented visual inspection"，论文未报告任何裁判-人类一致率。
- **为什么重要**：ISR/LRA 是本文相对已有基准的主要增量，如果裁判对"动作/终态是否出现"的判断本身有系统性偏差（尤其对风格化、低质量或运动模糊输出），那么所有方法排序、gISR/gLRA 的加减权重都会连带失真；"valid response"条件还可能把解析失败混进失败率。
- **当前能够得出的判断**：指标对时间线错配敏感（0.46–0.85 → 0.07–0.20）且与 IoU 基本独立，说明它测的不是放置，但"测得准"这一步证据不足；这是测量效度未验证，不是结论错误。
- **如何验证或补强**：公开裁判 prompt 与逐样本判定，抽样做人类标注并报告一致率/混淆矩阵；报告"invalid response"比例；对帧数、裁剪、prompt 措辞做敏感性分析。
- **严重程度**：主要问题。

#### 质疑：基准构建与评测和 MiniMax-H3 深度耦合，而其同时是被评模型且常年居前

- **原文依据**：Verified-FF 的 40 张首帧全部由 MiniMax-H3 从 colored-OBB proxy 生成并校验（Appendix 6.2），"every method that accepts a first frame receives this identical image"（§3.3）；Unverified-FF 的候选集筛选用了 MiniMax-H3 输出，论文自述"results involving MiniMax-H3 should be read with this potential bias in mind"（§3.3）；主赛道中所有需要 RGB 首帧的方法（相机条件世界模型与 CWM）收到的是"MiniMax-H3 输出的第 0 帧"，§4.2 承认"it can transmit MiniMax-H3's appearance assignments"；Appendix 6.1 的 170 例图库也用 MiniMax-H3 输出展示。
- **为什么重要**：主赛道里 MiniMax-H3 与 LynnReal-Omni（基于 MiniMax-H3）常居第一或第二（Table 1），首帧条件把外观与布局先验直接喂给它们；这影响的是方法间公平性与基准的"中立性"主张。
- **当前能够得出的判断**：作者已披露但未量化；在无首帧的 Unverified-FF 中 MiniMax-H3 仍居前（IoU 0.409、LRA 0.806），说明其优势不全来自首帧，但耦合带来的偏高无法从当前材料中排除。
- **如何验证或补强**：用第二家生成器重建首帧并重跑关键表；报告"逐方法是否使用 MiniMax-H3 首帧/第 0 帧"的消融；公布 Unc 设置下与首帧无关的子集结果。
- **严重程度**：主要问题。

#### 质疑：自评风险——两个被评模型与基准作者同组，其中 PWM 的枪战优势缺少训练数据与基准源记录的隔离说明

- **原文依据**：分析范围作者署名显示本基准由 Alaya Lab 的 9 人完成；被评的 PWM（Huang et al., 2026a）参考文献条目为"Z.-H. Huang, G. Lin, …, K. Zhang, et al., Programmable world model"，与本基准第一、二作者及通讯作者同名；AlayaWorld v1.1（Team et al., 2026）条目中包含通讯作者 K. Zhang。PWM 在枪战集拿到最高 ISR（0.850）与 IoU（0.602，Table 4），而枪战集 20 例由 10 段源录制派生（Appendix 6.1）。论文未说明 PWM 的训练场景与这 10 段源录制是否同源或有无重叠（论文未报告）。
- **为什么重要**：若域内模型的"胜利"部分来自训练数据与评测源记录的分布重叠，Table 4 的对比会高估专用训练的价值；这类同机构自评是审稿人常规关注点。
- **当前能够得出的判断**：署名关联可从论文自身核实；训练/评测数据是否重叠当前材料无法确认，论文未披露。
- **如何验证或补强**：披露 PWM 训练数据来源与种子协议，明确与评测源录制的隔离；或改用不参与构建的第三方域内模型做对照。
- **严重程度**：主要问题（若训练集与评测同源则升级）。

#### 质疑：跨族比较混杂输入与协议，挑战赛道单元过小且无方差/显著性

- **原文依据**：三族模型的输入定义不同（§4.1），prompt 被按接口分别改写（Table 6.3，C2R 族还被压到 512 token 且去掉 proxy 术语），输出分辨率/帧率/帧数各不同（Table 8.1）；长时程的窗口衔接协议不同，论文自述"this section measures end-to-end long-horizon preservation under each method's actual protocol, not an isolated internal memory"（§4.4）；长时程与多视角各 10 个单元、枪战 20 例、表示研究 10 对，State Persistence 只覆盖 17–21 个事件且裁判未校准，"indicate tendencies rather than a stable ranking"（§4.4）；所有表格未报告方差或置信区间，若干结论建立在 $p\ge 0.25$ 的不显著差异上（Table 5）。
- **为什么重要**：这决定"哪一族/哪一模型更好"这类结论的可推广性；也影响读者对 T1–T3 类总结的信任度。
- **当前能够得出的判断**：作者对长时程协议与置信度的局限有自觉披露，主赛道配对比较是论文中最扎实的部分；但跨族结论必然混杂"输入信息量"这一变量，当前材料无法把"proxy 表示"与"更多条件/更强基座"分离。
- **如何验证或补强**：对同一基座做输入消融（同一模型加/不加 proxy 与相机输入）；扩大挑战赛道并给出多种子方差；报告逐场景明细以便第三方重算配对检验。
- **严重程度**：主要问题。

#### 质疑："真值"是作者编写的执行记录，标签经 AI 辅助；首帧自动校验阈值较松

- **原文依据**：Appendix 6.1 scope notes 明确"Engine event records specify the authored execution, not independently verified physical causality"；交互标签为"AI-assisted review"（293 个剧集-标签），风格标签"describe requested styles rather than measured output appearance"；Verified-FF 首帧的硬校验为人物计数精确匹配、人框平均 IoU ≥ 0.30、朝向与引擎框一致（Appendix 6.2）——0.30 的 IoU 门槛对"首帧可作为几何参照"来说偏高容差；无标注者间一致性数据。
- **为什么重要**：整篇基准把引擎记录当 ground truth 使用，若记录本身与"可观察因果"存在系统性差异（例如事件语义在渲染上不可判读），则 ISR/LRA 的失败判罚会把"不可判读"算成模型错误；"0/3 vs 3/3"式的判定也因此缺少语义层的独立复核。
- **当前能够得出的判断**：作者在 scope notes 中承认记录是"authored execution"，属于有限度的诚实披露；但缺少对其可判读性（例如让裁判对引擎渲染的 proxy 本身打分）的上界检验——该检验恰好可以量化裁判的假阴性。
- **如何验证或补强**：报告裁判在引擎渲染/真值 proxy 上的 ISR/LRA（应接近满分，否则说明指标或裁判有假阴性）；给出标注一致性；对首帧校验阈值做敏感性分析。
- **严重程度**：次要问题（对结论方向影响有限，但影响误差归因）。

## 6. 审稿式总评

作者观察到"程序执行正确 ≠ 渲染忠实"，且现有基准缺少可回放记录与成对表示来测量这一点，因此提出 PROWBench：用程序化世界引擎产出 170 个剧集、600 段同步 proxy 视频与带时间戳事件的世界记录，让同一份状态可以渲染成多表示、多视角并作为评测参照；配套的 ISR/LRA 两个 VLM 裁判指标以引擎事件而非 prompt 语义为准。实验在 11 个模型、两套主赛道与两个挑战设置上表明：实体级 proxy 条件显著优于仅相机条件（38/40 场景，$p<10^{-8}$），但外观身份绑定、朝向、30 秒长时程回归（Reappearance IoU 0.053–0.131）与多视角身份一致性仍未解决；其中主赛道配对比较与"CLIP 与事件指标脱钩"的证据较强，而 ISR/LRA 的测量效度、MiniMax-H3 深度参与带来的公平性、以及同组模型自评（PWM）这三处仍缺少充分支持。本文最有价值的部分是"以引擎记录为真值 + 成对 proxy/视角"这套评测范式与随之暴露的失败清单；最大的审稿风险是核心指标建立在一个论文自己承认未校准的 VLM 裁判之上，且基准构建方与被评方法（MiniMax-H3 生态、PWM、AlayaWorld）存在多重关联。

- **问题定义清晰度**：强。要解决的问题（程序规约→视频的忠实渲染）与"缺什么基础设施"在 §1、§2.3 与 Table 6.1 中被明确界定，且区分了"合理"与"忠实"。
- **创新性证据**：中。数据构造与指标参照来源确有增量（Table 6.1 的对比），但多数度量组件为现有工具的直接组合，且"是否首个"只能依据作者自己的 related work 对比确认。
- **方法可信度**：中。确定性 prompt 生成、配对的基座对照与符号检验是加分项；但裁判未校准、跨族输入/协议混杂与自评关联削弱了"机制已获验证"的强度。
- **实验支持力度**：中。主赛道（40+90 对）与多组配对比较足以支撑"哪类方法更跟得住"的方向性结论；挑战赛道每组 10 个单元、无方差/置信区间，且缺少对裁判的假阴性上界检验。
- **可复现性**：弱。论文给出 pipeline 描述、公式与 prompt 示例，但 Benchmark data 与 Evaluation code 在归档日尚未发布，评测依赖多家闭源/第三方模型，且论文未报告算力与标注成本。
- **综合阅读价值**：高。对做视频生成、世界模型与多模态评测的读者，这是一份结构清楚、失败分析具体、并公开承认局限的基准论文；阅读时需对"VLM 裁判"与"MiniMax-H3 耦合"两处保持保留。
