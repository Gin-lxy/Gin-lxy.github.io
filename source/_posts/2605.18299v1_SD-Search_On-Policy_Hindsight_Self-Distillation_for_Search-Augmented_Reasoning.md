## 0. 一句话结论

SD-Search 针对搜索增强推理（search-augmented reasoning）中轨迹级奖励（trajectory-level reward）无法区分单条查询好坏的问题，让同一策略在事后回看（hindsight）条件下扮演教师、只在搜索查询 token 上做 Jensen-Shannon 散度（Jensen-Shannon divergence，JSD）自蒸馏，从而在不引入外部教师或额外标注的情况下获得步级信用分配（step-level credit assignment）。在论文报告的七个问答基准上，3B 平均精确匹配（Exact Match，EM）为 0.428、7B 为 0.476，平均不弱于强基线；但 7B 对 MR-Search 的优势主要来自仅 125 题的 Bamboogle，教师输入是否包含被监督查询、算力是否对齐和统计显著性仍未澄清，因此证据只支持“平均意义上的竞争力”，不支持“全面优越”。

## 1. 论文具体想解决什么问题？

论文研究的是知识密集型问答中的搜索增强推理。大语言模型（large language models，LLMs）的参数知识受预训练截止时间限制，一类做法是让模型在推理过程中交替生成内部思考、向外部检索器发出查询、读取返回文档，最后给出答案；这种轨迹通常被建模为 think、search、documents、answer 四类跨度（span）。训练时主流做法是 GRPO（Group Relative Policy Optimization，组相对策略优化）：对同一个问题采样一组轨迹，用最终答案与标准答案的 F1 作为标量奖励，再在组内归一化得到优势（advantage）。问题在于，这条奖励是轨迹级的：一条轨迹里的每个 token 都乘以同一个优势，无论它属于一条措辞精准的查询，还是一条冗余、指代错误或检索不到关键证据的查询。查询本身决定了模型能看到什么证据，因此这种“同奖同罚”在多跳问题上尤其粗糙——某一跳查对了、另一跳查偏了，整条轨迹仍然只得到一个总分。

这不是一个全新的一般性问题。Search-R1、ReSearch、AutoRefine、MR-Search 等 outcome-reward 方法都建立在轨迹级奖励上；作者对它们的批评不是“效果不好”，而是“监督粒度与决策粒度不匹配”。已有的 process-supervision 路线试图补上这一层：Thinker 用 72B 教师模型把问题分解成子问题并合成训练轨迹，再对学生做监督微调（supervised fine-tuning，SFT）；StepSearch 用 GPT-4o 生成子问题标注，据此构造步级奖励。这些方法确实能带来提升，但步级信号是从策略外部“进口”的：要么依赖一个更大的教师，要么依赖商业模型的标注管线，成本和适用条件都受外部资源约束。论文还把 GiGPO 这类利用重复环境状态构造步级优势的方法放在相关工作里，但没有把它纳入实验比较。

论文的新观察是：策略本身在获得“同题一组 rollout 实际怎么展开、哪些成功”的事后信息后，会比决策时刻的自己更有能力判断哪些查询值得发出。这个观察把问题从“去哪里找步级监督”转成“能否让策略在另一种条件下给自己提供监督”。作者据此提出的具体子问题是：在搜索增强推理的 GRPO 训练循环内，用同策略、同参数、仅条件不同的教师，对 search-query token 提供稠密的分布匹配信号，并且不增加外部教师推理、不增加标注阶段、不改变推理路径。

支撑这一问题判断的证据主要是现象层面的。论文报告 3B 模型相对 AutoRefine-Base 的平均提升为 2.3 个 EM 点，且提升集中在多跳基准：Bamboogle +5.8、MuSiQue +3.1、2Wiki +2.7（论文 Table 1、§3.2）。作者还展示了训练动态：自蒸馏开启后，验证 EM 与“检索文档中包含标准答案的比例”上升，而每条轨迹的平均搜索次数与 AutoRefine 基本持平（论文 Appendix F、论文 Fig. 5）；以及一个失败轨迹上的逐 token 概率轨迹（论文 Appendix H、论文 Fig. 6）。这些证据说明“查询质量”而不是“搜得更多”可能是主要通道，但它们仍是相关性证据：论文没有直接测量每个查询的因果贡献，也没有证明所有提升都来自信用分配而不是额外的训练算力或正则化效应。

作者对原因的解释是监督粒度不足，而不是模型容量不足：在同样的底座、同样的检索器和同样的搜索预算下，只改变监督信号就能获得提升。这个解释与“多跳提升更大”的模式一致，但论文没有做严格的因果隔离。更准确的说法是：论文观察到了轨迹级奖励下的查询级信用缺失，并提出了一个合理的补足机制；该机制的有效性有消融支持，但“提升完全由信用分配导致”仍是作者主张，而不是已经被实验证明的事实。

论文最终要验证的核心假设可以拆成三条：第一，同一策略在 hindsight 条件下产生的查询分布，比学生当前分布更接近“好查询”；第二，在这种分布上做 token 级对齐，能改善下游 EM；第三，这种改善不需要外部教师或标注，且能在不同模型规模上成立。第一条由逐 token 概率轨迹和消融间接支持，第二条由主结果和训练动态支持，第三条由 3B/7B 主实验与 1.5B–14B 扩展实验支持，但后者的 14B 增益已经缩到 0.6–0.9 个点，接近种子噪声。论文的结论范围应限定在“有可评分标准答案的单跳/多跳问答、固定检索器、固定搜索预算”的设定内；开放生成、多工具智能体或没有可靠参考答案的任务不在证据覆盖范围内，作者在 §4 也承认了这一点。

## 2. 创新点是什么？

真正的技术增量不是提出了一种全新的学习原则，而是把“同策略自蒸馏”具体化为一个可训练的搜索查询监督器：教师不是另一个模型，也不是固定的专家轨迹，而是同一策略在“同题 rollout 组 + 结果标签”这一事后条件下的副本；监督只落在 search-query token 上，并通过 JSD 与 GRPO 组合。与最接近的工作相比，它把特权信息（privileged information）的来源从外部专家/标准答案轨迹换成了策略自己的 on-policy rollout 组，这是本文最核心的差异化。

1. **事后信息块的构造。** 新增的是数据构造方法：对 GRPO 已经采样的同一组轨迹，保留每条轨迹的 search 跨度、丢弃 think/documents/answer，附上由 F1 阈值得到的 Correct/Incorrect 标签，再把兄弟轨迹骨架与 focal 轨迹自身的查询骨架拼成教师的条件上下文；块的最大长度设为 1024 token，并对 (queries, outcome) 做字符串级去重。它与 Thinker、StepSearch 的区别在于不依赖 72B 教师或 GPT-4o 标注；与已有自蒸馏的区别在于特权信息不是固定的专家轨迹，而是当前策略在本轮训练中产生的、带结果对比的 rollout 组。这个设计对应“外部步级信号太贵”的问题，证据是论文 Fig. 3 的构造消融。

2. **查询位置上的 token 级 JSD 目标。** 新增的是一个损失项：教师分布在同一前缀上、以事后信息块为条件，学生分布只以推理时可见的前缀为条件；两者只在 search-query token 上计算对称 JSD，教师侧 stop-gradient，学生侧回传梯度。它与常见的 on-policy distillation 的区别是教师与学生共享全部参数、只在条件上不同，而且监督范围被限制在查询 token，而不是整条序列；与 RL 的 process reward 的区别是它直接匹配分布，不需要额外的奖励模型或步级标量。这个设计对应“轨迹级优势太粗”的问题，证据是论文 Table 3 的散度替换消融。

3. **把上述信号嵌入 GRPO 的训练配方。** 新增的是一套工程上可复用的组合方式：总损失为 GRPO 损失加一个系数乘 JSD 损失，优势估计器不变；前 50 步做 warmup（预热），期间蒸馏系数为 0；默认系数为 $10^{-3}$，top-k 截断为 50，结果阈值 $\rho=0$；训练只增加一次教师前向和一次学生侧反向，推理完全移除教师。它与“先合成数据再 SFT”或“先标注再 RL”的多阶段管线不同，整个信号留在标准 RL 循环内，论文报告 3B 全量 200 步训练的端到端墙钟开销为 15.5%。这更像工程实现与训练流程的创新，而不是新的数学目标；证据是论文 Appendix E 的成本分解。

原创边界需要谨慎表述。On-policy distillation、以特权信息做自蒸馏、hindsight experience replay、hindsight credit assignment 都已有文献；本文的组合方式——用同一策略的 on-policy rollout 组及其结果标签作为教师条件，并在搜索查询 token 上做 JSD——在论文的相关工作中没有看到完全相同的先例，但这是否构成“首次提出”仍需更完整的文献检索。可以确认的是：与论文直接比较的 Thinker、StepSearch、AutoRefine、Search-R1 等方法相比，本文的差异是真实的；不能确认的是它相对于更广泛的自蒸馏/过程监督文献的绝对新颖性。

## 3. 作者如何解决？

核心直觉可以这样理解：一个学生在考试时只能看到题目和已经写下的推理，但一个“事后诸葛亮”在看完同一道题的五份答卷、并知道哪份对了之后，再回头看某一步该查什么，往往能给出更好的判断。SD-Search 把这位“事后诸葛亮”实现为同一模型在额外条件下的副本：它看到同题其他 rollout 的查询骨架和成败标签，于是对“哪些查询值得发”有了更集中的分布；学生则在看不到这些信息的条件下，被要求在这些查询位置上去匹配教师的分布。因为教师与学生的参数完全相同，差异只能来自条件信息，作者希望学生学到的不是某个外部教师的风格，而是“在同样前缀下，若知道事后结果，会怎样改写查询”这一信号。

一次训练迭代的完整流程如下。

1. **输入与采样。** 输入是训练集中的一个问题 $q$、当前策略 $\pi_\theta$、固定检索器 $\mathcal{E}$。策略按结构化格式生成一组 $G=5$ 条轨迹；每条轨迹由 think（内部推理）、search（查询）、documents（检索返回）和 answer（最终答案）组成。查询 token 的位置集合记为 $\mathcal{Q}_\tau$，即 `<search>` 与 `</search>` 之间的 token；文档 token 不属于策略生成，因此不在监督范围内。每条轨迹用最终答案与标准答案的 F1 得到一个标量奖励，再在组内做均值/标准差归一化，得到所有 token 共享的优势 $\hat{A}_i$。这一步与标准 GRPO 完全相同，hindsight 复用的就是这批已经采样的轨迹，不额外增加 rollout。

2. **构造事后信息块。** 对组内每条轨迹 $\tau_j$，先做“未来掩码”（future masking）：只保留 search 跨度，丢掉 think、documents 和 answer；论文把这一步叫 future masking，是因为被丢掉的跨度在时间上都位于查询之后，保留它们会让教师直接看到检索文档或最终答案。然后根据最终答案的 F1 是否超过阈值 $\rho$ 生成二值标签 $y(\tau_j)\in\{\text{Correct},\text{Incorrect}\}$，默认 $\rho=0$，即只要与标准答案有非空重叠就记为 Correct。兄弟轨迹的查询骨架与标签按轨迹拼接，做字符串级去重，总长度上限 1024 token。教师上下文由“原始题目与已发生前缀 + 兄弟轨迹骨架与标签 + focal 轨迹自身的查询骨架与结果标签 + 被监督的查询动作”组成；论文 Appendix J 的论文 Fig. 8 给出了 token 级布局。这里的关键设计是“结果对比”：如果只给教师看一条失败轨迹，它只能模仿失败；同时给看成功与失败的兄弟轨迹，教师才能把概率质量从失败查询移向成功查询。

3. **教师前向与学生前向。** 学生分布是 $P_p^{\text{stu}}=\pi_\theta(\cdot\mid\tau_{<p})$，只以推理时可见的前缀为条件。教师分布是 $P_p^{\text{tch}}=\mathrm{sg}[\pi_\theta(\cdot\mid h(\mathcal{G}),\tau_{i,<p})]$，其中 $h(\mathcal{G})$ 是上述事后信息块，$\mathrm{sg}[\cdot]$ 表示 stop-gradient：教师分布只作为固定目标，不通过它更新参数。两个前向共享同一组权重；教师分支多出的只是对事后信息块的编码。因为教师目标被 stop-gradient，反向传播只来自学生侧的蒸馏损失，不存在“更新一个单独教师模型”的问题。

4. **token 级 JSD。** 在每个查询 token 上，把教师和学生的分布限制在二者 top-k 的并集上（默认 $k=50$），重新归一化后计算对称 JSD，再对整条轨迹的查询位置取平均。若某条轨迹没有查询位置，则该项为 0，只用 GRPO 训练。总损失为

$$
\mathcal{L}_{\text{SD}}(\tau)=\frac{1}{|\mathcal{Q}_\tau|}\sum_{p\in\mathcal{Q}_\tau}\mathrm{JSD}\left(P_p^{\text{tch}}\,\|\,P_p^{\text{stu}}\right),
\qquad
\mathcal{L}_{\text{total}}=\mathcal{L}_{\text{GRPO}}+\alpha_{\text{SD}}\,\mathcal{L}_{\text{SD}}.
$$

选择 JSD 而不是前向 KL 或反向 KL，作者给出两个理由：JSD 对称，不会把学生偏向“覆盖所有众模”或“只追一个众模”；JSD 有界（不超过 $\log 2$），早期教师与学生差异很大时训练更稳。top-k 截断是为了避免在整个词表上计算 JSD。监督范围只取查询位置，是因为这些位置直接表达搜索决策；作者在 §3.3.2 把范围扩大到全部策略生成 token，平均 EM 反而下降 0.7 点。

5. **训练配置。** 实现基于 veRL 框架，策略优化器为 GRPO；底座为 Qwen2.5-3B 与 7B 的 base/instruct 版本。训练 200 步，批大小 256，组大小 5，每条轨迹最多 3 次搜索调用，采样温度 1.0；检索器为 E5-base-v2，语料为 2018 年 12 月的 Wikipedia，每次查询返回 3 篇文档。蒸馏系数 $\alpha_{\text{SD}}=10^{-3}$，前 50 步 warmup 期间为 0；top-k 为 50，结果阈值 $\rho=0$。训练更新全部策略参数，没有单独的教师、奖励模型或 SFT 阶段。论文报告 3B 全量训练在 8×H800 上约 11.9 小时，AutoRefine 基线在同一硬件、批大小、rollout 配置和检索器下约 10.3 小时。

6. **推理阶段。** 事后信息块、结果标签和教师前向全部被移除；两个视图坍缩回同一个策略。推理输入只有题目、系统提示和检索器；策略按正常方式决定何时搜索、发什么查询、何时给出答案。因为教师只存在于训练图里，推理时没有额外的模型副本、没有额外的前向、也没有对测试问题的任何结果标签，所以方法不构成测试时泄漏（test-time leakage）。需要强调的是，训练时使用的 Correct/Incorrect 标签来自训练集标准答案，和 GRPO 的奖励同源；测试时既没有标准答案，也没有同题 rollout 组，因此这套特权信息在部署时不可用。

7. **信息流总结。** 在每个被监督的查询位置，教师与学生的唯一上下文差异就是事后信息块；题目、已发生的前缀、模型参数都相同。训练的目标是把“看到事后信息的分布”蒸馏进“看不到事后信息的分布”。这正是方法名称中 on-policy 与 hindsight 的含义：教师是当前策略在训练中的副本，事后信息来自当前策略自己的 rollout，而不是一个固定的外部数据集。图 1 把这一信息流完整画了出来。

![图 1：方法总览](/images/dailypaper/2026-10-20/sdsearch_fig2_method_overview.png)

**图 1**（论文 Fig. 2）：方法的总信息流。学生与教师共享同一组参数，差别只在条件上下文：学生只看到推理时可用的题目与已发生的前缀，教师额外看到由同题 rollout 组构成的 hindsight 信息块；两侧在同一批 search-query token 上计算 JSD，教师分布被 stop-gradient 固定为目标，梯度只回到学生。训练时教师前向只增加一次上下文编码与查询位置上的分布计算，推理时教师分支被完全移除，因此部署路径与普通的 search-augmented agent 相同。

![图 2：教师输入布局](/images/dailypaper/2026-10-20/sdsearch_fig8_teacher_input.png)

**图 2**（论文 Fig. 8）：教师输入的 token 级布局。题目与已经发生的 think/search/documents 前缀与学生完全一致；随后插入兄弟 rollout 的 search-only 骨架及 Correct/Incorrect 标签，再给出 focal 轨迹自身的 search 骨架与结果标签，最后才到被监督的查询动作。这样，教师在同一前缀上多出的唯一信息就是“同题其他 rollout 怎么搜、结果如何”，而 JSD 只施加在查询 token 上；推理时整段 hindsight 被删除，教师视图退化为学生视图。图中也暴露出一个需要在 §5 进一步追问的细节：focal 自身的查询骨架出现在被监督动作之前，论文没有说明训练时是否把当前正在预测的查询从该骨架中屏蔽掉。

设计取舍可以逐项对应到方法组件。组聚合而不是只给 focal 轨迹，是为了在 focal 失败时仍然保留“成功兄弟怎么做”的对比；如果只看一条失败轨迹，教师没有可对比的正例。结果标签而不是只给查询文本，是为了把“哪些查询导致成功”变成条件信号；论文的消融显示，去掉标签损失 1.4 点，随机打乱标签损失 2.3 点，说明对比本身比标签存在更重要。未来掩码而不是保留完整轨迹，是为了防止 documents 或 answer 让教师直接看到答案；去掉掩码平均损失 3.0 点，多跳上损失更大。只用查询位置而不是全部 token，是为了把监督集中在搜索决策上；扩大到全部动作位置损失 0.7 点。JSD 而不是 KL 或 MSE，是为了兼顾对称性与有界性；替换为前向 KL、反向 KL、MSE 分别损失 1.0、1.4、2.1 点。warmup 的作用是避开训练早期格式尚未成形的 rollout；论文没有单独消融 warmup 的“有无”，只在论文 Fig. 4 中扫描了它的取值。

哪些行为由模型决定、哪些由固定流程控制，也需要分清。模型决定每条轨迹的推理内容、是否发起搜索、查询的具体措辞以及最终答案；检索器、语料、返回文档数、最大搜索次数、组大小、掩码规则、标签阈值和 JSD 的 top-k 都是固定的训练/系统配置。方法没有学习一个查询选择器或工具路由器，也没有让模型决定“是否使用教师”；教师分支是否启用完全由训练阶段决定。整个方法只增加了一个训练期的分布匹配项，不改变 agent 的动作空间、停止条件或工具接口。

## 4. 解决得怎么样？

### 4.1 实验设置

论文在七个问答基准上评测：单跳的 NQ、TriviaQA、PopQA，以及多跳的 HotpotQA、2Wiki、MuSiQue、Bamboogle。训练集沿用 Search-R1 一系的设定，由 NQ 与 HotpotQA 的训练划分合并而成；评测集在 NQ、TriviaQA、PopQA、Bamboogle 上用 test split，在 HotpotQA、2Wiki、MuSiQue 上用 dev split（论文 Appendix C、Table 5）。指标是标准化后的 Exact Match；主表报告七个基准的简单算术平均，而不是按题目数加权。数据规模差异很大：NQ test 为 3,610 题、TriviaQA test 为 11,313 题、PopQA test 为 14,267 题，而 Bamboogle 只有 125 题；HotpotQA dev 为 7,405 题、2Wiki dev 为 12,576 题、MuSiQue dev 为 2,417 题。这个规模差异是后文讨论平均值稳健性的关键背景。

底座模型是 Qwen2.5-3B 与 Qwen2.5-7B，各自都有 base 与 instruct 两个起点；所有消融都在 Qwen2.5-3B-Base 上完成。训练配置为 200 步、批大小 256、组大小 5、每条轨迹最多 3 次搜索、温度 1.0；检索器是 E5-base-v2，语料是 2018 年 12 月的 Wikipedia，每次查询取回 3 篇文档（论文 Appendix D、Table 6）。这些配置在 SD-Search 与 AutoRefine 的成本对比中被明确说明为相同；但论文没有逐一列出所有引用基线的搜索次数、rollout 数与训练步数，因此“同一检索器、同一语料”的声明是否对每个基线都成立，只能部分确认。

对比基线分三组：无检索的 Direct Generation、SFT、R1；单轮检索的 Naive RAG；多轮搜索增强方法，其中包括推理时提示的 Search-o1、IRCoT，outcome-reward RL 的 Search-R1、ReSearch、AutoRefine、MR-Search，以及依赖外部资源的 process-supervision 方法 StepSearch（GPT-4o 子问题标注）与 Thinker（72B 教师合成轨迹后 SFT）。表注明确写着“Dashes denote settings not reported by the original paper”，这意味着比较矩阵并不完整：StepSearch 在单跳列没有数字，也没有七基准平均值；MR-Search 只出现 Base 版本，没有 Instruct 版本；Thinker 只出现 Instruct 版本。论文还声明“Baseline numbers are taken from their original papers when evaluation protocols match”，但同时又说所有多轮基线共享同一检索器、语料和深度；这两句话之间存在张力，因为从原论文引用的数字未必是在同一检索器与同一搜索预算下得到的。论文没有逐项说明哪些数字是复跑、哪些是引用，这是后文公平性质疑的来源之一。

实验分工大致是：Table 1 与 Table 2 回答“在 3B/7B 上平均是否超过 outcome-reward 与 process-supervision 基线”；Table 3 与论文 Fig. 3 回答“事后信息块的哪些部分、哪种散度真正有用”；论文 Fig. 4 回答“四个自蒸馏超参数和组大小是否敏感”；Table 4 回答“五个随机种子下均值与方差是否稳定”；Appendix E 回答“训练成本增加多少”；Appendix F–I 回答“训练动态、逐 token 分布、案例与规模扩展是否支持机制解释”。这些实验覆盖了效果、消融、稳定性和成本四个维度，但没有一个实验把训练算力与基线严格对齐，这是后文要展开的主要缺口。

### 4.2 关键结果

先看 3B。论文 Table 1 报告，SD-Search-Base 的七基准平均 EM 为 0.428，AutoRefine-Base 为 0.405，MR-Search-Base 为 0.414，Thinker-Instruct 为 0.430；SD-Search-Instruct 为 0.427。按这些数字，SD-Search-Base 相对 AutoRefine-Base 提升 2.3 点、相对 MR-Search-Base 提升 1.4 点，与 Thinker-Instruct 相差 0.2 点。论文还报告，相对 StepSearch-Base，SD-Search-Base 在 HotpotQA 上高 9.6 点（0.425 对 0.329）、在 2Wiki 上高 8.1 点（0.420 对 0.339），在 MuSiQue 上高 0.7 点（0.188 对 0.181），在 Bamboogle 上高 7.4 点（0.402 对 0.328）。这些比较只覆盖 StepSearch 报告了数字的多跳列，不能推出“在所有基准上超过 StepSearch”。

逐基准看，3B 的 SD-Search-Base 相对 AutoRefine-Base 的提升并不均匀：NQ +0.3（0.470 对 0.467）、TriviaQA +0.4（0.624 对 0.620）、PopQA +1.7（0.467 对 0.450）、HotpotQA +2.0（0.425 对 0.405）、2Wiki +2.7（0.420 对 0.393）、MuSiQue +3.1（0.188 对 0.157）、Bamboogle +5.8（0.402 对 0.344）。所有基准方向都为正，但单跳增益明显小于多跳，这与作者“多跳轨迹内查询质量方差更大、token 级信号更有用”的解释一致。相对 MR-Search-Base，情况更复杂：NQ 低 0.7 点（0.470 对 0.477）、TriviaQA 低 1.1 点（0.624 对 0.635），PopQA 高 0.7、HotpotQA 高 0.6、2Wiki 高 1.9、MuSiQue 高 2.3、Bamboogle 高 5.8。相对 Thinker-Instruct，SD-Search-Base 在 NQ 高 3.1、TriviaQA 高 2.6、HotpotQA 高 2.5，但在 PopQA 低 0.2、2Wiki 低 4.9（0.420 对 0.469）、MuSiQue 低 2.6（0.188 对 0.214）、Bamboogle 低 2.2（0.402 对 0.424）。所以“与 Thinker 平均持平”是若干正负项相互抵消的结果，不是每个任务都持平。

再看 7B。论文 Table 2 报告，SD-Search-Instruct 平均 EM 为 0.476、SD-Search-Base 为 0.471；MR-Search-Base 为 0.460、AutoRefine-Base 为 0.455、Thinker-Instruct 为 0.452、Search-R1-Base 为 0.408。按这些数字，SD-Search-Instruct 相对 MR-Search-Base 提升 1.6 点、相对 AutoRefine-Base 提升 2.1 点、相对 Thinker-Instruct 提升 2.4 点。逐基准相对 AutoRefine-Base，七个方向全为正：NQ +1.1、TriviaQA +0.9、PopQA +0.7、HotpotQA +2.0、2Wiki +3.6、MuSiQue +3.5、Bamboogle +3.2。相对 MR-Search-Base 则只有 Bamboogle 拉开明显差距：NQ -0.7、TriviaQA +0.2、PopQA +2.2、HotpotQA +0.3、2Wiki +0.5、MuSiQue +0.1、Bamboogle +9.2（0.544 对 0.452）。相对 Thinker-Instruct，2Wiki 低 2.8 点（0.441 对 0.469），其余多为正。这个模式说明 7B 的“平均超过所有基线”主要靠 Bamboogle 与 PopQA，而不是在所有任务上普遍领先。

平均值受 Bamboogle 影响的程度可以按表中数字复算。七个基准的简单平均给 Bamboogle（125 题）与 NQ（3,610 题）、TriviaQA（11,313 题）相同的权重。去掉 Bamboogle 后，3B SD-Search-Base 相对 AutoRefine-Base 的平均优势从 2.3 点降到约 1.7 点，相对 MR-Search-Base 从 1.4 点降到约 0.6 点；7B SD-Search-Instruct 相对 MR-Search-Base 的平均优势从 1.6 点降到约 0.4 点。反过来，相对 AutoRefine-Base 的 7B 优势去掉 Bamboogle 后仍有约 2.0 点，说明对 AutoRefine 的比较相对稳健；但对 MR-Search 的比较对 Bamboogle 高度敏感。这些复算不是论文报告的数字，而是审稿人用 Table 1/Table 2 的逐项值做的算术检查，目的是说明“平均值被个别基准主导”的风险。

随机种子的结果给出了一些稳定性信息。论文 Table 4 报告，在 Qwen2.5-3B 上重训五个种子，SD-Search-Base 平均 EM 为 0.428±0.008，AutoRefine-Base 为 0.404±0.008，Thinker-Instruct 为 0.429±0.007；SD-Search 与 Thinker 的均值只差 0.001，与 AutoRefine 的均值差 0.024。论文声称 SD-Search 在“每一个种子”上都高于 AutoRefine，但表中只给均值±标准差，没有逐种子数值，读者无法独立复核“每一个种子”这一说法。作者也明确写道，这些差距是“consistent”而不是正式显著性检验的结果；五个种子在 RL 训练方差下只是 modest sample，Bamboogle 的标准差仍高达 0.022–0.028。Table 1 与 Table 4 的平均值还有小幅不一致：AutoRefine 在 Table 1 为 0.405、Table 4 均值为 0.404；Thinker 为 0.430 对 0.429；SD-Search 为 0.428 对 0.428。论文没有说明主表是单次运行、某个种子，还是另一组独立实验，这会影响读者对“主表数字代表什么”的理解。

规模扩展方面，论文 Appendix I 在 Qwen2.5 的 1.5B、3B、7B、14B 上训练 SD-Search、Thinker 与 AutoRefine，并在第 200 步报告七基准平均 EM（论文 Fig. 7）。按论文文字，1.5B 时 Thinker 相对 AutoRefine 为 +3.7，SD-Search 为 +2.5，Thinker 领先 SD-Search 1.2 点；3B 时两者基本持平（0.428 对 0.430）；7B 时 Thinker 相对 AutoRefine 转为 -0.3；14B 时转为 -0.5。SD-Search 在四个规模上都高于 AutoRefine：按“各自最佳变体”计为 +2.5/+2.3/+2.1/+0.9，按 Base-to-Base 计为 +2.5/+2.3/+1.6/+0.6。这个趋势支持“同策略教师会随学生一起变强，而固定外部教师会饱和”的解释，但 14B 的 +0.6 个百分点已经小于 3B 上 0.428±0.008 的平均标准差（即 0.8 个百分点），在没有 14B 多种子实验的情况下，不能把它当作稳定的正增益。论文的“never crosses zero”是描述点估计，不是统计结论。图 3 把四个规模上的相对位置画在一起。

![图 3：规模扩展](/images/dailypaper/2026-10-20/sdsearch_fig7_scaling.png)

**图 3**（论文 Fig. 7）：四个模型规模上的七基准平均 EM。三条曲线的相对位置随规模变化：1.5B 时外部教师仍占优，3B 基本重合，7B 之后 Thinker 相对 AutoRefine 的增益转负，而 SD-Search 始终保持在其上方；14B 处差距缩到不足 1 个点。该图支持“同策略教师随学生一起变强”的解释，但也显示收益在最大规模上接近噪声，不能据此断言 14B 仍稳定占优。

总体来看，规模扩展支持方法的相对优势，但 14B 的增益已经接近种子噪声，不能作为强结论。

### 4.3 机制证据

主结果只能说明“方法有效”，不能自动说明“有效的原因是作者说的那个机制”。SD-Search 的机制主张有三层：第一，事后信息块里的“结果对比”是信号来源；第二，token 级 JSD 比其它分布距离更适合把信号传给学生；第三，训练动态上应该看到查询质量上升而搜索次数不变。论文分别用构造消融、目标消融和训练曲线来支持这三层，但三者的证据强度不同。

先看事后信息块的构造消融（论文 Fig. 3、§3.3.1）。完整配置平均 EM 为 0.428。去掉结果标签损失 1.4 点，说明教师需要知道哪些轨迹成功；随机打乱标签损失 2.3 点，比去掉标签更差，说明“正确/错误”的对比本身在起作用，而不是标签文本作为一个普通条件在起作用；只保留成功轨迹损失 0.7 点，说明单侧模仿只能恢复部分收益；去掉整个多 rollout 组损失 1.0 点；leave-one-out（把 focal 轨迹从组里移除、保留 G−1 个兄弟）只损失 0.5 点，作者据此认为跨 rollout 的对比比 focal 自身的查询骨架更重要，教师不可能只是通过前缀块复制 focal 的查询。去掉未来掩码损失 3.0 点，HotpotQA 下降 3.8、2Wiki 下降 4.7；把整个块换成当前步文档损失 3.4 点。后两项是整个消融里最大的，说明“不要把答案/文档直接给教师”以及“要给跨 rollout 的查询骨架而不是局部检索结果”是方法成立的关键条件。图 4 把各构造变体的逐基准结果并列展示。

![图 4：事后信息块消融](/images/dailypaper/2026-10-20/sdsearch_fig3_hindsight_ablation.png)

**图 4**（论文 Fig. 3）：事后信息块构造的逐基准消融。完整配置在每个基准上最高或接近最高；去掉结果标签、打乱标签、只保留成功轨迹、去掉多 rollout 组、去掉未来掩码都会在至少一个多跳基准上造成可见下降，其中未来掩码和“教师只看当前文档”的下降最大。该图说明收益不是来自某一条固定查询模板，而是来自组内成败对比与查询骨架的共同作用；但图只给单次运行的柱状值，没有误差条，0.5–1.0 点的差异需要结合种子方差谨慎解读。

这些消融支持“构造方式有影响”，但还不足以证明“教师真的在评估查询质量”。一个关键问题是：论文 Fig. 3 没有误差条，也没有多种子重复；Table 4 给出的平均种子标准差约为 0.008（0.8 个百分点），而 leave-one-out 的 0.5 点、只保留成功轨迹的 0.7 点、去掉多 rollout 组的 1.0 点都接近或小于一个种子标准差。也就是说，真正稳健的结论是“未来掩码、结果对比和不要用当前文档替代整块”这几项影响较大；至于 focal 自身查询骨架是否有独立贡献，0.5 点的差异不足以单独下结论。论文用“cross-rollout contrast contributes more than τ_i's own search spans”来总结，方向合理，但统计上偏强。

再看对齐目标的消融（论文 Table 3、§3.3.2）。在查询位置固定为 JSD 时，换成前向 KL 平均下降 1.0 点，换成反向 KL 下降 1.4 点，换成 MSE 下降 2.1 点；把监督范围从查询位置扩大到全部策略生成 token 下降 0.7 点。作者对方向的解释是：前向 KL 是 mode-covering（众模覆盖），会让学生在所有教师支持的 token 上保留概率，导致预测变“软”；反向 KL 是 mode-seeking（众模寻找），会把学生压到教师最高概率的单个 token，损害多跳查询的多种可行改写；MSE 把每个 logit 坐标等权处理，忽略了概率单纯形的结构。这些解释与结果方向一致，但实验有一个明显的混杂：所有替代目标都沿用为 JSD 调好的 $\alpha_{\text{SD}}$ 与 top-k，没有为每种散度重新调参。MSE 在原始 logit 上的尺度与 JSD 完全不同，1.0–2.1 点的差距可能部分来自“没有调好”，而不是散度本身的优劣。Table 3 也没有种子误差条，因此它更像“默认配置下的工程比较”，而不是“JSD 在理论上更优”的严格证据。

训练动态提供了目前最强的机制证据（论文 Appendix F、论文 Fig. 5）。在 warmup 之前，SD-Search 与 AutoRefine 在验证 EM、检索质量、搜索频率上没有区别，因为蒸馏损失尚未开启；第 50 步之后，两者在 EM 与检索质量上分开，但搜索频率仍然接近。论文报告的教师—学生熵差从 warmup 前的约 0.25 降到 warmup 后约 30 步的 0.10 左右，再到第 200 步的约 0.065；检索质量（返回文档中包含标准答案的比例）从约 40% 上升到 50% 以上，SD-Search 在后期比 AutoRefine 高约 3 个百分点；搜索频率两者都维持在每轨迹约 2 次。作者据此认为增益来自“查询更好”而不是“搜得更多”，这排除了搜索次数这一替代解释。这个论证是有效的，但仍有两个限制：检索质量本身是一个代理指标，查询越长、越包含答案实体，越容易让返回文档命中标准答案，而这恰好与“教师可能通过查询串泄漏答案”的担忧重合；另外，训练动态只比较了 SD-Search 与 AutoRefine，没有与 Thinker 对比（作者解释 Thinker 是 SFT 而非 RL，训练轨迹不可逐 step 对齐）。图 5 把两条训练曲线与熵差放在同一时间轴上。

![图 5：训练动态](/images/dailypaper/2026-10-20/sdsearch_fig5_training_dynamics.png)

**图 5**（论文 Fig. 5）：SD-Search 与 AutoRefine 在 3B 上的训练动态。教师—学生熵差在 warmup 后快速下降，说明学生的查询分布正在向事后教师靠拢；验证 EM 与检索质量在蒸馏开启后分离，而搜索频率几乎重合。这个组合支持“查询质量而不是搜索数量”的解释：如果方法只是鼓励模型多搜，搜索频率曲线应该先上升；如果只是普通的 RL 继续训练，检索质量不该在 warmup 后出现系统性分离。图仍然只是两个方法的单次训练曲线，没有多种子带状区间。

逐 token 分布的证据更直接，但样本更窄（论文 Appendix H、论文 Fig. 6）。作者取一条失败的 Bamboogle 轨迹，在查询区间内比较三种条件下模型对“实际发出的 token”的概率：学生（无 hindsight）、教师（真实结果标签）、教师（把兄弟标签翻转）。在查询区间外，三条曲线基本重合；在查询区间内，真实教师给实际失败查询 token 的概率最低，翻转教师最高，学生居中。这个结果与“教师会把概率质量从失败查询移开”的机制一致，也说明信号定位在查询 token 上。但它是单条轨迹的示例，没有跨样本聚合；而且它与论文 Fig. 8 的输入布局存在张力：如果教师上下文里已经包含 focal 自身的查询骨架，教师预测这些 token 时可以直接复制，概率应该更高，而不是更低。论文没有解释这一矛盾，这可能意味着实际实现中当前查询被屏蔽了，也可能意味着论文 Fig. 8 只是示意而非逐 token 的真实输入。无论哪种情况，都需要作者澄清。图 6 给出这条轨迹上的逐 token 概率。

![图 6：逐 token 概率轨迹](/images/dailypaper/2026-10-20/sdsearch_fig6_token_trace.png)

**图 6**（论文 Fig. 6）：一条失败轨迹上的逐 token 条件概率。三种条件在查询区间之外几乎重合，在查询区间内分离：真实结果教师压低失败查询 token 的概率，翻转标签教师则抬高它，学生位于两者之间。该图把“事后结果对比”的作用定位到了查询 token，而不是整条轨迹；但它是单条 Bamboogle 轨迹的示例，且与论文 Fig. 8 中教师可见 focal 查询骨架的布局存在解释上的冲突，不能单独作为机制已证实的证据。

案例研究（论文 Appendix G、Table 8）展示了一个 2Wiki 问题：“Alexander of Masovia 的父亲的死亡日期是什么？”AutoRefine 把两跳压成一条查询，检索到 Alexander 本人的文档，答成 1400；Thinker 正确地分成两跳，但第二跳是泛化的 biography 查询，只得到年份 1426；SD-Search 先查父亲，再查父亲的死亡日期，得到 21 January 1426。这个例子很好地说明了“查询焦点”差异，但它是一个精心挑选的案例，不能替代系统性统计。论文没有报告失败案例的比例，也没有报告 SD-Search 在哪些问题上比基线更差。

把 §2 的三个创新点逐一对照，可以得到如下判断。事后信息块的构造有直接消融支持，其中结果对比、未来掩码、跨 rollout 聚合的作用较强；token 级 JSD 有目标消融支持，但受固定超参数混杂；把信号嵌入 GRPO 的工程组合有成本分解支持，但这属于效率证据而不是机制证据。最核心的“同策略教师”条件本身反而没有被单独隔离：论文没有把教师换成另一个 checkpoint、不同规模的模型、随机初始化的模型，或一个只看兄弟轨迹但参数不同的教师，因此无法判断收益究竟来自“同策略”这一条件，还是来自“任何带有事后信息的强条件”都能提供的正则化/自训练效应。也没有 compute-matched 的 AutoRefine（例如同样多训练 15.5% 的墙钟时间或同样多的 GPU-hours）来排除“多算一点自然更好”的解释；考虑到每步训练开销增加 41.6%，这是一个实质性的替代解释。

### 4.4 成本与适用范围

训练成本是论文报告得比较清楚的部分。3B、8×H800、200 步、批大小 256、组大小 5 的设定下，SD-Search 全量训练约 11.9 小时，AutoRefine 约 10.3 小时，端到端增加 15.5%（论文 Appendix E、Table 7）。但 15.5% 是摊薄后的数字：前 50 步 warmup 没有蒸馏开销，周期性的验证、checkpoint 保存和初始化合计约 5.2 小时且两种方法相同；按纯训练步计算，开销是 31.2%；按 warmup 后的单步计算，开销是 41.6%（92.40 秒对 130.83 秒）。其中 94% 的额外开销来自教师前向 + JSD 计算（+20.31 秒/步，+22.0%）和学生侧蒸馏反向（+16.13 秒/步，+17.5%）。论文没有报告显存占用，也没有报告推理时延；它只论证了推理路径不增加前向，因此“推理成本不变”是结构性的论断，而不是实测的延迟数字。对于只有 3B 模型的训练，8×H800 的配置和 11.9 小时墙钟并不算轻，论文也没有给出与 Thinker/StepSearch 的外部成本在同一单位下的总账：72B 教师被描述为“约 24 倍于 3B 教师前向的每 token 成本”，GPT-4o 标注被描述为覆盖约 10 万条训练样本，但没有给出 GPU-hours 或金额，因此“更 favorable 的成本—质量点”是合理的方向性判断，不是完整的成本比较。

超参数敏感性由论文 Fig. 4 给出：$\alpha_{\text{SD}}$、$T_{\text{warm}}$、top-k、$\rho$ 与 GRPO 组大小 $G$ 各扫一条曲线，默认值都位于峰值附近，整个扫描窗口内的平均 EM 振幅不超过 2.5 点。top-k 在 25–100 区间几乎平坦，作者解释为 JSD 的质量集中在少数高概率 token 上；$\rho$ 在 0 处最好，收紧到 0.75 时因太多 rollout 被标为 Incorrect、对比消失而下降，$\rho=1.0$ 又有小幅恢复。这个“默认值恰好在峰值”的模式本身值得注意：论文 Appendix D 说四个自蒸馏超参数是在 NQ 与 HotpotQA 的验证子集上选的，而 NQ 与 HotpotQA 同时出现在七个评测基准中（尽管用的是不同 split）。这不一定构成数据泄漏，但意味着“默认值在评测集上也是峰值”并不是完全独立的验证；论文没有报告验证子集的大小、选择准则或重复次数。7B 与 14B 直接沿用 3B 的配方，没有做 per-scale 调参；这保证了比较的一致性，但也可能让大模型的收益被 3B 的最优超参数低估或高估。

适用范围方面，论文自己在 §4 给出两条限制：第一，结果标签来自标准答案，因此方法要求任务有可靠可评分的参考答案；开放生成需要用偏好分数或组内多数投票替代二值标签，作者留作未来工作。第二，当组内所有 rollout 都成功或都失败时，Correct/Incorrect 对比退化；全失败时 GRPO 的优势也同时坍缩，全成功时对比消失，作者在 14B 上观察到增益收窄，并把这归因于更高的基础成功率导致组内标签更同质。这个解释与论文 Fig. 7 的 14B 收窄一致，但论文没有报告不同规模下的组内标签分布，也没有给出“同质组比例”的定量统计。除此之外，实验只覆盖固定检索器、固定语料、最多 3 次搜索、单工具问答；没有覆盖多工具、网页浏览、开放域长尾或需要多轮澄清的任务。单跳基准上的增益本来就小（3B 对 AutoRefine 的 NQ +0.3、TriviaQA +0.4），因此“搜索查询信用分配”在简单任务上是否仍有价值，证据不足。

哪些问题得到了改善、哪些仍未解决，可以分开列。改善的是：在不引入外部教师/标注的前提下，给出了一个可运行的步级查询监督信号；在多跳 QA 上取得了平均层面的提升；训练成本有一个明确的、可复现的分解；推理路径不变。未解决的是：教师条件的精确构造（当前查询是否可见）没有说明；与基线的算力对齐和统计显著性没有做；Bamboogle 这类小基准对平均值的影响没有被正面处理；开放生成、多工具、无参考答案的设置没有覆盖；没有官方代码，复现依赖作者未公开的实现细节。论文的结论应限定在“有可评分答案的单跳/多跳 QA、固定检索器与搜索预算、3B/7B 为主”的范围内，14B 的结论只能算初步。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：教师上下文可能包含被监督查询本身，复制与答案泄漏的边界没有被隔离

- **原文依据**：论文 Fig. 8（Appendix J）把 focal 轨迹自身的 search 骨架放在被监督查询动作之前，示例中这两段是同一串 token；§2.2 也明确说，当 $j=i$ 时教师会看到 $\tau_i$ 自己的 search spans。§3.3.1 的 leave-one-out 消融移除的是整个 focal 块（查询骨架加结果标签），只损失 0.5 点；Appendix H 的论文 Fig. 6 又显示真实教师给实际查询 token 的概率低于学生。成功兄弟的查询串还可能包含答案实体，例如论文 Fig. 8 中一条正确兄弟的查询就含 “January 1426”。
- **为什么重要**：如果当前查询在教师上下文中完整可见，JSD 目标可能退化为“复制已经采样到的查询”，而不是“判断这条查询值不值得发”；如果成功兄弟的查询串本身包含答案，即使 future masking 去掉了 documents 和 answer，答案仍可能通过查询串泄漏，模型学到的可能是“把答案写进查询”而不是“查得更准”。这直接影响方法正确性、机制解释和“无泄漏”的主张。
- **当前能够得出的判断**：当前材料无法确认。论文 Fig. 8 与论文 Fig. 6 的张力说明，要么实际实现屏蔽了当前查询但正文没有写，要么图示只是示意、不是真实的 token 布局；在作者澄清之前，不能把“教师评估查询质量”当作已经证实的机制。0.5 点的 leave-one-out 差异也不足以排除复制，因为它同时移除了 focal 的结果标签，两个因素没有被隔离。
- **如何验证或补强**：明确披露教师输入的 token 级构造；增加“只屏蔽当前查询、保留 focal 结果标签”的消融；测量教师对当前查询 token 的复制率（例如教师 top-1 与学生实际 token 的一致率）；做实体级泄漏分析，把兄弟查询中的答案实体遮蔽或替换；用不同 checkpoint 或随机初始化的教师做对照，确认“同策略”条件是否真的必要。
- **严重程度**：主要问题。

#### 质疑：比较矩阵不完整，且没有做算力对齐；“统计持平”也缺少检验

- **原文依据**：Table 1/Table 2 的表注写明 “Dashes denote settings not reported by the original paper”；MR-Search 只出现 Base 版本，StepSearch 没有单跳数字和七基准平均值；§3.1 说 “Baseline numbers are taken from their original papers when evaluation protocols match”。§3.2 使用 “statistically matching” 与 “statistically indistinguishable”，但 Appendix B 明确说这些差距是 “consistent rather than the result of formal significance testing”。Appendix E 显示 SD-Search 每步训练开销 +41.6%、端到端 +15.5%，论文没有给 AutoRefine 一个同等墙钟或同等 GPU-hours 的对照。
- **为什么重要**：如果给 AutoRefine 多 15.5% 的端到端时间或多 31–42% 的训练步计算，3B 上 2.3/1.4 点的平均优势可能缩小；不完整的比较矩阵使 “surpasses every baseline on the average” 只对表中有数字的基线成立。没有正式检验却使用 “statistically” 措辞，会让读者误以为显著性已经建立。
- **当前能够得出的判断**：证据不足，结论范围被夸大。更稳妥的说法是“在论文报告的数字上，平均 EM 高于 AutoRefine 与 MR-Search，与 Thinker 接近”；不能说“在同等成本下全面优于所有基线”。
- **如何验证或补强**：在同一训练/检索 harness 下复跑所有基线，逐项报告训练步数、rollout 数、搜索调用次数与 token 预算；做 equal-wall-clock 和 equal-GPU-hour 两组对照；补齐 MR-Search-Instruct 与 StepSearch 的单跳结果；对主表和种子结果给出配对检验或置信区间。
- **严重程度**：主要问题。

#### 质疑：平均提升被 125 题的 Bamboogle 放大，单基准存在负提升；“consistent” 的说法过强

- **原文依据**：Table 1/Table 2 与 Table 5 显示 Bamboogle 只有 125 题，而七个基准的简单平均给它和 NQ、TriviaQA 相同的权重；Table 4 中 Bamboogle 的种子标准差为 0.022–0.028，远高于其它基准的 0.006–0.015。3B 的 SD-Search-Base 相对 MR-Search-Base 在 NQ 低 0.7、TriviaQA 低 1.1；相对 Thinker-Instruct 在 2Wiki 低 4.9、MuSiQue 低 2.6、Bamboogle 低 2.2；7B 的 SD-Search-Instruct 相对 MR-Search-Base 在 NQ 低 0.7，相对 Thinker-Instruct 在 2Wiki 低 2.8。按表中数字复算，去掉 Bamboogle 后，3B 相对 AutoRefine 的平均优势从 2.3 点降到约 1.7 点、相对 MR-Search 从 1.4 点降到约 0.6 点，7B 相对 MR-Search 从 1.6 点降到约 0.4 点。
- **为什么重要**：这说明平均值被小样本基准和多跳任务主导，单基准并非全面占优；论文用 “consistent gains” 概括全部任务，超出了数据能支持的范围。Table 1 与 Table 4 的平均值还有约 0.001 的小差异（AutoRefine 0.405 对 0.404、Thinker 0.430 对 0.429），论文没有说明主表是单次运行还是种子均值，进一步削弱了“稳定”的叙事。
- **当前能够得出的判断**：平均提升是真实的点估计，但稳健性不足，尤其对 MR-Search 的比较；结论应改为“在多跳和平均值上具有竞争力，单跳上存在与强基线的互有胜负”，而不是“consistent gains over all benchmarks”。
- **如何验证或补强**：同时报告按题目数加权的平均与宏平均；给出每个基准的置信区间或种子分布；对 Bamboogle 做单独分析和 leave-one-benchmark-out 复算；补充 7B/14B 的多种子实验；把主表的运行次数与聚合方式写清楚。
- **严重程度**：主要问题。

#### 质疑：训练标签是“任意重叠即 Correct”，评测却是 EM；目标消融也没有为替代散度调参

- **原文依据**：§2.1 的奖励用最终答案的 F1；§2.2 的 Correct/Incorrect 标签由 F1 阈值 $\rho$ 得到，默认 $\rho=0$，“any non-empty overlap with the gold answer counts as Correct”；§3.1 的评测指标是 EM。Table 3 把 JSD 换成前向 KL、反向 KL、MSE 时，沿用 JSD 调好的 $\alpha_{\text{SD}}$ 与 top-k；论文 Fig. 3 与 Table 3 都没有误差条。Appendix D 说四个自蒸馏超参数是在 NQ 与 HotpotQA 的验证子集上选的，而这两个数据集同时出现在评测集中。
- **为什么重要**：一个回答只要与标准答案有一个 token 重叠就被标为 Correct，即使它的 EM 为 0；这样的“成功轨迹”可能包含错误答案，教师从中提取的“成功查询模式”可能是噪声。训练信号与评测目标不一致，会削弱“查询质量提升导致 EM 提升”的因果链。目标消融如果没有为每种散度重新调参，就不能公平地说 JSD 优于 KL/MSE；0.7–2.1 点的差异可能部分来自超参数不匹配。
- **当前能够得出的判断**：证据不足，设计需要补强。这不是致命错误，因为 GRPO 本来就用 F1 奖励，且论文 Fig. 4 显示 $\rho=0$ 在评测上最好；但论文没有报告“被标为 Correct 但 EM=0”的比例，也没有分析这种标签噪声如何影响蒸馏目标。
- **如何验证或补强**：用 EM 或更严格的 F1 阈值重做标签，比较不同 $\rho$ 下的 EM 与标签噪声率；统计 Correct 标签中 EM=0 的比例；为每种散度分别调 $\alpha_{\text{SD}}$ 与 top-k；给论文 Fig. 3/Table 3 加多种子误差条；在完全独立的验证集上选择目标函数与超参数。
- **严重程度**：次要问题。

#### 质疑：成本口径的头部数字偏乐观，关键复现细节与代码缺失

- **原文依据**：Abstract 与 Conclusion 强调 15.5% 的端到端开销；Appendix E 同时给出 per-step +41.6% 与 training-only +31.2%，并说明固定验证/保存/初始化约 5.2 小时且两种方法相同。论文没有报告显存占用，也没有测量推理时延；没有给出官方代码链接；1024-token hindsight 的截断方式、字符串级去重的具体规则、验证子集大小都没有说明；7B/14B 直接沿用 3B 的配方，没有 per-scale 调参。
- **为什么重要**：15.5% 是摊薄后的数字，实际训练循环的额外开销更接近 31–42%；没有显存和延迟数据，工程采用者无法评估部署成本；没有代码和截断细节，复现困难；超参数在包含评测数据集的 NQ/HotpotQA 验证子集上选择，独立验证不足。这些不影响论文的核心点估计，但影响可复现性和成本—收益判断。
- **当前能够得出的判断**：透明性部分足够（至少给出了三种口径），但可复现性弱；没有证据表明结果错误，但“15.5%”作为摘要数字有选择性，容易让读者低估训练开销。
- **如何验证或补强**：发布代码、配置、数据预处理与截断脚本；报告 GPU 显存、吞吐和推理延迟；把验证子集从评测数据集中彻底分离，或改用独立数据；在摘要中并列 per-step 与 end-to-end 两个数字，而不是只报较小的那个。
- **严重程度**：次要问题。

## 6. 审稿式总评

作者发现轨迹级奖励无法给搜索查询提供步级信用，因此提出同策略事后自蒸馏，通过让同一策略在“同题 rollout 组 + 成败标签”的事后条件下扮演教师、并在查询 token 上做 JSD 对齐来实现。实验在七个 QA 基准、3B/7B 两个规模、五个种子以及 1.5B–14B 扩展上表明：平均 EM 具有竞争力，多跳上的查询质量证据较强，训练成本有一个可以留在标准 RL 循环内的分解；但 Bamboogle 主导平均值、教师输入是否包含当前查询、算力未对齐、统计检验缺失，使“全面优于基线”和“机制已证实”仍缺少充分支持。本文最有价值的部分是把 on-policy rollout 组变成可复用的步级监督源，并诚实地报告了训练成本与两条失效条件；最大的审稿风险是教师条件的构造细节与比较公平性——如果这两点不能澄清，方法的核心解释会被削弱，但它的工程思路仍然值得关注。

- **问题定义清晰度**：强。论文把“轨迹级奖励无法区分查询好坏”定义得很具体，并在 §4 明确了两条失效条件；任务边界（有可评分答案的 QA、固定检索器）也交代得清楚。
- **创新性证据**：中。同策略自蒸馏、特权信息、hindsight credit assignment 都有先例，本文的增量主要在“用 rollout 组及结果标签构造教师条件、只在查询 token 上做 JSD”这一组合；论文与 Thinker/StepSearch 的差异是真实的，但是否“首次”缺少更完整的文献比较。
- **方法可信度**：中。方法结构简单、训练路径清晰、推理不改动；但教师输入中当前查询是否可见没有说明，论文 Fig. 8 与论文 Fig. 6 存在解释张力，核心的“同策略”条件没有被单独隔离。
- **实验支持力度**：中。七个基准、两个规模、五个种子、四个规模的扩展和三类消融覆盖较广；但比较矩阵不完整、没有算力对齐、没有正式显著性检验、小样本 Bamboogle 对平均值影响大。
- **可复现性**：弱。论文给出了较完整的超参数与成本分解，但没有官方代码，截断/去重/验证子集等细节缺失，baseline 是复跑还是引用也没有逐项说明。
- **综合阅读价值**：高。论文把“如何在不引入外部教师的情况下获得步级监督”讲得清楚，消融和成本分析有信息量，Limitations 也写得克制；即使方法本身仍有争议，它对搜索智能体的信用分配问题提供了一个可复用的思路。
