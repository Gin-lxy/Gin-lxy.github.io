## 0. 一句话结论

论文要解决的是评测效度（validity）问题：现有针对"经验学习/自我进化智能体（self-evolving agents）"的基准，其任务规则要么写在指令里、要么已被预训练覆盖，因此无法区分"从交互中学到新规则"与"复用已有知识"。作者的做法是新建 Learn2Play Bench——20 个手工设计的文本游戏，规则故意新颖甚至反直觉（例如"偷同事的午餐反而升职"）、反馈确定、自动评分，其中 10 个保持同一实例（fixed）、10 个每局更换可见实例但保留底层规则（re-shuffled），再用统一协议评测 11 个基础模型（backbone）、6 种经验保留方法、3 种智能体运行框架（harness），并与人类玩家对照。主要结论方向一致："保留完整交互历史比把经验蒸馏成规则更有利"只在 Kimi K3 上四项指标全面成立；"同一 backbone 换 harness 可同时提升性能与降低成本"和"实例洗牌拖慢学习、弱模型更明显"有多个模型支持；人类 Top-1 的峰值分（Max 84.3）高于所有被测智能体（最优 Claude Code + Opus 5 为 81.8），但这是按每游戏 21–30 名参与者中取最优 k 名的选择后统计，口径与智能体的三次 trial 平均并不对称。总体判断：作为评测框架与首批经验发现，证据有边界地成立（限于论文报告的 20 个游戏、黑盒文本接口、无权重更新的设定）；但"分数提升确实等于学到了隐藏规则"这一核心构念主要靠个案日志支撑，尚未被聚合成可检验的量化证据。

## 1. 论文具体想解决什么问题？

**研究背景与具体任务。** 论文关注的场景是：智能体部署到陌生环境（unfamiliar environment），其规则不在预训练知识内——例如"通过陌生指令接口控制机器人时，必须逐个尝试命令、观察运动，才能知道每个命令控制哪些关节"（§1）。这类任务中智能体不能更新模型权重，只能通过把交互反馈沉淀为记忆、规则、推理模式或配置更新来"自我进化"（§2）。论文问的是：**在这种环境下，现有 LLM 智能体到底能多有效地从经验中学习**（§1 核心问句）。

**现有方法通常如何处理、以及具体差在哪儿。** 评测侧，既有基准用任务序列或重复交互衡量提升：StreamBench（输入-反馈流）、MemoryBench / Evo-Memory（记忆更新）、LifelongAgentBench（技能累积）、SWE-Bench-CL（连续代码 issue）、MemoryArena（跨会话记忆）（§2）。论文指出它们的共同问题：**任务的底层规则往往来自熟悉的真实场景，可能已经存在于预训练中**，所以"越打越好"既可能来自学习新规则，也可能只是把预训练知识检索了出来（§1）。更接近本文动机的两个基准也被点出局限：J-TTL 用 Jericho 游戏测重复提升，但"公开内容可能已被预训练覆盖"；ARC-AGI-3 测试陌生视觉环境，但成绩被视觉能力混淆（§2）。

**作者的新观察与被忽略的问题。** 这是本文的出发点而非实验发现（属设计动机）：**"更好的任务表现"不等于"更强的学习能力"**，现有评价缺少一个把"规则必须是新的"当作硬约束的受控设置。论文把它具体化为四个设计原则（§3）：规则新颖性（rule novelty）、自动评分、可复现（反馈确定，可重放）、受控变化（跨 episode 改变可见情形以测试迁移）。

**支撑证据与原因归因。** 对"现有评测测不出学习"这一判断，论文给出的是综述性论证与引用（§1、§2），不是新实验。作者认为问题成因是任务设计与模型先验纠缠：只要规则可能出现在预训练分布里，"改进"就永远无法归因（§1）。本文实际解决的具体子问题是：构建一个规则全新、反馈确定、可自动评分的游戏基准，并在同一协议下回答五个研究问题（RQ1–RQ5，research question）：当前智能体学得多好、harness 如何影响学习、人类与 agent 有何不同、学到的知识能否迁移到新实例、更高推理成本是否带来更好表现（§4.2–§4.6）。

**核心假设。** "在新设计、隐藏规则的确定性文本游戏上，跨 episode 的分数提升主要来自从交互中发现规则，而不是预训练知识或纯粹的工具使用能力；并且这个设置足以区分不同 backbone、方法与 harness 的学习能力差异。"

**三类问题的区分：**

- **领域早已存在的一般问题**：智能体在测试时的经验复用与记忆管理；评测中"提升"归因困难——这些问题在 continual learning / self-evolving agent 文献中已被提出（§2）。
- **本文的新观察**：尚没有基准把"规则新颖性"作为硬约束，并为每个游戏档案化"规则发现证据"（Appendix D）；本文新增的实证发现包括：保留原始历史 vs 蒸馏规则的差异（§4.2.2）、实例洗牌对学习斜率的普遍拖累及其与模型能力的相关性（§4.5）、harness 对学习与成本的双重影响（§4.3、§4.6）。
- **本文实际解决的具体子问题**：构建 20 个游戏、四种指标（Max/Mean/LG/LS）、三层实例控制（fixed / re-shuffled / 同实例对照）的评测框架，并给出 31 个智能体配置与人类玩家的横向比较。

## 2. 创新点是什么？

**总括。** 本文不是提出新的学习算法，而是提出一个**受控评测基准 + 系统性实证研究 + 人类对照**的组合。技术增量在于：把"规则必须是新的"落实为可操作的游戏设计约束；用"同规则、不同可见实例"的成对条件把"学会规则"与"记住实例"分开（§3、§4.5）；在同一协议下把 backbone、方法、harness、人类四条对比线放在一起，并公开每个游戏的参考分数与评分依据（Appendix A.2.4）；全部评测不更新模型权重（§2 末）。这些都是评测方法层面的设计组合，不是新算法机制。

**创新点 1：20 个隐藏规则的文本游戏基准与固定/洗牌双条件设计。**

- 新增了什么：20 个人工设计的游戏模板（Appendix A.1 的 Table 4/5 逐条列出每个游戏"玩家需要学什么"），每个模板可用不同随机种子生成多个实例，实例间布局、角色或隐藏规则参数不同；10 个 fixed（同实例重复，考察对单一实例的记忆精化）+ 10 个 re-shuffled（每局换可见实例、规则固定，考察迁移）；通过 pilot 评测选出 5 个 challenge games（Catnip、DreamGarden、Mola Tea、RedEye、Roadside Observatory）用 10 局评分窗口，其余游戏用 5 局窗口（§3 脚注 1）。
- 与最接近方法的差异：J-TTL 复用公开 Jericho 游戏（规则可能已在预训练中），ARC-AGI-3 依赖视觉，StreamBench 类基准的任务是熟悉场景；本基准的差异是**规则的新颖性 + 确定性反馈 + 自动评分 + 实例重洗的对照**四者组合。
- 类型：**数据/评测设计**，含相当的人工工作量（20 个游戏 + 参考分数体系 + 21–30 名/游戏的人类被试），但设计原则（隐藏规则、确定性、可比条件）本身是已有评测思想的组合。
- 对应问题：直接回应"无法区分学习与已有知识"。
- 原文证据：Appendix A 的游戏与评分细节；§4 的五个 RQ 结果；Appendix D 的逐游戏档案。
- 是否"首次"：论文用"新设计游戏"措辞，未声称首创评测思路；related work 中 AutoEnv 也"创建新环境"，是否构成首次需要更完整检索。

**创新点 2：四指标度量体系与参考分数归一化，把"学得多好"拆成水平与趋势。**

- 新增机制：Max（各 trial 峰值分的平均）、Mean、学习增益（Learning Gain, LG；首尾 $k_g=\min(3,\lfloor T_g/2\rfloor)$ 局均分之差）、学习斜率（Learning Slope, LS；对局均分做线性拟合的斜率）（§4.1，Eq. 见 §4.1 定义式）。原始分按参考分数 $C_g$ 归一化为 $z=100x/C_g$；参考分数分三个证据级别：exact（有 oracle/证明）、partial（已证明的局部值）、estimated（合法搜索或分数上界的估计）（Appendix A.2.4, Table 6）。挑战游戏在聚合时权重 3、普通游戏权重 1，使两组各占 50% 权重（§4.1、Appendix A.2.3）。
- 差异与作用：把"绝对水平"（Max/Mean）与"改进速度"（LG/LS）分开，正是为了支撑"得分最高的模型不一定学得最快"这类发现（§4.2.1）。
- 原文证据：Table 1、Table 13（含 trial SD）；Appendix A.2 的完整公式；Appendix A.2.2 给出 Max 的语义例子（三个 trial 峰值 40、60、80 时 Max = 60 而非 80——即 Max 不是单次最高分）。

**创新点 3：方法、harness 与人类的三线对照，其中 harness 维度被显式控制。**

- 新增内容：在固定 backbone 下比较 6 种经验保留方法（Naive、Memory、Reflexion、EvoTest、ReasoningBank、Agent Workflow Memory（AWM））（§4.2.2）；在固定 backbone 下比较 harness（OpenCode vs Claude Code vs Codex）（§4.3）；人类研究使用同一界面，21–30 名大学生/游戏，另以行为统计（动作序列相似度、受挫后恢复率）比较策略差异（§4.4、Appendix B.3.3）。
- 与已有比较类工作差异：此前方法比较多为"每篇论文各自用不同模型与协议"（§1 指出这一困难）；本文在同一协议下重跑。
- 类型：**实验协议设计**；结论中"harness 改变可同时提升性能、降低成本"是单次比较中很少见的维度（§4.3、§4.6）。
- 原文证据：Table 2（harness 对照）、Table 1（方法对照）、Appendix B.3（人类细节）。
- 局限（审稿人判断）：方法对照只在 3 个 backbone 上做，且结论并不在每个 backbone 上同方向（详见 §5 质疑二）；harness 差异的机制解释（"模型在自己的 harness 上训练过"）是作者主张，只有文献引用支撑（§4.3）。

## 3. 作者如何解决？

**直觉。** 如果想让"学习"可测量，就要把"答案"从模型先验里拿走：把待学规则设计成预训练分布之外的新知识，把环境做成确定性、可重放、自动打分的文本接口，让"改进"只能来自试验与观察；再加一个"同规则、换实例"的对照，区分"记住这一局的答案"与"学会规则本身"。

**运行流程（按实际评测顺序展开；§3、§4.1、Appendix A、Appendix B.2）：**

1. **输入**：每个游戏向智能体呈现目标、当前状态描述与合法动作清单；智能体通过黑盒命令接口（black-box command interface）发出动作，只能看到文本反馈，不能访问游戏源码或 oracle 求解器（§4.1）。Figure 1 右面板以 Poisoner 为例展示了完整协议：环境枚举可选动作（serve_0 / serve_1 / serve_2），智能体选择 serve_2，环境返回结果描述（"The king eats the dish. Poison doses delivered: 1 of 3"），一局结束时自动给出分数（图示终局分 67 分，三次宴会中成功两次）。
2. **两类游戏实例控制**：fixed 游戏（10 个）重复同一实例，玩家可以持续精化地图/配方/动作序列；re-shuffled 游戏（10 个）每局更换菜单、客人、布局等可见要素，但底层规则保持不变，用于测试能否把学到的规则应用到新情形（§3、Appendix A.1）。
3. **局数与 trial 协议**：普通游戏每局序列 5 episode、挑战游戏 10 episode；每个配置-游戏组合要求 **3 个独立 trial**；每个 trial 从零经验开始，trial 内部保留多少跨局信息由 harness 决定（§4.1、Appendix A.2.1、Appendix B.2 明确 Claude Code 关闭持久记忆、Codex 使用 `--ephemeral`、OpenCode 每 trial 新 session，以隔离 trial）。
4. **计分与聚合**：先按参考分数归一化，再在每个游戏内计算 Max/Mean/LG/LS，最后按游戏权重（挑战 3、普通 1）聚合；学习曲线聚合时把不同局长映射到 0–100% 相对进度（§4.1、Appendix A.2.3）。
5. **无权重更新**：这些配置全部是"测试时学习"——智能体跨局复用经验的方式只有 prompt 上下文/记忆文件等外部载体，模型权重保持不变（§2 末、§3）。
6. **对照配置**：11 个 backbone 统一用 OpenCode harness；6 种方法分别在 Kimi K3、Opus 5、GPT-5 Mini 上固定 backbone 比较；harness 对照（Opus 5 用 OpenCode vs Claude Code；GPT-5.6-SOL 用 OpenCode vs Codex）；人类玩家用同一界面（§4.1–§4.4）。
7. **输出**：每个配置四项聚合指标（含 trial 标准差，Appendix C）、逐游戏学习曲线与"规则发现证据"标注（S = 至少一个 trial 提供完整证据；P = 仅有部分证据；– = 证据不足；Appendix D）。

Figure 1 的阅读方式：左面板是 20 个游戏模板的图标与名称，标注了三种属性——解谜图标（重洗实例）、锁图标（固定实例）、星标（挑战游戏），它说明基准覆盖的规则类型很广（合成配方、社交禁忌、遗传规律、侦查推理等），并提示每个模板可生成多个实例；右面板是 Poisoner 的交互协议，展示一次完整的"观察-决策-反馈"循环和终局自动计分。为什么需要这两部分：左面板保证"规则新颖性"不是单一题材的偶然（20 个游戏分散在不同推理类型上），右面板展示了度量的最小单元——确定性文本反馈 + 自动分数，这是后续所有 learning curve 能够可复现对比的前提。注意：智能体看不到毒药机制等隐藏参数，它只能从"国王是否吃下"这类二元反馈中推断，这正是"必须通过交互学习"的具体操作化。

**关键约定（评审时容易忽略的点）：** 分数区间因游戏而异（参考分数从 7 到 6300，Table 6），所以跨游戏聚合必须先归一化；Max 定义为"每个 trial 各自峰值分再取平均"，因此同一份日志用不同聚合方式会得到不同名次（Appendix A.2.2 专门给了例子说明）。这些都是本文为"可复现比较"付出的额外设计。

**教学简化示例（显式标注，非论文实验）：** 可以把 re-shuffled 设计想象成"换一张卷子考同一个知识点"：fixed 游戏像反复做同一套题，分数上涨可能来自背答案；re-shuffled 游戏像每次换题面，只有真正掌握规则的人才能保持上升。论文用 Table 3 的"同实例对照 vs 洗牌条件"对比学习斜率，正是这个直觉的量化版本——但如果 agent 的改进只是更熟练地使用工具（比如更会写搜索脚本），这个类比并不能自动成立，这也是 §5 质疑一的核心。

## 4. 解决得怎么样？

#### 4.1 实验设置

- **任务与数据**：20 个游戏模板各固定一个 seed 实例（Table 6），普通游戏 5 局评分窗口、挑战游戏（Catnip、DreamGarden、Mola Tea、RedEye、Roadside Observatory）10 局；每个配置-游戏组合跑 3 个独立 trial，无缺失 episode 分数填补（§4.1、Appendix A.2.1、Appendix C）。
- **基础模型（backbone）**：11 个被测模型——GPT-6 Astra、Claude Opus 5.5、Claude Opus 5、Claude Sonnet 5、Gemini 3.5 Flash、Gemini 3.7 Flash、GPT-5.6-SOL、GPT-5 Mini、DeepSeek V4 Pro、Kimi K3、Qwen 3.8 Max——统一在 OpenCode harness 下运行（shell 与文件工具、相同 agent loop、replay 协议与记忆格式）（§4.2）。
- **方法**：Naive（不留跨局经验）、Memory（把前几局完整历史原样追加进新局 prompt，超上下文预算时丢弃最老的局）、Reflexion、EvoTest、ReasoningBank、Agent Workflow Memory（AWM），分别在 Kimi K3、Claude Opus 5、GPT-5 Mini 上固定 backbone 比较（§4.2、Table 1、Table 7）。除 Naive 外，其余方法均为引用已有工作的实现（非本文提出）。
- **harness**：OpenCode（通用开源编码 agent）、Claude Code（配 Opus 5）、Codex（配 GPT-5.6-SOL）；trial 隔离与上下文处理设置见 Appendix B.2。
- **人类对照**：每游戏 21–30 名大学生，使用同一界面，禁止使用 AI 工具或代码，按 Max 选出 Top-1/3/5；额外公布全体参与者平均（Max 43.6）（§4.4、Appendix B.3.1–B.3.2）。行为统计只用 Human Top-3 与 6 个 Opus 5 方法在 fixed 游戏上的观测记录（Appendix B.3.3）。
- **指标与成本口径**：Max/Mean/LG/LS（§4.1 公式）；成本用记录的 token 用量估价（除 Opus 5.5 用 2026-10-07 官方价、GPT-6 Astra 用确认账单外，其余用 2026-08-30 价格快照）（Appendix B.5.1）。
- **公平性设计**：同游戏实例、同评分窗口、同 trial 协议；方法与 harness 比较都固定 backbone。主实验回答 RQ1–RQ5；Appendix C 回答"结果是否稳定"（31 个配置 × 4 指标的 trial 标准差）；Appendix D 回答"每个游戏里具体发生了什么"（曲线 + 规则发现标注）。

#### 4.2 关键结果

**（1）backbone：得分最高 ≠ 学得最快（RQ1，Table 1、Fig. 2A）。** Claude Opus 5.5 的 Max 80.1 与 Mean 61.0 全场最高；但学习速度指标由 Qwen 3.8 Max 领先（LG +25.2、LS +6.30，对比 Opus 5.5 的 LG +23.0、LS +5.22）。最弱的 GPT-5 Mini 的 Max 仅 34.0（OpenCode 下）。交互日志显示差异来自反馈使用方式：Opus 5 与 Qwen 3.8 Max 会检验并修正对隐藏规则的假设，而弱模型会重复以前有效的动作、或在一次尝试中同时改变多个因素（§4.2.1 的 Poisoner 案例：GPT-5 Mini 固定按菜单位置点菜，Kimi K3 则用"接受/拒绝"反馈推断下一个要测的属性，Appendix B.1.4）。

**（2）方法：保留原始历史只在 Kimi K3 上全面占优（RQ1，Table 1、Fig. 2B）。** 在 Kimi K3 上，不做任何反思/蒸馏的 Memory 以 Max 63.3、Mean 48.0、LG +16.9、LS +4.69 四项第一，优于 Reflexion、EvoTest、ReasoningBank、AWM；对比之下 EvoTest 在 Kimi K3 上的 LG 只有 +1.8、AWM +4.8，接近"没有学习"。但这一结论并不跨 backbone 成立：Opus 5 上 EvoTest（Max 66.1）与 Reflexion（64.8）都高于 Memory（60.9）；GPT-5 Mini 上 Reflexion（53.5）最高，且 OpenCode 该模型（34.0）低于全部六种方法。三 backbone 平均（Table 7）里，Memory 的 Mean（44.5）与 LS（+3.04）最好，但 Max 第一是 Reflexion（60.0）。作者给 Memory 的机制解释是：反思与蒸馏会把不完整证据固化成规则，原始历史则保留了可修正的证据（Appendix B.1.3 的 GemForge 案例：EvoTest–Opus 5 因一次合成失败就在 prompt 里禁止了"tier-2/tier-3 融合"，连未测试过的可行组合也被排除）。

**（3）harness：同模型换执行框架全面提升（RQ2，Table 2）。** Opus 5 下 Claude Code 对照 OpenCode：Max 81.8 vs 74.5、Mean 62.3 vs 53.8、LG +27.1 vs +21.3、LS +6.59 vs +5.13；GPT-5.6-SOL 下 Codex 对照 OpenCode：Max 74.3 vs 57.0、Mean 54.8 vs 41.1、LG +22.2 vs +14.5、LS +5.66 vs +3.71。作者的解释是模型在自家 harness 上被训练过、且 harness 适配模型能力（§4.3，属作者主张，有引用但无组件级消融）。

**（4）人类对照：峰值领先，均值落后（RQ3，Table 1、Fig. 2C）。** Human Top-1 的 Max 84.3 高于所有智能体配置（最高的 Claude Code + Opus 5 为 81.8；人类 Top-k 不报告 trial SD，Appendix C）；但注意其 Mean 53.5 低于 Claude Code（62.3），也略低于 OpenCode–Opus 5（53.8）。行为统计（Appendix B.3.3）：fixed 游戏上相邻两局动作序列平均相似度人类 0.5379（150 对）vs 智能体 0.6575（918 对）；一局分数回落后下一局刷新个人最好的比例人类 33.3%（13/39）vs 智能体 21.8%（52/238）。分游戏看，人类 Top-1 在 GemForge、Grapevine 得分更高（策略发现型），OpenCode–Opus 5.5 在 RedEye、Model Auditor 更高（长序列执行与程序化计算型）（§4.4）。全体人类平均 Max 43.6，低于除 OpenCode + GPT-5 Mini（34.0）外的全部智能体配置（Appendix B.3.2）。

**（5）迁移：实例洗牌拖慢学习，且对弱模型更狠（RQ4，Table 3）。** 同规则下把"同实例重复（Control）"换成"每局换实例（Re-shuf.）"，学习斜率下降最大的是 Claude Sonnet 5（4.90→2.23，drop 2.67）、Gemini 3.7 Flash（2.15）、GPT-5.6-SOL（1.94）、Gemini 3.5 Flash（1.73）；Opus 5（0.59）、Claude Code + Opus 5（0.52）、Kimi K3（0.88）受影响最小；Qwen 3.8 Max（−0.41）与 Codex（−0.19）甚至出现负 drop（洗牌条件下拟合斜率略高，属噪声量级）。方法侧（Appendix B.4, Table 9）：Opus 5 配 Memory 的 drop 0.88 最大，AWM（−0.37）与 Naive（−0.08）无损失但也无学习。SynergyCorp 的日志案例显示两种迁移方式：Opus 5 把从旧 boss 学到的"可见桌面特征→偏好动作"映射直接用于新 boss（在 30 个动作预算下常能一次选对有效动作，得 137），Sonnet 5 与 Gemini 3.5 Flash 则对每个新 boss 重新试探（分别得 67 与 84）（Appendix B.4.1）。

#### 4.3 机制证据

论文的机制论述可以分成三层，强度不同：

**第一层：曲线证据（较强但只说明"发生了学习"）。** 20 个游戏的学习曲线（Fig. 2A/B 聚合、Appendix D 逐游戏）显示分数随 episode 普遍上升，且 fixed 与 re-shuffled 条件存在系统性差异（Table 3）；trial 标准差已报告（Appendix C），但如前所述这批曲线只能支持"行为在改善"，不能单独区分改善来自规则学习还是探索/工具熟练度。

**第二层：个案日志（存在，但被作者自己限定为示例）。** 论文用档案化的交互记录支撑机制解释：Memory 的优势被归因于"原始证据可修正错误规则"（GemForge 案例，Appendix B.1.3）；探索停止被归因于"找到局部可行策略后不再测试替代方案"（Opus 5 在 GemForge 得出"更高价值宝石无法合成"后重复已知配方，§4.2.3）；规划失败与规则知识分离被 Haunted Inn 案例展示——agent 能陈述相关禁忌却没有为最后一位客人预留安全房间，下一局才改为预留（§4.2.3、Appendix B.1.2）。这些案例都来自记录的动作与可见旁白（非私有思维链），但覆盖范围有限：Appendix B.1.2 明确说明这些是"说明可能机制而非其频率"，Appendix B.1.3 更进一步声明"不能据此断言压缩就是 Memory 与其它方法总体差异的原因"（原文：It does not establish that compression causes the aggregate difference from Memory）。

**第三层：规则发现标注（存在但刻意不聚合）。** Appendix D 为每个游戏定义了局部目标 T1–Tk，并给每个配置标注 S（至少一个 trial 提供完整规则证据）/P（部分）/–（不足）；论文明确不做总体百分比汇总，理由是"标注标准混合了完整规则发现与成功执行"（Appendix B.1.1），且"高分本身不能证明每条隐藏规则都被掌握"（Appendix D 引言）。此外 Opus 5.5 与 GPT-6 Astra 不参与标注（"仅分数验证不足以证明规则发现"）。

**替代解释是否被排除：部分。** 成本机制有直接的 token/调用数据支持（方法每次动作都调模型并重复供给历史：calls/episode 27–30 vs OpenCode 8.1，Table 11）；但 (i) 未做"删除/打乱历史内容"的干预实验来证明 agent 真的在用学到的规则；(ii) 方法比较不是机制消融（无组件移除实验）；(iii) harness 优势的归因（"模型在自家 harness 上训练过"）没有组件级验证；(iv) 人类-智能体行为差异统计在原文中即被声明为描述性而非因果检验（样本内观测不独立，Appendix B.3.3）。因此按证据分类：性能层面的结论是原文事实；机制层面的结论多为作者主张 + 案例佐证，尚未达到因果验证的强度。

![Figure 4：Memory 方法在四种 backbone 上的学习曲线](/images/dailypaper/2026-10-09/2610.08215_fig4.png)

Figure 4 单独看 Memory 这一种方法在四个 backbone 上的曲线，是"方法效果依赖 backbone"这个论点的最直观证据：Gemini 3.5 Flash（紫）曲线最高、Kimi K3（蓝）与 Opus 5（绿）居中且几乎重叠，GPT-5 Mini（红）全程压在 40 以下且增长缓慢。它说明两件事：其一，同一个"原样保留历史"的策略在不同模型上收益差别很大——强模型能把原始历史转成有效推断，弱模型则不能；其二，曲线在前 20–30% 进度涨幅最快、之后趋平，提示收益主要来自早期对环境的适应。需要谨慎的地方：四个 backbone 的起点不同（Gemini 3.5 Flash 起点也最高），所以曲线高低不能直接读作"Memory 对 Gemini 最有帮助"，判断增益要看各自的 Naive 或 OpenCode 基线（Table 1/13）。

#### 4.4 成本与适用范围

**论文报告的成本（RQ5，Fig. 3、Table 11–12）。**

- **单局成本**：全部配置的估计成本区间约为 $0.0063–3.09/episode（Table 12）。以 Kimi K3 为例：OpenCode 0.56M tokens/局、$0.313/局、Max 68.5；对比 Claude Sonnet 5 的 OpenCode 配置 0.73M tokens/局、$1.33/局、Max 55.9——"单价更贵的模型总成本反而更低"（§4.6，Table 12 数字）。
- **harness 省成本**：Kimi K3 下 OpenCode 比 Memory 少 56% 输入 tokens，比 EvoTest、ReasoningBank 分别少 71%、41% 生成 tokens；原因是 OpenCode 一次模型回复可执行多个游戏动作（一次 GemForge 轨迹把 9 个动作合并进 1 次调用，只回传最后 60 行输出），而六种自进化方法每个动作调一次模型并重复供给历史（§4.6、Table 11、Appendix B.5.1）。EvoTest 光"更新"（跨局反思/策略演化）每局就生成 11.5K tokens，超过 OpenCode 的全部生成量 7.2K（Table 11）。
- **省成本≠有收益**：Reflexion 与 AWM 的总估计成本低于 OpenCode，但 Max 也更低（Kimi K3，Table 11：Reflexion $0.300 对 OpenCode $0.313，Max 61.6 对 68.5）。
- **账单与估计的混合**：GPT-6 Astra 是唯一有确认账单的配置（$150 / 600 episodes = $0.25/episode），其 token 用量不完整（4,253 条唯一记录中 13 条缺可用 token 计数），因此被排除在成本-性能前沿之外（Appendix B.5.1 称 token 总量"仍是下界"）。
- **论文未报告的成本**：墙钟时延（wall-clock latency）、harness 的完整提示词长度、以及人类实验的时长；游戏设计、参考分数计算与 21–30 名/游戏的人类被试招募是本文的人力成本，论文未给出总工量估计。

![Figure 3：Max 分数与平均单局成本（x 轴为对数尺度；虚线为标准价格估计配置的性能-成本前沿）](/images/dailypaper/2026-10-09/2610.08215_fig3.png)

Figure 3 的读法：每个点是一个配置（形状区分方法、颜色区分模型），纵轴是 Max、横轴是单局平均成本（对数坐标），虚线是"标准价格估计"配置里可达到的最优权衡前沿。它要回答 RQ5：更多钱是否买到更高分。图中几个关键结构：右上角的 Claude Code + Opus 5 与 Codex + GPT-5.6-SOL 用较低成本拿到高 Max（Codex 约 $0.144/局、Max 74.3，比值 516.6 Max/USD，Table 12）；中部的 Qwen 3.8 Max 在 $0.225/局达到 72.5（性价比高于 $2.57/局的 OpenCode + Opus 5 的 74.5）；左侧低成本的 Gemini 3.7 Flash / GPT-5 Mini / DeepSeek V4 Pro 分数也低。结论是成本与性能不单调：换成与模型匹配的 harness 或更省 token 的模型，可以在更低成本下提高 Max（§4.6）。注意 Astra（确认账单配置）不在这条前沿上，其效率比值被论文省略。

**适用范围与边界。** 论文结论成立于：黑盒文本接口、确定性反馈、每配置 3 trial、5–10 episode 窗口、模型权重不变、20 个特定游戏。对连续控制、视觉交互、真实代码库任务或需要权重更新的自进化方法，论文没有实验证据。方法侧结论（Memory > 蒸馏类）只在 3 个 backbone 上测试且方向依 backbone 而变；"harness 很重要"这一条对两个模型对儿成立，但依赖具体 harness-模型的配对关系。作者在 §5 提出的三个开放方向（探索-利用平衡、如何存储规则、如何识别环境变化中不变的规则）也说明这些问题目前仍未解决。

## 5. 最容易受到审稿人质疑的地方

#### 质疑：基准的核心构念"学到了规则"没有被聚合成可检验的证据，分数提升与规则发现之间存在缺口

- **原文依据**：Appendix B.1.1 明确记录"不把规则发现标注聚合成总体百分比，因为存档标准混合了完整规则发现与成功执行"；Appendix D 的 S/P/– 标注只按游戏保留；机制解释全部是个案日志（GemForge、Haunted Inn、Poisoner，§4.2.3、Appendix B.1.2–B.1.4），且 Appendix B.1.3 自己声明"不能据此断言压缩就是方法间总体差异的原因"；得分曲线（Fig. 2、Appendix D）只证明行为改善。另外，论文没有报告任何"模型在交互前不知道这些规则"的直接校验（如受控问答、零交互先验测试），规则新颖性只有设计声明与 pilot 难度估计（§3）。
- **为什么重要**：这决定基准是否兑现了它自己的承诺——"区分从交互中学到的东西与预训练知识"（§1）。如果分数提升可以来自更熟练地使用工具、更长的思考预算或 in-context 搜索，那么 Table 1–3 的比较就不能被读作"学习能力"的对比，整篇论文的构念效度（construct validity）受损。
- **当前能够得出的判断**：分数随 episode 改进、且 fixed 与 re-shuffled 条件存在系统差异，是可复现的原文事实；"改进=学到隐藏规则"目前主要是设计假设 + 案例佐证，证据不足；S/P 标注体系已经存在，具备聚合条件但论文选择不做。
- **如何验证或补强**：汇总并报告 S/P 标注的总体分布与评分者一致性；增加"规则内容干预"实验（如清空/打乱记忆中的规则性内容，观察成绩回退）；给出交互前的先验测试以证明规则确实不在预训练中；对同一日志的"工具使用熟练度"与"规则发现"做分项归因。
- **严重程度**：主要问题

#### 质疑：关键结论的适用范围被概括性表述放大，且与自己的表格存在矛盾

- **原文依据**：摘要与 §1 finding (1) 泛化陈述"保留完整动作与反馈记录比把经验总结成规则或策略更能支持学习"，但 Table 1 中该结论只在 Kimi K3 上四项指标全部成立：Opus 5 上 EvoTest（Max 66.1）与 Reflexion（64.8）高于 Memory（60.9），GPT-5 Mini 上 Reflexion（53.5）最高；Table 7 的三 backbone 平均里 Max 第一也是 Reflexion（60.0）而非 Memory。§4.2.2 声称"OpenCode 在同一 backbone 下优于所有被测自进化方法"，但 GPT-5 Mini 下 OpenCode 的 Max 34.0 低于全部六种方法（Reflexion 53.5、ReasoningBank 51.9、Naive/Memory 48.7、EvoTest 47.5、AWM 47.0）（Table 1）。
- **为什么重要**：这是论文三大发现中的两条（经验保留、harness/框架灵活性）的证据基础；若结论只在部分 backbone 上成立，正确的表述应是"方法效果与 backbone 能力交互"，而不是普适排序；与实际表格矛盾的概括会直接影响读者对结论的信任。
- **当前能够得出的判断**：表格数字可核实，矛盾属实；论文未讨论 GPT-5 Mini 上的反向结果，也未解释为什么同一种 harness 在弱模型上反而不如逐动作调用的方法（可能如 §4.2.2 所述"模型决定何时查看反馈"在弱模型上失效，但这是审稿人推断，论文没有验证）。
- **如何验证或补强**：扩大方法比较的 backbone 覆盖（至少补 2–3 个中档模型）；对方法×backbone 的交互做配对统计检验；报告方法在弱模型上的失败模式（工具调用错误率、上下文超限率）；修改摘要与引言的概括，使之与 Table 1/7 一致。
- **严重程度**：主要问题

#### 质疑：人机对比不是同口径比较——人类值是 21–30 人中的 Top-k 选择，agent 值是 3 次 trial 峰值的平均

- **原文依据**：Appendix B.3.1 说明人类 Top-1/3/5 按每游戏 21–30 名参与者中观测到的最高分选择；Appendix A.2.2 说明 agent 的 Max 是各 trial 峰值分的平均；Appendix C 明确"Human Top-k 组不是独立重复 trial，我们不给这些被选组附加 agent 的 trial SD，也不将其解释为总体不确定性"。人类与 agent 的指标构造也不同（人类用 observed episode scores（观测分优先于回放值）；agent 用固定 5/10 局窗口，Appendix B.3.1–B.3.3）。若看同口径的全体参与者平均，人类 Max 43.6 低于多数 agent 配置（Appendix B.3.2）。行为统计（序列相似度 0.5379 vs 0.6575；恢复率 33.3% vs 21.8%）在原文中即被声明为"描述性比较而非因果检验"，且观测来自同一被试/同一 run 的重复测量，不独立（Appendix B.3.3）。
- **为什么重要**：finding (2) 与 §5 讨论的核心叙事是"顶级人类仍然强于 agent，因为探索更广"，但"顶级人类"是极值统计量；这影响结论的公平性表述与"人类上限"的解释力。它不否定现象的定性方向（多处案例支持人类策略更多样），但影响强度判断。
- **当前能够得出的判断**：Human Top-1 Max 84.3 是"21–30 人取最优"的描述统计，不能直接对比 agent 的 3-trial 平均；"人类在峰值上仍有优势"在论文数据内成立，但差距的统计显著性未知；"人类探索更广"目前只有行为相关性证据。
- **如何验证或补强**：报告人类峰值的分布（全分布或 bootstrap 区间）与 agent 峰值的同规模重采样；将人类样本量匹配到 agent 的 trial 数；对人类与 agent 的行为差异做分层配对检验；披露人类被试的游戏经验与练习效应控制。
- **严重程度**：主要问题

#### 质疑：复现材料当前不可得，成本数字依赖多项未完全披露的假设

- **原文依据**：Appendix B.2 只披露 trial 隔离设置（Claude Code 关闭 persistent auto-memory、Codex 用 `--ephemeral`、OpenCode 每 trial 新会话），其余"使用 CLI 或提供商默认设置"；全文未给出任何 harness 的提示词模板、最大上下文/token 预算与工具定义清单。项目网站（论文 §1 给出链接，本次核查 2026-10-09）显示代码仓库处于"access currently restricted"，游戏门户 learn2play.fun 需要登录。成本侧：除 GPT-6 Astra 用确认账单外，其余为"标准价格估计"（2026-08-30 快照），缓存复用按 5 分钟生命周期与各模型最小可缓存长度重建；4,253 条唯一记录中 13 条缺可用 token 计数，作者自认 token 总量"仍是下界"（Appendix B.5.1）。620 个配置-游戏 cell 的原始 trajectory 未公布。
- **为什么重要**：基准类工作的主要价值是让第三方能独立运行并验证；没有提示词、工具配置与游戏源码，"换一个 harness/方法就会变"的核心结论无法被独立复现或反驳。成本是结论 (3)/(5) 的支撑指标，其假设（缓存命中、价格快照时间）直接影响 harness 之间"更省"的比较。
- **当前能够得出的判断**：评测协议、指标定义、参考分数与 trial SD 的披露相当充分（Appendix A/C 是正面示例）；但"把代码跑起来"所需的关键材料当前不可得，作者似在准备公开（仓库链接已存在但受限），公开时间论文未承诺。
- **如何验证或补强**：随论文放出游戏源码、harness 配置与提示词、模型快照版本（尤其 GPT-6 Astra、Opus 5.5 这类闭源端点）、原始 trajectory 与成本计算脚本；对成本报告缓存命中率实测值与价格假设的敏感性分析。
- **严重程度**：主要问题

#### 质疑：试验次数少、只报标准差、无显著性检验，细粒度排名落在噪声区间内

- **原文依据**：Appendix C：每个配置-游戏 cell 仅 3 条完整 trajectory（共 620 个 cell），作者自述"少量 trial 限制了 SD 估计的精度"，且"这是 SD，不是多 trial 均值的标准误或置信区间"。Table 13 中若干相邻配置的区间明显重叠，例如 Kimi K3 下 Memory 63.3±4.0 vs EvoTest 62.4±3.5、Opus 5 下 Memory 60.9±3.9 vs ReasoningBank 60.2±4.8；Table 3 的洗牌 LS drop 里出现两个负值（Qwen 3.8 Max −0.41、Codex −0.19），提示部分条件的 trial 级波动与效应量同阶。全文没有显著性检验或多重比较校正。
- **为什么重要**：方法排名、"某 harness 更好"、"洗牌拖慢多少"这些论断的粒度依赖统计支撑；重叠区间意味着部分精细结论（例如 Kimi K3 下 Memory 与 EvoTest 的 Max 差 0.9）当前不可断言。它不推翻大效应结论（例如 GPT-5.6-SOL 的 harness 切换 Max +17.3、Claude Code 对 OpenCode +7.3，切换幅度大于各自 trial SD），但论文没有帮读者区分这两类。
- **当前能够得出的判断**：方向性大效应证据较强；相邻名次之间与部分游戏级差异证据不足；应把 Table 13 的 ±SD 作为解读所有排名的必要背景而不是装饰。
- **如何验证或补强**：增加独立 trial 数（作者已具备自动化框架，边际成本低）；报告基于 trial 的配对检验与效应量；对关键比较（方法×backbone、harness×模型）给出置信区间；对洗牌 drop 的负值给出解释或更稳健的估计。
- **严重程度**：次要问题

## 6. 审稿式总评

作者发现"自我进化智能体"的现有评测无法区分从交互中学到新规则与复用预训练知识，因此提出 Learn2Play Bench：20 个新设计的隐藏规则文本游戏，以固定的四条原则（规则新颖、自动评分、可复现、跨局受控变化）和 fixed/re-shuffled 成对条件，把"记住实例"与"学会规则"尝试分开，并在同一协议下比较 11 个 backbone、6 种经验保留方法、3 种 harness 与人类玩家（不更新权重）。实验在 20 个游戏、每配置 3 个独立 trial 的条件下表明：同 backbone 换用模型原生 harness 可四项指标全面提升且在部分组合下降成本（Opus 5 下 Claude Code 对 OpenCode：Max 74.5→81.8；GPT-5.6-SOL 下 Codex 对 OpenCode：57.0→74.3，Table 2）；实例洗牌普遍压低学习斜率且对弱模型更明显（drop 最大 2.67，Sonnet 5；Opus 5 仅 0.59，Table 3）；保留原始历史的 Memory 在 Kimi K3 上四项最优（63.3 / 48.0 / +16.9 / +4.69，Table 1）。其中**证据较强**的是 harness 切换效应（跨两个模型对一致、SD 小于效应量）、洗牌的学习斜率拖累（多模型一致方向）、以及"得分最高≠学得最快"的指标分离（Qwen 3.8 Max 的 LG/LS 领先于 Opus 5.5，Table 1）；**仍缺少充分支持**的是"保留原始证据优于蒸馏"的普适性（只在 Kimi K3 成立，Opus 5/GPT-5 Mini 上被 EvoTest/Reflexion 反超）、人类对 agent 的领先幅度（Top-k 选择口径 + 无显著性检验）、以及"agent 真的学到了隐藏规则"这一核心构念（只有归档个案与设计声明，没有聚合证据，Appendix B.1.1）。本文最有价值的部分是把"学习"从口号变成一套可重放、可迁移测试、含参考分数与 trial 方差的评测框架，并诚实报告了一批负结果（复杂方法不总是更好、更贵不总是更好、换实例可能让学习退化）；最大的审稿风险是核心构念没有被直接测量，加上若干概括性结论超出了其表格证据的覆盖范围。

- **问题定义清晰度**：强——§1 把问题收敛为一个可操作问句，§3 将"规则新颖性"落实为四条设计原则，§4.1 与 Appendix A.2 给出完整指标公式、归一化与权重规则，四个指标各自回答"水平"还是"趋势"有明确分工。
- **创新性证据**：中——基准设计（隐藏规则 + 确定性反馈 + 重洗对照 + 参考分数体系）是已有评测思想的系统性组合，harness 对照与人类行为统计提升了增量价值；但"规则不在预训练中"无独立校验，"是否首次"需要更完整检索，方法层面没有新算法。
- **方法可信度**：中——评测协议严密（同实例、同窗口、trial 隔离、自动评分、规则发现标注按游戏存档），但三处口径问题（GPT-5 Mini 上"OpenCode 全胜"的反例未讨论、人类 Top-k 与 agent 平均不同口径、机制归因以案例为主）削弱了方法层面的可归因性，且关键材料（提示词、游戏源码）未公开。
- **实验支持力度**：中——覆盖面广（31 个配置 × 20 游戏 × 3 trial，成本与方差都有报告），大效应结论有 trial SD 支撑；但每格 3 trial、只报 SD、无显著性检验，细粒度排名（方法之间、部分游戏之间）证据不足，核心"学习"构念依赖个案。
- **可复现性**：中——指标、参考分数、评分窗口、trial 协议与大部分模型身份披露充分（Appendix A/C 质量高），但 harness 提示词与配置细节、游戏源码、原始 trajectory 与成本脚本当前不可得（项目仓库受限、游戏门户需登录）；成本为含假设的估计且 token 记录存在下界问题。
- **综合阅读价值**：高——为 agent 经验学习与自我进化研究提供了可直接复用的评测视角（fixed/re-shuffled 对照、四指标分离、harness 变量控制），并给出多条可检验的负结果与开放问题（探索-利用平衡、经验表示形式、环境变化下的不变量识别），对做评测与做方法的研究者都有参考意义。
