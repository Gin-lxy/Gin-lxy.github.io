0. 一句话结论

论文针对流式视频交互中的一对矛盾——证据在”未来是否相关”已知之前就离开模型有限的视觉窗口，而响应时机又缺少稳定的监督信号——提出 OneStreamer：把”记录证据”（写记忆）与”按时响应”统一到同一个因果生成过程的任务控制 token 上（</Observe>/</Summary> 写记忆、</Silence>/</Standby>/</Response> 控制时机），并配套一条”内容与时间都对证据对齐”的流式数据合成管线（产出 OneStreamer-1M）。在论文报告的 8 个流式视频理解基准上，4B 模型取得所列对比方法中的最高分（Table 1）；消融支持”保留生成记忆可改善历史问答且不降实时感知”（Table 2）与”选择性状态监督优于密集监督”（Table 3）。但全部结果来自单次训练与单次评测、无方差／显著性报告，且各基准的评测协议并不统一，因此结论应限定为”在本文评测配置与对比集合内成立”，尚不能外推为流式视频交互已被普遍解决。

1. 论文具体想解决什么问题？

研究背景与任务。 真实世界的视频以开放式流到达（直播助手、可穿戴设备、安防监控等场景），模型必须在不知道”哪些观察以后会变得重要”的前提下解读不断到来的视觉证据；一个当下看似不重要的事件，等到相关提问出现时其源帧可能早已离开有限的视觉上下文；同时用户可见的响应必须”以目前已有的证据为依据”并及时给出（§1）。论文由此提出核心问题：流式视频 LLM 如何把到来的观察转化为可复用的事实记忆，并让其支撑及时的响应（§1）。

现有方法及其失效条件（作者综述）。 三条路线各有缺陷（§1）：(1) 压缩或检索远距视觉证据的记忆机制能延长可访问历史，但被保留的历史视觉 token 会与近期观察竞争有限的上下文容量，可能削弱实时感知（引用 [18] 的既有观察）；(2) streaming thinking 方法维护演化的推理轨迹，但推理轨迹不一定能充当未来任务可复用的、带时间锚定的事实记录；(3) 基于状态 token 的响应控制实现了主动输出，但密集监督这些 token 会让重复的静默标签相对稀疏的响应决策占比过高。

本文的新观察（作者主张）。 论文重述了 proactive generation 的角色：除了产生用户可见的响应，流式模型还可以学习把观察到的证据转化为可复用的事实记录，从而把”感知学习”与”与查询无关的记忆形成”连接起来（§1）。也就是说，”何时写记忆／何时回答”和”写什么／答什么”可以共用同一个生成过程。

问题判断的证据基础。 问题陈述本身主要引用既有工作（记忆与感知竞争引用 [18]；状态监督不平衡在 Streamo [28] 等生成式状态控制工作中被间接体现）；本文自己的实证锚点出现在后文消融：Table 2 中 Full（保留全部视觉历史）在 OVOBench Backward ASI 67.6 高于 FIFO（仅 Recent-16）63.5，但 FIFO 的 OVOBench Real-Time 80.9 高于 Full 70.9——这重现了”视觉历史与实时感知存在取舍”的现象（§5.2，Table 2）。注意这是相关性观察：论文没有做独立干预实验去分离”上下文容量竞争”与其他解释。

核心假设。 若把证据记录与任务响应放在同一因果生成序列中联合学习——用 </Observe>/</Summary> 生成带时间锚定的文本记录（训练时由流式 caption 目标监督”对已观察前缀的解读”），用选择性状态监督（PSTL）修正等待／输出状态失衡——则模型可以在不重访历史视觉特征的前提下获得可复用记忆，并学会在证据充分时及时响应（§3.1–§3.3）。

三个层次的区分。 领域一般问题：流式/在线视频理解的”记忆与实时感知权衡”以及”何时响应”的时机控制，均为已有研究方向（§2 引用了结构化记忆、检索、streaming thinking、状态 token 等大量工作）。本文新观察：把 proactive generation 复用作”与查询无关的记忆写入接口”，并把状态监督问题表述为”重复等待状态主导状态损失”的标签不平衡。本文实际解决的子问题：在 4B 模型、单阶段 SFT 的预算内，让一个模型在 8 个给定基准上同时改善记忆问答、实时感知与主动响应（§5）。

2. 创新点是什么？

一段话概括。 真正的技术增量是把已有的”生成式状态控制”机制（沿用 Streamo [28] 式控制 token 的范式，§1、Table 3 注明 Focal 损失即来自 Streamo）复用作两件事：其一，用两个专门的记录 token（</Observe>、</Summary>）让模型在流进行中主动写下两级粒度、时间锚定的文本记忆（PHCM），推理时以”Recent-N 视觉窗口 + 累积文本记录”的异构历史替代”重访历史视觉特征”；其二，用 PSTL 的选择性状态监督缓解”大量重复 </Silence> 淹没稀疏输出锚点”的标签不平衡；其三，配套一条可复用的流式数据合成管线，把离线视频资源转成”内容与释放时间都与可用证据对齐”的训练序列（OneStreamer-1M）。思想层面的核心是”proactive generation 作为共享学习接口”，其余多为已有组件（FIFO 窗口、控制 token、SFT、caption/QA 合成）的新组合与监督策略改进。

创新点 1：Proactive Hierarchical Caption Memory（PHCM）。

  • 新增了什么机制：两个控制 token——</Observe> 引出短区间内稠密的局部细节描述（对象、动作、场景、状态变化），</Summary> 引出对已完成事件或片段的稀疏语义总结；记录与来源时间区间对齐，生成后追加进文本历史，在源帧离开视觉窗口后继续可用（§3.1–§3.2）。
  • 与最接近工作的差异：记忆压缩／检索类方法保留的是历史视觉 token（与当前观察竞争容量）；streaming thinking 保留的是推理轨迹而非事实记录；PHCM 在推理时不做检索、不重访历史视觉特征，也没有外部 retriever 或记忆编码器（§1、§3.2、Appendix A.2）。
  • 是新思想还是组合：是”流式 caption + 记忆 + 控制 token”的组合，但”生成即记忆写入（query-independent memory writing）”是一个明确的表述性推进。
  • 对应什么问题：§1 的”形成可复用事实记忆而不损害实时感知”。
  • 证据：同 checkpoint、同 Recent-16 窗口下，仅改变”是否保留生成的 caption 记录”，OVOBench-Backward ASI 从 63.5 升到 71.6（+8.1），OVOBench Overall 70.1→72.1，StreamingBench Real-Time 86.3→86.9（Table 2）；两级记录分量消融中 Observe-only 使 OVOBench Overall 达 71.7、Summary-only 达 71.2、两者合用 72.1（Table 18）。
  • 移除后：退回 FIFO（丢弃远距事件）或 Full（挤占实时感知），两者各有一端明显较弱（Table 2）；若去掉 60K caption 监督数据、仅在推理时提示模型记录，则记忆增益消失（OVOBench Δ=-0.1、StreamingBench Δ=+0.3，Table 17）。

创新点 2：Proactive State Transition Learning（PSTL）。

  • 新增了什么机制：按”前一个控制状态→当前控制状态”的转移把状态 token 分组，取指向输出锚点的最大组大小作为全序列共享的监督配额 q=max⁡Xmax⁡a∈AτnX→aq=\max_{X}\max_{a\in\mathcal{A}_{\tau}} n_{X\to a}q=maxX​maxa∈Aτ​​nX→a​（Eq. 1）；每组均匀无放回抽样 min⁡(nX→Y,q)\min(n_{X\to Y}, q)min(nX→Y​,q) 个 token 计入状态损失（Eq. 2）；未入选 token 只从状态损失中屏蔽，仍留在因果序列中参与后续预测；caption 与答案文本的监督完全不变（§3.3，Appendix A.1，Eq. 3）。
  • 与最接近工作的差异：密集监督（含 Streamo 的频率平衡 Focal 损失）监督 100% 状态 token；”只监督状态切换”（Transition Only）缺失对”状态持续”的直接监督；PSTL 同时保留全部输出锚点与代表性的状态持续样本。
  • 是新思想还是组合：配额抽样本身是常规技术，但”锚点全覆盖 + 组级下采样”的监督选择规则是针对状态不平衡的组合式设计。
  • 对应什么问题：§1 的”重复静默标签主导状态目标”。
  • 证据：同数据、同输入序列、同文本监督下，PSTL 仅监督 27.5% 状态 token 即全面最优（ProactiveVQA 48.7、OmniMMI 36.6、OVO-Timing Avg F1 41.6），超过 100% 监督的密集 CE（26.1/30.8/1.5）与密集 Focal（47.0/32.8/26.5），也超过同监督比例的随机稀疏（26.6/27.4/1.4）与 Transition Only（46.7/27.4/15.3）（Table 3）。
  • 移除后：密集 CE 下三个主动响应基准分别只剩 26.1/30.8/1.5；随机稀疏说明”稀疏本身”不产生增益。配额 qqq 的其他定义方式（如按中位数、按固定比例）没有消融——论文未报告。

创新点 3：流式数据合成管线与 OneStreamer-1M。

  • 新增了什么：caption 分支（视频策展→多粒度标注→验证→因果流式序列构造：</Observe> 在支撑区间结束、</Summary> 在片段完成时释放，视频级 caption 作为流结束后的指令回答目标）；QA 分支（任务导向 QA 生成→粗粒度证据区间定位并用 VLM 复答验证→细粒度响应时刻校准：在区间内以 1 秒步长滑动窗口打分，取”平滑后分数不低于峰值 0.04 的第一候选”为响应时刻，再做可答性验证）（§4.1–§4.2，Appendix B.2–B.3）。
  • 与已有数据差异：论文指出既有流式 QA 数据的问题——响应目标早于充分证据出现（诱发语言先验与幻觉）或晚于证据可用时刻；该管线把”证据出现的位置”与”证据何时足够触发响应”分离处理，校准后平均提前响应时刻 13.72 s，86.62% 的记录获得更早的响应时间（Appendix B.3）。
  • 对应什么问题：§1 的”学习何时记录／响应”需要时间对齐的监督。
  • 证据：渐进式数据消融中，CQTC 阶段（只对既有 caption/QA 做内容验证与响应时间校准，不增加新样本）把 OVO-Timing 从 33.0 提到 42.0、五基准均值从 53.4 提到 55.6（Table 20）。
  • 规模与去污：OneStreamer-1M 共 1,160,004 条记录（Proactive Caption Memory 60,000、Proactive Interaction 271,570、Proactive QA 197,584、Perception & Memory QA 630,850），另混入清洗后的开源数据；训练前按”源视频级”对全部评测基准测试集去污（同一视频的非重叠片段也移除）（Appendix B.1）。

创新点 4（支撑性，不单独计为思想创新）：训练时的”记忆监督”双重作用。 caption 目标不仅教模型写记忆，还在视觉窗口受限时监督”对已观察前缀的解读”——去掉 60K caption 数据后，即便推理不使用记忆，OVOBench 69.8→70.9（Full 设置）等六个视觉-only 设置全面下降（Table 16）。这属于训练监督设计的改进。

原始性边界。 根据本文的 related work 与实验对比，只能确认作者声称的差异（相对记忆压缩/检索、streaming thinking、密集状态监督）；”把 proactive generation 同时用作记忆写入接口”是否首次提出，还需要更完整的文献检索；论文自身未使用 “first” 类表述。

3. 作者如何解决？

直觉说明。 与其让模型在”被提问”时才回头找证据（那时相关帧可能已被 FIFO 窗口丢弃），不如让它边看边把值得留的信息写成”事实卡片”（</Observe> 局部细节、</Summary> 事件总结），卡片是文本，不占视觉预算，之后提问时直接读卡片 + 看最近画面即可；再用一组控制状态让”写卡片””等待””待命””回答”成为同一个生成序列里可学习的决策，训练时用选择性监督避免”等待”标签淹没”动手”标签。图 3 给出了这一在线架构。

图 3 的分区逻辑（为什么这样设计）：底部是增量到来的 live video stream 与 ViT/投影器，只把最近 NNN 帧的视觉 token 放进 FIFO 窗口——这保证”输入序列只含当前时刻可得的信息”，代价是远距事件会离开窗口；中部 LLM 接收”视觉 token + 文本历史”的因果序列，左侧 Past Memory 区显示 </Observe>/</Summary> 记录（源帧离开后仍留在文本历史里，扮演远距事实来源）；右侧 Real-time Perception 与 Proactive Response 区显示 </Silence>/</Standby>/</Response> 在时间轴上的时机决策（提问在第 N+2 片段出现后，模型先 </Standby> 再 </Response>）。三类控制 token 合在一条序列里，是”记录、感知、响应共用一个生成过程”的直接体现。

运行流程（按实际执行顺序）。

  1. 输入。 时间有序的视频片段流；视觉编码器抽 token、投影器映射到 LLM 嵌入空间；Recent-NNN FIFO 窗口只保留最近 NNN 帧对应的视觉 token，与包含累积 caption 记录和对话的文本历史交错（§3.1）。训练数据含图像、离线视频与在线视频，采样率动态 1–4 FPS、最多 2,048 帧（Table 7）。
  2. 控制词汇（模型决定）。 任务特定的控制 token 表示”写记录、继续观察、或产生用户可见响应”（§3.1）：对 PHCM 任务是 </Silence>/</Observe>/</Summary>；对主动 QA 是 </Silence>/</Standby>/</Response>；对主动交互是 </Silence>/</Response>（Table 5）。输出锚点集合 Aτ\mathcal{A}_{\tau}Aτ​ 即能引发文本输出的状态（PHCM 为 </Observe>/</Summary>，主动类任务为 </Response>）。
  3. 推理循环（固定流程 + 模型决策，Appendix A.2）。 每个决策步把当前视觉 token 与保留的对话、已生成记录拼接；模型预测控制状态——预测为 </Observe>/</Summary> 时自回归生成记录文本并追加进文本历史（源帧之后可以离开 FIFO 窗口，记录保留）；预测为 </Silence> 则不写记录继续观察；主动 QA 时从当前上下文预测 </Silence>/</Standby>/</Response>，仅 </Response> 后生成用户可见回答。没有外部检索器、记忆编码器或对已丢弃视觉特征的事后访问（Appendix A.2）。
  4. 训练（一次性 SFT）。 从 Qwen3-VL-4B-Instruct 初始化（注册响应控制 token 与 summary token），在 OneStreamer-1M 与 LLaVA-Video 采样的离线数据上做单阶段 SFT：冻结视觉编码器，训练 projector 与 LLM；1 epoch / 1,174 步、全局批 128、样本与打包长度均 131,072 tokens、峰值学习率 1×10−51\times10^{-5}1×10−5 余弦退火至 1×10−61\times10^{-6}1×10−6、BF16 + FSDP + FlashAttention-2、32 张 H200、随机种子 42（§5 实现细节，Table 7；991,773 条装入样本打包为 150,261 条序列）。
  5. 4.2 关键结果

总体（Table 1，8/8 基准为对比方法最高）。 感知与记忆：OVOBench Overall 72.1（对同尺寸 Qwen3-VL-4B 58.8 提升 13.3；对 11B MOSS-VL-Realtime 70.2 提升 1.9）；StreamingBench Real-Time 86.9（对 81.8 / 82.9 分别 +5.1 / +4.0）；OVBench Avg 66.8（对 55.4 / 53.7 分别 +11.4 / +13.1）；ODVBench Overall 71.3（对 57.6 / 63.9 分别 +13.7 / +7.4）。主动响应：ProactiveVideoQA 48.7（对 34.3 / 47.2 分别 +14.4 / +1.5）；OmniMMI 36.6（对 29.4 / 32.7 分别 +7.2 / +3.9，OneStreamer 部分子任务使用 ASR）；OVO-Timing Avg F1 41.6（对 29.4 / 38.5 分别 +12.2 / +3.1）；ViSpeak 2.87（对 2.41 / 2.48）。Fig. 1 图注宣称平均相对提升 25.0%（对 Qwen3-VL 基线）与 6.1%（对各基准最强竞争者）。

图 1 的作用：把 8 个基准（度量各不相同：Overall 分、准确率、Avg F1、0–5 分）并排展示，一眼看出”全面领先”的结论建立在何种对比集合上；注意各面板纵轴不可比、基线集合随基准而异（各基准”最强竞争者”并不相同），这也是本报告 §5 质疑 1 的由来。

不应忽略的另一面。 (a) 提升幅度差异大：对最强竞争者，OVOBench 仅 +1.9、ProactiveVideoQA +1.5，而 OVBench +13.1；平均的”全面最优”掩盖了基准间差异。(b) 逐子任务并非全胜：OVO-Bench 的 Real-Time OCR 子项，Mage-VL 96.0 高于 OneStreamer 94.6（Table 8）；同时 OneStreamer 的 HLD 子项高达 99.5，而所列基线最高为 AURA 58.6——偏差异常大且正文未作解释（详见 §5 相关质疑）。(c) ViSpeak 的绝对值仍低：2.87 处于 0–5 分制低位（分制见官方仓库 README），说明主动交互任务远未解决，正文未讨论绝对水平。(d) 方差、置信区间与显著性检验全文未报告，所有数字来自单次训练（seed 42）与单次评测；部分基准的领先幅度（如 StreamingBench 86.3→86.9 的 +0.6）无法确认是否超出运行噪声。(e) 数据配方消融（Table 20）显示最终配方并非处处最优：ProactiveVQA 在加 FPPR 后从 49.7 降到 47.3、终值 48.7 低于早期阶段峰值 49.7；OmniMMI 与 OVO-Timing 的终值也略低于 CQTC 阶段（30.6 vs 30.8；41.6 vs 42.0）——作者将其解释为”各阶段各有最优、整体配方综合最强”（§E.4），态度诚实，但说明配方对基准的组合敏感性未经系统研究。(f) 失败案例：Appendix F.3 中模型在 00:10 把”掀开打印机盖”误报为”合上打印机”，随后 00:11–00:13 的新证据已能澄清状态却保持 </Silence>、不修正先前回答——论文未报告失败率。

4.3 机制证据

论文的消融矩阵在同类工作中属于较系统的，但”有效”与”为什么有效”要分开看：

  • PHCM 的”记忆可复用”（效果+部分机制）。 Table 2 用同 checkpoint、同 Recent-16 窗口，仅改变”是否保留生成记录”：ASI 63.5→71.6、Overall 70.1→72.1、StreamingBench 86.3→86.9。由于模型、数据、视觉窗口全同，这一对比排除了训练差异与视觉预算差异，支持”记录本身携带后续可用的信息”。Table 18 进一步分解两种记录的贡献（Observe-only 71.7 / Summary-only 71.2 / 合用 72.1，OVOBench Overall），说明增益不是单一粒度独有。
  • “监督 vs 提示”的分离（机制证据较强）。 Table 17 是关键对照：把”无 caption 监督数据”的模型也用同样的”主动记录提示”推理并保留其自生成描述，记忆加成只有 -0.1（OVOBench）/+0.3（StreamingBench）；有监督的模型则是 +2.0/+0.6。这支持”记忆构造与使用能力来自专门监督，而非推理时提示”。注意混杂：无监督模型不会用 </Observe>/</Summary>，只能用 </Response> 形式描述，两者文本形态不同，”同样保留文本却无增益”的结论因此仍带形式差异的保留。
  • PSTL 的因果隔离（机制证据最强）。 Table 3 在”同训练数据、同输入序列、同文本监督”下只改状态 token 选择与状态损失：同监督比例（27.5%）的随机稀疏只有 26.6/27.4/1.4，接近密集 CE 的崩溃水平，而 PSTL 为 48.7/36.6/41.6——排除”稀疏性本身”的解释；Transition Only（18.1%，只监督切换）在 OmniMMI/OVO-Timing 明显落后（27.4/15.3），说明”状态持续”样本有必要被监督；密集 CE 与密集 Focal 的差距（26.1 vs 47.0）复现了标签不平衡现象。这组对照干净地支持了设计动机。
  • 数据管线的机制证据（中等）。 Table 20 的 CQTC 阶段”不加新样本、只做验证与校准”使 OVO-Timing 33.0→42.0，支持”时间校准质量本身就是监督信号强度”。但渐进式配置是累积的，每阶段同时引入多类数据，无法把增益归因到单一数据类型；每阶段只有一次训练。
  • 不能排除的替代解释。 (1) 对比基线的训练语料与 OneStreamer-1M 不同且不可比（后者吸收了 Streamo、JoyAI-VL-Interaction、MMDuet-2、ViSpeak、StreamForest 等公开训练数据，Appendix B.1），”方法 vs 工程/数据规模”的贡献无法完全分离；(2) 文本上下文长度增加（PHCM 比 FIFO 多 1,272 tokens，Table 4）与”记录内容”的作用没有等长随机文本对照；(3) 主动响应的评测部分依赖自动裁判（ProactiveVideoQA 用 Qwen3-235B-A22B）与基准自带的时序指标，没有人工评分对照。

4.4 成本与适用范围

训练成本。 单阶段 SFT：32 张 H200、1 epoch / 1,174 步、打包后 150,261 条序列、最大长度 131,072（§5、Table 7）；wall-clock 训练时长与数据合成（百万级记录的闭源 API 调用）成本论文未报告。

推理成本（论文报告的两种口径）。 答案阶段（360 s OVOBench 样本、单张 H200，记忆预计算）：Full 25.18 GB / 62,094 tokens / TTFT 4.560 s；FIFO 9.69 GB / 3,036 tokens / 0.094 s；PHCM 9.98 GB / 4,308 tokens / 0.124 s（Table 4）——相对 Full 上下文降 93.1%、显存降 60.4%，相对 FIFO 只多 1,272 tokens、0.29 GB、0.030 s。在线记忆构建（360 s StreamingBench 片段、每秒更新一次、128 帧窗口）：PHCM 平均每步 0.636 s（低于 1 s 更新间隔）、峰值 10.327 GiB / 8,362 tokens，相对 FIFO 强制静默控制（0.472 s / 10.233 GiB / 7,914 tokens）只多约 0.164 s/步；相对 Full（4.013 s / 29.754 GiB / 87,535 tokens）延迟降 84.2%（Table 19）。注意 Table 4 是”预计算记忆”口径，端到端”边构建边应答”的完整延迟没有以单一数字报告（两表分别覆盖构建与回答阶段）。

外部依赖与人工环节。 数据合成依赖闭源模型（Gemini 3.1 Pro、Seed 2.1 Pro、Qwen3.5-397B-A17B、Qwen3.5-9B、WeMM-Embedding-9B）与”随机抽样人工检查”（未报告样本量与错误率，Appendix B.3）；OmniMMI 需要 ASR 转写；ProactiveVideoQA 需要 235B 级裁判模型。

未解决/未报告。 记忆文本历史持续累积，没有报告截断、驱逐或压缩上限（论文未报告），超长流的上下文增长行为未知（表 4/19 的测量仅 360 s 片段）；失败率与失败模式仅一条定性案例，无量化（论文未报告）；只报告了 4B 一个规模，无缩放研究（论文未报告）；模型页标注 “Public access pending”（README），权重尚未确认可完全复现。

适用结论。 在论文报告的 8 个基准、各自的推理配置与所示对比集合内，4B 的 OneStreamer 同时改善了记忆问答、实时感知与主动响应，并以远低于”全历史”的成本保留了远距证据；超出该范围（其他流式任务、更长流、更大模型、无字幕/无 ASR 场景）的结论论文未提供证据。

5. 最容易受到审稿人质疑的地方

质疑：八基准对比混合了三种来源的评测数字与逐模型最优配置选择，”全面最优”的公平性无法从论文内部完全核验

  • 原文依据：Appendix D 明确说明：已有报告结果的基线直接用原文数字；被作者重跑的基线在”其原论文配置”与”OneStreamer 配置”两种设置下评测，并按模型×基准汇报更优一侧；而 OneStreamer 使用逐基准的专用推理配置（OVOBench/StreamingBench 的 128 帧记忆 + 16 帧答题、OmniMMI 部分子任务带 ASR 等，Appendix D）。Fig. 1 图注称 “state-of-the-art results across all eight benchmarks”，摘要措辞则是 “among the compared methods”——两处强度不同。

  • 当前能够得出的判断：大差距结论（PHCM/PSTL 的消融收益、OVOBench/OVBench 等大分差）大概率稳健；小幅领先（部分基准和子项）在统计上无法确认。
  • 如何验证或补强：至少 3 个随机种子的重复训练与评测，报告均值±标准差；对关键对照（PHCM vs FIFO、PSTL vs 随机稀疏）做配对显著性检验；评测侧可用多次采样解码估计方差。
  • 严重程度：主要问题

质疑：训练数据合成依赖多个闭源模型与未经审计的启发式校准，”随机抽样人工检查”的样本量与错误率未公开，可复现性与数据质量难以独立验证

  • 原文依据：caption/QA 标注使用 Gemini 3.1 Pro 与 Seed 2.1 Pro，证据区间验证用 Qwen3.5-397B-A17B，响应时刻打分用 Qwen3.5-9B 与 WeMM-Embedding-9B（Appendix B.2–B.3）；校准规则（”平滑后分数不低于峰值 0.04 的最早候选”、中值平滑窗）中的 0.04 容差未做敏感性分析；B.3 仅称”对随机抽样的提醒与 QA 样本做人工检查”（Manual checks…supported these windows），未报告抽样数量、一致率或错误率；校准结果的验证也依赖同一族 VLM 的可答性判断。
  • 为什么重要：OneStreamer-1M 的标签质量与时间对齐是”何时响应”能力的直接监督来源；若校准系统性地把响应时刻推早到证据不足的位置，会训练出过早回答；而这些环节均不能从论文附录复算。
  • 当前能够得出的判断：CQTC 消融（Table 20）显示该管线整体有效；但校准容差、人工抽检规模与错误率、”提前 13.72 s”中是改善还是部分过激，当前材料无法确认。
  • 如何验证或补强：公开人工抽检的样本量与错误分类统计；对 0.04 容差与平滑窗口做敏感性实验；用独立人工标注比较校准前后响应时刻的正确-及时折中；披露各合成环节的弃置率。
  • 严重程度：主要问题

质疑：个别子项与边角结果未解释，结论的”均质性”被平均分掩盖

  • 原文依据：OVO-Bench 中 OneStreamer 的 HLD 子项 99.5，而基线最高约为 58.6（AURA），偏差约 41 分且正文未讨论（Table 8）；OCR 子项 94.6 低于 Mage-VL 96.0（Table 8）；ViSpeak 整体 2.87 处于 0–5 分制低位，正文未讨论绝对水平（Table 1、15）；Table 20 中最终数据配方在 ProactiveVQA（48.7 低于早期 49.7）、OmniMMI（30.6 vs 30.8）、OVO-Timing（41.6 vs 42.0）上略低于中间阶段，作者仅以”各阶段各有最优”概括。
  • 为什么重要：HLD 这种近满分异常值若源于子任务协议或评测逻辑（而非能力），会抬高 Overall；平均分掩盖子任务与配方组合间的差异，影响读者对”全面提升”的判断。
  • 当前能够得出的判断：论文报告了数字但没有提供解释或诊断；这不推翻总体结论，但”所有基准最好”的叙事在细节层面缺少支撑（审稿人判断）。
  • 如何验证或补强：对 HLD 的评测协议与题目构成给出说明或人工复核样例；报告含/不含 HLD 的 Overall 敏感性；分析 OCR 差距来源；给出配方各阶段在多基准上的权衡说明与推荐依据。
  • 严重程度：次要问题

质疑：成本与长期可扩展性报告不完整——记忆文本无上限策略、无失败率量化、无端到端延迟单一数字

  • 原文依据：Table 4 注明 PHCM 使用 “precomputed caption memory”（答案阶段不含记忆构建）；Table 19 只测 360 s 片段；全文未报告记忆文本历史的截断/驱逐/压缩机制（论文未报告）；失败率未量化，仅有 Appendix F.3 一条定性失败案例（误判打印机关合且不自我纠正）；训练 wall-clock 与数据合成 API 成本未报告。
  • 为什么重要：直播/监控等目标场景往往以小时计，若文本历史线性增长且无淘汰策略，Table 19 的”低于 1 s 更新间隔”能否保持未知；不报告失败率与端到端时延，使”可部署性”判断缺一块拼图。
  • 当前能够得出的判断：在 360 s 量级、单卡 H200 上，在线构建成本可接受（0.636 s/步）；更长时间尺度、多路并发与端到端（构建+应答一体）延迟无法从当前材料确认。
  • 如何验证或补强：给出小时级流的记忆增长与延迟曲线；报告记忆截断/摘要压缩策略及消融；统计失败率与失败类型分布；给出端到端延迟预算分解。

6. 审稿式总评

作者发现流式视频中”证据在相关性已知前就离开视觉窗口”与”密集状态监督让重复等待淹没稀疏响应”两个瓶颈，因此提出 OneStreamer，通过共享同一因果生成过程的控制 token（</Observe>/</Summary> 写记忆、</Silence>/</Standby>/</Response> 控时机）加选择性状态监督（PSTL）与证据对齐的数据合成管线实现”记忆写入 + 及时响应”的统一学习。实验在论文报告的 8 个流式视频理解基准上表明 4B 模型取得对比方法中的最高分（Table 1），其中 PSTL 的监督选择对照（Table 3：同监督比 27.5% 下 48.7/36.6/41.6 对随机稀疏 26.6/27.4/1.4）与 PHCM 的”监督 vs 提示”分离（Table 17：+2.0/+0.6 对 -0.1/+0.3）证据较强，但跨基准评测协议混杂、无方差/显著性报告、合成数据含未审计的闭源启发式，使”全面领先”仍缺少充分支持。本文最有价值的部分是把”何时写记忆/何时回答”变成同一生成接口上的监督设计问题，并给出可复用的数据合成流程与两种口径的效率数据；最大的审稿风险是跨协议对比的公平性与增益的统计稳健性。

  • 问题定义清晰度：强 —— 依据：§1 把挑战收敛为”形成可复用事实记忆而不损害实时感知 + 学会何时响应”，并逐条指出三类现有路线的具体不足；§3 用控制 token 词汇进行了可操作化的任务定义（Table 5）。
  • 创新性证据：中 —— 依据：增量相对 Streamo 式状态控制与记忆压缩类工作明确（§2 对比、Table 2/3 对照），但核心机制是已有组件（控制 token、FIFO 窗口、caption、SFT）的新组合与监督策略改进；”生成即记忆写入”的原创边界无法只凭本文 related work 确认。
  • 方法可信度：中 —— 依据：方法、公式（Eq. 1–3）、状态词汇（Table 5）、训练细节（Table 7）完整且自洽，PSTL 的设计动机有干净对照；但监督配额 qqq 的定义未消融，数据管线依赖闭源模型与启发式校准且审计信息不足。
  • 实验支持力度：中 —— 依据：8 基准覆盖广、消融成矩阵（记忆/监督/数据/效率各一组），失败案例与效率测量有报告；但评测协议跨源拼接、无方差/显著性、HLD 异常子项未解释、失败率未量化。
  • 可复现性：中 —— 依据：训练超参完整（Table 7）、数据集页与代码仓库可达（HTTP 200），但模型页 README 标注 “Public access pending”；合成管线依赖闭源 API 且人工检查细节未报告，完整复现数据需要外部资源。
  • 综合阅读价值：高 —— 依据：对做流式视频/在线助手的读者，提供了一套可迁移的”控制 token 同时管记忆与时机”的系统设计与数据合成思路，效率对照（Table 4、19）与消融矩阵（Table 2、3、16–20）数字密度高、可批判使用；需结合 §5 的协议与统计保留意见阅读结论。
