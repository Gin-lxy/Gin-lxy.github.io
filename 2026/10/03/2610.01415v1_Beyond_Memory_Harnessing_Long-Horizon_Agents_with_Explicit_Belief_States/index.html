0. 一句话结论

论文针对”长程 LLM agent 的记忆只是对历史证据的保留/压缩/重排，并不构成对当前世界的一致且可校验的估计，且显式维护的信念本身也会陷入’持续行动但无实质进展’（Belief Trapping）”这一问题，提出 PoS（Progression of States）：一个无需训练的推理时框架，把决策上下文替换为持续维护的结构化信念 Bt=(Wt,G,ΔtE,ΔtA)B_t=(W_t,G,\Delta_t^{E},\Delta_t^{A})Bt​=(Wt​,G,ΔtE​,ΔtA​)（世界状态 + 两类未解决差距），并用同后端的 Belief Sentinel 逐步校验一致性、用三个窗口信号（gap persistence、progress stagnation、belief recurrence）检测信念陷入，再按动力学模式（Static/Cycle/Drift）× 受阻差距类型（epistemic/achievement）施加因子化恢复约束。在论文报告的四个基准（ALFWorld、LOCA-Bench、RCA-100、ClinDiag）× 三个 LLM 后端（Qwen3.7-Plus、Kimi-K3、GLM-5.3）共 12 个组合上，PoS 全部取得最高总分（Table 1），相对最强基线最高提升 22.68%（ALFWorld，Qwen）与 37.89%（RCA-100 joint，Qwen）。但证据边界明确：总 token 消耗约为 Raw Trajectory 的 5.06 倍且成本只在 RCA-100/Qwen 单点报告（Table 2）；全部数字为单次运行点估计，无方差或显著性检验；trapping 检出率由方法自身的检测器统计；部分细分指标（RCA-100 的 RCL）PoS 并非最优。因此结论应限定为”在上述四个基准与三种 API 后端、论文的预算协议下有效，且对环境描述上下文增长（8K→256K）更稳健”。

1. 论文具体想解决什么问题？

研究背景与具体任务。 LLM agent 在长程任务中反复”行动—观察”：动作改变环境，新观察可能推翻先前推断，累积上下文于是混合了”关于过去状态的证据”与”中间判断”，agent 越来越难分辨哪些事实仍然成立、哪些推断仍有证据支持、哪些需求尚未解决（§1，原文事实）。论文要解决的任务是长程 agent 的决策上下文管理：如何让 agent 在超长交互中始终持有”对当前世界 + 剩余任务需求”的可行动、可修订、可检查的表示。

现有方法如何处理。 论文把已有工作按”暴露给 agent 的决策上下文”分为两类（§2）：memory-as-context——raw trajectory 按时间保留全部证据，压缩类方法（ReadAgent、ACON、SUPO）把历史摘要成紧凑形式，结构化方法（HiAgent、COMPASS、PACE）按子目标或相关性重组保留，工具化方法（MemGPT、CaT、AgentFold、Sculptor）把上下文管理变为 agent 可调用的操作；belief-as-context——把当前世界状态显式化，如 QuBE（问答式信念）、StateAct、ReflAct（回看当前状态）、Tru-POMDP（假设树+贝叶斯滤波）、Graph of States（因果图+状态机）、LongHorizon-Harness（以可审计的 requirements/artifacts/facts 记录任务状态）。

现有方法在哪里表现不好（作者主张）。 两处：(a) 记忆类方法的输出仍是”历史证据的变换记录”，而不是对当前世界的一致估计（§2.1）；(b) 已有信念显式化方法只解决了表示问题：LLM 自行生成的信念更新可能内部矛盾（同一个微波炉同时记为 open 与 closed）或缺乏观察支持；而 LongHorizon-Harness 依赖”可独立验证的中间产物”，当”进展”是不确定的推断（如诊断假设的推进）而非可观察产物时就不适用（§1、§2.2）。此外，T³（Zou et al., 2026）检测 belief deviation 并截断无信息轨迹，但那是 RL 训练信号，不提供 episode 内的恢复策略（§1、§2.2）。

作者的新观察。 全文最重要的新概念是 Belief Trapping：agent 仍在行动，但不再朝目标取得实质进展——重复无效动作、循环访问此前状态、收集无助于完成任务的信息，直至预算耗尽（§1，作者定义，Fig. 1 右给出真实案例）。也就是说”信念一致性”与”任务进展”是两个独立的失效维度，前者靠校验、后者靠进展监测与恢复，缺一不可（§1 结尾：”no existing framework maintains a belief state with both continual consistency validation and online diagnosis and recovery”，作者主张）。

支撑问题判断的证据。 主要来自定性案例与自测统计：Fig. 1 右侧用真实 ALFWorld case #0096（”Put a hot mug in the cabinet”）对比——隐式信念重构版反复 “Examine cabinet x36”、50 步预算耗尽失败；显式信念版记录实体状态、检出 static stagnation（健康度 Ht=0.1\mathcal{H}_t=0.1Ht​=0.1）并恢复，17 步成功；§4.2 用 PoS 自身检测器统计”trapping 在各基准普遍存在”（Fig. 3 左）；Fig. 4 显示基线方法在长环境描述下退化。论文观察到了这些现象，但没有用受控实验单独验证”隐式信念是性能下降的主因”这一因果解释（审稿人判断；相关内容只以案例和消融间接支持）。

作者认为问题产生的原因（作者主张）。 (a) 信念更新由任务 agent 自身产生，会继承其错误假设、推理错误或幻觉，导致内部/外部不一致（§3.2）；(b) 即使信念一致，agent 也可能因缺乏对”是否还在前进”的监控而长期空转（§1、§3.3）。这两个原因被分别映射到两个机制：Belief Sentinel 校验与 Trapping-Aware Recovery。

核心假设。 如果 agent 的决策上下文是”持续维护、逐步校验、带未解决差距”的显式信念，并在检出无进展时做针对性的因子化恢复，那么长程任务的决策质量会提升，且对上下文增长更稳健——这一切在推理时完成、无需训练（§3、摘要）。论文要验证的正是该假设在跨执行/诊断两类任务、多后端下的一般性。

区分层次。 领域早已存在的一般问题：长程 agent 的上下文/记忆管理与状态追踪。本文发现/命名的新观察：Belief Trapping 作为独立于”信念不一致”的失效模式，并主张两者需分开处理。本文实际解决的子问题：在四个既定基准上实现”信念构建+一致性校验+陷入检测与因子化恢复”的推理时闭环。论文未解决也不会解决的：域知识与执行技能的天花板（Appendix E(3)、G.2 自认）、语言化信念的固有开销（G.1）。

2. 创新点是什么？

一段话概括。 真正的技术增量是把 POMDP 中”信念状态是决策充分统计量”的思想落成一个可运行的推理时工程闭环：结构化、任务条件下的自然语言信念 BtB_tBt​（世界状态 WtW_tWt​ 用 Entity–State–Relation 表示并附带 provenance/confidence，加上目标 GGG 与 epistemic/achievement 两类差距）；每步”候选更新→审计→修订后提交”的一致性闸门（Belief Sentinel）；窗口化的三信号信念健康度与阈值化陷入检测；以及”动力学模式 × 受阻差距类型”的二维诊断和对应恢复约束。这些组件（信念形式化、LLM 状态追踪、监控指标、提示式恢复）单独看都不新，增量在于表示设计（世界状态 + 双差距）、”校验闸门”与”因子化恢复”的组合方式，以及 B.3 对健康度聚合形式的设计论证；整体为”已有组件的新组合 + 明确的工程化表述”，不是全新理论。

创新点 1：任务条件下的结构化信念 Bt=(Wt,G,ΔtE,ΔtA)B_t=(W_t,G,\Delta_t^{E},\Delta_t^{A})Bt​=(Wt​,G,ΔtE​,ΔtA​)（§3.1，式 (1)）。

  • 新增机制：WtW_tWt​ 用 Entity–State–Relation 结构，每条 State/Relation 带 provenance、confidence 与支持证据；只保留会影响动作可行性、结果判定或目标满足的记录，不追求穷举环境（§3.1）。ΔtE\Delta_t^{E}ΔtE​（还需弄清什么）与 ΔtA\Delta_t^{A}ΔtA​（还需达成什么）把”未知”与”未完成”分开，Δt\Delta_tΔt​（Active Gap）作为当步焦点但不丢弃整体信念（§3.2）。
  • 与最接近工作的差异：相比 QuBE/StateAct/ReflAct 类”把状态拿来看”的信念，这里显式区分两种差距并用于聚焦动作；相比 LongHorizon-Harness 的审计记录（要求可独立验证的产物），双差距设计允许”进展 = 不确定推断的推进”（如诊断假设消歧），适配诊断类任务（§2.2）。
  • 创新类型：表示设计 + 已有思想的组合。证据：论文没有单独消融”移除双差距只留世界状态”；其价值主要由诊断任务上的结果（RCA-100、ClinDiag 领先）与 E(1) 的 trace 分析间接支持。

创新点 2：Belief Sentinel 的在线一致性校验（§3.2，式 (3)）。

  • 新增机制：任务 agent 先产生候选信念 B~t+1=U(Bt,at,ot+1)\widetilde{B}_{t+1}=\mathcal{U}(B_t,a_t,o_{t+1})Bt+1​=U(Bt​,at​,ot+1​)，Sentinel 审计新增/修改的 Entities、States、Relations、Gaps，检查内部一致性（自相矛盾）与外部一致性（与最新观察/交互证据冲突），返回问题后由任务 agent 对照证据修订，通过才提交 Bt+1B_{t+1}Bt+1​（§3.2；Fig. 2 下部）。
  • 差异：与 T³ 的 belief deviation 检测不同，这里是推理时的”提交闸门”，不截断轨迹、不用于训练；与让模型”自我反思”的常见实践相比，检查维度与触发点被固定在流程中。
  • 证据：消融 -Consistency Validation 在四个基准全面下降，ALFWorld 最多降 14.93 分（Qwen，88.81→73.88）、LOCA-Bench 降 11.81 分（56.38→44.57），ClinDiag 仅降 0.33–0.66 分（§4.1，Table 1；作者解释为诊断任务不一致更新风险较低——作者主张）。

创新点 3：三信号信念健康度 + 因子化 trapping 诊断与恢复（§3.3，式 (4)–(7)）。

  • 新增机制：在 K=8 个已验证转移的窗口上定义 gap persistence PXP_XPX​、progress stagnation StS_tSt​、belief recurrence RtR_tRt​（Jaccard 距离、取最大时间滞后），健康度 Ht=1−max⁡X∈{E,A}[PXmax⁡(St,Rt)]\mathcal{H}_t=1-\max_{X\in\{E,A\}}\left[P_X\max(S_t,R_t)\right]Ht​=1−maxX∈{E,A}​[PX​max(St​,Rt​)]，Ht≤θH\mathcal{H}_t\le\theta_HHt​≤θH​ 判为陷入（式 (5)，Table 8 参数）；随后按有序条件分类动力学 ρt∈{Static,Cycle,Drift}\rho_t\in\{\mathrm{Static},\mathrm{Cycle},\mathrm{Drift}\}ρt​∈{Static,Cycle,Drift}（式 (6)）、按 PEP_EPE​ vs PAP_APA​ 选受阻差距类型；恢复约束 Ct=Cpattern(ρt,Wt)∪Cgap(X,Bt,Δt)\mathcal{C}_t=\mathcal{C}_{\mathrm{pattern}}(\rho_t,\mathcal{W}_t)\cup\mathcal{C}_{\mathrm{gap}}(X,B_t,\Delta_t)Ct​=Cpattern​(ρt​,Wt​)∪Cgap​(X,Bt​,Δt​) 注入动作分布 at∼π(⋅∣Bt,Δt,Ct)a_t\sim\pi(\cdot\mid B_t,\Delta_t,\mathcal{C}_t)at​∼π(⋅∣Bt​,Δt​,Ct​)（式 (7)、式 (2)），恢复期间 Active Gap 不变、逐步复评、Ht>θH\mathcal{H}_t>\theta_HHt​>θH​ 才释放。
  • 设计论证（本文较有分量的部分）：B.3 说明为何不用几何平均（任一信号为零即漏检）或 max 形式（gap persistence 单独高就误报），并用 Table 4 的三个边界配置 (1,1,0)、(1,0,1)、(1,0,0) 说明”停滞/复发/有进展但差距未闭合”三类情形下不同聚合的差异。这是对”什么叫卡住”的显式操作化。
  • 证据：与 generic recovery prompt 的只换恢复策略对照（Fig. 3 右，Qwen）四个基准全面更好；-Trapping Diagnosis 消融降 4.85–6.79 分（RCA-100 joint）与 2.65–3.97 分（ClinDiag）（§4.1、§4.2）。

创新点 4（工程性，支撑而非独立思想）：全过程无训练、纯推理时调度。 信念更新每步 1 次、局部审计每步、全局审计 LOCA 每 32 步、其他基准每 8 步（Table 8）；无任何训练阶段，基线组件也统一用同后端（§4、D.1）。这让方法易于移植，但也意味着所有效果都依赖提示工程与运行时调用。

原始性边界。 论文的定位论证（§2.2、D.2）显示：与 Tru-POMDP（结构化假设+信念空间规划）、Graph of States（因果图+状态机，绑定溯因诊断）、CGDP（耗尽门终止）等最接近的信念/陷入类工作均未做实验对比（D.2 给出理由：其表示与任务族绑定、不适配统一跨域协议）。因此”首个同时做持续一致性校验与在线陷入恢复的信念框架”这一说法（§1 的 to our knowledge 表述）目前只能确认作者的论证范围，是否首次提出需要更完整的文献检索，论文未使用 “first” 类措辞。

3. 作者如何解决？

直觉说明。 与其让 agent 每步从越来越长的历史里”重新理解处境”，不如维护一份随时可读、可查错的”局势简报”：世界状态（实体及其状态/关系、带置信与出处）+ 还没弄清的问题（epistemic gaps）+ 还没达成的目标差距（achievement gaps）。每步行动后由另一个同模型调用充当审计员，对照最新证据检查信念更新是否自相矛盾或与观察冲突，通过才提交；同时用滑动窗口盯住”卡住迹象”，一旦健康度过低就诊断卡住模式，生成约束回注下一步动作选择，直到恢复或重新诊断。

4. 解决得怎么样？

4.1 实验设置

  • 任务与数据（Appendix C，Table 5）。 四个长程基准分两类：执行类——ALFWorld（valid_unseen 划分，134 个未见环境任务：41 Place / 75 Transform / 18 Inspect）与 LOCA-Bench（15 个种子任务 × 7 档环境描述长度 8K/16K/32K/64K/96K/128K/256K × 5 随机环境种子 = 525 例，分 Cross-source Workflows / Structured Analytics / Environment Operations 三类）；诊断类——RCA-100（全部 103 例，指标为故障类型 FT、根因定位 RCL、两者皆对的 Joint）与 ClinDiag（Common 与 Rare 各随机取 302 例，共 604 例；Emergency 子集因数据访问限制被排除，Common 一次性采样后固定）。
  • 接口与预算（C.3、C.4，Table 6）。 所有方法经同一基准 adapter 交互、同一预算：ALFWorld 50 条文本动作；LOCA-Bench 100 次 MCP 工具调用（claim_done 触发官方 evaluator）；RCA-100 50 个决策轮且最多 150 次工具调用；ClinDiag 30 次问诊调用（submit_diagnosis 终止）；无有效提交即计失败。
  • 后端与解码（D.1）。 Qwen3.7-Plus、Kimi-K3、GLM-5.3 经 DashScope API（无固定 API snapshot），全部 LLM 组件使用 temperature 0 的确定性解码；同一后端设置下，PoS 与基线的 LLM 组件用同一后端，不使用更强辅助模型（ClinDiag 的 provider/judge 除外，固定为 Qwen3.7-plus 作为基准环境的一部分）。
  • 基线（§4、Table 7）。 Raw Trajectory（完整历史）、ACON（压缩，去除其失败驱动的 guideline 学习与压缩器蒸馏，保留运行时压缩）、PACE（按预测相关性调节历史粒度，因原仓库不可达由论文按算法 1 重实现，BGE-M3 换成 text-embedding-v4）、HiAgent（子目标分层工作记忆，从 AgentBoard 移植）、LongHorizon-Harness（原生 Manage–Execute–Audit 架构，保留官方实现）。前三者加 Raw 共用 ReAct harness。
  • 消融与分析。 Table 1 内嵌两组消融（- Consistency Validation、- Trapping Diagnosis）；§4.2 用 generic recovery prompt 对照因子化恢复；§4.3 成本对照；§4.4 上下文增长；Appendix E 细粒度分解；Appendix F 单案例深描。

4.2 关键结果

  • 主结果（Table 1，§4.1）。 指标：各基准总体成绩（ALFWorld/LOCA 成功率、RCA-100 joint、ClinDiag 诊断准确率）。条件：四个基准 × 三后端，同预算同接口。PoS 在全部 12 个组合取得最高分；相对最强基线（同后端）最高相对提升：ALFWorld 22.68%（Qwen：88.81% vs LongHorizon-Harness 72.39%）、RCA-100 joint 37.89%（Qwen：38.83% vs PACE/HiAgent 28.16%）、LOCA-Bench 7.53%（GLM-5.3：70.86% vs ACON 65.90%）、ClinDiag 11.31%（GLM-5.3：52.15% vs Raw Trajectory 46.85%）。
  • 细粒度结果给出重要限定（Table 9，Appendix E）。 RCA-100 上 PoS 的收益集中在 FT（故障类型判别）：Qwen FT 39.81% vs 最强基线 33.01%（PACE），但 RCL（根因定位）为 67.96%，低于 Raw/ACON（68.93%）、HiAgent（76.70%）、LongHorizon-Harness（75.73%），在六个方法中仅高于 PACE；Kimi（76.70% vs ACON 79.61%）与 GLM-5.3（75.73% vs PACE 78.64%）上 RCL 同样不是最优。作者的 trace 分析将 FT 收益解释为”多数纠错发生在实体已定位、故障类型判错的案例”（Kimi 14 例、GLM 16 例，E(1)）——即信念机制主要帮助故障消歧，而非根因定位。
  • 消融（Table 1、§4.1）。 -Consistency Validation：ALFWorld 降 14.93 分（Qwen）、LOCA 降 11.81 分（Qwen），ClinDiag 仅降 0.33–0.66 分；-Trapping Diagnosis：RCA-100 joint 降 4.85–6.79 分、ClinDiag 降 2.65–3.97 分。两模块在不同任务族上贡献不同（E(2)：验证影响 FT（Qwen 下 -6.80 分），恢复影响 RCL（-3.88 至 -4.85 分））。
  • 上下文增长（Fig. 4，§4.4）。 在 LOCA-Bench 环境描述从 8K 增至 256K 的曲线中，Raw/PACE 等显著下降，PoS 在 96K–256K 大致走平（Qwen 约 40–45%、Kimi 约 58–60%、GLM 约 59–63%），作者报告 256K 处超最强基线 10.67–16.00 分。注意：这里的”上下文”是环境描述长度，不是交互历史长度。
  • 负向/持平点。 作者明确报告：Place 类任务上 PoS 与最强基线打平（均 97.56%，E(1)）；LOCA 的 Environment Operations 类成功率仅 36.00–41.14%（E(3)）；基线在若干组合不如 Raw Trajectory（如 PACE 在 LOCA/Qwen 仅 17.33%、ClinDiag/GLM 上无基线优于 Raw），作者用它论证”更多上下文管理不必然更好”。

读图：Fig. 3 三块分别回答什么。 左（热力图）：各基准 × 各后端被 PoS 检测器判为 trapping 的 episode 比例——Qwen 明显最高（ALFWorld 38%、LOCA 72%、RCA-100 94%、ClinDiag 80%），Kimi/GLM 较低（如 RCA-100 74% vs 53%），说明弱后端更容易空转，但”检出率低 ≠ 性能高”（RCA-100 上 Kimi 检出多于 GLM-5.3 而 joint 更高，§4.2）。中（堆叠条）：检出事件的模式分布——ALFWorld 以 Cycle 为主（40.29%）、LOCA-Bench 与 RCA-100 以 Drift 为主（48.15%、55.93%）、ClinDiag 以 Static 为主（78.25%），支撑”卡住形态随任务结构而异，因此需要因子化诊断”这一动机。右（对比条）：在 Qwen 上只把恢复策略换成 generic prompt（其余组件不变）后各基准最终成绩——ALFWorld 76.87→88.81、LOCA 49.33→56.38、RCA 31.07→38.83、ClinDiag 42.22→45.03。为什么需要这张图：左/中证明现象普遍且形态多样，右是”因子化恢复设计是否不可替代”的最直接证据（审稿人判断：该对照目前只在 Qwen 上给出，见 §5）。注：trapping 的检出率与模式均由 PoS 自身检测器统计，没有独立标注校验（见 §5 质疑 3）。

4.3 机制证据

  • “有效”的证据较强。 主结果 12/12 组合最优（Table 1），且跨执行与诊断两类任务，不是单一任务结构；相对提升在多个组合上幅度较大（如 ALFWorld Transform 类 Qwen 从最强基线 56.00% 提到 81.33%，E(1)）。
  • “为什么有效”的证据是模块级 + 案例级。 (a) 因子化恢复 vs generic recovery 的只换恢复策略对照（Fig. 3 右）说明恢复的”因子化设计”而非”恢复提示的存在”带来差异，是最接近机制验证的实验；(b) 两组消融分别隔离一致性校验与陷入诊断的贡献（Table 1）；(c) 细粒度分解显示两模块作用在不同指标（验证→FT，恢复→RCL，E(2)），与设计意图自洽；(d) Appendix F 的 RCA-100 t024 案例完整展示一次 “Static Stagnation + epistemic gap → 约束 → CPU 证据 → 信念修订 → 正确提交”的链条。
  • 替代解释不能完全排除（审稿人判断）。 (a) 计算预算：PoS 每步多出信念更新与审计调用，总 token 达 5.06×（Table 2），论文没有做”给基线等量额外 token/反思机会”的匹配对照，因此”更多推理算力本身带来提升”无法被排除；(b) 检测器自证：progress 标签（执行任务）由同后端 LLM 判定、trapping 检出率与模式由自家检测器报告、阈值（θH=0.25\theta_H=0.25θH​=0.25、ϵ=0.30\epsilon=0.30ϵ=0.30、ϵW=0.15\epsilon_W=0.15ϵW​=0.15）的选取协议论文未报告（Table 8 只列值），既无法独立校准检测精度，也无法排除调参泄露的可能；(c) 统计：全部数字为单次运行点估计，无方差/置信区间/显著性（论文未报告），小差距（如 GLM-5.3 LOCA：70.86 vs 65.90）的稳定性未知；(d) 案例证据：Appendix F 作者自己限定”CPU 证据支持记录到的信念修订，但不能唯一确定最终故障类型”，单案例不能支撑普遍机制。
  • 结论。 “PoS 在报告基准上有效”证据较强且覆盖面好；”为什么有效”有设计层面的对照（因子化 vs generic）与模块消融，但缺少独立于自家检测器的验证与预算匹配对照，机制解释仍是”与原文证据一致”而非”被因果隔离”。

4.4 成本与适用范围

  • 论文实际报告的成本（Table 2，仅 RCA-100、仅 Qwen3.7-Plus、103 例平均，token 含输入+输出）。 PoS joint 38.83%（+14.56 分），Task Agent token 从 355.70K 降到 281.20K（-20.9%），但 Belief 696.69K + Sentinel 822.24K 使总消耗升至 1800.13K（5.06×）；-Consistency Validation 省 35.6% 总 token 但降 7.76 分；-Trapping Diagnosis 省 9.2% 但降 4.85 分，且两消融都让 Task Agent 消耗更多（作者解读为”花在信念维护上的计算换到了更好的决策”——作者主张）。
  • 未报告的成本项。 其他三个基准与其余两个后端的 token 成本、wall-clock 时延、每秒调用数、金钱成本均论文未报告；训练成本为零（无训练环节）；人工标注：论文未报告任何人工标注或人工评估（ClinDiag 用 LLM judge）；外部依赖：DashScope API（无固定模型 snapshot，D.1），复现需可访问该服务的环境。
  • 哪些问题得到改善。 诊断类任务的故障类型消歧（FT）与执行类任务的状态追踪（如 ALFWorld Transform、LOCA 整体）明显改善；长环境描述（至 256K）下的稳定性改善；因子化恢复优于笼统的”请恢复”提示。
  • 哪些仍未解决。 LOCA-Bench 的 Environment Operations 类成功率仍只有 36.00–41.14%（E(3)：知道要什么状态变化 ≠ 能做出来）；诊断中”信息正确但知识不足”导致的错误（E(3) trace 分析：agent 拿到正确信息仍答错，缺域知识）；语言化信念的冗余、信息遗漏与语义失真风险，以及成本（G.1 自认，未来方向包括潜空间世界状态表示）；域知识检索缺失（G.2）。此外根因定位（RCL）未见稳定改善（见 §5）。
  • 适用范围。 结论适用于四个基准、三个 API 后端、论文的预算协议；”上下文增长稳健”只由 LOCA-Bench 一个基准支持；未验证开源权重模型、更广模型族与真实生产环境；论文自认为 inference-time 通用框架，但实验未覆盖新域。

5. 最容易受到审稿人质疑的地方

质疑：多个关键基线经过论文自行适配或重实现（PACE 重写、ACON 去掉学习组件、HiAgent 跨代码库移植），且没有报告基线保真度校验，公平性存疑

  • 原文依据：Table 7 与 D.3——PACE “the published repository was inaccessible during implementation”，BGE-M3 换为 text-embedding-v4；ACON 省略 “failure-driven guideline optimization and compressor distillation”；HiAgent 从 AgentBoard 移植。PACE 在 LOCA-Bench/Qwen 上仅 17.33%（Raw 为 43.62%，Table 9），大幅低于原始方法本应表现的水平。
  • 为什么重要：若基线弱化来自适配或重实现缺陷，PoS 的相对优势被系统性夸大；最强的记忆压缩基线 ACON 恰好被去掉了其训练相关核心组件。

6. 审稿式总评

作者发现长程 agent 的失稳不只是”记忆不够”：记忆/压缩只提供历史证据，不构成对当前世界的一致估计，而显式维护的信念又会陷入”继续行动但无实质进展”的 Belief Trapping，因此提出 PoS，通过”结构化任务条件信念（世界状态 + epistemic/achievement 双差距）+ 逐步一致性审计（Belief Sentinel）+ 三信号信念健康度 + 动力学×差距类型的因子化恢复”实现推理时的信念维护与在线自救。实验在四个基准（ALFWorld、LOCA-Bench、RCA-100、ClinDiag）与三个后端上表明：PoS 全部取得最高总分（Table 1），因子化恢复优于泛化恢复提示（Fig. 3 右），且对上下文增长（LOCA 环境描述至 256K）更稳健（Fig. 4）；其中主结果覆盖面与因子化恢复对照证据较强，但基线适配保真度、单次运行统计、检测器自证与单一披露的成本仍缺少充分支持。本文最有价值的部分是把”信念维护”做成一个可校验、可在线诊断与恢复的工程闭环，并把”卡住”操作化为可分类、可定向恢复的状态；最大的审稿风险是基线适配与自证式检测叠加，外加约 5 倍 token 成本只有单点数据，使相对优势的归因存在不确定性。

  • 问题定义清晰度：强 —— §1 清晰区分 memory-as-context 与 belief-as-context 两条路线，Belief Trapping 有明确定义与操作化（Eq. (5)、三信号、Table 4 边界情形），问题边界（推理时、跨执行/诊断）明确。
  • 创新性证据：中 —— 增量是已有组件（POMDP 形式化、LLM 状态追踪、监控指标、提示恢复）的组合与表示/调度设计；B.3 对健康度聚合形式的设计论证与因子化恢复对照（Fig. 3 右）是较有分量的证据，但”首个同时校验+在线恢复”未经系统文献验证，且未与最接近信念类方法对比。
  • 方法可信度：中 —— 流程、公式（Eq. (1)–(7)）、算法（Algorithm 1）与超参（Table 8）完整且自洽；训练-free 降低复现门槛；但进度标签与陷入判定依赖自家 LLM 组件、阈值选择协议未报告，存在自证风险。
  • 实验支持力度：中 —— 4 基准 × 3 后端 × 6+ 类基线，细粒度结果（Table 9）与案例（Appendix F）公开，负向结果有述及；但单次运行无统计、基线多次适配、成本单点披露、上下文增长结论仅在 LOCA-Bench。
  • 可复现性：中 —— 代码开源可达（GitHub luoyu100/PoS，MIT，最后推送 2026-10-02，仅核验元数据），基准公开、协议与超参详细；但 API 无固定 snapshot、基线部分为论文自行重实现、评测依赖外部服务与 2026 年新基准，严格复现成本高。
  • 综合阅读价值：高 —— 对”长程 agent 上下文管理”给出了完整可迁移的范式（信念=世界状态+双差距；审计闸门；因子化恢复），消融、边界论证（Table 4）与诊断/执行分化的分析对后续研究有直接参考价值，代价是较高的推理成本与待补的统计强度。
