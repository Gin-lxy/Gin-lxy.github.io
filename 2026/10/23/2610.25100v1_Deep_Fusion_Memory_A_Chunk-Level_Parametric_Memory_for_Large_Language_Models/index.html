0. 一句话结论

论文问的是能否把「检索到的知识」在训练时压缩进一个块级参数化记忆（parametric memory），推理时不再查库、也不改主干权重，而是用门控交叉注意力把预测出的记忆注入解码器中间层；DFM 在六个英文问答任务上把 Mistral-7B 的六任务平均从最强基线的 24.14 提到 27.21、把 Qwen3-8B 从 23.80 提到 26.46，并把目标构造的检索查询量和返回项分别降到 1/32 与 1/2048，但「记忆内容本身是否在提供知识」没有被隔离，训练/推理的记忆对齐、基线强度与统计稳定性也仍有明显缺口。

1. 论文具体想解决什么问题？

大语言模型（LLMs）在知识密集型问答中需要预训练参数之外的事实；知识注入（knowledge injection）要在不破坏原有能力和控制成本之间取舍。持续预训练（continued pretraining, CPT）和 LoRA 让推理保持自包含，但可能带来灾难性遗忘（catastrophic forgetting）；检索增强生成（retrieval-augmented generation, RAG）与 RETRO 在推理时取回段落或块，能直接接触语料，却要付出在线检索与证据处理的时延（latency）（§1、§2）。

参数化记忆（parametric memory）走第三条路：离线从检索结果学习，推理时不再显式检索。MLP Memory 和 Memory Decoder 学习的是 token 级的「检索派生下一 token 分布」，再用输出概率插值融合。作者认为这条路线有两个被低估的成本：第一，构造 token 级目标要在语料库的每个 token 位置做检索；对一个 4B token 的语料，就是约 4B 次检索查询（retrieval query）、每次 Top-1024 个近邻（Top-K neighbors），共约 4.096T 个返回项；第二，输出级插值只是「浅融合」（shallow fusion），记忆没有进入解码器的隐藏状态（hidden states），后续层无法继续加工它（§1、§2）。

这里的「成本问题」主要是作者用配置计数做的论证（原文事实：§4.4、Appendix D），不是实测的墙钟时间（wall-clock time）或存储字节（storage bytes）。论文没有证明 token 级监督在质量上不必要，只证明了它在数量上很贵；也没有用受控实验证明「浅融合」一定弱于「深融合」，而是把它作为设计动机。更准确地说，本文发现的是一个可优化的瓶颈——块级（chunk-level）监督让同一块内 32 个 token 共享一份记忆目标——而不是一个全新的经验现象。

作者给出的原因是：token 级目标把「每个 token 都要一条检索监督」当成默认，忽略了同一块内 token 的上下文高度重叠；输出插值则把记忆限制在最终分布上。核心假设是：如果把监督粒度改成块级、用一个因果记忆预测器（memory predictor）从上下文预测连续记忆向量，再通过门控交叉注意力（gated cross-attention）注入中间层，同时冻结主干（frozen backbone），就能在更低的构造/训练成本下提升问答与域适配（domain adaptation），且推理不需要检索（§1、§3）。

需要区分三层：领域一般问题是「如何低成本地把外部知识注入 LLM」；本文的新观察是「块级共享监督 + 中间层融合」可以同时降低构造成本和改善融合方式；实际解决的具体子问题是「在英文 Wikipedia 2018 语料、7–8B 主干、六个 QA 基准和代码/数学/法律三个域上，DFM 是否比现有基线更好」。论文没有证明它能在全新知识、全新任务、更大模型或在线知识更新上成立。

2. 创新点是什么？

本文的技术增量不是新的优化器或新的注意力算子，而是把「检索监督」从 token 级改成块级，并把它从输出概率插值搬到解码器隐藏状态；三点分别对应构造成本、融合深度和主干保护。

第一，块级目标与因果记忆预测器。每个 32-token 块只构造一份目标记忆（target memory）：用前一个块去检索 Top-16 邻居，把 16 个嵌入按检索排名堆成 K×dmK\times d_mK×dm​ 的目标；一个因果 Transformer（causal Transformer）只看块级嵌入，就为每个块输出 16 个连续记忆向量。与 MLP Memory/Memory Decoder 的 token 级分布目标相比，这是监督粒度的改变，不是单纯工程优化；它把查询数降到 1/32、返回项降到 1/2048，但论文没有用 token 级 DFM 对照来证明质量不受损（§3.1–3.2、§4.4、Fig. 2）。

第二，门控交叉注意力的深融合。预测记忆（predicted memory）先经共享投影器（projector）映射到解码器隐藏维度，再在若干中间层与自注意力并行地做交叉注意力；每个头有一个由当前 token 状态算出的 sigmoid 门，控制记忆分支的贡献，融合结果回到残差流，后续层继续处理。与 MLP Memory 的输出插值不同，记忆进入隐藏状态；与 RETRO 的「推理时检索文本再交叉注意力」不同，这里的键/值是预测出的连续向量，推理不查库。它是已知组件的新组合，证据见 §3.2、§4.3 的融合位置消融（Fig. 3、Fig. 4）与门控消融（Table 3）。

第三，冻结主干的端到端训练配方。记忆预测器、投影器、查询投影、交叉注意力和门控一起用「语言建模损失 + 记忆预测均方误差（mean squared error, MSE）」训练，主干、检索编码器和目标记忆全部冻结；推理只保留预测器与融合层。与 CPT/LoRA 更新主干不同，这在结构上避免主干遗忘；与 MLP Memory 只学输出分布不同，这里同时学「怎么预测记忆」和「怎么用记忆」。证据见 §3.2、§4.4；但论文没有测域适配后的通用能力（general capabilities）保持，也没有去掉 MSE 的对照（§4.3）。

3. 作者如何解决？

直觉上，DFM 把「检索」当成一个可以学习的函数：给定当前上下文，先猜「如果去查库，会拿到哪些块的嵌入」，再把猜出来的向量注入解码器，让后续层把它们和上下文一起加工。训练时用真实检索结果监督这个猜测；推理时只运行猜测器和融合层，不再访问语料库。下面按数据流走一遍。

输入是 token 序列（QA 时是问题与模板），训练序列按 2,048 token 打包，再切成互不重叠的 32-token 块 X0,…,XJ−1X_0,\ldots,X_{J-1}X0​,…,XJ−1​。离线阶段，冻结的 Qwen3-Embedding-0.6B 对每个训练块做末 token 池化（last-token pooling）和 L2 归一化，得到 1,024 维嵌入，存入 FAISS IVF-PQ 索引；对每个块 XjX_jXj​（j≥1j\ge1j≥1），用前一个块 Xj−1X_{j-1}Xj−1​ 作查询，取 Top-16 邻居的完整块嵌入，按检索排名堆成目标记忆 Vj∈RK×dmV_j\in\mathbb{R}^{K\times d_m}Vj​∈RK×dm​，K=16K=16K=16。数据存储只含训练块；第一个块没有前驱，因而不参与记忆监督（§3.1、Appendix A.1）。图 1 把这条「离线检索—预测—融合」的链路画在一起。

图 1（论文 Fig. 1）：这张图的主线是「检索结果只做监督，预测出的连续记忆才进入推理」。离线检索器从固定语料中按前一个块取回 Top-16 嵌入，形成目标记忆；同一批块嵌入进入因果预测器，预测器用多个输出头给出 16 个记忆槽（memory slot）的预测记忆，共享投影器再把它们映射到解码器隐藏空间；MSE 只连到预测器，不进入主干。右侧的解码器在若干层插入记忆融合块：每个 token 的自注意力与对 16 个记忆槽的交叉注意力并行，交叉注意力的每个头先经 sigmoid 门缩放，再拼回残差流，后续层继续处理融合后的状态。推理时没有检索器和目标记忆，只有预测器与融合层工作；记忆在生成开始前算好并保持固定，因而这条链路的成本主要落在一次块级预测和少量交叉注意力上。

预测器是另一个小型因果 Transformer：对前一个块 Xj−1X_{j-1}Xj−1​ 的 token 嵌入做均值池化得到块嵌入 CjC_jCj​，第一个输入 C0C_0C0​ 用掩码占位；28 层、隐藏宽度 1,024、FFN 3,072、16 个查询头/8 个 KV 头，最后用 16 个线性输出头给出 16 个记忆槽。预测器用因果注意力看 C1,…,CjC_1,\ldots,C_jC1​,…,Cj​，因此预测 XjX_jXj​ 的记忆时只用到 X0,…,Xj−1X_0,\ldots,X_{j-1}X0​,…,Xj−1​ 的信息，和下一个 token 预测的可见性对齐。输出坐标被裁剪到 [−1,1][-1,1][−1,1]，与 L2 归一化目标的坐标范围一致（§3.2、Appendix A.1）：

V^j=Predictor⁡ϕ(C≤j),Mj=Pψ(V^j) \hat{V}_j=\operatorname{Predictor}_{\phi}(C_{\le j}),\qquad M_j=P_{\psi}(\hat{V}_j) V^j​=Predictorϕ​(C≤j​),Mj​=Pψ​(V^j​)

其中 PψP_{\psi}Pψ​ 是共享记忆投影器：对每个槽位独立做 LayerNorm、两层线性变换和 GELU，把 dmd_mdm​ 维记忆映射到解码器隐藏宽度 ddd；同一个 MjM_jMj​ 被所有融合层复用（§3.2）。

融合发生在选定的解码器层（Mistral/Qwen3 用零基编号 [9,16,24,31][9,16,24,31][9,16,24,31]）。对一个准备预测下一个 token 的位置 ttt，取归一化后的 token 状态 ztz_tzt​ 作查询，键和值来自 MjM_jMj​；每个头在 16 个记忆槽上做 softmax，得到 ot,ao_{t,a}ot,a​。然后每个头用一个由 ztz_tzt​ 算出的 sigmoid 门 gt,ag_{t,a}gt,a​ 缩放该头输出，拼接后经输出投影得到 utu_tut​，与自注意力输出一起加回残差：h~t=ht+SelfAttn⁡(z≤t)+ut\tilde{h}_t=h_t+\operatorname{SelfAttn}(z_{\le t})+u_th~t​=ht​+SelfAttn(z≤t​)+ut​，再进入原来的 FFN。门在初始化时偏置为 −2-2−2、权重为零，初始 σ(−2)≈0.119\sigma(-2)\approx0.119σ(−2)≈0.119，先把记忆分支压小，避免扰动预训练主干；第一个块的记忆更新为零（§3.2、Appendix A.1）。这里模型决定的是记忆向量的内容和每个头开多大；固定流程决定的是分块、检索目标、融合层位置和残差结构。

训练只更新新增模块：预测器、查询投影、共享投影器、交叉注意力和门控；主干、检索编码器、目标记忆都冻结。损失是下一 token 交叉熵加记忆预测 MSE，β=1\beta=1β=1，MSE 在去掉第一个块后的所有块、16 个槽位和 dmd_mdm​ 维上取平均；目标嵌入已 L2 归一化，预测不再归一化。语言建模损失的梯度会穿过融合层回到预测器，MSE 则直接监督预测记忆（§3.2）：

L=LLM+β LMSE,LMSE=1(J−1)Kdm∑j=1J−1∥V^j−Vj∥F2 \mathcal{L}=\mathcal{L}_{\mathrm{LM}}+\beta\,\mathcal{L}_{\mathrm{MSE}},\qquad \mathcal{L}_{\mathrm{MSE}}=\frac{1}{(J-1)Kd_m}\sum_{j=1}^{J-1}\|\hat{V}_j-V_j\|_F^2 L=LLM​+βLMSE​,LMSE​=(J−1)Kdm​1​j=1∑J−1​∥V^j​−Vj​∥F2​

QA 训练用 Wikipedia 2018（Mistral 4.70B、Qwen3 4.29B、OLMo3 4.08B token），AdamW、学习率 1×10−51\times10^{-5}1×10−5、全局批大小 128、单 epoch、16 张 A800 80GB、BF16、seed 42，取最终检查点（checkpoint）；新增模块在 7–8B 主干上约 0.75B 参数，在 Qwen3-4B 上约 0.6B（§4.1、Appendix A.1）。域适配对每个域单独训练一个模型，每次更新 262,144 token，数据量为 Code/Math 各 100M、Law 123.5M token（Appendix A.2）。

推理阶段没有目标记忆，也没有检索器或外部编码器：块查询由主干输入嵌入构成，预测器给出记忆，融合层在「与 prompt 块关联的位置」使用它。QA 时记忆从可见 prompt 计算一次，生成期间保持不变；新生成的答案块查询被补零，因而没有直接的记忆更新，答案也不刷新查询；论文的实现没有做增量预测器缓存（§3.3、Appendix A.1）。这意味着记忆主要是在编码 prompt 时通过隐藏状态间接影响答案，而不是在解码每一步持续提供新证据；这也是后面质疑训练/推理对齐的起点。

为什么这样设计？块级监督把「每个 token 一条检索」降为「每个块一条」，直接对应构造成本；把记忆放进中间层，是希望后续层能把记忆和不断演化的上下文一起加工，而不是只在输出端做一次插值；冻结主干则是为了在不重训、不破坏原能力的前提下叠加记忆。代价是执行层的知识被压缩进 0.75B 的预测器和少量融合参数，记忆是连续的、不可直接引用，也不能在推理时更新。

4. 解决得怎么样？

4.1 实验设置

QA 主实验在英文 Wikipedia 2018 上训练，评测六个知识密集型问答：单跳（single-hop）的 NQ（3,610 个测试样本，F1，最多生成 15 token）和 WebQA（2,032，子串匹配（substring match），100 token），多跳（multi-hop）的 HotpotQA（7,405 验证，F1，15 token）、2WikiMultiHopQA（12,576 验证，F1，32 token）、MuSiQue（2,417 验证，F1，32 token）和 Bamboogle（125 测试，F1，32 token）；平均是六任务等权平均（unweighted average）（Table 1、Table 4）。主干为 Mistral-7B-v0.3 和 Qwen3-8B-Base，附录 B.1 增加 OLMo-3-1025-7B。评测是零样本（zero-shot）贪心解码（greedy decoding），不提供检索文档、gold 文档或思维链（Appendix A.1）。

基线分三类：非参数方法 RAG（用 Qwen3-Embedding-0.6B 取 Top-1 文档）、xRAG（把检索文档嵌入投影成一个前缀 token）、RETRO（块级检索 + 交叉注意力）；参数方法 CPT（全参数继续预训练一个 epoch）、LoRA（参数预算与 DFM 匹配）、MLP Memory（token 级 kNN 分布 + 输出插值，1.5B 配置）。需要特别记录：MLP Memory 的插值权重 λ\lambdaλ 是在每个「报告的评测 split」上从 {0,0.05,…,1}\{0,0.05,\ldots,1\}{0,0.05,…,1} 里选的（Appendix A.1）——这让基线占了一点测试集调参的便宜，DFM 的对比因此不算被基线欠调；但换个角度看，这也说明比较条件并非完全一致。

域适配在 Qwen3-4B-Base 和 Qwen3-8B-Base 上做，Code 用 HumanEval/HumanEval+，Math 用 GSM8K，Law 用 LawBench 的 20 个子任务宏平均（macro average）；DFM 与 CPT/LoRA 使用相同数据和序列长度，RAG 用冻结的 Base 主干、取对应域训练语料的 Top-1 文档（§4.1、Appendix A.2）。HumanEval 用 3 个示例、每题 4 个样本，HumanEval+ 零样本 1 个样本，GSM8K 8 个示例，LawBench 零样本 500 例/任务（Appendix A.2）。主表回答「是否更好」，附录 B.1/B.2 回答「第三个主干和 LawBench 子任务是否一致」，§5 的消融回答「哪些结构选择重要」，Appendix D 回答「资源账怎么算」。

预算方面：DFM 在 16 张 A800 上训练 24 小时；CPT/LoRA 只报告了一个 epoch、学习率 2×10−52\times10^{-5}2×10−5 等设置，没有报告训练时长；RAG/xRAG/RETRO 的推理检索次数或时延也没有报告。因此除 MLP Memory 外，方法之间的比较不是严格算力匹配的。附录 C 明确消融全部为单次运行（single run）；主结果也没有报告重复次数、标准差（standard deviation）、置信区间（confidence interval）或统计显著性（statistical significance）。

4.2 关键结果

先看 Mistral。Table 1 中 Base 的六任务平均是 13.63，最强基线 xRAG 是 24.14，DFM 是 27.21：绝对提升 3.07 分，相对提升 12.71%。DFM 在六个任务上都高于 Base：NQ 33.57（+13.27）、WebQA 42.47（+13.19）、HotpotQA 29.53（+8.57）、2Wiki 25.00（+19.13）、MuSiQue 10.05（+8.62）、Bamboogle 22.65（+18.74）。但这些数字要分任务看：2Wiki 上 RAG 仍有 31.02，DFM 的 25.00 低于 RAG；Bamboogle 只有 125 个样本，DFM 相对 Base 的 +18.74 按六任务等权平均折算约贡献 +3.12 分，占 DFM 相对 Base 的 +13.58 分的约 23%（这是按 Table 1 的算术，不是论文报告）。绝对分数仍不高，六任务平均 27.21 说明这是很难的零样本闭卷设置。

Qwen3-8B 上，Base 22.71，最强基线 MLP Memory 23.80，DFM 26.46：绝对 +2.66，相对 11.19%。NQ 从 17.60 升到 27.46（+9.86），2Wiki 从 24.83 升到 32.38（+7.55），但 WebQA 从 41.78 降到 39.47，且低于 MLP Memory 的 43.26；HotpotQA 26.46 也低于 xRAG 的 27.74。论文自己写了「memory adaptation is not uniformly beneficial across backbones」（§4.2）——这比摘要的「五个任务提升」更值得记住：DFM 的平均优势不是每个任务都更好。

附录 B.1 的 OLMo-3-1025-7B 给出第三个数据点：Base 17.99，DFM 25.49，最强基线 RETRO 23.63，DFM 只领先 1.86 分（约 7.9% 相对）；WebQA（39.03 vs 40.31）和 HotpotQA（27.36 vs 27.99）低于 Base。也就是说，12.71%/11.19% 不是跨主干的常数，OLMo 上的增益明显更小，且仍然依赖任务。

域适配见表 2。Qwen3-4B 上 DFM 平均 64.69，Base 58.18，提升 6.51 分；Qwen3-8B 上 67.52 对 63.14，提升 4.38 分。但「相对 Base」容易掩盖「相对最强非 DFM 基线」的差距：4B 上 CPT 是 62.92，DFM 只高 1.77 分；8B 上 LoRA 是 66.96，DFM 只高 0.56 分（Table 2，按表中数字计算）。分任务看，4B 的 LawBench 40.41 低于 CPT 41.66；8B 的 HumanEval+ 64.02 低于 LoRA 65.85，GSM8K 86.43 低于 LoRA 87.19。LawBench 子任务（Table 7）还显示平均会掩盖大幅回退：4B 的 3-1「根据案情预测法条」DFM 37.32，CPT 72.03；8B 的 1-1「法条背诵」DFM 29.71，CPT 54.57。DFM 的域适配平均优势主要来自 HumanEval、LawBench 的若干理解和应用子任务，而不是所有子任务。

4.3 机制证据

消融在 Mistral-7B 上做，全部是单次运行，结论要按「趋势」而非「精确点」读（Appendix C）。图 2 把块大小、融合层配置和记忆槽数放在一起。

图 2（论文 Fig. 3）：三条曲线的纵轴都是 Mistral 上六任务 QA 平均分，横轴分别扫块大小、融合层配置和 Top-K 记忆槽；实心圆和虚线是主配置。最醒目的不是「哪个点最高」，而是融合位置的跳变：只在最后一层融合（21.11）远低于把融合分散到中间到后段（27.09–27.54），而 2/4/6/8 层之间只差约 0.45；块大小 16/32/64 只差 0.70/0.14，Top-2 到 Top-16 只差 0.33。读图应理解：论文的「deep fusion」主要赢在「不要在输出端才融合」，而不是「层数越多越好」；同时这些差异都在单次运行的噪声量级附近，不能当成精确排序。

块大小上，16/32/64 token 的平均分别是 26.51/27.21/27.07（Fig. 3(a)、§5.1）。融合层上，单层最后一层 21.11，两层 [9,31][9,31][9,31] 27.54，四层主配置 27.21，六层 27.22，八层 27.09；最后四层 [28,29,30,31][28,29,30,31][28,29,30,31] 只有 22.07，起点改为第 2 层 [2,10,21,31][2,10,21,31][2,10,21,31] 是 26.32（Fig. 3(b)、Appendix C.1）。这说明「中间到后段分布」比「堆在最后几层」重要，但两层配置其实最高，四层默认不是最优；而且这个 sweep 同时改变了层数和位置，不能把差异完全归因于深度。记忆槽数 2/4/8/16 为 26.88/27.04/27.09/27.21，Top-8 在五个任务上更高，但在 125 例的 Bamboogle 上低 3.07 分，等权平均才略低（Fig. 3(c)、§5.1）。

门控消融（Table 3）显示：无门控 26.83，默认 bg=−2b_g=-2bg​=−2 27.21，bg=0b_g=0bg​=0 27.90，bg=−4b_g=-4bg​=−4 26.73，bg=−6b_g=-6bg​=−6 25.10。门控确实比无门控略好，但默认初始化比 bg=0b_g=0bg​=0 低 0.69 分；作者选择 −2-2−2 是为了「保守地少扰动主干」，不是因为它最优。这个 0.69 分与很多结构差异同量级，说明门控的收益不算强，且对初始偏置敏感。其他消融：学习率 2×10−52\times10^{-5}2×10−5 27.10 对 1×10−51\times10^{-5}1×10−5 27.21；共享投影器 27.21 对逐层投影器 26.88；预测器 14/28/56 层为 27.31/27.21/26.47；余弦损失 26.87 对原始 MSE 27.21（Appendix C.2–C.5）。14 层预测器略好且更省，2 层融合也略好，说明默认配置不是成本/效果的最优点。

图 3 把任务级变化拆开，解释为什么只看平均会误判。

图 3（论文 Fig. 4）：这张热力图把每个消融配置相对主配置的六任务分数变化拆开，蓝色为升、棕色为降，最后一列是等权平均变化。它说明平均分接近的配置可能在任务间互相抵消：例如 Fusion 2 的平均只 +0.33，但 NQ −12.42、Bamboogle −10.75，同时 2Wiki +3.69；Start layer 2 的平均 −0.89，也由 Bamboogle 的 −4.57 主导。读图时应把「平均变化」和「任务级方差」分开看：DFM 的结构选择对某些任务是明显有利的，对另一些任务则可能大幅回退；单次运行下，这些任务级变化很难区分真实效应与噪声。

机制证据到这里只能支持一个有限的结论：在中间层插入门控交叉注意力、并让记忆分支与自注意力并行，比只在最后一层融合更好；块大小、槽数、学习率、投影器共享、预测器深度在测试范围内都不敏感。它不能支持更强的结论，因为缺少四个关键对照：

  1. 没有「零记忆/随机记忆/打乱目标」的对照。把预测记忆换成常数或随机向量，若平均分仍接近，就说明增益来自新增容量或适配器（adapter），而不是记忆内容；论文没有做。
  2. 没有 token 级 DFM。块级监督是核心创新，但没有在 DFM 内部把目标改成 token 级再比较质量；只有 16/32/64 的块大小 sweep，不能隔离「共享监督」本身。
  3. 没有输出级 DFM。要证明「深融合优于浅融合」，需要在同一预测器上把融合换成输出概率插值；论文与 MLP Memory 的比较同时改变了监督粒度、融合位置、参数和训练，不能单独归因于融合深度。
  4. 没有去掉 LMSE\mathcal{L}_{\mathrm{MSE}}LMSE​ 的对照。MSE 与余弦损失的对比只换了距离，没有证明检索监督本身必要；预测记忆的保真度（held-out MSE、检索召回、近邻一致性）也没有报告。Fig. 6 的离线检索样例只说明目标与续写相关，作者自己承认「不能直接衡量预测记忆的保真度」（Appendix E.2）。

另外，Fig. 5 的六个 HotpotQA 案例是「DFM 对、Base/MLP Memory 错」的挑选样例，作者明确说「without establishing their frequency」（Appendix E.1）；它们能帮助理解差异，不能作为机制证据。整体上，效果证据（QA/域适配平均分）是中等偏正面，机制证据（为什么是记忆在起作用）目前是弱的。

4.4 成本与适用范围

论文报告的资源账集中在图 4 与 Appendix D/Table 13。

图 4（论文 Fig. 2）：三组柱状图把 DFM 与 token 级 MLP Memory 的资源账放在同一尺度：新增参数 0.75B 对 1.5B；16 张 A800 上的训练时间 24 小时对 64 小时（384 对 1,024 GPU 小时）；4B token 语料的检索查询 125M 对 4B、返回项 2B 对 4.096T。箭头上的百分比是相对 MLP Memory 的下降幅度，不是绝对成本；训练时间只覆盖训练，不含目标构造和评测（Appendix D）。读图时要把「构造工作量」和「训练成本」分开：前者是计数，后者是实测小时数，两者都不是端到端墙钟时间，也不含存储和推理。

训练成本：DFM 新增 0.75B 参数，是 Mistral MLP Memory 1.5B 配置的约一半；在 16 张 A800 上训练约 24 小时，MLP Memory 约 64 小时，训练时间降低 62.5%（Fig. 2、Appendix D）。目标构造：4B token 语料上，token 级要 4B 次查询、Top-1024，DFM 用 32-token 块只要 125M 次查询、Top-16，查询少 32 倍（96.88%），返回项从 4.096T 降到 2B，少 2048 倍（99.95%）（§4.4、Appendix D）。这些数字是配置计数；论文明确说它们「不计算不同 token、搜索候选、存储字节或 FLOPs」（Appendix D），也「没有测量构造的实际耗时」（Appendix C.1）。

存储成本是本文没有回答的部分。目标记忆是按块保存的 16 个 1,024 维嵌入；按 2B 个返回槽位粗算，如果逐槽以 fp16 保存约 4 TB，如果只存块 id 再回查 125M×1,024 的嵌入表则约 256 GB——这是分析者按论文公开数字做的量级估算，不是论文报告；论文没有给出索引大小、目标记忆字节数或每域模型的存储。推理侧，DFM 不需要在线检索，但多了 0.75B 的预测器和四层交叉注意力；论文没有报告时延、吞吐（throughput）、显存或与 RAG 的端到端对比，因此「无检索」是否在延迟上更省，当前材料无法确认。

域适配的成本也不完整：每个域单独训练一个模型（Code/Math 各 100M token、Law 123.5M token，每次更新 262,144 token），Qwen3-4B 上新增 0.6B 参数；三个域同时部署就是三套记忆模块，存储随域数线性增长，论文没有讨论合并或共享。训练成本只给了 QA 主实验的 24 小时；域适配的 GPU 小时、构造时间、存储都没有报告。

适用范围：全部实验是英文 Wikipedia 2018 的闭卷问答和代码/数学/法律三个域，主干是 7–8B；没有多语言（multilingual）、长文生成（long-form generation）、更大模型、在线知识更新（knowledge update）、事实溯源（factual attribution）或通用能力保持的评测。记忆在训练后是静态的，换语料要重训；推理时记忆只作用于 prompt 块，答案块没有直接记忆更新。因此论文能支持的是「在英文 Wikipedia 同分布 QA 和这三个域上，块级预测记忆 + 中间层融合能以更低的构造/训练成本取得更好的平均分」；不能支持「普遍的新知识注入」「任意新任务泛化」「比 RAG 更可信/更可溯源」或「在真实在线知识场景中更省」。

5. 最容易受到审稿人质疑的地方

质疑：预测记忆本身是否提供知识没有被隔离，增益可能来自新增容量或域适配

  • 原文依据：DFM 新增约 0.75B 参数（§4.1），消融只改块大小、融合层、槽数、门控、学习率、投影器、预测器深度和 MSE/余弦（§5.1–5.2、Appendix C），没有零记忆、随机记忆、打乱目标或「只训融合、不训预测器」的对照；没有 token 级 DFM，也没有输出级 DFM；预测记忆的保真度没有报告（Appendix E.2 明确 Fig. 6 不衡量保真度）；Fig. 5 是挑选的成功案例（Appendix E.1）。
  • 为什么重要：论文的核心主张是「记忆被注入并起作用」。如果 0.75B 的新增模块只是适配器，或预测记忆换成随机向量也差不多，那么「parametric memory」的解释就不成立，创新性会退化为「加了一个大 adapter + 交叉注意力」。
  • 当前能够得出的判断：现有证据只能说明「加了块级预测器 + 中间层融合的系统更好」，不能说明「预测出的检索记忆本身在提供知识」。这是审稿人判断，不是论文已证实的结论；论文没有报告这些对照。
  • 如何验证或补强：加入零记忆/随机记忆/打乱目标、冻结预测器只训融合、去掉 MSE、token 级 DFM、输出级 DFM 五组对照；报告 held-out 块上的记忆预测 MSE、Top-16 近邻一致性、预测记忆与真实检索的召回；对记忆槽做探针或消融，确认哪些槽位承载信息。
  • 严重程度：主要问题。

质疑：基线强度与比较口径不一致，12.71%/11.19% 的「最强基线」在不同主干上不是同一个方法

  • 原文依据：Table 1 中 RETRO 在 Mistral 是 13.73（Base 13.63）、在 Qwen3 是 22.69（Base 22.71），几乎不带来增益；Appendix A.1 没有给 RETRO/xRAG 的训练细节；RAG 只取 Top-1 文档；CPT/LoRA 统一用一个 epoch、学习率 2×10−52\times10^{-5}2×10−5，CPT 在 NQ 上跌到 11.44/11.83，LoRA 在 Qwen3 上跌到 11.72，论文未报告是否调参；§2 引用了 Memory Decoder、MemSFT 等参数化记忆方法，但 §4.1 的基线只有 MLP Memory；摘要的 12.71% 对 Mistral 的 xRAG，11.19% 对 Qwen3 的 MLP Memory，是两个不同的「最强基线」；域适配的 6.51/4.38 是相对 Base，而相对最强非 DFM 基线只有 +1.77/+0.56（Table 2）。
  • 为什么重要：如果 RETRO/xRAG/RAG 没有被公平训练或调参，DFM 的平均优势可能被高估；如果最接近的 Memory Decoder/MemSFT 没有比较，创新性证据不完整；如果「最强基线」随主干漂移，摘要的相对提升就不能当作单一方法的稳定优势。
  • 当前能够得出的判断：MLP Memory 的 λ\lambdaλ 在每个评测 split 上调过，DFM 对它的优势反而更可信；但 RETRO 的异常低分、CPT/LoRA 的坍缩和缺失的 Memory Decoder 对照，使「比现有参数化记忆更好」只能算部分支持。基线细节不足，当前材料无法确认它们是否被公平训练。
  • 如何验证或补强：报告 RETRO/xRAG 的训练数据、目标、超参和算力；用多段落、重排的强 RAG；在同一设置下加入 Memory Decoder/MemSFT；对 CPT/LoRA 做学习率和 epoch 搜索；在摘要/表中明确「最强基线」的具体方法，并给出所有主干上的同一基线对比。
  • 严重程度：主要问题。

质疑：训练与推理的记忆对齐不一致，记忆只作用于 prompt，长生成没有验证

  • 原文依据：§3.1 的目标记忆 VjV_jVj​ 是用前一个块 Xj−1X_{j-1}Xj−1​ 检索出来的，用于预测 XjX_jXj​ 的 token；Appendix A.1 却说 QA 推理时「每个记忆查询由当前可见的 prompt chunk 构造，而不是训练时的前一个 chunk」，生成期间查询和记忆固定；新生成的答案块查询补零，「没有直接的记忆更新」，答案块不刷新查询，也没有增量预测器缓存；训练时第一个块不参与记忆监督，推理时第一个 prompt chunk 是否获得记忆、如何与 C0C_0C0​ 对应，论文没有展开（当前材料无法确认）。
  • 为什么重要：融合层是在「用前一块的记忆预测下一块」的条件下训练的，推理却把「当前 prompt 块」的记忆用在当前块上；这是分布错位，可能帮助也可能伤害，论文没有消融。记忆只在 prompt 编码时注入，答案生成没有直接记忆，长文/多轮生成的能力没有被测试。若方法依赖这种未验证的错位，结论的范围和可复现性都会受影响。
  • 当前能够得出的判断：论文披露了查询来源的差异，但没有给出对齐实验或效果分析；现有证据不足以判断这是有意的「用当前块精炼记忆」还是实现上的权宜。长生成、多轮对话、答案块记忆刷新都没有报告。
  • 如何验证或补强：做四组对照：训练/推理都用前一块、训练/推理都用当前块、训练前一块/推理当前块（现状）、训练当前块/推理前一块；报告每组 QA 与长生成结果；说明第一个 prompt chunk 的记忆规则；在生成过程中刷新记忆或做增量缓存，测长答案的增益；报告门控/注意力在 prompt 与答案位置的实际取值。
  • 严重程度：主要问题。

质疑：评测汇总与统计强度不足，Bamboogle 只有 125 例，训练语料与 QA 知识重叠未核查

  • 原文依据：六任务平均是等权平均（Table 1），Bamboogle 只有 125 个测试样本（Table 4）；Mistral 上 DFM 的 Bamboogle +18.74 按等权平均约贡献 +3.12 分，占相对 Base 的 +13.58 的约 23%（按 Table 1 算术）；消融明确为单次运行，主结果未报告重复次数、标准差、置信区间或显著性检验（Appendix C）；训练语料是 Wikipedia 2018，六个 QA 基准也是 Wikipedia 知识型问答，Appendix A.1 没有像域适配 Appendix A.2 那样做 benchmark overlap 的精确匹配筛查；没有测后 2018 的新事实或主干未见过的知识。
  • 为什么重要：12.71%/11.19% 是精确到小数点后两位的相对提升，但在 125 例的小基准、未报告重复/方差和无显著性的条件下，这个精度没有统计基础；如果 QA 测试事实与训练语料/主干预训练高度重叠，增益可能反映「同分布知识访问」而非「新知识注入」，这会改变论文的结论边界。
  • 当前能够得出的判断：Mistral 上六个任务全部提升、Qwen3 上五个提升，说明方向性效果不是单一小基准造成的；但 Bamboogle 的权重、缺少方差报告和潜在重叠使精确百分比不可靠。论文没有报告这些稳定性/重叠分析。
  • 如何验证或补强：用 3–5 个训练种子重复主实验并报告均值/标准差；对任务级结果做 bootstrap 或配对检验；报告按样本数加权和去掉 Bamboogle 的平均；做 QA 问题/答案与训练语料的 overlap 分析；增加 2018 年后事实、主干未见过实体或人工构造的新知识 QA。
  • 严重程度：主要问题。

质疑：成本报告不完整，存储字节、构造墙钟时间和推理时延都没有测

  • 原文依据：Appendix D 明确说 32×/2048× 只计检索查询和返回槽位，「不计算不同 token、搜索候选、存储字节或 FLOPs」，训练时间「不含目标构造和评测」；Appendix C.1 说块大小实验「没有测量构造的实际耗时」；论文没有报告推理时延、吞吐、显存、RAG 的端到端延迟；新增 0.75B 参数、每个域单独一个模型（Appendix A.2），但没有报告目标记忆/索引的存储和每域部署成本。
  • 为什么重要：论文的卖点是「更低的构造/训练成本、推理不检索」。构造计数下降不等于总成本下降；如果目标记忆的 2B 个槽位需要数 TB 存储，或 0.75B 预测器让推理更慢，「效率」结论就要重新表述。存储和时延是部署时最关心的两项。
  • 当前能够得出的判断：训练小时数、参数数和查询/返回项计数是论文报告的，可信；但端到端构造时间、存储字节、推理时延/吞吐、每域存储都没有报告，当前材料无法确认 DFM 在总成本上优于 RAG 或 MLP Memory。按公开数字的量级估算（分析者估算，不是论文报告）提示目标记忆存储不可忽略。
  • 如何验证或补强：报告目标构造的墙钟时间、索引/目标记忆字节数、每域模型存储；在同一硬件上测 DFM、RAG、MLP Memory 的推理时延、吞吐、显存和端到端成本；报告不同 K/块大小/预测器深度下的成本-效果曲线；给出总成本（构造+训练+推理）的对比。
  • 严重程度：次要问题。

6. 审稿式总评

作者发现现有参数化记忆的两个成本——token 级监督要逐 token 检索、输出级插值只做浅融合——因此提出 DFM：用块级共享监督训练一个因果记忆预测器，把预测出的连续记忆通过门控交叉注意力注入解码器中间层，并冻结主干、端到端训练新增模块。实验在 Mistral-7B、Qwen3-8B（附录还有 OLMo-3-7B）的六个英文 QA 任务和 Qwen3-4B/8B 的代码、数学、法律域适配任务上表明，DFM 在两个主干的六任务平均上比最强基线相对高 12.71%/11.19%（OLMo 上约 +7.9%），域适配平均比 Base 高 6.51/4.38 分，训练时间和目标构造计数明显低于 MLP Memory；其中「块级监督显著降低构造计数」「中间层融合明显优于末层融合」「训练时间/参数量的对比」证据较强，但「预测记忆本身提供知识」「训练/推理对齐」「相对最强基线的稳定优势」「统计稳定性」「存储与推理成本」仍缺少充分支持。本文最有价值的部分是把「检索监督→连续记忆→隐藏状态融合」这条链路做得干净、可解释，并公开了足够多的结构消融；最大的审稿风险是把「平均分提升」当成「记忆机制已被证明」，以及在基线强度、统计口径和成本报告上留下缺口。

  • 问题定义清晰度：强。论文把 CPT、RAG、参数化记忆的取舍讲清楚，并把「token 级构造贵、输出融合浅」作为明确问题；扣分点是「知识注入」与「同分布知识访问」没有区分，结论边界主要靠读者自己从实验设置推断。
  • 创新性证据：中。块级共享监督和把预测记忆注入中间层是实质的组合创新，32×/2048× 的构造削减也有明确设计对应；但组件（因果 Transformer、交叉注意力、sigmoid 门、MSE 监督）都是已有技术，最接近的 Memory Decoder/MemSFT 没有实验比较，token 级/输出级 DFM 对照缺失，「首次」或「普遍优于」都不能成立。
  • 方法可信度：中。结构、损失、层号、超参和数据构造写得具体，冻结主干和共享投影器的设计合理；但训练/推理的查询来源不一致、目标记忆包含最近邻（可能是自身）的实现细节、首个 prompt 块的记忆规则没有交代，且缺少记忆保真度与零/随机记忆对照，方法的核心因果链没有闭合。
  • 实验支持力度：中。三个主干、六个 QA、三个域、多个消融，覆盖面在同类论文里不算窄；但消融单次运行、主结果无方差/置信区间、Bamboogle 仅 125 例、基线训练不透明（RETRO 异常低、CPT/LoRA 坍缩）、域适配相对最强基线的边际很小，使「平均更好」成立、「精确提升」和「机制成立」不成立。
  • 可复现性：弱。论文给了完整超参、数据来源和结构细节，但代码/检查点当前未发布（摘要只说即将发布），目标记忆构造和索引没有公开脚本，存储/时延数据缺失；按论文重实现可行，但端到端复现和结果核对目前无法确认。
  • 综合阅读价值：高。对想做参数化记忆、知识注入或「免检索 RAG」的学生，这篇论文把问题、结构、成本和失败模式都摆得很清楚，消融也提供了「融合位置比深度更重要」这类可迁移的经验；适合作为设计入门和批判性阅读材料，但不应把它的平均分当成记忆机制已被证明。
