0. 一句话结论

论文研究预训练视觉-语言-动作模型（vision-language-action model，VLA）在新多步操作任务上失败后，应当改“调用方式”还是改“权重”这一归因问题，提出先改进执行支架（harness）、再用反事实重试定位剩余失败、只对执行器确实缺失的子步骤做微调的 AdaRSI。它在 RoboCasa365 全部 50 个目标任务上把 Composite-Unseen 成功率从 4.6% 提高到 13.8%，但净增益高度集中在两个任务，且缺少统计检验与真实机器人验证。

1. 论文具体想解决什么问题？

预训练 VLA 已能在多种环境中执行操作任务，也能借助记忆处理部分长程任务，但在训练分布之外的多步组合任务上仍会中途失败：可能靠近错误目标、误判某一步是否完成，或者根本做不出某个动作（§1）。这些失败有的出在“执行器被怎样调用”，有的出在“执行器本身做不到”，而失败结果本身并不告诉我们是哪一种。

现有方法大致分两层。执行支架层面的方法让编码智能体（coding agent）改写技能、工具和调用流程，执行器保持冻结；这类改动便宜、可读、可回退，但当任务需要一个执行器做不出的动作时就会停滞（§1、§2）。策略层面的方法更新执行器权重，有的把训练集中在近期成功率低的任务，有的针对高风险场景训练专用策略，也有工作同时利用两层；但它们决定的是“在哪些任务上训练”，而不是“这个失败究竟该由哪一层负责”（§1、§2）。作者指出，如果失败其实源于调用方式，为它训练新权重不仅昂贵，还可能让原本能完成的子步骤变差；Table 4 的配对实验正是这一风险的直接证据：微调让微波炉开门和玻璃瓶抓取变好，却让已经能做好的羊角面包和果酱放置变差。

因此论文提出的核心假设是：只有当某个子步骤在执行支架已经尝试过不同指令、不同机器人位姿和不同接近方式之后仍然不可靠时，才应该改变执行器权重；先改进执行支架不仅吸收了“调用失败”，还决定了后续策略在什么状态下训练和被调用（§1、§4.1）。图 1 把这个假设与两条替代路线并列。

图 1（论文 Fig. 1）：图中比较了三种系统级策略。只改 harness 的路线可以改工具和调用流程，但执行器仍冻结，因此当任务卡在“微波炉门被弹回”这类动作缺口时，改流程无法让系统越过它；为每个子步骤都训练新策略的路线虽然复用了工具，却对每次执行器调用都做微调，训练成本高，而且新策略未必比原执行器更好；AdaRSI 的路线是先改 harness，用它把机器人带到需要动作的状态，再自己采集演示、只训练目标子步骤并验证，最后让基础执行器继续完成其余步骤。这个对比想说明的不是“训练一定有用”，而是训练必须发生在正确的状态和正确的子步骤上。

论文最终要验证的子问题因此可以写得很具体：在 RoboCasa365 的目标任务上，先做 harness 改进、再做失败归因、最后按需微调，能否在显著低于“全部子步骤都训练”的成本下提高任务成功率，并且这种提升是否来自“执行器缺失的动作”而不是别的混杂因素（§4、§5）。

2. 创新点是什么？

论文的真正增量是把“何时改权重”从一个工程直觉变成一个可操作的归因流程，并把该流程嵌入跨轮次、跨任务的自我改进循环。具体有三点。

第一，作者把具身系统的递归自我改进（recursive self-improvement，RSI）表述为“失败归因问题”：系统有一个执行支架层和一个执行器库层，每次持久失败先被归到其中一层；只有被归为“执行器受限”的子步骤才进入训练。这个表述改变了已有工作只比较“改 harness”或“改权重”的默认框架，把两者组织成有先后顺序的决策（§1、§3）。

第二，方法上新增了“先 harness、再反事实重试、再按需训练”的流水线：harness 轮次由智能体自己写工具和流程，并在留出验证场景上迭代；权重轮次从保存的模拟器状态重放失败子步骤，用不同指令或接近方式区分“调用不好”和“动作缺失”；对仍然失败的子步骤，系统自己采集演示、微调、在留出起始状态上与原执行器比较，只有验证更好的地方才在流程中推荐新策略（§4.1、§4.2）。这套流程的关键不是某个新网络，而是把“归因—训练—验证—采用”串成可回退的闭环。

第三，系统把改进经验跨任务复用：先在覆盖高、中、低基础成功率的试点任务上不限额训练，写出经验文档，再按固定规则从试点策略的实际开销推导后续任务的训练预算；后续任务的智能体在这个预算下决定训练什么（§4.3）。这使“如何改进”本身也随任务积累，而不只是单个任务的策略变好。

3. 作者如何解决？

直觉上，AdaRSI 把一次任务执行看成“上层智能体编排工具与策略、下层 VLA 执行动作”的两级系统。失败可能出在上层的调用，也可能出在下层的动作能力；先让上层充分改进，既消除了调用类失败，也把机器人带到真实使用时会到达的状态。此时仍然失败的子步骤，才有资格被怀疑为执行器能力缺口；从这些状态采集演示并训练，学到的才是“在这个调用条件下缺失的动作”，而不是在任意状态下重新学一遍。

3.1 系统与两层改动

论文把具身智能体系统写成三元组 S=(A,H,Π)S=(A,H,\Pi)S=(A,H,Π)：编码智能体 AAA 负责任务理解、运行系统和读取执行反馈；执行支架 HHH 包含智能体写的技能、工具以及把工具组合成任务流程的程序；执行器库 Π\PiΠ 存放低层操作策略，初始只有预训练 VLA π0\pi_0π0​，训练出新策略后加入库中（§3）。工具有时可以直接移动机器人，例如导航到某个固定装置，但每个操作子步骤都由库中的某个策略执行，由 harness 选择策略并给出语言指令。

改进只发生在模拟器中的改进阶段，此时可以反复运行任务并访问特权模拟器状态；部署阶段 harness 和策略库固定，系统只使用机器人的常规观测（§3）。系统要同时优化部署成功率 J(S)J(S)J(S) 和改进成本 C(S)=CH+CΠC(S)=C_H+C_\PiC(S)=CH​+CΠ​，其中 CHC_HCH​ 计语言模型 token，CΠC_\PiCΠ​ 计自采集演示和训练算力，包括训练了但最终没被采用的策略。这个成本定义很重要：它决定了“按需训练”不只是精度问题，也是一个显式的资源分配问题。

3.2 Harness 轮次：先把调用方式做到头

harness 从一个最小版本开始：只暴露执行器（给定语言指令、执行有界步数）、相机图像和本体感知、场景固定装置地图、底座与机械臂的低层命令，以及一个把底座导航到固定装置的基础工具（§4.1）。其余工具由智能体自己写，例如在固定装置前精细定位、复位机械臂、把相机放大到某个区域；流程则规定部署时智能体应执行哪些子步骤、每一步调用哪个工具或策略、如何检查进度。

开发阶段，智能体可以重置场景、保存和恢复模拟器快照，并查询任务的官方成功检查。快照支持反事实重执行：把同一个失败子步骤从同一状态出发，换一条指令或换一种接近方式再试，从而把“指令不好/接近方式不好”与“执行器做不出这个动作”分开（§4.1）。每轮结束后，系统在留出的验证场景上按部署方式运行，运行记录作为下一轮反馈；智能体在一组场景上调整 harness，在另一组场景上接受评判，目的是暴露只在新场景出现的失败。图 2 给出了整个循环的数据流。

图 2（论文 Fig. 2）：流程从 harness 改进开始，智能体在任务环境中反复执行、根据执行记录修改工具和流程，经过两轮后在留出验证集上评估；随后进入失败归因，利用保存的快照在不同指令或接近方式下重放失败子步骤，判断它是“调用问题”还是“执行器受限”；只有后者进入按需策略改进，系统自己采集演示、微调子步骤策略，并在相同起始状态和指令下与原执行器比较，把更好的策略加入策略库并在流程中标注推荐位置；最后是部署，固定 harness 与策略，新的智能体实例按流程调用工具和策略，在未见场景中只依赖常规观测运行。图中的闭环说明，训练不是默认动作，而是归因和验证之后的最后一个分支。

这条流水线也界定了两轮改进的分工：harness 轮次负责把执行器带到可训练的状态，权重轮次只处理归因后仍被判定为执行器受限的子步骤。

3.3 权重轮次：归因、采集、微调与采用

权重轮次从失败归因开始。论文把一个子步骤称为“执行器受限”（executor-limited），如果智能体找不到任何 harness 能让 π0\pi_0π0​ 可靠完成它（§4.2）。在 harness 轮次结束时，智能体记录那些“机器人已经就位、指令也是执行器认识的，但仍然失败”的子步骤，以及从这些状态测到的 π0\pi_0π0​ 成功率；这些候选和背后的验证记录一起指导权重轮次。

对决定训练的子步骤，智能体在模拟器里自己采集演示。它可以用拒绝采样（rejection sampling）反复滚动基础执行器，只保留成功的片段；也可以写一个脚本专家（scripted expert），读取物体位姿、关节状态等特权信息来生成动作。后者属于特权信息学习：特权教师为只看到常规观测的学生标注数据。论文明确限定特权状态只用于生成和标注数据，部署系统永远看不到它（§4.2）。

每个演示集从 π0\pi_0π0​ 或智能体此前的某个策略出发，微调出一个子步骤策略，加入策略库，并通过与基础执行器相同的接口调用。随后是关键的一步：智能体在开发状态上把新策略与 π0\pi_0π0​ 比较，把结果写进流程——在新策略更好的子步骤上推荐它，在其他地方继续默认使用 π0\pi_0π0​。同一轮里，智能体还要弄清如何调用新策略，例如调用前机器人应站在哪里。所有训练过的策略都留在库中，部署智能体按流程推荐执行，但在 π0\pi_0π0​ 反复失败后仍可选择库里的其他策略（§4.2）。

这一节的设计理由可以归纳为三点：先归因，避免为“调用失败”训练权重；从 harness 到达的状态训练，保证策略学到的是实际会被调用到的分布；用留出起始状态比较后再采用，避免把只在少数开发场景上看起来更好的策略直接推到部署。第三点在论文自己的结果里并没有完全成立，后文会把它作为主要质疑之一。

3.4 跨轮次与跨任务的递归

每一轮把当前系统和这一轮积累的经验映射到改进后的系统；经验 Ek\mathcal{E}_kEk​ 包含开发运行、验证记录，以及权重轮次里每个策略（无论是否被采用）的训练结果（§4.3）。由于 harness 和策略都会保留，后续轮次可以建立在前一轮的发现上，新的 harness 修改也可以像使用基础执行器一样使用新训练的策略。

跨任务复用通过试点任务实现。作者选择在开发场景上覆盖高、中、低基础 VLA 成功率的试点任务，让它们在不受训练预算限制的情况下改进；从训练日志中，智能体写出一份经验文档，记录哪些类型的子步骤从训练中受益、多少数据足够、哪些努力被浪费。同一批日志再按固定规则推导出一个训练预算，规则按试点任务中被采用策略的实际训练量缩放；后续任务在这个预算下改进，环境对训练步数和自采集演示数量强制执行预算（§4.3）。这样，“在哪里训练”就变成了一个受预算约束的显式取舍，而不是无限试错。

部署时，一个新的智能体实例读取最终流程，在未见场景中调用工具和策略，并从图像检查进度；它没有快照、成功检查或特权状态（§4.3）。这意味着训练阶段可以“作弊”获取状态和标签，但测试阶段不能；论文在这一点上的边界是清楚的。

4. 解决得怎么样？

4.1 实验设置

实验在 RoboCasa365 的全部 50 个目标任务上进行，分为 18 个 Atomic-Seen、16 个 Composite-Seen 和 16 个 Composite-Unseen 任务（§5.1）。前两类出现在执行器训练数据中，Composite-Unseen 则把熟悉的子任务组合成训练数据里没有的任务。论文遵循官方协议，使用 target split（厨房和物体与预训练不重叠）、官方任务时域（也计入工具消耗的步数）和官方成功检查；每个任务测试 50 个场景，开发、验证和测试场景互不重叠，测试场景在改进阶段从不使用。

执行器 π0\pi_0π0​ 是 GR00T N1.5，复合任务使用官方 Composite-Seen checkpoint，原子任务使用 Atomic-Seen checkpoint；编码智能体是 GPT-6.1-sol，通过 Codex 运行（§5.1）。系统不使用人类演示。对比系统包括：单独运行 VLA、只让智能体用自己的指令调用 VLA（Agent + VLA）、只做 harness 改进（Agent + harness），以及在此之上加入权重轮次的 AdaRSI。消融还包括只训练不改进 harness（Agent + weights）、训练每个子步骤并默认调用新策略（Always train）、把 AdaRSI 的流程和策略当固定程序执行（Fixed procedure）、保留最终系统但用 π0\pi_0π0​ 替换微调策略（AdaRSI w/ π0\pi_0π0​），以及按最低成功率选择训练对象的规则（Lowest first）。

评价指标是任务成功率，按套件内任务取平均。论文报告了每个任务 50 个场景的结果，但没有报告置信区间、随机种子或多次训练/智能体运行的方差；这一点会影响对小幅提升的解读。

4.2 关键结果

主结果在 Table 1。单独 VLA 在 Atomic-Seen / Composite-Seen / Composite-Unseen / 全部 50 个任务上的成功率是 75.4 / 43.0 / 4.6 / 42.4。只让智能体调用 VLA、不做开发，反而在 Atomic-Seen 下降到 72.2，总体 41.8，低于单独 VLA；这说明“让智能体发子指令”本身不是收益来源。只改进 harness 后，三个套件分别升到 78.3 / 48.0 / 9.9，总体 46.7；再加入权重轮次，AdaRSI 达到 79.7 / 49.0 / 13.8，总体 48.8，相对 VLA 的增益为 +4.3 / +6.0 / +9.2 / +6.4。Composite-Unseen 的相对提升最大（约为基础成功率的 3 倍），但绝对水平仍是 13.8%，也就是绝大多数回合仍然失败。

权重轮次对 Composite-Unseen 的贡献是 +3.9 个百分点，对 Atomic-Seen 和 Composite-Seen 分别只有 +1.4 和 +1.0（Table 1）。Table 2 的任务级结果说明这 3.9 点从哪里来：WaffleReheat 从 0% 升到 38%，RecycleBottlesByType 从 0% 升到 18%，BreadSelection 从 42% 升到 52%，WashFruitColander 从 48% 升到 58%；但 CuttingToolSelection 从 50% 降到 36%。按 16 个任务、每任务 50 个场景复算，净增益约 31 次成功，其中 WaffleReheat 贡献 19 次、RecycleBottlesByType 贡献 9 次，两者合计约占净增益的 90%（审稿人判断，基于 Table 2 的逐任务数字计算）。这意味着“权重轮次在未见组合任务上有效”的证据主要由两个任务支撑，而不是普遍分布在 16 个任务上。

Table 3 给出了训练发生在哪里。Composite-Unseen 上 AdaRSI 训练了 38 个策略，其中 32 个在测试时被调用，85% 的训练时间花在被采用的策略上；微调策略只执行 14.7% 的操作步，而 Always train 训练 118 个策略、调用 104 个、执行 71.2% 的操作步。相反，在两个已见套件上，大多数训练出的策略从未被调用：Atomic-Seen 使用 12/72，Composite-Seen 使用 8/34，π0\pi_0π0​ 仍执行 78% 和 98% 的操作步。作者把这解释为“训练集中在执行器不足的地方”，这个解释与数据一致，但也说明在已见任务上权重轮次的收益很小，训练大部分是冗余的。

Table 4 的配对测试进一步隔离了微调权重本身的作用。测试把同一回合重放到第一次调用某策略、保存快照，然后让 π0\pi_0π0​ 和微调策略从同一状态、用同一指令、执行同样步数，由特权状态判定成功。对 π0\pi_0π0​ 不会的动作，微调把微波炉开门从 0/18 提到 7/18，把玻璃瓶抓取从 2/44 提到 17/44；对 π0\pi_0π0​ 已经会的动作，微调把羊角面包放置从 16/40 降到 11/40，把果酱放置从 14/39 降到 9/39。这是全文最干净的一组机制证据：同一个训练过程既补上了缺失动作，也损伤了已有动作，因此“只在必要时训练”不是修辞，而是有直接实验支撑的设计约束。这两组配对结果也为后面的机制分析定下前提：微调既可能补缺，也可能造成负迁移。

4.3 机制证据

消融结果在 Table 5。只训练不改进 harness（Agent + weights）在 Composite-Unseen 上只到 7.2%，训练了 45 个策略、采集 556 个演示、花 1,204 GPU 分钟；只改进 harness 到 9.9%；两者结合到 13.8%，训练 38 个策略、416 个演示、966 GPU 分钟。Always train 训练 118 个策略、1,877 个演示、3,411 GPU 分钟，只到 12.6%。Fixed procedure 复用 AdaRSI 的同一套策略，但把流程当固定程序执行，只到 6.9%，即使它还能使用特权状态做状态估计。这些结果支持两个判断：两层都不能单独达到组合效果；harness 是更大的杠杆，而且它通过“告诉智能体该在哪些状态训练”放大了权重轮次的效果。

图 3 把成功率与训练成本放在同一平面上。harness 轮次把系统从 5.9% 推到 9.9%，不花训练算力；权重轮次再花 966 GPU 分钟把成功率推到 13.8%。Always train 花 3,411 分钟只得到 12.6%，Agent + weights 花 1,204 分钟得到 7.2%，Fixed procedure 与 AdaRSI 用同样的策略却只有 6.9%。因此在这个比较集合里，AdaRSI 位于成本—成功率的支配边界上：没有系统以更低的训练成本取得更高成功率。

图 3（论文 Fig. 3）：横轴是训练 GPU 时间，纵轴是 Composite-Unseen 成功率，箭头表示 AdaRSI 的改进顺序。它先从“智能体 + VLA”的 5.9% 出发，经过零训练的 harness 轮次到达 9.9%，再经过一次权重轮次到达 13.8%；阴影区域表示“成本不低于 AdaRSI 且成功率更低”的系统。这个图的作用不是证明 AdaRSI 在所有维度上最优，而是说明在作者设计的这套消融里，训练成本和收益的折中点落在“先 harness、后按需训练”的路径上，而不是“训练所有子步骤”或“只训练不改进 harness”。

Table 6 进一步拆分权重轮次内部的两类贡献。对五个成功率发生变化的 Composite-Unseen 任务，harness 之后先加入修订后的流程，总成功数从 70/250 升到 84/250（+14）；再加入微调权重，升到 101/250（+17）。AdaRSI 相对 harness 增加的 31 次成功中，有 17 次在把微调策略换回 π0\pi_0π0​ 后消失，剩下 14 次来自流程修订。WaffleReheat 从 38% 降到 10% 证明了权重的作用；BreadSelection 则保留了全部增益，说明它的提升主要来自指令修订。作者据此说“微调和围绕它的流程贡献大致相当，权重承担了流程无法解决的任务”，这个说法与数据一致，但也提醒读者：AdaRSI 的收益并不是“训练万能”，而是训练与流程修订各占一半。

Table 8 是全文最接近“归因是否必要”的对照。Lowest first 规则从同一套 harness、同一预算、同一演示采集和采用规则出发，测量 π0\pi_0π0​ 在每个操作子步骤上的成功率，按最低成功率优先训练与 AdaRSI 相同数量的子步骤，但不从其他状态或其他指令重试。它在非试点 Composite-Unseen 任务上只有 11.8%，与只改进 harness 的 12.0% 基本持平；AdaRSI 在相似训练成本下达到 16.6%。Lowest first 选中的 13 个子步骤中有 11 个与 AdaRSI 相同，却没有转化为增益；作者以 WaffleReheat 为例，说两者都训练微波炉门，但只有 AdaRSI 在重试后发现失败取决于手接近把手的角度，并从有效的接近方式开始训练，因此一个成功 38%、一个只有 2%。这组对照支持“归因决定的不只是训练哪个子步骤，还包括从什么状态学”，但它同时改变了“是否重试”“是否选择状态”和“开发时间分配”，所以还不能把差异单独归给归因算法本身，后文会展开。

图 4 用两个失败任务说明“层级选择”在具体回合里意味着什么。WashFruitColander 的问题出在流程顺序和底座位置：π0\pi_0π0​ 先拿起滤盆再清洗，导致可放置的位置被压缩；AdaRSI 把清洗调整到前面，并让训练状态从已经放好底座的位置开始，任务因此走通。GetToastedBread 的问题在抓取动作本身：面包在烤面包机里时直接抓取会失败，系统改为先开门、再从较低位置抓取，并对“从烤面包机里取出”这一子步骤做定向微调。两个案例的共同点是：失败不是靠换一个更大的模型解决的，而是先定位到“哪一步、在什么状态下失败”，再决定是改流程还是训练策略。

图 4（论文 Fig. 4）：这组案例把 AdaRSI 的决策链完整走了一遍——回合失败后，系统先判断失败属于流程、状态还是执行器能力，再在 harness 层修订流程或在权重层训练对应子步骤，最后用验证回合确认改动是否保留。WashFruitColander 展示的是流程顺序与训练起始状态的联合调整，GetToastedBread 展示的是针对单一抓取子步骤的定向微调；两者都表明收益来自“定位到正确的干预层级”，而不是统一地多训练或统一地改提示。

Table 9 则给出了训练子步骤的多种结局，避免把“训练”当成必然有效：French-door 冰箱门在 20 个演示后从 0/6 升到 6/6，但整个任务仍然失败，因为后续子步骤没解决；烤串抓取只从 0/16 到 3/16；烤面包机关门从 1/9 到 0/9；而对 π0\pi_0π0​ 已经能做的子步骤，训练有时能把杯子放置从 13/20 提到 31/40，有时毫无变化（水龙头 11/12 对 11/12），还有抽屉子步骤从 22/27 提到 26/27、任务成功率却下降的情况。作者从这些案例中提炼出“子步骤成功不等于任务成功”，这也是后文质疑验证门控的直接依据。

4.4 成本与适用范围

Table 7 对比 AdaRSI 与 Always train 的总成本：AdaRSI 在 16 个 Composite-Unseen 任务上取得 110 次成功，Always train 取得 101 次；AdaRSI 训练 38 个策略（Always 118）、消耗 2,468M 输入 token（Always 3,087M）、采集 416 个演示（Always 1,877）、使用 966 GPU 分钟（Always 3,411）。按这些数字，AdaRSI 用约 28% 的训练 GPU 时间、22% 的自采集演示，取得了略高的成功率；反过来，Always train 的策略数是 3.1 倍、演示数是 4.5 倍、GPU 时间是 3.5 倍。论文在 §5.4 还报告：Composite-Unseen 上平均每任务训练 2.4 个策略（含未被采用的）、26 个自采集演示、1.9k 次更新、约 1 GPU 小时；改进阶段每任务消耗 154M 输入 token 和 0.64M 输出 token；部署时每回合消耗 4.2M 输入 token 和 7.2k 输出 token，其中约 97% 的输入 token 是缓存命中。Atomic-Seen 和 Composite-Seen 的改进阶段分别消耗 117M 和 137M 输入 token/任务，部署阶段每回合 1.2M 和 1.9M。

这些数字说明“按需训练”在训练算力和演示数量上确实便宜，但成本口径仍不完整。论文的 C(S)C(S)C(S) 把语言模型 token 和训练算力分开计，Table 7 的 GPU 分钟只覆盖训练，不覆盖智能体在改进和部署时的推理；154M token/任务的改进开销和 4.2M token/回合的部署开销虽然被报告，却没有被折算成 GPU 时间、美元成本或墙钟时延，因此“28% GPU 时间”不能被理解为端到端总成本。Always train 的部署阶段需要 5.3M 输入 token/回合，Agent + weights 只需 1.5M，但后者成功率更低；这说明 token 成本与成功率之间也存在取舍，论文没有给出统一的成本—成功率前沿。

适用范围方面，所有实验都在模拟器中进行，特权状态让演示生成和标注变得容易；作者在 §6 明确说真实机器人上需要用成功检测器、脚本复位或偶尔的人工帮助替代，成本会上升，并计划在下一版加入真实机器人实验。系统只测试了一种执行器（GR00T N1.5）和一种闭源编码智能体（GPT-6.1-sol），任务全部来自 RoboCasa365 的 50 个目标；因此结论应限定为“在该模拟基准、该执行器和该智能体下，先 harness 后按需微调优于若干替代方案”，不能外推为普遍提升具身智能体的自我改进能力。论文也承认，多个子步骤都超出执行器能力时，链条中每个微调策略都必须在同一回合成功，任务才可能成功；这类组合失败仍是未解决问题。

5. 最容易受到审稿人质疑的地方

质疑：主要增益高度集中，且缺少统计不确定性

  • 原文依据：Table 2 的 16 个 Composite-Unseen 任务中，WaffleReheat 从 0% 到 38%、RecycleBottlesByType 从 0% 到 18%，两者合计贡献约 28 次净成功；按表中逐任务数字复算，AdaRSI 相对 harness 的净增益约 31 次成功，其余任务多为 ±2–10 个百分点的波动。Table 1 的 Composite-Seen 仅 +1.0、Atomic-Seen +1.4。论文没有报告置信区间、随机种子或重复运行。
  • 为什么重要：如果 3.9 个百分点的套件提升主要由两个任务驱动，那么“权重轮次在未见组合任务上普遍有效”的结论就被削弱；每任务只有 50 个场景，单个任务的二项标准误差约 4–7 个百分点，BreadSelection 的 +10、WashFruitColander 的 +10 和 CuttingToolSelection 的 -14 都可能包含较大抽样波动。
  • 当前能够得出的判断：证据足以支持“在这两个任务上，按需微调解决了执行器缺失动作”，但不足以支持“该方法在 16 个未见组合任务上普遍带来稳定提升”。论文的措辞基本承认了这一点（“not every task benefits”），但摘要和引言中的“3 倍”相对提升容易被读成普遍效果。
  • 如何验证或补强：报告按任务配对的置信区间或分层 bootstrap，明确训练/智能体运行的重复次数；增加场景数或种子数，尤其是对 WaffleReheat、RecycleBottlesByType 之外的 14 个任务；给出“去掉这两个任务后”的套件均值。
  • 严重程度：主要问题。

质疑：归因机制没有被独立隔离，Lowest first 对照混合了多个变量

  • 原文依据：Table 8 的 Lowest first 与 AdaRSI 使用同一 harness、同一预算、同一演示采集和采用规则，但 Lowest first“不从其他状态或其他指令重试”，而 AdaRSI 会做反事实重试并选择有效状态；两者在开发阶段的时间分配也不同，论文还提到 Lowest first 在四个任务上因逐个子步骤测量而耗尽开发会话，未能训练任何策略（§5.3）。Table 3 的“85% 训练时间花在被采用策略上”也是采用后的统计，不能反过来证明归因本身准确。
  • 为什么重要：论文的核心创新是“归因决定何时训练、从哪里训练”。Lowest first 的失败可能来自“没有重试”，也可能来自“测量所有子步骤太耗时”，还可能来自“没有选中正确状态”；当前设计无法把这些因素分开。若收益主要来自额外的重试和状态选择，那么贡献更像“多花开发时间搜索状态”，而不是一个新的归因原则。
  • 当前能够得出的判断：证据支持“AdaRSI 的整套流程比最低成功率优先规则更有效”，但不足以证明“归因标签本身”是收益的唯一或主要来源。作者把差异解释为“归因告诉智能体从哪些状态学习”，这是一个合理的假设，但尚未被独立操纵验证。
  • 如何验证或补强：增加三个等预算对照：(a) 只做反事实重试但不训练；(b) 训练同一批子步骤，但从随机开发状态而非归因状态采集演示；(c) 用人工/规则给定的“执行器受限”标签替代智能体归因，其余流程不变。若 (c) 接近 AdaRSI，说明归因可以由简单规则替代；若 (a) 已带来大部分收益，说明主要价值在重试而非训练。
  • 严重程度：主要问题。

质疑：验证门控不能可靠防止负迁移，采用准则与任务目标错位

  • 原文依据：Table 4 显示微调让羊角面包放置从 16/40 降到 11/40、果酱放置从 14/39 降到 9/39；Table 2 显示 CuttingToolSelection 在权重轮次后从 50% 降到 36%；Table 9 的抽屉案例中子步骤从 22/27 升到 26/27，但任务成功率反而下降。作者在 §6 承认，智能体可能采用“在少数开发场景上看起来更好、在测试场景上更差”的改动；CuttingToolSelection 的专用抓取步骤在开发中略好，却在测试中让需要削皮器的回合成功率减半。
  • 为什么重要：AdaRSI 的核心安全主张是“权重改动只有在归因并被验证后才进入系统”。如果验证只看子步骤在开发状态上的成功率，而子步骤成功与任务成功不一致，那么门控就可能把有害改动放进来。部署智能体在 π0\pi_0π0​ 反复失败后还可以绕过流程选择其他策略，这进一步削弱了“验证后采用”的可控性。
  • 当前能够得出的判断：论文提供了负迁移的直接证据，并诚实报告了失败案例，但没有给出一个在测试分布上可靠的采用准则。当前的“在开发状态上更好就推荐”是一个弱门控，不能支撑“验证保证安全”的强主张。
  • 如何验证或补强：把采用准则从子步骤成功率改为任务级、多场景的配对评估，并加入对已有子步骤的回退保护；报告每个被采用策略在测试集上的负迁移率；对 CuttingToolSelection 这类案例做逐回合分析，区分是策略本身变差还是流程编排导致。
  • 严重程度：主要问题。

质疑：成本比较只覆盖训练算力，未计入智能体推理与端到端时延

  • 原文依据：论文把改进成本定义为 C(S)=CH+CΠC(S)=C_H+C_\PiC(S)=CH​+CΠ​，CHC_HCH​ 计语言模型 token，CΠC_\PiCΠ​ 计演示和训练算力；但 Table 7 的“GPU 分钟”只统计训练，摘要中的“28% GPU 时间、22% 演示”也是相对 Always train 的训练开销。与此同时，改进阶段每任务消耗 154M 输入 token，部署阶段每回合 4.2M 输入 token（§5.4）；这些 token 需要由 GPT-6.1-sol 推理产生，论文没有给出其 GPU 时间、美元成本或墙钟时延。
  • 为什么重要：如果智能体推理成本与训练成本同一量级甚至更高，“用 28% GPU 时间”就可能误导读者对总成本的判断；实际部署中每回合 4.2M 输入 token 也可能成为瓶颈。论文没有与“人工设计 harness + 少量训练”或“固定强流程 + 同等 token 预算”的基线比较，因此无法判断成本优势是否来自方法本身，还是来自把大量工作转移给了更强的智能体。
  • 当前能够得出的判断：在“训练 GPU 分钟”和“自采集演示数”这两个口径上，AdaRSI 确实比 Always train 便宜；但端到端成本、部署吞吐和美元成本无法从论文确认。
  • 如何验证或补强：报告改进与部署的墙钟时间、token 到 GPU 小时的换算、API 费用（若使用闭源模型），并加入同等总预算（训练 + 推理）的对照；至少给出一个“固定流程 + 相同智能体 token 预算”的基线。
  • 严重程度：主要问题。

质疑：单一模拟基准、单一执行器与单一闭源智能体，复现性不足

  • 原文依据：全部实验在 RoboCasa365 模拟器上完成（§5.1、§6）；执行器只有 GR00T N1.5，智能体只有 GPT-6.1-sol（通过 Codex）；演示可以由脚本专家读取特权状态生成；论文没有提供公开代码或项目页。作者在 §6 明确说真实机器人实验仍在进行，将在下一版加入。
  • 为什么重要：方法的关键决策（找不找得到更好的 harness、能否写出有效的脚本专家、如何选择验证场景）都依赖智能体能力和模拟器特权信息；换一个执行器、换一个编码智能体或换到真实机器人，归因与训练的效果都可能改变。没有代码和真实机器人结果，独立复现和外部有效性都受限。
  • 当前能够得出的判断：论文的结论应限定在“RoboCasa365 + GR00T N1.5 + GPT-6.1-sol + 模拟器特权状态”这一组合内；不能据此断言方法在真实机器人或更弱智能体上同样有效。没有公开代码使复现性只能评为“弱/无法确认”。
  • 如何验证或补强：至少在第二个执行器（如 π0\pi_0π0​ 或 OpenVLA）和第二个编码智能体上复现；公开 harness 生成、快照重放、演示采集和微调的代码与配置；加入真实机器人或高保真 sim-to-real 实验，报告成功检测与复位的人力成本。
  • 严重程度：主要问题。

6. 审稿式总评

作者发现预训练 VLA 在新多步任务上的失败可能来自调用方式，也可能来自动作能力，而现有自我改进方法没有在训练前区分两者，因此提出 AdaRSI，通过“先 harness、再反事实归因、只对执行器受限子步骤微调并在留出状态上验证”的流程，把权重改动限制在必要位置。实验在 RoboCasa365 全部 50 个目标任务上表明，AdaRSI 在三个套件上都优于单独 VLA 和只改 harness 的系统，Composite-Unseen 从 4.6% 升到 13.8%，并以约 28% 的训练 GPU 时间和 22% 的演示达到略高于 Always train 的成功率；其中 Table 4 的配对测试和 Table 6 的“流程 vs 权重”拆分是较强的机制证据，说明微调确实补上了缺失动作、也可能损伤已有动作。但套件增益高度集中在两个任务、缺少统计检验，归因机制没有被独立隔离，验证门控在 CuttingToolSelection 等案例中明显失效，成本口径也没有覆盖智能体推理与端到端时延。本文最有价值的部分是把“何时改权重”变成了一个可操作、可回退的归因流程；最大的审稿风险是把这个在单一模拟基准、单一执行器和强闭源智能体上得到的结果，外推为普遍的具身自我改进能力。
