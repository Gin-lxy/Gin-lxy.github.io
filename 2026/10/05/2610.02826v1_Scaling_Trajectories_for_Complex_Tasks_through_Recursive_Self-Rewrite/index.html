0. 一句话结论

论文要解决的问题是：不同 harness（智能体执行框架）能让同一个模型解出不同的困难 terminal 任务，但这些成功轨迹混入了 harness 专有的控制指令与工作流约定，直接混合训练会产生分布错配。核心思路是 Recursive Self-Rewrite（RSR）：用同一个基座模型 Qwen-3.8-27B 扮演 planner / critic / executor 三个角色，把多 harness 成功轨迹重写成在通用 Terminus 2 harness 下全新沙盒重解的轨迹，经泄漏审计与验证过滤后用于 SFT。在论文报告的 5 个 terminal 基准上，RSR 相对 Base 与 Direct SFT 均有提升（TB2 pass@3 57.0%→74.2%，TBH 39.0%→63.0%），证据在 TB2 与 TBH 上较强；但”提升来自重写本身还是数据量约 6 倍放大”未被消融隔离，自建基准的同源污染风险与论文两处数据账目不一致使其余结论需保留。

1. 论文具体想解决什么问题？

背景与任务：terminal / 长程 agent 任务的成败不只有模型权重决定，harness 决定模型如何接收观察、调用工具、跟踪进度、验证中间结果、从失败恢复以及何时停止（§1）。已有工作（Terminus-KIRA、StateM、Self-Harness、Meta-Harness 等，§4）几乎都在推理时优化单个 harness，不更新模型参数。

作者观察到的新现象（证据较强）：(1) 同一模型在不同 harness 下解出的任务集合不同。在约 3K 个自建 terminal 任务池上，三个 harness 的并集解出 759 个任务（25.9%），比最强单 harness（Terminus 2，565 个）多 194 个（相对 +34.3%）；在把 rollout 数控制到相同的子集（1,247 个任务）上互补性仍成立（union 352 vs 最强单 harness 285，+23.5%）（Table 1、Table 2、§3.3）。(2) 不同 harness 在不同领域互有胜负，没有哪个 harness 在所有领域都最强（Figure 5，§3.3）。

现有方法的失效条件：把这些轨迹直接混在一起做 SFT 会引入分布错配——每条轨迹都是”模型 + 源 harness”的联合行为，包含控制器干预、任务专用提示、工作流逻辑与停止规则；直接池化学到的是 harness 专有约定，推理时在通用 harness 下不可用（§1，引用 Thangarajah et al., 2026）。论文用 Direct SFT 实证佐证这一点：直接训练在 TB2 上不升反降 3.6 个百分点（pass@3），mean per-run 从 51.7% 降到 43.8%（Table 5、§3.6）。

作者认为的原因：成功行为（planning、verification、recovery、continuation）与 harness 控制机制纠缠在同一轨迹里，需要”保留行为、剥离脚手架”的重写（§1、§2）。

核心假设：把多 harness 辅助下取得的成功重写成”通用 harness 下独立重解并验证通过”的轨迹，用于 SFT 可以让模型在推理时不依赖任何专用 harness 而内化这些行为（§2–§3.5）。

区分三类问题：harness 影响 agent 性能是领域已有认知（§4 的 harness 工程线）；”多 harness 联合扩大可解任务集、且互补性不是采样量不均所致”是本文给出的系统测量（其 equal-rollout 控制是有效证据）；本文实际解决的子问题是”这些经验能否、如何变成通用 harness 下的训练数据”。注意：论文观察到了 Direct SFT 的退化现象，并把原因解释为长轨迹与死循环，但该因果解释只有 3 条轨迹的巡查支撑（§3.6），未做验证——这是”观察到现象、因果未充分验证”的情形。

2. 创新点是什么？

一段话概括：本文真正的技术增量是把”多 harness”从推理时的控制器重新定位为训练数据的发现器，并配一条”重写—审计—重解”数据构造管线：同一基座模型先作为 planner 把成功轨迹压缩成不含最终交付物的 runbook（提取目标、里程碑、检查、恢复策略与常见坑），再作为 critic（确定性规则 + 模型判断）筛掉 verifier/solution leakage 与不可用工具引用，最后作为 executor 在全新沙盒、通用 Terminus 2 harness 下按 runbook 重解；每条源成功采样 K=4 个 runbook、每个入选 runbook 执行 M=4 次，只有验证通过且通过泄漏审计的轨迹进入 SFT。经验效果是把 2,001 条源成功轨迹放大成 11,094 条重写轨迹，模型在五个基准上全面优于 Base 与 Direct SFT（Table 5）。它不是新 harness、也不是新训练算法，而是一条新的经验蒸馏数据管线。

逐项分析：

  1. 多 harness 发现协议（§2.1、§3.2）。新增内容：把 Terminus 2（通用循环）、StateM（显式工作流状态 + 受检转换）、RSRT（用 verifier 结果触发反思续跑）三个已有 harness 作为”经验发现器”编排使用。与最接近工作差异：harness 工程线（Meta-Harness、Self-Harness 等）目标是优化单个 harness 的推理表现；本文目标是用多个 harness 扩大”可训练的成功经验”集合。证据：Table 1/2 的覆盖与 union 分析、equal-rollout 子集分析；Table 6 显示同一 base 模型换 harness 时结果变化巨大（TBH 上 Terminus 2 33.0% vs RSRT 66.0%）。移除后的变化：只剩单 harness 时覆盖收窄（Table 1 任何单 harness 都低于任何 pairwise union）——但论文没有”只用单 harness 做重写训练”的消融。

  2. 轨迹重写三役 + 泄漏过滤（§2.2、§3.4）。新增内容：runbook 格式约束（可描述任务、接口与验证流程，但不直接给交付物）、planner 前先压缩源轨迹（只留任务指令、模型动作、环境观察，去 harness 控制消息）、critic 两段式过滤（schema 校验/已知 artifact/不支持工具引用 + 只见公开任务指令的模型审查）、执行时 runbook 仅作私有引导、不写入训练数据；另有独立于验证的 underived values 泄漏审计。与 Reflexion/ExpeL（推断时不改参数的反思）不同，这里是产生可训练轨迹；与 Harness-Zero（把 harness 支持行为蒸馏进参数）不同，本文强调多 harness 来源与”重解”而非直接模仿。属于已有组件（拒绝采样、SFT）的新组合 + 流程约束设计，是否构成首次提出需要更完整的文献检索。

  3. K×M 拒绝采样放大（§3.4；首页示意插图，HTML Figure 1 / PDF 无编号题头图）。新增内容：一次成功（source rollout）通过 K 个 runbook × M 次执行最多变成 K×M 条候选新轨迹，只留通过者。与 Direct SFT 的差异是数据规模与形态同时改变。证据：11,094/12,893 ≈ 86% 通过率；移除后即退回 Direct SFT 设置（Table 5 有对照）。

原创边界说明：根据本文的 related work 和实验对比，只能确认作者声称的差异；是否构成首次提出，还需要更完整的文献检索。

3. 作者如何解决？

直觉：把”扶着脚手架解出来的成功”变成”空手重解一遍的示范”。harness 像脚手架，帮模型一次性够到难题；但直接抄脚手架上的过程会学到依赖脚手架的习惯（如 StatoM 的 statem goto implement 这类源 harness 专有命令）。因此先让模型把解法提炼成”提纲”（runbook：目标、步骤、检查、避坑，但不含最终答案），审查提纲没有泄题、没有引用外部工具后，让它在空白沙盒里照提纲独立重做；重做成功的那条独立交互历史才是训练数据——推理时模型带着这段”肌肉记忆”在通用 harness 下独跑。

按实际运行流程（§2.2、§3.4、§3.5）：

  1. 输入：自建约 3K terminal 任务池（SWR 自建约 2.5K 个任务、覆盖 50+ 领域，外加 420 个取自 RST 数据集、经改造加难的任务，§3.1）；单个基础模型 Qwen-3.8-27B（全文唯一模型）。
  2. 多 harness 发现（§2.1、§3.3）：对任务池分别在 Terminus 2、StateM、RSRT 下 rollout，共 14,598 条，得 2,001 条成功轨迹（覆盖 759 个任务）。RSRT 的发现协议给出 180 分钟/任务 wall-clock 预算，完成声明被 verifier 拒绝后回看轨迹继续调试；Terminus 2 与 StateM 的预算论文未报告。
  3. 重写（§2.2、§3.4）：重写只针对 StateM 与 RSRT 的源成功（Terminus 2 的 766 条成功轨迹不重写、直接保留——§3.5）。planner 先压缩源轨迹再产 runbook，同一源采样 K=4 个候选；critic 先做确定性校验（schema、已知 artifact、不支持的工具引用），再用只看到公开任务指令与候选 runbook 的模型判断是否泄题，不合格的打回重生成；executor 对每个入选 runbook 在全新沙盒、通用 Terminus 2 下按 runbook 重解，M=4 次、temperature 0.7。
  4. 过滤与放大（§2.2、§3.4）：验证通过 + underived values（无法从任务或环境推导的值）审计通过才保留；共 12,893 条重写 rollout、11,094 条通过（约 86%）。训练时只保留公开交互历史（任务、环境观察、模型回复），runbook 与 critic 对话剔除。
  5. 训练（§3.5）：三组共用同一 Qwen-3.8-27B——Base（原模型）；Direct SFT（2,001 条源轨迹去掉 harness 专用插入语后直接 SFT）；RSR（11,094 条重写轨迹 + 766 条 Terminus 2 直通轨迹 SFT）。训练超参数论文未报告。
  6. 推理：微调后的模型只在 Terminus 2 通用 harness 下运行，无源 harness、无 runbook、无 critic——规划、检查、恢复、续跑全部必须来自模型自身。

图中的每个部分做什么：

Figure 2 左侧 Discover：任务池同时进入多个 harness，产出 passing traces——这是”发现”阶段，回答”经验从哪来”；中框 Rewrite 是核心：Planner 为每条成功轨迹产 K 个 runbook（”milestones + checks”），说明为什么需要 planner——直接拿源轨迹训练会混入 harness 控制信息，先蒸馏成不含答案的提纲才能跨 harness；Critic 做”rule checks + model”双重筛查（solution、verifier & harness leakage），漏了则”resample with reason”，保证提纲不泄题、不依赖源 harness 工具；Executor 在”Fresh sandbox ×M per runbook”里用通用 harness 重解，图中 “One model in all three roles” 与 “Private guide excluded from training data” 两个注记分别说明三役共用同一模型、runbook 不进训练数据；右框 Verify：Task verifier 隐藏检查（fail 即弃）、Leak audit 找”underived values”（无法从任务或环境推导的数值，视为隐藏答案转移的迹象）、Filter，最终产出 Verified trajectories。整张图解释了方法的核心主张：经验要被”净化 + 重解”才能变成通用 harness 下的可训练数据。

Figure 3 解释互补覆盖的机制来源：(a) Terminus 2 是最小循环——Model 与 Terminal 之间 act/observe，模型自行决定 Finish，几乎没有外部结构；(b) StateM 在”Model acts”与”Check transition”之间加了持久 Workflow state + context，检查不过则 repair 回退——提供结构化进度控制，这也是它通过轨迹中 29.6% 命令用于状态管理的原因（Table 3）；(c) RSRT 把 Task verifier 放进循环：finish 后 fail 则进入 Reflect + debug 续跑，pass 或超时才停——提供基于结果的重试机会，通过轨迹平均 2.20 次完成声明、4.5% 的通过轨迹经历过一次被拒的完成（Table 3）。三者的结构差异正是它们解出不同任务子集的机制解释（Table 1、Figure 5）。

教学简化示例（非论文实验）：把 Markdown 案例的机理放大——源轨迹在第 26 步还在 tree-sitter 生成/兼容性挣扎，runbook 把”用预编译 parser”写进提纲后，通过的重写第 9 步就用上了（§3.4，Figure 6）。但论文同时展示：同样照这份提纲，有的重写 32 步通过、有的 38 步仍失败——提纲压缩的是摸索期，不能替代解题本身。

区分自研组件与现成物：planner/critic/executor 角色设计、runbook 格式、三段式过滤流程、RSRT 改造是论文提出的；直接使用：Qwen-3.8-27B（基础模型）、Terminus 2（Harbor Framework 的通用 harness，作为目标 harness 与基线）、StateM（Qin et al., 2026，直接用作发现 harness）、RST 任务管线（Li et al., 2026a，用于任务池与 TBH）。

4. 解决得怎么样？

4.1 实验设置

  • 任务与数据集：训练池约 3K（SWR 自建约 2.5K 任务、50+ 领域 + 420 条 RST 改造任务，§3.1）；评测 TB2（89 题）、TB3（74 题）、TB4（66 题）、TBH（100 题）、SWR100（100 题），另有 LHTB（46 题）以 process reward 评测（§3.5）。TBH、LHTB 出自同组先前工作（Li et al., 2026a；2026c），SWR100 为自建（脚注 4）。
  • 基础模型：Qwen-3.8-27B，全流程（发现/重写/训练/推理）唯一模型。
  • 基线：Base（原模型）与 Direct SFT（同模型、源轨迹直训，去 harness 专用插入语）。更强基线（RL、更强模型、其它经验蒸馏方法如 Harness-Zero）论文未比较。
  • 指标：pass@3 与 3 次运行的 mean per-run pass rate（前五基准）；process reward（LHTB）。括号内的通过数是论文按百分比与题量四舍五入的估计值（§3.6）。
  • 重写配置：K=4、M=4、temperature 0.7（§3.4）；RSRT 发现预算 180 分钟/任务（§3.2）。
  • 预算公平性：两训练组共用同一基座与同一任务池；RSR 的有效训练数据约为 Direct SFT 的 5.9 倍（11,094+766 vs 2,001），这是方法设计使然，但缺少”数据量放大但形式不变”的对照（见 §5 质疑一）。发现阶段 equal-rollout 子集控制了 rollout 数量，但未控制时间预算。
  • 各实验回答什么：Table 1/2 + §3.3 回答”多 harness 是否扩大可解集”（含 equal-rollout 与失败轨迹统计）；§3.4/§3.4.1/Table 4 回答”重写能否保留行为、runbook 指导是否影响执行结构”（2 个案例）；§3.5–3.6/Table 5 回答”训练是否有效”；§3.7/Table 6 回答”仅换 harness 对未训练模型的影响”（每格只跑 1 次）。

4.2 关键结果

  • 多 harness 覆盖（task coverage，约 3K 任务池）：三 harness 并集解 759 个任务（25.9%），比最强单 harness（Terminus 2 的 565 个）多 194 个（相对 +34.3%）；equal-rollout 子集（1,247 任务、每 harness 2,074 条 rollout）union 352（28.2%）vs RSRT 285（22.9%），+67（+23.5%）——互补性不是 rollout 数不均造成的（Table 1、Table 2、§3.3）。
  • 主结果 pass@3（Table 5；顺序为 Base / Direct SFT / RSR）：TB2 57.0% / 53.4% / 74.2%；TB3 0.0% / 5.4% / 9.5%；TB4 1.5% / 4.5% / 9.1%；TBH 39.0% / 56.0% / 63.0%；SWR100 3.0% / 3.0% / 6.0%。RSR 相对 Direct SFT 分别 +20.8 / +4.1 / +4.6 / +7.0 / +3.0 个百分点（§3.6）。
  • 提升小或无提升的情况：Direct SFT 在 SWR100 与 Base 持平（均 3.0%），且 pass@3 与 mean 在 TB2 均低于 Base（-3.6 pp / -7.9 pp）；作者归因于过长轨迹与死循环行为，但依据仅是对 direct-SFT checkpoint 的 3 条轨迹的抽查（§3.6）——审稿人判断：该归因为观察性推测。
  • LHTB：process reward 0.21 → 0.25 → 0.29（Base/Direct SFT/RSR），但三组均 0/46 完成任务，提升只反映部分进展（Table 5、§3.6）。
  • 案例（§3.4、Figure 6）：Markdown inline parsing，12 条重写 7 条通过（58.3%），通过的中位长度 32 步、源 64 步（-50.0%）；OpenFOAM PitzDaily，8 条 7 条通过（87.5%），中位 29 步、源 38 步。同一 runbook 下不同重写可一过一败；作者明确写道更短更干净的执行并不保证成功。
  • runbook 指导的结构性效应（Table 4，0–100 分）：同 runbook 对 vs 不同 runbook 对——Markdown exact command overlap 19.1 vs 12.1、命令顺序 24.6 vs 15.7；OpenFOAM 12.6 vs 10.4、18.2 vs 14.7；但 OpenFOAM 的 tool-transition 重叠几乎无差（28.4 vs 28.5）、action-sequence 同 runbook 反而略低（61.0 vs 63.1）——工作流层面的相似度更依赖任务。
  • harness 消融（Table 6，未训练 base 模型，每格 1 次运行）：TBH 上 Terminus 2 33.0% → RSRT 66.0%、StateM 46.0%、三 harness 并集 70.0%；但 TB3 上所有 harness 都 ≤4.3%。
  • 执行风格差异（Table 3）：StateM 通过轨迹中位 24 步、29.6% 命令用于状态管理；RSRT 平均每条轨迹 2.20 次完成声明；失败轨迹样本（每 harness 固定 200 条）中 RSRT 平均 67.1 步 vs Terminus 2 22.8 与 StateM 23.4。
  • 统计稳定性：只有 3-run mean，无置信区间/方差/显著性检验；TB3/TB4/SWR100 的组间差只有约 3 个任务（如 TB4 3/66→6/66），属小样本。

Figure 4 是覆盖结论的主证据：(a) 柱状图分别给出 RST（n=420）、SWR（n=2509）与合并集（n=2929）上每个 harness 单独与 Union 的任务解决率，Union 三列（30.7% / 25.1% / 25.9%）都高于任何单 harness；(b) 是 pooled 集上的 solve 区域分解——308 个任务三个 harness 都解、129 个只有 Terminus 2、91 个只有 RSRT、68 个只有 StateM，其余两两重叠区域 78/50/35，底部标注 “Union: 759 | best single: 565 | additional tasks: 194”。这张图为什么必要：它把”互补性”从叙述变成可核算的数字（288 个任务仅被单一 harness 解出，占 759 的 38%），也提示并集之外的 2,170 个任务三 harness 都未解。

Figure 5 把互补性拆到领域层：行为 RST/SWR 细分领域（括号内为题量），列为 Terminus 2 / RSRT / StateM / Union，单元格为至少一次通过的覆盖率，红点标记每行最强单 harness，右侧标注各 harness 独占解出的任务数（T/R/S）。图中可见 RSRT 领先 RST scripting & automation（35.7%）与 SWR media & signal（13.1%），StateM 领先 RST software dev. & debugging（26.2%），Terminus 2 领先 version control（33.3%）；Union 把 media & signal 提到 22.3%、earth & geospatial 提到 19.8%（单 harness 最好 13.1% / 12.2%）。为什么需要它：Figure 4 只证明”总量互补”，Figure 5 证明这种互补是领域结构性的——所以”发现哪些经验”取决于用哪些 harness，而不是简单多数投票。

Figure 6 用两个案例（Case 1 Markdown inline parsing，源自 RSRT；Case 2 OpenFOAM PitzDaily 输出重建，源自 StateM）各对比三条轨迹：Source、Pass、Fail（同一 runbook 引导）。表头给出成功率与长度变化（7/12、64→32 步；7/8、38→29 步），格内是代表性命令摘录——Source 列可见源 harness 专有命令（如 statem goto implement）与反复的摸索（tree-sitter 生成/兼容性调试），Pass 列显示重写直接沿用提纲中的关键步骤（如 tree-sitter parse --lang-name markdown），Fail 列显示在通用 harness 下出现的环境/代码错误（xxd: command not found、NameError）。为什么需要它（以及它的局限）：它直观展示”重写保留了解题结构、剥离了 harness 专属命令”，但也暴露同一提纲下成败仍随机分布，且题注明确说明”显示的错误并不构成最终失败原因、verifier 通过也不代表质量审计通过”——这张图支持的是”流程直觉”，不是”机制已证明”。

4.3 机制证据

“有效”层面：证据链较完整——多 harness 覆盖与互补（Table 1/2、Figure 4/5，含 equal-rollout 控制）、换 harness 对同一模型的直接影响（Table 6）、训练收益（Table 5）、以及直接训练导致退化的负面对照（Direct SFT 在 TB2 掉 3.6 pp）。
“为什么有效”层面：论文给的是流程合理化 + 弱证据，存在以下缺口：

  • 组件级因果缺失：没有移除 critic、泄漏审计、fresh sandbox 重解，或改变 K/M 的消融；RSR 与 Direct SFT 的对比同时改变了数据量（约 5.9×）、数据形态（重写/标准化 vs 原样）与来源筛选（拒绝采样），无法把这些因素分开。因此”重写机制本身至关重要”并未被实验隔离。
  • 案例研究（2 个任务）支持”runbook 能传递有效流程、缩短摸索期”，但同 runbook 下一过一败（Markdown 58.3% 通过），作者自己也写明”更短更干净不保证成功”。
  • Table 4 的相似度分析是相关性证据：同 runbook 轨迹在命令级更像，但这是”指导意见影响了执行结构”，不等于”结构相似带来了更高成功率”（该表同时包含通过和失败轨迹，未做通过率的因果对比）。
  • 替代解释未被排除：例如提升可能主要来自训练数据量（Direct SFT 只有 2,001 条 vs RSR 11,860 条）与过滤掉低质量轨迹（拒绝采样天然筛掉了难吸收的长轨迹）；论文没有设”把 2,001 条源轨迹重复采样到 11K 再直接 SFT”这类对照。

4.4 成本与适用范围

论文报告的代价：RSRT 发现阶段 wall-clock 预算 180 分钟/任务（§3.2）；流程规模可观——发现阶段 14,598 条 rollout + 重写阶段 12,893 条 rollout，全部由 27B 模型推理完成（§3.3、§3.4）。论文未报告的内容：训练成本（GPU 时数/费用）、推理时延、token 消耗、数据存储与管线系统开销、人工标注量（从描述看无人工标注，但未明说）、失败重写（约 14%）与失败发现轨迹的处置统计、各发现 harness 的 wall-clock 与 token 预算（仅 RSRT 报告 180 分钟）。外部依赖：全流程使用单一模型 Qwen-3.8-27B 完成（论文未报告使用闭源 API、外部服务或人工评分）；评测侧 TBH/LHTB/SWR100 为自建或同组基准。
改善了什么：在通用 harness 单独运行条件下提升了 terminal 任务 pass@3（TB2/TBH 幅度大，TB3/TB4/SWR100 幅度小）与 LHTB 的部分进展。未解决：跨模型（仅 27B）、跨领域（仅 terminal）、跨 harness 组合（仅这 3 个）的泛化均无验证；重写各组件的独立贡献、数据量放大 vs 重写的归因未分离；成本不可评估。结论的适用边界：方法在”论文的 Qwen-3.8-27B + 3 个 harness + 5 个 terminal 基准”这一范围内被验证，不能外推为普遍提升了 agent 能力。

5. 最容易受到审稿人质疑的地方

质疑：重写收益与数据量放大混杂，缺少隔离关键组件的消融

  • 原文依据：RSR 训练集 = 11,094 条重写轨迹 + 766 条 Terminus 2 直通（§3.5） vs Direct SFT = 2,001 条源轨迹；两组差异不仅是”重写”，还包含约 5.9× 的数据量、拒绝采样筛选与来源构成变化。论文 §3.6 “Rewriting improves experience scaling” 没有”同倍放大的原始轨迹”对照，也没有移除 critic/泄漏审计/fresh-sandbox 重解或改变 K、M 的消融。
  • 为什么重要：直接影响对方法核心贡献的归因——若单纯增大数据量即可接近 RSR 的效果，这条重写管线（及其数万条 27B rollout 的成本）的必要性就被高估；review 的问题定义（分布错配）也未被独立验证。
  • 当前能够得出的判断：现有证据支持”多 harness 数据 + 重写流程整体有效”这一弱结论；”重写机制不可替代”在当前材料中无法确认——这是证据不足，尚不能判断作者结论错误。
  • 如何验证或补强：增设”源轨迹重复/扩充采样到同等规模后 Direct SFT”的对照；逐组件消融（去掉 critic 或泄漏审计、跳过重解直接把 runbook 注入上下文、改变 K/M 与温度）；报告各变体的通过率与下游表现。
  • 严重程度：主要问题

质疑：训练任务池与自建评测基准（TBH、SWR100、LHTB）同源，污染风险未报告

  • 原文依据：训练池含 420 条来自 RST（Li et al., 2026a）的改造任务（§3.1）；TBH 与 LHTB 均出自同一作者组（§3.5 参考文献、Table 5 标注 “ours”），SWR100 为自建（脚注 4）。论文未报告任何训练任务与评测任务之间的去重或污染检查。
  • 为什么重要：论文的最大增量之一出现在自建 TBH（39.0% → 63.0%，相对 Base），若训练任务与 TBH/LHTB 存在重叠或同分布泄漏，该结论的有效性被直接削弱；这属于实验公平性问题。
  • 当前能够得出的判断：当前材料无法确认是否存在重叠；公共基准 TB2 上的提升（57.0% → 74.2%）是较强的独立证据，但它无法覆盖自建基准的疑问，且 TB2 是否与训练池去重也未说明。
  • 如何验证或补强：公开训练任务清单/哈希并与评测集做任务级去重；报告严格不相交切分上的复验结果；说明 TB2/TB3/TB4 与训练池的去重流程。
  • 严重程度：主要问题

质疑：核心数据账目自相矛盾，影响结论可信度

  • 原文依据：§3.4 称 RSR 共产生 “12,893 rollouts… covering 975 unique tasks”——但重写只针对源成功轨迹（覆盖 759 个任务，且实际重写来源 StateM ∪ RSRT 只覆盖 630 个任务），重写覆盖的任务数不可能超过 759；此外摘要称 “expanding the training set from 2,001 to 11,094 high-quality trajectories”，而 §3.5 明确 RSR 训练集是 11,094 条重写 + 766 条 Terminus 2 直通（合 11,860 条）——两处口径无法同时成立。经 PDF 交叉核对，两处不一致在 HTML 与 PDF 文本中均如此，非渲染问题。
  • 为什么重要：”经验规模放大”是本文核心卖点，账目对不上会让读者无法判断训练数据的真实构成与规模，也会动摇对其它数字的信任；这属于可复现性与严谨性问题。
  • 当前能够得出的判断：可以确认这是论文内部的数字不一致；无法判断 975 是笔误、口径不同（如把源任务与重写任务混计）还是统计错误。
  • 如何验证或补强：作者澄清 “975 unique tasks” 的计数口径与 12,893 条重写对应的任务集合；澄清 RSR 训练数据的确切构成（是否含 766 条、两类数据配比）并保持全文一致。
  • 严重程度：主要问题

质疑：小样本基准上的差异缺少统计稳定性证据

  • 原文依据：TB4 相对 Direct SFT 只多 3 题（3/66 → 6/66）、SWR100 多 3 题（3/100 → 6/100）、TB3 多 3 题（4/74 → 7/74）；所有结果仅报告 3 次运行的均值，无方差、置信区间或显著性检验（Table 5）。LHTB process reward 0.25 → 0.29 同样无方差报告，且全部组 0/46 完成。Table 6 每格仅 1 次运行；其题注称括号内为 “task counts”，但实际内容是通过题数（如 51.7% ↔ 46/89 吻合），且 union 行 TB3 的 4.3% 与 3/74 ≈ 4.1% 无法对应。
  • 为什么重要：这些基准上的”RSR 更优”结论可能被个别任务的翻转抹平；process reward 的小幅提升可能处于噪声范围内。指标口径（Table 6 题注）不一致会加剧复现困难。
  • 当前能够得出的判断：TB2（+20.8 pp over Direct SFT）与 TBH（+7.0 pp）的幅度足以支撑定性结论；TB3/TB4/SWR100 与 LHTB 的提升”统计稳定性不足”，当前证据薄弱。
  • 如何验证或补强：报告方差/置信区间与更多运行次数；按任务配对（哪些任务发生翻转）；发布每次运行的原始结果；修正 Table 6 题注与百分比口径。
  • 严重程度：次要问题

质疑：成本、预算与训练细节披露不足，可复现性受限

  • 原文依据：训练超参数（学习率、epoch、全参还是 LoRA、数据配比）、算力成本、推理时延与 token 量均未报告；三个发现 harness 的 wall-clock 预算只对 RSRT 报告了 180 分钟/任务，Terminus 2 与 StateM 未报告（§3.2）；equal-rollout 分析只控制了 rollout 数量、未控制时间预算。RSRT 的 verifier 触发续跑机制天然获得更多”重试”机会（其 rollout 成功率 15.9% 高于 Terminus 2 的 14.2%，但总 rollout 更少，§3.3 脚注 2 仅解释为沙盒错误更多）。
  • 为什么重要：影响实验公平性与方法的成本可行性评估——无法判断互补覆盖结论中有多少来自 harness 逻辑、多少来自预算/重试机制差异；也无法估计复现这套管线需要多少算力。
  • 当前能够得出的判断：论文对 equal-rollout 的控制显示了方法自觉，部分缓解了公平性质疑；但预算与成本维度确实是披露缺口，当前材料无法验证方法性价比。
  • 如何验证或补强：报告逐 harness 的 wall-clock/token 预算与成本；在匹配时间预算下重跑覆盖与互补性分析；公开训练脚本、超参数与数据样例。
  • 严重程度：次要问题

6. 审稿式总评

作者发现同一个模型在不同 harness 下能解出互补的 terminal 任务子集（三 harness 并集比最强单 harness 多 34.3% 任务，equal-rollout 子集上互补性仍成立），但直接混合这些轨迹做 SFT 会引入 harness 专有的分布错配（Direct SFT 在 TB2 上反降 3.6 个百分点），因此提出 Recursive Self-Rewrite：用同一 Qwen-3.8-27B 以 planner–critic–executor 三角色把成功经验重写为通用 harness 下全新沙盒重解的验证轨迹，经泄漏审计与拒绝采样把 2,001 条成功放大为 11,094 条训练轨迹。实验在 5 个 terminal 基准与 LHTB 上表明 RSR 全面优于 Base 与 Direct SFT（TB2 pass@3 57.0%→74.2%，TBH 39.0%→63.0%，LHTB process reward 0.21→0.29 但均未完整解出任何任务）；其中多 harness 互补覆盖与 TB2/TBH 上的提升证据较强，但”重写相对数据量放大的独立贡献””自建基准的同源污染可能””数字口径的内部不一致”仍缺少充分支持。本文最有价值的部分是把 harness 从推理时的控制器重新定位为训练经验的发现器，并给出一条可操作的”重写—审计—重解”数据管线；最大的审稿风险是核心贡献的归因（重写 vs 数据量放大）没有消融隔离，且论文内部存在对不上的数据账目。

  • 问题定义清晰度：强——harness 迁移导致的分布错配被具体化为可做实验的问题（§1、§2），有 Direct SFT 负面对照支撑问题真实性。
  • 创新性证据：中——“多 harness 发现 + 自重写 + 泄漏审计 + 重解”相对 Harness-Zero、Reflexion、DCAS 等的定位清楚（§4），但属组合式创新，缺少组件消融与更完整检索来支撑”首次”级的主张。
  • 方法可信度：中——流程与过滤规则描述具体（K/M、温度、leakage 检查、私有引导不写进训练数据），但关键组件无隔离实验，且两处数据账目（975 vs 759；11,094 vs +766）自相矛盾。
  • 实验支持力度：中——TB2/TBH 的提升与 equal-rollout 控制较扎实，负面对照（Direct SFT 退化）加分；小样本基准缺方差、自建基准无污染说明、Table 6 仅单次运行。
  • 可复现性：弱——训练超参数、算力成本、各 harness 预算、失败轨迹统计均未报告，训练任务池未明确公开；仅 HF 模型页可达（论文未报告的信息偏多，复现关键路径不完整）。
  • 综合阅读价值：中——“多 harness 当数据源 + 三役重写”的管线思路对 agent 训练有可迁移价值，且论文坦陈述了 Direct SFT 的退化与案例中的失败重写；但结果数字需要带着第一节的保留读——尤其自建基准与数据量混淆问题。
