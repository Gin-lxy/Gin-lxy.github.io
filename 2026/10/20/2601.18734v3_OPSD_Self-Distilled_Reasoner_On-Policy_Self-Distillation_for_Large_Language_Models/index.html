0. 一句话结论

这篇论文要把“学生在自己采样的轨迹上接受教师逐 token 监督”的同策略蒸馏（on-policy distillation），改造成同一个大语言模型（LLM）在两种上下文下的自蒸馏（self-distillation）：教师看到含思维链的参考解，学生只看到题目，学生在自己的 rollout（采样轨迹）上逐 token 匹配教师的下一 token 分布。作者在 Qwen3-1.7B/4B/8B 和三个数学竞赛基准上报告了优于 SFT、总体匹配或略优于 GRPO 的结果；但证据只覆盖数学、LoRA 微调和不超过 8B 的模型，且 token 效率（token efficiency）的统计口径与训练/评测设置存在需要澄清的问题。

1. 论文具体想解决什么问题？

研究背景与任务。 论文关注大语言模型在数学推理任务上的后训练（post-training）。给定题目 xxx 与带思维链（chain-of-thought, CoT）的参考解 y⋆y^\stary⋆，目标是提升模型在竞赛级数学题上的准确率。现有三条路线各有代价：监督微调（SFT）直接在专家轨迹上做离线模仿，存在暴露偏差（exposure bias）与分布不匹配；带可验证奖励的强化学习（RLVR，典型算法为 Group Relative Policy Optimization，GRPO）在策略自己采样的回答上优化，但奖励是序列级二值信号，且每个问题要采样一组回答；知识蒸馏（knowledge distillation）能提供稠密的 token 级监督，但传统做法是离策略（off-policy）的，而同策略蒸馏又通常需要一个独立、往往更大的教师模型（§1、§2）。

现有方法在哪些条件下表现不好。 论文给出了两类具体失效条件。第一类是数据风格条件：在 OpenThoughts 数学子集上训练 SFT 时，参考解普遍较短，SFT 会把这种“简洁推理”风格学进去，导致测试时生成长度下降，因而在三个模型规模上平均分都不如基座（Qwen3-1.7B 从 37.1 降到 35.8，4B 从 61.2 降到 58.6，8B 从 61.8 降到 59.8；Table 2，作者归因见 §4.2）。第二类是奖励多样性条件：在同一个数据集上，GRPO 的组内奖励经常全部相同，组内奖励标准差为零，梯度消失；论文 Fig. 3 中的零奖励标准差子图与题注称，在 100 步内超过一半的 batch 出现零奖励标准差。这两点都是论文报告的现象，但“原因就是数据太简洁/太简单”仍主要是作者的解释。

论文发现的新现象。 除了上述训练信号问题，论文还报告了一个关于 token 类别的经验观察：教师与学生分布之间的逐 token Kullback–Leibler（KL）散度在词表条目上高度偏斜，风格类 token（如 “wait”“think”“therefore”）的 KL 可以显著高于数学类 token；在作者最终采用的 TM-off 学生 / TM-on 教师配置下，Table 5 给出的风格/数学 KL 比约为 6–13 倍（Qwen3-1.7B 为 0.85 对 0.14，4B 为 0.92 对 0.10，8B 为 0.79 对 0.06）。这个观察直接催生了逐点 KL 裁剪（pointwise KL clipping）的设计。

被忽略的问题与研究假设。 作者认为，同策略蒸馏的核心限制是“必须有外部教师”，而推理数据集本身已经带有可用的参考解；如果模型足够强，看到参考解后“合理化/讲解”（rationalization）应当比从零生成更容易——论文引用“评估可能比生成更容易”的已有观点（Sun et al., 2024；Naor, 1996）作为类比。由此提出核心假设：同一个模型在“题目 + 参考解”的条件下可以充当教师，在“仅题目”的条件下作为学生，学生只在自己的 rollout 上学习，就能同时获得同策略数据、稠密 token 监督和真实答案信号，而不需要外部教师或奖励模型（reward model）（§1、§3.2）。

边界。 需要区分三类内容：暴露偏差、RL 奖励稀疏、教师模型成本是领域早已知道的一般问题；本文新增的是“把参考解当作特权信息（privileged information）、让同一模型自蒸馏”的具体算法，以及在 OpenThoughts/GRPO 设置下观察到的零奖励方差与风格 token KL 偏斜；本文实际解决的是“在数学竞赛题、Qwen3 指令模型、LoRA 训练”这一具体子问题。论文没有证明该机制在代码、科学推理、多轮任务或更大模型上同样成立；Appendix A 明确承认实验只做到 8B，且当题目超出模型理解能力时教师也无法提供有意义的监督。

2. 创新点是什么？

真正的技术增量不是提出了新的基础模型或新数据，而是把三个已有组件——上下文条件化的“教师”、学生自己的 on-policy rollout、逐 token 分布匹配——组合成一个不需要外部教师的自蒸馏流程，并补上一个稳定训练用的裁剪技巧。根据本文的 related work，最接近的工作是上下文蒸馏（context distillation）、GKD 式的同策略蒸馏，以及并发的 SDPO/SDFT；因此只能确认作者声称的差异，是否“首次提出”需要更完整的独立文献检索。

  1. 单模型双角色的 OPSD 框架。 同一个 LLM 用两套提示分别实例化学生策略 pS(⋅∣x)p_S(\cdot\mid x)pS​(⋅∣x) 与教师策略 pT(⋅∣x,y⋆)p_T(\cdot\mid x,y^\star)pT​(⋅∣x,y⋆)；教师看到完整的参考解（含 CoT），学生只看到题目，学生采样自己的轨迹，教师在该轨迹的每个前缀上给出下一 token 分布。与上下文蒸馏的区别是：后者让教师先“生成”一段回答，再对学生做 SFT，属于离线硬蒸馏；与常规同策略蒸馏的区别是：后者需要另一个教师模型。该设计对应 §1 的“外部教师依赖”问题，主要证据在 §4.2 的主结果与 §4.3 的机制证据。

  2. 在学生 rollout 上做全词表（full-vocabulary）前向 KL 匹配。 论文没有停在“对采样到的 token 算一个反 KL 优势”，而是对每个位置在整个词表上计算 D(pT∥pS)D(p_T\|p_S)D(pT​∥pS​)，并选择前向 KL（forward KL）；教师固定为初始策略，梯度只回传学生。与 Thinking Machines Lab 的同策略蒸馏（Lu and Lab, 2025）式“采样 token + 策略梯度”做法相比，这提供了更完整的分布监督；对应的消融是 Table 4。该设计对应“奖励稀疏、只有序列级反馈”的问题。

  3. 逐点 KL 裁剪。 对每个位置、每个词表条目 vvv 的散度贡献设上限 τ\tauτ，再求和，以避免少数风格 token 的高 KL 主导训练信号。它对应 Table 5 报告的 KL 偏斜现象，证据是论文 Fig. 4 的“有无裁剪”对比；这是三个创新中最偏工程稳定性的一个，也是论文正文披露最少的一个（τ\tauτ 的取值未在正文给出）。

3. 作者如何解决？

核心直觉可以这样理解：学生先独立做一遍题，教师不直接给答案，而是拿着标准解“看懂”学生的每一步，并在每个位置告诉学生“如果知道正确答案，这里更可能该写什么”。由于教师和学生共享同一组参数、只差上下文，教师不需要比学生更强的推理能力，只需要具备“看着答案解释思路”的能力；学生的任务也不是复述标准解，而是把自己的生成分布拉向这个“带答案的教师分布”。这样既保留了学生自己的状态分布（on-policy），又获得了每个 token 位置的稠密监督，而且不依赖外部教师或奖励模型。

3.1 输入：题目、参考解与两套提示

训练数据是问题—参考解对 S={(xi,yi⋆)}i=1N\mathcal{S}=\{(x_i,y_i^\star)\}_{i=1}^{N}S={(xi​,yi⋆​)}i=1N​，其中 xix_ixi​ 是题目，yi⋆y_i^\staryi⋆​ 是参考解，可以包含完整的思维链。论文使用 OpenThoughts 的数学推理子集，最多取 30K 对带 CoT 的样本（§4.1）。同一个样本会被改写为两套提示：学生提示只有题目和一个“Answer:”槽位；教师提示在题目后插入“Here is a reference solution: …”，再要求“After understanding the reference solution, please try to solve this problem using your own approach below:”，最后同样以“Answer:”结尾（论文 Fig. 2）。图 1 展示了这套双提示如何接入同一个模型并形成训练闭环。

图 1（论文 Fig. 1）：OPSD 把同一个 LLM 实例化为共享参数 θ\thetaθ 的两个条件策略。数据集中的 (x,y⋆)(x,y^\star)(x,y⋆) 先被改写成学生提示与教师提示；学生策略从自己的分布采样一条轨迹 y^\hat yy^​，教师策略在同一个轨迹前缀上给出下一 token 分布；两者逐位置比较后，梯度只沿学生的 logits 回传。关键在于教师不生成新轨迹，而是对学生已经走过的前缀做“带答案的再评估”，因此监督既落在学生自己的状态分布上，又是逐 token 稠密的。

两套提示在内容上的差别是 OPSD 的关键输入设计，图 2 给出了学生与教师提示的具体形式：学生端只有题目和待填的答案槽位，教师端在题目后插入参考解，再用一句指令把上下文引向“理解之后自己求解”。

图 2（论文 Fig. 2）：学生提示只包含题目和待填的 “Answer:” 槽位；教师提示在题目后加入参考解，并要求模型在理解参考解后用自己的方法继续求解。这段指令的作用不是让教师输出一段新解答，而是把教师的上下文从“阅读参考解”自然过渡到“评估学生接下来的 token”，使教师对同一学生前缀的下一 token 分布携带答案信息。教师端只做一次前向计算，不产生额外的生成 token；论文特别说明，所谓“合理化”是在这一次前向中隐式完成的（§3.2、论文 Fig. 2 题注）。

这里有一个容易误解的点：教师并不是把参考解逐字复制给学生，也不是在学生轨迹后面拼接标准答案。教师看到的是“题目 + 参考解 + 要求自己求解的指令”，然后被要求在学生的前缀之后继续预测；因此它的分布是“在已经知道正确答案的前提下，对学生当前前缀的下一 token 应该是什么”的判断。学生看到的则只有题目，分布必须从零开始生成。两者共享参数但条件信息不同，这正是 OPSD 与“两个不同模型”的同策略蒸馏的本质区别。

3.2 一次训练迭代的数据流

一次迭代从 mini-batch B⊂S\mathcal{B}\subset\mathcal{S}B⊂S 开始（有效 batch 为 32，Table 6）。对每个样本 (x,y⋆)(x,y^\star)(x,y⋆)，学生先以当前策略采样一条 on-policy 回答 y^=(y^1,…,y^∣y^∣)∼pS(⋅∣x)\hat y=(\hat y_1,\ldots,\hat y_{|\hat y|})\sim p_S(\cdot\mid x)y^​=(y^​1​,…,y^​∣y^​∣​)∼pS​(⋅∣x)，训练时最大生成长度为 1024 个 token（Table 6）。随后，教师和学生分别对同一条学生轨迹打分：在第 nnn 个位置，学生分布是 pS(⋅∣x,y^<n)p_S(\cdot\mid x,\hat y_{<n})pS​(⋅∣x,y^​<n​)，教师分布是 pT(⋅∣x,y⋆,y^<n)p_T(\cdot\mid x,y^\star,\hat y_{<n})pT​(⋅∣x,y⋆,y^​<n​)。教师端的输入是“教师提示 + 学生已生成的前缀”，学生端的输入是“学生提示 + 同一前缀”；两者在每个位置都输出整个词表上的下一 token 分布。

这一步由谁执行、哪些部分是固定的，值得说清楚。采样由学生策略执行；两套分布的计算由同一个模型的两组前向执行；提示模板、数据采样、裁剪规则和教师快照都由固定流程控制；只有学生侧的 LoRA 权重在训练中更新。教师不生成 tokens，也不把自己的分布采样成一条新轨迹；它只提供每个位置的软目标。这一点与 STaR/ReST 式的“先生成、再筛选、再 SFT”不同：OPSD 不需要等学生生成完整答案再判断对错，也不要求最终答案正确才有学习信号（§3.2、Appendix D）。

由于学生只在自己的前缀上被评估，训练分布与部署时学生看到的状态分布一致；由于每个位置都有教师分布，监督信号从“整条回答一个二值奖励”变成“每个位置一个词表上的软目标”。论文把这两点分别称为 on-policy 与 dense，并把它们与“无外部教师”一起列为 OPSD 相对 SFT、GRPO 和常规同策略蒸馏的组合优势（Table 1）。

3.4 训练配置与推理阶段的变化

训练使用 LoRA（低秩适配，low-rank adaptation）：rank 64、alpha 128，作用在 q/k/v/o 与 gate/up/down 投影上；优化器为 AdamW，学习率 5×10−65\times10^{-6}5×10−6，有效 batch 32，bfloat16，8 张 A100 或 H100，配合梯度检查点和 Flash Attention 2（Table 6、Appendix B）。OPSD 训练 100 步，每步每个问题只采样 1 条最长 1024-token 的回答；GRPO 基线训练 500 步，每步每个问题采样 8 条最长 16k 的回答（Table 6）。学生训练时使用 Thinking Mode off（TM-off，思考模式关闭）的提示格式，教师使用 Thinking Mode on（TM-on，思考模式开启）；这是作者通过 Table 5 的 KL 分析和早期下游实验选出的组合（§4.3.2、Appendix B）。

推理阶段只保留学生：不再需要参考解、教师提示或第二次前向，直接把训练后的 LoRA 合并/加载到 Qwen3 指令模型上，用正常的 thinking mode 评测。评测参数为 temperature 1.0、max new tokens 38,912、top-p 0.95、每个问题采样 12 次，报告 Avg@12（12 次采样的平均准确率；Table 8）。也就是说，OPSD 的额外成本集中在训练期的教师前向与全词表 logits 存储，推理期没有额外的教师调用；这与需要外部大教师的方法在部署成本上有本质区别。

不过，训练期与评测期的生成模式并不一致：学生在训练时以 TM-off 格式生成最长 1024-token 的短回答，评测时却开启 thinking mode、允许 38,912 个新 token（Table 8）。论文没有解释这一安排，也没有报告“训练时也用 TM-on 学生”的对照。这一点直接关系到“学生训练分布与推理分布一致”的 on-policy 论证，后文 §5 会把它作为主要质疑之一。

4. 解决得怎么样？

4.1 实验设置

任务、数据与模型。 训练数据为 OpenThoughts 数学推理子集，最多 30K 个带 CoT 的问题—参考解对；评测使用 AIME 2024、AIME 2025、HMMT 2025 三个竞赛级数学基准。模型为 Qwen3 指令版的 1.7B、4B、8B 三个规模（§4.1）。所有方法使用同一份训练数据和同一套 LoRA 配置（Table 6、Table 7）。

基线。 两个基线都与 OPSD 在同一数据上训练：SFT 在专家轨迹上做标准监督微调，可以视为对生成这些轨迹的更强模型的离策略蒸馏；GRPO 使用二值结果奖励，最大生成长度 16k，每个问题 8 条 rollout，训练 500 步（§4.1、Table 6）。OPSD 每个问题 1 条 rollout、最长 1024 token、训练 100 步。三者都只训练 LoRA，不更新全参数。

指标与预算。 主表使用 Avg@12（temperature 1.0、thinking mode、max new tokens 38,912；Table 8），Table 4 的消融使用 pass@8（8 次采样中至少一次正确的比例），两者不可直接比较。SFT 与 OPSD 都训练 100 步，且 SFT 使用与 OPSD 相同数量的训练样本；GRPO 训练 500 步，并在 500 步内取峰值。OPSD 每 20 步评测一次，取 100 步内的最佳 checkpoint；GRPO 取 500 步内的峰值（Table 2 题注）。

各实验回答什么。 主实验（Table 2）回答“OPSD 相对 SFT/GRPO 的准确率如何”；论文 Fig. 3 回答“在相同训练步数下，OPSD 与 GRPO 的准确率—生成 token 关系如何”；§4.3 的消融分别回答散度选择（Table 3）、裁剪（论文 Fig. 4、Table 5）、生成长度（论文 Fig. 5）、全词表 vs 采样 token（Table 4）以及生成风格（Table 5）的问题。Appendix B 给出训练与评测超参数，Appendix D 给出 OPSD 与 STaR 的策略梯度解释。

4.2 关键结果

主结果。 Table 2 报告，OPSD 在三个规模上平均分都高于基座和 SFT，并且总体匹配或略高于 GRPO：

  • Qwen3-1.7B：基座 37.1 → OPSD 43.4（+6.3），GRPO 37.7（+0.6），SFT 35.8（−1.3）；
  • Qwen3-4B：基座 61.2 → OPSD 63.6（+2.4），GRPO 62.7（+1.5），SFT 58.6（−2.6）；
  • Qwen3-8B：基座 61.8 → OPSD 64.8（+3.0），GRPO 64.0（+2.2），SFT 59.8（−2.0）。

提升主要集中在 1.7B；4B 和 8B 相对 GRPO 的平均优势只有 0.9 和 0.8 个百分点。分任务看，8B 的 HMMT25 上 OPSD 为 45.8，低于 GRPO 的 46.7（基座 43.9）；4B 的 AIME25 上 OPSD 68.3 对 GRPO 68.1，基本持平；8B 的 AIME24 上 OPSD 77.8 对 GRPO 76.4，优势 1.4 个百分点。也就是说，“匹配或超过 GRPO”在平均值上成立，但不是每个任务都赢；作者没有报告标准差或置信区间，无法判断这些差距是否超出训练/解码噪声。

SFT 的负结果。 SFT 在三个规模、三个基准上几乎全面下降，唯一例外是 4B 的 HMMT25（43.4 对基座 42.2，略升 1.2 个百分点）；作者归因于 OpenThoughts 参考解较短，SFT 学到了“短推理”风格，测试时生成长度下降（§4.2、Table 2 题注）。这个解释与观察一致，但论文没有给出 SFT 前后生成长度的统计，也没有做“把参考解扩写后再 SFT”的对照，因此“简洁风格导致退化”仍是作者主张，而不是被隔离验证的因果结论。

token 效率。 图 3 在 Qwen3-1.7B 上比较 OPSD 与 GRPO：在相同训练步数下，OPSD 的 Avg@12 曲线持续上升，GRPO 基本停滞；论文 Fig. 3 还把平均准确率对“累计生成 token 数”作图，OPSD 在更少的生成 token 下达到更高准确率。题注报告，100 步内超过一半的 GRPO batch 组内奖励标准差为零，因而没有梯度信号。这里的“token”指学生实际生成的 token 数；教师前向、全词表 logits、训练墙钟时间和 FLOPs 都没有计入。v3 正文和摘要没有给出“4–8×”或“8–12×”的具体倍数；这两个数字分别出现在 v1 和 v2 的摘要中，v3 已删去，HF 页面仍保留 v1 自动摘要的“4–8×”说法（见 §5 的版本核对）。

图 3（论文 Fig. 3）：横轴是梯度更新步数或累计生成的 token 数，纵轴是 Avg@12 准确率；OPSD 的曲线在三个基准和平均值上都随步数上升，而 GRPO 在相同步数内基本走平。图中的零奖励标准差比例曲线解释了 GRPO 为何停滞：在 OpenThoughts 数据上，超过一半的 batch 组内奖励全部相同，优势为零，采样预算被浪费。图想传达的机制是：OPSD 的监督来自逐 token 的教师分布，不依赖组内奖励是否有差异，因此能在单条 rollout、最长 1024 token 的预算下继续获得梯度；但该图只比较采样 token，不包含教师前向与全词表 softmax 的开销。

与“效率”有关的边界。 论文的训练预算设置是：OPSD 100 步 × batch 32 × 1 条 × 最长 1024 token；GRPO 500 步 × batch 32 × 8 条 × 最长 16k token（Table 6）。按最大生成长度上限计，GRPO 的最大采样量约为 OPSD 的 500×8×16k/(100×1×1k)=640500\times8\times16\text{k}/(100\times1\times1\text{k})=640500×8×16k/(100×1×1k)=640 倍，实际生成长度未知。这个对比对 GRPO 在“步数”上更宽松，但在“每组 8 条”和“500 步”上也给了它更多机会；OPSD 则只取 100 步内的最佳 checkpoint。两边都取了峰值，不能据此判断收敛稳定性或统计显著性。

4.3 机制证据

4.3.1 散度目标：前向 KL 在报告的消融中优于反向 KL/JSD

Table 3 在 Qwen3-1.7B/AIME25 上比较三种散度，三者都使用相同的逐点裁剪：前向 KL 从 36.7 升到 step 50 的 43.9，step 100 回落到 41.1；反向 KL 为 37.5（step 50）、35.0（step 100），低于基座；JSD（β=0.5\beta=0.5β=0.5）为 36.9、39.0。这个结果支持“前向 KL 更适合把教师分布当作目标”的设计，但证据只在单一模型、单一基准、单次训练上，且 step 100 的前向 KL 已经比 step 50 低 2.8 个百分点，说明最佳 checkpoint 的选择会影响结论。作者没有解释为什么前向 KL 在 50 步后回落，也没有报告其他模型上的散度消融。

4.3.2 逐点裁剪：稳定训练，但机制与超参数披露不足

图 4 在 Qwen3-1.7B/AIME24 上比较有无裁剪：不裁剪时准确率在 step 25 见顶（约 52.6）后总体下滑，step 100 降到约 49.2；裁剪后从基座约 51.5 持续上升到约 57.1（均为按图读取的近似值）。这个对比直接支持“裁剪防止性能崩溃”的工程结论。Table 5 提供了动机：在最终采用的 TM-off 学生 / TM-on 教师配置下，1.7B 的风格/数学/其他三类 token 平均 KL 为 0.85/0.14/0.25，4B 为 0.92/0.10/0.29，8B 为 0.79/0.06/0.25；风格 token 的 KL 是数学 token 的约 6–13 倍，确实可能主导总和。

图 4（论文 Fig. 4）：两条曲线使用同一模型和同一训练流程，只差是否对每个词表条目的散度贡献做上限截断。不裁剪的曲线在前期略有上升后持续下滑，裁剪后的曲线在 100 步内保持上升并在末端明显高于起点。图想说明的机制是：当少数风格 token 的 KL 远高于数学 token 时，未裁剪的逐词表总和会被这些高贡献条目支配，学生被推向模仿教师的措辞而不是数学步骤；逐点截断限制了单个条目的影响力，使训练信号更多来自大量中低贡献的数学 token。

但这里有几处证据缺口。第一，论文正文没有给出 τ\tauτ 的取值，也没有做 τ\tauτ 的敏感性分析；Appendix B 明确说没有调优该参数，代码 README 的默认值是 0.05。第二，裁剪是“逐词表条目”而不是“逐 token 类别”，论文没有证明它真的把风格 token 的贡献压下去，只证明了端到端准确率更稳；Table 5 的类别 KL 是相关性证据，不是裁剪生效的直接测量。第三，裁剪后的目标不再是严格的散度，可能为负，论文没有讨论优化性质的变化。第四，Table 5 的 KL 是在 10 个问题上平均的，没有方差，也没有报告不同问题难度下的分布。

4.3.3 全词表 vs 采样 token：有提升，但对照不隔离变量

Table 4 在 Qwen3-4B、2048 生成长度上比较两种实现：全词表 logit 蒸馏（full-vocabulary logit distillation）在 AIME25/HMMT25 上 pass@8 为 84.1/60.0，采样 token 蒸馏（sampled-token distillation）为 82.1/57.3，前者高 2.0/2.7 个百分点。作者据此认为“暴露给完整教师分布比只对采样 token 做 on-policy shaping 更有信息量”（论文 §4.3.5）。这个结论方向合理，但对照并不干净：Table 4 题注没有逐项说明两个变体的散度方向与裁剪设置；按正文主配方，全词表版本使用前向 KL 加逐点裁剪，而采样 token 版本按 §3.2 是反向 KL 优势的策略梯度，代码 README 又说明该变体“目前没有实现裁剪”。因此，2 个百分点的差距至少混合了三个因素——全词表 vs 单 token、前向 KL vs 反向 KL、裁剪 vs 不裁剪；Table 3 已经显示反向 KL 在同一裁剪方案下明显更差，所以不能把差距单独归因于“全词表”。

4.3.4 生成长度与生成风格：负结果与未报告的对照

图 5 在 Qwen3-1.7B 上比较 1024 与 4096 的生成长度。4096 在 AIME24 的 step 50 达到约 58.6，高于 1024 的 52.8，但在 step 100 回落到 55.7，低于 1024 的 57.2；AIME25 上两者在 step 50 为 42.8 vs 43.9，step 100 为 41.6 vs 41.1，差距在噪声范围内。作者据此认为“更长的生成本身不带来一致提升”，并假设早期 token 是更关键的分支点、后期 token 在长前缀下对教师更可预测（§4.3.4）。这个假设与观察相容，但论文没有直接测量“早期/后期 token 的 KL 或梯度贡献”，也没有控制 4096 版本的最大生成长度（以及训练 token 预算上限）是 1024 版本的四倍这一事实；因此它是事后解释，不是被验证的机制。

图 5（论文 Fig. 5）：在同一模型上只改变学生 rollout 的最大长度，比较 1024 与 4096 两条训练曲线。更长的 rollout 让教师能在更多位置上给出反馈，但也把每个样本的采样成本提高约四倍，并让后期位置处于更长的学生前缀下。图中 4096 在部分基准的早期步数更高，但到 100 步并没有稳定优势；这说明“监督位置更多”不等于“学习信号更好”，与作者关于早期 token 更重要的假设一致，但尚未把该假设与长度带来的计算/分布变化分开。

生成风格方面，Table 5 比较了四种学生/教师 TM 组合的平均 KL：在三个模型上，TM-off 学生 + TM-on 教师的数学 token KL 都是最高的（0.14/0.10/0.06），作者据此选择该组合，并称它在早期下游实验中最好（§4.3.2）。但论文没有给出四种组合的下游准确率表格，也没有报告 TM-on 学生训练的完整结果；同时，该组合的风格与其他 token KL 也是最高的（0.85/0.25、0.92/0.29、0.79/0.25），这恰好是裁剪要处理的情形。更关键的是，训练用 TM-off 学生、评测却开启 thinking mode（Table 8），论文没有解释这种训练/评测模式不一致对 on-policy 论证的影响。

4.3.5 对 §2 三项创新的逐项核对

创新 1：单模型双角色、教师看参考解。 论文用 Table 2 的 SFT/GRPO 对比支持“OPSD 整体有效”，但没有做“教师只看题目、不看 y⋆y^\stary⋆”的对照，也没有与“外部教师 + 同策略蒸馏”在同一数据/预算下比较。因此，无法从现有实验单独分离“特权信息 y⋆y^\stary⋆”的贡献：OPSD 相对 SFT 的优势可能来自 on-policy rollout，相对 GRPO 的优势可能来自稠密分布监督，而“同一模型做教师”本身的必要性没有被直接检验。作者在 §4.2 把效率归因于稠密 token 监督，这是作者主张；机制证据只到“整体方法有效”这一层。

创新 2：全词表前向 KL 匹配。 Table 3 支持前向 KL 优于反向 KL/JSD；Table 4 支持全词表版本优于采样 token 版本，但如 §4.3.3 所述，Table 4 混合了散度方向与裁剪两个变量。论文没有做“全词表前向 KL、无裁剪”与“采样 token 前向 KL、无裁剪”的 2×2 对照，也没有报告全词表带来的显存/吞吐代价的具体数字（论文 §4.3.5 只说“peak memory 更高”）。因此，全词表监督的独立增益是“有支持但不够干净”。

创新 3：逐点 KL 裁剪。 论文 Fig. 4 是最直接的证据：去掉裁剪后性能在 100 步内崩溃，保留裁剪则持续上升。这个消融只在一个模型（1.7B）、一个基准（AIME24）上报告；没有 τ\tauτ 扫描、没有多 seed、没有对风格/数学 token 贡献的直接测量。它可以支持“裁剪对稳定性重要”，但不足以支持“裁剪通过抑制风格 token 起作用”这一具体机制解释。总体而言，三项创新中裁剪的证据最直接但覆盖面最窄，OPSD 框架的证据最广但无法隔离各组件，全词表目标的证据介于两者之间且对照有混杂。

4.4 成本与适用范围

训练成本。 论文报告使用 8 张 A100 或 H100、LoRA rank 64、batch 32、100 步、每问题 1 条 1024-token rollout；没有报告墙钟时间、GPU 小时、FLOPs 或显存峰值。代码 README 称 Qwen3-1.7B 在 4×H100 上训练约 15 分钟，但这是仓库说明，不是论文数据。OPSD 每个训练样本需要学生前向和教师前向各一次，且教师在每个位置输出全词表 logits；相比只做学生前向的 SFT，训练计算和显存更高，论文只在 §4.3.5 提到全词表带来更高峰值显存，没有量化。

推理成本。 推理阶段不需要教师、参考解或额外前向；学生就是普通的 Qwen3 + LoRA，按 Table 8 的 thinking mode 评测。因而部署成本与基座模型相同，这是 OPSD 相对“外部大教师蒸馏”的实际优势。评测本身成本不低：每个问题 12 次采样、每次最多 38,912 个新 token，三个基准 × 三个规模 × 多个 checkpoint，但论文没有报告评测总成本。

数据与人工标注。 训练数据来自公开的 OpenThoughts 数学子集，最多 30K 对，带有 CoT；不需要额外的人工过程标注或奖励模型训练。论文没有说明这 30K 是如何从更大的 OpenThoughts 中筛选的（按难度、长度、正确性还是随机采样），也没有报告去重、污染检查或数据难度分布。这会影响复现与对结论外推的判断。

适用范围与未解决问题。 实验只覆盖 Qwen3 指令模型的 1.7B/4B/8B、三个数学竞赛基准、LoRA 微调；没有代码、科学推理、多轮 Agent 或长上下文任务，也没有全参数微调或超过 8B 的模型。4B/8B 相对 GRPO 的优势很小，8B 的 HMMT25 还略低于 GRPO，说明“匹配或超过”是平均值意义上的。Appendix A 承认：题目超出模型理解能力时，教师即使看到答案也无法提供有意义的监督；当前框架没有显式利用答案正确性验证；课程学习是未来方向。因此，OPSD 更适合“模型本身已具备基础推理能力、参考解在模型可理解范围内、希望用单条 rollout 获得稠密监督”的场景，而不能直接外推到“弱模型靠答案自学”或“所有推理任务”。

5. 最容易受到审稿人质疑的地方

质疑：token 效率的比较口径与版本数字不一致，可能被夸大

  • 原文依据：v3 摘要只说“superior token efficiency”，正文没有给出倍数；v1 摘要写“4-8x token efficiency”，v2 摘要写“8-12x”，v3 删去具体数字（arXiv abs 各版本）。HF 页面仍保留 v1 自动摘要的“4-8x”。论文 Fig. 3 的横轴是“累计生成 token”，只统计学生采样；Table 6 的预算为 OPSD 1×1024 vs GRPO 8×16k，且 GRPO 训练 500 步、OPSD 100 步。论文没有报告教师前向、全词表 softmax、墙钟时间或 FLOPs。
  • 为什么重要：如果“效率”只指学生生成的 token，而教师前向和全词表 logits 的成本不计入，那么它不能等同于训练总计算或墙钟效率；不同版本的倍数从 4–8× 变为 8–12× 再被删除，也会让读者无法判断作者最终认可的结论是什么。这影响核心卖点的可信度与与 RL 的效率比较。
  • 当前能够得出的判断：现有材料只能支持“在报告的学生采样 token 口径下，OPSD 比 GRPO 更省”，不能支持“总训练计算或墙钟时间省 4–8×/8–12×”。倍数的版本差异是材料内部不一致，不是审稿人推测。
  • 如何验证或补强：报告每步的教师/学生前向 FLOPs、全词表 logits 显存、总 GPU 小时与墙钟时间；在相同总计算或相同墙钟预算下比较 OPSD 与 GRPO；明确“token efficiency”的定义并给出与 v1/v2 数字差异的解释。
  • 严重程度：主要问题。

质疑：训练用 TM-off 学生、评测开启 thinking mode，破坏“on-policy 分布一致”的前提

  • 原文依据：§3.2 说学生只观察题目，“matching the inference-time condition”；§4.3.2 与 Appendix B 明确主实验采用 TM-off 学生 / TM-on 教师；Table 8 的评测参数却写 Thinking Mode = Enabled，max new tokens 38,912。学生在训练时最多生成 1024-token 的短回答，评测时生成带长思维链的回答。论文没有报告 TM-on 学生训练的对照，也没有解释这一安排。
  • 为什么重要：OPSD 的核心卖点之一是 on-policy：学生在自己会访问的状态分布上学习，从而避免 exposure bias。如果训练用 TM-off、评测用 TM-on，那么评测时的前缀分布与训练时不同，“on-policy”只对训练时的短回答成立；这可能削弱方法动机，也可能解释为什么 4B/8B 的提升有限。
  • 当前能够得出的判断：这是原文设置之间的明显不一致；论文没有提供证据证明 TM-off 训练的优势能迁移到 TM-on 评测。不能据此断定方法无效，但“on-policy 匹配推理条件”的表述被过度简化。
  • 如何验证或补强：报告 TM-on 学生 + TM-on 教师的训练/评测结果，或至少在 TM-off 评测下比较；给出训练与评测的生成长度/模式分布；解释为什么 TM-off 学生的分布可以作为 TM-on 推理的代理。
  • 严重程度：主要问题。

质疑：最佳 checkpoint + 单 seed + 无置信区间，结果稳定性不足

  • 原文依据：Table 2 题注：OPSD 每 20 步评测一次、取 100 步内最佳分数；GRPO 取 500 步内峰值；SFT 与 OPSD 同训练样本数。正文没有报告多 seed、标准差、置信区间或显著性检验。代码 README 的“Reproducibility note”明确说明其 Qwen3-1.7B 结果来自 single seed run，并承认应采用多 seed 评测。
  • 为什么重要：OPSD 与 GRPO 的 4B/8B 平均差距只有 0.8–0.9 个百分点，8B HMMT25 还落后 0.9 个百分点；在这种量级上，单 seed + 最佳 checkpoint 的选择足以改变结论。Avg@12 只降低解码采样噪声，不解决训练随机性。
  • 当前能够得出的判断：主结果的方向（OPSD 优于 SFT、总体不差于 GRPO）有一定一致性，但“匹配或超过 GRPO”的细节差距不能视为稳定结论；没有统计证据支持逐项胜负。
  • 如何验证或补强：至少 3 个训练 seed，报告均值/标准差；固定评测 checkpoint（如最后一步）与最佳 checkpoint 两套结果；对 OPSD vs GRPO 的差值做配对检验或置信区间；公开每个 checkpoint 的完整曲线。
  • 严重程度：主要问题。

质疑：机制消融没有隔离关键变量，无法证明“全词表/特权教师”各自必要

  • 原文依据：Table 4 题注没有说明两个变体的散度方向与裁剪设置；按正文主配方，“全词表”是前向 KL + 裁剪，而“采样 token”按 §3.2 是反向 KL 策略梯度，代码 README 又说该变体未实现裁剪；Table 3 已显示反向 KL 在相同裁剪下明显更差。论文没有“教师不看 y⋆y^\stary⋆”的对照，没有“外部教师 + 同策略蒸馏”的同预算基线，也没有“固定教师 vs 更新教师”的消融；§4.1 只说固定教师“helps stabilize”，未给数字。生成风格的四种组合只有 KL 分析，没有下游表格。
  • 为什么重要：这关系到创新性归因：OPSD 的收益到底来自 on-policy rollout、特权答案、全词表监督，还是裁剪/散度选择？如果 Table 4 的差距主要来自反向 KL 或裁剪，那么“全词表分布匹配”这一创新点的证据就被削弱；如果增益主要来自 on-policy，那么“同一模型当教师”并非必要，外部教师也可能达到类似效果。
  • 当前能够得出的判断：现有实验支持“整套 OPSD 配方有效”，但不足以逐项证明每个组件的独立贡献；Table 4 的对照存在混杂，固定教师与特权信息的必要性属于未验证。
  • 如何验证或补强：做 2×2 消融（全词表/采样 token × 前向/反向 KL，均加/不加裁剪）；加入“教师仅看题目”“教师看答案但去掉 CoT”“外部同规模/更大教师”的对照；报告固定 vs 更新教师的训练曲线；给出四种 TM 组合的下游准确率。
  • 严重程度：主要问题。

质疑：适用范围窄、数据筛选与基准污染未讨论，结论外推有限

  • 原文依据：§4.1 只使用 OpenThoughts 数学子集（最多 30K 对）与 AIME24/25、HMMT25；模型只到 Qwen3-8B；全部实验用 LoRA（Table 6/7）；Appendix A 承认 8B 上限与教师能力门槛。数据筛选只写“sampling up to 30K”，没有过滤标准、难度分布、去重或污染检查；论文没有讨论 AIME/HMMT 题目是否可能出现在 OpenThoughts 或其上游数据中。全文没有使用 Amo-Bench，因此与本论文的基准污染问题无关。
  • 为什么重要：数学竞赛基准题目数量少、公开时间长，训练数据与评测集的污染风险需要主动排查；只用 LoRA 也不能说明全参数微调下同样有效。若 30K 子集偏向某类难度或风格，OPSD 的收益可能部分来自数据选择而不是算法。
  • 当前能够得出的判断：论文的结论应限定在“Qwen3 指令模型、LoRA、数学竞赛题、最多 8B”的范围；对代码/科学/多轮任务、全参数训练、更大模型和污染控制，当前材料无法确认。
  • 如何验证或补强：披露 30K 子集的筛选流程与难度/长度分布；做 n-gram/嵌入级污染检查并在去污染后重跑；增加代码或科学推理基准；至少在一个模型上做全参数微调对照；报告超过 8B 的结果或明确不外推。
  • 严重程度：次要问题（对论文主张的边界重要，但不否定现有数学结果）。

6. 审稿式总评

作者发现同策略蒸馏虽然能提供稠密 token 监督，却依赖外部教师，而推理数据集本身已带有参考解；因此提出 OPSD，让同一个 LLM 在“题目 + 参考解”的教师上下文和“仅题目”的学生上下文下共享参数，在学生自己的 rollout 上做逐 token 全词表前向 KL 匹配，并用逐点 KL 裁剪抑制风格 token 的支配。实验在 Qwen3-1.7B/4B/8B 与 AIME24/25、HMMT25 上表明：OPSD 稳定优于 SFT，平均匹配或略优于 GRPO，且只用单条 rollout 与最长 1024 token；其中“优于 SFT”和“1.7B 上的大幅提升”证据较强，裁剪稳定训练的曲线也较直接，但“token 效率”的总计算口径、训练/评测生成模式不一致、最佳 checkpoint 与单 seed、以及全词表/特权教师各组件的独立贡献仍缺少充分支持。本文最有价值的部分是把“参考答案当作特权信息、在 student rollout 上做软蒸馏”这一简单机制讲清楚，并给出可复现的 LoRA 配方；最大的审稿风险是效率主张与 on-policy 前提的设置不一致，以及消融无法隔离关键变量。

  • 问题定义清晰度：强。论文明确把问题限定为“同策略蒸馏需要外部教师、且未利用参考解”，并用 Table 1 对比 SFT/GRPO/同策略蒸馏/OPSD 的四项属性；读者能清楚知道它想补哪个缺口。
  • 创新性证据：中。单模型双角色与上下文蒸馏、GKD 式同策略蒸馏有直接血缘，SDPO/SDFT 为并发工作；真正的增量是“参考解作为特权信息 + 全词表前向 KL + 逐点裁剪”的组合，论文没有与外部教师同策略蒸馏做同预算比较，首次性无法确认。
  • 方法可信度：中。算法本身简单、梯度路径明确、代码与超参数公开；但固定教师、裁剪阈值、生成风格等关键选择缺少消融或正文披露，Table 4 的对照存在混杂。
  • 实验支持力度：中。三个模型规模、三个数学基准、一致的主结果方向是优点；但只有数学、最多 8B、LoRA、单 seed、无置信区间、最佳 checkpoint，4B/8B 相对 GRPO 的差距很小。
  • 可复现性：中。代码、LoRA 配置、训练/评测参数和 30K 数据来源都公开，1.7B 配方在仓库中有快速复现说明；但 30K 子集的筛选细节、裁剪阈值在正文缺失、单 seed 结果有波动，严格复现论文数字仍有距离。
  • 综合阅读价值：高。它把“自蒸馏 + 特权信息 + on-policy 软监督”讲得直观，Table 1 与 Table 5 的框架对理解后训练路线很有帮助；同时它也是一个适合用来讨论“效率口径、消融隔离、训练/评测一致性”的案例。
