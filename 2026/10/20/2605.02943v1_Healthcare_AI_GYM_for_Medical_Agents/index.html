0. 一句话结论

论文搭建了一个覆盖 10 个临床领域、3.6K 级任务、135 个临床工具和 828K 医学知识片段的 Gymnasium 环境 Healthcare AI GYM，并在其上研究多轮医疗智能体强化学习（multi-turn agentic reinforcement learning），提出用指数滑动平均教师（EMA teacher）、结果条件特权提示（outcome-conditioned privileged hints）和余弦长度奖励（cosine length reward）组成的 TT-OPD 来稳定训练。实验报告 TT-OPD 在 16 行主表中拿下 10 行最优、相对无 RL 的 AgentRunner 基线平均约 +4 pp，并把响应长度和工具轮次控制得更稳；但训练任务与评测集来源重叠、VQA/LFQA 评分口径混杂、消融是累积式且缺少多种子，使这些数字目前只能算初步证据，不能支持“普遍提升医疗智能体能力”的结论。

1. 论文具体想解决什么问题？

临床诊疗不是一次性选择题，而是一个反复收集病史、开检查、读结果、调整治疗方案的循环。论文指出，现有医疗大模型在 USMLE 一类静态基准上分数很高，但真实临床能力要求的是多轮工具使用和持续的状态维护；这条从“会答题”到“会执行临床动作”的差距，被作者称为 action gap（行动鸿沟）。这个背景判断本身并不新，ReAct、工具调用和医疗智能体文献都已反复讨论；论文的新意主要在于把“多轮 agentic RL 在医疗场景里会发生什么”当作一个需要系统观察和修复的工程科学问题。

作者对现有环境的批评是：AgentClinic 能模拟诊断对话，但没有工具生态和 RL 训练接口；Agent Hospital 侧重多智能体工作流，没有显式的策略优化；MedAgentGym 虽有 Gymnasium 接口，工具却偏代码执行，而非“开化验、算 SOFA、查药物相互作用”这类临床动作；MedOpenClaw 则报告了“直接提示专业工具反而掉分”的工具使用悖论。论文据此声称，此前没有一个环境同时具备多领域覆盖、临床工具、安全评测和现代 RL 框架兼容性。这个判断是作者的主张，论文没有做系统性的环境对比实验，只能视为其设计动机。

更具体的问题来自作者在自建环境中的训练观察。作者报告了三类相互纠缠的失败：一是 response explosion（响应爆炸），输出长度单调增长到上限，模型把“覆盖更多 token”当成完成任务的代理信号；二是 multi-turn collapse（多轮坍缩），原本应该由工具调用支撑的对话退化成冗长的单轮独白，工具轮次从 7.65 降到 5.52；三是 distillation instability（蒸馏不稳定），同策略蒸馏（on-policy distillation，OPD）在单轮推理里有效，到了组合空间巨大的多轮轨迹里，教师策略很快过期。作者还给出一个把三者串起来的解释：稀疏的终局奖励（sparse terminal reward）与序列决策不匹配，GRPO 把同一个优势值广播给整条轨迹的所有 token，无法把信用分配给具体轮次，于是模型选择“更长但更省事”的单轮路径。

这里需要区分三层内容。第一层是领域早已知道的一般问题：医疗智能体需要多轮工具使用、需要安全约束、需要比准确率更细的奖励。第二层是本文的新观察：在作者这套环境、这个基座和这套奖励下，多轮 RL 会出现长度爆炸与轮次坍缩，而且 OPD 的失败模式与单轮不同。第三层是本文实际要验证的子问题：加入轮级 KL 正则、结果条件提示和长度控制，能否在不牺牲准确率的情况下稳定多轮训练，并把这种能力迁移到 18 个（论文口径）医疗基准上。论文对第二层的证据主要是训练曲线和四个变体的失败 progression；对第三层的证据是主表和消融。问题在于，作者把“稀疏终局奖励是根因”写成了接近结论的因果解释，但并没有做“只改奖励密度、其他不变”的对照，也没有对“单轮独白”做独立的文本或行为标注；因此更准确的表述是：论文观察到了现象，并提出了一个合理的机制假设，但因果解释尚未被充分验证。

论文最终要验证的核心假设可以拆成两句：其一，医疗智能体的能力可以通过在一个足够广、足够像临床工作流的 RL 环境里做多轮训练而提升；其二，TT-OPD 这种“教师只比学生多看一眼结果提示”的自蒸馏，能够提供比稀疏终局奖励更密的轮级信号，从而同时改善稳定性和最终表现。第二句是本论文真正的技术主张，第一句则依赖环境与评测的可信度。后续的审稿风险，很大一部分就落在第一句和第二句的证据是否被评测口径污染。

2. 创新点是什么？

真正的技术增量可以概括为“一个环境 + 一个训练配方 + 一组失败模式分析”。环境提供广度与临床工具，训练配方把已有的 EMA、特权提示、轮级 KL 和余弦长度奖励组合到多轮工具轨迹上，失败模式分析则试图说明为什么朴素的 GRPO/OPD 会崩。三者中，环境是工程量最大的贡献，TT-OPD 是方法贡献，失败模式分析是实证贡献；但三者都不是从零发明的新原理，创新性需要按“组合方式是否解决了一个此前没有被解决的问题”来评判。

第一，Healthcare AI GYM 把 10 个临床领域、3,631 个任务、135 个工具、828,473 个知识片段和 5D 奖励封装成标准 Gymnasium 接口，并提供任务生成器、领域策略文件、工具 schema 自动生成和评测套件。与 AgentClinic、Agent Hospital、MedAgentGym 相比，它的差异主要是覆盖面和“临床动作”而非代码动作；这属于实质性的系统与资源贡献，但是否构成“首个”需要更完整的文献检索。证据见 §4.1 与 §4.3：环境组件本身几乎没有被逐项消融，Base+AR 只提供了工具/知识库相对无工具文本评测的粗粒度对照，不能证明 135 个工具或 10 个领域各自必要。

第二，TT-OPD 把 OPD 从单轮推理扩展到多轮工具轨迹：教师是学生的 EMA 副本，不是更强的外部模型；教师额外看到一条由轨迹正确性决定的结果提示，学生看不到；KL 在每个轮次的每个 token 上计算，而不是只在最终答案上计算；再用余弦长度奖励抑制长度爆炸。与 OPSD、Self-Distilled RLVR、SRPO、CRISP、HiLL 等工作相比，差别在于“多轮 + 结果条件提示 + 轮级 KL + 长度控制”的组合，而不是单个组件。论文没有证明这个组合不能被更简单的“GRPO + 长度奖励”或“固定教师 + 正确/错误标记”替代；证据见 §4.3，现有消融不足以把组合优势归因到某个组件。

第三，论文声称给出了首个关于“agentic-textual transfer gap（智能体—文本迁移鸿沟）”的系统分析：RL 提升了程序性工具能力，却没有迁移到文本 QA，原因是格式奖励稀释（format reward dilution）。这个观察如果成立会很有价值，但它的证据同样依赖评测口径。论文用 MMLU 从 83.8% 掉到 60.6%、SLAKE 从 79.0% 掉到 30.6% 来说明“参数知识还在，只是多轮工具调用引入格式错误”，却没有报告 TT-OPD 在纯文本评测下的成绩，也没有分离“工具调用失败”“答案抽取失败”“评分规则变化”三种解释。因此这部分更适合被看作一个有启发性的假设，而不是已经证明的迁移规律。

此外，论文还提出 EMA 作为隐式学习率退火、梯度信号稀释等三条分析性命题（Appendix E）。这些命题借用了自然梯度与 EMA 的已知结果，作者自己也说明“不声称形式化新颖性”；它们能帮助读者建立直觉，但不能替代消融实验。总体而言，本文的创新性证据是“中等”：环境与问题设置扎实，方法组合合理，但关键组件的不可替代性和迁移结论都还没有被干净地隔离出来。

3. 作者如何解决？

3.1 直觉：把“终局裁判”变成“每轮教练”

论文的核心直觉是：多轮临床任务只在最后给一个奖励，模型很难知道是哪一轮搜错了、哪一次检查开错了、哪一句推理把诊断带偏了。既然人工标注每一步的 process reward model（过程奖励模型，PRM）成本高，而且工具返回的动态上下文使“这一步好不好”依赖外部数据，作者换了一个办法：让一个与学生同源、但通过 EMA 缓慢跟随学生的教师，在每一轮都给出一个分布；教师比学生多看到一条“这条轨迹最后对不对”的提示，于是它的分布带有结果信息。学生通过 KL 散度去匹配教师，就相当于在每一轮都收到一个稠密但不需要人工标注的监督信号。这个思路是否真的比“只给最终奖励 + 长度惩罚”更好，取决于教师是否真的比学生更可靠；论文没有直接报告教师的准确率，这是后面要追问的关键。

3.2 环境：从患者 ticket 到 5D 奖励

Healthcare AI GYM 的接口是一个标准的 Gymnasium 环境：观测空间是长度上限 100,000 的文本，包含对话历史、工具返回和患者信息；动作空间是长度上限 10,000 的文本，可以是 JSON 工具调用，也可以是自然语言回答；reset() 加载任务并返回系统提示和患者 ticket，step(action) 解析并执行工具，返回新的观测；当模型调用 submit_answer() 或达到最大轮次时回合结束。环境按领域懒加载 10 个模块，每个模块包含 Pydantic 数据模型、工具集、环境入口、任务 JSON 和领域策略文件。工具通过装饰器注册为 READ、WRITE、THINK、GENERIC 四类，方法的签名和 docstring 会自动转换成 OpenAI 兼容的函数调用 schema；工具执行失败或 JSON 非法时返回错误消息，而不是让整个回合崩溃。这些都是工程实现细节，但对复现很重要，因为“工具 schema 如何注入提示”会直接影响模型能否正确调用。

图 1 展示了环境的四层结构。最外层是模拟临床环境，包含会诊室、病房、影像中心、药房等场景，以及 135 个工具；数据层接入 EHR、影像、化验、文献和 828K 知识片段；学习层是 Gym AI Training Engine，包含轨迹表示、GRPO/TT-OPD、奖励函数和策略更新；评测层则把任务分成文本 MCQ、长文本 QA、视觉 QA、EHR 四类。对读者来说，这张图最重要的信息不是“有四个框”，而是数据流的方向：患者 ticket 和工具目录进入策略，策略产生工具调用，工具返回结果并改变状态，最终由奖励函数在回合结束时打分；训练引擎再把轨迹和奖励转成策略更新。理解了这个闭环，才能理解为什么作者把“轮次”和“长度”当作一等公民。

图 1（论文 Fig. 1）：Healthcare AI GYM 把模拟临床环境、真实数据与知识库、RL 训练引擎和评测套件串成一个闭环。患者 ticket 与工具目录进入策略，策略在环境中执行工具调用，工具输出回到下一轮观测，回合结束时 5D 奖励进入 GRPO/TT-OPD 更新；评测层把文本、视觉、EHR 和长文本任务组织成统一套件。该图解释的是系统边界与数据流，而不是某个单点模块的性能。

环境中的任务来自三条管线：1,138 个专家种子任务；AutoTaskGenerator 从外部基准和知识源扩展出的任务；以及指南/知识挖掘生成的任务。论文报告最终有 3,631 个实例化任务，其中 2,657 个用于 RL 训练，307 个用于验证；三个数字相减还剩 667 个任务没有说明去向。任务 JSON 包含患者场景 ticket、预期工具交互、自然语言断言和 reward_basis，后者决定用动作覆盖还是自然语言断言来评分。工具总数为 135，论文说它们被合并成 25 个用户可见类别，分为证据检索、临床评估（22 个验证过的评分量表）、干预动作和推理支架四类。知识库是 SQLite FTS5 + BM25，索引了 828,473 个片段，来源包括 MedCPT 证据、生物医学 QA、生成器片段和 MedInstruct；另外还有一个 26M 文章、188GB 的离线 Wikipedia 索引。这个规模是环境贡献的重要部分，但也带来了数据来源、许可和去重的问题，后文会展开。

奖励是论文最需要仔细看的地方。作者定义了一个 5D 奖励：准确率、过程质量、安全、格式、连贯性，默认权重分别是 0.25、0.20、0.20、0.10、0.10；如果有 rubric 断言，再加入 0.15 的 assertion 维度。没有 assertion 时权重和只有 0.85，论文没有说明是否重新归一化，也没有说明训练时是否总是有 assertion。安全维度是规则式的：50 多条违规模式、5 个严重度，最严重的违规（忽略禁忌、危险剂量、漏诊急症）把总分上限压到 0.1，严重违规扣 0.3，较轻的扣 0.15/0.05/0.01。过程质量由 60% 工具覆盖、20% 工具多样性、20% 彻底性组成，有 rubric 时 rubric 占 70%。这些设计的意图是让“按临床流程做事”也能得分，而不只是看最后答案；但它们是否真的在训练中生效、是否会被模型钻空子，论文没有给出逐维度的统计或消融。

3.3 TT-OPD：轮级 KL、结果提示与长度控制

TT-OPD 把临床智能体的决策过程建模为部分可观测马尔可夫决策过程（partially observable Markov decision process，POMDP）。在第 ttt 轮，智能体看到状态 sts_tst​（对话历史、工具输出、患者数据），产生动作 ata_tat​（自然语言推理或结构化工具调用），环境执行动作并转到 st+1s_{t+1}st+1​；回合在 submit_answer() 或达到时域 TTT 时结束，整条轨迹只在最后得到一个终局奖励。GRPO 用一组 GGG 条 rollout 的组内相对优势替代价值函数，优势是 Ai=(Ri−mean(R))/std(R)A_i=(R_i-\mathrm{mean}(R))/\mathrm{std}(R)Ai​=(Ri​−mean(R))/std(R)；论文特别指出，在在线单迭代设置里重要性比恒为 1，所以 DAPO 一类为多迭代设计的裁剪机制在这里没有作用。这个观察是对的，但也意味着 GRPO 的稳定性高度依赖组内奖励的方差和采样质量。

3.4 推理与一个教学简化示例

推理阶段，模型不再需要教师，也不再注入提示；它作为一个多轮 AgentRunner，带着 135 个工具和 828K 知识库，反复执行“思考—检索—验证—提交”。论文强调，如果用单轮方式评测，TT-OPD 模型会在所有基准上得到 0，因为它已经学会先调用工具、最后才 submit_answer()，单轮评测在提交之前就截断了。这个说法在作者自己的评测脚本里有一定依据：脚本在最后一轮会强制提示模型提交，且答案只在 submit_answer 的参数里被读取；但它也暴露了一个评测协议问题——零分可能只是“没有按评测器的格式提交”，不一定是“没有知识”。后文会把这一点作为核心质疑之一。

用一个教学简化示例说明训练回路（不是论文实验）：假设一道 MedQA 题问 ACEI 与 ARB 对缓激肽和血管紧张素 II 的影响。学生第一轮推理，第二轮调用 retrieve_evidence，第三轮调用 search_medical_wiki，第四轮用 analyze_answer_options 排除选项，第五轮 submit_answer。如果最终答案正确，教师看到“推理合理”的提示，它在每一轮对“继续检索、继续验证”的 token 给予更高概率；如果答案错误，教师看到“重新检查鉴别诊断”的提示，它在错误分支上的分布被压低。学生通过 KL 去贴近教师的分布，相当于在不看到提示的情况下，被轻轻地推向“更可能通向正确答案的推理路径”。这个例子来自论文 Appendix J.1 的轨迹结构，但这里的“教师如何改变分布”是教学解释，不是论文的可视化证据。

从输入到输出完整走一遍：患者 ticket 和工具目录进入系统提示；策略在每一轮选择工具或作答；工具执行后把 JSON 结果写回观测；回合结束后 5D 奖励和正确性信号进入奖励/提示模块；GRPO 用组内相对优势更新学生；TT-OPD 用教师 KL 追加一个稠密正则；EMA 把学生的新权重缓慢写回教师。固定流程控制的是工具 schema、回合上限、奖励计算和 EMA 更新；模型决定的是每一轮说什么、调用哪个工具、传什么参数、何时提交。训练只更新学生参数，教师不加梯度；推理阶段只保留学生。这个分工是清楚的，但“教师是否比学生更会做题”没有被单独测量，而这正是 KL 正则能否有用的前提。

4. 解决得怎么样？

4.1 实验设置

主实验以 Qwen3.5-9B 为唯一基座，在 8×A100 80GB 上训练 60 步，不做 SFT warmup。评测对象有四列：Base (text) 是不给工具的 log-probability 或答案抽取；Base+AR 是同一个多轮 AgentRunner、同样 135 个工具和 828K 知识库，但不做 RL；GRPO 和 TT-OPD 是 RL 后的模型，均用多轮 AgentRunner 评测。论文 Table 1 把结果分成 MC QA、Visual QA、EHR、LFQA 四类，Table 5 给出样本量：MedQA 1,273、MedMCQA 4,183、MMLU 六个子集合计 1,089、六个 VQA 集合计 11,637、五个 LFQA 集合计 4,948、MIMIC-III 与 eICU 各 5,000。按这些数字相加，评测规模约 33,130 个回合；论文没有报告这些回合的总 token、工具调用次数、延迟或费用。

这里先出现第一个口径问题：论文反复说 “18 个 benchmark”，但 Table 1 实际只有 16 行；如果按 Table 5 把 MMLU 的 6 个子集拆开，则是 21 项；如果不拆，则只有 16 项。18 既不是 Table 1 的行数，也不是 Table 5 的条目数。Table 1 的题注还明确写 “MMLU-Med. aggregates 6 subtypes”，所以 16 行是论文自己的聚合口径。这个数字不一致会直接影响 “10/18” 与 “12/18” 的可核验性，后文会给出逐行计数。

Table 1 的四个评测列并不是同一种测量。Base (text) 用 log-probability 或答案抽取，Base+AR/GRPO/TT-OPD 用多轮工具调用；SLAKE 与 PMC-VQA 的 Base (text) 数字还标了 †，表示来自参考文献而不是作者用同一个 Qwen3.5-9B 重测。Table 5 说 LFQA 的指标是 ROUGE-L、Hallucination、Completeness 三项，但 Table 1 每行只给一个数；仓库评测脚本显示，这个数实际是 ROUGE-L 不低于 0.3 的二值 “correct” 比例。VQA 的 “accuracy” 在论文报告的版本里用的是子串包含（substring containment）：只要 gold 字符串出现在提交文本里就算对；仓库的 vqa_scoring.py 明确写道，一段固定的、完全不看图像的 317 字符 “对冲段落” 在 VQA-RAD 上能拿到 56.5%、在 SLAKE 上能拿到 45.4%，后者“高于论文印出的三行 SLAKE 结果”。EHR 的 “action score” 则是预期工具调用覆盖率不低于 0.5 的二值判定，不是临床答案正确率。把这些指标都叫 “accuracy” 并放在同一张表里比较，会制造一种它们可比的错觉；这是后文质疑 2 的核心。

训练配置也有多处需要对齐。Table 4 写 GRPO 训练 3 个 epoch、TT-OPD 训练 1 个 epoch，但 §5.1 又说 “GRPO baseline uses identical hyperparameters (Table 4) but without distillation or cosine reward”；如果 epoch 数不同，就不能叫 identical。仓库的 v16 TT-OPD 脚本写的是 trainer.total_epochs=3，GRPO 脚本也是 3，和论文 Table 4 的 1 不一致。Table 4 写 “Full-param (FSDP)”，Appendix D.1 却写 “RL training with LoRA (rank 64, MLP + attention projections)”；仓库脚本没有 LoRA 配置，只有 FSDP offload。Table 4 写最多 5 个 assistant turn，论文 Fig. 3/论文 Fig. 4 却报告每回合 7.0–7.4 turns；按代码推测，图里的 “turn” 统计的是工具调用/消息轮次而不是 assistant turn，但论文没有定义这个口径。论文还声称 5D 奖励是训练目标，仓库 reward_fn.py 的注释却写 “every published run optimized accuracy + 0.1format_bonus - 0.2n_invalid, so the composite was an evaluation-time quantity only”，并且 v16 脚本设置的是 COSINE_REWARD=1，没有设置 HCGYM_REWARD_WEIGHTS；这意味着论文报告的 TT-OPD 训练很可能用的是“准确率 + 余弦长度奖励”，而不是 5D 复合奖励。这个差异后文会作为主要质疑展开。

单 seed、无置信区间是另一个设置层面的限制。论文报告的 61.1%、62.0%、59.5%±1.4 都来自一次训练；±1.4 pp 是第 40–60 步之间的波动，不是多次独立训练的方差。Table 1 的每格也只评一次，没有 seed、方差或显著性检验。对于 eICU 57.1 对 55.9、MIMIC-III 62.7 对 62.1 这种 1 pp 以内的差距，单次评测不足以支撑 “best” 的判断。

训练动态方面，图 3 给出四条轨迹：准确率、KL、响应长度、每回合轮次。TT-OPD 在第 60 步达到 61.1%，比 52.6% 的 base 高 8.5 pp；GRPO 在第 55 步达到 62.0% 的更高峰值，但响应长度在 7.7K–10.8K token 之间摆动。TT-OPD 的响应长度控制在 5.7–9.3K，轮次稳定在 7.0–7.4；KL 从接近 0 持续升到约 1.06。作者把这种 “accuracy 先升后降再升” 的非单调收敛解释为 EMA 的 “弹簧” 效应：学生偏离教师越远，KL 梯度越强，把它拉回来。这个解释有直觉吸引力，但也暴露了一个问题：如果教师真是稳定的锚，KL 应该在一个有界范围内波动，而不是从 0.001 单调涨到 1.063；持续增长的 KL 说明师生分布越走越远，所谓 “稳定” 更多是 “没有崩” 而不是 “收敛到教师”。论文 Appendix E.3 给出一个 KL 上界命题，但那是基于每步更新幅度有界的假设，并没有用实验验证这个假设。

图 3（论文 Fig. 3）：四条轨迹分别记录验证准确率、师生 KL、响应长度和每回合轮次。TT-OPD 的准确率不是最高，但长度和轮次更稳；GRPO 的准确率峰值更高，长度摆动更大；KL 持续上升说明学生并没有停在教师附近，而是在奖励与正则之间持续移动。读这张图时应把“稳定”理解为“没有出现长度爆炸或轮次坍缩”，而不是“已经收敛”。

因此，图 3 能支持 “这条训练轨迹更稳”，但不能单独支持 “最终模型在 18 个基准上更强”；后者仍要看 Table 1，而 Table 1 又受 §5 的污染与评分问题影响。

4.3 机制证据

论文把 “方法有效” 与 “机制被验证” 分开得不够。先看环境侧：Base+AR 相对 Base (text) 的提升，被用来证明工具和知识库的贡献；但这个比较同时改变了三件事——是否给工具、是否多轮、答案如何抽取。SLAKE/PMC-VQA 的 Base text 还是参考文献数字，因此 Base+AR 的 “提升” 或 “下降” 不能干净地归因于工具。环境内部也没有做 “去掉知识库”“只保留 10 个工具”“去掉安全维度”“把 10 个领域减到 1 个” 这类消融；135 个工具、828K 片段、10 个领域都是整体打包出现。而且工具数本身就有三个口径：Table 2 逐域相加是 175，Table 3 逐域相加是 161，正文却写 135，读者无法确认环境到底有多少个可调用工具。对于一个以环境为核心贡献的论文，这会让读者无法判断规模中哪些部分是必要的。

再看 TT-OPD 侧。论文 Fig. 4 的四个变体是累积式的：先做周期性教师重置（T=10 与 T=30 两条线），再把重置换成 EMA，再加结果提示，最后加余弦长度奖励。每一步只加一个组件，这是它的优点；但它不是 “从完整方法逐一移除” 的消融，因此不能回答 “完整方法去掉提示会怎样”“完整方法去掉 EMA 会怎样”。更严重的是，完整方法自己也有 “每 30 步硬拷贝教师” 的设置，而 “周期性重置 T=30” 正是导致 KL 崩塌的那个操作。论文说完整方法在第 30 步硬拷贝后仍然稳定，论文 Fig. 3 的 KL 也没有在 30 步出现断崖；这与 “硬拷贝会造成 KL collapse” 的因果叙述直接冲突。可能的解释是硬拷贝只在某个条件下触发、或完整方法的 EMA 更新把硬拷贝的影响抹平了，但论文没有说明。这个矛盾使 论文 Fig. 4 的 “每个组件对应一种失败模式” 只能算一个叙事，而不是被隔离的因果证据。

论文 Fig. 4 还有一个比较窗口问题：失败变体在约第 25–47 步先后终止（EMA/提示变体约第 40 步，按图读取），完整 TT-OPD 和 GRPO 跑到第 60 步；论文用崩塌后的 49.0%（正文，图 4 中 EMA/提示变体的终点）与完整方法第 60 步的 61.1% 对比，两者的训练步数并不相同。即使失败变体在第 40 步已经崩，读者也无法判断它在第 60 步会不会恢复。论文没有给出 “同一 stop step” 的对照，也没有给出每个变体的 seed 数。

提示机制本身没有被验证。教师和学生同源，教师唯一的额外信息是一条正确/错误提示；论文没有报告教师在这些任务上的准确率，也没有比较 “真实提示” 与 “随机提示/固定模板/只有正确性位” 的差异。仓库脚本显示提示可以是动态生成的（HINT_OPD_DYNAMIC=1），也有静态 fallback；这意味着提示内容可能因轨迹而异，但论文只给了两句示例。若把提示换成一句无关的话，KL 正则是否仍然有效？没有这个对照，“结果条件” 的贡献就无法与 “任何额外的教师上下文” 区分开。仓库还设置了 BT_OPD_BIDIRECTIONAL=1（对负轨迹启用纠正梯度），论文的 Eq. 2 并没有描述这个双向项；这属于方法细节缺失，会让复现者不知道到底在复现哪一个损失。

长度奖励的消融也不充分。图 4 的 “EMA + 提示（无长度控制）” 与完整方法的差别是余弦奖励，这看起来隔离了长度控制；但余弦奖励同时改变了奖励的尺度和正确/错误的分支形状，不只是 “长度”。论文没有做 “GRPO + 余弦奖励但无提示” 的对照，因此无法判断稳定性来自长度控制、提示，还是两者的交互。错误分支的形状也有问题：论文 Eq. 3 在 L=Lmax⁡L=L_{\max}L=Lmax​ 时给错误答案 −0.7-0.7−0.7，仓库 v16 脚本的 COSINE_RL_WRONG=-0.3；同一篇论文的公式和代码不是同一个奖励函数。这个差异会直接改变 GRPO 的组内优势和模型 “不会就少说” 的倾向。

图 4（论文 Fig. 4）：周期性重置导致 KL 崩塌和准确率下降，EMA 消除了崩塌但轮次继续侵蚀，加入结果提示后出现长度爆炸，完整方法再把长度压回可控范围。图中还画出了 GRPO 基线，说明 “稳定” 不是 RL 的默认状态。需要警惕的是，这些曲线是累积式变体、失败变体在约第 25–47 步先后停止，而且完整方法自身也含硬拷贝；因此它展示的是失败模式的顺序，而不是每个组件的独立因果效应。

最后是统计与混杂。所有主结果和消融都是单 seed；Table 1 的许多 “best” 差距小于 2 pp；验证集的 ±1.4 pp 是步间波动，不是训练间方差。再加上训练/评测重叠与 VQA/LFQA 评分规则，当前证据只能支持 “在这套环境和这套评测器下，TT-OPD 的训练曲线比 GRPO 更稳，并且在多个基准上高于 Base+AR”，还不能支持 “TT-OPD 的某个组件是必要的” 或 “医疗智能体能力被普遍提升”。

4.4 成本与适用范围

论文报告的成本信息很少。训练是 8×A100 80GB、60 步、9B 全参数 FSDP、bf16，教师推理额外占用 2 张 GPU（SGLang），学生和教师都要跑多轮工具环境；论文没有给墙钟时间、总 token 数、总工具调用数、GPU 小时或费用。推理侧，论文给了响应长度 5.7–9.3K token、每回合 7.0–7.4 轮，但没有给单次评测的延迟或吞吐；按 Table 5 的样本量估算，完整评测约 33,130 个回合，若每回合 7 轮，约 23 万次工具交互（这是本文按论文数字做的算术，不是论文报告的成本）。环境本身还有 828K 片段的 SQLite FTS5 索引、26M 文章/188GB 的离线 Wikipedia 索引、约 30K 行代码；这些存储和运维成本没有量化。

适用范围也有限。基座只有 Qwen3.5-9B 一个，没有跨模型规模或跨家族的对照；训练/验证/评测都是英语医疗任务；EHR 使用 MIMIC-III/IV 与 eICU 的回顾性数据，视觉任务使用公开 VQA 数据集，没有前瞻性临床部署或真人患者交互；没有临床医生对轨迹质量、安全性或可解释性做人工评估。论文在 Discussion 里把 “human-in-the-loop evaluation” 列为未来工作，这等于承认当前结论只适用于模拟环境和自动指标。README 在 2026-06-01 之后新增的 Docker MCP 环境（11 个实时公共 API 的 MCP server）不在这篇论文的实验范围内，不能拿来支持论文的 135 工具环境或结果。

因此，本文能支持的边界是：在一个自行构建的、以 Qwen3.5-9B 为基座的医疗工具环境里，TT-OPD 相比 “无 RL 的 AgentRunner” 在多轮评测上平均约 +4 pp，并把响应长度和轮次控制得更稳；它不能支持 “TT-OPD 普遍优于 GRPO”“医疗智能体可以安全部署”“5D 安全奖励有效” 或 “多轮 agentic RL 能迁移到文本知识” 这些更强的结论。最能说明问题的是：论文自己承认 GRPO 的验证峰值更高，而 Table 1 又显示 TT-OPD 在 14/16 行高于 GRPO；这两个事实之间的张力没有被解释。

  • 严重程度：主要问题。

6. 审稿式总评

作者发现医疗 LLM 在静态考试上很强、在多轮临床执行上存在行动鸿沟，并观察到多轮 agentic RL 会出现响应爆炸、轮次坍缩和蒸馏不稳定；因此搭建了 Healthcare AI GYM，提出用 EMA 教师、结果条件特权提示和余弦长度奖励组成的 TT-OPD，通过轮级 KL 把终局结果信息变成稠密正则。实验在 Qwen3.5-9B、8×A100、60 步、单 seed 的条件下表明：TT-OPD 的训练长度和轮次比 GRPO 更稳，在 16 行主表中 10 行取得最高分，相对 Base+AR 平均约 +4 pp；其中 “训练曲线更稳” 的证据相对直接，“比 GRPO 更好” 和 “机制组件必要” 的证据较弱，“零污染” 与 “安全有效” 则目前不能成立。本文最有价值的部分是把医疗工具环境、多轮失败模式和 OPD 组合成一个可运行的系统，并暴露了多轮 RL 的长度/轮次病理；最大的审稿风险是训练任务与评测集来源重叠、VQA/LFQA 评分口径不可比、以及论文与代码/README 的多处不一致，这些会让主表数字无法作为泛化证据。

  • 问题定义清晰度：强。行动鸿沟、三个失败模式和 “稀疏终局奖励” 的动机在 §1/§3 交代清楚，读者能理解要解决什么。
  • 创新性证据：中。环境是实质性系统贡献，TT-OPD 是已有组件的合理组合；但 “首个” 与 “每个组件必要” 的证据不足，提示机制没有被单独验证。
  • 方法可信度：中。轮级 KL、EMA 和长度奖励的组合在逻辑上成立，但硬拷贝/截断/奖励公式与代码不一致，教师是否优于学生没有测量。
  • 实验支持力度：弱。16/18/21 的基准数不一致，10/18 与 12/18 冲突，+3.9 无法精确复算，单 seed、无置信区间，且存在训练/评测重叠与评分规则混杂。
  • 可复现性：弱。代码与配置公开是优点，但论文/代码/README 在 epoch、LoRA/FSDP、turn 上限、奖励函数、数据来源上多处不一致；关键数据 split 与许可未披露。
  • 综合阅读价值：中。适合作为 “医疗多轮 agentic RL 系统工程 + 失败模式分析” 的案例阅读，也能让读者看到环境型论文在污染、指标与复现上的典型陷阱；但不宜把其中的基准数字当作可靠的 SOTA 证据。
