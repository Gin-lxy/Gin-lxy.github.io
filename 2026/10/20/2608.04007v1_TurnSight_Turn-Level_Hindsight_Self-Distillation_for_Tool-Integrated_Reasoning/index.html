0. 一句话结论

TurnSight 试图解决多轮工具集成推理（Tool-Integrated Reasoning, TIR）中轨迹级奖励难以做细粒度信用分配（credit assignment）的问题：它把学生自己轨迹中的工具调用与执行结果当作事后回望（hindsight）信号，聚合到交互轮次（turn）级，在多个前瞻深度上按方向一致性筛选，再以有界权重调制强化学习（Reinforcement Learning, RL）的优势（advantage）。论文在 FTRL、BFCL、ToolHop 三个基准和 Qwen3-4B/8B 上报告了稳定增益（8B 总体平均 42.02，较同骨干模型（backbone）的 MatchTIR 39.03 高 2.99 分），但 ToolHop 增益只有 +1.04、实验是单次运行且缺少最近邻基线，因此证据足以支持“在论文报告的工具调用设置下有效”，尚不足以支持普遍提升 Agent 能力或“完全摆脱参考轨迹”的强结论。

1. 论文具体想解决什么问题？

TIR 要求大语言模型（Large Language Models, LLMs）在多轮交互中反复选择工具、填写参数、读取执行结果并据此调整后续行为（引言）。与单步生成相比，这种交互把最终成败拆散到许多中间决策上：一条轨迹最后失败，并不说明每个中间工具调用都错；轨迹成功，也不说明每一步都值得保留。论文把这一点概括为长时程 TIR 的时序信用分配问题：结果奖励只告诉模型“整条轨迹是否成功”，却不告诉它“哪一次工具交互有用、冗余或有害”（引言）。

现有做法大致分三类。第一类是结果级 RL，例如组相对策略优化（Group Relative Policy Optimization, GRPO）把轨迹级奖励归一化成组相对优势，再广播到该轨迹的所有策略 token；论文认为这会让因果作用差异很大的决策拿到相近信用（引言、预备知识·Agentic RL、论文 Fig. 1）。第二类是用参考轨迹做更细的监督，例如把生成的工具调用与标注或参考工具执行结果匹配（ToolRL、MatchTIR）；这类方法依赖“参考动作在当前策略访问到的状态下仍然合适”这一假设，而多轮环境会因一次不同的工具调用而改变后续状态，参考路径随之失配（引言、相关工作·TIR）。第三类是在线自蒸馏（On-Policy Self-Distillation, OPSD）：用同一个模型加一份只在训练时可见的特权上下文（privileged context）作教师，在学生实际访问到的状态上打分；但已有工作常用标准答案、参考轨迹采样（rollout）或检索到的技能作为特权信息，这些信息描述“任务该怎么解”，却不直接回答“当前这次工具交互在这个状态下是否合适”（引言、相关工作·OPSD）。

作者进一步指出一个粒度问题：TIR 的天然决策单元是一整个 turn，即一段推理加工具选择和参数构造；已有 OPSD 多在 token 级给信号，而同一个 turn 内不同 token 的信号可能因格式 token、参数写法而方向不一致，独立优化会造成“同一交互内部互相打架”的信用（引言、方法·执行条件化回望）。据此，论文提出两条要求：监督要与在线执行状态对齐，且要在交互层面保持一致（引言、方法）。支撑这一判断的主要是概念论证和论文 Fig. 1 的示意对比，而不是对真实训练轨迹的量化诊断；论文没有报告例如同一 turn 内 token 级信号符号冲突的比例，也没有报告 turn 级 hindsight 与真实 turn 正确性的相关性。

图 1（论文 Fig. 1）：图中对比了轨迹级 RL、已有 OPSD 与 TurnSight 三种信用分配方式。轨迹级方法把同一个优势广播给整条轨迹的所有 turn；已有 OPSD 虽然引入了只在训练时可见的特权上下文，但特权和学生状态可能错位，且信用落在 token 级，容易在同一 turn 内产生互相冲突的方向；TurnSight 则把学生自己执行得到的工具返回当作回望信息，在不同前瞻深度上形成共享于整个 turn 的信用信号，再用于调制优势。读者应从中理解论文的核心主张：不是换一个更强的教师模型，而是换一种与学生实际执行状态对齐、且与工具交互粒度一致的监督来源。

这里要区分三个层次。一般问题是可验证奖励强化学习（Reinforcement Learning with Verifiable Rewards, RLVR）在长时程任务中的稀疏奖励与信用分配困难，这在 agent 研究中早已存在；本文的新观察是“学生自己的工具执行结果本身就是最贴近其访问状态的特权信息”，并据此把 turn 作为聚合单位；本文实际解决的具体子问题是：如何在多个可能互相矛盾的事后回望视角中选出一个可靠信号，并在不翻转 RL 优势方向的前提下调制其大小。论文观察到了轨迹级监督在长时程 TIR 上的性能差距，但对其因果解释——参考轨迹失配、token 级信号冲突——主要是论证性的，尚未用诊断实验直接证实（引言、方法·执行条件化回望）。

论文最终要验证的核心假设因此可以写成：如果教师看到的是学生自己轨迹中当前及后续若干 turn 的工具执行结果，并把 token 级对数概率差聚合成 turn 级信号，再按跨前瞻方向一致性筛选、按同组 rollout 归一化后有界地调制优势，那么策略能在保持探索的同时获得更准确的 turn 级信用，并在域内与域外工具调用基准上优于轨迹级、参考匹配级和已有 OPSD 基线（引言、方法、实验）。

2. 创新点是什么？

真正的技术增量不在于提出新的策略梯度算法，而在于把“执行结果”重新组织成一种 turn 级、可选择、可调制的自蒸馏信号：教师仍是冻结的初始策略，RL 目标仍是带裁剪的策略梯度，新增的是教师上下文从哪里来、信号在什么粒度上聚合、多个视角如何筛选，以及信号如何进入优势。四项设计分别对应引言中的两个要求，下面只辨认增量，证据与消融统一放到 §4。

  • 执行条件化的事后回望教师：与用标准答案、参考轨迹或检索技能作特权的 OPSD 不同，TurnSight 把学生自己当前及后续 turn 的工具调用和执行返回拼进教师上下文，让教师评价“这次调用在这个状态下带来了什么后果”，而不是“任务的标准解法是什么”（方法·执行条件化回望）。这是已有组件（特权上下文自蒸馏）在新信息源上的重新组织，对应状态对齐要求；其直接证据是 §4.3 的上下文组成实验。
  • turn 级信号聚合：把同一 turn 内所有策略 token 的对数概率差取平均，得到一个共享给该 turn 全部 token 的信号，而不是逐 token 独立使用（方法·执行条件化回望）。这一改动针对“TIR 的决策单元是完整工具交互”这一粒度判断；它看似只是池化，但会改变信号符号与优化单元，§4.3 用去掉聚合的消融检验其作用。
  • 多前瞻视角与方向一致性选择：用 1、2、3 个 turn 的前瞻构造三个教师视角，先按符号多数投票确定方向，再在同意该方向的教师中选绝对值最大的信号（方法·多前瞻选择）。与固定单视野或直接融合不同，它试图同时避免“孤立教师放大噪声”和“平均融合稀释信息”；§4.3 将其与固定深度、教师融合比较。
  • 组内归一化的有界符号感知调制：把选出的 turn 级信号在同一 prompt 的 16 条同组并行采样轨迹（sibling rollout）内做组内标准分（z-score），再用 tanh 构造落在 [1−ε_w, 1+ε_w] 的权重，乘到原优势上；权重只放大或衰减与原优势同向/反向的信号，不改变逐 token 的优势符号，也不引入额外的模仿损失（方法·组内归一化权重、策略优化）。这使方法可以套在现有策略梯度算法上，但其“保持原优化方向”的确切含义需要结合本报告 §3.4 与 §5 理解。

需要提前说明边界：上述“不依赖参考轨迹”只适用于 hindsight 教师信号本身；论文实验中的 RL backbone 是 MatchTIR，而 MatchTIR 的训练奖励本身会用真值工具调用做匹配（实验·设置；详见下文质疑一）。因此 TurnSight 不是一条完全不用参考轨迹的训练管线，而是在参考匹配奖励之上再加一层执行条件化的自蒸馏。

3. 作者如何解决？

直觉上，TurnSight 让教师“先看到学生这次工具调用造成了什么后果”，再回头判断学生在这次调用中写下的 token 是否合理。教师不是更强的外部模型，而是冻结的初始策略；它比学生多出来的信息，是学生自己轨迹里当前及后续若干 turn 的工具调用与执行返回。于是，教师对学生已采样 token 的置信度变化，可以被当作一种“事后回望”证据：如果看到执行结果后教师更确信学生写下的 token，说明这次交互可能带来了有用信息；反之则可能有问题。论文再把这种证据从 token 级聚合成 turn 级，用多个前瞻深度互相校验，最后只在大小上调制 RL 优势，不改变优势的符号。

3.3 多前瞻视角与方向一致性选择

单一前瞻深度并不适合所有交互状态：有些决策看一眼当前执行结果就能判断对错，例如工具名不存在或参数类型错误；有些决策的后果要到后续 turn 才显现，例如当前检索到的信息是否足以支撑后面的计算。短前瞻可能漏掉延迟效应，长前瞻又可能把无关的后续交互混进来，稀释当前决策的证据（方法·多前瞻选择）。因此论文构造 DH={1,2,3}\mathcal{D}_H=\{1,2,3\}DH​={1,2,3} 三个执行条件化的教师视角；每个视角都用同一个冻结参考策略，只是看到的未来执行信息量不同，分别给出该 turn 的 δˉi,k(d)\bar\delta_{i,k}^{(d)}δˉi,k(d)​。浅层教师偏向即时执行质量，深层教师反映更下游的轨迹贡献（方法·多前瞻选择）。

三个教师可能对同一 turn 给出不同甚至相反的方向。论文没有直接平均，也没有只取绝对值最大的一个，而是分两步选择（方法·多前瞻选择）。第一步，把每个教师的信号映射成符号 si,k(d)∈{+1,−1}s_{i,k}^{(d)}\in\{+1,-1\}si,k(d)​∈{+1,−1}，对三个符号做多数投票，得到共识方向 vi,kv_{i,k}vi,k​。第二步，只在符号与共识一致的教师中选绝对值最大的那个，记其深度为 di,k∗d_{i,k}^{*}di,k∗​，对应信号为 δˉi,k∗\bar\delta_{i,k}^{*}δˉi,k∗​。这样做的直觉是：与多数视角冲突的孤立教师可能是噪声，不应让它单独决定信用；而在方向一致的教师中取最强信号，可以保留信息量，又不像直接融合那样把强弱不同的信号平均稀释。代价是这套规则是启发式的：三个视角、多数投票、取最大绝对值都没有理论保证；当某个教师信号恰为 0 时，论文的符号定义把它归入 +1+1+1，可能影响投票；轨迹末尾的 turn 在 d=2,3d=2,3d=2,3 时会被截断到同一个终止 turn，多个视角可能退化成相同或近乎空的上下文。论文没有分析这些边界情况，也没有报告三个深度被选中的频率。§4.3 的图 4 显示，固定使用 d=1d=1d=1 在平均上是三个固定深度中最好的，这一点会让“多前瞻互补”的解释打折扣，后文还会讨论。

3.4 组内归一化与有界符号感知加权

选出的 turn 级信号 δˉi,k∗\bar\delta^{*}_{i,k}δˉi,k∗​ 还不能直接拿来加权，因为它的绝对大小会受问题难度、轨迹长度、turn 位置和训练进程影响；同一个模型在不同 prompt 上的 gap 尺度可能差别很大（方法·组内归一化权重）。论文借用 GRPO 的组相对思想，在同一个问题的所有 sibling rollout 内做归一化：把该问题下所有有效 turn、所有有效策略 token 位置上的选中 gap 汇成一个池，计算共享均值 μqi\mu_{q_i}μqi​​ 和标准差 σqi\sigma_{q_i}σqi​​，再得到 δ^i,k=(δˉi,k∗−μqi)/(σqi+ϵ)\hat\delta_{i,k}=(\bar\delta^{*}_{i,k}-\mu_{q_i})/(\sigma_{q_i}+\epsilon)δ^i,k​=(δˉi,k∗​−μqi​​)/(σqi​​+ϵ)（方法·组内归一化权重、Appendix B）。这样信号衡量的是“当前 turn 相对于同组其他交互有多值得被教师认可”，而不是绝对 gap。需要注意，池化的是 token 位置；由于同一 turn 内信号被广播到所有 token，长 turn 在均值和方差中占的权重更大，这一点论文没有讨论。

3.5 训练与推理阶段

训练时，基础模型直接用 Qwen3-4B 或 Qwen3-8B 的基础检查点（base checkpoint），不做中间监督微调（SFT）；在 FTRL 的 2,215 个可执行工具任务上训练 3 个 epoch，每个优化 batch 含 32 个问题、每个问题采样 16 条轨迹，每条轨迹最多 10 个交互 turn，学习率 1×10−61\times10^{-6}1×10−6，不做显式 KL 正则，使用 8 张 A800-80GB（实验·设置、Appendix B）。教师和参考分支都从对应的策略 backbone 初始化并全程冻结；被训练的只有策略本身，没有额外的价值网络、选择器或教师参数（实验·设置、Appendix B）。哪些行为由模型决定、哪些由固定流程控制也很清楚：工具选择、参数和最终答案由策略生成；工具返回由环境给出；教师上下文拼接、turn 边界、token 聚合、符号投票、组内归一化和优势加权都由固定代码完成。

推理阶段没有教师，也没有前瞻上下文；部署的只是学到的策略，按普通的 Qwen3 工具调用格式与工具环境交互并输出答案（Appendix B）。因此 TurnSight 的额外开销集中在训练：每个有效 turn 需要三个教师视角各做一次覆盖整段回答的 teacher forcing，教师上下文还要额外容纳当前及后续 turn 的工具调用和返回。论文没有报告这部分 GPU 小时、token 数或训练时延，本报告 §4.4 会单独讨论这一缺口。

4.1 实验设置

总体增益。 Table 1 的总体平均是 FTRL、BFCL、ToolHop 三个基准 Avg. 的等权平均。8B 上 TurnSight 为 42.02，MatchTIR 为 39.03，绝对提高 2.99 分，相对提高 7.66%；4B 上为 37.51 对 34.76，绝对提高 2.75 分（相对 7.91%）。8B 相对上一强基线 SDAR 的 38.04 也高 3.98 分。这个量级与论文摘要所说的“7.7%”一致，是本报告认为最可信的效果证据。

分域表现。 8B 的增益主要来自 FTRL 与 BFCL：FTRL Avg. 46.92 对 42.78（+4.14），BFCL Avg. 37.56 对 33.78（+3.78），ToolHop Acc. 41.58 对 40.54（+1.04）。4B 同向：FTRL Avg. 41.00 对 35.91（+5.09；但表内三个分项 44.61、40.16、38.44 的算术平均是 41.07，表内 Avg. 少写了 0.07），BFCL 33.18 对 30.82（+2.36），ToolHop 38.29 对 37.56（+0.73）。域内增益最大、域外 BFCL 次之、ToolHop 最弱，说明方法对训练分布附近的工具交互更有效，跨工具集合的迁移有限。

逐列限定。 “consistently outperforms all baselines”（实验·结果）并不成立：4B 的 BFCL Base 上 TurnSight 50.50 低于 MatchTIR 51.00；8B 的 ToolHop 41.58 只比 SDAR 41.37 高 0.21。论文说最大改进出现在 BFCL 的 Long Context 与 Miss Parameter；按绝对分数，8B 的 FTRL Solve-P 从 40.88 到 46.99（+6.11），大于 LC 的 +5.50 和 MP 的 +5.00；4B 的 Solve-P +6.84 也大于 MP 的 +5.50。因此这句话只在“相对提升”或“困难子集”的宽泛意义上成立，不是按绝对分数排序的结果。

与自蒸馏基线比较。 8B 上 SDPO 33.39、RLSD 35.69、SDAR 38.04、SOD 32.23，TurnSight 42.02；4B 上分别为 27.61、31.02、33.55、26.06，TurnSight 37.51。SDAR 是最接近的对手，尤其在 8B ToolHop 上 41.37 对 41.58。由于 backbone 未完全对齐，这组比较适合说明“TurnSight 不弱于已有 OPSD”，不适合精确归因；最可信的因果比较仍是 TurnSight 对 MatchTIR。

统计稳定性。 论文没有给出 seed 数、方差、置信区间或显著性检验；Table 1 的许多差距在 1–3 分之间，8B ToolHop 的 +1.04、4B ToolHop 的 +0.73 在没有方差信息时不能视为稳定增益。消融和敏感性分析只在 8B、FTRL 上做，不能自动推广到 4B 或域外。“stable”“consistently”一类措辞强于证据。

4.3 机制证据

Table 2 在 Qwen3-8B 上逐一去掉核心部件：完整模型 FTRL Avg. 46.92；去掉 turn 级聚合降到 43.23（−3.69）；去掉组内归一化降到 43.65（−3.27）；把多教师选择换成单一固定深度教师降到 45.62（−1.30）。三个部件都有正贡献，turn 聚合与组内归一化的贡献最大，多教师选择最小。下面按本报告 §2 的四项创新逐一核对证据与替代解释。

（1）执行条件化 hindsight。 图 3 是论文对“教师该看什么”的直接比较：三种教师上下文——只看工具返回、工具返回加标准答案、只看标准答案——在 FTRL 四个指标上的热力图。它对应 §2 的第一项创新，也是全文最接近“机制证据”的实验。

图 3（论文 Fig. 3）：横轴是 FTRL 的 Solve-P、Solve-R、Solve-F1 与 Avg.，纵轴是三种教师上下文配置，颜色越深表示分数越高。只看工具返回时四项分别为 46.99、50.71、43.07、46.92，均为最高；加入标准答案后降到 40.87、43.92、37.89、40.89；只看标准答案时为 39.72、47.81、40.87、42.80。图中传达的机制主张是：与学生实际执行状态对齐的工具返回，比轨迹级的标准答案更适合评价单个 turn。

这组结果支持“工具返回优于标准答案”的现象，但把它解释成“状态对齐”仍有两个替代解释未被排除。第一，“工具返回+答案”同时增加了上下文长度和潜在的信息冲突，性能下降可能来自上下文变长或教师被两种信号拉扯，而不一定是答案本身与状态错位；论文没有做等长上下文或只加无关文本的对照。第二，工具返回本身可能包含最终答案（例如检索结果直接给出数值），这时教师看到的不只是“执行后果”，而是变相的结果监督；论文没有统计工具返回与标准答案的重叠率，也没有在“返回泄露答案”的子集上分开报告。此外，该图注没有注明 backbone，按所在小节的上下文推断为 Qwen3-8B，但论文没有明说。

（2）turn 级聚合。 Table 2 的 w/o turn-level aggregation 把教师信号改回逐 token 选择与调制，Avg. 从 46.92 降到 43.23（−3.69），是三个消融中最大的降幅。这支持“turn 级聚合有用”，但没有直接验证作者给出的因果机制——同一 turn 内 token 级信号符号冲突。论文没有报告冲突频率、冲突 token 的比例，也没有报告 δ\deltaδ 与该 turn 实际正确性（例如工具调用是否匹配参考、答案是否正确）的相关性。另一个混淆是：去掉 turn 聚合不仅改变粒度，也改变了后续组内归一化的池（从 turn 级均值变成逐 token 值），因此降幅不能全部归因于“turn 内一致性”。论文也没有比较 median、min、按工具调用 span 聚合等替代方案；均值可能把“工具选对但参数写错”的正负信号抵消，这一点在本报告 §3.2 已经提到。

（3）多前瞻与方向一致性选择。 图 4 比较固定前瞻 1、2、3 个 turn、教师融合与方向一致性选择。它对应 §2 的第三项创新，也直接检验“多前瞻互补”是否成立。

图 4（论文 Fig. 4）：四个面板分别是 Solve-P、Solve-R、Solve-F1 与 Avg.；蓝色为固定前瞻深度 LA1、LA2、LA3，绿色为教师融合，橙色为方向一致性选择。Avg. 上 LA1 45.62、LA2 44.83、LA3 42.30、融合 45.70、选择 46.92。图中可见两个事实：更长前瞻在平均上更差，融合只比最好的固定深度高 0.08，选择比 LA1 高 1.30。

这组结果并不完全支持论文的机制叙事。论文说不同深度提供互补信息、短深度看即时质量、长深度看延迟后果；但如果长深度真的携带互补信号，LA2/LA3 不应在平均上单调变差，融合也不应几乎等于 LA1。更合理的替代解释是：LA1 已经是噪声最小的教师，LA2/LA3 主要引入无关的未来交互；选择策略的 +1.30 可能来自“在方向一致时取最大 ∣δ∣|\delta|∣δ∣”这一幅度选择或锐化效应，而不是深度互补。论文没有报告每个深度被选中的频率，也没有报告选择策略在只有两个教师或不同投票规则下的表现。Table 2 的 w/o multi-teacher selection 为 45.62，与论文 Fig. 4 的 LA1 完全一致，说明它很可能就是 LA1；若是如此，消融比较是公平地对最强固定深度，而不是对最弱深度，但也意味着多教师机制的净增量只有 1.30 分。

（4）组内归一化与有界符号感知调制。 Table 2 的 w/o group normalization 直接把选中的 turn 级信号拿来调制，Avg. 降到 43.65（−3.27），说明尺度校准重要。但论文没有分别消融 tanh 有界、符号感知、λ\lambdaλ 插值这三件事：去掉有界性或去掉 sign 项都可能产生不同结果，而当前实验只证明了“整组归一化 + 有界符号感知调制”作为一个整体有用。更根本的是，组内归一化让同一 prompt 的 16 条轨迹互相耦合：一条轨迹的权重取决于同组其他轨迹的 δ\deltaδ 分布，因此它改变的不只是尺度，还可能改变不同 turn 在更新中的相对权重，进而改变优化目标的最优点；论文只证明了去掉归一化会掉分，没有分析这种耦合是否会把策略推向与原始 GRPO 不同的解，也没有收敛性论证。图 5 进一步给出 λ\lambdaλ 与 ϵw\epsilon_wϵw​ 的敏感性，但它只覆盖 8B、FTRL，且是单次运行。

4.4 成本、范围与证据边界

成本。 推理阶段没有教师，也没有前瞻上下文，部署开销与普通策略相同；额外成本集中在训练。每个有效 turn 需要三个教师视角各做一次覆盖整段回答的 teacher forcing，外加参考分支的前向；训练序列最长 13,000 token、最多 10 个 turn、每个 query 16 条 rollout，用 8 张 A800 跑 3 个 epoch。论文没有报告 GPU 小时、教师前向的 token 数、训练墙钟时间或相对 MatchTIR 的开销倍数，因此无法判断 2.99 分的总体增益是否以显著更高的训练成本换取。长时程场景下，教师上下文还要拼接未来 turn 的工具调用与返回，成本会随 turn 数和返回长度增长；方法是否适合 20–50 turn 的交互，论文没有数据。

范围。 实验只覆盖 Qwen3-4B/8B、FTRL 的 2,215 个训练任务、最多 10 个 turn、tool-only 教师上下文。BFCL Web Search 子集依赖 Serper API 获取搜索结果（Appendix B），属于外部服务，结果可能随搜索端点与网络状态变化；其余子集在本地执行环境评测。论文没有覆盖真实 API、网页之外的工具、多模态工具、跨会话记忆，也没有超过 10 turn 的长时程实验。ToolHop 的 +1.04（8B）和 +0.73（4B）说明跨工具集合的迁移有限，不能把 FTRL/BFCL 的增益直接外推到任意 agent 场景。

失败案例与分层分析。 论文没有失败案例分析，也没有按 turn 位置、轨迹长度、工具类型、是否发生执行错误分层报告；因此无法判断方法在哪些交互模式上失效，例如长轨迹末尾、工具返回噪声大、或答案藏在工具返回中的任务。论文也没有报告教师信号与真实 turn 质量的相关性，无法说明教师什么时候可信。

未报告的信息。 除上述训练成本与失败分析外，论文未报告：随机种子与方差、置信区间与显著性、每个前瞻深度被选中的频率、同一 turn 内 token 级信号的冲突率、教师上下文与标准答案的重叠率、不同模型规模下的消融、以及 checkpoint 选择准则。官方代码显示 Data/test.parquet 被用作验证并开启 save_best_only，且训练奖励函数用 gt_tool_call 做 Hungarian 匹配，这两点与论文“不依赖参考轨迹”的表述存在张力，下一节展开。

6. 审稿式总评

作者发现多轮 TIR 的轨迹级奖励难以区分一条轨迹内部各 turn 的贡献，且已有 OPSD 的特权信息（标准答案、参考轨迹）与学生在 rollout 中实际访问到的状态不对齐，因此提出 TurnSight：用学生自己当前及后续 turn 的工具调用与执行返回构造教师上下文，把 token 级对数概率差聚合成 turn 级信号，在 1、2、3 个前瞻深度上按符号多数与最大幅度选择，再在同组 16 条 sibling rollout 内归一化，以有界、符号感知的权重调制 RL 优势。实验在 FTRL、BFCL、ToolHop 和 Qwen3-4B/8B 上表明，TurnSight 相对 MatchTIR 的总体平均分别提高 2.99（8B）和 2.75（4B），域内 FTRL 与 BFCL 的增益较清楚，ToolHop 的迁移增益较弱；其中“turn 级聚合 + 组内归一化”的消融证据较强，“执行条件化优于标准答案”只有论文 Fig. 3 的现象支持，机制解释仍缺少直接测量；单 seed、测试集参与验证、论文—代码在 base advantage/参考轨迹上的不一致，使精确数值与“完全不依赖参考轨迹”的强结论缺少充分支持。本文最有价值的部分是把“执行后果”组织成可选择的 turn 级自蒸馏信号，并给出了一套可复现的工程实现与消融框架；最大的审稿风险是核心机制证据不足且评测卫生与披露存在问题。

  • 问题定义清晰度：强。引言把长时程 TIR 的信用分配拆成“状态对齐”和“交互粒度”两个要求，并用论文 Fig. 1 画出三类方法的差异；具体子问题（如何从多个回望视角得到可靠 turn 级信号）边界明确。扣分点仅在于“hindsight self-distillation”一词同时指信息源、聚合方式和调制方式，读者需要读方法部分才能分清。
  • 创新性证据：中。执行条件化教师、turn 级聚合、多前瞻选择、组内归一化都是已有组件的新组合，论文没有提出新的理论结果；与 SDPO/RLSD/SDAR/SOD 的差异清楚，但缺少与 SD-Search、TurnOPD、StepOPSD、SAGE-OPD 等最近邻方法的直接比较（质疑五）。
  • 方法可信度：中。机制直觉合理，实现简单，教师冻结、推理零开销；但 base advantage 的实际实现与论文方法描述不一致，turn 均值可能抵消混合信号，方向一致性选择是启发式，且没有与“总是用 LA1”拉开足够差距（质疑一、三）。
  • 实验支持力度：中。三个基准、两个模型规模、八个基线、三组消融和两组敏感性分析构成了较完整的证据面；但单 seed、无方差/显著性、FTRL 测试集参与验证与超参数选择、ToolHop 增益仅约 1 分，使“稳定、一致”的强结论缺少支撑（质疑二、四）。
  • 可复现性：中。代码、数据与超参数表公开，方法本身容易实现；但论文—代码在奖励函数、base advantage、entropy 系数和验证集使用上存在未披露差异，BFCL Web Search 依赖 Serper API，且没有训练日志/成本，复现出的数值可能偏离 Table 1（质疑一、二、四）。
  • 综合阅读价值：高。论文把“执行结果作为 turn 级特权信息”讲得清楚，论文 Fig. 3/论文 Fig. 4 的实验设计和 Table 2 的消融对做 agentic RL 的读者有直接参考价值；即使不完全接受其机制解释，也可以把 TurnSight 当作一个强 baseline 和一套可改造的工程模板。
