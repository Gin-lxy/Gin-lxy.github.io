0. 一句话结论

CoDA 把生成式仿真（generative simulation）和机器人动作策略（action policy）放进同一个闭环：数据引擎（data engine）生成可执行场景，策略在其上 rollout，视觉—语言批评器（vision-language critic）把失败诊断成“因素—阶段—原因—证据”，共享异构记忆（shared heterogeneous memory）把反复出现的失败聚成难度模式（difficulty mode），再编译成“造环境”和“训练策略”两类程序，后者通过 Text2potential 转成分段势函数（staged potential），为动作块（action chunk）价值学习提供密集监督；在四个 MuJoCo 操作任务族上，分布外（out-of-distribution, OOD）成功率从监督微调（supervised fine-tuning, SFT）的 5.3% 提升到 27.6%，比最强的标量反馈闭环基线高 9.5 个百分点，LIBERO-Pro 上 15 轮把位置与指令扰动下的成功率从 25%/1% 提升到 84%/76%。这些结果支持“按策略当前失败模式定向生成环境、并把诊断编译成密集监督”在仿真操作中有效，但主比较只对齐了被接受环境数量而非 token 与 GPU 成本，关键表格只有 3 个种子且缺少标准误，没有真机实验，代码尚未发布，因此还不足以支持“可扩展的机器人数据—策略共进化”这一更大结论。

1. 论文具体想解决什么问题？

生成式仿真已经让“造环境”不再是稀缺资源。编码智能体可以写场景、articulation 和任务规格，语言模型可以写奖励函数；真正的瓶颈变成了两个相邻的问题：下一步该造什么环境，以及用什么监督信号让策略从这些环境里学到东西（§1）。已有的环境生成方法大致沿三条路走：从人工设定的参数范围里采样变化，反复修场景直到物理上合法，或者按每个任务的成功率分配生成预算（§1、§2）。这三类信号能回答“环境是否合法”“当前策略表现如何”，却不能直接回答“策略在这个环境上训练后能进步多少”。没有学习进度（learning progress）的反馈，生成器很容易把预算花在策略已经掌握的简单环境，或者策略暂时学不动的过难环境上。

论文的核心问题是：能否让数据引擎和动作策略通过一份共享记忆共同进化，使生成的环境持续对准策略当前的失败模式，同时把失败诊断转化成可执行的训练监督？作者把这个问题拆成三个可操作的部分。第一，场景要被表示成可独立扰动、可被批评器定位的因子，否则“针对某个失败原因生成环境”无从谈起。第二，失败要被诊断到具体因子和轨迹阶段，并被控制实验验证，否则记忆里积累的只是批评器的猜测。第三，诊断要被编译成策略能用的训练信号，而不是只停留在自然语言建议；这需要把“失败原因”变成状态空间上的势函数，并与稀疏的任务成功谓词（success predicate）结合。

这条路线与几类已有工作相邻但不同。生成式仿真与 agentic scene generation 关注“如何造出合法、多样的场景”；环境课程学习（environment curriculum learning）与无监督环境设计（unsupervised environment design）关注“如何按学习进度选环境”；语言奖励合成与奖励塑造（reward shaping）关注“如何把任务描述变成密集奖励”；VLA 后训练关注“如何用更多数据或 RL 提升策略”。CoDA 的野心是把这四件事接成一个闭环：环境生成的选择依据来自策略 rollout 的诊断，诊断又同时喂给环境生成器和训练信号编译器，而学习进度再反过来评价环境是否有用（§1、§3）。论文没有提出新的策略网络或新的强化学习算法，它的主张是系统层的：把“数据引擎”和“策略”从两个独立优化的模块，变成一个由共享记忆耦合的联合过程。

需要先划清边界。论文的主实验是四个 MuJoCo 操作任务族（pick-place、articulated、put-inside、stack/insert），每个族有分布内评测和四个各 100 个环境的 held-out 套件，分别测试未见过的物体实例、布局、任务和类别；held-out 环境从不进入记忆（Appendix B）。第二个实验从 30 个 LIBERO 源任务出发，在 LIBERO-Pro 的位置与指令扰动上评测（§4、Appendix B）。这里的“OOD”是指在同一个仿真器、同一套资产池和同一个机器人平台内，对未见实例、布局、任务或类别的泛化；不是跨仿真器、跨机器人或真实世界的零样本迁移。论文也没有把 LIBERO-Pro 的结果称为零样本：策略确实在 LIBERO 源任务生成的变体上继续训练，LIBERO-Pro 是测试扰动鲁棒性的目标集。这个边界在后面讨论证据强度时很关键。

2. 创新点是什么？

第一，把“共享异构记忆”做成数据引擎和策略之间的共同接口。记忆分三层：情景层（episodic tier）记录每个场景程序、验证器、生成轨迹、成功率和学习进度；语义层（semantic tier）把反复出现的失败按“因子—轨迹阶段—原因”聚成难度模式，并记录硬度与重要性；程序层（procedural tier）为每个被验证的难度模式编译两类程序：生成程序（generation program）说明如何复现和扰动该难度，训练程序（training program）说明如何用子目标、势函数和学习工具帮策略克服它（§3.2）。这套分层本身借鉴了语言智能体的 episodic–semantic–procedural 记忆组织，但把“环境生成经验”和“策略失败经验”放进同一份记忆、让两个消费者分别检索，是本文最有辨识度的系统设计。

第二，Text2potential：把失败诊断编译成状态空间上的分段势函数，而不是自由文本奖励。批评器给出失败阶段 ppp 和原因 ccc，编译器把任务在该阶段切成 mmm 个子目标，为每个子目标生成完成谓词 donek\mathrm{done}_kdonek​ 和进度函数 φk\varphi_kφk​，再组合成分段势函数；最终完成谓词就是任务验证器 ν\nuν（§3.4）。与“让 LLM 直接写一个密集奖励”相比，势函数形式保留了任务奖励，理论上在固定势函数下不改变最优策略；与“用任务描述生成势函数”相比，这里的势函数条件在策略自己的失败证据上，因而更有针对性（§3.4、§4.3）。这是把“诊断”变成“可优化信号”的关键桥梁。

第三，按可测量的学习进度分配生成预算，并用控制批次验证诊断。每个难度模式有硬度 p^j\hat p_jp^​j​ 和重要性 wjw_jwj​，生成预算用上置信界（upper confidence bound, UCB）在模式间分配；预算的一部分留给新环境，一部分用于回放已见模式以检测回退；只有成功率落在 [0.2,0.8][0.2,0.8][0.2,0.8] 成功带内的生成程序才会被保留（§3.3）。对每个候选难度模式，引擎生成一批“只改被诊断因子”的目标批次和一批“改另一个因子”的控制批次；只有目标批次确实比控制批次更难，该诊断才被编译进程序层（§3.3）。这套“目标—控制”验证是对 LLM 诊断幻觉的直接防线，也是本文区别于普通 LLM 课程生成的地方。

第四，生成程序可以跨任务族“提升”（lifting）。生成程序用符号角色（target、obstacle、support）而不是具体物体来写条件；角色带类别或可供性要求，程序还带角色间关系约束。换到新任务族时，编译器把角色绑定到新场景的物体上，最多保留三个有效绑定，每个绑定生成一个变体及自己的控制批次； transferred program 仍要通过同样的物理合法性与成功带检查（Appendix A）。这把“在一个任务族学到的环境生成经验”变成可复用的程序，而不是只在新任务上重新提示 LLM。

这四点里，真正的新算法成分不多：记忆分层、课程学习、势函数塑造、UCB、代码生成都是已有组件。论文的贡献更像一次有明确约束的系统集成：用因子化场景把诊断、生成和训练对齐；用控制批次把 LLM 诊断变成可验证的假设；用两类程序把“环境难度”和“训练监督”分开存放。是否“首次”提出这些组合，需要更完整的文献检索；但作为系统设计，这套约束是清楚的。

3. 作者如何解决？

把 CoDA 想成一个由记忆驱动的研究循环：数据引擎是“会写仿真场景代码的智能体”，策略是“在场景里反复试错的学生”，批评器是“看 rollout 录像找失败原因的分析师”，记忆是“三者共用的实验记录本”。每一轮，记忆告诉引擎该复现哪些失败条件、该扰动哪个因子；引擎写出场景程序并做物理合法性检查；策略在合法场景上 rollout；批评器把失败定位到因子和阶段；控制批次检验这个定位是否真的对应难度；被验证的模式被编译成生成程序和训练程序；训练程序通过 Text2potential 变成势函数，塑造动作块价值学习的目标；训练后的策略再产生新的 rollout，学习进度回到记忆，决定下一轮预算。图 1 把这个循环放在一张系统图里。

3.1 场景表示与种子环境

种子阶段从一个物体池开始：有任务族资产就用任务族资产，否则从预定义池采样。给定物体后，引擎提出一个任务，写明指令、参与物体、初始/终止物体状态和可执行成功谓词 ν\nuν；没有验证器的提议会被丢弃（§3.1）。这一步很重要：它保证每个环境都有机器可判定的成功条件，而不是靠批评器主观判断任务是否完成。

场景被参数化为三个可独立编辑的因子 s=(τ,σ,α)s=(\tau,\sigma,\alpha)s=(τ,σ,α)：其中 τ\tauτ 是任务因子（目标谓词、指令、物体初始/终止状态），σ\sigmaσ 是物体—空间因子（位姿、支撑/包含关系、间隙、遮挡），α\alphaα 是物体自身属性因子（几何、尺度、质量、摩擦、articulation、外观）。仿真 SDK 暴露 set_task、set_layout、set_attributes 三个接口，引擎可以在固定另外两个因子的情况下重采样任意一个（§3.1）。这个因子化是后面所有机制的前提：批评器的诊断、引擎的干预、生成程序的适用条件都用同一套表示，所以“诊断说问题在空间遮挡”可以直接翻译成“只改 σ\sigmaσ 的目标批次”。

每个场景程序在执行前要通过三类物理检查：无碰撞放置、短时间被动仿真下的静态稳定、合理的度量尺度。失败的场景不会进入策略 rollout，但仍留在记忆里，供后续生成参考（§3.1）。这一步把“物理合法”与“对训练有用”分开了：合法只是入场券，是否有用要靠后面的控制批次和学习进度判断。

3.2 共享异构记忆

记忆有两个来源：引擎的构造/修复轨迹，以及策略的 rollout 结果与失败诊断。按语言智能体记忆的 episodic–semantic–procedural 组织，CoDA 保留三类记录（§3.2）。

情景层是一个只追加的轨迹库 B\mathcal{B}B，记录每个场景程序 ggg、验证器 ν\nuν、生成轨迹摘要（违反的约束、验证结果）；对已部署环境，还记录 NNN 次 rollout 的成功率 p^(s)\hat p(s)p^​(s) 和训练带来的学习进度 LV(s)\mathrm{LV}(s)LV(s)（§3.2）。批评器 C\mathcal{C}C 看场景与 rollout 证据，输出失败诊断 ψ=(δ,p,c,e)\psi=(\delta,p,c,e)ψ=(δ,p,c,e)，其中 δ∈{\textsctask,\textscspatial,\textscattribute,\textscexecution}\delta\in\{\textsc{task},\textsc{spatial},\textsc{attribute},\textsc{execution}\}δ∈{\textsctask,\textscspatial,\textscattribute,\textscexecution} 是归因因子，ppp 是轨迹阶段，ccc 是自然语言原因，eee 是支持证据；额外的 execution 标签专门记录运动执行失败，避免把“夹爪没抓住”误归因成场景太难（§3.2）。诊断和对应轨迹一起存入情景层。

语义层把情景记录在线聚成难度模式 Kj\mathcal{K}_jKj​：聚类键是因子—阶段对 (δ,p)(\delta,p)(δ,p) 加诊断原因的相似度。一个模式可以跨任务和策略骨干复现，例如“目标接近侧旁边有一个遮挡物”。每个模式有两个量：硬度 p^j\hat p_jp^​j​ 是当前策略在该模式上的成功率，越低越难；重要性 wjw_jwj​ 是由模式级学习进度更新的运行分数，学习进度定义为训练前后策略在该模式上成功率的变化（§3.2）。这两个量刻意分开：一个模式可以一直很难但训练收益很小，也可以在被训练后变得容易；生成预算应该优先给“还有学习空间”的模式，而不是单纯最难的。每个模式还带一个由控制批次决定的验证状态，只有被验证的模式才能进入程序层（§3.2、§3.3）。

程序层把同一个被验证模式编译成两种互补程序。生成程序存在 Ω\OmegaΩ 里，编码如何复现和扰动被诊断的场景条件，保留父场景程序、沿单一因子的已验证变体、编译检查结果，以及用符号角色表达的关系结构；训练程序存在 Φ\PhiΦ 里，指定如何通过子目标分解、势函数和学习工具解决策略失败，保留诊断阶段和“哪些训练程序真的提升了策略”的证据（§3.2）。生成编译器是 Rgrind\mathcal{R}_{\mathrm{grind}}Rgrind​，训练编译器是 Rhone\mathcal{R}_{\mathrm{hone}}Rhone​，后者就是 Text2potential（§3.4）。部署时，训练好的策略只从观测和指令预测动作，不执行这些程序；程序是训练期的脚手架，不是推理期的控制器（§3.2）。

3.3 记忆引导的场景生成

每一轮，记忆决定“ revisit 哪些难度模式”和“如何在新区境里实例化它们”。生成预算按模式的硬度与学习进度用 UCB 分配；一部分预算（ε=0.15\varepsilon=0.15ε=0.15）留给全新环境，另一部分（0.10）用于回放已见模式以检测性能回退（§3.3）。一个生成程序只有在它的变体上策略成功率落在 [0.2,0.8][0.2,0.8][0.2,0.8] 成功带内时才进入 Ω\OmegaΩ，离开成功带时被移除（§3.3）。这个成功带的作用是双重的：太低说明当前策略学不动，太高说明已经掌握；两种都不值得继续花生成预算。

对每个被选中的候选难度模式，引擎生成两批环境：目标批次只改被诊断的因子（例如只改 σ\sigmaσ 中的遮挡关系），控制批次改另一个因子（例如只改 α\alphaα 中的外观）。两批都通过物理检查后，当前策略在每批上 rollout；如果目标批次的成功率低于控制批次，说明“这个因子确实是难度来源”，该模式才被编译成可复用的生成/训练程序（§3.3）。如果目标批次并不更难，诊断被拒绝，记忆里会留下这次反证。这个设计把 LLM 的因果判断变成了一个可重复的对照实验，是全文最值得借鉴的工程细节之一。

生成程序还能跨任务族复用。程序用符号角色写条件：角色 target 可能要求 graspable 或某个类别，角色 obstacle 要求占据目标的接近路径，角色 support 要求可支撑；换到新场景时，编译器把角色绑定到场景符号表里的不同物体，检查类别、可供性和关系约束，最多保留三个有效绑定，每个绑定生成一个变体及自己的控制批次（Appendix A）。绑定是穷举匹配，程序最多五个角色、场景几十个物体，匹配在毫秒级； transferred program 仍要通过物理检查、成功带和控制比较，才会进入新任务族的 Ω\OmegaΩ（Appendix A）。论文把这种跨族复用称为 lifting。

4.2 主结果：OOD、LIBERO-Pro 与 scaling

先看四个 MuJoCo 任务族的 OOD 结果（Table 1）。CoDA 平均 OOD 成功率 27.6%±0.5%，SFT 只有 5.3%±0.3%，域随机化 7.9%±0.4%，均匀变体 8.5%±0.2%，按成功率引导的标量反馈闭环 18.1%±0.5%，用本文批评器但没有记忆 19.2%±0.7%。相对最强的闭环基线，CoDA 高 9.5 个百分点；相对无记忆变体高 8.4 个百分点。四个任务族上 CoDA 都是最高：pick-place 33.1%、articulated 24.7%、put-inside 28.9%、stack/insert 23.7%；相对标量反馈的增益分别是 +12.2、+9.4、+9.3、+7.1 个百分点。这个“四个族都赢、且增益幅度相近”的模式，比单一平均分更能说明生成策略不是只对一个任务族有效。

4.3 消融：批评器、Text2potential、记忆与迁移

先看批评器的影响（Table 3）。固定引擎和编译器，只换诊断模型：GPT-5.5 27.6%±0.5，Claude Opus 5 26.1%±0.6，InternVL3-78B 25.7%±0.7，Qwen3-VL-235B 24.9%±0.8；对应的控制实验拒绝率是 18.2%、20.3%、24.1%、27.5%，与两个人类标注者的一致率是 82.4%、81.5%、76.3%、73.8%。四个模型都高于标量反馈的 18.1%，即使最弱的 Qwen3-VL-235B 也高 6.8 个百分点。这个消融说明框架对诊断模型有一定容忍度，但也说明诊断质量确实影响最终性能：最好与最差相差 2.7 个百分点，且拒绝率从 18.2% 升到 27.5%。论文没有报告这四个模型在 token 成本上的差异，而 GPT-5.5 是其中最强的闭源模型，这使“默认配置”的结论带有模型依赖。

Text2potential 的消融更能说明“诊断条件”与“势函数形式”各自的作用（Table 4）。只用稀疏验证器时 OOD 22.3%±0.8，达到 25% OOD 需要 31k 次策略更新；用任务描述生成势函数是 24.6%±0.7、29k 次；自由形式的密集奖励（不是势函数）是 23.5%±1.0、33k 次；冻结策略、只用 QϕQ_\phiQϕ​ 做动作块选择是 21.4%±0.9；Text2potential 去掉 refinement 是 26.1%±0.6、27k 次；完整方法是 27.6%±0.5、21k 次，与稀疏批评器的动作块选择一致率 97.2%。完整方法相对稀疏验证器少用约 32% 的策略更新（31k→21k），这个效率提升比 5.3 个百分点的成功率提升更稳健。自由形式密集奖励比稀疏还差、冻结策略的 Q-only 选择也低于稀疏，说明“有密集信号”本身不够：信号必须是与任务完成对齐的势函数，而且必须通过策略更新把价值变成行为；只做候选块选择不够。

图 4 进一步拆开学习动态。面板 (a) 在相同的 pick-and-place 生成数据上比较“有势函数塑造”和“只有稀疏奖励”：塑造让分布内成功率更早达到约 60%，比稀疏条件早约 20,000 次策略更新，但两者的最终成功率接近。这说明势函数主要是加速学习，而不是提高分布内的最终上限；OOD 的提升更多来自数据引擎选对了环境，而不是势函数单独带来的。面板 (b) 是两个价值批评器在动作块选择上的一致率，训练结束时约 97%，说明塑造后的价值排序与稀疏价值排序在最终趋于一致，符合“势函数不改变最优策略”的理论预期。面板 (c) 是 OOD 成功率随记忆里已验证模式数的变化：同时保留生成程序和训练程序最高，单独保留任一类都低约 10 个百分点。这个曲线是“记忆累积—性能”的机制证据，但横轴是已验证模式数，不是独立的环境数或 token 数，因此不能直接读出“每增加一个模式值多少算力”。

图 4（论文 Fig. 4）：这张图把 Text2potential 的作用从“最终分数”拆成三个过程量。面板 (a) 的横轴是策略更新步数，纵轴是 pick-and-place 的分布内成功率；实线是有势函数塑造，虚线是稀疏奖励，塑造曲线在早期更陡，约 20k 步前达到相同水平，最终两者收敛到相近高度。面板 (b) 的横轴是训练步数，纵轴是两个价值批评器在动作块选择上的一致率，从早期的约 20% 上升到接近 97%，说明塑造主要改变学习早期的价值排序，而不是最终的价值函数。面板 (c) 的横轴是记忆里已验证的难度模式数，纵轴是 OOD 成功率；同时保留生成程序 Ω\OmegaΩ 和训练程序 Φ\PhiΦ 的曲线最高，单独保留任一类都低约 10 个百分点。读图时要注意：这三张图分别对应“学得更快”“最终价值排序趋同”“两类程序互补”，它们共同支持 Text2potential 的机制解释，但不能单独证明 OOD 增益来自势函数，因为 OOD 还依赖生成器选环境。

记忆设计的消融在 Table 5。无记忆 19.2%±0.7，达到 25% OOD 需要 14 轮；只保留生成程序 Ω\OmegaΩ 是 22.8%±0.7、9 轮；只保留训练程序 Φ\PhiΦ 是 22.1%±0.8、11 轮；单记忆的三种替代——原始轨迹检索 20.1%、蒸馏洞见 21.6%、技能库 21.0%——都低于两类专用程序；Φ\PhiΦ 用自由形式奖励代替势函数是 24.3%±0.9、8 轮；Ω\OmegaΩ 不做 lifting（只保留任务绑定程序）是 25.4%±0.6、7 轮；完整方法 27.6%±0.5、5 轮。论文强调完整方法相对无记忆的 8.4 个百分点增益，大于单独保留 Ω\OmegaΩ 的 3.6 与单独保留 Φ\PhiΦ 的 2.9 之和（6.5），因此称两类程序是“超加性”的。这个说法在方向上合理：生成程序提供“去哪练”，训练程序提供“怎么练”，两者确实互补；但单程序变体只保留一类程序，记忆容量和编译预算也更少，超加性可能部分来自“程序总数/总 token”而非纯粹的机制互补，后文会继续讨论。

跨任务族迁移（Table 6）是本文比较有说服力的部分。把在源任务族学到的生成程序通过符号角色绑定到目标任务族，不重新学习程序；与“在目标任务族用相同 LLM token 预算从零学程序”相比，复用程序平均达到族内学习进度的 60.3%，从零只有 35.8%，而且每一个跨族组合都更好。例如 pick-place→put-inside 达到 79%，put-inside→pick-place 81%，stack/insert→pick-place 70%，articulated→pick-place 52%。跨策略骨干迁移（Table 7）也成立：用 π0.5\pi_{0.5}π0.5​ 收集的记忆直接训练 OpenVLA-OFT，OOD 从无记忆 SFT 的 3.8% 升到 21.1%；反方向从 5.3% 升到 25.8%；两个方向都落在目标骨干完整 CoDA 的 2 个百分点以内（21.1 对 22.7、25.8 对 27.6），且不再生成新环境。这说明记忆里的难度模式和训练程序在一定程度上是策略无关的；但 Table 7 只有两个骨干、3 个种子，且迁移方向的记忆是冻结的，不能说明记忆会随新骨干继续进化。

生成质量与诊断验证（Table 8）给出中间过程的量化：均匀变体的物理合法性 71.3%、覆盖熵 3.42 bits、目标命中率 24.6%；CoDA 是 88.9%、3.18 bits、66.7%；不用控制批次的 CoDA 变体是 88.2%、3.21 bits、58.4%，与人类标注一致率 73.6%；完整 CoDA 的拒绝率 18.2%、人类一致率 82.4%。物理合法性和目标命中率都明显提升，覆盖熵略低（3.18 对 3.42，约低 7%），说明“更瞄准当前失败”确实以少量多样性为代价；论文说“保持广泛覆盖”有点宽松，读者应把它理解为“覆盖没有大幅塌缩”，而不是“覆盖不变”。控制批次把目标命中率从 58.4% 提到 66.7%、人类一致率从 73.6% 提到 82.4%，但它对最终 OOD 成功率的贡献没有单独报告；“无控制”变体只有中间指标，没有跑完整训练，因此不能判断验证门是否真的提升了策略学习。

成本（Table 9）是理解这篇论文定位的关键。按每 1,000 个被接受环境计，均匀变体用 3.1M LLM token、14.2 仿真小时、38 GPU 小时，OOD 8.5%；标量反馈用 4.6M、22.5、51，OOD 18.1%；CoDA 固定调度用 8.3M、27.8、74，OOD 26.1%；CoDA 自适应调度用 7.4M、25.1、66，OOD 27.6%。自适应调度相对固定调度省约 11% 的 token 和 GPU 时间，还把 OOD 从 26.1% 提到 27.6%。相对标量反馈，CoDA 的 OOD 高 9.5 个百分点，但 token 是 1.6 倍、GPU 小时是 1.3 倍、仿真小时是 1.1 倍；论文的“52% 相对提升”是成功率相对提升，不是成本调整后的效率。这个成本结构本身不意外：诊断、编译和额外的策略更新都要钱；但它决定了“共进化”是否值得，后文会把它列为主要质疑之一。

4.4 定性结果、成本与证据边界

图 5 展示数据引擎生成的场景变化：四个种子任务（工具分拣、餐盘摆放、手工台整理、面条准备），每个种子给出三个幅度递增的空间扰动、一个目标尺寸变化和一个目标物体替换。所有展示的变体都通过物理合法性检查。这张图的价值在于说明生成程序如何“只改一个因子”：空间扰动改变 σ\sigmaσ，尺寸变化和物体替换改变 α\alphaα，任务语义 τ\tauτ 保持不变；这正是 §3.3 的目标批次构造方式。它也让读者直观看到“难度”可以来自很小的布局变化（5 cm 偏移）或很大的变化（43 cm、1.65× 尺寸），而这些变化在视觉上仍然合理。但图 5 只展示合法变体，没有给出每个变体的策略成功率或难度标签；这些信息在聚合的 Table 8 和 Table 2 里，不能从图中读出。

图 5（论文 Fig. 5）：这张图是生成程序的“因子干预”在四个任务上的具体样子。每个 2×3 的面板组对应一个种子任务：第一行是种子场景、小幅空间偏移、中幅空间偏移；第二行是大幅空间偏移、目标尺寸变化、目标物体替换。读者应把它读成“同一个任务语义下，空间因子和属性因子被分别扰动”的矩阵，而不是六张无关的漂亮场景。空间偏移改变的是物体相对位置和接近路径，尺寸变化改变的是抓取/放置的几何尺度，物体替换改变的是类别与外观但保留角色；三者都对应 §3.1 的 (τ,σ,α)(\tau,\sigma,\alpha)(τ,σ,α) 分解。所有变体都通过无碰撞、静态稳定和尺度检查，说明生成器不是随意摆放；但图没有标注每个变体的成功率，因此不能判断这些变化是否都落在“可学习”的成功带内。

图 6 补充了更多成功 rollout：左侧是五个 LIBERO-Pro 任务（番茄酱→篮子、奶油奶酪→篮子、巧克力布丁→篮子、酒瓶→柜子、盘子→柜子），右侧是一个水果准备种子场景和五个变体（5 cm、19 cm、43 cm 偏移、0.75× 尺寸、苹果→手电筒替换）。它与图 3 的结构相同，功能是展示策略在更多物体和变体上的阶段化执行。两张图都只展示成功案例，没有失败案例、失败阶段分布或逐变体成功率；这使得它们只能作为“机制看起来在工作”的定性证据，不能作为“方法稳定”的统计证据。

图 6（论文 Fig. 6）：这张图与图 3 是同一类证据的扩展。左半部分是五个 LIBERO-Pro 任务，右半部分是一个水果准备种子和五个生成变体；列仍然是初始、抓取、运输、放置、成功。它想说明策略的动作序列在不同物体、不同空间偏移和不同目标替换下都遵循子目标结构，且最终完成任务。读图时应关注“变体改变了什么、策略仍然做了什么”：空间偏移改变接近路径，尺寸变化改变抓取高度和放置间隙，物体替换改变类别但保留“可抓取/可放置”的角色；策略的成功说明这些变化没有破坏任务语义。和图 3 一样，这张图只展示成功轨迹，不能回答“失败率多少”“失败集中在哪个阶段”“生成的变体是否都难而可学”；这些要靠 Table 2、Table 8 和 §4.3 的消融。

把证据边界收拢一下。第一，所有实验都在仿真里：四个 MuJoCo 任务族和 LIBERO-Pro 都是仿真环境，机器人是 Franka Panda，观测是干净的 224×224 RGB，没有真实传感器噪声、接触不确定性或人类干预；Appendix D 明确承认“迁移到物理机器人仍待建立”。第二，批评器用的是仿真特权信息：rollout 视频、接触信息、关节状态和每步验证器输出；真实机器人上接触信息和任务验证器都不是免费可得的。第三，held-out 套件虽然隔离了未见实例/布局/任务/类别，但仍共享同一个仿真器、同一套资产池和同一个生成器；“OOD”不等于跨域。第四，LIBERO-Pro 不是零样本：策略在 LIBERO 源任务的生成变体上继续训练，Table 2 衡量的是对位置/指令扰动的鲁棒性，而不是“完全没见过的任务”。第五，绝对 OOD 27.6% 和分布内 39.4% 说明方法仍处在“提升很明显、但能力有限”的阶段；+9.5 个百分点是相对基线的信号，不是可用性的证明。这些边界不否定论文的贡献，但决定了它的结论应该被读成“仿真内的系统可行性”，而不是“通用机器人数据引擎”。

5. 最容易受到审稿人质疑的地方

质疑：主比较没有做算力匹配，“同样的生成预算”只是同样的被接受环境数

  • 原文依据：摘要说 CoDA 比最强闭环基线高 9.5 个百分点，且“with the same generation budget”（§Abstract）；§4 说生成基线使用相同的 SDK 和预算；但 Table 9 明确给出每 1,000 个被接受环境的成本：CoDA 自适应调度 7.4M LLM token、25.1 仿真小时、66 GPU 小时，标量反馈 4.6M、22.5、51，均匀变体 3.1M、14.2、38；CoDA 的 token 是标量反馈的 1.6 倍，GPU 小时是 1.3 倍。Table 1 的“same generation budget”对齐的是每族 320 个被接受环境，而不是总 token、总仿真时间或总 GPU 小时；Text2potential 的编译、批评器诊断和额外策略更新都计入 CoDA 的成本，但基线的成本结构不同（Appendix B、Table 9）。
  • 为什么重要：论文的核心主张是“共享记忆引导的共进化”比“按成功率引导的标量反馈”更会选环境、更会训练；如果 CoDA 只是花了更多 LLM 调用和 GPU 时间，那么 +9.5 个百分点可能来自“更多算力”，而不是“更好的分配原则”。这直接决定读者应该把 CoDA 当成方法创新，还是当成一个昂贵的系统。成本表的存在说明作者意识到了这个问题，但主表没有给出等成本比较，正文也没有讨论“每美元/每 GPU 小时的 OOD 增益”。
  • 当前能够得出的判断：原文事实是 CoDA 在 Table 9 中确实更贵，且论文没有报告等 token/等 GPU 的标量反馈基线；作者主张“same generation budget”下比较公平；审稿人判断是这个预算口径只对齐了环境数量，不能排除算力解释。无法确认的是：如果把标量反馈的 token/GPU 提高到与 CoDA 相同，它能否接近 27.6%；论文没有给出这条 scaling 曲线。Table 1 中“无记忆但用本文批评器”的 19.2% 是一个有用的中间点，但它也不是等成本对照。
  • 如何验证或补强：在相同 LLM token、相同仿真小时、相同 GPU 小时的预算下重跑标量反馈、均匀变体和域随机化；或者给出“OOD 成功率 vs 累计 token/GPU 小时”的 Pareto 曲线，让读者看 CoDA 是否在同等成本下更优，而不是只在同等环境数下更优。还应把诊断、编译、生成、策略更新四类成本分开报告，做 leave-one-cost-out 的缩放实验；如果 CoDA 的优势在等成本下消失，论文的贡献应改述为“在给定环境数下更强的数据选择”，而不是“更高效的共进化”。
  • 严重程度：主要问题。

  • 严重程度：主要问题。

质疑：只有仿真、没有真机，批评器依赖仿真特权信息，“OOD”仍在同一仿真器与资产池内

  • 原文依据：Appendix D 明确写“Our evaluation also focuses on simulated manipulation. Transfer to physical robots remains to be established, particularly for tasks sensitive to differences in contact dynamics, sensing, and actuation.” 四个任务族是 MuJoCo，LIBERO-Pro 也是仿真；机器人是 Franka Panda，观测是前后两个 224×224 RGB，动作是 7 维末端位姿增量，没有真实传感器噪声或接触不确定性（Appendix B）。诊断模型接收 rollout 视频、接触信息、关节状态和每步验证器输出（Appendix B）；这些输入在真实机器人上要么不可得（接触力、精确关节状态），要么需要额外的感知/标定（任务验证器）。held-out 套件隔离了未见实例/布局/任务/类别，但共享同一个仿真器、同一套 Objaverse/ArtiCraft/TableVerse 资产池和同一个生成器（Appendix B）。
  • 为什么重要：论文的标题和摘要面向“robot manipulation”和“action policies”，读者很容易把结果外推到真实机器人。但 CoDA 的核心信号——失败诊断——依赖仿真特权信息；如果去掉接触信息、关节状态和验证器输出，批评器的诊断质量可能大幅下降。Table 3 已经显示诊断模型从 GPT-5.5 换到 Qwen3-VL-235B 会掉 2.7 个百分点，而真实部署的输入退化可能比换模型更严重。另一个问题是“OOD”的含金量：同一仿真器、同一资产池内的未见类别，和跨仿真器/跨机器人/真实世界的分布偏移不是一回事；论文没有给出资产池与 held-out 类别的重叠审计。
  • 当前能够得出的判断：原文事实是全部实验在仿真中，批评器使用特权输入，作者在 Appendix D 承认真机迁移未验证；作者主张方法面向机器人操作，但没有声称已经真机部署；审稿人判断是证据支持“仿真内的数据—策略共进化”，不支持“真实机器人可用”或“跨 embodiment 泛化”。无法确认的是：held-out 类别是否真的与训练资产池完全不相交；生成器是否在 held-out 套件上做过任何形式的调参；真实传感器噪声下诊断与势函数编译是否仍然有效。
  • 如何验证或补强：在真实 Franka 或类似平台上做 sim-to-real 迁移，至少覆盖抓取、放置和一种 articulation 任务；把批评器的输入从“视频+接触+关节状态+验证器”逐步退化为“仅视频”或“视频+本体感知”，测量性能下降；加入相机噪声、光照变化、标定误差和物体物理参数扰动；用与训练资产池不相交的物体类别和布局做 held-out；如果目标是跨 embodiment，至少换一种夹爪或机器人，报告共享记忆是否仍然有效。
  • 严重程度：主要问题。

质疑：消融没有做等容量/等 token 的因子设计，“超加性”和验证门的因果贡献没有被隔离

  • 原文依据：Table 5 比较完整方法（27.6%）与只保留 Ω\OmegaΩ（22.8%）、只保留 Φ\PhiΦ（22.1%）、单记忆替代（20.1–21.6%）等；论文说完整方法相对无记忆的 8.4 个百分点增益大于单独保留 Ω\OmegaΩ 的 3.6 与 Φ\PhiΦ 的 2.9 之和（6.5），因此是超加性（§4、Appendix C）。但这些单程序变体只编译一类程序，记忆容量、程序数量、LLM 编译 token 都可能少于完整方法；论文说“same fixed generation budget”，但没有说程序数量/编译 token 是否对齐。Table 8 的“CoDA, no controls”只报告物理合法性 88.2%、覆盖 3.21 bits、目标命中 58.4%、人类一致率 73.6%，没有报告 OOD 成功率；因此控制批次验证对最终策略学习的贡献没有被隔离。Table 9 的固定/自适应调度是一个好的消融，但 UCB 分配、成功带 [0.2,0.8][0.2,0.8][0.2,0.8]、新环境/回放比例、8 个模式的触发阈值都没有单独消融。
  • 为什么重要：论文的卖点是“共享记忆让生成和训练互相促进”，而“超加性”是这一卖点最强的量化表述。如果完整方法只是拥有更多程序/更多 token，那么超加性就退化为“更多容量更好”，不能说明两类程序的机制互补。验证门是另一个核心设计：如果它只提高中间指标（目标命中率、人类一致率）而不提高最终 OOD，那么它的价值主要是可解释性/安全性，而不是性能。缺少这些消融，读者无法判断系统的哪一部分是真正必要的，也无法复现“该在哪里花预算”的建议。
  • 当前能够得出的判断：原文事实是两类程序各自都优于无记忆，完整方法最好；作者主张两者超加性；审稿人判断是方向可信，但当前设计不能把“互补机制”与“程序容量/编译 token”分开。无法确认的是：在等程序数、等编译 token、等策略更新次数的条件下，超加性是否仍然存在；控制批次验证是否真的提升最终 OOD；UCB 与成功带是否比简单的均匀分配更好（Table 9 的固定/自适应只比较了调度，不是分配规则）。
  • 如何验证或补强：做等容量/等 token 的 2×2 因子设计（有/无 Ω\OmegaΩ × 有/无 Φ\PhiΦ），把程序数和编译 token 对齐；报告“OOD vs 程序数/编译 token”的曲线；让“no controls”变体跑完整训练并报告 OOD、诊断拒绝率和失败阶段分布；对 UCB、成功带、ε\varepsilonε、回放比例、8 模式阈值做逐一消融或至少做敏感度分析；报告每个组件的成本，给出“在固定预算下先加哪个组件”的建议。
  • 严重程度：主要问题。

质疑：代码未发布、三角色绑定 GPT-5.5，势函数最优策略保证只对固定势函数成立

  • 原文依据：项目页（https://plan-lab.github.io/projects/coda/）标注 “Code (coming soon)”，没有公开仓库、prompt、生成的场景程序或日志；论文打印的项目地址 https://plan-lab.github.io/coda 返回 404（实际页面是 /projects/coda/）。数据引擎、失败诊断和势函数编译三个角色都使用 GPT-5.5（Appendix B）；Appendix D 承认“Results may also vary with changes to the underlying models, making model versions and configurations important for reproducibility.” Table 3 显示换批评器会掉 2.7 个百分点，拒绝率从 18.2% 升到 27.5%。§3.5 的最优策略保证写的是“For a fixed, bounded potential with appropriate terminal-state handling, potential-based shaping preserves the policies that maximize the original task return”；但 Text2potential 会跨轮次修订势函数（refinement 还会在同一轮内根据收敛情况重编译），因此该保证不适用于整个自适应过程；论文自己也说“This property concerns exact values; the effect of shaping on the learned critic and policy is assessed through subsequent policy progress.”
  • 为什么重要：这是一篇以“数据引擎”为核心的系统论文，代码、prompt 和生成程序是方法的一部分；没有它们，独立研究者无法验证 27.6% 或 LIBERO-Pro 的 84%/76%，也无法判断生成程序的质量是否依赖 GPT-5.5 的特定行为。三个角色都绑定闭源模型，使“用开源模型复现”变得不确定；Table 3 只是批评器的敏感性，没有替换引擎和编译器。理论方面，势函数保证是论文为 Text2potential 提供的主要理论支撑；如果势函数在训练中不断变化，那么“保留最优策略”的保证就不能直接套用到 CoDA 的完整循环，读者需要区分“单次势函数的性质”和“自适应系统的性质”。
  • 当前能够得出的判断：原文事实是没有公开代码、三个角色都用 GPT-5.5、势函数会跨轮修订；作者主张框架对诊断模型有一定容忍度、势函数形式有理论依据；审稿人判断是可复现性弱，理论保证的适用范围比论文的叙述窄。无法确认的是：用开源模型替换引擎/编译器后，生成程序的质量和最终 OOD 会下降多少；势函数跨轮修订是否会破坏策略不变性，还是只在早期加速学习；项目页的 “coming soon” 是否会在论文接收后兑现。
  • 如何验证或补强：发布代码、prompt、生成的场景程序、势函数程序、诊断日志、评测脚本和资产清单；至少用一组开源模型（如 Qwen3-VL 作为批评器、一个开源编码模型作为引擎/编译器）跑完整流程，报告与 GPT-5.5 的差异；对势函数跨轮修订做消融（固定第一轮势函数 vs 每轮修订），测量最终策略与原始任务最优策略的偏差；把“固定势函数下的策略不变性”和“自适应循环的经验效果”分开陈述，避免读者把前者当成后者的证明。
  • 严重程度：次要问题。

6. 审稿式总评

CoDA 解决的是一个真实且重要的问题：生成式仿真让环境不再稀缺，但“该造什么环境、该怎么教策略”仍然没有闭环。论文的答案是共享异构记忆：把场景构造经验、策略失败诊断和学习进度放在同一份记忆里，让数据引擎和策略训练分别消费；再用 Text2potential 把诊断编译成状态空间上的分段势函数，用动作块价值学习把密集信号变成策略更新。这个系统设计有几个值得借鉴的点：因子化场景让诊断、生成和训练共享表示；目标/控制批次把 LLM 诊断变成可验证的假设；生成程序用符号角色跨任务族 lifting；成功带和学习进度让生成预算跟着策略的“可学习性”走，而不是只看难度或成功率。实验上，四个 MuJoCo 任务族的 OOD 从 SFT 的 5.3% 提到 27.6%，四个族都赢；LIBERO-Pro 15 轮把位置/指令扰动下的成功率提到 84%/76%，并在 Goal/Spatial 套件上超过 ASPIRE；跨任务族和跨策略骨干的记忆迁移也有可观的增益。这些结果足以支持“在仿真操作中，按失败模式定向生成环境 + 诊断编译密集监督”是一个有效方向。

但证据的边界也很清楚。主比较只对齐了被接受环境数，没有做等 token/等 GPU 的算力匹配；CoDA 比标量反馈贵 1.6 倍 token、1.3 倍 GPU 小时，+9.5 个百分点不能直接归因于“更聪明的分配”。关键表格只有 3 个种子，LIBERO-Pro 和迁移表没有标准误，细粒度消融的 1.5–2.7 个百分点差距可能落在噪声里。全部实验在仿真中，批评器使用接触、关节状态和验证器等特权输入，真机迁移未验证；“OOD”仍在同一仿真器、同一资产池内，LIBERO-Pro 也不是零样本。消融没有做等容量/等 token 的因子设计，“超加性”和控制批次验证的因果贡献没有被完全隔离。代码尚未发布，三个核心角色绑定 GPT-5.5，势函数最优策略保证只对固定势函数成立。这些不是边角问题，而是决定“CoDA 是一个可复用的方法，还是一个特定配置下的系统演示”的关键。

对读者的建议：如果你在做机器人数据生成、环境课程或 VLA 后训练，这篇论文的系统结构值得细读——尤其是“诊断到因子/阶段”“目标/控制批次验证”“生成程序与训练程序分开存储”“用势函数而不是自由奖励”这几个设计选择；它们可以独立于具体数字被复用。但如果你要找的是“已经验证的通用机器人数据引擎”，当前证据还不够：应把 27.6%、42.1%、84%/76% 当作仿真内的系统信号，而不是真实世界或跨平台的能力证明；在复现或扩展时，优先补等成本比较、多种子统计和真机/去特权输入的实验。

  • 问题定义清晰度：强。论文把“造什么环境、用什么监督”拆成可操作的因子、诊断、验证和编译四步，因子化场景与失败诊断共享表示，问题边界（仿真、held-out 套件、LIBERO-Pro 扰动）也写得比较清楚；不足之处是“共进化”更多是系统叙事，没有形式化定义或收敛性分析。
  • 创新性证据：中。共享异构记忆、Text2potential、学习进度分配、目标/控制批次和跨任务族 lifting 组合起来有辨识度，且每个组件都有消融；但记忆分层、课程学习、势函数塑造、UCB、代码生成都是已有概念，论文没有与“独立的环境生成器 + 独立的奖励设计”在等算力下正面对照，“首次提出”的主张需要更完整的文献检索。
  • 方法可信度：中。管线细节充分，势函数在固定势函数下的性质、控制批次的验证逻辑、成功带与学习进度的分配都能自洽；但批评器依赖仿真特权输入，势函数跨轮修订使理论保证的适用范围变窄，若干超参数（成功带、ε\varepsilonε、回放比例、8 模式阈值）没有敏感度分析。
  • 实验支持力度：中。四个任务族 + LIBERO-Pro + 跨任务族/跨骨干迁移，覆盖面在同类工作中算宽；主效应大且方向一致，跨族迁移和跨骨干迁移是亮点；但只有 3 个种子，关键表缺标准误，没有等成本比较，没有真机，定性图只展示成功案例，绝对 OOD 27.6% 仍偏低。
  • 可复现性：弱。项目页标注代码 “coming soon”，没有公开 prompt、生成的场景程序、势函数程序、日志或评测脚本；三个核心角色都绑定 GPT-5.5，Asset 与 held-out 类别的重叠审计也未给出；论文打印的项目 URL 还是 404。独立复现当前的核心数字很难。
  • 综合阅读价值：中。对做机器人数据引擎、环境课程、VLA 后训练和 agent memory 的读者，这篇论文提供了一个结构清晰的系统蓝图，几个工程约束（因子化、控制批次、两类程序分离、势函数而非自由奖励）可以直接借鉴；但阅读时应把 +9.5 个百分点、42.1% 和 84%/76% 当作有边界的仿真信号，而不是已经验证的通用能力。
