0. 一句话结论

这篇论文把 ARC-AGI-3 这类”规则未知、只能靠交互摸索”的视觉游戏重新表述为视觉问题，用一个不含任何可训练参数的 visual harness（视觉外部脚手架，下称 harness）：模型每步只看最新一帧，全部历史帧以原图形式存在模型上下文之外的无损视觉记忆里，模型在推理中途随时调用工具把历史帧调出来看或放大局部。在不做程序合成的前提下，Claude Opus 5.0 在 25 个公开游戏上取得 RHAE 100.00（相对人类动作效率满分）、比首次游玩的人类少 57.4% 动作，GPT-5.6 Sol 取得 99.00。方法可行性这一层证据较强（分档消融、跨 4 个基准、开源权重模型复现），但机制归因（到底是哪一部分在起作用）与统计稳定性仍有缺口，且结论严格限定在”模型本身的推理能力已经具备、只差合适脚手架”这一前提之下。

1. 论文具体想解决什么问题？

研究背景与任务。 ARC-AGI-3（arXiv:2603.24621）是一组交互式视觉游戏：规则、目标、可用动作都不给出，智能体必须在多关卡、数百步的交互中自己发现对象角色、转移规则与隐藏状态，并把前面关卡学到的知识迁移到新关卡（§4.1 Dataset）。这是”长时程（long-horizon）”任务：一条轨迹动辄上千次动作，信息在整条轨迹上分布。

现有方法怎么做。 论文把已有路线分成两支（§1、§2）：一支是语言路线——把环境状态转成文本网格（每格一个颜色编号）或结构化表示交给 LLM，再用程序合成（program synthesis）把环境抽象成可执行、可验证、可搜索的符号程序来指导动作（Schema、Retrodict、Tycho、ewma_sv_v1.6 等，Table 1）；另一支是多模态路线——VLM 直接看截图（computer-use agents、SIMA/Cradle/Game-TARS 等游戏智能体），但这些系统通常只保留有界的视觉上下文，或把过去经验选择性压缩。

现有方法具体差在哪。 作者指出两个具体机制（§3 开头，论文 Fig. 1b）：其一，现有 VLM 把每张图编码一次就把原图丢掉，得到的视觉表示可能是”压缩的、有损的”，未必保留后续推理才需要的信息；其二，随着上下文填满，早期观测会被删除或被文本摘要替换，而且模型无法控制保留什么。作者补充了一条更根本的理由：在编码时刻，模型自己也不知道哪块视觉信息以后有用——某个阶段够用的表示，可能在后面几步就不够用了。因此在长时程交互中，模型的推理能力会被”看不见旧画面”这件事限制住。

新观察 vs 一般问题。 需要区分三层：① “长时程交互中上下文有限”是早就存在的一般问题；② 本文相对新的观察是”多模态模型把图像一次性编码后无法回头重看，且重看哪一块应当由模型在推理时决定”，并把它形式化为”模型对交互历史缺少显式注意力”；③ 本文真正动手解决的子问题是：在没有程序合成、且不训练任何模型的前提下，让一个通用多模态模型在 ARC-AGI-3 上达到接近甚至达到人类首次游玩水平的动作效率。

证据强度说明。 论文观察到的”现象”是基线分数低（官方最小 harness 下 Opus 5.0 high 只有 RHAE 40.68、GPT-5.6 Sol max 只有 13.33，Table 1）；”编码有损”则是作者的解释性主张，论文没有直接测量表示损失（例如比较不同编码下重建图像或信息量），所以因果解释并未被充分验证——目前能确认的是”改了输入与记忆方式之后分数大幅上升”，而不是”分数低就是因为编码有损”。

核心假设。 如果给模型原始视觉观测 + 上下文之外的无损记忆 + 由模型自己决定取用哪些帧/哪些区域的工具，那么模型已有的视觉推理能力就能被释放出来，在陌生交互环境中完成长时程任务，而无需把环境写成程序。作者在 Limitations（§6）中明确承认：模型自身能力仍是成功的关键因素，VISTA 只是”引出（elicit）”这种能力的方式。

图 1 把上述三种设计并排画出，是理解本文问题定位的最短路径。

图 1（论文 Fig. 1）：论文用三条数据流对比三种智能体设计。语言智能体把环境压成文本交给 LLM 再出动作，信息通道最窄；多模态智能体虽然接了图像，但图像经 ViT 编码成视觉表示后进入 LLM，表示被压缩且只编码一次，出动作之后原始像素就不再可得；VISTA 则把 VLM 放在一个回路里——模型在每次行动之前可以反复调用视觉工具，工具返回的”视图”再喂回同一个 VLM，形成”看—取—再看”的迭代，直到模型决定行动。三者差别不在基础模型规模，而在VLM 与环境之间那条数据通道是否可反复回访；这也解释了为什么本文把贡献定位为 harness 设计而非模型能力。

由此，论文要验证的事情可以压缩成一句可证伪的话：在完全不构造可执行世界模型、也不训练任何组件的前提下，仅靠改变视觉输入的组织方式，通用多模态模型能否在陌生交互环境中达到人类首次游玩的动作效率。第 2 节先识别这套设计相对已有工作的真实增量，第 3 节再展开它的运行流程。

2. 创新点是什么？

真正的技术增量可以概括为：把”记忆”和”注意力”从模型内部搬到模型外部，并用工具接口把它们交给模型自己调度。VISTA 没有训练任何参数、也没有新增网络结构，它的新增物是一套围绕通用多模态模型的交互协议与外部存储。按论文自己强调的三项组件（§3.1），逐项说明增量边界：

（1）无损视觉记忆（lossless visual memory）。 新增的是一个 harness 侧的全量帧归档：环境返回的每一帧——包括一次动作产生的中间动画帧——都以原始分辨率原样存下，并按 turn（回合）与 frame（帧）编号索引，在整个交互过程中始终可寻址（§3.1，论文 Fig. 3b）。与最接近的已有做法的差异是”存什么”：现有游戏智能体要么只保留有界视觉上下文，要么把过去经验压缩成文本摘要、技能库或检索条目；VISTA 保存的是不可再生的原始像素。它对应的问题是”模型不知道以后需要哪块细节，因此不能预先决定压缩什么”，用”不压缩、按需取”来回避这一取舍。证据指向 §4.3 的消融阶梯（configuration (v)）与 §4.4 中模型跨 22 个回合一次性取回 4 帧的例子。

（2）模型导向的视觉检视（model-directed visual inspection）。 新增两个只读工具：inspect 可以在任意历史帧上截取任意矩形区域并放大返回（空间上），也可以一次取回任意多个历史回合的帧（时间上）；read_pixels 则把选定区域按网格切分，直接返回每个格子的像素/调色板数值（§3.1，附录 A.4）。与已有视觉智能体的差别是谁在选：官方 ARC-AGI-3 协议是每个动作后自动附带最多 7 帧，模型被动接收；VISTA 只自动给最后一帧，其余全由模型在推理中主动索取。作者把它称为对交互历史的”explicit attention mechanism（显式注意力机制）”。这一项对应的问题是”模型需要在自己推理到某一步时，才决定重看什么、放到多大”，证据同样落在 §4.3 的 (v)/(vi) 两档。

（3）视觉优先的任务重表述与跨环境可移植的接口。 论文把 ARC-AGI-3 从”文本网格 + 程序合成”改写为”渲染图像 + 自然语言推理 + 工具调用”，默认观测是官方 64×64 帧经 8× 最近邻放大得到的 512×512 PNG（§4.3）。与最接近的已有方法（同样不做程序合成的官方最小实现）的具体差异是观测通道与记忆机制整条替换；与程序合成路线的差异则是不构造任何显式世界模型。作者称 VISTA 是”首个不做程序合成就能达到满分或接近满分的系统”（Table 1 标题）。该设计还带来一个可移植性主张：同一套工具接口与同一份简短提示模板只需替换动作空间描述，就能迁移到浏览器游戏与静态视觉问答（§5，附录 A.5）。证据指向 §4.2 的跨基准结果与 §4.3 的文本网格/图像对照。

需要明确划界的是：连续对话 + 原生上下文压缩、以及两个笔记文件 GUIDE.md/WORKING.md，是消融阶梯上与上述三项并列的独立组件（configuration (iii) 与 (iv)），论文把它们描述为”最小记忆机制”，并未列为核心创新；把它们算作 VISTA 的方法贡献、但不当作新颖点，是更稳妥的读法。此外，本文不做训练，因此”用更大的基础模型””换数据集或指标”这类增量在这里都不适用——贡献完全落在推理期系统设计上。本节证据的一句话指向：§4.3 给出逐档消融，§4.2 给出跨基准结果。

3. 作者如何解决？

直觉。 VISTA 的起点是一个很朴素的判断：在交互式任务里，”哪块画面以后有用”往往要到后面才知道，所以让模型在编码时刻就决定压缩什么，是注定要吃亏的。作者于是做了个反转：不去改进编码，而是把上下文里的图像减到最少、把完整历史放到上下文之外，然后把”看什么、看多大、什么时候看”的决定权交还给正在推理的模型。这样模型当前上下文只承担”推理”的负荷，视觉证据则存放在一个模型可以随时点名调取的外部档案里。论文把这个外部档案叫 lossless visual memory（无损视觉记忆），把模型点名调取的动作叫 visual inspection（视觉检视）。这里的 “harness” 指的是包在通用模型外面、决定它能看见什么、能做什么的那层运行时框架——它本身不含可训练参数，只是机械地执行模型发出的工具调用（§3.2 明确写道：”The harness is purely mechanical and does not involve any trained model”）。

输入是什么。 每一步，智能体收到三样东西：① 当前视觉状态——一帧 512×512 的 PNG（消融默认设置，由官方 64×64 帧做 8× 最近邻放大得到，约 308 个图像 token）；② 当前可用的动作列表；③ 它自己维护的两份笔记——GUIDE.md 记录跨关卡、跨会话可复用的游戏理解，WORKING.md 是当前关卡的草稿纸。ARC-AGI-3 的动作空间是 RESET 加 ACTION1..7，其中 ACTION6 是带 (x, y) 坐标的点击（附录 A.4，Algorithm 1）。

一个回合里发生什么。 关键设计是：一个游戏回合并不会消耗一次模型调用。同一个回合之内，模型可以与 harness 做多轮交换——想看就看、想放大就放大、想记笔记就记笔记——直到它调用 play 执行一个游戏动作，环境才前进一步（§3.2，论文 Fig. 3d）。工具集由宿主侧的一名单一控制器（host-side controller）统一执行；这个控制器持有环境连接、帧档案和两份笔记，并且是唯一有权限推进游戏的组件，它还强制串行：上一次 play 的结果没有返回给模型之前，新的 play 不会被接受（附录 A.4）。这套”回合内自由、回合间严格串行”的划分，是为了防止模型在还没看到动作后果的情况下盲目连发动作。

数据在工具之间怎么流动。 每个回合结束时，控制器把本回合所有返回帧（含中间动画帧）写进档案，并给每张图打上 turn 与帧索引标签。模型随后可以用三类只读工具回访这些标签：inspect(question, views) 按 {label, turn, frame, region={x,y,w,h}} 取任意归档帧的任意矩形区域，裁剪并放大后返回图像；read_pixels(question, views) 把选定区域切成行列网格，直接返回数值化的像素/调色板读数；history(view, start_turn, end_turn, limit) 返回精确的动作/结果记录（view=”events”）或当前关卡每个 attempt 的摘要（view=”attempts”，一次 attempt 从进入关卡或 RESET 开始，到 GAME_OVER / WIN / TERMINAL 结束）。写侧只有 play（唯一改变环境的工具）与笔记写入类工具（write_guide、write_working、save_compact_checkpoint）；inspect、read_pixels、history、读取笔记全是只读，不花费游戏动作。

哪些由模型决定，哪些由固定流程控制。 这是理解 VISTA 的关键分界。模型决定：是否检视、检视哪一帧哪一区域、放多大、何时写笔记、写什么、最终选哪个动作；它还用自由文本推理，并在每次 play 之前先写下”我预期看到什么”、之后写下”实际发生了什么变化”（附录 A.5 Prompt 1），这实际上是把”预测—校验”循环写进了提示模板。固定流程决定：工具的执行、帧的归档与编号、动作的串行化、以及上下文压缩的触发——当上下文接近上限时，控制器会暂停普通工具使用，要求模型先把继续所需的状态存下来（Codex 里调用 save_compact_checkpoint，Claude Code 里由 pre-compaction 钩子触发 write_working），然后模型在一个全新的上下文里带着 GUIDE.md、WORKING.md、动作历史和当前帧继续工作（§3.2，附录 A.4）。注意这里的分工：上下文会丢，档案不会丢——压缩只影响模型眼前看到的推理历史，视觉记忆、动作历史和笔记都跨上下文边界存活。

要不要训练。 完全不训练。VISTA 是 training-free 的系统设计：论文没有微调、没有 SFT 样本、没有强化学习奖励设计，所有能力都来自被冻结的通用多模态模型，harness 只负责喂图、存帧和执行工具。这一点在消融中也很清楚——消融的对象是 harness 配置，而不是模型参数。

模型与 harness 怎么接。 为了不让模型绕过工具直接读文件或写代码，接入层做了约束：在 Claude Code 中，工具通过 MCP server 暴露并禁用全部内置工具；在 Codex 中，同样的工具直接注册到 app server；两种情况都跑在没有环境凭证的沙箱容器里。两者有个实现差异：Claude Code 能把工具返回的图片直接放进 MCP 结果，而 Codex 的工具输出只能是文本，因此控制器把对应的图片作为同一回合的独立内容另行提供（附录 A.4）。这是”同一套 harness、两种宿主”的工程细节，但它说明 VISTA 的工具语义并不依赖某个特定 CLI。

输出。 一步输出就是一次 play（或跨基准时的 act）以及随之更新的笔记；整条轨迹则是一串游戏动作。在 ARC-AGI-3 上就是驱动 25 个游戏直至通关；在 GameWorld / AI GameStore 上改为通过键鼠（computer-use 接口）操作浏览器游戏；在 BabyVision 这种静态任务上，交互退化为”先检视再回答”，模型用 inspect/read_pixels 取完证据后给出答案，且不使用持久笔记（§5.1，附录 A.5 Prompt 3）。这说明该 harness 的抽象不是”游戏动作”，而是”在推理过程中重新组织视觉输入”——动作只是它的一个特例。

图 2 把上面这套流程拆成组件图与单回合时序图两部分，是把 §2 三项创新落到具体部件上的那张图。

图 2（论文 Fig. 3）：这张图把 VISTA 的组件定义和它的运行时形态放在一起。组件层面它回答三个问题——模型的视觉输入从哪来（环境渲染出的画面直接作为观测进入模型，不再先转成数字文本）、画面放在哪（每一帧返回后都以原分辨率、按回合与帧索引存入模型上下文之外的档案，任何时刻可按编号寻址）、以及怎么取回（模型可以要求任意一段历史的多帧，或某一帧的某个矩形区域被裁剪放大后送回）。运行时层面，单个回合被拆成观察、推理、行动三段，而真正把这三段与两个外部存储（代理笔记、视觉记忆）串起来的是挂在存储上的可选调用箭头：read/update 通往笔记，inspect/read_pixels 通往视觉记忆；图中标注为 optional 的箭头都不由 harness 自动触发，而是模型在推理途中自行决定是否插入，唯一强制执行的通路是”上一帧成为下一次观测”。读者应从中看出，VISTA 相对既有系统增加的主要是可选的回访通路，而不是更多的自动输入——这也正是它与官方实现”每步自动附带多帧”最本质的差别。

默认配置与”官方实现”的差别。 为后续结果作铺垫：默认设置是 GPT-5.6 Sol max 推理档 + 200K token 上下文 + 512×512 观测 + 每局最多 2,000 动作、48 小时。作为对照的官方最小实现（organizers’ official implementation）则把观测压成文本网格、保留最多 7 帧中间状态、维护 175K token 上下文且超出后丢弃最早回合（即没有长期记忆），并对 Claude Opus 5.0 / GPT-5.6 Sol 限制每局 2,000 动作（附录 A.1）。两者的差别不止”有没有视觉”，还包括记忆、动作上限与中断策略——这会在 §4.3 的消融解读中变得重要。

4. 解决得怎么样？

4.1 实验设置

评测任务。 主战场是 ARC-AGI-3 的 25 个公开游戏；通用性验证另选三个基准：GameWorld（34 个浏览器游戏、170 个任务，指标为成功率 SR 与进度 PG）、AI GameStore（10 个公开浏览器游戏，把每个游戏的原始分按其公布的人类中位数归一后取几何平均，人类中位数对应 100）、BabyVision（388 道静态视觉推理题中选取两个 Visual Tracking 子类共 39 题——20 道迷宫 + 19 道连线，指标为准确率）。前两个是交互式的，BabyVision 是静态的，用来把”交互”这一因素拿掉后单独考察视觉检视（§5.1）。

模型与配置。 主结果是两个闭源通用多模态模型：Claude Opus 5.0（xhigh 推理档，经 Claude Code CLI）与 GPT-5.6 Sol（max 推理档，经 Codex CLI）；另用开源权重模型 GLM-5.3 Flash 320B（经 Codex CLI，动作上限放宽到 3,000）做一次独立复现（§4.1，§4.3）。消融的默认设置是 GPT-5.6 Sol max + 200K token 上下文 + 512×512 图像观测 + 每局 2,000 动作/48 小时（§4.3）。

基线。 分三类：① 官方最小实现，把观测压成文本网格、保留最多 7 个中间帧、175K 上下文且超限即丢弃最早回合、无长期记忆（附录 A.1）——这是”同样不使用程序合成”的同模型对照；② 并发工作的程序合成系统 Schema、ewma_sv_v1.6、Retrodict、Tycho，直接引用其报告分数（Table 1）；③ 跨基准上各自的人类参考（GameWorld 为一名未接触过游戏的计算机研究生、AI GameStore 为 106 名 Prolific 参与者的中位数、BabyVision 为 16 名成年人的加权均值 92.3%）（附录 A.6）。

指标。 核心指标 RHAE（Relative Human Action Efficiency，相对人类动作效率）把智能体动作数与首次游玩人类的上中位数比较。单个已完成关卡得分为 Sℓ,g=min⁡(1.15,(hℓ,g/aℓ,g)2)S_{\ell,g}=\min\left(1.15,\left(h_{\ell,g}/a_{\ell,g}\right)^{2}\right)Sℓ,g​=min(1.15,(hℓ,g​/aℓ,g​)2)，其中 aaa 是智能体动作数、hhh 是人类参考动作数（用平方是为了放大效率差异）；未完成的关卡计 0 分；第 ℓ\ellℓ 关权重为 ℓ\ellℓ，越靠后的关卡越重要；整局得分被”已完成关卡的加权占比”封顶，因此 100.00 是该指标的满分（附录 A.3）。论文同时报告总动作数，用来区分 RHAE 相同但效率不同的运行。

各实验回答什么。 §4.2 主实验回答”这套 harness 能不能让通用模型做到”，§4.3 消融回答”是哪一部分在起作用”、并额外考察上下文大小、图像分辨率、3D 渲染和开源模型，§4.4 用定性轨迹回答”模型怎么用这套工具”，附录 A 补配置与提示细节、附录 B 补三次重复运行的方差与逐游戏结果。

4.2 关键结果

主结果（ARC-AGI-3，25 个公开游戏）。 Claude Opus 5.0 + VISTA 取得 RHAE 100.00，25 个游戏每一个都是满分，总动作数 7,302，是人类参考 17,135 动作的 0.43 倍（少 57.4%）（§4.2 正文、Table 1、附录 B.2 Table 2）。作为对照，同一个模型在官方最小实现（文本网格、无长期记忆）下只有 40.68（Table 1）。GPT-5.6 Sol + VISTA 取得 RHAE 99.00、9,126 动作（0.53×），同样完成全部 25 个游戏；相对地，该模型在官方最小实现下只有 13.33，且只完成了 4% 的游戏、用了 10,619 次动作（Table 1、论文 Fig. 5 的斜线柱）。这两组数字是本文最主要的证据。

唯一明显掉队的单局。 逐游戏表（附录 B.2 Table 2）显示 GPT-5.6 Sol 在 25 个游戏中有 24 个拿到 100.00，唯独 ls20 只有 75.03，用了 1,135 次动作、达人类参考的 1.46 倍；Claude Opus 5.0 在同一局拿到 100.00 且只用 458 次动作。也就是说 99.00 这个均值掩盖了一个”效率反而不如人类”的单点失败。

与程序合成系统的横向比较。 Table 1 中 Schema 为 95.35、ewma_sv_v1.6 为 98.97、Retrodict 为 99.86、Tycho 为 100.00（均在程序合成一栏为 Yes）。VISTA 的 99.00 / 100.00 与它们同档，但并未超过 Tycho；作者的主张严格来说是”首个在不做程序合成的情况下达到满分或接近满分的系统”，而不是总体最优。

跨基准迁移（最小改动）。 把同一套 harness 换到另外三个基准（§5.2）：GameWorld 上 VISTA 的成功率 **63.3%**、进度 **79.3%**，官方实现为 40.0% / 62.9%，人类新手为 55.3% / 64.1%——即超过官方实现也超过新手人类，但进度只比人类高约 15 个百分点；AI GameStore 上归一化几何平均为 140.3（人类中位数 = 100），官方实现为 47.3；BabyVision 上准确率从官方 one-shot 的 41.0% 提升到 **63.2%**，但与人类 92.3% 仍有很大距离（论文 Fig. 11，附录 A.6）。这三组数说明”可迁移”成立，但迁移后的绝对水平差异很大：在静态视觉任务上，检视工具的收益明显不足以补齐人类与模型之间的差距。

图 3 给出跨基准结果的完整对照，包括每个基准的人类参考和”此前最佳报告值”两条参照线。

图 3（论文 Fig. 11）：这张图先给出三个基准的环境截图，用来标出任务形态的差异——GameWorld 与 AI GameStore 是需要键鼠长期操作的浏览器游戏，BabyVision 只给一张静态图和一道题，没有交互历史可供回访；随后用四张柱状图把每个基准下人类参考、官方最小实现与 VISTA 摆在同一把尺子上，并以虚线标出该基准此前的最佳报告值（其中 BabyVision 的 25.7% 甚至低于官方实现本身）。读这张图要分开看两条落差：官方实现与 VISTA 之间的落差，衡量的是同一模型换用不同 harness 之后的增益，这是本文真正要主张的东西；人类参考与 VISTA 之间的落差，衡量的是方法离人类还有多远，其中 GameWorld 的两项指标上 VISTA 已经超过人类参考，而 BabyVision 上仍明显落后。把”换 harness 带来的增益”与”模型能力上限”分开读，是理解本文结论边界的关键。

其余单点结果。 ① 3D 渲染：把同样的游戏渲染成 3D 后 RHAE 降到 84.12，动作数涨到 20,640（2D 为 99.00 / 9,126），作者称仍大幅优于文本基线（§4.3，论文 Fig. 9）。② 开源权重模型：GLM-5.3 Flash 320B 上 VISTA 取得 66.93，去掉 inspect 与 read_pixels 的版本只有 13.27，官方实现 1.89（§4.3，论文 Fig. 8）——这是唯一一条不依赖闭源模型的证据，但绝对水平明显低于闭源结果。③ 观测表示：把图像换成文本网格后 RHAE 为 96.75（图像 99.00），动作数 10,614（图像 9,126），而每局 token 从 30.7M 涨到 71.9M（§4.3，论文 Fig. 6）。④ 上下文大小：100K / 200K / 500K / 780K 对应 RHAE 98.6 / 99.0 / 94.4 / 93.9，每局 token 为 17.3M / 30.7M / 84.1M / 105.7M（论文 Fig. 7a）。⑤ 图像尺度：2× / 4× / 8× / 16× 对应 RHAE 96.6 / 99.7 / 99.0 / 88.3（论文 Fig. 7b）——注意默认的 8× 并非最优，4× 反而更高且每局 token 从 30.7M 降到 28.2M。⑥ 方差（附录 B.1）：GPT-5.6 Sol 重复三次得 99.04 ± 0.17（99.00 / 98.90 / 99.23），GameWorld 为 63.33 ± 2.37% SR、79.30 ± 2.14% PG，BabyVision 为 63.23 ± 3.00%；AI GameStore 三次聚合为 119.99 / 148.58 / 140.06，论文按该基准官方的多次运行协议先按游戏平均原始分再归一，报出 140.3。Claude Opus 5.0 的 100.00 只有单次运行，论文未报告其方差。

4.3 机制证据

主结果只是”有效”，消融才触及”为什么有效”。 论文最强的机制证据是论文 Fig. 5 的六档递进消融（同一模型 GPT-5.6 Sol max、同一 200K 上下文与观测配置），它把 harness 一个部件一个部件加上去：官方文本网格 13.33 → (i) 换成渲染图像 47.32 → (ii) 放宽动作与时间上限 51.66 → (iii) 连续对话 + 原生上下文压缩 65.82 → (iv) 加入两份笔记 70.05 → (v) 加入无损视觉记忆与模型导向检视 94.10 → (vi) 加入精确像素读出 99.00。设计意图上每档只叠加一个组件，因此这条阶梯比单纯的”我们比基线高”要强得多；但其中最大的一跳同时改动了帧投递方式，这一点在下面单独讨论。

图 4 把这六档在三个指标上的变化并排画出，是判断”哪一部分贡献最大”的直接依据。

图 4（论文 Fig. 5）：这张图用 RHAE、25 个游戏的总动作数和通关游戏比例三个指标衡量六档递进的 harness 配置，横轴共用同一批配置标签，另有一条斜线柱作为论文引用的官方文本网格成绩这一外部参照。读它的关键是看相邻两档之间的落差而不是终点：从文本网格到图像、到放宽动作与时间上限、再到引入连续对话与笔记，前三步把 RHAE 从 13.33 推到 70.05，同时动作数先升后降、通关率从 4% 升到 76%，说明这部分增益主要来自”跑得完、记得住”；随后一步加入无损视觉记忆与检视工具，RHAE 一次性跳到 94.10、动作数腰斩到 12,261、通关率达到 96%，曲线形状正是在这一档发生质变。因此这张图同时说明了两件事：视觉记忆与检视是主要推力，而在它们之前的所有配置，都不足以让游戏被稳定完成。

逐项核对其对 §2 三个创新的支持。 ① 无损视觉记忆 + 模型导向检视：由 (iv)→(v) 支撑，单步 +24.05 RHAE，是全阶梯最大的一跳；但这一步同时改变了帧投递方式——配置 (i)–(iv) 按官方协议每步自动附带最多 7 帧，配置 (v)–(vi) 只自动给最后一帧、其余靠模型索取（论文 Fig. 5 标题明确写出这一点）。也就是说 24 分的增益混合了”新增记忆与检视”和”从被动多帧改为主动取帧”两个变量，论文没有做只改其中之一的对照。② 精确像素读出（read_pixels）：由 (v)→(vi) 支撑，单步 +4.9 RHAE，这是被最干净隔离的一项。③ 视觉观测：由官方 13.33 → (i) 47.32 支撑（**+33.99），作者的机制解释是 token 效率——7 帧请求下文本观测约 28K token、图像约 2.2K，留给推理的上下文更多（附录 A.2）。但论文 Fig. 6 显示，在完整 harness** 下文本网格能拿到 96.75、图像 99.00，两者只差 2.25 分，说明”换成图像”的净收益在完整系统里远小于 (i) 那一跳所暗示的幅度。这两组证据之间的张力论文没有讨论。

图 5 正是这个张力的来源，它把两种观测表示放在完全相同 harness 下对照。

图 5（论文 Fig. 6）：这张图要回答的不是”哪种观测表示更强”，而是”视觉表示到底买到了什么”，因此它把同一个游戏状态的两种表示——被广泛使用的 64×64 颜色编号文本网格与直接渲染出的 2D 图像——放在完全相同的 harness 下对照，并给出 RHAE、总动作数与每局平均 token 三组读数。前两组读数上两者几乎持平（99.00 对 96.75、9,126 对 10,614），差距被压在很小的范围内；真正被拉开的是 token 消耗，文本网格每局 71.9M、图像每局 30.7M，相差一倍以上。由此得到的判断是：在这套 harness 下，视觉观测的主要回报是上下文预算而不是推理上限，这一点也顺带解释了消融第一档为何涨得那么猛——那一档相对官方实现的优势，很可能同样来自 token 预算，而不只是”看的是图像”这件事本身。

定性机制证据。 §4.4 与论文 Fig. 10 给出模型实际使用记忆的两个例子：一次是在棋盘重置后，模型用单次 inspect 调用取回此前 22 个回合中的四帧，把它们拼起来重建地图；另一次是对三个很小的方块做约 13× 放大，从而分辨每个方块侧面是否带紫色标记、进而确定朝向（§4.4，论文 Fig. 10）。这两例说明工具确实被使用、且用途符合设计意图（跨时间整合 + 空间细节），但它们是被挑选出来的成功示例，论文没有统计 inspect/read_pixels 的调用分布、也没有报告”模型在什么条件下不用工具”。

图 6 展示了上述两次回访的具体形态，用来确认”显式注意力”不是纸面概念。

图 6（论文 Fig. 10）：这张图用两个互补的片段展示模型如何主动使用存档的画面。一个片段是跨时间的回访：棋盘被重置会抹掉眼前的画面，模型于是把重置前若干回合的存档帧一次性取回，用这些帧把地图重新拼出来，图注中”1,472 frames kept so far”也顺带交代了档案规模的量级。另一个片段是空间上的回访：全图分辨率下无法判断的小方块，被放大十几倍后其侧面标记才变得可辨，模型据此确定每个方块的朝向并安排处理顺序。两个片段都附上了模型自己的提问与结论，读者应从中看到一个完整闭环——模型先提出一个需要视觉事实才能回答的问题，再指定要看的帧与区域，拿到返回图像后更新自己的结论；这正是”把注意力外置、由模型自行调度”落到具体行为上的样子。

证据能排除哪些替代解释。 配置 (ii)–(vi) 使用相同的 2,000 动作 / 48 小时预算，因此动作与时间上限在阶梯内部是被控住的；但总 token 消耗在阶梯上没有对照（论文 Fig. 5 不报告 token，论文 Fig. 7a 显示上下文上限越高 token 越高而分数反而下降），也就无法排除”多花 token 换分数”这一解释。此外，论文对”现有编码有损、不足以支撑后续推理”这一根本解释没有任何直接测量——没有重建实验、没有信息量对比，只有”改了观测与记忆方式后分数上升”这一间接链条。§2 三项创新中，read_pixels 有干净的单变量支持，无损视觉记忆与主动检视有强但混杂的支持，视觉表示的必要性支持最弱。

4.4 成本与适用范围

训练成本。 没有。VISTA 全程不训练、不微调，只有推理期开销，也没有人工标注（附录 A 未报告任何标注流程）。

推理开销。 论文报告的是 token 与动作两类：图像观测下每局约 30.7M token（200K 上下文、512×512），若改用文本网格则升到 71.9M，把上下文放宽到 780K 会升到 105.7M，把上下文收紧到 100K 则约 17.3M 而 RHAE 只掉 0.4（§4.3，论文 Fig. 7a）；动作数方面 Claude Opus 5.0 共 7,302 次、GPT-5.6 Sol 共 9,126 次。墙钟时延与费用论文未报告，只给出运行上限”每局 2,000 动作、48 小时”（附录 A.2）。

存储与系统复杂度。 无损记忆意味着归档全部返回帧、含中间动画帧、保持原始分辨率；论文 Fig. 10 提到某局中途已保存 1,472 帧，但磁盘占用与增长速率的量化数据论文未报告。系统侧需要一条宿主控制器、一个 MCP server 或 app-server 注册、以及禁用内置工具的沙箱容器；开源仓库的说明还要求 Docker、Claude Code 或 Codex CLI，批量跑 ARC-AGI-3 还需 tmux（这些属于补充材料信息）。

外部依赖。 两个主结果依赖闭源模型及其订阅制 CLI（Claude Code / Codex），无法固定快照；唯一的开源权重替代是 GLM-5.3 Flash 320B，其 RHAE 为 66.93，与闭源结果差距很大。

哪些问题解决了、哪些没有。 解决的是”通用多模态模型在陌生视觉游戏里能否稳定跑完长时程任务并达到人类效率”——在 ARC-AGI-3 的 25 个公开游戏上，答案是能，且不需要程序合成；在 GameWorld / AI GameStore 上也超过同模型官方实现。未解决的是：BabyVision 上 63.2% 仍远低于人类 92.3%，说明检视工具补不上模型本身的视觉推理差距；3D 渲染下掉到 84.12 且动作翻倍，说明对更复杂的视觉表示还不稳健；私有测试集未评估，训练数据污染无法排除（§6）。结论的适用范围因此限定为”模型本身已具备所需推理能力、任务形态为视觉交互或静态视觉问答、且允许高 token 预算与长时间运行”这一组合。

5. 最容易受到审稿人质疑的地方

质疑：主结果依赖两个闭源模型且经订阅制 CLI 调用，最关键的 100.00 只有单次运行

  • 原文依据：§4.1 说明两个后端都是闭源模型；附录 A.1 明确写道”我们经订阅制 CLI 而不是直接 API 调用来使用这些模型”；附录 B.1 只对 GPT-5.6 Sol 做了三次重复（99.04 ± 0.17），Claude Opus 5.0 的 100.00 没有重复、没有方差；AI GameStore 的三次聚合在 119.99 到 148.58 之间波动。
  • 为什么重要：闭源模型会静默更新，订阅制 CLI 的封装（系统提示、工具调度、压缩时机）不完全受论文控制，这直接影响可复现性；没有方差就无法判断 100.00 与 99.00 之间的差距、以及 VISTA 与 Tycho 之间的差距是否有意义。
  • 当前能够得出的判断：这是当前材料无法确认的部分——单次运行的满分成绩不足以支撑”稳定达到满分”的结论；AI GameStore 的跨运行波动说明这类评测本身方差可观，但论文只用协议内的聚合掩盖了它。
  • 如何验证或补强：公布 Claude Opus 5.0 的多次重复与置信区间；固定模型快照版本与 CLI 版本号；对 VISTA 与最强的程序合成系统在同一时间窗、同一模型快照下重跑。
  • 严重程度：主要问题

质疑：关键消融 (iv)→(v) 同时改了两个变量，”无损视觉记忆是主要推力”并未被隔离

  • 原文依据：论文 Fig. 5 标题写明配置 (i)–(iv) 按官方协议”每个动作后自动收到最多七帧”，而 (v)–(vi)”只自动收到最后一帧”、其余靠模型主动检视；正文把 70.05 → 94.10 的跳升直接归因于加入视觉记忆与检视（§4.3）。
  • 为什么重要：这决定了论文的核心机制主张是否成立。24 分的增益里混杂着”新增记忆与检视工具”和”从被动多帧改为按需取帧”两个变量，后者是纯粹的输入协议变化，与记忆机制无关。
  • 当前能够得出的判断：证据不足。阶梯消融整体方向可信（每一档只加一个组件，且 (ii)–(vi) 预算一致），但最大的一跳恰好不是单变量；论文没有做”保留自动 7 帧 + 额外加检视工具”或”只把帧投递改为单帧、不加工具”这两个对照。
  • 如何验证或补强：补两组消融——(a) 自动 7 帧 + 无损记忆 + inspect；(b) 仅把帧投递改为单帧、不加任何工具；再补一组 (c) 有记忆但禁用 inspect（模型只能靠上下文里的最后一帧）。
  • 严重程度：主要问题

质疑：”首个不做程序合成达到满分”的对照面过窄，且比较中推理档位不一致

  • 原文依据：Table 1 中”程序合成 = No”的系统只有官方最小实现（GPT-5.6 Sol max 13.33、Opus 5.0 high 40.68）和 VISTA（99.00 / 100.00）；所有强基线 Schema、ewma_sv_v1.6、Retrodict、Tycho 都是程序合成路线，其中 Tycho 已达 100.00。摘要所述”从 40.68 提升到 100.00”中，40.68 来自官方实现的 high 档，而 VISTA 用的是 xhigh 档（§4.1、Table 1）。
  • 为什么重要：这关系到创新性主张的强度。如果”不做程序合成”这一条件的对照集只有官方最小 harness，那么”首个”的断言实际上是在与一个未经优化的系统比较；而推理档位从 high 改为 xhigh 本身就可能带来可观增益，官方实现并未在 xhigh 下报告成绩。
  • 当前能够得出的判断：论文的主张在其自身给出的表格内成立，但对照面不足以支撑”不做程序合成就够了”这样的外推。VISTA 与 Tycho 的差距（99.00 对 100.00）说明它的价值更多在于”省掉了程序合成这一工程环节”，而非取得更高上限。
  • 如何验证或补强：补齐官方最小实现在 xhigh/max 档下的成绩；增加更多非程序合成但经过充分工程优化的基线；报告各系统在相同动作上限与相同时间预算下的成绩。
  • 严重程度：主要问题

质疑：训练数据污染无法排除，且未在私有测试集上评估

  • 原文依据：§6 Limitations 中作者自述”我们使用的模型是在这些公开基准发布之后才发布的，因此我们无法排除这些游戏被包含在其训练数据中的可能性”，并提出在 ARC-AGI-3 的私有集上评测会更有说服力；论文全部实验都止步于 25 个公开游戏与另外三个公开基准。
  • 为什么重要：本文的结论是”harness 释放了模型已有的能力”，而如果模型此前见过这些游戏的解法，结论就退化为”harness 帮助模型回忆”，这会改变论文的核心叙事；ARC-AGI-3 公开集已被广泛讨论，公开游戏的规则与解法在网络上可获得。
  • 当前能够得出的判断：这是论文自认的局限，当前材料无法排除。可以补强的一点是跨基准结果——GameWorld 与 BabyVision 的结果同样是”公开基准 + 新模型”，不能作为污染的对照；OpenAI 在官方实现上只有 13.33 这一事实间接说明模型并非”记住即能通关”，但不足以排除部分记忆。
  • 如何验证或补强：在 ARC-AGI-3 私有集上评测；用人工构造的新游戏或对公开游戏做视觉/规则改写；对模型做成员推断或对照”未见过的同构变体”。
  • 严重程度：主要问题

质疑：”视觉观测带来能力提升”的证据自相矛盾，净收益更像是 token 预算

  • 原文依据：消融 (i) 把官方文本网格换成图像后 RHAE 从 13.33 升到 47.32（§4.3），作者的解释是 token 效率（7 帧请求 28K vs 2.2K，附录 A.2）；但论文 Fig. 6 显示在完整 harness 下文本网格可达 96.75、图像为 99.00，仅差 2.25 分，动作数 10,614 对 9,126，差距集中在每局 token（71.9M 对 30.7M）。
  • 为什么重要：论文标题与摘要把”视觉”放在核心位置，若净收益主要来自上下文预算而非视觉表示本身，那么”把 ARC-AGI-3 重塑为视觉问题”这一框架的必然性就被削弱——只要给足 token，文本网格同样接近满分。
  • 当前能够得出的判断：审稿人判断属于”结论被部分夸大”。图像表示确实带来 token 效率与少量精度提升，但论文没有给出关键对照：把文本网格的请求放宽到与图像相同的 token 预算（例如减少每次请求携带的帧数）后成绩如何。此外，read_pixels 让模型能读回精确数值，这在某种程度上是”把文本网格的能力重新装回视觉管线”，也说明纯视觉通道本身不够。
  • 如何验证或补强：在相同 token 预算下对照文本网格与图像；单独消融 read_pixels 对”纯视觉”能力上限的影响；报告不同表示下模型的错误类型分布。
  • 严重程度：次要问题

6. 审稿式总评

作者发现，现有系统在 ARC-AGI-3 这类陌生视觉游戏上受限于”图像只被编码一次、旧观测会被挤出上下文”这一结构性缺陷，因此提出把记忆与注意力搬到模型外部——用一个不含可训练参数的 harness 保存全部原始帧，并把回访的决定权交给模型自己，通过 inspect / read_pixels 两个只读工具实现”想什么时候看、看哪一块”的显式注意力。实验在 25 个公开 ARC-AGI-3 游戏上表明，不做程序合成的通用多模态模型可以拿到 RHAE 100.00（Opus 5.0，7,302 动作，比人类少 57.4%）与 99.00（GPT-5.6 Sol），并在 GameWorld、AI GameStore、BabyVision 三个基准上以最小改动超过同模型官方实现；其中”递进消融阶梯”和”开源权重模型的独立复现”证据较强，但”无损记忆是主要推力”缺少单变量隔离，闭源模型依赖与单次满分的统计稳定性、”首个不做程序合成”的对照面、以及训练数据污染三项仍缺少充分支持。本文最有价值的部分是把”harness 设计”确立为一个可独立于模型能力推进的变量，并用一套极简接口证明了它的杠杆率；最大的审稿风险是核心机制结论建立在一个混杂了两处改变的消融台阶上，且满分成绩不可复现地依赖会静默更新的闭源模型。

  • 问题定义清晰度：强 —— §1 把”长时程交互中视觉信息丢失”拆成”一次性编码”与”上下文淘汰”两条具体机制，并明确给出核心假设；§3 开头进一步说明为什么编码时刻无法预知后续需求，问题边界清楚。
  • 创新性证据：中 —— 三项组件（无损记忆、模型导向检视、视觉优先的任务重表述）都没有引入新的学习算法或网络结构，本质是”档案 + 工具接口”的组合与任务重表述；论文给出的原创性依据主要是 Table 1 中”程序合成 = No”一栏的对比，而非完整文献检索。
  • 方法可信度：中 —— 流水线描述完整、工具语义有伪代码（附录 A.4），harness 无训练参数因而不存在训练不稳定的问题；但关键组件未被单变量隔离，且两处实现差异（Claude Code 直接返回图像、Codex 只能文本输出后另行附图）提示行为可能依赖宿主实现。
  • 实验支持力度：中 —— 主结果覆盖 25 个游戏并有逐游戏表、跨 4 个基准迁移、额外给出开源权重模型与 3D 渲染两类压力测试；但 Claude Opus 5.0 无重复运行、AI GameStore 跨运行波动大、消融缺失关键对照，均值掩盖了 ls20 上效率低于人类的单点失败。
  • 可复现性：中 —— 论文给出完整的工具伪代码、三份提示模板、评测指标公式与人类参考构造方式，官方仓库以 MIT 许可开源；但主结果依赖两个闭源模型经订阅制 CLI 调用，模型快照与 CLI 版本未固定，且仓库在论文公开后仍有更新。
  • 综合阅读价值：高 —— 方法简单到可以在一天内复刻，思路（把记忆与注意力外置、由模型自行调度）可直接迁移到其他长时程视觉任务；对做 agent 系统与评测的同学来说，它同时提供了一份”harness 变量该怎么消融”的正面样本和一份”消融该怎么隔离”的反面教材。
