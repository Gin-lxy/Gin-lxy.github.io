0. 一句话结论

Harness VLA 把冻结的预训练 VLA（视觉-语言-动作模型，Vision-Language-Action model）降格为一个”可重试的接触密集原语”，与一组小而固定的解析式原语（grounding/staging/transport/navigation/release）一起交给带双层记忆的 LLM 智能体规划器编排，从而在不微调 VLA 的前提下把预训练策略推广到指令重定向、位置交换等部署扰动场景；论文在四个仿真基准上报告了相对冻结 VLA 与所引最强先验基线的大幅提升（LIBERO-Pro +38.6 个百分点、RoboCasa365 +27.1 个百分点、RoboTwin C2R 58.4%，作者主张），但”提升来自分层编排设计”的因果归因仍掺杂测试时预算与闭源规划器主干两个主要混杂因素，且正文与表格存在数字口径不一致，证据强度需要打折。

1. 论文具体想解决什么问题

研究背景与具体任务。机器人操作（robotic manipulation）的长期目标是让系统按自由形式的自然语言指令在变化的物体、布局与形态下可靠执行任务。当前有两条对立路线（§1）：端到端 VLA 模型直接从机器人轨迹学习接触密集（contact-rich）的视觉运动控制；LLM 编程智能体（coding agent）用语言模型推理去组合显式的感知与控制 API（application programming interface，应用程序接口）。本文的具体任务设定是语言条件操作（language-conditioned manipulation）：环境 E\mathcal{E}E 在每个时刻暴露观测 ot=(Itrgb,Itd,qt)o_t=(I_t^{\text{rgb}}, I_t^{\text{d}}, q_t)ot​=(Itrgb​,Itd​,qt​)（agent 视角 RGB 图、对齐的度量深度图、机器人本体感知（proprioception）状态），任务由自然语言描述 ℓ\ellℓ 与仅在回合结束时给出的稀疏成功信号、二值完成谓词（completion predicate）G\mathcal{G}G 定义（§2.1）。

现有做法在哪些条件下表现不好。作者的主张是两条路线各自把错误的组件放到了过大的职责上（§1）。端到端 VLA 擅长局部的图像条件接触（抓取不规则物体、在紧凑公差下放置、操作对解析控制器脆弱的固定装置），但在偏离训练轨迹分布（trajectory distribution）的部署扰动（deployment perturbations）下急剧退化——语义重定向（semantic retargeting）、目标重绑定（goal re-binding）、物体布局移动、把短技能组合成长流程时，策略可能重复熟悉的训练期行为，而一次不稳定的接触失败即可毁掉整个单体（monolithic）回合（§1）。论文给出的量化证据是 LIBERO-Pro 上的对照（Table 3，PDF p8）：冻结的多种 VLA 在指令重定向（T）/位置交换（S）扰动的八个评测格上大面积崩溃——OpenVLA、NORA 均 0.0%，π0\pi_{0}π0​ 0.3%，π0.5\pi_{0.5}π0.5​ 11.0%，作者评测的 πRLinf\pi_{\mathrm{RLinf}}πRLinf​ 50.0%；此前最强已报告基线 RATS 也只有 43.8%。另一侧，解析式原语（analytic primitives，基于运动学/模型的确定性控制器，如逆运动学（inverse kinematics, IK）搬运、腕部旋转、底座移动、夹爪开合与释放）难以处理不规则抓取、受限放置与铰接物体（articulated object）交互，而编程智能体类系统在操作领域往往仍靠扩技能库（skill library）来补能力（§1、§5）。

作者发现/强调的现象。论文把部署扰动刻画成”超出冻结 VLA 轨迹分布的空间”，并用 Figure 3 的终端帧对比说明冻结策略的行为对语言条件化很弱：在任务描述重定向而视觉场景几乎不变的 Object-Pro 用例中，πRLinf\pi_{\mathrm{RLinf}}πRLinf​ 重复标准行为而不跟随新指令；在布局交换的 Goal-Pro 用例中，它仍把物体移向训练时的区域（§3.3，Fig. 3，PDF p10）。需要说明：这一”VLA 对扰动脆弱”的现象在领域内早已存在（LIBERO-Pro 等工作本身就在测量），本文的新观察是把该现象归因于”职责分配错误”，并据此提出分解方案；该归因是作者的解释框架，论文没有对”单体架构为何失败”做机制性的因果实验（审稿人判断）。

作者认为的原因与核心假设。原因：单体 VLA 被迫在一个策略内同时承担语言接地、长程组合与底层控制，超出了它的训练分布；而编程智能体一侧又试图用手写/自动生成的 API 覆盖物理细腻交互（§1）。核心假设：保持原语库固定且小，让智能体学习”何时、如何”编排它——把语义重定位（semantic re-grounding）、非接触执行与 VLA 再摆位（re-staging）提升到规划器层，冻结 VLA 只负责局部接触密集阶段；这样无需微调即可扩展预训练 VLA 的轨迹分布（§1、§2.3，Fig. 2）。

2. 创新点是什么

一句话概括：本文的技术增量不是新模型或新训练方法，而是一套”把冻结 VLA 暴露为单一原语、把编排交给带双层记忆的 LLM 智能体、并保持原语库固定”的系统性框架（training-free 的智能体层 + 一个仅做 SFT 的 VLA 后端），并配套一组机制分析（调用预算曲线、完成归因、原语使用统计）来支撑”分工有效”的主张。其组件（harness、记忆、原语组合、code-as-policies 思想）在既有工作中都有原型，本文属于”已有范式在机器人操作上的新组合与系统性实现”，原创边界主要落在”冻结 VLA 作为可重试原语 + 双记忆学习原语操作范围”这一设计（审稿人判断；论文 Related Work 只对比了各条线的代表工作，是否首次提出还需更完整文献检索）。

逐项分析：

  1. VLA-作为-原语的抽象与固定小原语库（§2.3，Table 1，PDF pp. 5–6）。新增机制：原语库 P\mathcal{P}P 是规划器唯一可调用的动作接口，含 6 个解析式原语（move_to、move_pose、rotate_wrist、rotate_pitch、set_gripper、release；RoboCasa365 另加 navigate_to、move_base）与 1 个学习原语 vla_act；vla_act 绑定各基准的冻结 VLA，由规划器给出任务条件提示与早退谓词 τ\tauτ，执行动作块（action chunk）直到 τ\tauτ 满足或块预算耗尽。与最接近已有方法（Code as Policies、ProgPrompt、RATS、Cap-X 等）的差异：不合成可执行代码、不扩技能库，而是发出结构化 JSON 原语调用并在闭环中逐次重建参数；与 ASPIRE（自动扩张技能库）方向正相反（§5）。对应问题：单体 VLA 被迫承担全部职责。证据：πRLinf\pi_{\mathrm{RLinf}}πRLinf​ 冻结权重不变、仅换编排方式后在 LIBERO-Pro 从 50.0% 提到 82.4%（Table 3），说明该抽象确实能在不改模型的前提下改变行为分布；”原语库必须固定”本身没有被直接消融，论文用 ASPIRE 式扩张留作未来工作（§6，审稿人判断）。

  2. 双层记忆与”学习原语操作范围”的自举流程（§2.2、附录 A）。新增机制：仅在单个参考种子 s0s_0s0​ 上做智能体探索（探索期可用 reset、宽裕墙钟预算），把成功轨迹序列化为”空间坐标替换为符号化感知查询”的 JSONL 过程记忆（Task Specific Memory（任务特定记忆）的 procedural trace + 语义审计 JSON），并把可复用的成功规则（success rules）与失败模型（failure models，如空抓取、假成功）沉淀到跨任务的 Global Memory（全局记忆）；部署期禁用 reset、缩短预算，检索记忆并按当前 RGB-D 重新接地（re-ground）。与最接近工作（Voyager 的持久记忆、SWE-agent/OpenHands 的 harness）的差异：把记忆机制与 VLA 后备的接触原语结合到物理操作（§5 作者自述的空白点）。证据：附录 A 给出记忆文件格式与”结合结构、不重放字面坐标”的规则；Table 5 的零样本对照（去掉记忆后 Goal-S 从 87.0% 掉到 31.0%）间接显示记忆的贡献。该记忆设计如何对应问题：把”每任务一次成功探索”变成可迁移的结构先验，降低对 VLA 泛化的要求。

  3. 机制分析套件（§3.3，Fig. 4/6，Table 19/20）。新增内容：调用上限曲线（Fig. 4）把”允许的最大 vla_act 调用数 kkk”与累计成功率联立，用受控的调用预算探针检验”稀疏但可重试的调用”有效性；完成归因（Fig. 6）统计成功回合由解析式还是 VLA 触发最终完成谓词；使用统计（Table 19/20）给出各环境下原语类别配比（LIBERO 解析式 84.2%、vla_act 15.8%；RoboCasa365 vla_act 35.3%；RoboTwin C2R vla_act 47.4%）。与”只报总成功率”的一般工作相比，这组分析把”分工假设”变成可检验的中间量。局限见 §4.3 与 §5：这些证据部分是描述性的，未把”再摆位质量”与”重试次数”分离。

什么不算创新（审稿人判断）：没有新模型架构、没有针对 VLA 的强化学习或偏好优化（§6 明确列为未来工作）；VLA 后端（π0.5\pi_{0.5}π0.5​-SFT 检查点、RLDX-1）与解析控制器都复用现成组件；Flash Mode 是把成功序列编译成任务卡（task card）的重放工程（附录 G），属工程改进；”更强 LLM 规划器带来更好结果”（附录 H）是观测到的相关性，不构成本文方法性创新。

3. 作者如何解决

直觉说明。把一次长程操作想成”搬运路线 + 若干接触关口”：路线（去哪、以什么姿态接近、搬到哪里、何时松手）用确定性运动学原语就能可靠完成；真正需要”手感”的只有抓取、放置、按压、拧龙头这类接触密集关口，而这些恰恰是预训练 VLA 表现最好的局部能力。于是论文的解法不是让 VLA 变强，而是让它”少干活”：规划器负责理解语言、在当前场景里重新定位目标、把机器人摆到 VLA 熟悉的局部观测/触碰位姿，然后调用冻结 VLA 做一小段接触动作，观察结果，必要时再次摆位重试。

按实际运行流程展开（§2、附录 A/E）：

  1. 输入：任务描述 ℓ\ellℓ、RGB-D 观测、机器人状态（本体感知 + 末端执行器（end-effector）位姿与夹爪状态）。规划器看不到仿真器的特权信息（物体真值位姿、控制器内部量），只能通过 RGB 图像语义识别 + 在预计算世界图上索引像素来获得度量定位（附录 E.2 的感知隔离规则）。
  2. 执行循环：规划器 Π\PiΠ（Codex 或 Claude Code）每回合只写一条 JSON 原语调用到 command.json；环境 worker 执行直到该原语的后置条件（post-condition）满足或内部预算耗尽，写回 state_NN.json、log_NN.json、新观测与同步标志；规划器读取新证据后再决定下一动作（文件中介的 Read-Eval-Print Loop（REPL，读取-求值-打印循环），附录 A，Table 8）。循环直到完成谓词满足或步数预算耗尽（§2.1）。
  3. 谁来决策、谁来固定流程：规划器决定原语选择、参数绑定（目标坐标来自当轮感知/记忆）、vla_act 的提示与调用时机，以及是否重试或换策略；固定流程控制 JSON 序列化、原语内部执行、后置条件、预算与审计文件写入。二者边界明确——原语库在评测前冻结，规划器不能发明新原语（§2.3）。
  4. 两个阶段（§2.2）：探索自举（bootstrapping）阶段在单个参考种子（seed s0s_0s0​）上让智能体自由尝试摆位顺序、预接触位姿、vla_act 调用时机与早退阈值，成功后把经验写成任务特定记忆（含”把具体坐标参数化为符号感知查询”的 JSONL）与全局记忆；严格部署阶段禁用 reset、压缩预算，检索并动态重接地记忆轨迹来求解新种子/扰动。
  5. 是否需要训练：框架本身无训练；唯一训练环节是 RoboTwin 后端 LingBot-VLA 的监督微调（supervised fine-tuning, SFT）（附录 D.3，Table 15：AdamW、学习率 1×10−41\times 10^{-4}1×10−4、全局 batch 256、chunk size 50、flow steps 10、FSDP2、bf16/fp32 混合精度），此后冻结；LIBERO/LIBERO-Pro 用 RLinf 发布的 pi05_libero130_fullshot π0.5\pi_{0.5}π0.5​-SFT 检查点（记 πRLinf\pi_{\mathrm{RLinf}}πRLinf​，完全冻结），RoboCasa365 用官方 RLDX-1 检查点（冻结）。
  6. 推理阶段的变化：策略参数零变化，变化全在外部——多轮文件往返、记忆检索与重接地、解析原语的对位与再摆位、可重试的 vla_act 调用；Flash Mode（§4.1）进一步把成功序列编译成任务卡，用 VLM（vision-language model，视觉-语言模型）定位锚点后按序重放，无需在线规划（重接地公式见附录 G 的 Δxi=xiref−aj(i)ref\Delta\mathbf{x}_i=\mathbf{x}^{\text{ref}}_i-\mathbf{a}^{\text{ref}}_{j(i)}Δxi​=xiref​−aj(i)ref​、xirun=a^j(i)+Δxi\mathbf{x}^{\text{run}}_i=\widehat{\mathbf{a}}_{j(i)}+\Delta\mathbf{x}_ixirun​=aj(i)​+Δxi​，Eq. (1)）。
  7. 输出：每个回合的审计 JSON 与命令 JSONL；基准成功信号决定分数（附录 C）。真实双 Franka（附录 F 之外的第 4 节）用同一分工：Codex(GPT-5.5) 调用冻结的 π0.5\pi_{0.5}π0.5​ 桌面清理策略做抓取/交接/放置，解析原语负责预接触摆位、自由空间搬运与转向，人工负责 reset 与成功判定（§4.2）。

4. 解决得怎么样

4.1 实验设置

  • 如何验证或补强：分记忆消融（仅任务特定记忆 / 仅全局记忆 / 两者）；固定 vla_act 调用次数，对比”原地重试 vs 摆位后重试”；测量冻结 VLA 在不同预接触位姿下的成功率曲线，直接检验”摆位恢复 VLA 兼容性”的机制假设；报告 τ\tauτ 与容差的敏感性分析；对失败回合做分类统计（空抓取、错目标、假成功等，附录 A 已有失败模型的定义可利用）。
  • 严重程度：主要问题。

质疑：正文与表格数字不一致、聚合口径不一致（57.1/57.2、48.6/48.8、27.1 vs 27.2；RATS 6 格 vs 8 格）

  • 原文依据：§3.2 正文（PDF p9）写 “Harness VLA reaches 57.1% with Codex and 48.6% with CC”，而同页 Table 4 列出 57.2 与 48.8；摘要与 §1 的头条 “+27.1 percentage points on RoboCasa365” 只能由正文的 57.1−30.0 得出，而 Table 4 自身数字给出 27.2（分析者复算；Table 4 分列 92.2/61.3/13.8 与 80.0/47.5/15.0 按回合数加权分别为 143/250=57.2 与 122/250=48.8，表内自洽，正文误差）；Table 3 表注明确 “Cap-X and RATS report only the six non-LIBERO-10 cells, so their overall values average over reported cells only”——头条 +38.6 是 8 格平均（CC 82.4）对 6 格平均（RATS 43.8）的跨口径差；此外，Table 7 的 Codex 78.50% 与 Table 3 的 Codex 72.1% 是同一基准同规模（800 回合）的两个不同数字，表注解释为”separate batch”。两处在 HTML 与 PDF 两版完全一致，排除转录或渲染错误（分析者核对）。
  • 为什么重要：这些数字是论文的核心卖点与后续引用对象；正文与表格冲突会使读者无法确定官方值，跨口径聚合（不同评测格集合的”overall”）则可能放大头条差值，两者都会影响引用与再对比的公平性。
  • 当前能够得出的判断：正文 57.1/48.6 与 Table 4 的 57.2/48.8 至少有一处错误（表内数字与分列自洽，倾向表对文错），需要勘误；+38.6 的差值方向不受口径选择影响（若把 Harness 也限制在 6 格，其平均为 87.7%，差值反而更大——分析者复算），但这不等于可以隐去口径差异；Table 7 与 Table 3 的 72.1/78.50 差异虽经表注说明为不同批次，读者仍无法判断哪个是”标准配置”结果。
  • 如何验证或补强：以勘误统一正文与表格数字；在所有跨方法表中同时给出各评测格的逐格值，并显式标注聚合范围（6 格/8 格/加权方式）；披露 Table 7 与 Table 3 两批 Codex 运行的差异原因（版本、提示或预算）。
  • 严重程度：主要问题。

质疑：成本、方差与真实世界证据报告不足

  • 原文依据：论文未报告规划器 token 用量与调用次数、自举探索的尝试数与墙钟、LingBot-VLA 后训练的算力规模；全部主表无方差、置信区间或显著性检验，而 Table 5 逐任务波动极大（Harness Task 4 为 90.0%、Task 5 为 0.0%）；RoboCasa365 每任务仅 5 个种子（Table 12）；Flash Mode 的 max-card 选择与报告同种子混合，附录 G 自认 “retrospective best-card result … can be optimistic”；真实世界只有定性演示与人工判定（§4.2），无成功率与失败分类。
  • 为什么重要：这些报告项决定读者对方法成本的直觉（一个回合要多少 LLM 调用/多少钱、自举一个任务要多久）、对数值稳定性的信任（100–250 回合的二项噪声约 ±5–10 个百分点），以及”真实世界可用”主张的强度；对做工程落地的读者尤甚。
  • 当前能够得出的判断：论文对部分局限诚实自述（Flash 乐观性、计时口径、开放环反馈），但关键成本指标与统计量缺失属于可补交的披露缺口，而非不可修复的方法缺陷；真实世界结论目前只能定位为”同一冻结 VLA 上可演示新行为”。
  • 如何验证或补强：披露 token/调用/时长与自举成本；报告每任务/每格的方差与置信区间（或多次重复）；真实世界补小规模成功率与失败模式统计；Flash Mode 用留出种子重估最优卡片的泛化表现。
  • 严重程度：次要问题。

6. 审稿式总评

作者发现：端到端 VLA 的强项在局部接触密集控制，但部署扰动（语义重定向、目标重绑定、布局变化、不稳定接触）会把它打出训练轨迹分布，而编程智能体一侧又把物理接触交给不擅长它的解析 API（§1、Table 3 的冻结策略崩溃与 Fig. 3 的行为证据）；因此提出 Harness VLA——保持原语库固定且小，把冻结 VLA 暴露为单一可重试原语 vla_act，由带任务特定记忆与全局记忆的 LLM 规划器学习”何时、在哪个局部区域、以什么前置状态”调用它，其余交给解析原语（§2、Fig. 1/2）；通过文件中介 REPL 的回合循环与”自举-严格部署”两阶段实现，无 VLA 微调（§2.2、附录 A）。实验在 4 个基准共 1,700 个主协议回合、外加零样本、Flash 与真实定性条件下表明：同一冻结 VLA 在扰动基准上大幅抬升（LIBERO-Pro 50.0→82.4，RoboCasa365 30.0→57.2，RoboTwin C2R 50.4→58.4，Table 3/4/6），其中”选对时机调用 VLA”的调用预算证据较强（Fig. 4(a)：1 次调用即 52%>50%）、记忆贡献有半隔离证据（Table 5：位置交换 87.0→31.0），但增益归因仍缺少等预算对照与分机制消融，且结果随闭源规划器换代大幅摆动（72.1/82.4/92.63，Table 3/21），正文与表格存在数字不一致（质疑四）。本文最有价值的部分是”冻结模型 + 智能体编排”的实证范式与可移植的双记忆原语框架——它给出一条不训模型、靠 harness 工程扩展 VLA 有效工作范围的清晰路线；最大的审稿风险是：核心因果主张（分层编排带来增益）与测试时预算、闭源规划器能力两个混杂因素纠缠，使其”可靠、state-of-the-art 鲁棒”的强表述目前只能按”在论文报告的主干与协议下成立”来理解。

  • 问题定义清晰度：强（两条路线各自的错配讲得清楚，任务形式化（§2.1）、原语接口（Table 1）、评测协议（附录 C）与记忆格式（附录 A）均明确给出）。
  • 创新性证据：中（”冻结 VLA 作为可重试接触原语 + 双记忆学习操作范围”是真实的系统增量，且用 ASPIRE/RATS/Cap-X 等正面对比了定位；但组件均为已有范式的新组合，无同协议重跑的最近邻基线，”首次”边界无法仅凭本文确认）。
  • 方法可信度：中（框架描述完整、提示全文公开、perception 隔离规则明确；但 τ\tauτ/容差与自举过程未报告、依赖三个闭源主干、开放环反馈为自述局限）。
  • 实验支持力度：中（四个基准 + 零样本 + Flash + 真实演示的覆盖面强，关键效果量级大且两版数字一致；但无方差/显著性、跨协议基线混杂、两处数字口径不一致、机制证据部分为描述性）。
  • 可复现性：中（代码仓库公开且为 Apache-2.0 许可、提示与协议全文给出；但主结果依赖三个闭源规划器与特定冻结检查点，LingBot-VLA 检查点可用性未报告，Token/成本口径缺失）。
  • 综合阅读价值：高（把”何时该不该让 VLA 干活”这一被广泛讨论的直觉做成了可度量的系统与机制分析，”冻结模型 + harness 工程”的路线对做机器人学习、智能体与系统集成的读者都有直接参考价值；但引用其数字时需带上质疑四的口径提示）。
