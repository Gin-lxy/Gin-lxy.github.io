0. 一句话结论

本文问的是编程智能体那套「SFT + 多轮 RL」后训练能否直接提升机器人 harness 中规划器的能力；作者提出 AgenticRoboRL，把训练接口放在模型调用边界，用记录代理和五字段适配器把 VLA 技能调用与控制代码生成接进同一管线。LIBERO-PRO 上 9B 规划器从 18.1% 升到 71.0%（SFT 65.1%，RL +5.9），LIBERO-Plus 72.2%，CaP-X 2.7%→28.5%，但训练与评测共用同一批 LIBERO 任务，证据只支持「同任务、跨初始状态与扰动」的提升，尚不足以支持「新任务泛化」或「通用机器人智能体」的强结论。

1. 论文具体想解决什么问题？

先交代任务形态。智能体机器人系统（agentic robotics systems）把一个语言模型规划器（planner）和一个机器人执行框架（robot harness）组合起来：规划器读取任务与观测，输出工具调用或控制程序，harness 执行并反馈，双方多轮交互直到任务结束。执行机制至少有两类：一类是 VLA（Vision-Language-Action，视觉-语言-动作模型）技能调用，规划器选择技能并填参数，冻结的 VLA 策略把调用变成低层动作；另一类是控制代码生成，规划器直接写 Python 调用感知与控制 API，由运动控制器执行。RPent 属于前者，CaP-X 属于后者（§1、§3.1）。

现有工作主要走两个方向：一是改 harness，把 VLA、感知原语、任务记忆组织得更好，例如 Harness VLA 用冻结 VLA 加分析原语和任务记忆；二是换更强的规划器，直接用 Codex、Claude Code 这类编程智能体，不改权重。两者都在利用规划器已有能力、强化周围支撑，而不是提升规划器本身（§1）。既然 SFT（supervised fine-tuning，监督微调）与 RL（reinforcement learning，强化学习）后训练能显著增强编程智能体，作者便问：这套方法能不能迁移到机器人规划器？

迁移并不只是换数据集：不同 harness 的执行机制、返回的反馈、成功判定都不同。已有 agent RL 基础设施通常假设共享低层动作接口，或至少假设交互记录可完整重放。论文指出后者也不成立：harness 可能在两次请求间裁剪图像、丢掉推理、改写历史，「拿最终对话重放」得到的上下文未必等于模型当时看到的（§3.2）。因此训练接口应放在模型调用边界，而不是低层动作边界。

现有小模型表现很差。Table 1 中，LIBERO-PRO/RPent 下原始 Qwen3.5-9B 只有 18.1%，接外部记忆也只有 18.9%；27B 教师带记忆 74.0%，Codex（GPT-5.5）带记忆 72.1%，Claude Code（Opus 4.7）82.4%，单独运行冻结 VLA 是 50.0%。这支持「9B 规划器是瓶颈」的判断。论文没有做因果实验分离「规划器能力不足」与「harness 接口不适配」；「记忆对 9B 几乎无效、对 27B 提升 16.1 个百分点」只是 Table 1 的间接线索。

核心假设是：只更新规划器、冻结感知/VLA/控制器，用「成功轨迹 SFT + 以任务成功为唯一奖励的多轮 RL」，再给每个 harness 配一个轻量适配器，就能同时改善两类规划器。它包含两个子问题：后训练是否真的提升规划器；同一管线能否跨 harness 复用。前者在单任务集上得到较强支持，后者有两个 harness 的原理验证，但覆盖仍有限。

需要区分三层：领域一般问题是长程操作需要好的规划与反馈；本文新提出的是「跨 harness 复用编程智能体后训练配方」；实际解决的是「在 LIBERO 仿真的两个 harness 上，用 9B 开源规划器超过无记忆教师的部分表现」。论文没有证明它是首个可行方法，也未证明在真机或全新任务上成立。

2. 创新点是什么？

本文的技术增量不是新的 RL 目标函数，而是一套把已有 agent 训练组件接到异构机器人 harness 上的系统抽象与数据配方。作者以「模型调用」而非「低层动作」为训练单元，围绕它组织记录、分组、奖励关联与策略更新；以下三点分别对应「跨 harness」「教师与学生上下文不一致」「只优化规划器」。

第一，模型调用边界上的统一训练接口与五字段 harness 适配器（adapter）。记录代理（recording proxy）在模型服务边界保存请求上下文、token id 和采样对数概率；适配器只报告任务、初始状态、尝试序号、奖励和有效性五个字段，不要求共享动作表示。与 action-level 共享接口相比，这让两类 harness 共用样本构造与优化代码；CaP-X 实验说明该接口可迁移（§4.4，Table 3）。这属于系统抽象加工程实现，不是新学习算法。

第二，面向「教师有记忆、学生没有记忆」的 SFT 数据构造：rewrite-and-filter。教师上下文包含学生看不到的记忆调用与内容，不能原样蒸馏；作者先重建学生实际会看到的上下文，再用关键词、连续八字重合和「只出现在被删记忆结果里的数字」三种启发式标记依赖记忆的回复，让评审模型改写推理与文本，只保留判定为 OK 的改写作为监督目标。与「直接丢掉所有依赖记忆的回复」相比，这保留了更多监督信号；论文报告它在相近更新步数下优于 mask-only（§4.5，Table 4、论文 Fig. 3），但作者也承认两个数据集在规模和内容上都不同，不能把差异全部归因于改写。

第三，以任务成功为唯一奖励的多轮 RL 配方。每个（任务，初始状态）组采样六次，用组内留一法（leave-one-out）优势，不加 critic、不做奖励标准化；每个 episode 最多选 16 个回复，按 1/K 加权，采用 dual-clip PPO 与截断重要性采样（truncated IS），不加 KL 或熵正则。算法组件来自 GRPO/PPO 一系，增量在于把它用于「规划器多轮调用 harness」并配合策略版本化轮次（policy-versioned rounds）。论文在 RPent 与 CaP-X 上都报告了 RL 在 SFT 之上的进一步提升（§4.2 的 Table 1、§4.4 的 Table 3），但没有做 RL 组件消融，因此「为什么这些设计起作用」仍待验证。

3. 作者如何解决？

整体直觉是：把机器人 harness 当成「工具环境」，把规划器当成会写工具调用或代码的编程智能体；既然编程智能体可以通过「先模仿成功轨迹、再用任务结果做 RL」变强，那么机器人规划器也能在同一个 harness 里这样变强。关键约束是只动规划器权重，不动 VLA、感知和控制代码，因此学到的能力可随模型迁移、执行层保持原样。图 1 给出了这一思路的系统位置与整体流程。

图 1（论文 Fig. 1）：这张图把论文的出发点、训练配方和主要结果组织成一个系统视图。它先呈现智能体机器人系统的运行闭环：规划器与机器人 harness 多轮交互，harness 把规划器的决定交给 VLA 技能或控制代码执行，再把观测与执行结果送回规划器。训练配方建立在这个闭环之上：教师产生的成功轨迹先用于 SFT，把规划器初始化到「会使用这个 harness」的状态，然后在同一 harness 里做规划器 rollout，用任务结果做 RL。图中还把不同规划器的 LIBERO-PRO 成功率放在一起，说明本文的目标不是换更大的模型，而是让 9B 规划器在无外部记忆时接近带记忆的闭源编程智能体。整张图的主线是「执行组件不动、只训练规划器」。

第一阶段是 SFT。教师是带记忆的 Qwen3.8-27B，在 RPent 初始状态 11–44 上跑成功轨迹；学生是没有外部记忆的 Qwen3.5-9B。直接在教师的上下文上做模仿是不行的，因为学生看不到教师记忆模块里的内容。作者因此逐回合重建学生上下文：从记录的 episode 中删掉记忆访问调用及其结果，得到学生实际会收到的 prompt；然后判断教师回复是否依赖被删掉的记忆。判定使用三种启发式：回复里出现指向记忆的关键词、连续八个词与记忆文本重合、出现只存在于被删记忆结果中的数字。被标记的回复交给评审模型（judge）改写其中的推理和文本，工具调用参数保持不变；只有评审判定为 OK 的改写才作为监督目标。每个回合最终有三种命运：作为训练目标、只作为历史上下文、直接丢弃（§3.3.1）。

CaP-X 的 SFT 更简单：教师和学生使用同一套 harness 配置，不需要重建记忆上下文；取成功 episode 中正常结束的模型调用，用学生的 chat template 重新渲染 prompt，教师当时生成的 token 直接作为目标。SFT 损失只在回复 token 上计算，推理、文本、工具调用或代码以及结束 token 都受监督，上下文 token 被 mask；分母是整个优化批次内的受监督 token 总数，而不是对每个回复单独归一化后再平均（§3.3.1）。RPent 训练集 40,047 个目标回合，一个 epoch 626 步，主结果用验证状态 45–49 上选出的第 563 步检查点（§4.1、Appendix C.1）。

第二阶段是多轮 RL。这里最关键的基础设施是记录代理。RL 时训练单元不是仿真器步，也不是重建出来的完整对话，而是「规划器的一次请求」：代理在模型服务边界记录该次请求的上下文、生成的 token id 和 rollout 对数概率；图像和工具说明在适用时保留。训练器在构造样本时重新渲染 prompt，并与记录下来的 prompt token 逐一比对；不一致的样本优化权重为零（§3.2）。这防止训练器悄悄换一份「看起来一样」的上下文，避免策略梯度作用在错误的条件分布上。

每个 harness 配一个适配器，按 episode 报告五个字段：任务、初始状态标识、尝试序号、奖励、有效性标志。前两个字段定义「组」——同一个任务、同一个初始状态的所有尝试算一组，用于组内比较；有效性标志把「任务失败」和「基础设施失败」分开：前者保留为零奖励样本，后者从优化中剔除。适配器是纯转换代码，没有可学习参数，不改变 harness 的工具、prompt 或控制循环，只把不同 harness 的 episode 记录映射成统一训练表示（§3.2、Appendix B）。RPent 奖励来自仿真器成功检查，而不是规划器自报完成；CaP-X 的奖励来自 harness 写入的完成标志，报错或执行失败算「有效失败」、奖励为零（Appendix B，Table 5）。

推理阶段没有额外的模块或检索步骤：训练后的规划器直接放回原 harness，prompt、工具、控制循环都不变，只是不再使用外部记忆；RPent 的 episode 上限是 100 个规划器回合或 7,200 秒，评测采样温度为 1.0、top-p 0.95、top-k 20、存在惩罚 1.5（§4.1、Appendix C.4）。最终输出仍是 harness 原生工具调用或 Python 代码，由冻结的 VLA 或控制器执行。好处是推理开销与原始规划器基本相同，坏处是规划器只能通过 harness 接口行动，无法绕过执行层限制。

为什么这样设计？模型调用边界的选择，来自 harness 会改写历史这一事实：如果按低层动作对齐，VLA 技能调用和控制代码生成无法共享表示；如果按完整对话重放，又可能拿到与采样时不同的上下文。适配器的五字段设计，则把「什么算一组」「什么算成功」「什么算基础设施失败」这些 harness 特有语义留在 harness 侧，训练侧只做统一计算。只训练规划器，是为了让方法直接叠加在现有 harness 上，不必重训 VLA 或控制器；代价是执行层的错误无法通过后训练修复，规划器只能学习在给定执行器下做出更好决策。

4. 解决得怎么样？

4.1 实验设置

主实验在 LIBERO-PRO 上使用 RPent（Harness VLA 发布的 VLA 调用型 harness）。LIBERO-PRO 在四个 LIBERO 套件上各做位置交换（S）与任务指令扰动（T），形成八个套件，每个 10 个任务 × 10 个初始状态，共 800 个 episode（§4.2，Table 1）。鲁棒性在 LIBERO-Plus 上测试，它含七类扰动（布局、相机、机器人初始状态、语言、光照、背景、传感器噪声），共 10,030 个配置、每个跑一个 episode，且不再训练（§4.3）。跨 harness 在 CaP-X 上进行，使用 Object/Goal/Spatial 的位置与任务扰动，共 60 个任务、600 个 episode（§4.4，Table 3）；CaP-X 按 CaP-RL 设置使用特权状态（privileged state），对比共享该设置。

模型方面，学生是 Qwen3.5-9B、教师是 Qwen3.8-27B；VLA、感知与运动控制器全部冻结。RPent 的冻结 VLA 是 πRLinf\pi_{\mathrm{RLinf}}πRLinf​，与 Harness VLA 表格行使用同一 harness 与 VLA，差别只在规划器（Table 1）。教师使用 Harness VLA 任务与全局记忆；学生在 RL rollout 和评测中都不访问外部记忆。数据划分：每个 LIBERO 任务 50 个固定初始状态，训练 11–44、验证 45–49、评测 1–10，教师演示和 RL rollout 都不碰评测状态；LIBERO-Plus 在训练设置固定后才运行（§4.1）。

对比对象分三层：同模型消融（原始 9B、SFT、SFT+RL）、执行层参考（VLA 单独运行、CaP-X、RATS 等）、系统级参考（带记忆的 Codex、Claude Code、27B 教师）。† 行取自 Harness VLA 与 LIBERO-Plus 排行榜；Table 2 的 † 行是单个 VLA 策略，而本文行是「规划器 + 同一冻结 VLA」（Table 1、Table 2 说明）。评价指标是任务成功率，另对 800 个配对 episode 做精确符号检验（§4.2）；论文没有报告训练种子、置信区间或该检验外的显著性检验。

训练细节：SFT 用 AdamW、学习率 10−510^{-5}10−5、批大小 64 个目标回合、一个 epoch；RPent 626 步、CaP-X 37 步，主结果取第 563 步（Appendix C.1、C.3）。RL 学习率 10−610^{-6}10−6、批大小 128，每轮 384 个 episode；RPent 跑 9 轮、报告第 6 轮，CaP-X 跑 15 轮（Appendix C.2、C.3）。这些设置只回答「固定预算下是否有效」，没有回答「换种子是否仍有效」。

4.2 关键结果

先看主结果。Table 1 显示，RPent + 9B 从 18.1% 提升到 SFT 的 65.1%，再提升到 SFT+RL 的 71.0%；SFT 贡献绝大部分增益，RL 再增加 5.9 个百分点。71.0% 超过无记忆的 27B 教师（57.9%），接近带记忆的 27B 教师（74.0%）与 Codex（GPT-5.5，72.1%）；但同表 Claude Code（Opus 4.7）带记忆是 82.4%，摘要只挑 72.1% 作参照，属于叙述上的选择性。与单独运行的冻结 VLA（50.0%）相比，RL 规划器在八个套件中七个更高；Goal-T 只从 45.0% 升到 54.0%，L10-S 从 14.0% 升到 39.0%，但 L10-T 反而从 49.0% 降到 41.0%。完整结果见 Table 1。800 个配对 episode 上，RL 在 121 个 SFT 失败上成功、在 74 个 SFT 成功上失败，符号检验 p=0.001p=0.001p=0.001（§4.2）。

鲁棒性结果见 Table 2。LIBERO-Plus 上，原始 9B 是 19.2%，SFT 后 66.7%，RL 后 72.2%；七类扰动上都有提升，RL 相对 SFT 的增量从物体布局的 2.2 到光照的 7.0 个百分点不等。按同一批实例配对，RL 在 1,547 个 SFT 失败的实例上成功，在 999 个 SFT 成功的实例上失败，净增 548 个成功 episode（§4.3）。在不使用 LIBERO-Plus 训练的方法中，72.2% 是最高的总体成功率；但排行榜上 OpenVLA-OFT+ 在 LIBERO-Plus 上训练后达到 79.6%，因此「最高」须限定为「未用 LIBERO-Plus 训练」。机器初始状态扰动上的差距最大：本文 75.2%，对比中最强基线 46.2%（§4.3）。同表还显示，本文两行在每一类扰动上都高于未训练 9B，说明增益不限于某一类；RL 相对 SFT 的增量在各类之间不一致，物体布局只增加 2.2 个百分点，光照、噪声、相机等更多。由于评测实例与训练任务同源，这张表证明「同任务上的扰动鲁棒性」，不是「对新任务的泛化」。

跨 harness 结果见表 3。CaP-X 上 9B 从 2.7% 到 SFT 18.7%、RL 28.5%，超过 27B 教师的 20.3%；RL 相对 SFT 增加 9.8 个百分点，比 RPent 的 5.9 更大。但绝对水平低且集中在 Object：SFT 的 49.0%/39.0% 被推到 67.0%/72.0%；Goal 任务扰动从 4.0% 到 16.0%、位置扰动停在 10.0%；Spatial 位置扰动从 10.0% 降到 6.0%，任务扰动仍为 0.0%（Table 3）。论文归因于教师只在 26/60 个任务上有成功数据，Goal/Spatial 的教师成功率太低；这说明「跨 harness 有效」目前是「两个 harness 都能跑通并提升」，不是「所有任务类型稳定提升」。

易忽略的细节：CaP-X 的 RL 任务池是 35 个任务（20 Object、9 Goal、6 Spatial），选择标准是 SFT 规划器在五个验证 episode 中成功 1–4 个；教师数据覆盖其中 26 个任务，剩下 25 个评测任务没有参与训练（Appendix C.3）。Table 3 报告的是全部 60 个任务的平均，但没有把「参与 RL 的 35 个任务」和「未参与训练的 25 个任务」拆开。由于 RL 的提升几乎都来自 Object 套件，而 Object 的 20 个任务全部在 RL 池里，读者无法判断 28.5% 中有多少来自「见过任务」的拟合、多少来自可迁移的规划能力。

4.3 机制证据

论文对「为什么有效」的证据主要在 SFT 数据配方，而非 RL 机制。Table 4 与论文 Fig. 3 比较两种处理记忆依赖回复的方式：mask-only 直接剔除，得到 27,110 个目标回合、424 步/epoch，成功率 55.2%；rewrite-and-filter 改写并保留评审通过的回复，得到 40,047 个目标回合、626 步，成功率 64.6%。为缓解规模差异，作者比较相近步数：rewrite-and-filter 第 438 步 60.2%，mask-only 第 424 步 55.2%（§4.5，Table 4、论文 Fig. 3）。这支持「保留改写后的监督比直接丢弃更有用」，但作者承认两个数据集在规模和内容上都不同，没有隔离「改写」本身。图 3 展示了两条曲线随步数的变化。

图 3（论文 Fig. 3）：这张图把两种监督配方放在同一条「优化步数—LIBERO-PRO 成功率」曲线上。横轴是 SFT 优化步数，纵轴是 800 个评测 episode 的成功率；两条曲线分别对应直接屏蔽记忆回复与改写后保留回复，圆点标出进入 RL 的检查点。rewrite-and-filter 在早期就更高，并在相近步数保持优势；但两条曲线的训练集大小与终点步数不同，因此这张图说明「新配方整体更好」，不能单独证明「改写操作本身带来全部差异」。读图时应区分「收敛趋势」与「数据规模差异」。

「不是靠测试时记忆」上证据较强。Table 1 中 9B 带记忆 18.9%、不带记忆 18.1%，说明外部记忆对 9B 几乎没用；而 SFT+RL 后的 9B 不带记忆达到 71.0%，排除了「测试时检索」这一替代解释：增益确实进入权重。但权重里是「通用规划策略」还是「教师记忆中的任务知识」，现有实验无法区分。教师是带记忆的 27B，学生在 11–44 状态上模仿它的成功轨迹，轨迹本身包含针对 LIBERO 任务的成功动作序列。论文 §4.2 明确说带记忆规划器的比较是系统级参考，不能隔离「来自带记忆教师的监督」；但摘要和标题仍容易让读者把 71.0% 理解为纯粹的能力提升。

RL 的机制证据更薄。论文未报告：去 RL、更长 SFT 的算力匹配对照；RL 轮次曲线；RL 前后回合数、工具调用与失败类型分布；不同奖励设计的对照；不同组大小/优势估计的消融。Appendix A 只说明没有 KL/熵、token 平均而非严格 episode 平均；Appendix C.2 说明全同奖励组不贡献梯度。因此 65.1→71.0 的 +5.9 只说明「该配置下 RL 带来更好的评测成功率」，不能说明「RL 通过某条机制提升规划能力」。Table 3 证明适配器「能接通」，但没有共享动作接口或去掉 token 匹配的对照，适配器的必要性仍是设计论证。

4.4 成本与适用范围

论文报告的成本主要是训练步数与 episode 数：RL 在 RPent 前 6 轮采集 2,304 个 episode、选中 26,052 个回复、做 206 步优化，CaP-X 跑 15 轮、每轮 384 个 episode（Appendix C.2、C.3）。单个 RPent episode 最多 100 个回合或 7,200 秒，CaP-X 单条回复最多 32,768 个 token（Appendix C.4）；评测为 800 与 10,030 个 episode。论文没有报告 GPU 型号/数量、GPU 小时、token 量、墙钟时间与费用，也没有报告基础设施失败率、被剔除 episode 比例和重试次数。这是明显的成本信息缺口。

论文没有报告人工标注；教师轨迹与记忆回复的改写均由模型自动完成。外部依赖包括 Qwen、RPent、CaP-X、LIBERO、冻结 VLA 与 SAM3 等组件（代码仓库 README）。推理不依赖闭源 API，也不需要外部记忆。代码与检查点已公开（GitHub、Hugging Face，均 HTTP 200）。不过仓库 README 明确说明 SFT 使用的教师轨迹未发布；论文 §5 只说「将发布」，因此目前完整复现 SFT 阶段仍缺关键数据。

全部实验都在 LIBERO 仿真桌面操作任务上，使用两个 harness、一个 9B 基座模型；CaP-X 还依赖真实部署中通常拿不到的特权状态，且没有真实机器人、移动操作或跨任务集评测。LIBERO-Plus 改变了相机、光照、背景、噪声等条件，但底层任务仍是同一批 LIBERO 任务；CaP-X 的 25 个未参与训练的任务没有单独报告。因此，本文能支持「在 LIBERO 同任务分布内，后训练能显著提升 9B 规划器的成功率与扰动鲁棒性，且同一管线可接到两种 harness」；不能支持「可泛化到新任务」「零样本上真机」「比闭源编程智能体更强」等更大结论。

5. 最容易受到审稿人质疑的地方

质疑：训练与评测共享同一批 LIBERO 任务，结论被外推为「规划能力」甚至「通用性」

  • 原文依据：§4.1 说明训练用每个任务的初始状态 11–44、评测用 1–10，任务集合相同；§4.3 说明 LIBERO-Plus 使用「same underlying LIBERO tasks」，只是增加扰动；§4.4 的 CaP-X 虽有 25 个未参与训练的评测任务，但 Table 3 只报告 60 个任务的总平均，没有拆分 seen/unseen（Appendix C.3）。摘要与 §1 的表述是提升「planners’ own capabilities」，论文 Fig. 1 也把 71.0% 与带记忆的闭源规划器并列。
  • 为什么重要：若增益主要来自对 40 个 LIBERO 任务的任务级拟合，「规划器能力提升」就被夸大；部署更关心新物体、新指令、新场景。这直接影响创新性与结论范围。
  • 当前能够得出的判断：现有证据支持「同任务、跨初始状态与扰动」的提升；新任务泛化未证明。CaP-X 的 25 个 held-out 任务本可提供关键证据，但论文没有分组结果，无法确认增益中有多少来自训练任务。
  • 如何验证或补强：报告 CaP-X 训练池 35 个任务与 held-out 25 个任务的分列成功率；在 LIBERO 上留出整个任务/套件；增加新物体、新指令组合；若 held-out 无提升，应把标题与摘要收缩到「同任务规划」。
  • 严重程度：主要问题。

质疑：SFT 贡献占主导，RL 的 +5.9 缺少训练方差与算力匹配对照

  • 原文依据：Table 1 中 18.1→65.1→71.0，SFT 贡献 +47.0，RL 只增加 +5.9；§4.2 的符号检验只针对 800 个评测 episode 上的两个固定检查点（121 胜 74 负，p=0.001p=0.001p=0.001），不是跨训练种子的方差；§4.1 的检查点是在验证状态 45–49 上从十个 SFT 检查点和多个 RL 轮次中选出的；论文没有报告重复训练、置信区间或 RL 轮次曲线。CaP-X 上 RL 的 +9.8 也没有配对检验。
  • 为什么重要：论文卖点是「SFT+RL 配方」；若 RL 增益落在训练/选择噪声内，实际贡献主要是 SFT。65% 成功率附近组内六次常全成功、优势为零，RL 信号本就可能弱。
  • 当前能够得出的判断：SFT 大幅提升稳健（多套件、两基准一致）；RL 的方向性证据存在（配对符号检验、LIBERO-Plus 净增 548、CaP-X 绝对值提升），但训练级稳健性无法确认。缺少「继续 SFT 相同步数」对照，无法排除「RL 只是多训了一点」。
  • 如何验证或补强：用 3–5 个训练种子重复 SFT/RL 并报告均值与标准差；加入「SFT 继续训练相同步数/预算」基线；报告每轮 RL 的验证曲线；对任务级结果做 cluster bootstrap；报告全成功/全失败组比例。
  • 严重程度：主要问题。

质疑：教师带记忆的蒸馏混淆，「无外部记忆」只是测试时成立

  • 原文依据：§4.1 说明教师 Qwen3.8-27B 使用 Harness VLA 发布的记忆文件，学生在评测与 RL rollout 中不访问记忆；§4.2 作者自己写道「The student can learn task knowledge from the trajectories of the teacher with memory」，并承认与带记忆规划器的比较是 system-level reference；§3.3.1 的记忆依赖判定是关键词、连续八字重合、独特数字三种启发式，改写由评审模型完成，但论文没有报告评审的准确率、接受率或人工抽检结果；§4.5 的两种配方在数据规模和内容上都不同。
  • 为什么重要：若学生主要是把教师记忆中的任务知识「压进权重」，71.0% 更像任务知识蒸馏，而不是规划能力后训练；「without external memory」只在测试时成立。评审模型的可靠性也直接影响 SFT 目标质量。
  • 当前能够得出的判断：论文对这个混淆是透明的，但摘要与标题没有充分限定；「9B + 记忆 18.9%」排除了「测试时记忆直接带来增益」，但不能排除「教师记忆经监督进入权重」。改写配方优于 mask-only 支持保留监督有价值，但数据规模不同，不能隔离改写操作。
  • 如何验证或补强：用不带记忆的 27B 教师重复 SFT；让学生测试时也用记忆，做 2×2 对照；报告评审模型的判定一致性、接受率与错误案例；构造等规模数据集，分离「改写」与「保留更多目标」。
  • 严重程度：主要问题。

质疑：「首个通用后训练框架」的创新边界不清，且缺少与最接近方法的实证比较

  • 原文依据：§1 声称「to our knowledge, AgenticRoboRL is the first general post-training framework to agentic robotics systems」；§2 列出 Robo-Harness K1、World Action Agent（都在各自 harness 内用教师轨迹训练 9B 学生）、REAL（SFT+在线 RL，规则规划器监督与 shaped reward）、CaP-RL（单轮控制代码 RL），以及 Agent Lightning、LEGO-RL、POLAR 等 agent RL 基础设施；§3.3 的优化组件是标准的组内留一法、dual-clip PPO 与截断重要性采样（Appendix A）。
  • 为什么重要：最接近的 9B 学生训练方法已经存在，本文的核心增量是「多轮 RL + 跨 harness 适配器」的组合，而不是「首个框架」。缺少与 Robo-Harness K1/World Action Agent/REAL 的同 harness 对照，无法判断收益来自新框架还是「27B 教师轨迹 SFT」本身。
  • 当前能够得出的判断：系统抽象（模型调用边界、五字段适配器、token 匹配）是有价值的工程贡献，跨两个 harness 跑通也是实质工作；但「首个」「通用」是作者主张，按本文的相关工作与实验只能确认差异，不能确认首创。算法层面没有新目标函数，创新性主要是集成与适配。
  • 如何验证或补强：在同一 RPent/LIBERO-PRO 设置下复现或引用 Robo-Harness K1、World Action Agent 的 9B 结果；加入「SFT-only + 相同教师数据」与「SFT+RL 用共享动作接口」对照；明确「首个」的范围（跨 harness、多轮 RL，还是只训练规划器）。
  • 严重程度：主要问题。

质疑：成本、失败率与复现材料报告不足，CaP-X 还依赖特权状态

  • 原文依据：§4.1 与 Appendix C 报告了学习率、批大小、步数、episode 数和回合上限，但没有 GPU 型号/数量、GPU 小时、token 总量、墙钟时间或费用；没有报告基础设施失败率、被剔除 episode 比例、重试次数；LIBERO-Plus 每个配置只跑一个 episode（§4.3）；CaP-X 使用 privileged state（§4.4）；代码仓库 README 说明 SFT 教师轨迹未发布，而论文 §5 表示将发布教师轨迹与检查点。
  • 为什么重要：这是框架论文，读者最关心「要多少资源、失败率多高、能否复现」；特权状态在真机上通常不可得，若结论依赖它，「通用性」就更偏仿真。
  • 当前能够得出的判断：代码、检查点和超参已公开，复现条件较好；但 SFT 的教师轨迹缺失，成本与失败率未报告，LIBERO-Plus 单次评测无方差信息。CaP-X 结果应视为「特权状态仿真」结论，不能直接外推到真机。
  • 如何验证或补强：发布教师轨迹或数据构造脚本；报告 GPU 小时、token/调用数、墙钟时间与基础设施失败率；对 LIBERO-Plus 做固定种子重复评测并给出置信区间；增加无特权状态对照，或明确标注限制。
  • 严重程度：次要问题。

6. 审稿式总评

作者发现现有智能体机器人系统主要靠改进 harness 和外部记忆、依赖强闭源规划器，而没有提升规划器自身；因此提出 AgenticRoboRL，把编程智能体的 SFT+多轮 RL 后训练搬到机器人 harness 中，通过记录代理、五字段适配器与「只训练规划器」的约束，让两类执行机制共享同一条训练管线。实验在 LIBERO-PRO、LIBERO-Plus 与 CaP-X 上表明，9B 规划器的成功率从 18.1% 提升到 71.0%，在 LIBERO-Plus 上达到 72.2%，CaP-X 上从 2.7% 到 28.5%；其中「SFT 带来大部分增益」「测试时不用记忆也能提升」「跨两个 harness 能跑通」证据较强，但「RL 的独立贡献」「新任务泛化」「教师记忆蒸馏的作用」仍缺少充分支持。本文最有价值的是把 agent RL 训练接口抽象成可跨 harness 复用的工程方案，并公开代码与检查点；最大的审稿风险是把同任务上的强结果外推为通用规划能力，以及缺少与最接近的 9B 学生训练方法的对照。

  • 问题定义清晰度：强。论文明确区分了 VLA 技能调用与控制代码生成两种执行机制，并把「只训练规划器」作为核心约束；问题边界在 §3.1 交代得清楚。扣分点是「通用」「首个」的措辞比实验覆盖更宽。
  • 创新性证据：中。模型调用边界与适配器是实质的系统抽象，跨 harness 跑通有演示价值；但 RL 算法组件是标准的，缺少与 Robo-Harness K1、World Action Agent、REAL 等最接近工作的实证比较，「首个」未被证明。
  • 方法可信度：中。管线具体、超参完整、代码与检查点公开，token 匹配与有效性标志等工程细节可信；但教师记忆蒸馏、评审模型可靠性、RL 的算力匹配对照都没有充分隔离。
  • 实验支持力度：中。主结果提升大，且有配对符号检验、扰动分类结果和第二个 harness；但训练与评测同任务、单训练种子、无置信区间，CaP-X 绝对水平低且 seen/unseen 未拆分。
  • 可复现性：中。代码、两个检查点、详细超参和最小可运行 harness 都已公开；但教师轨迹未发布、训练种子与成本未报告，完整复现 SFT 阶段仍受限。
  • 综合阅读价值：高。对 agentic robotics、agent RL 或 VLA 读者，本文提供了可操作的训练接口设计与大量工程细节，且作者对部分限制有诚实交代；适合作为该方向的入门与批判性阅读材料。
