0. 一句话结论

论文针对的问题是：视觉-语言-动作模型（vision-language-action model, VLA）与世界动作模型（world-action model, WAM）从通用视觉语言模型（vision-language model, VLM）或视频生成基座继承感知，在密集场景与微小目标上定位不够精确，导致稀缺的动作数据被迫同时承担感知与控制两项学习。作者把定位（grounding）做成基座模型的原生能力：用共享词表上的量化坐标 token 统一生成点与框，经多模态预训练、坐标对齐监督微调（supervised fine-tuning, SFT）与 GRPO 强化学习训练出约 4.84B 参数的 GroundingPI，再作为视觉基座接入下游动作学习。在作者统一评测协议下覆盖 34 个基准、11 类感知能力，平均 73.68%（高于 GPT-6 Astra 的 71.54%），并在固定动作头与预算的受控实验中改善机械臂操作与自动驾驶；但”定位能力本身带来动作收益”的因果归因受基座规模、预训练数据与评测协议差异混杂，且闭环控制时延未被验证。

1. 论文具体想解决什么问题

物理智能（physical intelligence）场景遵循”先确定在哪行动、再决定如何行动”：整理杂乱的桌面时，需要先找到杯子和杯柄，才能规划如何抓取。VLA 与 WAM 模型越来越多地依赖通用 VLM 或视频生成基座获得感知能力，但这些基座的预训练目标不是精确的空间定位，作者称其中存在”能力错配”（capability mismatch）：动作学习需要的精确、任务条件化的感知没有被预训练覆盖，感知成为下游动作学习的瓶颈（§2.2）。

现有做法在两个层面的不足构成了论文的问题判断。第一，通用 VLM 与专用 grounding 模型的感知能力本身有缺口。作者自评 44 个基线后发现：Qwen3.5 系列在密集目标场景明显吃力，就连 GPT-6 Astra 也有提升空间——例如 Dense200 上 Qwen3-VL-4B 仅 14.02 F1mIoU、Astra 65.04（Table 1，§1）。第二，近期 VLA 策略配方把感知作为辅助目标引入动作学习（如 π0 → π0.5 在训练中加入包围盒预测、其他工作加入辅助模块或区域重建），作者认为这类机制只覆盖部分感知信号、往往依赖额外标注或策略专用组件，难以在物理智能的多样场景中规模化（§2.3）。

作者的归因和核心假设是：与其在动作学习中”补感知”，不如把强定位作为基座的原生能力先行预训练（perception-native foundation，感知原生基座），让下游策略”建立在感知之上”，而不是从任务专用代理目标中恢复感知。为此论文提出三个研究问题：定位基础模型的感知能力能被推到多远（Q1）、更强的定位对物理智能贡献什么、哪种能力最重要（Q2）、这对未来具身基础模型设计有什么启示（Q3）（§1）。

需要区分三层：感知瓶颈与动作数据稀缺是领域早已存在的一般问题；本文的新观察是在统一协议下量化了通用模型与专用模型在密集/微小目标上的缺口，并系统测量了 grounding 训练规模与数据组成对下游迁移的影响（§5.3）；本文实际解决的具体子问题则是”训练一个强定位基座并验证其作为动作学习基座的价值”，而非直接交付闭环控制器——System-1 部署、物理提示（physical prompting）等被作者明确列为”方向”而非已验证能力（§10.4、§11）。

2. 创新点是什么

真正的技术增量可以概括为”把 grounding 作为可预训练的原生能力做全做强，并把它当作受控变量验证对物理智能的迁移价值”。具体包括：量化坐标 token 的统一生成式接口覆盖 8 类空间任务；字段级融合、任务验证与专家迭代的数据引擎（data engine）；为定位与 OCR 设计多奖励 GRPO 后训练；以及”固定动作学习其余环节、只换感知基座”的跨域迁移实验设计与规模/数据组成分析。以下逐项说明。

  1. 统一视觉基元接口：坐标离散化为 <0>–<999> 共 1,000 个原子 token，与语义标签、协议标记共享同一输出词表，点/框/轨迹按模板结构自回归生成，缺席类别显式输出 None（§3.1、§7.1）。与最接近的生成式 grounding 方法 Rex-Omni、LocateAnything 相比，差异在于同一接口覆盖的任务组更多、prompt 协议统一，属于已有思路的组合与规模扩展，而非全新思想。证据一句话：§4.2 的 11 类能力广度与 Fig. 10 的坐标表示消融（量化 73.68 vs 文本 71.21）。

  2. 数据引擎：多教师按字段（语义/几何）融合标注，按任务所需字段做三分验证（accepted/rejected/unresolved），由统一 grounding 专家迭代标注、对不确定项调用互补教师与局部视图（§3.2、§7.3）。相对常见自动标注流水线，差异点是字段级验证、任务依赖的完整性与覆盖检查、以及修订传播机制。证据一句话：论文未报告该引擎的对照消融，贡献比例无法从现有材料确认（§4.3）。

  3. 面向定位的多奖励 GRPO 后训练：为 grounding 设计集合覆盖奖励 R_set 与严格定位奖励 R_strict（多阈值 F1、匹配 IoU、格式/计数/顺序与重复、超框惩罚），组内标准化后按 0.7/0.3 组合；OCR 用匈牙利匹配的文本-几何复合奖励（§3.3.3、§7.6）。这是把 GRPO 从推理/数学任务迁移到结构化空间输出的多奖励工程。证据一句话：Fig. 10 中去掉该阶段 72.86 vs 73.68（+0.82 pp）。

  4. 受控的”感知基座→动作学习”迁移协议与规模/组成分析：固定 Action DiT、动作数据、优化预算与推理流程，仅替换预训练基座（8 个基线、4 个家族），并单列 grounding 训练规模（88.4B→221B tokens）与数据组成（leave-one-out，留一法）两条分析线（§4、§5.2–5.3）。它比常见的整系统对比更干净，但基座间的规模/数据/算力差异仍未消除（§4.3）。

3. 作者如何解决

核心思路的直觉是：把”在哪里”变成一种可以像语言一样生成的能力——坐标先离散成词表里的原子 token，模型以自回归方式输出”标签 + 几何载荷”的结构化响应；这种能力经大规模预训练固化为基座的感知接口，下游动作学习只在这个接口上做少量适配。下面按实际运行流程走一遍。

（1）输入与输出协议。输入是图像 I 与语言查询 P，每类任务固定 prompt 模板（如”Locate all the instances that match the following categories: cat1cat2…”，Table 7）。输出是变长结构化响应：每个条目为 <|object_ref_start|>标签<|object_ref_end|> 加 <|box_start|>载荷<|box_end|>，框用 4 个连续坐标 token（xyxy 顺序），点用 2 个；同一标签的多个实例共用一个 wrapper，条目间用逗号加空格分隔；被查询但不存在的类别保留标签并输出文本 None（§3.1、§7.1）。坐标约定：图像坐标按宽高归一化到 [0,1000] 网格后映射

q(v) = ⌊(999v + 500) / 1000⌋

由 <0>–<999> token 编码，还原时用 q/999 乘图像尺寸；源数据的 xywh 先转为 xyxy，多边形取轴对齐外框，非有限、越界、倒置或退化的几何值直接拒绝而不是静默修补（§7.1）。

（2）模型与固定流程。视觉侧是 MoonViT-V2（Kimi K3，27 层、patch size 14）；每 2×2 相邻 patch 的 1024 维特征聚合为一个 4096 维特征，经两层无偏置线性层（4096→4096→2560，GELU + RMSNorm）投影到语言嵌入空间；视觉预算最多 4096 patch，产生最多 1024 个视觉 token。语言侧是 Qwen3-4B 解码器（36 层全注意力、隐藏宽 2560、32 查询头 / 8 键值头、RoPE base 5M、无滑窗），词表从 151,669 扩到 152,670（新增 1,000 个坐标 token 与 分隔符，坐标 token ID 为 151669–152668），输入嵌入与输出头不共享；完整模型约 4.844B 参数，其中视觉编码器 0.40B、projector 0.027B（Table 8、Table 9、§7.2）。哪些由模型决定、哪些固定：输出什么类别、多少个实例、坐标值与顺序由模型自回归决定；协议层面则固定——量化网格、模板与分隔符、同一标签内按 x1（框）或 x（点）稳定排序、非法几何拒绝，都是流程约定（§7.1）。图 1 展示了从图像到结构化 token 序列的完整数据通路。

图 1（论文 Fig. 1，arXiv HTML 编号；PDF 中因多一张 teaser 图为 Fig. 2）：图像经 MoonViT-V2 编码、2×2 空间聚合与 MLP 投影进入 Qwen3-4B 语言序列后，解码器在同一个词表上自回归生成语义标签与坐标 token，并组装成”标签-几何载荷”结构化响应（示例中含两个 minion、一个人与缺席的 car 类别）。读者应理解两点：其一，定位被完全表述为带几何载荷的语言生成，没有任何独立的检测头或坐标回归模块；其二，标签与坐标共享同一输出头，是后续用同一权重覆盖 8 类任务、并把轨迹也纳入同一接口的前提。

（3）数据构建。监督来自公开数据集叠加数据引擎产出。数据引擎的运行链路是：多教师集成（面向目标定位、分割、文本识别、GUI 元素、文档区域的互补模型）先生成候选，类别级任务先做类别发现再条件定位；然后按字段融合——语义与几何字段分别处理，已验证信息保留、分歧字段触发额外补证，对象-部件包含关系与词-行关系保留而不当重复合并；接着是任务相关验证，每条监督项被标为 accepted/rejected/unresolved，只有查询所需字段全部通过才接受，要求全部实例或计数的查询还要做覆盖性检查，”不存在”本身也是需要验证的事实（空预测不构成证据）；通过验证的标注训练一个统一 grounding 专家做迭代标注，其预测再走同一套融合与验证，未解决情形调用互补教师与局部视图（裁剪预测量映射回原坐标），修订会传播到依赖任务、失效标签撤回（§3.2、§7.3）。图 2 给出这条”候选—融合—验证—版本化监督”的闭环。

图 2（论文 Fig. 2；PDF 中为 Fig. 3）：教师集成产出候选后，逐条目按字段（框、掩码、属性）打上通过/待定/失败标记；只有任务所需字段与（必要时）覆盖检查全部通过，才进入 versioned supervision，按 8 类任务派生训练监督；待定项经互补教师或局部视图回流再融合，被接受的标签用于训练 grounding 专家继续迭代标注。读者应理解它是一条带三态验证和回流的闭环数据生产管线，而非一次性伪标注，这正是训练监督规模的主要来源——同时也是论文中唯一没有对照消融的组件。

（4）训练配方分三阶段：基础 VLM 训练（Pretrain 1，含 Stage 1–3）、坐标对齐（Pretrain 2，即 SFT，Stage 4）、强化学习（RL）。论文报告总训练曝光为 500.41B + 221.17B tokens（论文未说明两个数字各自对应哪一子阶段；Fig. 8 的规模分析用 88.4B–221B 的 grounding 训练曝光口径）（§7.4）。Pretrain 1 依次为：冻结两侧骨干、仅训练 projector 的图像-描述对齐；解冻全部模块的文本 + 图文联合预训练（语言峰值学习率 1e-5，视觉/projector 1e-6）；通用视觉与视频理解（上下文从 8192 扩到 32768 token）。SFT 从 Stage 3 权重出发，用 8 个空间任务组（检测、GUI、指代框、指代指向、OCR、文档布局、密集指向与计数、视觉提示）做助手响应位置的因果交叉熵监督；语义、坐标与协议 token 共用同一下一 token 预测目标，没有额外 IoU 回归损失（§7.4–7.5，Table 10）。

（5）RL 后训练（GRPO）。每个图像-查询采 G=8 条自回归回答。grounding 用两个奖励分量：R_set 以”每个参考框取与预测的最大 IoU 并按类别校验”计算软召回与软精确率，再合成 F1 型覆盖分数（匹配对每个参考独立进行、可复用同一预测，因此该代理分数可超过 1）；R_strict 是加权和——结构格式 0.10、预测与参考数量一致 0.10、IoU 0.50/0.75/0.95 的平均检测 F1 0.50、匹配框 IoU 0.25、顺序约定 0.05，另有超框 -0.07 与重复框 -0.03 惩罚（Table 12）。两分量各自在 prompt 内标准化，优势为

Ã = 0.7·Z(R_set) + 0.3·Z(R_strict)

再在整批响应上做二次标准化；OCR 则用匈牙利一对匹配对文本与几何整体打分，乘格式门控与去重/超框/无效惩罚得到单一复合奖励（§3.3.3、§7.6.1）。优化用带裁剪的 GRPO 目标，以冻结的 SFT 检查点作参考策略、KL 惩罚系数 β=0.02；该阶段冻结视觉编码器与 projector，只更新语言参数（含输入嵌入与输出头），学习率 5e-7 恒定，256 GPU（§7.6、Table 11）。图 3 把 SFT 与 GRPO 两阶段的监督信号与奖励路径画在一起。

图 3（论文 Fig. 3；PDF 中为 Fig. 4）：左侧 SFT 阶段对完整结构化响应（含坐标 token 与协议标记）做 token 级交叉熵的教师强迫；右侧 GRPO 阶段对每个图像-查询采样 G=8 条 rollout（同一因果掩码下的自回归序列），grounding 响应按集合覆盖与严格定位两个奖励标准化组合优势，OCR 响应按文本+几何复合奖励给优势，再经裁剪 GRPO 目标回传，只更新语言参数。图中 rollout 示例（缺失、重复、对齐）说明奖励要同时惩罚漏检、冗余与位置偏差。读者应从中理解：奖励的信用分配是”整条响应一个优势值分摊到每个 token”，没有 token 级细粒度标注输入。

（6）推理阶段的变化与两类下游适配。RL 后视觉侧保持冻结，输出仍是同一套 token 协议；下游适配发生在接口层。自动驾驶（nuScenes）：不做额外动作头，直接把未来 3 秒轨迹表示为 6 个有序 waypoint（路点；0.5 秒间隔、当前自车坐标系、x 向前 y 向左、单位米），用固定范围 x∈[-60,60]、y∈[-20,20] 映射到同一 <0>–<999> 词表，由语言头自回归生成，仅对轨迹响应做交叉熵适配；观测是前视相机加最多 7 条历史自车状态（§4.1、§8.1）。机械臂操作：沿用 StarVLA 的层级连接（非本文发明）——预训练基座对每条观测加指令只前向一次，取 8 个归一化深度的隐藏状态（hidden states），经 LayerNorm、各基座专属线性投影与深度嵌入，再由共享重采样器（resampler）压成每深度 64 个条件 token，注入固定的 π0 式 Action DiT（16 个原子块：8 个交叉注意力块分别读 8 个深度特征，与 8 个动作自注意力块交替；宽 1024），在机器人状态条件下对噪声动作块做流匹配（flow matching）去噪，推理用 4 步 Euler、每个观测仅 1 次基座前向；论文移除了模型专属的文本/本体感受旁路，使信息只能经被评测的基座表征到达动作专家（§8.2.1–8.2.2，Table 14）。每个基准内固定动作专家、演示数据、优化预算（40,000 updates、40 accelerators、全局批 1280）与推理流程，只替换基座（§8.2.3、Table 15）。

4. 解决得怎么样

4.1 实验设置

  • 定位评测：44 个基线 × 34 个基准 × 11 类感知能力（常用/长尾检测、密集/微小检测、指代检测、对象指向、指代指向、机器人/空间指向、OCR、GUI、布局、视觉提示）（§5.1、§12）。指标：框与 OCR 用 F1mIoU（IoU 阈值上的平均），指向用 F1@Point，空间/机器人/GUI 用任务准确率，另报 parse error。作者模型为 10 次运行（5 随机种子 × 每种子 2 次）均值；本地评测的基线为 3 次运行均值；GPT-6 Astra 以 thinking effort=High 评测；部分基线分数为外部引用（星号标注），另有条目因 prompt/parser 兼容性标 † 或 N/A（§5.1、§12 开头）。
  • 迁移评测：nuScenes 开环 L2（六个 waypoint、平均 L2@1/2/3s）；RoboTwin 2.0（50 个桌面任务；Full 用 Clean+Randomized 训练评测，Clean2Random 仅用 Clean 训练、Randomized 场景测试）；RoboCasa-GR1 人形灵巧手（仅头摄；ID 全协议 + Unseen Appearance/Combinations/Object Types 三个 OOD 套件）（§5.2、§8.1–8.2）。基线为 8 个预训练基座、4 个家族：通用 VLM（Qwen3-VL-4B、PaliGemma-3B）、视频生成（Wan2.2-TI2V-5B、Cosmos-Predict2.5-2B）、grounding 模型（LocateAnything-3B、Rex-Omni-3B）、具身基座（RynnBrain、RynnBrain1.1，均 2B）（§5.2.2）。
  • 主实验回答”感知广度与迁移收益”，消融与附录回答”哪个设计/数据起作用”：Fig. 10（坐标表示、视觉编码器、RL 阶段）、Fig. 9 数据组成 leave-one-out、Fig. 8 规模扫描、§9.4 OCR 混合调度、Table 5/Fig. 11 输出效率，以及各基准完整表（§12）。

4.2 关键结果

  • 总体：34 基准 11 类能力均值 73.68%，高于 GPT-6 Astra 的 71.54%（同协议评测；摘要、§5.1、Fig. 4）。优势集中在密集/微小目标：Dense200 以 74.53 F1mIoU 大幅领先 Astra 65.04 与 Qwen3-VL-4B 14.02（Table 1）；常用/长尾与指代基本持平或小胜：COCO 62.98 vs Astra 62.75、LVIS 56.02 vs 54.97、HumanRef 88.56 vs 83.01（Table 1）。OCR/布局多数领先（SROIE 72.47 vs 53.57、M6Doc 74.82 vs 60.59），但 TotalText 49.32 落后 Astra 53.55（Table 3）。
  • 明确落后项：ScreenSpot-Pro 65.78 vs Astra 86.70（作者称 “Astra retains a substantial advantage”）；FSC147 视觉提示 57.99，落后 Astra 61.04 与 SenseNova-Vision 62.51（Table 36）；COCO 严格阈值 F1@IoU0.95 为 22.84，落后 SenseNova-Vision 的 28.88（§12.1）。
  • 操作迁移（固定动作头、数据与预算）：RoboTwin2.0-Full 以 66.20% 成功率居首；Clean2Random 场景鲁棒性 OOD 17.60% vs 次优 Rex-Omni 14.10%，摘要中”up to 24.8%”的相对提升即此口径（§5.2.2）。RoboCasa-GR1 ID 37.75% 未拿第一，落后 RynnBrain 39.00%；三个 OOD 套件（Type/Appearance/Container）均第一（§5.2.2）。数据效率：用 50% 演示达到 28.75% SR，超过所有基线在 75% 数据下的成绩（最高 RynnBrain 27.75%）（Fig. 7、§5.2.3）。图 4 汇总了这套受控比较。

图 4（论文 Fig. 5；PDF 中为 Fig. 6）：所有基座接到同一固定 Action DiT、相同动作数据与训练预算，仅替换预训练基座；六个操作面板为成功率（RoboTwin Full/Clean2Random 与 RoboCasa-GR1 的 ID 与三个 OOD 套件），三个驾驶面板画的是 nuScenes 开环 L2 误差的倒数（越高越好），同一颜色对应同一基座家族。读者应从中理解”固定下游配方、只换感知基座”的设计在哪些条件成立：GroundingPI 在 6 个操作设置中 5 个第一（唯一例外是 RoboCasa-GR1 ID），且四个 OOD 全部第一——这正是论文”感知基座支撑泛化”主张的主要视觉证据。

  • 自动驾驶：nuScenes 开环 L2 平均误差 0.296 m，优于 Qwen3-VL-4B 0.301 m 与 RynnBrain 0.308 m；作者自称这是”modest, consistent gain”，并明确该评测不涉及闭环节奏或时延（§5.2.1）。
  • 消融：量化坐标 73.68 vs 文本坐标 71.21，且文本坐标推理相对速度仅 0.25×；MoonViT-V2 73.68 vs MoonViT 73.17 vs Qwen3-ViT 71.65；去掉 RL 阶段 72.86（Fig. 10、§5.3.4）。输出效率：每框 7.6/5.1 token（COCO/Dense200）vs SEED1.5-VL 的 148.8/74.5（Table 5；论文强调这是序列化口径，不是实测加速）。
  • 方差缺口：下游操作与驾驶结果未报告重复种子方差或置信区间；论文仅在规模分析处自认”4 个设置、无重复种子，不足以确立 scaling law”（§9.2）。grounding 基准的 10 次运行口径只覆盖作者自家模型的总分。

4.3 机制证据

论文提供了”有效”的较充分证据，以及部分”为什么有效”的配置级证据，但关键机制的隔离实验缺失较多，作者对此有较多自我披露。

  • 接口设计的支持证据：坐标表示有直接对照（量化 vs 文本：+2.47 pp，且文本显著更慢），这是设计选择层面的有效支持（§9.5）；但视觉编码器比较同时更换了预训练视觉表征，论文自认”不能隔离跨层融合”的作用（§9.5）。
  • RL 阶段的贡献较小：去掉后只降 0.82 pp（Fig. 10）；论文未报告 RL 对下游迁移的单独消融。
  • 数据引擎：论文未报告”多教师融合 + 三分验证”相对朴素标注（单教师伪标签、直接混用公开标注）的同预算对照——这是审稿人判断，论文未报告（§7.3 仅有流程描述）。
  • 迁移的替代解释：下游比较固定了动作头容量、数据量、训练步数与推理流程，能排除这些混杂；但基座本身在参数量（GroundingPI 4.844B vs PaliGemma 3B、Rex-Omni/LocateAnything 3B、RynnBrain 2B）、架构、预训练数据（含自建数据引擎）与算力上均不同，论文在 §10.1、§11 自认”pretrained foundations differ in scale, architecture, and supervision””cannot isolate architectural causes”——“更强的基座赢了”与”更强的定位赢了”两种解释无法分离。
  • OCR”催化剂”假设：论文给出梯度对齐的理论框架（§9.4 的局部下降界）与混合调度实验（Table 18：cold-start + batch 混合在操作上最好、驾驶不变），并明确称其为 hypothesis，未做决定性对照。
  • 规模与组成的机制证据（图 5）：grounding 曝光从 88.4B 到 221B tokens 时，grounding 均分单调上升、操作 OOD 成功率同步上升（26.59→33.38），但 ID 在末点回落（38.75→37.75），论文自认只能算趋势（§9.2、Table 16）。

图 5（论文 Fig. 8；PDF 中为 Fig. 9）：固定下游动作配方，把 grounding 训练曝光从 88.4B 扫到 221B tokens。grounding 均分（左轴）单调上升，RoboCasa-GR1 的 ID 与 OOD 成功率（右轴）整体上行，其中 OOD 与 grounding 的曲线走势最贴合，ID 在末点小幅回落。读者应理解这张图的证据性质：两组曲线同向变化支持”感知随规模增强、泛化随感知增强”的叙事，但四个点、无重复种子，作者也只将其表述为趋势而非定律。

数据组成的影响见图 6：leave-one-out 显示，密集 grounding（B 组）是空间核心（去掉降 4.67/3.47 pp、L2 升 0.015 m）；OCR+布局+GUI（F 组）单独使用最弱，但去掉后降幅最大（5.33/3.63 pp）——支持”互补组合”结论；不过这是不完整因子设计，论文自认无法识别交互效应、A 组单独效应或 OCR 的因果效应（§9.3）。

图 6（论文 Fig. 9；PDF 中为 Fig. 10）：左侧列出各配方包含的任务组（A 基础 grounding、B 密集 grounding、C 指代、D 基础指向、E 机器人指向、F OCR/布局/GUI），中面板给出同一动作配方下的下游成绩（操作 ID/OOD 成功率与 nuScenes L2），右面板是 leave-one-out 降幅矩阵（颜色越深降幅越大，A、D 行缺失表示对应消融不可得）。读者应理解其核心结论：全六组最好（37.75/33.38/0.296）；去掉 B 或 F 的代价明显大于去掉 C、E，但 F 单独使用时最弱——即”密集 grounding 提供空间核心、辅助感知须组合使用才放大价值”，这也是论文”规模决定学多少、组成决定迁移好不好”这一论断的全部实验基础。

综合 §4.2–4.3 可以总结：论文证明了”用这套基座替换后，动作学习的平均表现与 OOD 泛化更好、且更省演示数据”；但对其中每项设计（接口、数据、奖励）为何贡献、贡献多少，只有配置级和相关性证据。

4.4 成本与适用范围

  • 训练成本：Pretrain 1 + Pretrain 2 用 128 GPU（BF16、ZeRO-1、FlashAttention），RL 用 256 GPU（ZeRO-2）；总训练曝光 500.41B + 221.17B tokens；下游动作学习每个基准 40,000 updates、40 accelerators。墙钟时间与 GPU-hours 论文未报告。
  • 数据成本：监督来自公开数据集加数据引擎；引擎依赖多教师集成，但教师模型清单、人工复核量与其生产成本论文未报告；论文在 Reproducibility Statement 中承诺公开代码、模型权重与评测数据（含统一 prompt、parser 与指标实现），截至归档日（2026-10-13）代码仓库与模型权重已可访问，评测数据尚未见发布说明，训练数据与数据引擎标注未公开。教学提示：这不同于”无数据成本”，而是成本被转移到多教师推理与验证规则的工程维护上，论文未量化。
  • 推理成本：绝对时延与吞吐论文未报告；报告的是相对量——文本坐标相对速度 0.25× 量化坐标、每框 token 数 7.6/5.1（vs SEED1.5-VL 148.8/74.5）、生成时间随预测目标数上升（Fig. 11）；动作推理为每观测 1 次基座前向 + 4 步 Euler 去噪（Table 14）。作者明确这些不是闭环动作时延口径（§9.5、§11）。
  • 改善了什么：密集与微小目标的覆盖（Dense200）、空间/OCR/布局多数基准、操作的泛化与动作数据效率、nuScenes 开环误差的小幅下降。
  • 仍未解决：微小框与高 IoU 边界精度、TotalText、FSC147、前沿 GUI（ScreenSpot-Pro 大幅落后 Astra）、闭环驾驶与实时双系统控制、物理提示、以及 §10 提出的”门控记忆/多层视觉注入”等架构机制——论文在 §11 逐项自认。

5. 最容易受到审稿人质疑的地方

质疑：SOTA 结论建立在自建统一评测协议上，部分最强基线的可比性未被证明

  • 原文依据：§5.1 与 §12 的 reporting conventions——多条基线因 prompt/parser 兼容性标 †（”descriptive rather than definitive”）、因接口不支持标 N/A（GroundingDINO 的 GUI/OCR/layout、Kimi-K3 的 pointing/OCR/layout、SenseNova-Vision 的 GUI 等）；本地评测基线 3 runs vs 自家模型 10 runs；大量行来自外部引用（星号）；”Avg” 是 11 个能力分的等权均值，且由作者定义的能力划分计算（§12 开头）。
  • 为什么重要：直接影响”new state of the art, above the larger GPT-6 Astra (71.54%)”这一头条结论的有效范围——若协议（prompt 模板、parser、能力等权）与基线原生使用方式不一致，总分差距可能部分来自评测设计而非能力差异。
  • 当前能够得出的判断：论文对不可比条目做了披露（应肯定），但不可比与外部引用条目如何影响总分排名，当前材料无法确认；”44 baselines”的池中也包含无语言接口的 closed-set 检测器，使规模观感大于实际可比数量。
  • 如何验证或补强：公开全部 prompt/parser 与逐条评测脚本；报告剔除 N/A/† 与外部行后的排名敏感性分析；对 2–3 个最强基线做多 prompt 敏感性测试并人工复核。
  • 严重程度：主要问题。

质疑：”更强的定位带来更好的动作学习”的因果归因混杂在基座整体差异之中

  • 原文依据：§8.2 固定了动作头、数据与预算，但 §10.1/§11 自认基座在”scale, architecture, and supervision”上均不同、”cannot isolate architectural causes”；GroundingPI 额外拥有数据引擎标注与 500B 级训练曝光，且下游适配会更新基座参数（1e-5 学习率）。
  • 为什么重要：论文的中心主张是”grounding 作为感知基础”的价值；若增益主要来自更大的模型、更好的数据或更多算力，结论应弱化为”一个更强的基座赢了”，影响创新性主张的成立范围。
  • 当前能够得出的判断：现有证据支持”GroundingPI 是更有效的动作学习基座”（受控配方下 5/6 设置第一）；但对”增益由定位能力贡献”只有相关性证据（规模曲线、组成消融），无法排除规模/数据/算力混杂。
  • 如何验证或补强：给通用基座（如 Qwen3-VL-4B）施加同数据、同算力的后训练作为对照；或对 GroundingPI 做能力退火（打乱/替换坐标监督）后的下游对照，检验定位质量与动作收益的耦合。
  • 严重程度：主要问题。

质疑：开篇动机强调”足够快以支持闭环控制”，但闭环与时延证据缺失

  • 原文依据：摘要与 §1 将 closed-loop control 的时延要求列为动机；实际评测是 nuScenes 开环 L2（§8.1 自认 “does not establish closed-loop control performance”）与离线操作基准；没有绝对时延测量，只有相对速度与 token 数（§9.5）；§10.4/§11 自认部署级双系统控制器 “remains to be evaluated”。
  • 为什么重要：动机与证据链不闭合会削弱”面向物理智能”的定位；开环 L2 的 0.296 vs 0.301 m 差距本身很小，不能支撑闭环可用性主张。
  • 当前能够得出的判断：论文达到的是”感知基座改善离线动作学习”的层次；”满足闭环控制需求”没有任何实验直接支持（论文未报告）。
  • 如何验证或补强：报告端到端观测-动作时延（含生成）随目标数的 p50/p99，以及闭环驾驶或真机节拍实验。
  • 严重程度：主要问题。

质疑：关键机制的消融不完整，数据引擎与 OCR 催化等模块的贡献无法分离

  • 原文依据：数据引擎无对照消融（§7.3）；编码器比较混入预训练视觉表征差异（§9.5）；leave-one-out 缺 A、D 行且论文自认”no interaction effect or OCR-only causal effect is identified by this incomplete factorial design”（§9.3）；OCR 催化为 hypothesis（§5.3.2、§9.4）；通用数据组成（Stage 2/3 的文本/视频混合）未做消融。
  • 为什么重要：创新性主张（数据引擎、观察—融合—验证流程、OCR 催化）缺少”移除该设计会怎样”的直接证据时，方法的可替代性与贡献比例无法评估。
  • 当前能够得出的判断：作者对大多数不完整之处已主动披露；机制层面的因果结论当前属于”配置级经验”，证据不足。
  • 如何验证或补强：数据引擎 vs 单教师/原始标注的同预算对照；§9.4 已给出 box-only 控制的设计蓝图，可落地执行；补全因子设计（含 A-only 行）。
  • 严重程度：次要问题。

质疑：下游关键结论缺少统计稳定性证据，多处优势差距在噪声量级

  • 原文依据：操作与驾驶结果未报告重复种子方差/置信区间；数据效率优势为 28.75% vs 27.75%（1 pp，§5.2.3）；RoboCasa-GR1 ID 落后 1.25 pp（37.75 vs 39.00）；nuScenes 优势 0.005 m；§9.2 自认 4 个规模设置无重复种子。
  • 为什么重要：这些数字支撑”泛化更好””数据效率更高”等核心结论；无方差时无法判断 1 pp 级别差异是否稳定，也无法判断 ID 末点回落是否系统性。
  • 当前能够得出的判断：证据方向一致（四个 OOD 设置、两个域、两条分析线），但单点差距的统计显著性与稳定性当前无法确认（论文未报告）。
  • 如何验证或补强：报告 3–5 个种子的均值±标准差、逐 OOD 套件成绩与配对显著性检验。
  • 严重程度：次要问题。

6. 审稿式总评

作者发现通用 VLM 与视频生成基座在密集场景、微小目标的精确定位上留下能力缺口（自评 Dense200 上 Qwen3-VL-4B 仅 14.02、Astra 65.04），因此提出把 grounding 作为基座原生能力来预训练，通过”量化坐标 token 统一接口 + 多教师数据引擎 + 多模态预训练/坐标对齐 SFT/GRPO 三阶段训练”实现约 4.84B 的 GroundingPI。实验在作者统一协议下的 34 个基准、11 类能力上取得 73.68% 均值（高于 GPT-6 Astra 71.54%），并在固定动作头与预算的受控比较中改善机械臂操作的泛化与数据效率、小幅改善 nuScenes 开环误差；其中”定位广度与密集目标覆盖”的基准证据较强，但”定位能力因果地带来动作收益””满足闭环时延”与”数据引擎/OCR 催化等机制贡献”仍缺少充分支持。本文最有价值的部分是把”感知基座”作为受控变量、跨两个具身域系统验证其价值与数据效率收益；最大的审稿风险是头条 SOTA 与迁移结论都建立在自建协议与未被隔离的基座差异上。

  • 问题定义清晰度：强。能力错配、三个研究问题与”先定位后动作”的动机明确，且 §10.4/§11 对主张边界有自我限定。
  • 创新性证据：中。统一接口与多奖励 GRPO 属已有思路的组合扩展，数据引擎与 OCR 催化缺乏隔离消融，原创边界只能确认到作者声称的差异。
  • 方法可信度：中。受控迁移协议设计认真（固定 Action DiT、数据与预算），但依赖自建评测协议、训练数据未发布，部分组件贡献不可分离。
  • 实验支持力度：中。广度（34 基准/11 能力/44 基线）与跨域迁移是实打实的；方差缺失、因果归因混杂与明显落后项（ScreenSpot-Pro、FSC147、TotalText）限制了结论强度。
  • 可复现性：中。代码（Apache-2.0，含 train/eval/infer/vla 目录）、模型权重与项目页均已公开且可访问（2026-10-13 核查），训练与评测配置（Table 8–15）较完整，论文承诺公开评测数据（含统一 prompt/parser）；但训练数据集与数据引擎教师清单未公开，评测数据截至归档日尚未见发布，部分基线评测细节未完全披露。
  • 综合阅读价值：高。受控的”感知基座 vs 动作学习”实验设计、数据组成分析（密集 grounding 为核心、辅助感知需组合）与 System-1/System-2 分工讨论，对做 VLA/具身方向的读者有直接参考价值。
