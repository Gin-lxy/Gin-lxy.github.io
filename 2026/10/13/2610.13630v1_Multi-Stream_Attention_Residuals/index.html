0. 一句话结论

论文把 Attention Residuals（AttnRes，注意力残差）沿网络深度方向的单头 softmax 检索扩展为多头深度注意力（multi-head depth attention）：用多尺度因果卷积从序列上下文为每个残差源（residual source）生成多条全维”流”（stream），每条流独立做深度检索，再融合回单流层输入。在作者自研的 18B/28B MoE 模型上，MSAR 在 12 项下游基准上均优于标准残差、mHC 与 AttnRes，四档缩放实验给出相对 Vanilla 的 1.58× 等损失算力加速（iso-loss compute speedup）。证据足以支持”该架构在其自研预训练设置下改善损失—算力权衡”，但训练 token 预算未披露、结果无方差报告，结论不宜外推到更大规模或对实际系统时延的断言。

1. 论文具体想解决什么问题

研究背景与任务：加深深度的 Transformer 是提升 LLM 能力的主要手段之一，但在现代 PreNorm 架构下，”加层”不总能带来预期收益（§1）。论文沿用 AttnRes 提出的”时间—深度对偶”视角（作者主张）：沿深度轴看，标准残差连接等价于对所有历史层输出的固定系数求和；HC/mHC（Hyper-Connections）一族的多状态残差类似循环式（线性注意力式）的深度记忆；AttnRes 则是沿深度轴的单头 softmax 注意力。

现有做法及其瓶颈：

  • 标准残差流把历史更新压缩进单一状态，层越深、单条更新相对累积状态越小，早期层形成的特征被逐渐稀释（depth-wise information dilution），后层难以按内容取回（§1，作者主张，引用 Gromov et al. 2024 等）。
  • AttnRes 用可学习伪查询（pseudo-query）在深度方向做 softmax 检索，本身已是”单头深度注意力”。作者转述其失败尝试：把隐状态按通道切分来做多头深度聚合会掉点——因为在深度注意力中，被检索的 value 就是隐状态本身，应被视为一个整体，切成低维碎片会破坏其完整性（§1，转述 AttnRes 的结论）。
  • 另一条直觉路线是用 (m)HC 的 H^post 式写回从单个层输出派生多个候选流当”头”：候选虽保持全维，但只是同一向量的标量重加权，归一化（RMSNorm）会抹掉幅值差异，导致各头的 key 几乎相同、来源多样性不足（§1，作者分析）。

本文发现的新观察与核心设计挑战：多头深度注意力需要”从单个层输出构造足够多样的头、又不破坏隐表示的完整性”，而已有两条路线（通道切分、标量重加权派生）分别破坏完整性或欠多样性。这是本文把一般性”深层残差信息稀释”问题具体化出的子问题。核心假设：深度注意力头的多样性可以从序列轴借用——不同感受野的因果卷积把邻近 token 的同层历史状态聚合进每个残差源，形成不同的上下文视角，各头据此检索出不同的深度分布，从而在几乎不增加算力的条件下改善损失—算力权衡（§1，作者主张）。

区分层次：领域一般问题=深度缩放效率与残差信息稀释（前人已指出）；本文新观察=构造多头深度注意力时，通道切分会破坏完整性、标量重加权会被归一化抹平多样性；实际解决的子问题=廉价构造全维多视角的深度注意力头，并在块级存储、流水线通信等系统约束下保持与 AttnRes 相同的持久存储成本（§3.4）。因果解释（”多尺度上下文视角带来多样性、多样性带来收益”）目前主要是作者主张，机制证据见 §4.3。

2. 创新点是什么

总括：真正的技术增量是把 AttnRes 的深度检索从单头推广为多头，并且用”序列轴的卷积上下文视角”——而不是持久多流状态或通道切分——来制造头间多样性；配套给出保持单流存储与通信的执行方案。方法组件大多能在 mHC/AttnRes 中找到出处，创新点属于”新机制（流扩展方式）+ 已有组件的新组合 + 系统级工程改进”的混合。

  1. 上下文流扩展（multi-scale causal depthwise convolution，多尺度因果深度可分离卷积）。每个残差源经恒等映射与核大小 {4,8,12} 的三条卷积得到 4 条全维流，各配独立伪查询做逐流深度 softmax 检索；多样性来自序列上下文，而非切分隐藏维度或标量重加权。与最接近的 AttnRes 的差异是”单查询单流 vs 多查询多源视角”。证据指向 §4.3 的 w/o Conv 消融（去掉卷积、只留多查询会使 Pile 损失从 1.847 升至 1.862）。
  2. 按需流扩展的执行设计（system-level）：持久存储只保留单流块摘要，检索时才卷积展开，流水线通信与 prefill 激活存储从 O(mNd) 降到 O(Nd)，与 Block AttnRes 持平，且兼容跨阶段缓存与两阶段计算，卷积展开与逐流注意力可融合进同一 kernel。属工程实现改进。证据指向 §3.4 与 Appendix C（Table 5、Table 6）。
  3. 大规模验证：在 18B/28B MoE 自研预训练上给出 12 项基准全胜与四档缩放实验（1.58× 等损失加速），把 AttnRes 式深度检索的证据推进到 28B 规模与多分档缩放曲线。证据见 §4.2、§4.3。

3. 作者如何解决

直觉：多头注意力在序列轴上的多样性来自不同投影子空间，那么深度轴上的多样性可以来自”不同的序列上下文视角”——同一个残差源，经不同窗口的因果卷积后得到 m 个全维版本（保留隐表示完整性），每个版本配一个可学习伪查询独立检索历史，最后压回一条流送入目标层。这样主干网络与单流层输入形状都不变，只是”生成层输入”的方式被替换。

以下按训练时前向流程走查（默认 Block MSAR：m=4 条流、每 block 含 S≈8 个残差子层；论文按残差分支计数，一个 Attention 或 MLP 分支算一层）：

输入：token 嵌入作为第 0 号源；主干为 DeepSeekMoE 风格的 Transformer（1 个前置稠密层 + MoE 层，GQA 注意力，SwiGLU FFN）。每个残差子层的输出 v_i = f_i(h_i) 是需要被后续层检索的”源”。

步骤 1（块摘要，block summary）：把 L 个残差子层划分为 N≈8 个连续 block；block 内子层输出先以普通残差方式累加成单流摘要 b_n，当前 block 中尚未完成的部分构成”部分和” b_n^{<l}。这一步刻意先累加、后展开（§3.4），是”只持久存单流”的前提。

步骤 2（流扩展）：对每个可用源（嵌入、已完成 block 摘要、当前 partial）做卷积展开，得到第 r 条流的源。论文 Eq. (9)(10) 的含义：

v_{i,t}^{(0)} = v_{i,t}；　v_{i,t}^{(r)} = Σ_{δ=0}^{κ_r−1} c_{i,r,δ} ⊙ v_{i,t−δ}（r = 1,…,m−1）

即第 0 条流是原始源（恒等），其余流是每通道可学系数、核大小 κ_r 的因果深度卷积，聚合本层邻近位置的源状态；序列起点做零填充，因此不泄露未来信息。默认 κ = {4,8,12}，m = 4。

下图对比三种残差架构在层与 block 粒度上的数据流，图 1 是论文 Fig. 2。

图 1（论文 Fig. 2）：该图把标准残差、Block AttnRes 与 Block MSAR 的层间信息流并排呈现。标准残差中每层只读上一条累加状态；Block AttnRes 让每个目标层跨 block 检索已完成摘要与当前 partial（虚线圆圈示意可检索源）；Block MSAR 则在每个检索入口前多了一步”流扩展”——同一组单流摘要经恒等与三种窗口的卷积变成多路并列的候选视图，各视图独立打分后融合成一条层输入，再由普通 Attention/MoE 分支处理。读者应从中理解 MSAR 的连接拓扑：写入路径保持单流（箭头始终只有一条回写线），读取路径临时变宽又立即收窄，这正是”存储成本不变、检索表达变宽”在结构上的体现。

步骤 3（逐流深度检索）：每条流 r 有独立伪查询 w_l^(r)，对全部可用源（经本流扩展后）做 softmax 打分并加权求和，得到检索结果 z_l^(r)：

z_l^{(r)} = Σ_i α_{i→l}^{(r)} v_i^{(r)}，　α_{i→l}^{(r)} = exp(w_l^{(r)ᵀ·RMSNorm(v_i^{(r)})) / Σ_j exp(w_l^{(r)ᵀ·RMSNorm(v_j^{(r)}))}

借由 RMSNorm 后的指数核，深度检索类似”以层为 token 的注意力”；每条流独立归一化，因此同一目标层的 m 个头可以给出不同的深度分布（§3.2 Eq. 11–12）。

步骤 4（流融合，stream fusion）：m 个检索结果 Z_l = [z_l^(0), …]（m×d）经轻量 H^pre 式混合器压成单流层输入：把 Z_l 展平为 md 维，经 RMSNorm 与线性投影后取 sigmoid 得到 m 个标量权重 g_l^(r)，h_l = Σ_r g_l^(r) z_l^(r)（Eq. 13–14）。相比序列注意力常用的 md×d 输出投影，标量混合参数与算力都极小。

下面的图 2 从”深度混合矩阵”的角度解释 MSAR 与三种机制的差别，图 2 是论文 Fig. 5（附录 E.2）。

图 2（论文 Fig. 5）：该图用 L=4、块大小 S=2 的小例子把”每个目标层从哪些历史源读多少”画成矩阵。Vanilla 是固定单位系数；mHC 的每个系数由”写向量×状态转移×读向量”连乘得到（受限双随机矩阵的展平形式）；Block AttnRes 每个目标层对 block 级源有一行 softmax 分数，跨两列的单元格表示一个 block 源被整体检索；Block MSAR 的关键差别是”每个流一张打分矩阵”——打分与 value 都作用在扩展后的源上，各流独立归一化，最后由门控权重把多张矩阵的读出融合成一行。读者应从中理解：MSAR 不是给 AttnRes 简单加几个头，而是把”源集合”与”归一化”都按流分解，再在输出侧收回单流。

步骤 5（输出与收尾）：最后一个子层不做流扩展，直接做残差合并后送入 LM head，产出下一个 token 分布（§3.2 末尾）。

模型决定 vs 固定流程：由模型学习的是各流伪查询、卷积系数、融合混合器参数与门控缩放（α 初始化为 0.01、卷积权重与伪查询零初始化，Appendix A）；由设计固定的是 block 划分、流数 m=4、核大小 {4,8,12}、可用源集合与两阶段执行顺序。

训练了什么：MSAR 是从零预训练的架构改动（training-based，无 SFT/RL 阶段），训练目标与主干一致（下一 token 预测）。推理阶段的变化：深度注意力权重按上式即时计算，没有独立的”训练后适配”；执行上兼容 AttnRes 的跨阶段缓存（cross-stage caching）与两阶段推理策略——同一 block 内各目标层的伪查询在 block 执行前已知，第一阶段批量对已完成源打分并保存 softmax 统计量，第二阶段各层并入当前 partial 的贡献（在线 softmax，online softmax），以减少重复内存访问（§3.4）。

效率设计（对应 §2 第 2 条）：由于扩展流是单流摘要的确定性函数，持久存储与流水线通信只传单流，源数量 N 条时存储从 O(mNd) 降到 O(Nd)；卷积展开与逐流注意力的输出没有其他消费者，可合并为融合 kernel（fused kernel）避免中间写回；代价是检索出的 m 条结果仍需写回并在融合时读回，这部分访存高于 AttnRes（Table 6）。

教学简化示例（非论文实验）：取 d=1、κ=2、卷积系数 c=(1,1)，则第 r 条流在位置 t 的源向量为 v_{i,t}+v_{i,t−1}，即把前一个位置的同层输出并入当前源。这就是”同一残差源的不同上下文视角”的字面含义——卷积流让深度检索在”哪个位置的历史”上多了一个可选的粒度；真实实现中系数按通道可学、各源使用独立的卷积”银行”（bank），视角由训练自行塑造。

4. 解决得怎么样

4.1 实验设置

  • 模型：DeepSeekMoE 风格主干（前置 1 个稠密层 + MoE 层、GQA、SwiGLU）。消融用 10B（15 个 Transformer 层=30 个残差子层），主结果用 18B（28 层）与 28B（32 层），均从零预训练，序列长 8192，Qwen2 tokenizer。全局 batch：10B 为 288、28B 为 768，18B 未报告；三档模型的训练 token 数均未报告（Table 3 “Training Tokens” 一行为 “-“）。
  • 配置：Block MSAR m=4 流、N≈8（18B N=7、28B N=8；每 block 4 个 Transformer 层，对应 S=8 个残差子层）；基线 mHC 同样 m=4，AttnRes 与 MSAR 使用相同 block 划分，另有 Vanilla（标准残差）。
  • 评估：12 项基准分三类——通用能力（MMLU、MMLU-Pro、MMLU-Redux、ARC-C、BBH）、代码与数学（HumanEval、LCBench、GSM8K、MATH）、中文理解（CMMLU、C-Eval、C3）；基于 OpenCompass 的轻量评估套件，似然打分与生成式评估混用（few-shot 设置见 Appendix A），消融用 Pile 验证损失。缩放实验分四档模型（2.21B/3.75B/9.47B/17.40B 总参），各档方法间声明匹配 token 预算但同样未给数字（Table 4 “Training Budget” 为 “-“）。
  • 各实验分工：主表回答”下游是否全面更好”；缩放实验回答”损失—算力曲线是否更优”；消融（10B）回答”哪个组件带来收益”；附录给出参数量/FLOPs/访存明细、注意力模式与形式化比较。

4.2 关键结果

  • 训练损失（原文事实，Fig. 1a 与 §1 正文）：18B 终值 MSAR 1.750，对比 Vanilla 1.799、mHC 1.776、AttnRes 1.769。
  • 下游平均分（原文事实，Table 1）：18B 平均 45.7，对比 Vanilla 37.5（+8.2）、mHC 41.7（+4.0）、AttnRes 41.8（+3.9）；28B 平均 52.4，对比 44.6（+7.8）、47.4（+5.0）、49.4（+3.0）。12 项基准在两个规模上均取最高（作者主张加表格支撑）。
  • 代表项与差距小项（Table 1）：28B GSM8K 65.7 vs AttnRes 57.2（+8.5）、18B MMLU 56.6 vs 53.0（+3.5）差距较大；但 18B HumanEval 仅 +0.6（26.8 vs 26.2）、28B MATH +0.8（28.8 vs 28.0）、28B C-Eval +0.8（59.9 vs 59.1）。个别基准上基线排序不稳：28B BBH 中 AttnRes（40.7）低于 mHC（43.6）甚至 Vanilla（41.7），提示评测存在噪声，而全篇没有任何种子方差或置信区间。

4.3 机制证据

消融（原文事实，Table 2，10B/30 残差子层/Pile loss，均为单点值）：

  • w/o Conv（每个源复制成四条相同流、保留四查询）：1.862 vs 默认 1.847，损失差 0.015。该消融把”多头查询”与”多源视角”分离：仅增加查询多样性收益很小，主要收益来自卷积带来的源多样性。这是对 §2 第 1 条创新最接近因果的消融。
  • w/o H^pre（融合改为均值）：1.851（+0.004）。自适应融合有增益但均匀平均保留大部分收益；作者称 H^pre 对训练稳定有帮助，但未给出稳定性证据（作者主张）。
  • AttnRes+mHC 混合（同时保留跨层源与 mHC 多流循环状态）：1.861，比 AttnRes 仅再降 0.006，而 MSAR 在此基础上再降 0.014——支持”MSAR 的收益不是把两种已有机制叠加”（作者据此判断，Table 2 行 (4)(5)）。
  • 超参：流数 m=2/4/8 为 1.850/1.847/1.846（收益递减，作者选 4）；block 粒度 S=1/2/4/8（越细越好）为 1.843/1.845/1.847/1.852，默认 N≈8 是精度—成本折中。注意 S=1（逐子层检索）仍最好，说明默认配置未榨干全部精度。

机制可视化（原文事实＋作者解读，Appendix D，论文 Fig. 4，对应图 5）：10B 模型学到的深度注意力权重显示流间确实分化——例如 Pre-MLP 读取对嵌入的强关注集中在流 2（Conv-4）与流 3（Conv-8），流 2/4 在 block 6 出现强”竖直带”、流 3 偏好 block 7；Pre-Attn 读取分布宽、保留对嵌入的访问，Pre-MLP 读取更尖锐。这是”流学到了不同源选择分布”的相关性证据。

图 5（论文 Fig. 4）：该热图矩阵按”子层类型×流”分 8 格，行是 10B 模型的 15 个 Transformer 层、列是深度源（嵌入与 8 个 block，当前 block 用其 partial 表示），颜色是 token 平均后的注意力权重，斜线区为不可用源。读者应从中读到：不同流的权重结构确实不同——有的流把注意力集中在嵌入与早期 block，有的青睐特定 block 的竖直检索带，说明多流不是同一分布的复制；同时它只是训练后观察，不能证明”上下文视角”与收益之间的因果链，作者也未报告对流的表示相似度或干预实验。

替代解释的排除情况：参数与算力开销受控（§4.4 的明细表），AttnRes+mHC 对照排除了”叠加已有机制”的解释，w/o Conv 排除了”仅多查询”的解释；但训练 token 预算未披露，无法核对”同数据同预算”的公平性；全篇无多种子方差，w/o H^pre 的 0.004 级差异可能落在噪声内。

4.4 成本与适用范围

  • 参数开销（原文事实，Appendix C Table 5）：相对 Vanilla，MSAR 在 18B/28B 增加 5.204M/7.209M 参数，占激活参数 0.31%/0.27%；对比 mHC 11.356M/15.730M（0.67%/0.58%）、AttnRes 0.120M/0.166M（0.01%）。即 MSAR 参数远多于 AttnRes、少于 mHC。
  • 训练算力（原文事实，Table 5）：MSAR 增加训练 FLOPs 0.51%（18B）/0.48%（28B），AttnRes +0.10%，mHC +0.66%/0.60%——算力代价小，这是”minimal overhead”最实在的部分。
  • 存储与通信（原文事实，§3.4 与 Table 6）：持久源存储与流水线通信为 O(Nd) 每 token，与 Block AttnRes 持平，兼容跨阶段缓存；但每 token 每残差子层的内存访问（forward，典型配置 N=8、S=16、m=4）MSAR 为 21.5d，明显高于 Block AttnRes 的 5.5d（Vanilla 3d、mHC 34d）——融合 kernel 已消除卷积展开的中间写回，剩余开销来自多流检索结果的写回与聚合（§3.4 自述）。论文未报告实际吞吐、step 时间或端到端时延，也未展示 kernel 级 profiling（论文未报告）。
  • 训练成本：GPU 数量、训练时长、总 token 数均未报告（论文未报告），无法估计复现或扩展成本。
  • 外部依赖与复现材料：无外部模型/闭源服务依赖；主干与残差配置、学习率等超参已给（Table 3/4）。官方项目页 https://github.com/jianke0604/MSAR 可访问，但截至 2026-10-13 仅含 README、图片与论文 PDF，无训练代码或权重（2026-10-13 核查）。
  • 改善了什么、仍未解决什么：改善的是深度方向检索的表达力与损失—算力权衡（在自研 18B/28B 设置内），代价是访存与参数增加；未解决/未验证：访存开销的实际影响（无时延数据）、token 预算与数据披露、超过 28B 的外推、非 MoE 架构与推理库（kernel 融合与两阶段计算的工程落地）的兼容性。适用范围应限定为”预训练阶段的残差架构替换”，而非推理期的能力注入或普遍性结论。

5. 最容易受到审稿人质疑的地方

质疑：训练数据与 token 预算未披露，”匹配预算”的公平性无法核验

原文依据：Table 3 的 “Training Tokens” 三档均为 “-“，Table 4 的 “Training Budget” 一列亦为 “-“；而 §4.3 与 Appendix B 均声称各方法”matched training-token budgets”。

为什么重要：架构对比的核心混淆变量（数据量与训练时长）不可见——损失或下游差距可能部分来自训练更久/更多 token，而不全是归因架构；这直接影响主要结论的可信度。

当前能够得出的判断：证据不足（审稿人判断）。作者的匹配声明没有数字支撑，外部无法验证；主表也只说”comparable parameter counts and training FLOPs”。

如何验证或补强：公开每档、每方法的训练 token 数、步数与数据配比；或补充同 token/同 wall-clock 下的对照训练曲线。

严重程度：主要问题。

质疑：所有结果为单点数字，无方差、置信区间或显著性检验

原文依据：全篇（Table 1、Table 2、Fig. 1–3）均为单次训练/单次评估数字；差距小的项如 18B HumanEval +0.6、28B C-Eval +0.8、w/o H^pre 仅 +0.004；28B BBH 上 AttnRes（40.7）反低于 mHC（43.6）与 Vanilla（41.7），显示评测与训练噪声不可忽略。

为什么重要：”全部 12 项基准全胜”与增量消融的解读都依赖这些点值；若评测方差与差距同量级，个别宣称（尤其消融 0.004 级）不成立。

当前能够得出的判断：损失曲线的大趋势（1.750 vs 1.799）较可信；小差距项与消融差分稳健性未知（审稿人判断）。

如何验证或补强：多种子预训练与评测并报告 std/CI；至少对评测做重复实验；给出对差距的显著性讨论。

严重程度：主要问题。

质疑：与最近邻方法缺乏对照，创新边界不能由本文单独确证

原文依据：Appendix E.1 自述 DAR 同样在探索 “stream-width expansion for depth retrieval”（其两流在同 token 位置维持不同残差轨迹）；相关工作中还有 xHC、Single-Pass mHC、MUDDFormer、MoDA 等跨层/多状态方法未进入实验对比；本文实验基线只有 Vanilla、mHC、AttnRes 与自设的 AttnRes+mHC 混合。

为什么重要：MSAR 的卖点是”序列上下文构造多头”相对已有方案的独占增益；缺少与 DAR 等最接近方法的同预算对照，无法判断增益是否只是对既有方向的实现改进，也难以支撑”首次实现多头深度注意力”的隐含主张。

当前能够得出的判断：根据本文材料只能确认作者声称的差异（多样性来源为序列上下文视角、保持单流存储）；是否构成首创需更完整文献检索与直接对照（审稿人判断）。

如何验证或补强：把 DAR、xHC、Single-Pass mHC 等纳入同一设置与同预算对比；消融替换成”另一条序列轴多样化途径”（如 Mamba 式扫描、不同卷积类型）以界定机制边界。

严重程度：主要问题。

质疑：”多尺度上下文视角带来收益”的机制证据偏弱，卷积设计本身未做敏感性消融

原文依据：机制证据主要是 Fig. 4 的注意力热图（Appendix D）与单一 w/o Conv 消融（Table 2 行 (6)）；无核大小 {4,8,12} 的消融、无单尺度 vs 多尺度对照、无流表示相似度的定量分析；w/o Conv 只能证明”源多样性优于仅查询多样性”，不能证明”多尺度”这一选择必要。

为什么重要：若换成单尺度卷积甚至任意可微扰动的源，收益相同，则”多尺度/上下文”的叙事是装饰性的，方法可被更便宜的方案替代；这关系创新点的真实性。

当前能够得出的判断：现象（去卷积掉点、流模式分化）成立，但机制解释未与替代设计隔离（审稿人判断）。

如何验证或补强：核大小与卷积类型消融；随机特征流对照；对流的 CKA/相似度与”源多样性—损失”相关性做定量分析。

严重程度：主要问题。

质疑：效率叙事与访存实况存在张力，且无任何实测时延

原文依据：摘要与 §1 强调 “minimal additional overhead”（0.5% FLOPs、0.3% 激活参数），而 Table 6 显示 MSAR 每 token 每子层访存 21.5d，为 Block AttnRes（5.5d）的近 4 倍；§3.4 自述额外开销来自多流写回，缓解手段（融合 kernel、两阶段计算）为方案描述，无实现或 profiling 数据。

为什么重要：预训练吞吐由访存与 kernel 实现决定；若 4× 访存无法被融合消化，实际吞吐优势可能逆转，工程可行性受质疑。

当前能够得出的判断：FLOPs 与存储的”持平/微小”有明细支撑；访存升高属实、实际影响未知（审稿人判断）。

如何验证或补强：给出真实实现下的吞吐/step time 对比与 kernel 级 profiling；报告融合 kernel 的实测收益。

严重程度：次要。

6. 审稿式总评

作者把”深层残差信息稀释”这一既有问题细化为”如何从单层输出构造多样且完整的深度注意力头”，指出通道切分与标量重加权两条既有路线分别破坏完整性、丧失多样性，因此提出 MSAR：用多尺度因果卷积从序列上下文生成 4 条全维流，逐流做深度 softmax 检索，再以标量混合器融合回单流，并用”先累加后展开”保证存储与通信与 Block AttnRes 持平。实验在自研 18B/28B MoE 上显示 12 项基准全胜与 1.58× 等损失加速，w/o Conv 与 AttnRes+mHC 消融具体指出收益来自源多样性而非叠加既有机制；机制侧还有学到的逐流注意力模式佐证。其中最有力的部分是”去卷积掉点 + 混合架构不加分”的正反两组消融，与访存/参数明细表；最薄弱的是训练 token 预算未披露、全部点值无方差、以及与 DAR/xHC 等最近邻方法缺对照。本文最有价值之处在于给出”深度方向注意力化残差”的一种干净、可复现设计空间与系统取舍分析；最大的审稿风险是公平性与统计稳健性无法从论文内部确认。

  • 问题定义清晰度：强——§1 把一般性深度稀释问题细化为两条失败路线的具体分析（通道切分破完整性、标量重加权欠多样性），并给出可检验假设。
  • 创新性证据：中——核心机制（卷积造流）有新意，w/o Conv 消融提供主要支撑；但组件可追溯至 mHC/AttnRes，最近邻方法缺对照，首发性不能确证。
  • 方法可信度：中——公式与执行流程完整自洽，消融设计能分离”多头查询”与”多源视角”；训练数据不透明、无方差报告削弱可信度。
  • 实验支持力度：中——双规模 12 基准 + 四档缩放 + 组件消融覆盖面佳，训练全程曲线一致领先；但单点结果、轻量评估、缺统计检验与替代设计对照。
  • 可复现性：弱——主干配置与超参较全，但训练数据/token 预算未披露，项目页无代码或权重（截至 2026-10-13）。
  • 综合阅读价值：高——对该方向的读者，本文提供了清晰的多头深度注意力设计、单流存储的执行方案与诚实的成本明细，是理解”残差即深度注意力”路线的良好入口。
