0. 一句话结论

论文把扩散语言模型（DLM）每一步去噪中”所有 mask 位置用同一固定深度 denoiser”改成”逐 token 自适应循环深度”：容易的 token 先在步内提前提交并作为离散上下文回填，困难的 token 保留潜状态继续递归精炼，并用一个把 exit schedule 当隐变量的 conditional NELBO 端到端训练该策略。在论文报告的 11 个推理/数学/代码基准上，1.7B 与 8B 两个规模的平均分均超过所有被评测的 DLM 与对应的 Qwen3 AR 基线（65.5 与 80.3），GSM8K 上 8B 模型吞吐约为 vLLM 服务 Qwen3-8B 的 2.7 倍；但该结论受限于主结果无统计稳定性报告、缺少”自适应 vs 同等算力固定深度”的直接对照，以及训练语料未披露。

1. 论文具体想解决什么问题？

  • 研究背景与具体任务：自回归（AR）LLM 逐 token 解码慢；DLM 通过并行去噪多个 mask 位置换速度，但与同规模 AR 模型存在持久的生成质量差距（§1）。
  • 现有方法如何处理：两条主流路线——(a) 把 AR 结构重新引入扩散过程（Block Diffusion、Fast-dLLM-v2、SDAR、WeDLM、Nemotron-Labs-Diffusion 等半 AR/块扩散）；(b) 把 DLM 降格为草稿器、交给 AR 验证（TiDAR、I-DLM、DFlash、Uno 等）。此外 confidence-based 解码（如 LLaDA 类方案）把低置信 token 推迟到后续去噪步（§1、Appendix A）。
  • 现有方法在哪些条件下不好：DLM 每步对全部 mask 位置施加固定深度 denoiser，把每个位置都当作”可直接从污染上下文预测目标”来训练；confidence-based 解码虽然推迟了低置信 token，但被推迟 token 的潜计算在步间被丢弃，下一步从 mask embedding 重新计算，等于没有把”等待”转化为”更多计算”（§1）。
  • 本文发现的新现象/瓶颈：作者提出 computation–difficulty mismatch（计算–难度错配）：同一步内不同 mask 位置的预测难度差异很大（内在不确定性、多跳推理、对未决 token 的依赖），均匀深度既在简单位置上浪费计算，又让困难位置得不到足够计算。需要说明：这是作者提出的假设与机制解释（§1 明确写 “We hypothesize”），论文没有直接测量”每 token 难度 vs 所需计算”的分布来证伪或证实该错配本身；支撑它的是间接证据（Fig. 3b 的 frontier、Fig. 4 的 halting 统计）。区分：DLM 落后 AR 是领域一般问题；”均匀深度 + 潜状态不持久导致错配”是本文的机制性主张；本文实际解决的子问题是：在 mask/block diffusion 框架下，让每个去噪步内的循环精炼深度按 token 自适应，并给出可端到端训练的目标与推理流程。
  • 作者认为问题产生的原因：固定深度的均匀分配，加上 unresolved token 的潜计算不能跨 pass 累积（§1、§3.1）。
  • 核心假设：如果维持每个困难 token 的持久潜状态、让简单 token 先提交为离散上下文、并把 token 级计算日程作为隐变量联合优化词预测与分配策略，就能在保持并行解码的同时缩小与 AR 的质量差距（Abstract、§3.2）。

2. 创新点是什么？

概括（审稿人判断）：真正的技术增量不是某个单点模块，而是把”token 级自适应循环深度”做成一个端到端可训练、可推理、可服务的完整系统：循环架构（Prelude / Recurrent Core / Coda + ExitGate）、exit schedule 隐变量化的 conditional NELBO、单轨迹无偏梯度估计器与方差缩减、以及配套的推理机制（entropy 提交 + 累积 halt 阈值 + 深度感知 KV cache）。基础组件多来自既有工作（循环 Transformer、PonderNet 式 halting、WeDLM 的 block-diffusion 转换管线、Qwen3 骨干），创新主要在组合方式与训练目标的推导。逐项如下。

（1）token 自适应循环架构 + 潜状态持久化

  • 新增机制：每个去噪步（outer loop）内允许多次 recurrent pass（inner loop）。每 pass 后，预测熵 ≤ τ 的位置立即提交、其 token 嵌入回填进循环状态（Eq. 3）；未决位置保留累积潜状态继续精炼；ExitGate 输出的 halting 概率累积到阈值 q 或无可提交位置时结束步内循环（§3.1，Algorithm 1，Fig. 2）。
  • 与最接近方法的差异：循环 DLM（Lee et al. 2026 等）在每步内对所有位置用同一循环深度；FReDA 支持 token 级提交但迭代修订显式 draft、不跨 loop 传递内部潜状态；PonderNet / Ouro 式自适应深度需要对所有候选退出深度求和，而本问题中早期提交会改变上下文使精确求和不可行（§2、Appendix A）。
  • 类型：已有组件（循环块、halting 门、置信度提交）的新组合 + 针对 DLM 场景的机制改造，属新思想与工程结合。
  • 对应问题：直接针对 computation–difficulty mismatch——简单 token 提前退出的同时为困难 token 保留计算。
  • 证据：Fig. 2 流程；Fig. 4（右）显示数字类 token 的首 pass halt 概率系统性偏低（0.369 vs 参考均值 0.417），说明模型自发学到 token 依赖的精炼偏好；Fig. 6 个案显示同一响应内提交深度交错。
  • 移除该设计会怎样：论文未提供“移除 token 自适应、改为同等平均算力的固定深度”的直接消融（见 §5 质疑三）。

（2）exit schedule 隐变量化的训练目标（conditional NELBO）

  • 新增目标：把每条 mask 位置的退出深度组成 exit schedule z\mathbf{z}z 作为离散隐变量，定义调度条件似然（Eq. 4），对变分后验 qϕq_\phiqϕ​（由 ExitGate 参数化）导出 conditional NELBO JJJ（Eq. 5）与总体损失 Ltrain\mathcal{L}_{\mathrm{train}}Ltrain​（Eq. 6，含标准 diffusion 的 1/t1/t1/t 加权）；先验为截断几何分布（Eq. 23，K=4K=4K=4、c=0.4c=0.4c=0.4，先验均值深度 ≈2.02）。
  • 与既有方法差异：PonderNet/Ouro 的精确期望求和在此不可行（提交改变后续上下文），改为变分 + 单轨迹估计（§2、Appendix C.1）。
  • 类型：理论推导 + 已有变分框架的适配。
  • 证据：Appendix C.1 给出归一化与界的证明（Proposition 2）；C.3 的 Theorem 3 证明 (α,β)=(1,1)(\alpha,\beta)=(1,1)(α,β)=(1,1) 时正则项的期望恰为联合 KL，实际使用 (0.1,1)(0.1,1)(0.1,1) 的松弛以允许 token 间深度差异。
  • 移除会怎样：无该目标则 ExitGate 无梯度信号来源；论文通过 Fig. 5（右）的梯度方差实验间接支持方差缩减项的必要性。

（3）无偏梯度估计器与方差缩减

  • 新增流程：对 θ\thetaθ（去噪器）用常规反传（固定采样日程后），对 ϕ\phiϕ（ExitGate）用 score-function 估计（Eq. 7 的 surrogate，Proposition 1 证明无偏，Eq. 8，依赖 Eq. 2 中 sg[] 的 stop-gradient 约定与 Appendix C.2 的参考骨干记号）；方差缩减包括：把每个 token 在 s≤zis \le z_is≤zi​ 的所有中间 readout 用重加权（Eq. 32–33）纳入去噪器监督（不需要额外前向），以及用 first-pass loss 作 control variate（Eq. 29–31，无额外前向）。完整训练代理 = 去噪损失 + gate 代理损失 + 等权 AR 辅助 loss（Eq. 34，Appendix C.4，AR 辅助 loss 沿用 AR→DLM 转换的既有做法）。
  • 证据：Fig. 5（右）在 4,096 个参数子集上测得去掉中间监督后条件梯度方差升为 1.76×/1.49×/1.42×（步数 1k/6.5k/17k，paired bootstrap 95% CI）。
  • 类型：成熟 RL/变分工具的移植与适配（工程+理论细节）。

（4）规模化与”低成本转换”

  • 将 Qwen3-1.7B/8B 直接经 WeDLM 的 streaming block-diffusion 框架做 SFT（跳过 CPT，5B-token 语料），得到作者声称的”迄今最大的 looped DLM”（8B，Abstract、§4.1）。
  • 与 SDAR/WeDLM 等需要 continued pretraining 的转换管线相比是流程简化；但转换框架本身来自 WeDLM，属已有组件重用（§4.1）。

（5）推理机制工程

  • entropy 阈值 τ 的提交判据 + cumulative halt 阈值 q 的停止判据 + “无提交时强制提交最低熵位置”的保进度回退（Algorithm 1）；depth-aware KV caching：为循环层按”层 × 递归深度”维护逻辑 KV buffer，8B 配置共 L+(K−1)m=36+3×16=84L+(K-1)m = 36+3\times16 = 84L+(K−1)m=36+3×16=84 对，其中 64 对属于循环核（Appendix B.1，Eq. 9–10）。
  • 证据：Fig. 3(a) 给出 τ、q 对精度-速度的单调影响；§4.3 给出 matched-accuracy 下的吞吐与 GFLOPs 优势（详见 §4.3）。

3. 作者如何解决？

直觉：主流 DLM 把”一次前向 → 提交一步”做成等长流水线，但一条序列里各个 mask 位置的难度天差地别。ALoDLM 的做法是给每个去噪步装一个”内循环”：先用一遍计算看看谁能猜准，猜准的（预测熵低）立刻”落子”并成为已解上下文，帮助剩下的位置；猜不准的不要重来，而是把刚才算出的隐表示留着继续叠循环，直到 ExitGate 认为可以停止或到最大深度 K=4。训练时，每个 token”在第几圈退出”被视为一个离散隐变量，用变分下界同时学”预测什么”和”算多少”。

Fig. 2 逐部分解释（图中每部分做什么、为什么需要它）：

  • 左上对比条：标准 DLM 解码每个去噪步只跑 1 pass 就整步推进；ALoDLM 解码在同一步里跑多个 Adaptive Loop。它解释了”outer loop / inner loop”的嵌套关系，是全文推理流程的骨架。
  • 下半主图：输入经过 Prelude（词嵌入层 + 可选前缀 Transformer 块，8B 为 [0,10)[0,10)[0,10) 层）得到初始循环状态；Recurrent Core（共享的中间层，8B 为 [10,26)[10,26)[10,26) 的 16 层）被反复调用，每次调用后经 Coda（8B 为 [26,36)[26,36)[26,36) 层）产生 readout；readout 分两路进 LMHead（词分布，决定”谁可以提交”）和 ExitGate（halt 概率，决定”是否继续精炼”）。
  • 四个内部迭代块的差别：第 1 圈只有少数 token（图中 E、F）已提交为绿色离散上下文，其余仍是 mask（M）或持续演化的潜状态（L，红色的 h~ 块）；到第 3、4 圈提交位置逐渐增多、剩余位置减少；每个 pass 上方标出各位置的 low/medium/high entropy 与 gate 开关。这正说明机制核心：已提交 token 以嵌入形式回填（Eq. 3），未决 token 的状态跨 pass 累积而非重算。

  • 为什么需要这张图：它把 §3.1 的 Algorithm 1（第 9–14 行的提交与回填、第 15 行的停止判据）可视化为一条可跟踪的数据流，是理解训练目标里”为什么 exit schedule 的精确求和不可行”（提交改变上下文）的前提。

按流程展开（§3.1、Algorithm 1、Appendix B/D）：

  1. 输入：部分被 mask 的序列 xt\mathbf{x}_txt​（训练时每个 32-token block 独立采 mask 概率 ttt；评测时按窗口 16 解码）。初始未决集合 U={i:xi=[MASK]}\mathcal{U}=\{i:x_i=\mathtt{[MASK]}\}U={i:xi​=[MASK]}。
  2. 关键步骤（每个 outer step 内）：Prelude 产生 h(0)\mathbf{h}^{(0)}h(0)；对 s=1..Ks=1..Ks=1..K：Recurrent Core → Coda → readout r(s)r^{(s)}r(s)；LMHead 得 pi(s)p_i^{(s)}pi(s)​、ExitGate 得 λi(s)\lambda_i^{(s)}λi(s)​（Eq. 2，gate 输入的 stop-gradient 把策略学习与骨干解耦）；累积 halt ai←ai+(1−ai)λia_i \leftarrow a_i + (1-a_i)\lambda_iai​←ai​+(1−ai​)λi​；对熵 ≤ τ 的位置采样提交并回填嵌入（Eq. 3）；若 U=∅\mathcal{U}=\varnothingU=∅ 或未决位置平均累积 halt ≥ q 则跳出内循环；若整步无任何提交，强制提交熵最低的位置以保证进度。
  3. 组件分工：模型决定——每 pass 的词分布与 halt 概率；固定流程——阈值 τ、q、最大深度 K、强制提交回退、外循环直到无 mask。
  4. 训练了什么：骨干（Qwen3 转成 block-diffusion 形态，含双向 attention 语义的 causal mask 与流式前缀）与 ExitGate 全部端到端学习；损失 Eq. 5/6 为主，加等权 AR 辅助损失（Eq. 34）。训练细节：5B-token 语料、AdamW、lr 10−510^{-5}10−5、cosine、warmup 3%、wd 0.01、全局 batch 256 条（每条 4,096 token 的打包序列）、bf16、DeepSpeed ZeRO-2；8B 跑 8 epochs（34,512 步）、每两次循环层调用做梯度检查点（Table 2、Appendix D.1）。
  5. 推理变化：τ 控制”多激进地并行提交”，q 控制”未决位置精炼多久”，二者构成质量-速度旋钮（Fig. 3a）；服务端用 depth-aware KV cache（同深度命中、否则回退到最深可用深度）把循环模型塞进并行解码引擎（§4.1、Appendix B.1）。
  6. 输出：当序列不再含 mask 时返回完整文本；每一步可以只提交一个 token（公平评测预设，τ 关闭），也可以在并行模式下一次提交多个。

教学简化示例（非论文实验）：假设序列为 “3+5=[MASK][MASK]”，第一个 [MASK] 极可能为 “8”（熵低），第二个（结果的写法/后续 token）更难。ALoDLM 在第 1 圈就提交 “8” 并回填其嵌入，第 2–4 圈的循环把剩余位置在”已知 8”的上下文里继续精炼。标准 DLM 若把两个位置一起推迟，下一去噪步两个位置都要从 mask 嵌入重算，第 1 圈花在这两个位置上的计算被丢掉。

瓶颈与额外开销：循环核 + Coda 每 pass 都要重算（8B 四 pass 路径 = 10+4×(16+10)=11410+4\times(16+10)=11410+4×(16+10)=114 层评估，对比整栈四次的 144 层，Appendix B.2 Eq. 11）；KV cache 需要按深度分桶（84 对逻辑 buffer），prefill 要为全深度构建 cache，导致 time-to-first-token 变长（§5 局限性）。

4. 解决得怎么样？

4.1 实验设置

  • 任务与数据集（11 个）：通用/科学推理——ARC-Easy、ARC-Challenge、MMLU、MMLU-Pro、GPQA-Diamond；数学——GSM8K、MATH-500；代码——HumanEval、sanitized MBPP 及两者 EvalPlus 变体（§4.1）。
  • 基础模型与配置：由 Qwen3-1.7B/8B 经 WeDLM block-diffusion 框架直接 SFT 转换；K=4；1.7B 全部 28 层作循环核，8B 为 prelude [0,10)[0,10)[0,10)/core [10,26)[10,26)[10,26)/coda [26,36)[26,36)[26,36)；不设 CPT 阶段（§4.1、Table 2）。
  • 基线：Qwen3-1.7B/8B（AR）、LLaDA-8B、Dream-7B、Fast-dLLM-v2-7B、SDAR-1.7B/8B、WeDLM-8B。每个基线使用其优化推理引擎（dInfer/JetEngine/vLLM/native），ALoDLM 用自身 CUDA-graph 引擎（§4.1、Appendix D.2；注：§4.1 叙述为”经 vLLM 服务”，与 D.2 的 native engine 表述不完全一致，审稿时需留意）。
  • 指标：非代码用 accuracy / exact match，代码用执行 pass@1；Table 1 平均为 11 项无权重平均（Appendix D.2）。
  • 公平性措施：统一 OpenCompass 协议、原生 chat template、greedy、4096 token 生成上限；Table 1 中所有模型被约束为”每次模型前向恰好提交 1 个 token”（按各自默认解码规则，如取最低熵），消除并行度差异；ALoDLM 质量预设关闭 τ（不启用 entropy 选择）、但同一次去噪步内仍可经多次内循环提交多个 token（§4.1、Appendix D.2）。
  • 其他复现细节与缺口：Appendix D.2 提到 (q,τ)(q,\tau)(q,τ) 扫描使用位置系数 γ=0.02\gamma=0.02γ=0.02，但正文未给出该系数的定义；训练语料构成、随机种子与主结果方差均未报告。
  • 各实验回答的问题：Table 1 + Fig. 1 回答”质量是否超过基线与 AR”；Fig. 3 回答”质量-效率权衡与旋钮作用”；Fig. 4/5 回答”机制是否按预期工作（测试时扩展、token 自适应、K/循环位置/方差缩减）”。附录 D 给出协议与成本口径；Appendix E 是个案研究。

4.2 关键结果

以下数字均为论文报告值（原文事实），条件为 §4.1 所述单 token/步 greedy 协议：

  • 平均分（Table 1）：ALoDLM-8B 80.3，超过 Qwen3-8B 78.5（+1.8）、WeDLM-8B 75.1（+5.2）、SDAR-8B 74.2；ALoDLM-1.7B 65.5，超过 Qwen3-1.7B 63.8（+1.7）与 SDAR-1.7B 61.0。相对最强 DLM 基线 WeDLM-8B，ALoDLM-8B 在 11 项中 10 项领先（§4.2）。
  • 未领先/持平项：MMLU 上 ALoDLM-8B 为 76.6，低于 WeDLM-8B 的 78.0（与 Qwen3-8B 的 76.6 持平）；1.7B 上 MMLU 59.4 低于 Qwen3-1.7B 60.3 与 SDAR-1.7B 63.4，MATH-500 61.8 明显低于 Qwen3-1.7B 的 72.0（Table 1）。即”平均占优”掩盖了 MMLU/MATH-500 等单项的落后，且 1.7B 规模并非全面超越。
  • 代码任务：四项全胜 DLM 基线（如 HumanEval 87.8 vs SDAR-8B 78.0、WeDLM-8B 79.9），但 MBPP+ 72.5 略低于 Qwen3-8B 74.5（作者自述 “except slightly behind the AR models on MBPP+”，§4.2）。
  • 效率（Fig. 1、Fig. 3b、§4.3）：GSM8K 上 ALoDLM-8B 达 vLLM 服务 Qwen3-8B 约 2.7× 吞吐、精度相当或更高（94.2 vs 93.6）；与 WeDLM-8B 在 93.25% 匹配精度下 612.4 vs 564.2 tok/s（+8.5%），GFLOPs/token 133.5 vs 154.6（−13.6%，估算值）；两者 frontier 在约 650 tok/s 处交叉，更高速端 WeDLM 占优（§4.3）。
  • 显著性/方差：Table 1 未报告重复运行、置信区间或显著性检验；仅 Fig. 5（右）的梯度方差分析给出 bootstrap CI。平均增益 +1.7/+1.8 分是否稳定，当前材料无法确认。

Fig. 1 解释：左图为 11 个基准的雷达图，按四类（reasoning/knowledge/math & science/code）分组，把各模型在每项上的得分画成多边形；ALoDLM-8B（粗蓝线）在多数轴向外扩张，直观说明”不是单项冲高，而是整体外圈”。右图为 GSM8K 精度-单流吞吐散点（1×B200），每个模型旁标注其推理引擎（HF generate/vLLM/JetEngine/dInfer/nano-vLLM）；ALoDLM-8B 位于右上角，即”高精度 + 高吞吐”象限，而 Qwen3-8B（vLLM）在其左下。为什么需要：Table 1 只给质量，这一张右图承担”质量-速度联合占优”的主主张的视觉证据。

4.3 机制证据

支持”确实有效”的证据：

  • GSM8K 旋钮扫描（Fig. 3a、§4.3）：固定 q=0.5 时 τ 从 0.1 升到 0.6，吞吐 278.7→508.3 tok/s、精度 93.8%→92.3%，τ=0.9 时精度跌到 89.9%；固定 τ=0.2 时 q 从 0.1 升到 0.9，精度 93.3%→93.8%、吞吐 455.3→309.0 tok/s。说明两个旋钮分别控制”并行提交激进程度”与”潜精炼时长”，方向符合设计预期。
  • 测试时扩展（Fig. 4 中）：q 增大使平均每 token 循环数从 1.60 升到 2.34，11 基准平均分从 77.9% 升到 79.1%。注意这是 1.2 分的提升，且为聚合平均。
  • token 自适应（Fig. 4 右）：数字类 token 平均首 pass halt 概率 0.369，比跨数据集参考均值 0.417 低约 11.5%，词类 token 最高（0.428）；论文强调无显式难度标签或预设 halt 目标。
  • 训练动力学（Fig. 4 左）：训练中后期，更深 readout 在其活跃 token 上 loss 更低，与”渐进精炼”一致。

Fig. 4 解释：左图（loss vs step，d=1…4 四条曲线）验证”更深循环 = 对未决 token 的更好预测”，若 d=4 曲线不降反升说明循环退化，因此是必要的健全性检查；中图（蓝色 accuracy 柱 + 红色 loops/token 折线，双轴）说明 q 是测试时算力的连续旋钮——增大 q 同时抬高循环数与精度，但有递减收益；右图（各 token 类别 halt 概率条形图，含 ±误差线）说明自适应来自学习而非人工规则，”Number” 类最低是全文最贴近 mechanism claim 的行为证据。

能否说明”为什么有效”：部分能。Fig. 4（中/右）与 Fig. 3(b) 构成”分配随难度走 + 计算换质量”的行为证据链；但注意这些都是描述性/相关性证据，并且：

  • 没有”固定深度、同等平均算力（same average passes/token）”的控制实验来隔离”自适应分配”本身的贡献；K∈{2,4,8} 消融比较的是上限深度而非”自适应 vs 均匀”（§4.4、Fig. 5 左）。
  • token 类别 halt 统计未给方差/显著性（论文未报告）。
  • 训练时提交位置回填的是目标 token 嵌入（teacher forcing，Appendix C.1/C.4、D.1 明示），推理时回填采样 token；halting 策略在训练/测试输入分布不同，论文自述该差距存在但未量化其对策略部署的影响。
    因此（审稿人判断）：论文证明了系统可用且随旋钮单调响应，但”错配假设被验证”仍缺少直接因果对照。

4.4 成本与适用范围

  • 训练成本：论文报告了优化超参与规模（5B-token 语料、8B 8 epochs/34,512 步、batch 256×4096、bf16、ZeRO-2、梯度检查点），但未报告训练 GPU 时数或训练总 FLOPs；训练语料来源与构成也未报告（官方仓库亦无数据获取代码）。
  • 推理成本：GSM8K 单流下 ALoDLM-8B 在匹配精度 93.25% 时 612.4 tok/s（WeDLM 564.2），GFLOPs/token 133.5 对 154.6（−13.6%，基于 Eq. 35 的估算，且论文说明 WeDLM 的执行工作量由其 prefill 长度/解码步数/图形状间接重建，属异构口径）；约 2.7× 于 vLLM 服务 Qwen3-8B（精度相当或更高）。
  • 内存/系统复杂度：8B 需 84 对逻辑 KV buffer（64 对属循环核）；显存占用与端到端延迟明细论文未报告。
  • 已知代价（作者在 §5 承认）：TTFT 因全深度 prefill 变长；吞吐随 prompt/域变化，训练分布外领域可能需要更多循环、更少并行提交，速度优势可能缩小甚至反转；两者均未给出量化数据。
  • 覆盖范围：结论限于 11 个英文推理/数学/代码基准、Qwen3 骨干、K=4、单流 B200 的评测设置；未覆盖多语言、长上下文（>4096 生成）、对话/agent 类任务与延迟敏感交互场景。

Fig. 3 解释：左面板 (a) 两个子图分别是 τ 扫描（精度下行、速度上行）与 q 扫描（精度上行、速度下行），说明两旋钮互补、可组合出不同操作点——没有它们，”自适应”就退化为固定行为；右面板 (b) 左图把 ALoDLM 与 WeDLM 在 94/21 组配置下的精度-吞吐 frontier 叠放（约 650 tok/s 交叉），右图换成精度-GFLOPs/token 以剥离 kernel/内存因素、只比算术量，ALoDLM 在该口径下全程占优。这组图承担”自适应循环改善每单位计算的生成质量”这一主张。

5. 最容易受到审稿人质疑的地方

质疑：核心机制缺少”自适应 vs 同等算力固定深度”的直接对照，收益归因不完整

  • 原文依据：Table 1 与 Fig. 3 证明”方法有效”；消融只覆盖最大深度 K（Fig. 5 左）、循环位置（Fig. 5 中）、方差缩减（Fig. 5 右）；token 自适应证据是类别 halt 统计（Fig. 4 右）与 q 的测试时扩展（Fig. 4 中），均为描述性/相关性。§1 的 computation–difficulty mismatch 以 “We hypothesize” 表述。
  • 为什么重要：论文的中心主张是”按 token 难度分配计算”带来质量增益；若增益主要来自”更多循环次数/更深有效深度/更大有效参数复用”，则机制叙事（自适应分配）与论据错位，影响创新性成立与否。
  • 当前能够得出的判断：系统整体有效、旋钮行为符合预期可以确认；”自适应分配本身（相对同等平均算力的均匀循环）是收益来源”证据不足，属混杂未排除。
  • 如何验证或补强：增加控制实验——同一骨干、同样平均 passes/token（例如所有 token 强制 K=2 的均匀循环 vs 平均深度 ≈2 的自适应循环），比较质量-算力曲线；并报告 token 级 halt 统计的置信区间与跨域泛化。
  • 严重程度：主要问题

质疑：训练语料不透明、与基线的训练预算口径不一，比较公平性无法完全核实

  • 原文依据：§4.1/Appendix D.1 仅写 “5B-token corpus”，未给来源、构成、过滤；官方仓库明确没有数据集获取代码与语料细节。基线数字（SDAR、WeDLM、LLaDA、Dream、Fast-dLLM-v2）未说明是自行复现还是取自原论文；SDAR/WeDLM 的训练管线包含 CPT，与 ALoDLM 的”直接 SFT”不同预算口径。
  • 为什么重要：直接决定 “outperforms all evaluated DLMs” 这一核心论断是方法优势还是数据/预算优势；也影响可复现性。
  • 当前能够得出的判断：解码协议（单 token/步、OpenCompass、greedy）对齐较严谨；但训练数据与训练预算层面无法核实，基线复现/引用情况文献未交代。
  • 如何验证或补强：披露语料来源与配比；说明每个基线数字出处并给出复现脚本；在相同数据与相同 token 预算下重训至少一个最接近的基线（WeDLM-8B）。
  • 严重程度：主要问题

质疑：主结果缺少统计稳定性报告，平均增益较小且掩盖任务级差异

  • 原文依据：Table 1 为单次评测点估计，无置信区间/多次运行/显著性；平均增益为 +1.7（1.7B 对 Qwen3）与 +1.8（8B 对 Qwen3）；同时 8B 在 MMLU 落后 WeDLM（76.6 vs 78.0），1.7B 在 MATH-500 大幅落后 Qwen3（61.8 vs 72.0）。附录 D 未提 seed 或重复评测。
  • 为什么重要：如果单基准波动与平均增益同量级，结论应表述为”在多数基准上有小幅优势”而非”state-of-the-art 平均分”。
  • 当前能够得出的判断：任务间表现不均衡是原文事实；平均增益是否超过评测噪声，当前材料无法确认。
  • 如何验证或补强：报告多次评测的均值±方差或 bootstrap CI；给出每个基准的判分脚本与样本量；对关键比较做配对检验。
  • 严重程度：主要问题

质疑：质量-效率 frontier 比较的对称性与 GFLOPs 口径问题

  • 原文依据：§4.3——ALoDLM 扫 94 个 (q,τ)(q,\tau)(q,τ) 配置，WeDLM 只有 21 个 entropy-threshold 配置，frontier 估计的分辨率与调参自由度不同；GFLOPs 为公式估算（Eq. 35），论文自述 WeDLM 的工作量由 prefill 长度/步数/图形状”重建”；§4.1 与 D.2 的服务引擎描述不一致（”via vLLM” vs “native CUDA-graph engines”）。
  • 为什么重要：影响 “quality-efficiency trade-off 优于 WeDLM” 的强度与速度数字的可审计性。
  • 当前能够得出的判断：matched-accuracy 点比较（612.4 vs 564.2 tok/s）与算术量比较（133.5 vs 154.6 GFLOPs/token）方向一致，主张有初步支持；但 frontier 形状与交叉点（约 650 tok/s）的稳健性无法确认。
  • 如何验证或补强：对 WeDLM 扫等密度的配置网格；实测等量计数（profiler）而非估算 GFLOPs；澄清并统一引擎描述；给出吞吐的多次测量方差。
  • 严重程度：次要问题

质疑：实用时延边界（TTFT、域外速度反转）未量化，2.7× 吞吐的适用范围被淡化

  • 原文依据：§5 明确承认 TTFT 更长（prefill 需构建全深度 KV cache）、吞吐输入依赖、训练分布外的域可能”reduce or entirely reverse”速度优势；但正文与附录未报告 TTFT 数值、域外速度的测量或失败/退化案例比例；2.7× 为 GSM8K 数据集级吞吐（总生成 token/总时间），非单请求延迟。
  • 为什么重要：影响”strong quality–efficiency trade-off”结论在交互式、低 batch、短回复场景的适用性；审稿人通常要求把此类边界写进结论而非只放在 Limitations。
  • 当前能够得出的判断：作者已如实披露方向性风险（值得肯定），但缺少数值边界，外部读者无法判断适用阈值。
  • 如何验证或补强：报告 TTFT/端到端延迟分布（按 prompt 长度分层）、域外数据集上的吞吐精度对照、并行提交数分布与最坏情况。
  • 严重程度：次要问题

6. 审稿式总评

作者发现扩散语言模型与同规模 AR 模型的质量差距可能源于”计算–难度错配”——去噪步内所有 mask 位置共享固定深度的均匀计算，而 confidence-based 解码推迟困难 token 时又会丢弃其潜计算，因此提出 ALoDLM：在每个去噪步内引入 token 自适应循环，简单 token 提前提交为离散上下文、困难 token 保留潜状态继续精炼，并把 token 级 exit schedule 作为隐变量用 conditional NELBO 端到端学习词预测与计算分配。实验在 11 个推理/数学/代码基准、1.7B 与 8B 两个规模、统一的”每次前向一个 token”评测协议下表明，平均分超过所有被评测 DLM 及对应 Qwen3 AR 基线（80.3 vs 78.5/75.1），且在 B200 单流下取得约 2.7× 于 vLLM 服务 Qwen3-8B 的吞吐；其中旋钮扫描、测试时扩展与梯度方差证据较强，但”自适应分配相对同等算力固定深度”这一核心因果链仍缺少直接对照，主结果无统计稳定性报告，训练语料与基线预算口径未披露。本文最有价值的部分是把”步内 token 自适应退出”从想法落成含目标函数推导、无偏估计器与可服务 KV cache 的完整系统，并开源代码与两个规模的 checkpoint；最大的审稿风险是收益归因不完整——现有证据足以说明”这套循环系统好用”，但不足以说明”好用在自适应分配本身”。

  • 问题定义清晰度：强（错配假设表述明确、可操作化为 exit schedule 与两个推理旋钮；但因果验证不完整）
  • 创新性证据：中（架构+目标+估计器组合是实质增量，推导有附录支撑；但核心机制缺直接消融，与 FReDA/Ouro 等的差异主要依赖文字对比）
  • 方法可信度：中（公式与证明完整、训练细节充分；teacher forcing 训练与采样推理的差距未量化，服务引擎描述两处不一致）
  • 实验支持力度：中（基准覆盖广、评测协议对齐、消融多样；但无统计稳定性、无关键对照、基线与训练预算口径存疑）
  • 可复现性：中（代码、1.7B/8B 权重与推理/训练代码已开源；训练语料未披露、训练成本未报告、WeDLM 派生组件附带的许可限制）
  • 综合阅读价值：高（对研究扩散语言模型、自适应计算与推理效率的读者，是”机制清楚、证据需进一步核验”的完整案例）
