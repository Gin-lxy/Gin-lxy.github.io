0. 一句话结论

论文指出失败 rollout 中除了奖励还包含”改哪一步、换成什么动作”的监督信号，据此构建了 AED——一个包含 50,228 个 error–diagnosis 对（33 个环境、19 个 harness 家族、23 个策略模型）的自然失败数据集，并用五阶段 AET 流水线把失败转成”诊断 / 恢复 / 偏好”三类训练视图，其中可在同 checkpoint 上重放的部分带原始动作对照实验。核心证据是：修正提案在 3,062 对匹配 replay 上把 verifier 通过率从 18.4% 提到 51.1%（+32.7 pp），full-diagnosis SFT 把 Qwen3-8B 与内部教师标签的 exact-step 一致率从 47.2% 提到 63.6%（优于最强 prompting 基线 54.7%）。但主要结论必须加边界：63.6% 衡量的是与论文自建教师标签的一致率（该冻结版本被论文自己审计出多处缺陷），公开基准迁移大多为负，actor 修复训练只在 WebShop-lite 上显著为正、在 TextQuest 与真实环境上明显退化，且大多为单种子实验。

1. 论文具体想解决什么问题？

背景与任务。LLM agent 通过 harness 连接工具与持久状态，在软件、网页等交互任务中工作（§1）。agent 后训练领域已用 reward 过滤轨迹做 SFT（AgentTuning）、把策略优化扩展到多轮环境反馈（RAGEN、AgentRL），但作者强调：outcome reward 本身不指明”该改哪一步决策、应换成什么动作”，而失败轨迹保留了观测、动作与环境响应，可以转化为”定位错误 + 解释原因 + 给出替代动作”的监督（§1）。

现有做法与不足。作者在 related work 中把已有工作分为失败归因（MAST 的失败模式分类、Who&When 的责任 agent/步骤定位、AgenTracer 的定位模型训练、AEGIS 的注入式验证）与恢复（AgentDebug、AgentDebugX）两条线，并给出 Table 1 的九项资源对比：已有资源要么只做标注（无执行修正证据、无对照），要么环境/harness/模型覆盖窄，或学习目标不是训练一个”会修复动作”的 acting policy（§2，Table 1）。

作者的问题判断。”需要一份更广的资源，把自然失败与解释、修正提案和执行证据连接起来，并同时支持诊断与动作两类训练”（§1）。论文指出跨资源研究困难的根源：执行设置、标注目标、修正证据的定义各不相同（§2）。需要注意：（审稿人判断）这是一个”资源缺口”型问题陈述，作者没有给出测量数据来量化该缺口（例如多少研究因资源不统一而受阻），Table 1 的对比即其全部证据；该问题判断的合理性主要来自相关工作总结本身。

核心假设。若把失败经验构造为（失败轨迹 → 有引用支撑的诊断与修正提案 → 可选的同 checkpoint 对照 replay → 目标专属训练视图）的流水线，则（i）修正提案可被执行验证，（ii）诊断本身可作为监督信号训练 debugger，（iii）修正行为可作为监督信号训练 actor（§1，§3.2，Figure 2）。三条假设在 §5 中被分别检验，且论文对每条的结论强弱不同（见 §4）。

2. 创新点是什么？

一段话概括：AED 的实质增量是”规模化 + 结构化 + 对照试验化”三项工程与实验设计的组合——把 33 个环境、19 个 harness、23 个策略模型的自然失败收集成带完整溯源与多次诊断的集合；用 AET 五阶段流水线为每条失败建立”诊断—引用—取证—（可选）重放”的证据链；并在可重放的子集上执行”修正动作 vs 同 checkpoint 原动作重试”的配对对照，把”修正是否真的有用”从相关性升级为干预证据；最后为诊断、恢复、偏好构造相互独立的训练视图。方法学上它没有提出新的模型或训练目标（诊断引擎直接调用已有的 AgentDebug/AgentDebugX API，训练都是标准 SFT/DPO），创新集中在数据资源与构建-验证流程。

创新点 1：带对照 replay 的修正有效性证据。机制：对每条失败，把修正提案与”同一 checkpoint 重放原动作”作对照，两者共享 policy、harness、预算、verifier 与温度调度（§3.2 阶段 4；Appendix D.1）。与最接近工作（AgentDebug 用修正反馈恢复、AgenTracer 做归因训练）的不同：AgentDebug 不保留同 checkpoint 对照，AgenTracer 的 replay 仅用于构造（Table 1 的 Ctrl. 列：AED 标记为部分支持，AgentDebug 为无）。证据：3,062 对配对中，修正胜出 1,454 对、失败 66 对；B.2 的 discordant 分析显示若不做对照，会把 1,564 次”修正成功”全记为收益，而其中 470 次（30.1%）原动作重试也成功（§5.1，Figure 1a，Appendix B.2）。移除该设计的后果论文报告得很清楚：匹配大小过滤后”更严格 admission 不带来学习收益”（§5.1、Appendix X），说明对照 replay 的价值主要体现在分析而非训练增益。

创新点 2：AET 五阶段流水线与证据分级。机制：Collect（仅自然失败，基础设施/grader 故障单独隔离）→ Diagnose（自由文本诊断，非固定分类法；保留初版提案与修订历史）→ Ground（引用必须在学生可见 trace 中可解析，双判官语义审查）→ Replay（可选，E0/E1/E2 证据分级：E2 要求每组 ≥2 次试验且治疗组全过、对照组全败）→ Build views（诊断/恢复/偏好视图各有独立准入规则）（§3.2，Appendix C.1、D.1、D.2）。差异：把”证据强度”显式分级并可只凭存储结果重算，区别于只存单一标注的已有数据集。证据：逐条留痕（接受与拒绝的提案都保留），但（审稿人判断）流水线的核心推理组件是外部系统，论文未做”移除该组件”的消融——G1b 的 X vs J 对比里两个构造法都没有超过 base（Appendix I.9），这是对该流水线训练价值的直接反证。

创新点 3：面向不同目标的训练视图拆分。机制：诊断视图（compact 只含 attribution；full 含 7 字段）、预防式恢复（pre-error 历史 → 通过分支的动作）、后错式恢复（历史+错误动作（masked）→ 修正，可带反思）、动作 DPO（同一状态下两个已执行的可比动作）（§4，Appendix Q.3、T.2）。差异：已有资源不同时提供”诊断”与”actor 修复”两种监督（Table 1 的 Train 列仅 AED 标 D, A）。证据：诊断侧有内部一致率提升（§5.2），actor 侧只有环境依赖的混合结果（§5.3）；反思（reflection）相对纯动作监督无检测到的增益，DPO 试点无恢复收益（§5.3，Appendix I.15）。也就是说该设计里只有”诊断视图”拿到了正面训练证据，”后错恢复视图”的增量收益未被证明。

创新点 4（需降级看待）：50,228 对的规模与多样性本身。这属于已有组件（失败收集、诊断、replay）的规模化整合，而非新研究思想；且论文标题的 50,000 是经过筛选后计数的 error–diagnosis 对，不等于独立失败次数（38,278 个 source-trace blob、9,961 个 source task，pairs/blob=1.31；Appendix B.1 明确”blob 身份不构成独立执行的计数”）。

3. 作者如何解决？

直觉：一次失败 rollout 相当于一次”已经跑过路径的搜索”——把它变成监督的关键动作是：指出哪一步是可避免的决策错误（而非失败暴露的步骤）、给出理由与证据、并用一次受控重放检验”换个动作会不会成功”。AET 就是把这套人工调试逻辑流水线化，并为不同下游目标导出不同”输入-目标”对。

运行流程（按实际 pipeline 展开）：

  1. 输入：环境适配器提供的任务、指令、工具与成功 verifier；策略模型在 harness 中的完整 action–observation 轨迹、终端结果（§3.1，Appendix D.1 阶段 1）。失败是自然产生的，不注入（Table 1：AED 项 Errors=nat.）。
  2. Collect：保存 policy/harness/environment 身份、动作、观测与结果；服务故障、harness 故障、grader 异常保留存档但排除在 agent-error 目标外；工具报错后任务成功的运行被排除（Table 附录 D.1 失败边界表）。
  3. Diagnose：通过 AgentDebugX 的 Python attribution API 产生 blamed step、责任 agent/组件、带 trace 引用的解释与替代动作；记录 privileged 参考信息与 learner 输入分离；保留全部尝试并区分”初版提案”与”重试后选中”提案；多个 debugger 可复用同一失败（§3.2，Appendix D）。
  4. Ground：引用必须在导出的学生输入中逐字解析（截断标记不算证据）、检查工具与信息可用性（修复只能用动作前可得的信息），双判官全部接受才通过；机械检查 + 语义判官 + 12 项 rubric v5（含泄漏/秘密、输入保真等）（Appendix D.1、E.6）。
  5. Replay（可选）：从恢复或重建的 checkpoint 起两个新执行——一个替代修正动作、一个重复原动作；匹配 policy/harness/预算/verifier/温度（首个样本 T=0.2、后续 0.8；源 rollout 是 0.7），两个臂共享调度（Appendix D）。状态恢复分三类记录：原生 harness 完整恢复（871 对）、替代 ReAct harness（1,846 对，因 smolagents/Pydantic AI/AutoGen/LangGraph/多 agent 等不被 replay runner 支持）、多 agent 状态部分恢复（345 对）（Appendix H.1，Table 14）。MCPMark 因两次重放判决不一致被排除出 verified-repair；GAIA/WideSearch 无法确定性重放，只保留诊断（Appendix O.4，Table 37）。
  6. Build views（训练）：仅目标 assistant token 计 loss（式 1：诊断用 per-example mean ℓi(θ)=−∑kmiklog⁡πθ(yik∣xi,yi,<k)\ell_i(\theta)=-\sum_k m_{ik}\log \pi_\theta(y_{ik}\mid x_i, y_{i,<k})ℓi​(θ)=−∑k​mik​logπθ​(yik​∣xi​,yi,<k​)，actor 用跨 rank 的 token mean）（§4，Eq. 1）。诊断视图输入=失败 trace，输出=attribution（compact）或 7 字段（full）；恢复视图把 pre-error 历史（+后错变体中被 mask 的错误动作与反馈）映射到通过分支的动作；偏好对要求同状态、已执行且结果有正反差。训练用 Qwen3-8B 全参 SFT（BF16、AdamW、lr 10−510^{-5}10−5、cosine、3% warmup、梯度裁剪 1.0；诊断 batch 12、2 epochs；actor batch 16、2 epochs）（Appendix I.2，Table 18）。
  7. 输出：带证据等级的记录（失败轨迹 + 诊断 + 修正 + replay 分支）、三类训练视图（诊断/恢复/偏好）以及可重算的 E0/E1/E2 分级（Appendix C.1、D.2）。

哪些由模型决定、哪些由固定流程控制：诊断、解释、修正提案由 LLM debugger 生成（模型决定）；引用解析、admission rubric、replay 调度、loss mask、split 划分由固定流程控制。判定”decisive step”的标准是”最早的有支持的、且修正后可避免失败的错误”——rubric 要求排除已于之后恢复的错误与纯粹症状（Appendix E.6 第 2 条）。

与直接使用的现有组件的关系（区分论文提出 vs 沿用）：诊断引擎沿用 AgentDebug/AgentDebugX（§3.2、Appendix D）；harness（OpenHands、π agent、ReAct、AutoGen 等）与基准（ALFWorld、BFCL、SWE-bench 等）都是现成的；论文新增的是环境适配器、证据检查、verifier 对照 replay、训练视图与准入规则（Appendix D）。

教学简化示例（非论文实验）：把一条失败轨迹想成”考试错题”。普通 outcome reward 只告诉你”这题错了（0 分）”；AED 的做法是让一位”讲评老师”（debugger）圈出”你是在第 2 步算错了符号”，写清”为什么这么判”（引用你的草稿原文），提出”如果改成 X 会怎样”，然后真的把 X 代回去重算一次（replay），并且同时把原解法原样重算一次（对照）——只有”改 X 成功、原解失败”才记为修正有效的证据。这个例子只是帮助理解流程，论文中的判定远比它严格（要求引用可解析、双判官通过、对照同 checkpoint 等）。

4. 解决得怎么样？

4.1 实验设置

  • 数据与测试台：内部冻结诊断集（frozen v14）4,319 行 / 2,309 source task / 15 环境（train 3,157 行、dev 219、holdout 943）（Table 7，Table 12）；配对 replay 队列 3,062 次尝试 / 1,284 source task；actor 实验用 6 个开发环境（Text-to-SQL、ALFWorld-lite、TextQuest、WebShop-lite、GridWorld、Warehouse）；真实环境仅在 ALFWorld / ScienceWorld 上补测 preventive 臂（§5.3，Appendix X.6）。公开基准：Who&When（184 例：HC 58 + AG 126）、AgentErrorBench（200 例）、TrajErrBench（486 例）（§5.2，Appendix I.1、X.5）。
  • 可训练模型：仅 Qwen3-8B（全参 SFT；DPO 用 LoRA，r=16r=16r=16、β=0.1\beta=0.1β=0.1、lr 10−510^{-5}10−5、3 seeds）（§5，Appendix I.2、I.15）。诊断的”教师标签”来自多模型共识（GPT-5-mini、Claude Haiku 4.5、Gemini 3.6 Flash 投票，Gemini 3.6 Flash 记录为 arbiter）（Appendix S）。
  • prompted 参照：Claude Opus 5、Claude Sonnet 5、Gemini 3.8 Flash、GPT-6 Astra、GPT-5.6 Sol 等（同一 943 例、同一解码设置、temp 0（提供方支持时）、8,192 token 预算）（Appendix I.3，X.1a）。
  • 指标：exact-step agreement（micro / family-macro）、unit+step 联合、verifier pass rate、初始状态任务成功率；缺失或不可解析答案一律计入分母算错（§5 Setup）。统计上报告 task-clustered 区间与 seed SD，两套不确定性分开表述（§5，Appendix I.5）。
  • 对照设计：修正 vs 原动作重试（同 checkpoint）；actor 实验以 success-only SFT 为参照（用论文自己的池，非 AgentTuning 数据）；资源对比用同 base、同 recipe、同任务数的 AgenTracer v1.0.0 数据（Appendix I.5、X.4）。

4.2 关键结果

修正有效性（§5.1，Figure 1a）。3,062 对匹配 replay 上：初版提案把 verifier 成功率从 18.4%（原动作重试）提到 51.1%，+32.7 pp（task-clustered 95% 区间 28.4–37.0）；搜索选出的提案 +45.3 pp（59.1% vs 13.7%，区间 41.3–49.2）；原生 harness 完整恢复的 871 对 +47.1 pp（42.3–51.7）（Appendix X.3、H.1）。队列中仅 11/3,062 次失败是”单纯耗尽步数预算”，且无一落在”只有原动作通过”的格子，限制了”对照成功只是预算伪影”的解释（Appendix H.1）。但 B.2 的对照分解显示：1,564 次”初版修正成功”中 470 次（30.1%）原动作重试也成功——净收益只来自 discordant 格子（1,094 vs 93）。

采集与生产（§5.1，Appendix I.6）。citation-first judge 在 1,500 条共同失败池上产出 93.5% 的”带引用诊断”，优于对照配置的 48.4–65.8%；但论文明确这是”产出兼容率”而非独立正确率（渲染与教师访问也不同）。

诊断学习（§5.2，Figure 5）。full-diagnosis SFT（1,656 任务、3 seeds）把 Qwen3-8B 在 943 例 holdout 上与内部教师标签的 micro exact-step 一致率从 47.19% 提到 63.56±0.82；最强 prompting 参照 Claude Opus 5 为 54.72，升幅在四个嵌套训练规模（240/480/948/1,656）上单调：53.13±1.43 → 57.26±1.60 → 60.59±0.93 → 63.56±0.82（Table 28）。作者同时写明：与参照相比”学生用共识标签训练、参照未训练”，测的是与记录标注（含其约定与缺陷）的一致率，不是诊断能力的普遍排序（§5.2）。

诊断学习的反面证据（§5.2，Appendix I.1、I.9、I.13）。公开迁移混乱：培训格式 prompt 下多数格显著下降（Who&When AG -21.43、AG+WG -29.37，TrajErrBench -12.14；Holm 校正后 13 项检验仅剩 3 项显著，全是损失）；唯一正格（unified Who&When +7.07，p=0.049）在 Holm 校正后不显著（p=0.437）；剔除与训练重叠的任务后，+7.97 的区间收缩到含零（+4.92 [-2.24,12.08]）（Table 15、30、31）。compact-target 的缩放曲线随训练集增大反而下降：48.89（120）→ 47.72（252）→ 47.40（504）→ 46.13（1,020）→ 46.59±0.12（1,656），base 47.19——因为 verdict-only 目标让模型输出越来越多空 reasoning block（1,020 任务时 90.4%，1,656 时约 100%）（Appendix I.13，Figure 14）。与 AgenTracer 数据的同 recipe 对比：在自己 holdout 上 AED 无增益（+0.11 [-2.72,2.99]），在对方测试集上落后 9.07 pp（31.65±0.33 vs 40.72±0.48）（Table 11，Appendix X.4）。

actor 修复训练（§5.3，Figure 6）。六环境、单种子、各 arm 任务池/曝光/更新数不同的对比：修复含入的配方在 WebShop-lite 上高于 success-only（preventive +4.67、post-error +6.67、+reflection +6.67，* 为 Holm 校正后显著），在 TextQuest 上显著更低（-9.00、-8.33、-9.67*）；反思相对纯动作无检测到的增益（Appendix X.6，R/A McNemar 均不显著）。真实环境反转：preventive 臂在真实 ALFWorld 仅解 1/134（0.75%）vs base 8/134（5.97%），真实 ScienceWorld 1/294（0.34%）vs base 29/300（9.67%）（Appendix X.6）。

供给位置下的恢复（§5.1，Figure 1c，Table 27）。给定错误位置，diagnosis-guided continuation 31.3%，generic reconsideration 26.0%，重放原动作 18.6%；”诊断内容 - 泛化重试”配对增益 +5.6 pp，区间 [0.0, 11.3]——诊断内容相对”再给一次机会”的额外收益未被确立（Appendix I.10）。

偏好试点。DPO（33 个训练对）在 94 个 holdout 对上把”选中动作”偏好从 54.3% 提到 54.6±0.6%，无任务恢复评估，论文自认不构成恢复收益证据（Appendix I.15）。

4.3 机制证据

  • 修正有效性属于干预证据：同 checkpoint、同执行条件的对照使”修正成功”与”原动作也能成功”可分离（§5.1，Figure 1a；Appendix B.2）。不过每臂当前只有一次执行（k=1），证据分级中 E2（≥2 次/臂）大量缺席，无法排除单次判决的随机性；论文在 Appendix R 的重放复现中报告了”同一动作重复执行会随机翻转”的现象，并建议保留控制臂结果与试验次数。
  • 诊断训练只证明了”拟合记录标签”：学生与参照都未见过这些标签（参照）或太多（学生），无法排除”学习教师的约定与缺陷”的解释；论文明确写”citation matching 检查的是存在性而非蕴含”（Appendix A）。直接反证是 G1b：执行辅助（X）与单判官（J）两种标签构造在 168 和 948 任务上都没有超过 base（Appendix I.9）。
  • 机制归因（为何 actor 训练环境依赖）：论文只给出了相关性——WebShop-lite 增益伴随更短 episode、TextQuest 新失败多撞步数上限，但明确声明”不隔离预算机制与曝光/更新次数差异”（§5.3，Appendix X.6）。同样，Compact 曲线的空 reasoning block 与确切度下降之间的因果也被保留（Appendix I.13）。
  • 论文自己反复划线：”性能提升不得自动解释为机制验证”的做法基本被贯彻——多处用”supports X under these conditions, not Y”的措辞（§3.2 阶段 4、§5.1）。

4.4 成本与适用范围

  • 构建成本（实际计费口径）：两个历史采集波次共 1,198 个完成 cell（21,629 次运行、6,898 条有效步骤诊断），rollout $415.53 + diagnosis $343.44 = $758.96；平均 $0.110/诊断（MCPMark 最贵 $0.469，AgentBench-DB 最低 $0.049）；仅含 rollout 与诊断 meters，不含 hosting、human labor 与 replay（Appendix I.7）。
  • 准入成本：admission 消融显示每保留一行成本随严格度上升：无检查 19,904 行（$0.04/行）→ 仅 grounding 2,628 行（$0.31/行）→ grounding+语义审查 767 行（$1.25/行）；而学习收益没有随严格度上升（”配对区间全部含零或为负”，Appendix I.8、X.3）。
  • 零散计费：盲化模型 panel 120 条 ×3 判 = $17.40；rubric 试验 $5.17；供给位置队列 $3.66；语义审查阶段 $0.039/条（Claude Opus 5 verdict）（Appendix E.4、G.1、M、I.8）。人工审核由 4 位作者志愿完成，未报告人工成本；GPU 训练成本、replay hosting 成本论文未报告。
  • 适用范围：全部为文本型 agent 环境（Table 1 脚注：AED 是 text-only）；”环境数”不等于公开基准数（含合成任务、简化移植与程序化玩具环境，Table 36）；replay 证据只覆盖可恢复状态的原生 harness 子集；actor 结论限于六环境配方；公开迁移结论全部受协议（prompt/答案 schema/step 坐标）影响。论文未报告：完整集合的训练效用（训练只在冻结子集上做）、部署失败率（失败样本无法估算）。

5. 最容易受到审稿人质疑的地方

质疑 1：主结果度量的是”与自建教师标签的一致率”，而该冻结版本被论文自己审计出系统性缺陷——这削弱了 63.6% 的解释力

  • 原文依据：§5.2 原话”measures agreement with the recorded annotations, including their conventions and defects”；Appendix S 记录教师为多模型共识（Gemini 3.6 Flash 记录为 arbiter）；Appendix E.1/E.5 列出冻结发布的具体缺陷：440/4,737 行（GAIA/WideSearch）所有检索调用失败却仍标注错误、AgentBench-DB gold SQL 在 234/455 个任务上无法通过 grader、617/1,016 行在任务契约进入 prompt 前完成标注、125/943 条 holdout 的 gold agent 是不出现在 trace 中的单元；E.5 的逐条审计拒绝 37/60 抽样行；Appendix C.3 记录 0/4,319 诊断行带 replay 佐证。
  • 为什么重要：这决定了论文第二号贡献（”能训练出有竞争力的失败诊断模型”）是否成立。若标签含大量缺陷，学生学到的是”符合缺陷”的输出，63.6% 可能高估真实诊断能力；反之如果缺陷稀疏，也应有证据排除。
  • 当前能够得出的判断：存在测量效度风险但方向未知。论文对缺陷披露非常充分，且声称”当前检查已修复这些缺陷”——但修复发生在评估之后，不会追溯修正已报告的分数；论文自己也承认”冻结 v14 保留被标记行”。
  • 如何验证或补强：用 rubric v5 修订后的导出重新训练与评估（论文报告了修订导出的行数：train 3,157→53 行通过全部过滤，Table 9，但未重训）；在无缺陷子集（剔除 108 个受影响 holdout case 后 835 例）上重算；引入独立人工金标评估 holdout 而不是只做 80 条覆盖选择审计。
  • 严重程度：主要问题。

质疑 2：公开基准上的迁移证据大多是负面的，”训练出有竞争力的诊断模型”仅在内部标签协议下成立

  • 原文依据：Table 30/31：13 项配对检验中培训格式 prompt 下最大跌幅 -29.37（Who&When AG+WG，Holm <0.001）；Holm 校正后仅存的 3 项显著全部是损失；唯一正格 unified Who&When +7.07（Holm 0.437）；TrajErrBench 在可解析子集上仍 -11.73（p<10⁻⁵）；与 AgenTracer 数据的资源对比在自己 holdout 上无增益、在对方测试集上 -9.07（Table 11）；Appendix I.1 的 overlap 敏感性把 +7.97 缩到 +4.92 [-2.24,12.08]。
  • 为什么重要：这直接限制论文主张的边界。作者在 §5.2 承认”resource rankings reverse across test distributions”，但摘要/引言仍把 63.6% 放在显眼位置，读者容易忽略多数公开协议为负。
  • 当前能够得出的判断：证据支持”内部标签拟合”结论，不支持”公共迁移”结论；论文对此基本诚实（Takeaway 与 Limitations 都写明），但头条数字的展示位置仍有放大之嫌。
  • 如何验证或补强：预注册多协议评测（prompt 与答案 schema 冻结后再训）；公布对 TrajErrBench 负迁移的诊断实验（如格式专属化 vs 标签质量）；在 decontaminated 重训（Table 16 只做了 Who&When one protocol）覆盖全部基准。
  • 严重程度：主要问题。

质疑 3：actor 修复训练是单种子、任务池/曝光/更新数混杂的配方对比，”修复监督有用”的机制没有被隔离

  • 原文依据：§5.3”their contrasts measure the combined recipe, not repair supervision alone”；Appendix X.6：repair arms 1,490 updates / success-only 1,326；preventive 与 success-only 的 token 曝光在 Text-to-SQL 差 +8.25%、WebShop-lite 差 -13.69%；真实环境仅 preventive 一臂对测（ALFWorld 0.75% vs 5.97%；ScienceWorld 0.34% vs 9.67%）。
  • 为什么重要：第三号贡献（error-aware post-training 对 acting policy 的价值）目前只有 WebShop-lite 一个环境的正面点估计；真实环境与 TextQuest 的显著退化恰恰说明用失败的修复轨迹训练 actor 可能损害原策略，这是部署层面的重要风险。
  • 当前能够得出的判断：结论被正确限定在”tested recipes and environments”（§5.3 Takeaway），但摘要”action-only repair training scores 6.67 pp higher on WebShop-lite”缺少”单种子、环境特异、且其他环境退化”的并列提示；机制解释（episode 变短、预算撞顶）为相关性。
  • 如何验证或补强：多种子 + 匹配 max-token/update 的对照；把 preventive 臂的真实环境评测补全到全部 arm；分解”任务覆盖”与”监督类型”（如固定任务集只换目标）；检查是否学到缩短 episode 的非预期策略（如提前放弃）。
  • 严重程度：主要问题。

质疑 4：replay 证据的外部效度受限（替代 harness、部分恢复、单次试验），且与冻结诊断集完全不相交

  • 原文依据：Table 14：原生 harness 完整恢复仅 871 对，1,846 对用替代 ReAct harness，345 对多 agent 状态部分恢复；§5.1”Both studies test correction at a supplied location; neither tests autonomous detection”；Appendix D：replay 温度调度（0.2/0.8）与源 rollout（0.7）不同、k=1 无法达 E2；Appendix C.3：0/4,319 诊断行与 replay 记录相交；Appendix T.2：9,715 次导出尝试中 9,712 从未 replay，冻结发布只物化诊断视图。
  • 为什么重要：修正有效性的 32.7 pp 是本论文最接近因果的结论，但它只覆盖可恢复子集，且替换 harness 会改变多 agent 协作/记忆/停止规则——修正在该环境有效不代表在原系统有效（Appendix Q.2 已自认）；同时”诊断训练数据”与”replay 验证数据”互不相交意味着训练用诊断的修正提案从未被执行验证过（论文中能验证的被验证了，被拿去训练的没有）。
  • 当前能够得出的判断：证据支持”在恢复或替代的连续性下修正优于原动作重试”；不支持”修正对原系统普遍有效”或”训练数据的修正提案都是有效的”。
  • 如何验证或补强：扩大原生 harness 支持（smolagents/Pydantic AI/AutoGen/LangGraph/planner–executor 目前全部被替代）；对每臂做 ≥2 次试验以达 E2；把 replay 验证结果与诊断训练集打通（对训练用提案做抽样 replay 审计）。
  • 严重程度：次要问题（论文已充分披露并分层报告，结论措辞与证据范围基本匹配）。

质疑 5：人工审核与质量审计的独立性不足

  • 原文依据：Appendix W：4 位作者在自愿参与下审核 80 条覆盖选择样本（模型 panel 报告先给出、审核时可见），”This is AI-assisted human verification by author volunteers… not independent external validation”；verdict 一致率 62.5%（50/80）、joint accept 51.3%（41/80）；Appendix E.4：盲化模型 panel 中三门一致”步骤合理+证据支持”仅 9/120（7.5%，Wilson 4.0–13.6%）；Appendix E.6：”Among 69 disagreements… a hand check of 10 found the stricter judge correct on 8”（样本极小）。
  • 为什么重要：数据集工作可信度取决于标签质量的独立验证强度。作者团队自我审核 + AI 辅助可能系统性高估质量；且最大规模审计只覆盖 80 条（占 50,228 对的 0.16%）。
  • 当前能够得出的判断：已知的三重机器审计（citation grounding 57.4% 通过；panel ALFWorld 243/323 vs solo 285/323；test-retest 已准入 88.2% vs 未准入 58.2%，gap 29.9 pp）是有价值的内部信号，但不能替代独立金标。
  • 如何验证或补强：外部标注团队对随机（非覆盖选择）样本做盲化定位与诊断接受度评估；报告分层间的盲评一致性（κ）而非 raw rate；对主张”修复正确”的记录做人工抽验。
  • 严重程度：次要问题。

6. 审稿式总评

作者发现失败 rollout 中被丢弃的”决策级信号”（改哪一步、换成什么动作）可以用受控重放检验，因此构建了 50,228 对自然失败诊断数据集 AED 与 AET 五阶段流水线，通过”收集—诊断—引用取证—可选对照重放—视图导出”实现。实验在 3,062 对同 checkpoint replay 上表明修正确实提高 verifier 通过率（18.4%→51.1%），在 943 例内部标签上表明 full-diagnosis SFT 优于所有 prompting 参照（63.6% vs 54.7%）；其中对照 replay 的干预证据与”成功重试也成功”的 discordant 分解较强，但诊断训练证据受制于标签自身的审计缺陷与公开迁移的普遍负迁移，actor 修复训练只有单种子、环境依赖的混合结果。本文最有价值的部分是近乎范例级的诚实披露——把数据集缺陷、负结果、成本口径、对照混淆全部写进正文与附录；最大的审稿风险是：最有把握的结论（replay 修正效用）覆盖的只是可恢复子集，而最显眼的数字（63.6%）衡量的是作者自己构造且自认有缺陷的标签。

  • 问题定义清晰度：中——资源缺口陈述清楚，但”缺口大小/为何致命”缺乏测量；数据集与训练用子集、replay 队列三者关系的边界是论文自己厘清的（§3.3、Table 7），读者需细读才不被 50,000 的标题数字误导。
  • 创新性证据：中——对照 replay 与证据分级是实打实的流程创新并有实验支撑；但核心诊断组件沿用 AgentDebug/AgentDebugX，训练目标均为标准 SFT/DPO，创新以数据工程与实验设计为主。
  • 方法可信度：中——pipeline 契约（引用可解析、信息可用性、泄漏检查、lineage 上限）设计审慎且有 schema 与审计支撑（Appendix D、E、T）；但训练数据无 replay 验证、标签由自建共识产生，方法正确性对外部使用者仍有依赖。
  • 实验支持力度：中——replay 与内部一致率实验有多 seed/对照/区间支撑且披露充分；公开迁移、actor 训练、DPO 均未达支持其主张的强度，论文对此的结论收束基本与证据一致。
  • 可复现性：无法确认——论文称接收后开源（数据与 checkpoint “planned after acceptance”），当前仓库、prompts、splits 与结果生成器均不可获取；教师与参照模型为闭源 API（含 2026 年各家的 Gemini/Claude/GPT 版本），标签重建依赖同一批服务。
  • 综合阅读价值：高——对做 agent 数据构建、失败分析与 error-aware post-training 的读者，本文提供了可操作的流水线契约、证据分级方案以及一整套”如何诚实报告混杂与负结果”的样板；其缺陷披露清单本身即是同类工作的检查表。
