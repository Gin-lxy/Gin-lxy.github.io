0. 一句话结论

论文针对”技能优化只能靠目标任务上昂贵的 agent rollout 迭代、而无视公开技能库中积累的程序性知识”这一问题，提出 RASO：用外部技能库做检索先验，并把检索到的内容经 Cross-Harness Adaptation 显式改写为目标任务与 harness 可用的”经验”，贯穿技能初始化（RASI，零 rollout）与迭代更新（RASU，rollout 反馈驱动检索）两个阶段。在 4 个 agent benchmark × 2 个模型（GPT-5.6-Luna、Qwen-3.5-9B）上，RASO 相对无检索的初始化与更新基线一致更好，但增益幅度差异很大（Qwen/WebShop +11.30，GPT/ALFWorld 仅 +1.49），只报告 3 个随机种子的均值±标准误、无显著性检验，且”跨 harness 适配”这一核心机制的功劳尚未与”一般性 LLM 改写/过滤”完全分离——结论应严格限定在该实验设置内。

1. 论文具体想解决什么问题？

背景与任务（领域一般问题）。 LLM 以 agent 形式运行在 execution harness 中（harness 定义可用工具、文件访问、观测接口与评分流程，§1、§3）。性能不只取决于模型参数知识，还取决于任务执行的程序性策略，即 agent skill——一种自然语言 artifact，作为 agent 的上下文指导其完成给定 harness 下的任务（§1）。因为 skill 是文本，它可以被检查、审计，并跨模型迁移而无需改权重（§1）。给定冻结的模型 M\mathcal{M}M 与固定 harness hhh，论文把技能优化形式化为：在训练集上产生候选 skill、在验证集上按期望奖励挑选、在测试集上评估（Eq. 1，§3）：s⋆=arg⁡max⁡sEx∼Dval[r(h(M,x,s))]s^{\star}=\arg\max_{s}\mathbb{E}_{x\sim\mathcal{D}_{\mathrm{val}}}[r(h(\mathcal{M},x,s))]s⋆=argmaxs​Ex∼Dval​​[r(h(M,x,s))]；唯一的决策变量是自然语言 skill sss，而且论文把”初始 skill 的构造”也纳入优化问题，不假设初始 skill 是外部给定的（§3）。

现有方法与其失败条件。 现有技能优化方法（TextGrad、GEPA、SkillOpt、WikiSkill 等）把 skill 当作文本决策变量，靠 agent 在目标任务上的 rollout 经验反复修改（§2、§5.1），并普遍以 LLM 直接生成的初始 skill（RFSI）为起点。作者指出两个问题：(1) 这需要昂贵的 rollout 迭代，且探索范围被自身 rollout 所见限制（§2 “Skill Optimization from Execution Experience”）；(2) 与此同时，公共技能库已积累”millions of publicly shared skills”（引 Destefanis et al., 2026 的 GitSkills 语料），这些跨任务、跨模型、跨 harness 的程序性知识基本没被利用（摘要、§1）。另一条线（从外部知识构造 skill，如 SkillRouter）要么在测试时对每个任务实例反复检索+适配，要么只在初始化时用外部知识、之后不再利用（§2 “Skill Construction from External Knowledge”）。

本文的新观察与支撑证据。 直接复用检索到的 skill 是有害的，因为来源任务/harness 与目标不匹配：Fig. 1（右）报告在 SpreadsheetBench 上检索到的技能 92.9% 来自不同 harness、仅 7.1% 与目标 harness 相同；Table 1 中只做检索不做适配的 SkillRouter 在多个 benchmark 上低于”No skill”（如 Qwen-3.5-9B 上 WebShop 9.42 vs 16.27、ALFWorld 31.34 vs 33.09；GPT-5.6-Luna 上 ALFWorld 55.97 vs 64.43），作者据此判断”直接复用会引入无关或不匹配的程序性知识”（§5.1）。注意：92.9% 这一分布统计只在 Fig. 1 出现，论文未说明 harness 归属如何判定（人工、元数据还是模型分类），属”有现象、无测量方法说明”。

这张图承担”问题动机 + 结果预览”两个作用：左侧两个小图解释为什么单靠 LLM 生成（缺知识）或单靠检索（缺适配）都不够，这是论文引入”检索+改写”的直接理由；右侧上图（失配分布）给出”不匹配是常态”的证据，下图提前展示了在 SpreadsheetBench 上 RASO 相对无 RAG 基线与直接检索基线的差距——它同时也是 §5 主结果的图形预告，其中 33.21 / 54.53 / 57.02 / 63.33 四根柱子与 Table 1 中 GPT-5.6-Luna 的对应行一致。

核心假设。 若把检索到的程序性知识显式改写（abstract away 源域特定指令、用目标 harness 的对象/命令/单位重述，§4.1）再注入 skill，则既能在零 rollout 下获得更好的初始 skill（RASI），又能在迭代更新中用外部知识补足仅有 rollout 反馈难以推断的空白（RASU）。需区分三层：领域早已存在的一般问题（技能优化依赖昂贵 rollout）；本文的新观察（公共技能库普遍存在 harness 不匹配、直接复用反而有害）；本文实际解决的子问题（在优化全程、用显式跨 harness 适配来利用外部技能库，且不要求语料中存在与目标匹配的 skill）。

2. 创新点是什么？

一段话概括。 真正的技术增量是把”外部技能库检索”从”初始化的直接复用或测试时逐任务检索”改造成”贯穿技能优化全程、且经过显式跨 harness/跨域改写”的知识注入：RASI 在零 rollout 下用检索+适配构造初始 skill；RASU 让失败轨迹与 textual gradient 决定检索什么，再用同一适配操作生成 lesson 参与 skill 更新（§4.1–4.3）。这是已有组件（BM25 检索、LLM 文本改写、文本梯度式 skill 优化）的新组合，加上一个明确的操作定义（Cross-Harness Adaptation 的三条原则），而非全新的学习范式，也没有任何模型权重训练。

逐项看：

  1. RASI（检索增强的零-rollout 初始化，§4.2，Eq. 3–4）。 新增机制：查询生成 agent 从任务描述 TTT 与 harness 描述 HHH 生成 requirement–query 对 {(ci,qi)}\{(c_i,q_i)\}{(ci​,qi​)}，逐 query 用 BM25 做段落级（heading 切分）检索 top-KKK，适配 agent 产出 lesson ℓi\ell_iℓi​，再由 skill-init agent 合成初始 skill s0s_0s0​。与最接近的已有方法 RFSI 的差异被作者刻意控制：附录 A.1 说明 RFSI 使用完全相同的 TTT、HHH、相同的 procedure 分解和相同的 skill-init 系统提示词，唯一区别是省略 lessons——因此 RASI−RFSI 的差距可归因于”检索并适配后的知识”，而不是流程或提示词。证据：Table 1 的 0-rollout 行里 RASI 在 4 benchmark × 2 模型上全部高于 RFSI（GPT-5.6-Luna：OfficeQA 45.74 vs 40.11、Spreadsheet 49.17 vs 44.40、ALFWorld 72.64 vs 69.40、WebShop 45.06 vs 43.89；Qwen-3.5-9B：40.50 vs 34.89、30.48 vs 27.74、47.76 vs 42.04、23.27 vs 12.54，§5.1）。移除 RASI（换成 RFSI）后，Table 2 显示 GPT-5.6-Luna 上 OfficeQA 从 49.03 降到 47.56、Spreadsheet 从 63.33 降到 61.07（RASI→RFSI，保留 RASU）。
  2. RASU（由执行反馈引导的检索式更新，§4.3，Eq. 5–6）。 新增机制：对失败轨迹按 chunk=8 生成 (textual gradient δi\delta_iδi​, retrieval query qiq_iqi​) 对（与 SkillOpt 相同的 chunk 设计），检索并适配出 lesson 集合，与 δi\delta_iδi​、当前 skill sts_tst​ 一起交给 skill-updater 生成候选 st+1s_{t+1}st+1​；只有验证集上不降才接受。与 TextGrad/GEPA 的区别是：它们的反馈只来自模型参数知识，RASU 的更新额外被外部检索知识 grounded。证据：Table 4（固定 RASI 初始化）中 RASU 在 OfficeQA 49.03、Spreadsheet 63.33，高于 SkillOpt（46.51 / 60.24）与 WikiSkill（47.09 / 55.00）等；附录 Table 6–8 在四种”初始化×模型”组合下 RASU 均为最优（§A.4）。
  3. Cross-Harness Adaptation（共享的适配操作，§4.1，Eq. 2）。 新增机制：适配 agent 以需求 cic_ici​、任务 TTT、harness HHH、检索段落 Sqi\mathcal{S}_{q_i}Sqi​​ 为输入，产出”聚焦单一需求、可执行的 lesson”，三条原则为：去除源域专有名词、省略目标 harness 中无对应物的步骤、只有被 HHH 佐证时才保留关于工具/参数行为的具体声明（§4.1）。证据是 Table 3 的消融：去掉适配（检索内容直接拼接）后，RASI 在 OfficeQA 从 45.74 降到 41.86、Spreadsheet 从 49.17 降到 41.43；RASU 从 49.03 降到 46.70、63.33 降到 57.86（GPT-5.6-Luna）。
  4. 原创边界。 检索增强、技能路由与检索（SkillRouter 及一系列 skill-retrieval 工作）、把外部经验适配到目标接口（Tang et al., 2025）都已有先例（§2）。作者声称”在优化全程利用外部语料、且用 Cross-Harness Adaptation 支持初始化与更新”这一点此前 largely unexplored（§1）。根据本文 related work 与实验对比，只能确认作者声称的差异；是否构成首次提出、以及”跨 harness”与”跨域”适配在文献中的区分是否成立，还需要更完整的文献检索（按规范，此为无法确认项）。

3. 作者如何解决？

直觉。 公开技能里真正可迁移的是”程序结构”而不是表面词汇：例如某技能里”若一组数据没有满足条件的行，跳过该组、输出留空”这一规则，可以迁移到电子表格任务；但技能原文用的是卫星影像、NDVI、numpy/raster array 等目标环境不存在的对象（Fig. 5）。直接拼接检索内容会把源域假设与不可用的工具引用带进来（SkillRouter 因此表现不佳，§5.1），所以论文在”检索”与”注入”之间插入一个显式的改写步骤——Cross-Harness Adaptation，把知识重述为目标任务与 harness 的对象、命令与单位（§4.1）。

  • 输入：任务描述 TTT 与 harness 描述 HHH（两阶段共用）；（RASU 另加）当前 skill sts_tst​ 与 training 任务上的 rollout 轨迹。
  • RASI 四个步骤（Fig. 2 上排）：(1) query 生成——Aquery_init(T,H)\mathcal{A}_{\mathrm{query\_init}}(T,H)Aquery_init​(T,H) 产出 MMM 个 requirement–query 对（Eq. 3），每个 cic_ici​ 是一个具体任务步骤或 harness 约束（论文举例”multi-turn budget management”），qiq_iqi​ 是为它构造的检索 query；(2) 段落级检索——先用 heading 把技能文档切成段落级语料 C\mathcal{C}C，再对每个 qiq_iqi​ 用 BM25（Robertson & Zaragoza, 2009）取 top-KKK 段 Sqi\mathcal{S}_{q_i}Sqi​​（§4.1）；论文明确说段落级而非整文档检索是为了提高信噪比、避免偏好”整体目标相似”的文档（§4.1）；(3) Cross-Harness Adaptation——ℓi=Aadaptation(ci,T,H,Sqi)\ell_i=\mathcal{A}_{\mathrm{adaptation}}(c_i,T,H,\mathcal{S}_{q_i})ℓi​=Aadaptation​(ci​,T,H,Sqi​​)（Eq. 2），输出聚焦 cic_ici​ 的可执行 lesson；(4) skill 初始化——Askill_init\mathcal{A}_{\mathrm{skill\_init}}Askill_init​ 把 TTT、HHH、{ci}\{c_i\}{ci​} 与 lessons Linit\mathcal{L}_{\mathrm{init}}Linit​ 合成初始 skill s0s_0s0​（Eq. 4），每个 lesson 被整合进对应执行步骤。
  • RASU 四个步骤（Fig. 2 下排）：从 s0=sts_0=s_ts0​=st​ 出发，在 Dtrain\mathcal{D}_{\mathrm{train}}Dtrain​ 上采样 minibatch（40 任务）执行 rollout；Aquery_update\mathcal{A}_{\mathrm{query\_update}}Aquery_update​ 分析失败轨迹，识别 failure mode，为每个 failure mode 生成 textual gradient δi\delta_iδi​（基于参数知识）和针对性检索 query qiq_iqi​（Eq. 5）；随后复用同一检索-适配流水线得到 lessons Lupdate\mathcal{L}_{\mathrm{update}}Lupdate​；Askill_update(st,{δi},Lupdate)\mathcal{A}_{\mathrm{skill\_update}}(s_t,\{\delta_i\},\mathcal{L}_{\mathrm{update}})Askill_update​(st​,{δi​},Lupdate​) 生成候选 st+1s_{t+1}st+1​（Eq. 6）；候选只在验证集不劣于 sts_tst​ 时才被接受（”accept only if it outperforms”，§4.3），并进入下一轮 rollout。这里的”模型决定 vs 固定流程”分工是：query 内容、failure mode、lesson 文本、skill 修改全部由 LLM agent 生成；而检索（BM25、top-KKK）、接受/拒绝判据、chunk 划分、迭代次数是固定流程。
  • 是否训练：全程不训练任何模型权重——M\mathcal{M}M 与 hhh 固定，唯一被优化的是文本 skill（training-based 的只是”文本优化循环”）。推理阶段的变化就是：把优化出的 skill.md 作为 agent 上下文注入。
  • 输出：一份 markdown 形式的 skill（Fig. 2 中的 skill.md），部署时作为目标 agent 的上下文。

关键设计假设（§4.1）：适配的三条原则假设”检索内容中可迁移的是程序结构，而具体的工具/参数声明可能不可靠，需要 harness 描述佐证”；以及假设目标 harness 中的一切可用信息都已被压缩进 HHH（由 codex 读 benchmark harness 代码一次性生成，附录 A.1）。

论文提出的组件 vs 直接使用的现有工具：RASO 提出的是 RASI/RASU 流程与 Cross-Harness Adaptation 操作；直接使用的是 BM25 检索器、GitSkills 外部语料、Qwen-3.5-9B / GPT-5.6-Luna 作为 target 与 optimizer 模型（同一模型兼任两角色）、vLLM 部署、以及作为对照复用其算法的 TextGrad/GEPA/SkillOpt/WikiSkill（附录 A.2）。

4. 解决得怎么样？

4.1 实验设置

  • 任务与数据：4 个 agent benchmark——OfficeQA（企业文档上的数值推理问答，246 题全用，50/24/172 划分）、SpreadsheetBench（真实电子表格操作，400 任务，80/40/280）、ALFWorld（文本具身家务，39/18 训练验证、134 个 OOD 评估游戏）、WebShop（模拟电商，80/40 训练验证、500 测试指令）（附录 A.3、Table 5）。train/val/test 划分沿用 SkillOpt，所有方法共用同一划分与同一验证集（附录 A.3）。
  • 模型与语料：target 与 optimizer 默认同一模型：GPT-5.6-Luna 与 Qwen-3.5-9B；外部语料为 GitSkills（Destefanis et al., 2026），并为每个 benchmark 做关键词、仓库级 blocklist 后建索引（附录 A.1）；TTT、HHH 由 coding agent（codex）读 harness 代码一次性生成、不接触测试实例、对所有方法与种子固定（附录 A.1）。
  • 对比基线：初始化侧为 No skill、SkillRouter（直接检索复用）、RFSI（无检索，流程与 RASI 完全对齐）；更新侧为 TextGrad、GEPA、SkillOpt、WikiSkill，全部从 RFSI 技能出发且不使用外部语料（§5.1、附录 A.2）。
  • 指标与预算：benchmark 原生奖励/成功率；3 个随机种子、报均值±标准误；所有更新方法 2 epochs、minibatch 40、top-KKK=5、chunk=8（附录 A.1）；成本与 rollout 数在 Table 9/10 对齐比较。
  • 各组实验回答什么：Table 1 回答”整体是否更好”；Table 2/3 回答组件与适配的贡献；Table 4 与附录 Table 6–8 固定初始化隔离”更新方法”；Fig. 3/4 回答检索量与语料规模的影响；Table 9/10 回答成本与预算公平性。

4.2 关键结果

以下数字均为表列均值±标准误（3 seeds），位置见 Table 1（§5.1）。

  • RASI vs RFSI（0 rollout，GPT-5.6-Luna）：OfficeQA 45.74±1.40 vs 40.11±0.58（+5.63）、Spreadsheet 49.17±1.52 vs 44.40±2.74（+4.77）、ALFWorld 72.64±1.63 vs 69.40±1.55（+3.24）、WebShop 45.06±0.40 vs 43.89±1.17（+1.17）。Qwen-3.5-9B：40.50±0.97 vs 34.89±2.93（+5.61）、30.48±0.78 vs 27.74±2.56（+2.74）、47.76±3.53 vs 42.04±2.87（+5.72）、23.27±0.98 vs 12.54±2.56（+10.73）。
  • RASO vs 最强竞争方法（Table 1，完整系统对比）：GPT-5.6-Luna 上 OfficeQA 49.03±1.85 vs 45.54（SkillOpt，+3.49）、Spreadsheet 63.33±2.69 vs 57.02（SkillOpt，+6.31）、ALFWorld 74.13±1.00 vs 72.64（SkillOpt，+1.49）、WebShop 46.61±0.11 vs 45.54（GEPA，+1.07）；Qwen-3.5-9B 上 42.25±1.52 vs 37.40（WikiSkill，+4.85）、31.55±0.31 vs 29.76（WikiSkill，+1.79）、51.00±2.45 vs 43.53（GEPA，+7.47）、24.73±0.41 vs 13.43（WikiSkill，+11.30）。
  • 提升小或无提升之处：GPT-5.6-Luna 的 ALFWorld（+1.49，双方 SE≈0.9–1.0，差异不到 2 倍 SE 量级）与 WebShop（+1.07，虽 RASO 的 SE 仅 0.11 但绝对差距小）属于弱增益；Table 2 中 RFSI+RASU（47.56±1.85）与 RASI+RFSU（45.93±1.58）在 OfficeQA 上不可区分，说明”仅换一个组件”的收益部分在噪声范围。
  • 负面结果（基线侧）：SkillRouter 在 Qwen-3.5-9B 上低于 No skill 多个 benchmark（WebShop 9.42±0.47 vs 16.27±0.25；ALFWorld 31.34±1.29 vs 33.09±0.66；Spreadsheet 23.45±0.48 vs 28.81±0.60）；TextGrad/GEPA 在 Qwen-3.5-9B 上把 RFSI 初始技能改差（Spreadsheet：25.95±0.63、24.05±1.56 vs 初始 27.74±2.56；附录 Table 7）；在 RASI 初始下，Qwen 上 TextGrad/GEPA/WikiSkill 甚至低于初始技能（38.76、38.18、40.12 vs 40.50；SkillOpt 仅 +0.20；TextGrad/WikiSkill 在 Spreadsheet 上因验证集无改进而原样返回初始技能）（附录 A.4、Table 6）。
  • 消融：Table 2 显示两组件互补（GPT-5.6-Luna，OfficeQA：RFSI+RFSU 40.70±1.67 → RASI+RASU 49.03±1.85；Spreadsheet：51.67±2.03 → 63.33±2.69）；Table 3 显示去掉 adaptation 后 RASI 41.86±1.53 / 41.43±2.83，RASU 46.70±2.05 / 57.86±2.92（均低于带 adaptation 版本）。
  • 敏感性：Fig. 3 显示 KKK 从 1 增到 5 时性能上升、KKK=10 略降（RASI 与 RASU 均如此，故选 KKK=5）；Fig. 4 显示只用 1% 语料就已超过无检索虚线（0%），语料增大总体继续改善、SpreadsheetBench 增益最大。
  • 方差/显著性：只报告 3 seeds 的均值±标准误，无置信区间、配对检验或显著性检验；论文未报告失败案例统计或错误分析。

此图把”检索多少”这一超参的取舍可视化：横轴 KKK、纵轴性能，蓝线 RASI、红线 RASU（后者以带适配的 RASI 为初始）。它解释了为何默认 KKK=5：知识覆盖与检索噪声的平衡；论文还据此指出 RASU 从多条相关段落中获得的收益比 RASI 更明显（”The gains are particularly pronounced for RASU”，§5.2），即迭代更新阶段更依赖检索到的外部知识。

4.3 机制证据

  • “有效”层面的证据较强：跨 4 benchmark、2 模型、3 种子的主结果 + 组件消融（Table 2）+ 适配消融（Table 3）+ 超参敏感性（Fig. 3/4）+ 固定初始化的更新方法对比（Table 4、附表 Table 6–8）+ 成本/预算对齐（Table 9/10），实验网撒得比较全。
  • “为什么有效”层面只有间接证据：Table 3 证明”有适配步骤 > 无适配步骤”，但没有证明功劳来自”跨 harness”这一维度——消融后的对照是”把检索内容直接交给 LLM”，它同时改变了改写程度与信息量，无法区分”跨 harness 翻译”与”一般的 LLM 摘要/过滤/去噪”。论文也没有对 lesson 的迁移正确率、失效比例做定量分析；Fig. 5 是单个 anecdote；92.9%/7.1% 的不匹配分布没有说明判定方法（§4.2 前的 Fig. 1 仅给结论）。
  • 替代解释排除程度：RASO 与竞争的对比中，RASO 从 RASI 出发而竞争者从 RFSI 出发（Table 1），这一”不公平”已被 Table 4/6–8 的固定初始化实验部分控制；rollout 数上与 TextGrad/WikiSkill 相同（Table 10），API 成本对齐（Table 9），所以”更多预算”不是主要解释。但 RASI/RASU 比 RFSI/RFSU 多消耗检索-适配的 LLM 调用（查询生成、逐 lesson 适配），论文没有单独报告这部分调用量与耗时，因此”更多 LLM 计算 vs 知识本身”的贡献无法完全分离。

4.4 成本与适用范围

  • 论文报告的成本：Table 9 给出 GPT-5.6-Luna 的完整优化 API 成本，RASO 在 4 个 benchmark 中 3 个最低（OfficeQA $0.84、ALFWorld $0.79、WebShop $10.28），SpreadsheetBench $0.49 距最低（WikiSkill $0.43）$0.06；同预算下比 TextGrad 降低 42–75%（WebShop：$10.28 vs $41.03）（附录 A.5）。rollout 数（Table 10，不含测试评估）：RASO 196/320/114/360，与 TextGrad、WikiSkill 相同，少于 GEPA（272/360/174/370）与 SkillOpt（236/360/154/400）。Qwen 侧用单张 RTX A6000 + vLLM 服务（附录 A.1）。
  • 论文未报告：RASI 一次性（零 rollout）阶段的 LLM 调用次数与单独成本；检索索引与 blocklist 构建成本；端到端推理延迟；被 blocklist 排除的仓库数量与关键词表；提示词全文与 TTT/HHH 原文；失败案例/失败率统计。论文没有 Limitations 章节。
  • 适用范围边界：结论适用于”冻结模型 + 固定文本 harness + 可用外部技能语料（GitSkills）”的 4 类文本型任务（文档问答、电子表格、具身文本、网页导航）与 2 个特定模型；是否迁移到多模态、工具调用型代码任务、其它语料或更大模型未验证（论文未报告）。得到改善的是初始终点质量与 rollout 效率；仍未解决的是机制层面的”哪种改写真正起作用”、跨 harness 失配程度的量化，以及语料质量/噪声对方法的影响。

5. 最容易受到审稿人质疑的地方

质疑：语料泄漏风险只靠关键词 blocklist 缓解，且缓解效果不可验证

  • 原文依据：附录 A.1 承认外部语料”may contain skills written specifically for our evaluation benchmarks”，做法是按 benchmark 名与其数据集名做关键词匹配、命中即整仓库排除；但论文未报告排除了多少仓库、用了哪些关键词、也未对最终检索命中内容与测试集做任何重叠审计（全文无此实验）。
  • 为什么重要：GitSkills 来自公开 GitHub，4 个 benchmark 都是知名公开评测集；若残留 benchmark 专属技能，RASI/RASU 的部分增益可能来自对测试程序的间接记忆而非”跨 harness 迁移能力”，直接影响创新性与结论有效性。
  • 当前能够得出的判断：作者意识到了问题并做了保守化处理（仓库级排除），但缓解效果无法从论文材料确认；这是不可验证的风险，不是已证实的泄漏。
  • 如何验证或补强：公开 blocklist 与排除统计；对被检索命中的段落做人工/自动的 benchmark 专属内容审计；补一个”完全在语料构建时由人工剔除过所有 Excel/网页/家务相关技能的语料”子集实验。
  • 严重程度：主要问题。

质疑：Cross-Harness Adaptation 的消融不能隔离”跨 harness 适配”这一机制

  • 原文依据：Table 3 的 × 版本是”去掉适配、检索内容直接注入”，同时改变了改写方式与信息量；而唯一”只检索不生成”的基线 SkillRouter 又换了检索器（bi-encoder + cross-encoder 的文档级两阶段检索，附录 A.2），与 RASI 的 BM25 段落级检索不同（§4.1）。因此论文没有干净的”同检索器、检索内容直接复用”基线点。§4.1 的三条适配原则也只是提示词层面的指导，无独立验证。
  • 为什么重要：论文标题与核心贡献就是”cross-harness adaptation”；若增益主要来自”LLM 对检索内容做一般性摘要/过滤”（与 harness 无关），则贡献描述需要弱化，机制主张与实验证据之间存在缺口。
  • 当前能够得出的判断：证据支持”检索 + LLM 改写 > 无检索”（Table 3 两侧一致），但不足以支持”区分跨域/跨 harness 两种失配并分别处理”这一更强主张；92.9% 的不匹配统计也没有给出测量方法，无法判断”harness 失配”这一维度的操作化是否成立。
  • 如何验证或补强：加入”BM25 段落级检索直接拼接”的中间基线；控制输入信息量做”通用改写 vs 跨 harness 改写”对照；让适配 agent 显式报告每条 lesson 被改写的对象/工具映射，并统计映射正确率；补充 harness 归属的标注方法说明。
  • 严重程度：主要问题。

质疑：”consistently outperforms”的统计基础偏弱

  • 原文依据：摘要与 §5.1 使用 “consistently outperforms” 的措辞；GPT-5.6-Luna 的 ALFWorld 增益 +1.49（74.13±1.00 vs 72.64±0.90）与 WebShop +1.07（46.61±0.11 vs 45.54±0.35）幅度小；Table 2 中 RFSI+RASU 47.56±1.85 与 RASI+RFSU 45.93±1.58 在 OfficeQA 上重叠。全文仅 3 seeds、无置信区间、无配对/显著性检验（Table 1–10 及附录均无）。
  • 为什么重要：工程型方法论文的”一致更好”若建立在个别接近噪声的对比上，结论强度会被削弱；也可能掩盖任务间差异（4×2 中至少 2 处弱增益）。
  • 当前能够得出的判断：按表列 SE 做近似推算（差异 SE ≈ √(SE₁²+SE₂²)，分析者估算、论文未做检验），8 个 RASO 主对比中只有 GPT/WebShop（+1.07 vs 合并 SE≈0.37）、Qwen/ALFWorld（+7.47 vs ≈3.16）、Qwen/WebShop（+11.30 vs ≈2.05）三处超过 2 倍合并 SE，其余多处增益在约 1–1.5 倍量级；”consistently”（8/8 组合方向一致）本身是可报告的观察，但单点幅度多数尚未与噪声强分离，该措辞略超出证据。这是表述与统计报告的局限，而非结果错误。
  • 如何验证或补强：增加种子数（≥5）、报告配对 bootstrap 置信区间与显著性、对每 benchmark 的多次运行做检验。
  • 严重程度：次要问题。

质疑：问题动机中的关键统计（92.9%）与”域失配 vs harness 失配”的区分缺乏方法学

  • 原文依据：Fig. 1 报告 SpreadsheetBench 上 92.9% 检索技能来自不同 harness，但全文（含附录 A.1–A.5）没有任何计算该比例的说明——harness 身份如何判定（语料元数据？人工标注？模型分类？）不可知；§4.1 声称同时处理 domain 与 harness 两种 mismatch，但没有任何实验把两者分开度量或分开消融。
  • 为什么重要：这是论文立论（”不匹配是常态、所以需要适配”）的核心证据，也是”跨 harness”与”跨域”两个概念边界的来源；缺乏方法说明则无法判断该统计的可复制性与概念有效性。
  • 当前能够得出的判断：当前材料无法确认该数字的测量口径；只能将其视为作者报告的观察，不能当作已独立验证的事实。
  • 如何验证或补强：给出语料中每个技能的 harness/domain 标注流程与一致性统计；补充分别针对 domain-match/harness-mismatch、harness-match/domain-mismatch 等四种组合的分层实验。
  • 严重程度：次要问题。

质疑：复现与成本披露不完整

  • 原文依据：论文未提供代码/项目页；提示词、TTT/HHH 原文、blocklist 关键词均未公开（附录仅描述流程）；RASI 的一次性 LLM 调用成本未单列（Table 9 只有全流程成本）；无 Limitations 章节，失败率未报告。
  • 为什么重要：影响可复现性与成本判断——RASI 宣称 “without requiring agent rollouts”，但仍需多次 LLM 调用（查询生成、逐 lesson 适配、初始化），读者无法判断它相对 RFSI 的额外推理开销。
  • 当前能够得出的判断：方法超参（2 epochs、minibatch 40、K=5、chunk 8、温度、vLLM/RTX A6000）报告较完整，但复现所需文本资产缺失，复现性只能评为”中”。
  • 如何验证或补强：开源提示词与 TTT/HHH、报告 RASI 的调用次数与 token 成本、补充失败模式分析。
  • 严重程度：次要问题。

6. 审稿式总评

作者发现公共技能库虽已积累规模可观的程序性知识，但现有技能优化方法只靠目标任务的 rollout 迭代、且直接复用检索结果会因任务与 harness 失配而失效，因此提出 RASO——用 BM25 段落级检索加显式的 Cross-Harness Adaptation，把外部程序知识贯穿到零 rollout 的初始化（RASI）与失败驱动的迭代更新（RASU）中。实验在 4 个 agent benchmark、2 个模型（GPT-5.6-Luna / Qwen-3.5-9B）、3 seeds 上表明 RASO 一致优于无检索的初始化与更新基线，且成本不高于甚至低于对比方法；其中”检索+改写优于纯检索或纯自生成”的方向一致性较可靠（RASI>RFSI、RASO>各基线在 8/8 个 benchmark×模型组合上同向，Table 1、Table 2/3、Fig. 3/4；但单点幅度多与 1–2 倍合并标准误同量级，显著性未建立），但”跨 harness 适配是增益来源”这一核心机制尚缺少可与”一般性 LLM 改写”分离的对照，语料泄漏缓解不可验证、统计检验缺失也削弱了”consistently”的强度。本文最有价值的部分是把”技能库复用”形式化为贯穿优化全程的检索-适配流水线，并给出干净的 RFSI 对齐对照；最大的审稿风险是外部语料与评测集的潜在重叠无法审计，以及机制归因实验不够隔离。

  • 问题定义清晰度：强——技能优化被形式化为固定模型与 harness 下的文本决策问题（Eq. 1，§3），且把”初始 skill 构造”纳入问题、用 RFSI 对齐对照隔离检索贡献（附录 A.1）。
  • 创新性证据：中——检索增强+适配是已有组件的新组合（§2 与 SkillRouter、Tang et al. 2025 对比），作者声称的”贯穿两阶段”差异只能确认其主张；跨 harness 适配的有效性证据（Table 3）未与一般改写分离。
  • 方法可信度：中——流程、超参、预算对齐报告完整（§4、附录 A.1、Table 9/10），但提示词与 TTT/HHH 未公开、适配原则不可验证、92.9% 统计无方法说明。
  • 实验支持力度：中——覆盖 4 任务×2 模型×3 种子、多种消融与成本表，设计较全面；但无显著性检验、个别对比弱增益、机制证据多为间接、无失败案例。
  • 可复现性：中——超参与流程细节可跟；关键文本资产（提示词、T/H、blocklist）与代码未提供，语料泄漏缓解不可核查。
  • 综合阅读价值：中——对关注 agent skill 库、跨环境知识迁移与 RAG-for-agents 方向的学生与研究者，是一份结构清楚、对照设计（RFSI 对齐、固定初始化更新对比、成本对齐）值得借鉴的系统性实验；但机制新颖度有限、审稿风险明确，宜作为方向参考而非定论证据。
