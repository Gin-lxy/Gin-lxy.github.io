0. 一句话结论

GraphForge 解决”工作型 agent（working agent）训练数据难以合成”的问题：用 O*NET 职业化种子固定任务方向，在检索到的真实文件上构建证据图，把任务陈述与评分规则（rubric）都编译为带文件锚点的可验证规格，再经教师试跑、一步修订、交付物与 rubric 评审筛选训练轨迹。在论文报告的三个基准上——GDPVal-AA 的 220 任务子集、Workspace-Bench-Lite、SpreadsheetBench II——用 2,169 条合成轨迹微调 Qwen3.6-27B 相对其基座分别提升 +65.7 Elo（OpenHands）、+7.7、+13.7。结论边界：证据支持”该语料在论文固定的 scaffold 配置与这两个同家族基座上优于各自基座”，不足以确认增益来自”证据图锚定”这一核心机制（与从更强教师 GLM-5.2 蒸馏混淆），RFT 阶段的进一步收益在统计上未被分辨（Appendix D：全部差值区间含 0）。

1. 论文具体想解决什么问题？

背景与任务。 工作型 agent（如论文提到的 OpenClaw、Hermes-Agent）被期待成为持久数字助手，在文件系统、数据库、终端上完成长程任务并产出可交付成果（deliverable），已有 Claw-Eval、GDPVal、Workspace-Bench 等基准。训练这类 agent 的通用做法是在强教师模型合成的轨迹上做监督微调（§1），但前提是存在”建立在大量真实文件之上、结果可验证”的任务数据。

现有方法怎么做。 论文点名两条最接近的合成管线（§1，Table 1）：EnvCraft（Zeng et al., 2026）用模型生成文件、用 Python 脚本对 workspace 状态做检查——脚本读不了文件内容，可能漏掉文档类交付物中的错误；NexForge（Zhao et al., 2026）在真实文件上造任务，但没有任务级 rubric 或 verifier，结果质量无法系统检查。Table 1 的定性对比显示：EnvCraft 20K 任务（合成 workspace、state-check 脚本），NexForge 5.6K 任务（真实文件、无验证），GraphForge 2.1K 任务（真实文件、evidence-anchored agent judge）。

通用问题 vs 本文子问题。 “agent 训练数据合成”是领域既有问题；本文的新观察是两条具体瓶颈：(1) 验证侧——状态检查脚本无法验证文档内容，真实文件任务缺 rubric 导致质量失控；(2) 构造侧——作者断言”让模型自由发明任务会向高频职业与通用任务类型塌缩”（§3.1），因此提出”种子与文件分工”：种子（O*NET 职业+官方 Detailed Work Activities）只固定任务方向以控制多样性，具体任务与验证标准则在真实 workspace 落地后从文件派生。

需要注意的论证强度。 “模型自由发明任务会塌缩”是全文多样性的核心动机，但论文没有给出对塌缩现象本身的实证测量（无对照的生成实验或统计），它只是设计论断；同样，”状态检查脚本会漏错”也未做实验验证，属于对 EnvCraft 的定性批评。论文实际解决的是”在真实文件上同时获得可控多样性与任务级可验证性”这一子问题，其验证方式是端到端训练效果（§4）。

核心假设。 把任务要求与验证标准都锚定到真实文件的证据图上，能合成出可执行、可验证、能训练出跨 scaffold 与跨职业可迁移的工作技能的数据。这一假设的验证证据是：三基准增益 + 污染审计（增益不集中在被覆盖职业）+ judge 敏感性探测（§4.5）。

2. 创新点是什么？

一段话概括。 GraphForge 的技术增量是：把”证据图”作为任务与验证之间的中间表示——先在实际抓取的真实文件（带隐藏文件角色）上让模型建图，再从图编译出任务陈述 q_i 与逐条 rubric 标准 c_k，每条标准携带锚点文件集合 A_k 与验证程序 φ_k；工作 agent 只看任务与文件，判分器看锚点与验证指令，二者分离。配套的流程创新是执行条件的一步修订（教师先跑一遍，修订 agent 对着原文件和这次执行修任务/rubric）与交付物级准入（确定性检查 + 加权 rubric 评分 Q>0.90）。训练层面，同一套锚定 rubric 还被复用于 RFT 的 best-of-4 选择，并用”去掉锚点的 judge”与”随机选一条”两个对照臂来论证选择信号的价值。相对 EnvCraft/NexForge，这是”真实文件 + 任务级 LLM 判分”的组合路线，规模更小（2.1K vs 20K/5.6K 任务）。

逐项分析：

  1. O*NET/DWA 受控种子与覆盖度贪心选择（§3.1）。 种子是六元组 s_i=(o_i, a_i, w_i, p_i, u_i, e^occ_i)：职业、DWA 任务类型、经证据支持的工作需求、16 类执行模式之一、预期输入文件家族、职业证据。数字：过滤后剩 246 个职业、16 个 sector、43 个 sub-sector、891 个 DWA 任务类型、3,419 个合法”职业–任务类型”对。选择用边际覆盖增益（未编号公式）Δ(s|S)=Σ_{d∈D} 1/(1+n_d(v_d(s)))，对维度 (o,a,p,u) 贪心取增益最大者，平局用任务 ID 哈希打破，文件下载落地后再按实际输入/输出家族重跑一次。性质：已有组件（O*NET、AI4Work 的 DIGITAL 注解）加新组合（覆盖度贪心 + 落地后重平衡）。对应问题：多样性控制。证据：Fig. 2(a) 显示 164/256 个 sector–pattern 组合被实现；但分布不均（data analysis and reporting 14.2%、research and source synthesis 13.2%，其余模式均 <9%）——多样性是部分的。移除会怎样：论文未报告（无”随机构造任务”对照臂）。

  2. 真实文件 workspace 与隐藏文件角色（§3.2）。 搜索 agent 为一个 case-neutral 种子找公开案例、抓取所需真实文件（原生格式、格式特定工具解析、去重），给每个文件一个隐藏角色 ρ(f)∈{core, supporting, confuser, ambient}——confuser 是”貌似相关但不可用”的备选，ambient 提供真实冗余；角色从不展示给工作 agent，文件可以跨组织混合。对应问题：真实性与干扰鲁棒性。证据：Fig. 2(b) 输入家族分布（PDF 出现在 96.7% 轨迹中，每任务平均 23.1 个输入文件）；无消融证明 role 设计的必要性。

  3. 证据图与可验证 rubric（§3.3，核心创新）。 图 G_i=(V_i,E_i)：节点记录来源文件+其提供的字段/事实+任务中的角色；边记录”解读/比较/对账/推导所需的跨文件依赖”。作者明确定位：”图不是真值，而是中间表示，其断言必须能从原文件恢复”。图编译为任务规格 C_i=(q_i, D_i, R_i^+, R_i^-; G_i)，每条正标准 c_k=(d_k, r_k, z_k, w_k, A_k, φ_k)，A_k⊆V_i，φ_k 是验证程序；负标准只在违规被直接证实时才扣分。与最接近方法的差异：EnvCraft 的脚本检查无法读文档内容；NexForge 无 rubric；GraphForge 把”判分要看的文件”与”怎么查”显式绑定到图节点。关键设计：执行与验证分离——agent 只见 q_i 和 W_i，judge 才见锚点与 φ_k，锚点不向任务陈述泄漏解题程序。不可替代性证据：论文只在 RFT 选择阶段部分探测（去掉锚点与 φ_k 的 unanchored judge 臂）。

  4. 执行条件一步修订（§3.4）。 静态检查抓不住长程任务的歧义，因此先用教师 π_T（GLM-5.2）跑一次得到 τ_i^0 与交付物，修订 agent 接收原文件、证据图、完整任务与 rubric、以及这次执行，检查任务是否自然可执行、数量是否被文件支持、每条标准锚定是否正确、验证指令是否足以检查产物；修订 agent 只返回需要改的组件，编译器保留未触碰字段并校验引用/schema。重跑条件是任务陈述归一化哈希 H(q) 是否变化：τ_i = τ_i^0（哈希未变且 τ_i^0 存在），否则 π_T(W_i, q_i^1)。证据：构造漏斗（Table 4b）显示 81.6%（2,967/3,638）的任务初始 rollout 被直接复用。

  5. 交付物级准入与轨迹清洗（§3.5）。 准入先做确定性检查（必需文件名、可读格式、表格的 sheet 与公式、任务特定结构约束），再由 judge 逐条评分：每个正标准贡献 权重×满足比例，每个负标准贡献按已证实违规程度的惩罚（准入阶段违规取 0/1），总分 Q_i(τ)=[Σ_{k∈R_i^+} w^+{ik}a{ik}(τ) − Σ_{j∈R_i^-} λ_{ij}v_{ij}(τ)] / Σ_{k∈R_i^+} w^+_{ik}（未编号公式；作者注明分数可低于 0、按原值使用）。另有行为过滤：反复的非 polling 调用、工具滥用、高工具失败率、反复截断的轨迹被丢弃。

  6. Rubric 引导的拒绝微调（RFT，§4.2/§4.4）。 对 2,000 条新合成查询（每执行模式 125 条）用 SFT 模型采样 K=4 条轨迹，锚定 judge 对同查询 4 个候选联合打分，取分数 >0.95 的最佳有效轨迹并过行为过滤，得 462 条；对照臂为 unanchored（judge 只看 rubric 文本、无显式锚点与验证指令）与 random-of-4（随机选一条），三臂共享查询 ID、候选池与优化预算。证据：random 臂在三基准上整体最差，支持”选择质量重要”；但”锚定优于不锚定”只在 Workspace-Bench-Lite 与 SpreadsheetBench II 上成立，GDPVal 上 unanchored 点估计更高（+34.1/+25.3 vs 锚定的 +7.2/+11.0），且全部差值区间含 0（Appendix D）。

原创边界说明。 根据本文 related work 与实验对比，只能确认作者声称的差异（对上 EnvCraft 与 NexForge 的两点缺口）；”证据图锚定”是否构成首次提出，需要更完整的文献检索。与更大基础模型、换数据集/指标、无对照的模块堆叠无关——本文创新落点在数据构造与验证流程，但其相对于”同教师、更简单管线”的不可替代性未被实验隔离（见 §5 质疑 1）。

3. 作者如何解决？

直觉。 合成训练数据质量难控的根因是”任务要求”与”验证标准”谁说了算：如果任务与判分标准都是凭空写的，就很难保证任务可执行、标准可核查。GraphForge 的做法是先让人能对得上账的东西（真实文件的图）存在，再让任务和标准都从它派生——每条评分标准都指着具体文件的节点，判分器拿着这些文件与检查指令去检查交付物。

实际运行流程（五个阶段 + 两阶段训练）：

  1. 输入：O*NET 数据库（现有公开资源，含职业、任务陈述、DWA 受控词表与官方任务→DWA 映射）；只保留被 AI4Work 标注为 DIGITAL 的任务，再按职业×DWA 组合成种子，用覆盖度贪心选出一批种子（§3.1，见 §2 第 1 条公式）。
  2. Workspace 物化：搜索 agent（GLM-5.2）为种子找相干公开案例并抓真实文件，native 格式解析、去重、剔除无效文件；给每个文件打隐藏角色（core/supporting/confuser/ambient），角色不进入任务（§3.2）。
  3. 证据图→任务规格：模型在文件上构建 G_i=(V_i,E_i)，再编译出 q_i、交付物要求 D_i、正/负标准集合（含锚点与验证程序）。这一步由模型完成，但输出受 schema/引用校验约束（§3.3）。
  4. 执行条件一步修订：教师模型跑一次初始任务，修订 agent 对着原文件与执行结果修补任务与 rubric；只有任务陈述变了才重跑教师，否则复用初次执行（§3.4）。模型决定：修订哪些字段；固定流程：哈希判定是否重跑、引用/一致性校验。
  5. 准入与清洗：确定性交付物检查 + judge 逐条评分（Q>0.90）+ 行为过滤，得到 2,169 条 SFT 轨迹（§3.5，§4.1）。
  6. 训练：SFT（Qwen3.6-27B 与 35B-A3B，同一语料与配方：3 epochs、Muon、峰值学习率 2×10⁻⁵、全局 batch 8、packing 上限 262,144 token，保留完整 assistant 推理与工具交互历史，超长样本剔除不截断）→ RFT（从同一 35B SFT 检查点分三臂，1 epoch、峰值学习率 1×10⁻⁶，每臂 462 条）（Appendix A，Table 5）。
  7. 推理阶段的变化：部署时模型在固定配置的 scaffold（OpenHands / Codex / Claude Code）中以固定 workspace 接口按 pass@1 运行（§4.2）；输出：workspace 内材料化的交付物文件（文档、表格等）。评测用内部 Elo 池：每个 (model, scaffold) 是独立节点，Bradley–Terry 拟合，Eq. (1)：Pr(i≻j)=σ(θ_i−θ_j)，Elo_i=1667+(400/ln10)(θ_i−θ_anchor)，锚点为 GLM-5.3 (OpenHands)=1667。

论文提出的组件 vs 直接使用的现有工具。 提出的：种子选择、角色标注、证据图编译、一步修订、准入评分、RFT 选择规则。直接使用的：O*NET 30.3 数据库与 AI4Work 的 DIGITAL 标注、GLM-5.2（承担全管线所有模型角色：workspace 检索、建图、任务生成、修订、教师 rollout、judge）、Qwen3.6 系列基座、OpenHands/Codex/Claude Code scaffolds、GDPVal/Workspace-Bench/SpreadsheetBench II 基准、Bradley–Terry/Elo 评估。

Fig. 1 的作用（原图说明：从 O*NET 派生种子开始，agent 组装带隐藏角色的真实文件 workspace，模型构建证据图并编译成带锚点的任务规格；初始教师 rollout 支持一步修订；最终轨迹经证据锚定 judge 评分后准入）。图中第一、二列是”方向固定、文件落地”的分离——第一列（示例种子：Financial & Investment Analysts / Analyze financial data / Quantitative modeling / Support investment decisions）决定”谁做什么类的工作”（避免塌缩），第二列把种子落地为真实文件（图中示例：F1 2025 annual filing（HTML，core）、F2 2025 financial report（XLSX，core）、F3 NVDA company facts（JSON，core）、F4 2024 annual filing（HTML，supporting）、F5 Income statement（HTML，supporting））并做覆盖度选择；第三列是核心：左侧把文件连成图（F4→F1 标注 “Prior year”、F3→F2 标注 “Data source”、F1→F2 标注 “Context”、F5 与后两者之间的 “Extracted statement”/“Income exhibit”），右侧把图编译成任务与交付物（”Create an NVDA investment workbook；Financial data → ratios → valuation model”）并给出私有评分标准示例（”FY2025 revenue USD 130,497M”，锚点 F2/F1/F5，验证指令 “Read revenue from F2, Cross-check with F1 and F5”）——没有这一列，任务与验证就退回成自由发挥；第四列说明修订只改必要的部分（”Fix task / rubric only”，两个分支：任务未变且轨迹可用→Reuse trace；任务变了或轨迹缺失→Rerun teacher）；第五列为准入（Figure 中直接画出被检查的 NVDA 投资分析表格截图、evidence-anchored judge、Trajectory cleaning（Score > 0.90）与 Admitted training trajectory）；底部说明这批数据用于 SFT/RFT 训练工作型 agent，其目标能力是真实世界知识、多文件推理、工具使用与长程执行、可验证可靠行为。

Fig. 2(a) 的作用：检验”种子控制多样性”是否真的兑现。横轴是 16 类执行模式，纵轴是 16 个 occupational sector（其中最底部 Healthcare Support 一整行为灰色，即该 sector 未被语料覆盖，与正文”覆盖 15/16 个 sector”一致），格子颜色（对数尺度）是轨迹数。256 个组合中 164 个非空说明覆盖确实广；但颜色分布不均——上部的 Life, Physical & Social Science、Business & Financial Operations 等职业行颜色最深，越靠下越稀疏，对应正文的 14.2%/13.2% 头部集中（data analysis and reporting、research and source synthesis）——这正是”多样性可控但并非均匀”的直接证据，也是审稿时质疑”覆盖面宣称”的落点。

Fig. 2(b) 的作用：刻画任务的”输入面”——真实办公环境以 PDF 为主（正文：96.7% 的轨迹含 PDF），表格与网页次之，演示文稿几乎不出现（0.15/任务）；插图显示每任务平均 23.1 个输入文件（中位 22），说明任务是”多文件依赖”型而不是单文件问答。这张图支撑论文”read diverse files”的问题设定，也解释了为什么判分必须锚定到具体文件。

Fig. 3 的作用：说明这些轨迹是长程、长上下文的（均值 50.0 个 assistant 步、162.0k token；95 分位 82 步、224.8k token），因此训练用了 262,144 token 的 packing 上限——28 条序列（1.3%）触及该上限（§4.1）。它同时提示成本：单条训练样本动辄十几万 token，也解释了 Appendix A 为什么强调”保留完整推理与工具交互历史”。

教学简化示例（非论文实验）。 假设一个”季度费用对账”任务：种子 = 职业”Financial Analyst” + DWA 任务类型，方向固定为对账；workspace 里放进真实公开的三份文件——f1 是公司季度费用明细表（core）、f2 是财务制度 PDF（supporting）、f3 是同行业另一家公司的类似报表（confuser，看起来相关但不能用）。证据图会有一条边 f1→f2（”哪些费用类别可报销，需要读制度文件”）；编译出的正标准形如 c_1=(d=”费用汇总表”, r=”按制度分类汇总”, z=”各分类合计=X”, w=0.4, A_1={f1,f2}, φ_1=”打开汇总表逐列核对，并与 f1/f2 交叉检查”)；判分器据 A_1、φ_1 去看交付物和这两份文件，而工作 agent 的任务陈述里不会出现”该用 f2”的提示——这个”信息差”就是执行/验证分离。真实实验中标准、锚点与验证程序由模型生成并经修订与校验（§3.3、§3.4），不是人工书写。

4. 解决得怎么样？

4.1 实验设置

  • 任务与数据集：GDPVal-AA（论文描述为”full GDPVal 的 220 任务 gold subset”，原文比对的是 44 个职业、1,320 任务的官方基准）、Workspace-Bench-Lite（micro 分数）、SpreadsheetBench II（执行准确率）（§4，Table 2 表头）。
  • 被训练模型：Qwen3.6-27B 与 Qwen3.6-35B-A3B，SFT 语料同为 2,169 条（466 个不同 O*NET 任务类型、15/16 sector、16/16 执行模式；来自 3,638 个材料化任务，准入率 59.2%，Table 4b）。
  • 对比对象：六个前沿模型（Claude Opus 5、GPT-5.6-sol、Qwen3.8-Max、GLM-5.3、Kimi-K3、DeepSeek-V4-Pro）、开源权重基线 Nex-N2-Mini-35B（NexForge 发布的模型），以及两个基座自身。
  • 评测协议：每模型 pass@1，scaffold 配置固定（GDPVal 用 OpenHands 与 Codex；WBL-Lite 与 SB II 用 Claude Code 与 Codex），模型对比始终在同一 scaffold 内；缺失/无效交付物或未完成任务记为失败，基础设施故障重试（§4.2）。GDPVal 用内部 Elo 池（Eq. 1）；Workspace-Bench-Lite 报 micro、SB II 报执行准确率。
  • RFT 设置：2,000 查询×4 候选→462 条/臂，三臂同预算（Table 5）。RFT 第二阶段的对比是各臂与 SFT 在同 scaffold 同任务上的直接配对比较，换算成 Elo 差加到冻结的主表 SFT 分数上（§4.4，Appendix D）。
  • 各实验回答什么：Table 2=端到端效果与跨 scaffold/模型迁移；Table 3=选择规则的作用（阶段二是否再加成）；Table 4=数据污染与判分机理（审计）；Appendix C/D=Elo 的统计不确定性。未做的对照：与”同教师+更简单管线”训练出的模型对比（回答”证据图是否不可替代”）。

4.2 关键结果

以下数字均取自 Table 2/3/4/6/7（GDPVal 列口径为 GDPVal-AA 220 任务）。

  • SFT 主结果（Table 2）：Qwen3.6-27B 基座 → SFT：GDPVal 1380.0→1445.7（+65.7）（OpenHands）、1364.0→1427.4（+63.4）（Codex）；Workspace-Bench-Lite 56.0→63.7（+7.7）（Claude Code）、61.4→65.2（+3.8）（Codex）；SpreadsheetBench II 10.3→24.0（+13.7）（Claude Code）、15.6→24.6（+9.0）（Codex）。Qwen3.6-35B-A3B 的增益更大：GDPVal +101.7/+101.4，WBL +3.8/+6.6，SB II +16.5/+14.0。
  • 提升有限/仍低之处：27B 在 Codex 下 WBL 只 +3.8；SB II 绝对分数 24.0 仍低（Claude Opus 5 33.6、Kimi-K3 35.8，Table 2）；SFT 后仍低于全部前沿模型（GDPVal 1445.7 < Claude Opus 5 1774.1、Qwen3.8-Max 1719.0、GPT-5.6-sol 1687.1、Kimi-K3 1615.5，仅高于 DeepSeek-V4-Pro 1531.5 与 Nex-N2-Mini-35B 1288.8）——增益是”相对自身基座”的大幅提升，不是超越前沿。
  • RFT（Table 3，35B-A3B SFT 之上）：锚定臂 +7.2/+11.0（GDPVal OpenHands/Codex）、WBL +4.0/+4.0、SB II +1.0/+0.9；unanchored 臂 GDPVal 点估计反而更高（+34.1/+25.3）但 SB II 一列为负（−1.8/0.0）；random-of-4 臂 GDPVal 变差（−9.0/−9.5）。正文明确：”none of these GDPVal differences is statistically resolved at this scale”；Appendix D 更直接：所有差值 95% 区间包含 0（Table 7）。
  • 统计细节：主表 Elo 的 95% bootstrap CI（Table 6）中，27B 基座 OpenHands [1326.6, 1432.1] 与 27B SFT [1376.2, 1513.8] 的边缘区间重叠——节点级 CI 不能直接当作配对差值检验；论文在污染审计中给出了直接配对证据（Table 4c）：base vs SFT 在全部 220 任务上 W/T/L=152/15/53，win rate 0.725，95% CI [0.668, 0.782]，不含 0.5。（该比较未注明所用 base model 与 scaffold，论文未报告。）
  • 迁移与污染（§4.5，Table 4a/c，Appendix B）：39,201 个训练文件哈希与 GDPVal 的 260 个文件哈希零共享；13-gram 相似度 top-20 对无实质内容重叠（5 对仅共享通用数字序列、15 对仅 PowerPoint 占位符文本）；44 个 GDPVal 职业仅 13 个被训练分类覆盖；按覆盖分组的 base-vs-SFT 胜率：未覆盖 155 任务 0.739 [0.671, 0.803] ≥ 覆盖 65 任务 0.692 [0.585, 0.800]，差值 0.047 的 CI [−0.079, 0.175]——增益不集中在被覆盖职业。

4.3 机制证据

区分”有效”与”为什么有效”：

  • 支持机制的证据（部分）：(1) RFT 三臂对照在选择规则层面是干净的（同查询、同候选池、同预算），random 最差支持”选择质量重要”——这是论文中设计最严谨的消融；(2) judge 敏感性扰动（Table 4d）：删除某条标准引用的工作表使该标准分数平均下降 0.377、非目标标准几乎不变（平均 |ΔQ|=0.016），说明 judge 确实在按锚点读文件、且响应定位到受影响标准——这是”锚定有效”的直接机制证据；(3) 三层污染审计（文件/文本/职业）与覆盖分组比较，排除了”记忆基准内容”这一替代解释，属较强证据。
  • 未支持/削弱机制的证据：(1) judge 对细粒度腐蚀不敏感——行、数字、引用级扰动造成的 ΔQ 均在 0.03 以下，论文将其归因于 GLM-5.2 作为 judge 的能力上限（”reliably detects structural evidence failures but struggles to verify fine-grained content”）。这意味着”每条标准可被验证”的框架承诺在内容级并未完全兑现，准入分数对数字错误的检出能力有限。(2) 论文没有消融”证据图/锚定 rubric 是否存在”对训练数据质量与模型增益的影响：RFT 的 unanchored 臂只改变 judge 的输入信息（仍用同一 rubric 文本与同一准入管线），且其结果在 GDPVal 上甚至不支持锚定优势。(3) 没有任何对照把 SFT 增益分解为”数据构造质量”与”从强教师（GLM-5.2）蒸馏”两部分——教师显著强于 Qwen3.6 基座（见 Table 2 前沿对比语境），SFT 本质上是蒸馏，因此”证据图锚定的数据教出了可迁移的工作技能”这一因果表述目前只是作者的解释（原文用词 “suggests”），未排除”任意真实文件任务上的教师轨迹都能达到类似增益”的替代解释。

4.4 成本与适用范围

  • 论文报告的成本类信息：轨迹长度（平均 50.0 步/162.0k token，P95 82 步/224.8k；28 条 1.3% 达 262,144 token 上限）；SFT/RFT 超参与 batch（Table 5）；语料漏斗（3,638→2,169）。数据与权重按声明已发布（CC BY 4.0，页面标注）。
  • 论文未报告：训练与合成的算力/时长/费用（Appendix A 只有超参表；Reproducibility 声明称”hardware and software setup is reported”，但 HTML 全文与附录中未见具体硬件配置）；管线各环节对 GLM-5.2 的调用量与成本；judge 在评测主表（GDPVal pairwise、WBL/SB II 打分）中由哪个模型执行——正文只写 “the judge”（Appendix B），未披露身份与协议（judge 一致性、人工复核比例均未报告）。
  • 外部依赖与系统复杂度：全管线依赖闭源前沿模型 GLM-5.2（workspace 检索、建图、任务生成、修订、教师、judge 六种角色），框架上限与成本都随之绑定（作者在 §6 自认）；真实文件抓取带来许可证/来源管理需求（Ethics 声明称只提供来源链接、不重分发内容）。
  • 适用边界：结论适用于论文的三个基准（其中两个是 Lite/子集版本）、两个同家族基座、三个 scaffold 的固定配置；语料规模 2,169，作者明确表示未研究数据规模扩展性、未验证跨模型家族迁移（§6）。”训练出可迁移工作技能”的推广表述应限制在上述条件内。

5. 最容易受到审稿人质疑的地方

质疑：无法隔离”证据图锚定”这一核心机制与”从更强教师蒸馏”的贡献

  • 原文依据：全管线（含教师 rollout 与 judge）用 GLM-5.2（§4.2），SFT 语料即教师轨迹；Table 1 对管线只做定性比较；Table 2 唯一的数据管线对照 Nex-N2-Mini-35B 来自不同团队、不同配方；Table 3 的消融只隔离 RFT 选择规则，不涉及证据图。
  • 为什么重要：论文标题与叙事把增益归功于 graph-anchored 数据构造；若”同教师+任意真实文件任务（无图、无锚定 rubric）”也能训练出接近效果，则”证据图”只是工程包装。这直接影响创新性证据的强度。
  • 当前判断：证据不足。论文证明了”这套数据+配方有效”，没有证明”没有证据图就不行”。
  • 如何验证：同教师（GLM-5.2）、同预算、同 SFT 配方下，用简化管线（如 NexForge 风格无 rubric、或 EnvCraft 风格合成文件）生成对照语料训练，三方比较；并对任务-标准锚定正确率做量化统计。
  • 严重程度：主要问题。

质疑：主表 Elo 的判分主体未披露，且与管线判分器同源风险未排除

  • 原文依据：§4.2 只说明 Elo 的统计模型（Eq. 1）与锚点（GLM-5.3=1667），未说明 pairwise 比较由谁执行；Appendix B 写”deliverables was presented to the judge”，未给身份；管线内 judge 已确认为 GLM-5.2（§4.2），同为 GLM 家族。WBL/SB II 的评分器也未说明（是否沿用 LLM judge 或官方 verifier 未报告）。
  • 为什么重要：头条数字（+65.7 Elo）与 Table 4c 的胜率全部依赖判分公平性；若由与教师/对照同家族的模型判分，存在自我偏好与系统性偏差风险（即便无证据表明存在，披露也是复现性的一部分）。
  • 当前判断：当前材料无法确认判分是否独立；论文未报告判分模型、协议与判分一致性。
  • 如何验证：披露判分模型与提示协议；用人工专家或第三方模型复核抽样子集并报告一致性（如与内部 Elo 的相关系数）；报告 balanced order 之外的 robustness（如判分顺序翻转率）。
  • 严重程度：主要问题。

质疑：RFT”锚定选择更优”的结论统计上未被分辨

  • 原文依据：Appendix D 明言 “All difference intervals include zero”；Table 3 中 GDPVal 上 unanchored 臂点估计（+34.1/+25.3）高于锚定臂（+7.2/+11.0）；锚定臂在 WBL（+4.0/+4.0）与 SB II（+1.0/+0.9）上增益最大，但各列排序并不一致（如 WBL 的 Codex 列 random +2.8 反而高于 unanchored +1.7）；摘要与结论仍用”rubrics provide a useful selection signal”。
  • 为什么重要：这是论文第二个贡献声明的全部证据；n=462、单次训练、单检查点的设计下，按基准排序推断选择规则优劣的说服力有限。
  • 当前判断：方向性证据（random 最差）成立；”证据锚定优于无锚定”证据不足。论文正文对此的表述已相当克制，但摘要的”suggesting”仍可能被读者高估。
  • 如何验证：扩大查询数与 rollout 数、多随机种子重复 RFT、跨基准合并的配对检验，或用人工标注对 judge 选择做外部效度检验。
  • 严重程度：主要问题。

质疑：”可验证”宣称与 judge 细粒度验证弱点的张力

  • 原文依据：Table 4d——删除被引用工作表 ΔQ=−0.377，但行/数字/引用腐蚀 ΔQ 仅 −0.018/−0.022/−0.013；作者自认 judge “struggles to verify fine-grained content” 并归因于 GLM-5.2 能力上限。
  • 为什么重要：Q>0.90 的准入与 best-of-4 选择都以该 judge 分数为唯一质量门；如果数字级错误系统性地漏检，训练数据中可能混入未被发现的错误内容（作者未测其对训练的影响，也未做人工抽查的错误率报告）。
  • 当前判断：论文自己提供了负面证据并如实标注——这是加分项；但”每条标准都锚定到可验证文件”的框架承诺因此只能算部分兑现。
  • 如何验证：构造含已知细粒度错误（错误数字、错误引用）的交付物测假阴性率；对 admitted 轨迹做分层人工抽检并报告错误率；训练带已知错误数据的对照模型评估敏感度。
  • 严重程度：主要问题（作者已披露）。

质疑：语料规模与 generality 的边界比标题暗示的窄

  • 原文依据：Table 1 显示语料 2.1K 任务，小于 EnvCraft 20K 与 NexForge 5.6K；实验只覆盖 Qwen3.6 家族两个模型（§4，§6 自认）；”模型自由发明任务会塌缩”（§3.1）无引用与实证实验；WBL-Lite/SB II 的任务数与统计功效未报告；多样性的头部集中（14.2%/13.2%，§4.1）显示覆盖不匀。
  • 为什么重要：影响”多样、可控、通用”的宣称为读者带来的预期；也影响方法在更大规模数据预算下的可用性判断。
  • 当前判断：作者在 §6 已主动承认规模与家族边界，此项属”结论范围应限定”而非缺陷隐藏；塌缩论断则完全缺乏证据支撑。
  • 如何验证：补充跨家族基座（如 Llama/DeepSeek 系）实验、数据规模消融（如 0.5K/1K/2K/4K 曲线）、对”自由发明 vs 种子引导”的任务分布对照测量。
  • 严重程度：次要问题。

6. 审稿式总评

作者发现工作型 agent 的训练数据同时缺”真实文件上的多样任务”与”任务级可验证标准”，因此提出 GraphForge：用 O*NET 职业种子固定方向、在真实文件上建证据图，并把任务陈述与 rubric 都编译成带文件锚点的规格，经教师试跑→一步修订→交付物与 rubric 评审得到 2,169 条轨迹；再用同一锚定 rubric 做 RFT 选择。实验在 GDPVal-AA（220 任务）、Workspace-Bench-Lite、SpreadsheetBench II 三个基准、三个固定 scaffold 配置下表明：2,169 条轨迹的 SFT 显著抬升了两个 Qwen3.6 基座（27B +65.7 Elo / +7.7 / +13.7），并配有三层污染审计与覆盖分组迁移分析（未覆盖职业胜率不低于覆盖职业，CI 不排除 0 差值），这两部分证据较强；但”增益来自证据图锚定而非教师蒸馏”缺乏对照（无同教师简化管线基线），RFT 的锚定优势统计上未被分辨（附录 D 全部区间含 0，GDPVal 点估计方向相反），主表判分主体未披露，且 judge 对细粒度内容错误不敏感（作者自认）。本文最有价值的部分是”任务-验证同源于证据图、执行与验证分离”的数据构造范式与可复用的审计方法（污染三查、judge 扰动探测、覆盖分组迁移），最大的审稿风险是核心机制的不可替代性没有实验隔离。

  • 问题定义清晰度：强。两类现有管线的缺口（EnvCraft 脚本读不了文档内容、NexForge 无 rubric）具体、可核对，目标指标体系（多样性、可执行性、可验证性、迁移性）与实验一一对应（§1、§4.5）。
  • 创新性证据：中。证据图→任务/ rubric 编译与隐藏角色是实质的流程设计，但相对最近管线只有定性比较；”模型自由发明会塌缩”等动机论断无实证；机制不可替代性未被消融（§2、§5 质疑 1）。
  • 方法可信度：中。管线五阶段描述完整、公式与超参齐全、修订与准入有防泄漏设计（执行/验证分离），但全管线依赖闭源 GLM-5.2、判分主体未披露、细粒度验证弱点自认（§3、§4.4、Table 4d）。
  • 实验支持力度：中。”三基准×多 scaffold×CI+污染审计”较扎实，RFT 三臂设计干净；但无数据管线对照、RFT 差值不显著、两基准为 Lite/子集版本（§4.2、Appendix C/D）。
  • 可复现性：中。训练配置、语料构造漏斗、CI 方法均详述，数据与权重声明公开；但合成管线的提示词/调用预算/成本、硬件配置、评测判分模型均未报告，”hardware reported”的声明在 HTML 版中未见落点。
  • 综合阅读价值：高。对想了解”工作型 agent 训练数据从哪来”的学生，本文给出了一个完整、诚实且带自我审计的管线模板；其负面结果（judge 细粒度弱点、RFT 不显著）与边界声明（§6）尤具教学价值——阅读时应带着”机制未被隔离”这一主线批判性吸收。
