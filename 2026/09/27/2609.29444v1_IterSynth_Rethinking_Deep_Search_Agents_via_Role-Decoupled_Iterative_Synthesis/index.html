IterSynth: Rethinking Deep Search Agents via Role-Decoupled Iterative Synthesis

1. 作者发现了什么问题？

Deep search（深度搜索）要求 Agent 把复杂问题拆解成子问题、反复检索、读证据、最后给出有依据的答案。目前开源 Agent 的主流做法是 ReAct 式单策略流水线：一个模型在一条不断增长的上下文里交替做「推理—搜索—总结」（§2.2）。作者指出这种范式有两个结构性缺陷（§1）：

  1. 角色耦合（role coupling）：规划、查询构造、证据筛选、冲突消解、最终综合这些异质能力全压在一个未分化的策略上，容易出现过早终止、重复搜索、浅层用证。
  2. 上下文累积（context accumulation）：检索到的段落、中间思路、部分结论不断堆进同一条上下文，有用信息越来越难找，早期错误还会一路传播。

作者没有停留在直觉论证上，而是做了量化：附录 H 用 DeepSeek-V3.1 和 Claude-Sonnet-4.6 跑标准 ReAct Agent，在 64K 上下文预算下统计「未完成（上下文耗尽前没给出答案）」的比例——xBench-2510 上 27%–30%，BrowseComp-ZH 的 100 题子集上 31%–34%，BrowseComp 的 100 题子集上高达 59%–65%，此时成功轨迹只剩 7%（DeepSeek）与 14%（Claude）。两个能力不同的骨干模型未完成率却相差不大，说明上下文耗尽来自 ReAct 范式本身，而不是某个模型不够强。

已有两条修补路线也各有短板（§2.2、附录 D）：多 Agent 系统给不同子任务配不同模型，能解耦但推理成本、部署复杂度、协调开销都上去了；摘要式（summarization）Agent 周期性压缩历史，但摘要通常只是外部辅助模块，不是可学习、可优化的搜索策略的一部分，规划与用证仍然耦合，摘要还可能丢掉有用信息或把误导性噪声留下来。表 D 的四维对比显示：在单策略方法里，此前没有任何一个同时做到「角色解耦」和「工作区重建」。

作者的核心判断是：瓶颈不在训练算法，而在 Agent workflow；要让摘要成为 Agent 行为的显式组成部分、并让不同认知角色各自获得清晰的优化信号。

2. 作者如何解决？

核心思路。 IterSynth 用同一个共享参数的 LLM扮演两个角色：Planner 只看紧凑状态 (q,Mt)(q, M_t)(q,Mt​)，决定「下一个该搜什么」或「给出最终答案」；Synthesizer 读检索回来的证据，把有用的结论合并进全局摘要 Mt+1M_{t+1}Mt+1​。每次迭代结束后，上下文从 (q,Mt+1)(q, M_{t+1})(q,Mt+1​) 重新构造，因此无论搜多少轮，每一步的上下文都是有界的；摘要就是搜索的持久状态，而不是事后压缩的附件（§3.1，图 1）。

原文图 1：IterSynth 流程总览。左侧 Workspace 只有问题与全局摘要 MtM_tMt​；中间 Planner 依据 MtM_tMt​ 选择 search 或 answer，若选 search 则由 Environment 检索，Synthesizer 把检索结果整合成 Mt+1M_{t+1}Mt+1​；每轮上下文都从 (q,Mt+1)(q, M_{t+1})(q,Mt+1​) 重建，因而结构上有界。

角色差异只来自角色专属提示词、信息可见性、动作约束（Synthesizer 只能更新记忆，不能发查询、不能给答案），不引入额外参数。附录 B.1 的算法 1 给出完整循环；训练时最大迭代 Tmax⁡=30T_{\max}=30Tmax​=30，评测放宽到 50（§B.3）。

第一阶段：SFT 冷启动（§3.2.1、§B.3）。 语料由公开深度搜索数据集（DeepDive、DeepForge、REDSearcher）加自建合成题构成；每题用前沿模型 Qwen3.5-397B-A17B 在真实搜索环境里 rollout 双角色循环，再经过滤（修复格式/工具调用错误，剔除幻觉推理步，只保留终答案可验证正确的轨迹），留下约 1 万条轨迹，平均 4.37 轮。每条轨迹拆成逐轮样本，Planner 和 Synthesizer 的每个回答都是独立监督目标，共约 87.4K 条角色条件样本。在 32 张 H20（96 GB）上对 Qwen3-8B 做全参数 SFT（约 24 小时，LR 1×10−51\times10^{-5}1×10−5，batch 512，4 epoch，上下文 32,768），损失只算角色回答部分，工具返回内容被 mask 掉，避免模型去模仿检索内容。

第二阶段：RDPO 强化学习（§3.2.2，图 2）。 论文观察到 IterSynth 的轨迹天然由多轮组成，于是不再把整条轨迹当一个大样本，而是把「每轮 × 每个角色」都当成优化单元。这带来两个设计：

原文图 2：RDPO 流程。终局正确性信号 raccr_{\text{acc}}racc​ 全局广播到所有轮次，与每个角色的逐轮 rubric 分组合成复合奖励，再按角色拆成两个奖励池，各自归一化出 advantage 后送入标准策略梯度更新。

    Ai,tρ=ri,tρ−μqρσqρ.A_{i,t}^{\rho}=\frac{r_{i,t}^{\rho}-\mu_q^{\rho}}{\sigma_q^{\rho}}.Ai,tρ​=σqρ​ri,tρ​−μqρ​​.

    其余部分原样接入标准 GRPO 目标，没有额外算法改动。作者的论据是：Synthesizer 的 rubric 分很密、Planner 的很稀，混在一起归一化会互相污染信用分配。

Rubric 怎么来（附录 C）。 不是手写：先用 SFT 策略在留出题上收集 20 组「同题、一对一对错」轨迹，让 Claude-4.6-Sonnet 逐对提炼出能区分成败的准则（Planner、Synthesizer 分开生成，避免混淆），再把 20 份准则合并、去重，每个角色最多保留 5 条并冻结。RL 时由 Gemini-2.5-flash-lite 在每个角色轮次上打分。

训练数据与工具环境。 RL 题集从 SFT 题目里筛：每题用 SFT 模型 rollout 5 次，只保留「恰好 1–2 次正确」的题（约 1,000 题），瞄准中等难度区间。工具是 SerpAPI 版 Google 搜索（一次可发多条 query，返回前 10 条标题/URL/摘要）和浏览器工具（Jina Reader 抓 HTML/PDF，再由 Qwen3-8B 做「按子问题条件化」的摘要）；RL rollout 用离线缓存检索控制成本，评测时切回真实在线工具，保证报出的数字是真实深搜场景（§4.1、§B.2）。RL 超参：64 张 H20 约 90 小时，LR 1×10−61\times10^{-6}1×10−6，每题组大小 8，batch 32，温度 1.0，top-p 0.95，KL 系数 0.001，α=0.5\alpha=0.5α=0.5。

3. 解决得怎么样？

设置。 五个长程基准：BrowseComp（1,266 题）、BrowseComp-ZH（289 题）、GAIA text-only 验证集（103 题）、Xbench-DeepSearch 的 2505/2510 两个 split（各 100 题）。训练数据与基准严格不重叠（§A.4）。

主结果（表 1）。 IterSynth-8B 平均 50.7：BrowseComp 30.9、BrowseComp-ZH 55.4、GAIA 55.3、Xbench-DS-2505 66.0、Xbench-DS-2510 46.0。

模型 参数量 BrowseComp BC-ZH GAIA Xb-2505 Xb-2510 平均
MiroThinker-v1.0-8B（此前最强 ≤8B） 8B 31.1 40.2 66.4 60.6 34.0 46.5
IterSynth-8B 8B 30.9 55.4 55.3 66.0 46.0 50.7
MiroThinker-v1.5-30B 30B 56.1 66.8 72.0 73.1 – 67.0
Tongyi-DR-30B 30B 43.4 46.7 70.9 75.0 55.0 58.2

比此前最强 ≤8B Agent 平均高 +4.2（50.7 vs 46.5），BrowseComp-ZH 上高 +15.2（55.4 vs 40.2），并且以不到三分之一的参数超过 ReSum-30B、AgentFold-30B-A3B、OpenSeeker-30B-SFT 等 30B 级 Agent。需要如实指出两点：在 BrowseComp（30.9 vs 31.1）和 GAIA（55.3 vs 66.4）上它并没有超过 MiroThinker-v1.0-8B，优势集中在探索密集型任务；另外原文 §4.2 称 Xbench-DS-2510「增益 +5.4」，表 1 里最强 ≤8B 先验值是 34.0、IterSynth 是 46.0（差 +12.0），+5.4 的比较对象原文未说明。还有一个值得注意的细节：表 J 中「不加重采样」的 IterSynth-8B 在三项上分别是 Xb-2510 37.0、BC 25.7、BC-ZH 49.1，而「+Resample」行是 46.0/30.9/55.4，与表 1 的三项数字完全相同——由此推断（原文未明说）主表成绩包含测试时「判定为未作答则重采样一次」的策略，去掉它成绩会明显下降。

消融是否支持解释（表 2、表 3、表 E）。 ① 训练配方：SFT 44.1 → 仅 outcome 的 GRPO 48.9 → RDPO 50.7，说明 RL 与 rubric 都有增量；但同用复合奖励、只把混合角色样本一起归一化（w/o RD）反而掉到 47.2，比纯 GRPO 还低，支持「按角色分组归一化」是关键而非 rubric 本身。② 角色互换（表 3，平均为 Xb05/BCzh/GAIA 三项均值 58.9）：把 Synthesizer 换成未训练 Qwen3-8B 平均掉 17.4，把 Planner 换掉掉 41.1，说明收益不是结构空壳，且 Planner 是更难的角色。③ 对照实验（表 E）：同题、同教师模型、同规模数据下 ReAct-SFT 32.6 vs IterSynth-SFT 44.1（+11.5），RL 后 38.1 vs 50.7（+12.6），排除「只是教师轨迹更好」这一混淆。④ 纯提示词版本（表 5.1）：不改参数时 Claude-4.5-Opus 平均比 ReAct 高 +5.5、DeepSeek-V3.1 高 +4.5，BC-ZH 上最多 +10.0。⑤ α\alphaα 消融（表 G）：0.3/0.5/0.7 对应 46.6/50.7/49.0，倒 U 形，说明逐轮信号过强会挤掉终局目标。

代价与边界。 显性成本是多了一轮完整 RL（64×H20 约 90 小时）和 rubric judge 的调用：论文估算 judge 总共约 12.8 万次调用、19.2 亿 token、约 192 美元，约合「每提升 1 个点 54.9 美元」（§F.2，数字为该文自估，未含 GPU 开销）；换 4 种 judge 模型时 rubric 均分只差 ±0.09、下游成绩 ±1.0 点内（附录 G）。推理侧共享参数比双模型部署省 13%–15% 墙钟时间，且比 Tongyi-DR-30B 快 1.5–1.6 倍、达到其约 87% 的平均分（附录 F.2）。轨迹统计（附录 F.3）显示平均搜索轮数 7–8（ReAct 12+）、上下文耗尽率 <5%（ReAct 59%）。失败分析（§F.4）给出两类残余错误：GAIA 上摘要把「两个事实之间的关系」漏掉，导致推理断链；BrowseComp 上 Synthesizer 把看似权威但错误的来源写进摘要，之后只找支持性证据，接近确认偏误。此外所有实验只针对 Qwen3-8B 一个底座、单次训练，未有多种子方差报告；测试时重采样带来的增益也说明相当比例的失败是「过早终止」而非能力缺失。

作者发现 ReAct 式单策略 Agent 同时受角色耦合与上下文累积拖累（64K 预算下 BrowseComp 上过半轨迹因上下文耗尽而未能作答），因此提出 IterSynth——用共享参数的单策略交替扮演 Planner 与 Synthesizer、以持续演化的摘要为搜索状态并在每轮重建上下文，并配套提出 RDPO（终局奖励 + 逐轮 rubric 奖励的复合奖励、按角色分组归一化的优势估计）来优化两个角色，实验表明 IterSynth-8B 在五个长程深搜基准上平均 50.7、超过此前最强 ≤8B Agent 4.2 个点并可对标部分 30B 级系统，纯提示词形式也能提升闭源前沿模型，但其优势在 BrowseComp/GAIA 上并不全面、主表成绩疑似包含测试时重采样、摘要仍会丢关系或固化错误证据，训练成本与单底座单种子的泛化性也仍待验证。
