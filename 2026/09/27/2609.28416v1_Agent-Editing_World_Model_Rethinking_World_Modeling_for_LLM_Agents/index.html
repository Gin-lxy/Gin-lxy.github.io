Agent-Editing World Model: Rethinking World Modeling for LLM Agents

1. 作者发现了什么问题？

近两年”语言世界模型”（language world model）的主流做法，是让模型预测动作之后的环境观测：给定任务和历史，模拟工具会返回什么搜索结果、终端输出或测试结果（§1、§6）。作者认为这条路线对任务型 LLM Agent 是错位的。理由有两点（§1、§2.1）：

  1. 这些观测本身就是高熵、依赖真实执行的：搜索结果取决于不断变化的网页内容与不透明的排序；终端输出和测试结果取决于文件系统和运行时状态。真实工具已经能提供 grounded feedback，模型再去重构它们既困难，价值也有限；更糟的是模拟可能凭空造出证据（fabricated evidence），误导后续决策。
  2. 真正出问题的地方不在环境，而在 agent 自身的状态。作者通过轨迹分析（§1、§5.1）发现一种反复出现的失败机制——task-state contamination（任务状态污染）：agent 在部分观测下探索未知环境时，会把没有依据的假设当成事实、在出现矛盾反馈后继续沿用过时的计划、或把局部进展误判为任务完成。这些错误一旦写进历史，就会被后续”局部看起来合理”的动作不断放大，即使环境反馈本身是真实、正确的。

论文给出的证据是逐动作的统计与案例：把三个域的 agent 轨迹按决策类型标注后（图 4、§5.1），Search 域有 60.0% 的决策属于 Noisy（无进展、重复、违背约束或方向错误）；Terminal 域的 Exploratory 占比最高（**43.2%**），Noisy 占 25.1%；SWE 域 Critical 占 42.1%、Noisy 占 28.0%。附录 D 的 9 个案例进一步展示了具体形态，例如 Search 里 agent 把”偏好的来源”直接当作出生姓氏的定论、Terminal 里把中间步骤的成功当成已验证的完成（§5.2、附录 D）。

因此，作者的核心判断是：语言世界模型该预测的不是环境观测，而是”当前推理与动作会如何影响后续任务进展”，并且应当直接干预 agent 的状态，而不是仅提供”批评意见”。

2. 作者如何解决？

核心思路：把 agent 在执行前的状态 sts_tst​（历史 + 当前提议的推理–动作对）作为世界模型的输入端，训练一个模型做两件事——判断这个提议属于 Critical / Exploratory / Noisy 三类中的哪一类（Action Judge），并为 Noisy 提议从同一历史出发重新生成推理与动作（State Revision）；两者组合成 EditAct：保留有价值的决策、改写有污染的决策、把最终选定的动作放进真实环境执行。图 2 给出整体框架。

原文图 2（正文 §2 前，官方 HTML 图）。左：合成 Action Judge 与 State Revision 数据，经 mid-training 与 SFT 训练 AEWM；右：推理时 EditAct 选择保留或改写提议的推理–动作状态，产出轨迹再用于 AEWM-RFT 拒绝采样微调。

即在保留历史 hth_tht​ 不变的前提下，替换当前的推理–动作续写；此后一切都由真实环境执行来获得观测。推理时的选择规则是（式 2）：

State Revision 只在被判为 Noisy 时触发。三类标签的语义（§2.2）：Critical 是”补齐关键证据或必要状态改变、走紧凑解题路径”的决策；Exploratory 是”显著降低不确定性或验证一个合理分支”的决策——显式保留这一类比只留”最优路径”更重要；Noisy 是预期进展很小、或造成重复、切题、违反约束、方向错误的决策。

训练数据怎么来（§3.1，附录 A）。 全部监督都从已验证成功的真实 agent 轨迹回标得到：

  • Action Judge 数据：把成功轨迹拆成单个 turn，由强标注模型（DeepSeek-V4-Pro，高推理强度，每个决策独立标注 3 次）回看完整轨迹后，为每个 turn 生成一段只允许使用当前可见信息的前瞻推理 rtAJr_t^{\mathrm{AJ}}rtAJ​ 与动作类型 yty_tyt​；标注一致（三次全同）的进”高置信储备”，多数一致的进 mid-training 池。这里有个有意思的训练哲学：用”事后回看”的标签去监督”事前预测”——训练目标与推理目标相同（预测动作的下游贡献类型），区别只在于标注时证据已经出现。过滤上，先做结构检查（参数格式、工具是否存在、原生工具调用是否残留文本壳），再用语义评分卡（表 4：每维 0–4 分，全维 ≥3 才收，如”前缀可依据性、推理质量、动作具体性、标签–理由一致性”等），最后做多样性配额抽样。
  • State Revision 数据：由 Qwen3.5-35B-A3B 当 proposal agent 正常解题；一旦 Action Judge 检查点判某步为 Noisy，就由 revision agent（DeepSeek-V4-Pro）从同一段历史生成新的推理–动作对，并在真实环境中执行；只有当后续轨迹显示这次改写确实带来实质进展时才保留样本（Search 要求最终答案正确，Terminal 要求任务验证通过，DeNovoSWE 要求最终分数 >0.8）。
  • 两阶段训练（§3.2，表 5–7）：backbone 为 Qwen3.5-35B-A3B，用 verl + Megatron 后端。Mid-training 语料约 52.16B tokens（其中 Action Judge 监督 20.56B、State Revision 监督 25.01B、原始交互轨迹 6.59B），学”交互知识 + 判断/改写”的粗能力；SFT 用 120K 条严格筛选样本（60K Action Judge + 60K State Revision，每个域各 40K；Search 的 AJ 标签刻意按 1:1:3 配比）激活并校准两种能力。两阶段学习率均为 1×10−51\times10^{-5}1×10−5，batch 分别 512/256，序列上限 262,144/131,072（表 7）。
  • AEWM-RFT（§3.3）：把 EditAct 干预下产生的经真实反馈验证的轨迹（含 AEWM 的改写）拿来对 agent 做拒绝采样微调，让 agent 把”纠错模式”内化，从而在推理时不需要 AEWM。数据规模为 Search 4,000 条、Terminal 7,095 条、SWE 1,456 条（表 8），训练超参与 Self-RFT 完全一致（表 9），两者唯一差别是 rollout 来源。

关键设计为什么可能有效。 一是同时改写推理和动作：被改写的 reasoning 会随历史进入后续决策，只改动作或只改推理都不足以切断污染（§2.2、§4.5 消融）。二是直接替换续写，而不是给提示让 agent 重新生成：消融显示 EditAct 优于”给 hint 让 agent 自己重写”和”让 agent 重采样”，说明把修正后的状态直接落到历史里比”批评式反馈”更有效（表 3、§4.5）。

3. 解决得怎么样？

Action Judge 能力（§4.2、表 11、附录 B）。 作者自建了 3,000 条决策的跨域基准（Search/Terminal/SWE 各 1,000；标签构成为 900 Critical、735 Exploratory、1,365 Noisy，表 10），每条只给任务、工具说明、执行前历史和当前提议，隐藏观测、金标与理由。与 5 个前沿模型对比（温度为 1.0，单次判定，不许投票）结果如下：

模型 Search macro-F1 Terminal macro-F1 SWE macro-F1 Overall macro-F1
Gemini-3-Pro 39.2 52.0 42.8 45.1
GLM-5.2 49.5 54.0 54.5 53.2
Qwen3.7-Max 50.5 56.1 57.4 54.9
GPT-5.5 46.6 61.3 54.4 55.3
DeepSeek-V4-Pro（最强基线） 50.6 61.6 64.4 59.9
AEWM 60.9 72.1 77.8 70.5

原文图 3（官方 HTML 图，条形图按域分组）。Search、Terminal、SWE 三域的 macro-F1：AEWM（斜纹柱）在每一域都最高；数值与表 11 一致，可见 Search 域整体最难，SWE 域基线间差距最大。

AEWM 总体 macro-F1 **70.5%**，比最强基线 DeepSeek-V4-Pro 高 10.6 个点；三个域分别高出 10.3/10.5/13.4 个点。类级表现上 Noisy 最好（F1 81.1），Critical 68.1、Exploratory 62.3（表 12）——即”该拦住的决定拦得住”，而”有价值探索”和”关键步骤”的区分仍更难。

评测设置（§4.1、附录 C）。 三个域各有一个真实工具环境的 ReAct 脚手架，EditAct 就直接嵌在其中（基于 AweAgent 实现）：Search 用 search_api（You.com 检索）、link_summary_tool（按查询抽取网页证据）与 finish，BrowseComp/DeepSearchQA 均限 600 步、256K 上下文；Terminal 用 CalibForge-Eval 的 execute_bash、str_replace_editor、finish（每容器 32 核 / 48GiB，单任务限时 10,800 秒）；SWE 用 SearchSWE 的 execute_bash、str_replace_editor、finish（SWE-Bench Pro ≤500 步、Doc2Repo ≤400 步、NL2Repo ≤500 步，表 13）。基线为 ReAct 与两种 Best@3——逐步 Best@3（每步采样 3 个候选、由 verifier 选一个执行）与轨迹级 Best@3（同题跑 3 条轨迹、由 verifier 选最终提交），verifier 均为 DeepSeek-V4-Pro（附录 C.2）。AEWM 推理时温度 1.0，Action Judge 单次最多 8K token、State Revision 最多 32K。

EditAct 对 agent 的提升（§4.3、表 1）。 六个基准覆盖搜索（BrowseComp 用 accuracy、DeepSearchQA 用 F1）、终端（Terminal-Bench 2.0 任务准确率）与 SWE（SWE-Bench Pro resolved rate、Doc2Repo/NL2Repo 测试通过率）；每项跑 3 次取均值。三个 backbone 上 EditAct 均全面领先 ReAct 与两种 Best@3 选择基线：

Backbone ReAct 均值 Step-level Best@3 Trajectory-level Best@3 EditAct 比最强基线
Qwen3.5-4B 28.5 35.1 33.7 41.8 +6.7 点
Qwen3.5-9B 34.5 38.9 38.9 44.1 +5.2 点
Qwen3.5-35B-A3B 42.2 45.4 45.6 48.8 +3.2 点

（表 1 六基准平均值；单基准如 35B-A3B 上 Terminal-Bench 2.0 为 48.3 vs 最强基线 44.9，SWE-Bench Pro 43.8 vs 43.5 等）。值得注意的是 9B + EditAct（44.1）超过了 35B-A3B + ReAct（42.2），说明外接一个更会”审题”的世界模型可以部分抵掉 agent 本身的规模差。作者还试了更强的 Qwen3.5-Plus：BrowseComp 从 44.1 提升到 52.7，但 Terminal/SWE 提升有限，作者归因于 AEWM 与更强 agent 之间的容量差（§4.3）。

AEWM-RFT：把纠错能力内化（§4.4、表 2）。 在 Qwen3.5-35B-A3B 上，两种 RFT 用同数据量、同过滤、同超参，只差 rollout 来源；评测时都用纯 ReAct，不带 AEWM：

方法 BrowseComp Terminal-Bench 2.0 Doc2Repo 平均轮数（BC/TB2）
Base agent 40.9 37.1 42.8 56.2 / 83.1
Self-RFT 43.2 40.8 46.1 44.0 / 73.6
AEWM-RFT 45.4 43.4 48.6 39.3 / 69.2

即相对 Self-RFT 再涨 2.2/2.6/2.5 个点；前两个 benchmark 上平均轮数还下降约 30% 和 16.7%，Doc2Repo 则以更多轮数（78.1→89.8）换来 +2.5。这说明被 AEWM 纠正过的轨迹本身就是可迁移的监督信号。

消融是否支持作者的解释（§4.5、表 3）。 在固定 35B-A3B 上：随机门控（Random Gate，按 AEWM 在线的 Noisy 率随机触发改写）在三个基准上都不如学习到的 Action Judge（如 BrowseComp 44.1 vs 48.1）；”让 agent 自己重采样”、”把 AEWM 的推理当 hint 交给 agent 重新生成” 也都不如直接替换状态；只改动作（Action-only）或只改推理（Reasoning-only）都不如联合改写；用 agent 自己当世界模型（Self-WM）在 BrowseComp/Terminal 上退化（39.3/30.7），换成 DeepSeek-V4-Pro 当世界模型仍全线低于 AEWM（47.4/45.7/46.3 vs 48.1/48.3/48.9）。训练消融中，mid-training + SFT 的完整配方优于只用 SFT（+0.8/+6.4/+4.3）和只用 mid-training（+0.3/+4.1/+1.9）。这些结果支持”要让 learned judge、联合编辑和专门训练的世界模型三者都在”的说法，但消融是按整体替换做的，无法分离各设计元素之间可能的交互。

原文图 4（§5.1，官方 HTML 图）。三个域在离线标注（Annotated）与在线 AEWM 指导（Online）下的 Critical / Exploratory / Noisy 占比：Search 以 Noisy 为主（在线 64.8%），Terminal 以 Exploratory 为主，SWE 三类较均衡；在线分布与标注分布同构，说明 AEWM 在推理时复用了训练中学到的域间决策差异。

行为层面的变化（§5.2、图 5、图 4）。 搜索域中，最长”纯搜索”连续段从 16.9 降到 13.2，访问到的不同网页数从 7.7 升到 10.1——与”打开更多来源验证假设”的解释一致；在线 Action Judge 的动作分布与离线标注分布基本一致（图 4），作者据此说明 AEWM 学到的域间差异在在线指导时被复用。

代价与边界。 论文没有报告整条流水线的美元成本或 GPU 小时；但代价结构是清楚的：造数据要调用多个前沿模型（标注、提议、改写、复核），mid-training 要 52B tokens，推理时每步多一次 Action Judge 调用（≤8K tokens）、触发改写时再生成一次（≤32K tokens），且 RFT 需要大量 EditAct rollout（附录 A.4）。此外：Action Judge 基准由作者自建、标注来自模型（DeepSeek-V4-Pro 三取一致 + GPT-5.6-Sol 复核，附录 B），70.5% 是”自家基准上的自家定制模型”成绩；评测虽跑 3 次但只报均值、未给方差；in-distribution 基准（BrowseComp、Terminal-Bench、Doc2Repo、NL2Repo）与训练分布重叠，只有 DeepSearchQA 与 SWE-Bench Pro 是 OOD；论文也未测量失败模式中”被误判为 Noisy 而被改坏”的比例。

作者发现观测预测型世界模型对任务型 Agent 价值有限、且 agent 自身会被 task-state contamination 污染，因此提出 AEWM：用 Action Judge 判断决策效应、用 State Revision 从同一历史改写被污染的推理–动作续写，并以 EditAct 在真实环境中执行；实验表明其动作判断 macro-F1（70.5%）超最强前沿基线 10.6 点，三个 backbone、六个基准上平均提升 3.2–6.7 点，AEWM-RFT 还能把纠错能力内化进 agent（比 Self-RFT 高 2.2–2.6 点）；但仍存在标注与训练成本未量化、基准自建且部分与训练同分布、误改率未评估等边界。
