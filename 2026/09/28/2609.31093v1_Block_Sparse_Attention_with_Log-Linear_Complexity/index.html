1. 作者发现了什么问题？

研究背景与任务

长上下文语言模型的瓶颈仍然是自注意力的二次开销。块稀疏注意力（block sparse attention, BSA）是主流解法之一：把 key 序列切成大小为 CCC 的连续块，每个 query 只挑 KKK 个块来算注意力。它天然分成两个阶段（第 1 节、第 3.1 节）：

  1. Top-KKK 块选择：给每个 query 打分挑块；
  2. 在选中块上做注意力：因为每个 query 最多读 KCKCKC 个 key，这一步随序列长度线性增长。

论文用 Eq. (1)–(6) 把标准 BSA 形式化了。设块大小 CCC，候选块数 M=⌈N/C⌉M = \lceil N/C \rceilM=⌈N/C⌉，第 iii 个块的摘要向量由块映射 fff 得到：

kˉi=f(Ki)∈Rd,st,i=qt⊤kˉid,It=TopKK(st),\bar{k}_i = f(K_i) \in \mathbb{R}^d, \qquad s_{t,i} = \frac{q_t^\top \bar{k}_i}{\sqrt{d}}, \qquad I_t = \mathrm{TopK}_K(s_t),kˉi​=f(Ki​)∈Rd,st,i​=d​qt⊤​kˉi​​,It​=TopKK​(st​),

然后只在 ItI_tIt​ 覆盖的原始 key/value 上算注意力（Eq. (6)）。

被忽略的瓶颈：选择阶段本身还是二次的

作者指出的问题是：第二阶段确实是线性的，但第一阶段不是。传统 Top-KKK 选择要求每个 query 和所有 N/CN/CN/C 个块摘要各算一次点积，整个序列累计复杂度为

O ⁣(N2C),O\!\left(\frac{N^2}{C}\right),O(CN2​),

也就是说，”稀疏”只省掉了注意力计算，没有省掉为做稀疏决策而要做的全量扫描（第 1 节、第 3.1 节结尾）。序列越长，这个扫描反而越像一个新的全注意力。

论文用 Table 1 把这一点坐实了：MoBA、NSA、HiLS、BSA 四个可训练方法的 prefill 复杂度都标注为 O(N2)O(N^2)O(N2)，decode 为 O(N)O(N)O(N)；只有训练无关的 HiP（多层重复选择，固定预算下 log-linear）和面向扩散模型的 LLSA 达到 O(Nlog⁡N)O(N\log N)O(NlogN)。这张表既是对现状的总结，也直接框定了本文的位置——训练友好的 LLM 稀疏注意力里，缺一个 O(Nlog⁡N)O(N\log N)O(NlogN) 的选择阶段。

核心判断

作者的核心判断是：要摆脱 O(N2/C)O(N^2/C)O(N2/C)，就不能让任何一步”对所有候选块打分”，必须让打分过程本身变成层次化的——每一层只对上一层的幸存者打分。这里有个容易被忽略的数学前提：一个块内所有 key 都要被读到，才能算出这个块的精确相关性分数；但只要允许近似，就可以用块摘要的聚合值代替。论文把这个近似做成了严格的层次结构，并用 LogSumExp 把”块内取 max 倾向”保留下来（见第 2 节与附录 A）。

另外，同期已有工作 HiP [19]（训练无关）和 LLSA [42]（扩散模型）做过层次化 Top-KKK，因此本文要补的不是”层次化选择”这个概念本身，而是：一个能从头训练、带原则性打分函数（LSE）并与 LLM 的 GQA、KV cache、Triton kernel 对齐的版本。

2. 作者如何解决？

核心思路

PISA（Pyramid Sparse Attention）的做法是：先把 key 用 mean pooling 逐级合并成一座”金字塔”，共 O(log⁡N)O(\log N)O(logN) 层；然后从最粗的一层开始做 Top-KKK，每层只对上一轮幸存块的子块打分，逐级向下展开，直到叶子块。

它和前面那个问题的对应关系很直接：O(N2/C)O(N^2/C)O(N2/C) 的根源是每个 query 要摸 N/CN/CN/C 个叶子块，而金字塔把”看得远”和”看得细”拆开了——粗层负责筛掉大片无关区域（候选数指数级下降），细层才用真正的 key 算分。每层候选数被固定预算卡死，所以每个 query 的总打分次数只和层数有关，即 O(log⁡N)O(\log N)O(logN)。

原文图 1（Figure 1，第 4 页）。该图说明：上半部分 BSA 对所有块都算一遍 mean score 再 Top-KKK；下半部分 PISA 先自下而上做 mean pooling 建金字塔（l=0l=0l=0 是原始 key，l=1l=1l=1 是叶块），再自上而下只对”被选中的候选”算 LSE 分数（中间层用 LSE over child-block，叶层用 LSE over original keys），灰色部分是完全跳过的计算。

关键机制一：为什么用 LogSumExp 打分

这是全文最值得看的数学设计（第 3.2 节 Eq. (21)、附录 A）。

在叶层，LSE 分数是精确的。因为 kˉr(0)=kr\bar{k}_r^{(0)} = k_rkˉr(0)​=kr​，所以叶层打分退化为对块内原始 key 的 LSE。而附录 A 开头指出：对某个查询头而言，一个（完全可见的）块占全注意力的比重正比于其原始 key LSE 分数的指数，两者的块排序完全相同。也就是说，如果每一层都能精确算，PISA 的块排序与全注意力一致。

在中间层，LSE 是比”取均值”更紧的近似。中间的块不可能把内部全部 key 读一遍（否则又回到二次复杂度），只能用子块摘要。作者比较了两种聚合方式，并在附录 A.1 用 Jensen 不等式证明了一个夹逼关系（规范化去掉输入个数项后，Eq. (39)）：

1g∑j=1gmj  ≤  F~(B):=log⁡ ⁣(1g∑j=1gemj)  ≤  Fq(B),\frac{1}{g}\sum_{j=1}^{g} m_j \;\le\; \tilde F(B) := \log\!\left(\frac{1}{g}\sum_{j=1}^{g} e^{m_j}\right) \;\le\; F_q(B),g1​j=1∑g​mj​≤F~(B):=log(g1​j=1∑g​emj​)≤Fq​(B),

左边是 PISA-1 用的”子块均值 logit 的平均”，中间是 PISA 的 LSE 分数（减 log⁡g\log glogg），右边是该父块的规范化原始 key LSE。证明路径是两处凸性：先对 ggg 个子块均值 logit 用 Jensen（Eq. (40)）得到左不等式，再在每个子块内部对原始 logit 用一次 Jensen（Eq. (41)–(42)）得到右不等式。结论是：在同一个块上，子块摘要的 LSE 至少和均值一样接近真实的父块 LSE；当每个子块内部 logit 完全相同时两者相等。

直觉版本（教学简化）：设某父块只有两个子块，子块平均 logit 分别是 m1=2m_1 = 2m1​=2、m2=−2m_2 = -2m2​=−2。均值打分给出 000，把”有一个非常相关的子块”这件事完全抹平；LSE 给出 log⁡(e2+e−2)≈2.02\log(e^{2}+e^{-2}) \approx 2.02log(e2+e−2)≈2.02，几乎等于最大值。也就是说，LSE 保留了”块内取最大”的倾向——只要块里有一小段高度相关，这个块就还有救，不会被大量无关内容稀释掉。这正符合注意力质量的分布特征（少数位置吃掉大部分权重），也解释了后面 Table 7 中 PISA 的 Recall@8 明显高于均值版本 PISA-1。

关键机制三：因果性与强制块（附录 B）

  • 候选块若越出序列范围、或起始位置在 query 之后，一律排除；
  • 沿用 NSA 在 flash-linear-attention [35] 中的策略，强制保留第一个、前一个、当前叶块及其祖先路径；
  • 细节值得注意：当前块路径上的摘要可能包含 query 之后的 key，这些节点只被保留、不参与打分排序；除它们以外的候选都完整落在过去，因此未来 key 无法影响选择；块内部未来 token 的遮挡由注意力 kernel 单独处理；
  • 反向传播时选中的块索引固定：梯度只流过被选中条目上的注意力计算，不流过离散的块选择决策。所以 PISA 的可训练性来自”用稀疏模式训练整个模型”，而不是”让选择器可微”。

关键机制四：kernel 实现（第 3.3 节、Algorithm 1）

  • GQA 共享：同一 KV head 组的 query head 共享选中块集合。打分先按 query head 算 LSE，再在组内求和作为共享分数（Eq. (22)）：uh,t,i(ℓ)=∑h′∈H(h)sh′,t,i(ℓ)u_{h,t,i}^{(\ell)} = \sum_{h' \in H(h)} s_{h',t,i}^{(\ell)}uh,t,i(ℓ)​=∑h′∈H(h)​sh′,t,i(ℓ)​。
  • 训练/prefill 用两阶段 kernel。第一阶段把从 LLL 到 222 的中间层选择全融合进一个 program，query 向量只加载一次，中间候选在寄存器/片上直接展开，不落盘、不物化 N×MN\times MN×M 的打分矩阵；第二阶段才给叶子块打真实分——按”需要给同一个候选块打分的 query”聚成 cluster，再切成最多 Qtile=4Q_{\text{tile}} = 4Qtile​=4 个 query 的小块并行，每个 key 块只加载一次、被多个 query 复用（Eq. (23)–(24)）。
  • 为什么训练用两阶段、decode 用单阶段（第 3.4 节末尾，Eq. (25)–(31)）：两阶段的叶层 Q/K IO 约为 O(NgKd (GQ+C/Qtile))O\big(NgKd\,(G_Q + C/Q_{\text{tile}})\big)O(NgKd(GQ​+C/Qtile​))，单阶段为 O(NgKCd)O(NgKCd)O(NgKCd)。按实现取值 GQ=16G_Q = 16GQ​=16、Qtile=4Q_{\text{tile}} = 4Qtile​=4、C=64C = 64C=64，有 16+64/4=32<6416 + 64/4 = 32 < 6416+64/4=32<64，两阶段更省 IO。而 decode 时每个 cluster 只有一个 query，没有跨 query 的 key 复用，两阶段反而要重复读 query；单阶段 kernel 直接复用中间层已经加载的 query，额外叶层 IO 只有 O(gKCd)O(gKCd)O(gKCd)，还省掉多次 kernel launch。因此 training/prefill 用两阶段、decode 用单阶段。
  • decode 缓存：缓存整座金字塔，每来一个新 token 只更新当前叶块的均值及其祖先路径。金字塔共 O((N/C)d)O((N/C)d)O((N/C)d) 个元素/KV head，各级容量按固定比例增长，所以序列长度翻倍时每级的扩容只有常数次；即使每次扩容都整体拷贝，兜底拷贝总量为 O((N/C)dlog⁡N)O((N/C)d\log N)O((N/C)dlogN)，摊销后不破坏 O(log⁡N)O(\log N)O(logN) 的每步解码成本（附录 B）。

复杂度结论（第 3.4 节）

金字塔层数 L=O(log⁡N)L = O(\log N)L=O(logN)；每层每个 query 至多给 gKgKgK 个候选打分，每个中间候选至多用到 ggg 个子摘要、每个叶候选至多用到 CCC 个原始 key。在 g,K,Cg, K, Cg,K,C、头数与头维度固定的前提下，单 query 选择复杂度 O(log⁡N)O(\log N)O(logN)，全序列 prefill 选择复杂度 O(Nlog⁡N)O(N\log N)O(NlogN)，decode 每步摊销 O(log⁡N)O(\log N)O(logN)。注意这个 O(Nlog⁡N)O(N\log N)O(NlogN) 指的是选择阶段；其上的稀疏注意力本身是 O(NKC)O(NKC)O(NKC)，在 K,CK, CK,C 固定时同样是线性项。

3. 解决得怎么样？

实验设置

三个规模：418M、1.47B、2.67B，同规模下 decoder backbone 与注意力投影完全对齐；基线为 Full Attention、BSA、NSA [36]、HiLS [14]。其中 BSA 就是 NSA 的 selected-attention 分支换成 mean-pooled 摘要（无压缩分支、无学习路由），所以 PISA vs BSA 基本隔离出了”选择机制”这一个变量。流程为 100B tokens @ 4K 预训练，再做 10B tokens @ 16K 继续预训练（CPT）；稀疏方法全程 C=64C=64C=64，预训练 K=8K=8K=8、CPT K=32K=32K=32。评测用 LM Eval Harness 的困惑度与 8 项选择题、6 项 containment 检索任务，以及 RULER 的四个 needle-in-a-haystack 家族（附录 C）。

语言建模与下游（Table 2）

  • 训练损失：2.67B 下 PISA 2.2151，低于 BSA 2.2184、PISA-1 2.2179、PISA-2 2.2152（1.47B 与 418M 同样成立）。但要注意，Table 2 里 HiLS（2.2047）和 NSA（2.2098）的损失更低，Full Attention 为 2.2209——PISA 的”最低损失”只在 BSA/PISA 变体这一族内成立。
  • 选择题平均：2.67B 下 PISA 58.10 vs BSA 58.61，BSA 略高；418M（50.52 vs 49.63）和 1.47B（55.96 vs 55.58）PISA 略高。总体是”持平”。
  • containment 平均（6 项）：PISA 在三个规模上都是稀疏方法里最高的——418M 41.77（BSA 38.18、HiLS 40.79、NSA 37.46）、1.47B 49.83（BSA 48.54）、2.67B 52.14（BSA 51.13、HiLS 51.62）。但 Full Attention 仍然更高（45.15 / 52.13 / 53.01）。

长上下文检索（Table 3）

2.67B 模型 CPT 后在 RULER 四个 NIAH 家族、1K–16K 五个长度上的平均：PISA 62.80，显著高于 BSA 54.99 与 NSA 61.07，接近 Full Attention 的 66.24。差距在 multikey/multiquery 上最明显（BSA 在 16K multiquery 只有 15.10，PISA 20.85；multikey 16K 7.13 vs 10.00），而在 single-key 上 BSA 早期反而更强（4K 93.60 vs 96.33 附近互有胜负）。

一个值得指出的细节：PISA-2（62.92）在这一项上略高于完整 LSE 的 PISA（62.80），而这与 Table 2 / Table 7 里 PISA 全面领先 PISA-2 的结论方向不一致。论文没有解释这个反转（分析者推断：RULER 是长上下文检索，二阶方差项可能对含噪的粗层摘要更稳健；但这只是推测，原文未给出因果解释）。

消融与分析：机制是否被证据支持？

打分函数消融：在完全相同的金字塔与注意力代码下，第 4.4 节报告 PISA 在三个规模上的训练损失都低于 PISA-1、PISA-2、BSA，containment 平均也最高。这与附录 A.1 的夹逼分析方向一致。

块选择质量诊断（Table 7、Figure 2）：这是一个很有说服力的设计——拿一个 418M Full Attention 检查点（100B tokens @ 4K）的同一批 query/key 张量回放所有选择器，用全注意力质量构造参考集，比较 Recall@8、captured mass 与 attention mass ratio（定义见 Eq. (35)–(36)、Eq. (55)–(57)；参考集与选择器共享预算、可用块范围和强制块策略，所以 Recall@8 里天然含 3 个块的保底重叠）：

选择器 Recall@8 Captured mass Attention mass ratio
PISA 90.95 86.47 99.46
PISA-2 88.24 86.13 99.02
BSA 85.91 85.67 98.42
PISA-1 84.75 85.50 98.22

原文图 2（Figure 2，第 10 页）。该图说明：在 100 条 FDA prompt、共享 Full-Attention 的 query/key 条件下，按 query 位置统计的 Recall@8 与 attention mass ratio 曲线；PISA（橙色实线）在两个子图中都位于最上方，且领先幅度随 query 位置后移（可用历史变长）而扩大。

这份诊断是”机制被解释”的主要证据：它把模型质量之外的、纯粹的选择精度单独测了出来，并且用的是同一批张量，排除了训练差异的干扰。但要注意两点边界：(1) 论文附录 A.1 自己明确写了，夹逼关系”只关涉块分数的数值误差，不保证更好的块排序，也不保证找回全局最高质量的叶块“——逐层贪心的粗到细搜索理论上可能错过最优叶子；(2) 诊断只在 418M 模型 + 100 条 FDA prompt 上做，规模有限。

一处值得注意的例外：Table 7 里 PISA-1 的 Recall@8（84.75）反而低于 BSA（85.91），而 PISA-1 与 PISA 的区别只是把 LSE 换成均值。附录 C.1 顺带提到 BSA 在组内会对候选分数先做归一化再跨 head 求和，而 PISA 系列直接求和（附录 A.3 也强调：跨 head 聚合规则不同，即使 LSE 精确，排序也可能不同）。这两者是否构成因果关系，原文并未论证，属分析者推断。

代价与仍未解决的问题

  • 没有额外参数：摘要用无参数的 mean pooling，选择不可微且索引固定。代价主要是工程性的（需要专门的 Triton kernel，训练/prefill 与 decode 两套实现），而不是训练成本或标注成本。
  • CPT 后检索优势反转：附录 D.1 的 Table 6（16K CPT 后，containment 只统计 SWDE/SQuAD/FDA 三项）显示 PISA 65.33 vs BSA 66.55（1.47B）、66.40 vs 68.15（2.67B）——PISA 的平均 containment 在两个规模上都低于 BSA，作者在附录里如实写了这一点。相比之下 PISA 的训练损失仍略低于 BSA 与 PISA-1。也就是说，4K 预训练阶段的检索优势在长上下文 CPT 之后没有保持住。
  • RULER 上 PISA-2 略优于 PISA（62.92 vs 62.80），与其余实验方向不一致，原文未解释。
  • 粗到细是贪心的：附录 A.1 明确声明夹逼界不能保证全局最优叶块，论文也没有给出”最优叶块召回率”这类上界诊断。
  • Full Attention 仍是上限：containment 平均、RULER 平均都还没追平全注意力。
  • 规模与预算受限：附录 E 只说了”算力限制了模型规模与预训练数据量，这两者都会显著影响性能与相对收益”，因此结论的适用范围是 ≤2.67B 参数、100B+10B tokens 的设定。
  • 缺少端到端成本数据：论文只测了”块选择”这一段的延迟（显式排除注意力计算），没有报告训练吞吐、显存占用或端到端推理加速；延迟基准用的是随机 Q/K 而不是真实激活，也没有与同为 O(Nlog⁡N)O(N\log N)O(NlogN) 的训练无关方法 HiP 做对比。

收束：作者发现块稀疏注意力真正被卡住的地方不是注意力计算、而是那个仍为 O(N2/C)O(N^2/C)O(N2/C) 的 Top-KKK 块选择扫描，因此提出 PISA——用 mean pooling 建 O(log⁡N)O(\log N)O(logN) 层 key 金字塔，从粗到细逐层用 LogSumExp 给有界候选集打分并展开，把选择复杂度降到 O(Nlog⁡N)O(N\log N)O(NlogN)，并配了训练/prefill 两阶段与 decode 单阶段的 Triton kernel；实验表明它在 418M–2.67B 三个规模上与稀疏基线语言建模持平、containment 与 RULER 检索更好，256K 序列上的路由延迟比 BSA 低近一个数量级；但短序列（≤16K）仍不如 BSA，16K 继续预训练后 containment 平均反而落后于 BSA，粗到细搜索的全局最优性没有保证，且验证规模与预算都还受限。
