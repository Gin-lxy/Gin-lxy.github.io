0. 一句话结论

论文要解决的问题是”LLM 能力评测本身不可靠”，核心思路是把评测从固定考卷改成统一协议下持续运行的多游戏竞技平台（Kaggle Game Arena），并用大规模全循环对局、方差削减与博弈论评分保证名次可解释；作者据此给出了 Chess、Poker、Werewolf 三个环境下 10 个前沿模型的完整排名。

在论文自己报告的范围（2026 年 2 月的 10 个模型 API 快照、默认采样参数、无工具无检索、三个游戏）内，”游戏内分层显著、跨游戏排序不一致”这一结论有大样本与置信区间支撑；但”平台可持续扩展、可做纵向比较”属于设计主张，论文给出的是框架与一次性运行，缺少跨运行、跨模型版本的验证，Werewolf 一项还只覆盖了 10 个模型中的 8 个。

1. 论文具体想解决什么问题？

研究背景与具体任务。 LLM 能力评测正在成为瓶颈。静态基准（MMLU、GSM8K、HellaSwag）在前沿模型上接近饱和，区分度下降，且固定测试集容易被训练语料污染导致高估（§1，引 White et al., 2024；Kapoor et al., 2024）。社区转向动态的偏好型评测——Chatbot Arena 的众包成对投票、MT-bench 的 LLM-as-a-judge——但作者认为这类方法引入了新的问题：人类评委与模型评委本质主观、标准不一致，且存在偏爱冗长输出（verbosity）与谄媚（sycophancy）等偏置，产出的评测数据噪声很大（§1）。

作者的主张与替代方案。 作者主张评测应当锚定 ground-truth 结果，而游戏同时化解”饱和”与”主观”两个问题：每局都要求玩家根据对手的决策做策略调整，模型变强时对局面貌随之演化，天然不易饱和；胜负、平局、筹码是客观可测的，不需要评委（§1）。这条脉络有长期历史支撑——从 Deep Blue、AlphaGo/AlphaZero、Cicero 到 AlphaStar、Libratus、Pluribus（§1）；把游戏用于 LLM 评测也有 AgentBench、GTBench、PokerBench、SmartPlay、Game Reasoning Arena、PokerBattle 等先例，这些工作共同显示：强模型在完美信息确定性游戏中仍会挣扎，在不完全信息博弈中更差（§1）。

已有游戏评测具体差在哪（本文问题意识最具体的一层，属于领域一般问题 + 作者重新强调）。 作者指出：已有的游戏基准通常以固定数据集或孤立评测的形式发布，”不是为持续评测、弹性接入新游戏、跨异构环境的大规模 head-to-head 竞争而设计的”；多数缺乏统计严谨性，只报告几千次交互，在高方差游戏中远低于得出显著结论所需的样本量；因此难以支持跨模型世代的纵向进度测量（§1）。最接近的对照是 NeurIPS 2025 的 MindGames 竞赛（Wang et al., 2026）——虽是 live arena，但范围局限于四款 theory-of-mind 风格的卡牌游戏（§1）。

支撑问题判断的证据。 作者用可核对的数字量化了样本量差距：PokerBattle 每模型约 3,800 手牌、PokerBench 评测不足 2,000 手，而本文扑克单项跑了 900,000 手、每模型 180,000 手（§2.2）。此外，论文在 Werewolf 上给出了”样本量与排序唯一性”的直接证据：完整 31,472 局数据的锦标赛图完全无环，而把每份重采样缩小到 1,000 局时平均出现 2.048 个环（附录 A.6、附录 Figure 7）——这是全文对”样本不足会毁掉结论”这一前提最实在的证据，而不只是引用他人结论。

论文发现的新观察（区别于上述一般问题）。 第一，不同游戏调动不同能力：完美信息（棋）考规划与搜索，不完全信息（扑克）考信念更新与风险，多人自然语言（狼人杀）考欺骗与社会推断（正文 Table 1），因此单一游戏的结论不可外推。第二，作者在 §3 与 §4 报告了自己的实验发现：模型强度在同一游戏内分层明显，但跨游戏并不一致（例如 Gemini 3 Pro Preview 在棋与狼人杀居首，在扑克却是 −15.17 BB/100 的亏损者）。第三，作者报告了两条负面结果：扑克的翻前激进度与盈利不呈线性（附录 A.3.4），狼人杀的常用启发式指标几乎没有区分度（附录 A.8）。第二条观察正是”平台化”主张的实证依据，属于本文的新观察。

本文实际解决的子问题（范围边界）。 论文并没有、也没有声称解决”如何给出跨游戏的统一能力分数”——§4 明确把”consolidated meta-rating”列为未做的工作。它实际交付的是：一个可运行的多游戏评测平台、三个环境的具体协议与提示词、三个环境各自的主指标与排名，以及配套的统计方法。把问题定义在”平台 + 单环境排名”这一层，是这篇论文边界清晰的地方。

作者认为问题产生的原因。 作者把”评测不可靠”归因于两类机制：静态基准的固定性与可污染性（数据层面的原因），以及主观评委的标准漂移与系统性偏置（评判层面的原因）。这两条都有文献与论证支撑，属于作者主张，本文没有做实验去验证偏置的具体大小。至于”游戏为什么比问答更能测能力”，作者给的机制解释是”游戏要求根据对手决策做适应”（§1），这是概念性论证，论文未提供对照实验。

核心假设。 可以概括为两条：(H1) 在统一 harness、足够样本量和方差削减手段下，同一游戏内的模型排名可以做到统计可分且可复现；(H2) 不同游戏测的是不同的战略能力，因此排名跨游戏不一致，而一个不断扩充游戏的平台会持续提供新信息。H1 在本文条件下得到较强支持，H2 得到的是”排名确实不一致”的描述性支持，其因果解释（”因为能力是多面的”）仍是解释而非验证。

2. 创新点是什么？

一段话概括真正的技术增量。 本文的增量不是某个新算法，而是把”游戏评测”从一次性数据集升级成一个基础设施：一套所有游戏共用的文本 harness（状态+历史进、单动作出、非法动作有限重试且反馈最小化）、一个声明式 JSON + Python 解释器的环境规范（能让新游戏接入而不作废旧结果）、一套移植自计算机扑克锦标赛的方差削减流程（duplicate poker 手牌镜像、大样本全循环、bootstrap 区间），以及一个面向不对称多人博弈的角色分解评分（GTE）。其中”把 known-good 的工程与统计实践系统性地组装成一个可运行的公共评测平台，并在 3 个信息结构完全不同的游戏上跑满 10 模型全循环”是真实且不平凡的工作量；但单个组件（duplicate poker、bootstrap、GTE、Bradley–Terry）都不是本文首创。

2.1 统一文本 harness 与可扩展环境规范

  • 新增了什么：所有环境共用同一协议——输入是”当前状态的自然语言描述 + 完整历史”，输出是规定格式的单个动作；非法输出只允许少量重试，且反馈被刻意最小化（不说为什么非法、不给候选）。环境侧由两部分组成：声明式 JSON 规范（定义模型能观察什么、允许哪些动作、奖励怎么算）与实现规则的 Python 解释器（§2、附录 A.1、附录 B.1）。
  • 与最接近已有方法的不同：AgentBench、GTBench、SmartPlay 等评测的是”多个独立任务环境”，Game Arena 评测的是”同一环境下持续的对局与排名”；MindGames 是 live arena，但只覆盖 4 款 theory-of-mind 卡牌游戏（§1）。
  • 属于哪一类：以工程实现与系统集成为主，叠加一条明确的研究设计思想（”让独立推断动作合法性本身成为被测能力”）。棋与扑克的环境适配自 Gymnasium、PettingZoo、OpenSpiel 等既有框架（附录 A.1），属于使用现有组件。
  • 如何对应问题：直接回应”既有基准不是为持续评测与弹性接入新游戏设计的”。
  • 证据与移除实验：论文没有做”去掉最小反馈”或”换成给出合法动作列表”的对照实验。作者对提示词中立性的论证是设计层面的（附录 B：”把状态说全、把目标说清、其余保持最小与中立，让行为反映模型自身能力而非提示词工程的产物”），这是作者主张，无消融支持。

2.2 duplicate poker + 大样本 + bootstrap

  • 新增了什么：把每对模型的对抗切成相互独立的 100 手 episode；episode 内模型能看到此前所有手牌的完整文本历史，且每手结束后无论是否摊牌都公开双方底牌（加速对手建模）；同时采用 hand-mirroring：预先洗好 100 手的牌序，同一序列打两遍、交换座位与手牌。每对模型 20,000 手（10,000 个发牌 × 2），10 模型全循环 (102)=45\binom{10}{2}=45(210​)=45 对，合计 900,000 手（§2.2）。
  • 与最接近已有方法的不同：duplicate poker 是计算机扑克锦标赛的标准做法（Bard et al., 2013），但作者称其”从未被用于 LLM 扑克基准”（§2.2，作者主张）；相较 PokerBattle 每模型约 3,800 手、PokerBench 不足 2,000 手，本文规模高出一到两个数量级（§2.2）。
  • 属于哪一类：已有实践的新领域移植 + 规模上的量变。作者对”首次用于 LLM 扑克评测”这一断言未做完整文献比较。
  • 如何对应问题：直接回应”样本量远低于高方差游戏得出显著结论所需”。
  • 证据与移除实验：论文报告了结果（bootstrap 分布与配对胜率），但没有做”关掉 hand-mirroring 会怎样”的对照。方差削减的效果只有间接证据：Werewolf 上”1,000 局出现 2.048 个环、31,472 局为 0 个环”（附录 A.6）说明样本量确实决定排序唯一性，但这是狼人杀、不是扑克，也没有把 duplicate 与单纯加大样本量这两种降方差手段分开。

  • 属于哪一类：GTE 框架本身引自 Liu et al. (2025)，代码在 google-deepmind/polarix（附录 A.7）；本文的增量是应用它、把它接进多游戏平台，并补上角色分解与替换分析。因此不能算本文提出的新评分理论。
  • 如何对应问题：回应”传统评分不是为不对称多人博弈设计的”（§3.3）。
  • 证据与移除实验：论文给了三者对比（附录 Figure 6）：排序趋势一致，而 GTE 的置信区间更紧、更能区分顶部模型，Elo 与 OpenSkill 的顶部区间大量重叠。这是”换成 GTE 更好”的对比证据，但比较方式是看图，没有量化区分度指标（见 §5 质疑 5）。

2.4 用 self-play 消融做游戏平衡

  • 新增了什么：把狼人杀规则平衡性当作评测效度问题来处理：标准 8 人配置村民胜率高达 73.4%，因为”预言家立刻亮明身份 + 医生每晚连保”形成无懈可击的信息优势；作者用 self-play 消融（单个 Gemini 3 Pro Preview 同时控制 8 个匿名玩家、每配置 500 局）逐条测试规则修改，最终采用四条改动（医生不可自救、不可连续保护同一人、平局不淘汰、首发言者/首投票者轮换）把村民胜率压到 56.7%（附录 A.5、附录 Table 2）。
  • 与最接近已有方法的不同：多数游戏类 benchmark 直接沿用默认规则，不报告平衡性分析。这一条是本文相对同类工作最实在的”数据构造方法”创新。
  • 属于哪一类：实验方法论上的改进（用 self-play 作为平衡性的经验代理），机制来自作者自述。
  • 证据与移除实验：这是本文少有的真正隔离了变量的消融——附录 Table 2 给出四个配置各自的村民胜率（0.734 → 0.724 → 0.606 → 0.567）与 95% 区间，可以逐条读出每一步改动的影响。作者也诚实说明 baseline 会随 self-play 所用模型/策略波动，因此该方法提供的是”比较信号”而非绝对平衡度（附录 A.5）。

2.5 什么不算本文的创新

  • 使用更大的基础模型、更换数据集或评测指标：不适用，本文不训练模型。
  • 未解释作用的模块堆叠：无。
  • 提示词工程：作者明确把提示词设计成”最小且中立”，并且没有把提示词技巧当作贡献（附录 B），这一点是加分项而非创新点。
  • 需要保留的谨慎表述：根据本文的 related work 与实验对比，只能确认作者声称的差异（如”duplicate poker 首次用于 LLM 扑克基准”）；是否构成”首次提出”，还需要更完整的文献检索。同理，”评测应做成持续运行的平台”这一想法在 MindGames 等工作中已有雏形，本文的贡献是把覆盖范围与工程完成度推到一个可用的程度。

3. 作者如何解决？

直觉说明。 把评测做成比赛：所有模型通过同一接口面对同一套游戏，每个决策点只给”当前状态 + 完整历史”，只收”一个规定格式的动作”，非法就重试、重试仍失败就判负；所有胜负由规则引擎客观判定，名次由对局结果统计算出。这样做的理由是：状态与历史给全、目标说清之后，剩下的差异就只能来自模型自身的决策质量；而游戏会随模型变强而演化，不会像固定考题那样被刷爆。为了让”名次”可信，作者在统计层加了三件事——让对局规模足够大、用配对镜像与 bootstrap 压方差、对多人不对称博弈做角色分解。

按运行流程展开（对应正文 Figure 1）。

  1. 输入：每个决策点，模型收到自然语言描述的局面与历史（棋为 FEN + PGN 着法表，扑克为 PokerStars 风格手牌历史，狼人杀为时序事件日志 + 阶段任务 + 角色信息），以及一段说明目标与输出格式的系统提示。
  2. 关键步骤：模型自由生成文本（含推理），harness 从输出中解析出规定格式的单个动作（棋为 SAN 记谱、扑克为 fold/check/call/raise 与加注尺度、狼人杀为 JSON 的 action 字段）。
  3. 组件分工：提示构造器（Prompt Creator）→ LLM → 响应解析器（Response Parser），解析失败进入重试逻辑（retry logic）——Figure 1 上半部分把这四段画成一个 Harness 框。环境（ENVIRONMENT）负责规则执行、合法性校验与状态推进。
  4. 模型决定什么、固定流程控制什么：模型决定动作内容与推理轨迹；动作是否合法、状态如何推进、信息给谁看、重试几次、超限如何处理，全部由 harness 与环境固定控制。狼人杀的不对称信息由环境级的 append-only Event 日志 + 集中式 event bus 按可见性权限强制分发（§2.3），不是靠提示词约束——这是设计上比较扎实的一点。
  5. 是否需要训练：完全 training-free。不训练、不微调任何模型，不给工具调用与检索，全部机制发生在环境、协议与评测方法层（§2.5）。
  6. 推理阶段：通过各家公开 API 以默认采样参数与生成长度访问；狼人杀侧另有工程容错（pyjson5 宽松解析、端点失败指数退避、上下文溢出时迭代截断并保留最新 75%、违规语言过滤），解析重试超限则强制弃权（在狼人杀规则内始终合法）（§2.3）。
  7. 输出：每回合产生一份不可变的完整状态快照（含动作与解释），串成可序列化为 JSON 的轨迹，供回放、大规模分析、可视化与排行榜使用（附录 A.1）。

评测方法层（怎么把对局变成名次）。

  • Chess：用 Bradley–Terry 模型拟合全部成对结果得到 Elo 式评分（和棋记 0.5）。由于 Elo 只在相差一个常数下可识别，作者把最低分模型锚定为 0；报告 bootstrap 95% 置信区间，并用 Stockfish 多档难度对弈插值到 CCRL 参考 Elo 做近似外部校准（作者提示超出引擎校准范围时该校准不可靠）（§2.4）。

教学简化示例（用于理解”角色玩家”这个设计，非论文实验）。 设 A、B 两个模型要在狼人杀里比高低。若只比总胜率，两个模型都会被随机分到的角色结构拖累；若指定单一角色（例如只比预言家），结论又会高度依赖这一个角色的噪声。GTE 的做法是引入第三个”玩家”——评测仲裁者：它不参与打牌，只挑”当前哪一对（模型, 角色）组合最能暴露差距”；把它的收益设成两模型胜率差的绝对值 ∣uA∣|u_A|∣uA​∣，它就会去挑区分度最大的角色；再要求解是”最大熵相关均衡”，是为了不把全部质量压到单一组合上。读者可以把这理解为”让评测主动寻找最有区分度的考法，但又不让它只盯一道题”。

4. 解决得怎么样？

4.1 实验设置

  • 任务与环境：三个自建环境，覆盖不同的信息结构与交互复杂度（正文 Table 1）：Chess（完美信息、确定性、2 人、无通信，主指标 Elo）、Poker（不完全信息、随机、2 人、无通信，主指标 BB/100）、Werewolf（不完全信息 + 不对称、随机、8 人、自然语言通信，主指标博弈论评分）。
  • 评测对象：5 家实验室的 10 个模型（截至 2026 年 2 月）——GPT-5.2、GPT-5 mini、o3（OpenAI）；Claude Opus 4.5、Claude Sonnet 4.5、Claude Haiku 4.5（Anthropic）；Gemini 3 Pro Preview、Gemini 3 Flash Preview（Google）；Grok 4、Grok 4.1 Fast Reasoning（xAI）；DeepSeek V3.2（DeepSeek）。全部通过公开 API、默认采样参数与生成长度访问，不微调、不给工具、不做检索（§2.5）。
  • 对局规模与公平性：棋每对 40 局、黑白各 20 局中和先手优势（§2.1）；扑克每对 20,000 手并用 duplicate poker 镜像手牌（§2.2）；狼人杀共 31,472 局（正文 Figure 6 图注、附录 Table 3）。三个环境都跑完整全循环（round-robin），每对模型在相同条件下对局，日志细到每步/每手/每局（§2.4）。
  • 基线：本文不比较”方法 vs 基线”，而是比较”模型 vs 模型”。在评分方法层面，狼人杀一项把 GTE 与 group Elo、OpenSkill 对比（附录 Figure 6），排序层面还与 Copeland、Ranked Pairs、迭代最大彩票做交叉验证（附录 A.6、附录 Table 3）。
  • 主实验 / 消融 / 附录的分工：§3 主实验回答”谁强、强在哪”；附录 A.2（Chess Opening 变体、rethink 分析）、A.3（扑克翻前风格）、A.5（规则平衡）、A.6（替代排序与传递性、合作博弈）、A.8（启发式指标）回答”为什么”以及”哪些替代解释被排除”；附录 B 提供完整提示词模板以支持复现。

4.2 关键结果

Chess：三个梯队，差距在中后盘产生。 Chess Text 的 Game Arena Elo（附录 Table 1、正文 Figure 2）呈三层：Gemini 3 Pro Preview 1325（95% CI 1217–1428）与 Gemini 3 Flash Preview 1297（1205–1405）居首；o3 1009（928–1107）与 GPT-5.2 933（849–1018）第二梯队（两者的区间与第一梯队下界不重叠）；Grok 4 773、Grok 4.1 Fast Reasoning 632、GPT-5 mini 525 第三梯队；Claude 4.5 系列垫底（Opus 236、Sonnet 189、Haiku 122）；DeepSeek V3.2 作为锚点记 0。作者用 Stockfish 定位”差距何时产生”：把逐位置 centipawn loss 折算成胜率、按棋局进度归一后取平均，得到胜率轨迹（正文 Figure 3 左）——开局阶段各模型大体均衡，中局开始分叉，弱模型（如 DeepSeek V3.2 与 Claude 4.5 系列）系统性下滑，说明差距来自中后盘决策质量而非开局选择（§3.1）。

Poker：GPT-5.2 独占第一，头部与尾部差距很大。 按 BB/100 分三层（正文 Table 2、正文 Figure 5）：第一梯队 GPT-5.2 +46.56、o3 +29.69、Grok 4 +27.11；第二梯队 Claude Opus 4.5 +17.62、Claude Sonnet 4.5 +12.83、Gemini 3 Flash Preview +5.49；第三梯队为负——DeepSeek V3.2 −10.05、Gemini 3 Pro Preview −15.17、Grok 4.1 Fast Reasoning −19.19、GPT-5 mini −94.87。配对层面：GPT-5.2 是唯一对每个对手都保持胜绩的模型（胜率 57%–76%）；o3 九组配对中八组不败（只输给 GPT-5.2 的 42%，与 Sonnet 打成 50%）；Grok 4 打出全场最悬殊的一组成绩（对 GPT-5 mini 90%），但九组里只有三组胜多负少，说明其高 BB/100 来自顺手对局的大幅领先而非全面稳定（§3.2）。

正文 Figure 5（Poker evaluation）。左图为模型两两对局的胜率热图（行模型对列模型的胜率，蓝高红低，对角线留空）；右图为十个模型 BB/100 的 bootstrap 分布（红色虚线为盈亏平衡 0 BB/100，黑色虚线为四分位数），按均值自下而上排序。该图说明本文如何同时呈现”排序”与”不确定性”：右图中 GPT-5.2 与 GPT-5 mini 分别孤立于两端，而中游若干的分布明显交叠——即点估计的次序并不都可靠。这是全文”用分布而非单点数说话”的代表性图例。

Werewolf：角色分解评分，Gemini 居首，弱点各有不同。 31,472 局经 GTE 分解到四个角色（正文 Figure 6、附录 Table 1）。附录 Table 1 的 equilibrium rating 是相对尺度（0 为 break-even，不是绝对胜率）：Gemini 3 Pro Preview +0.10%（−0.01%, 0.21%）是唯一区间触及平衡线的模型，其余全为负——Gemini 3 Flash Preview −0.36%、GPT-5.2 −1.12%、Claude Opus 4.5 −1.31%、Claude Sonnet 4.5 −3.67%、Grok 4.1 Fast Reasoning −5.23%、Grok 4 −5.28%、GPT-5 mini −6.78%。中段暴露出具体弱点：Claude Sonnet 4.5 与 Grok 4.1 Fast Reasoning 在预言家角色上贡献为负，作者解释为”难以在不引起怀疑的情况下传递私有信息”；末位 GPT-5 mini 在所有角色上都是显著负贡献（§3.3，作者对弱点的角色解释属于作者主张，论文未给出对应的对话层面证据）。

Chess Opening 变体：排序稳健，但没有提升。 引入 20 个流行两回合开局后，排序、分层与时间动态与 Chess Text 基本一致（附录 Figure 1、附录 Table 1）；唯一变化是 Gemini 3 Flash Preview 以 1263 反超 Gemini 3 Pro Preview 的 1253，但两者区间高度重叠（1157–1381 对 1165–1371），不构成可靠差异。作者据此认为 Chess Text 的结论不依赖模型对少数熟悉开局的依赖（§3.1、附录 A.2.1）。

跨游戏：本文最重要的结论，也是最需要谨慎读的部分。 作者把每个环境的成绩与推断成本画在同一张图上（正文 Figure 4）。结论有两条：其一，成本—性能的有效前沿只有部分跨游戏共享——棋类（两种模式）与狼人杀的前沿形状相近，而扑克重排了前沿、也重排了”哪些模型性价比高”；狼人杀面板中前沿由三个模型锚定：Grok 4.1 Fast Reasoning（低成本端）、Gemini 3 Flash Preview（以极小成本增量换来明显性能跃升）、Gemini 3 Pro Preview（性能上限）（§3.3、§4）。其二，模型强度在同一游戏内分层显著，但跨游戏不一致：Gemini 3 Pro Preview 在棋与狼人杀均居首，在扑克却亏 −15.17 BB/100；GPT-5 mini 在扑克与狼人杀都垫底、棋类也只列第 7，但在扑克头对头中赢过两个 Gemini（55%、65%）；Grok 4 在棋类只排中游，在扑克却是一线盈利者（§4，正文 Figure 5 左）。分析者注：§3.3 在描述狼人杀的成本—性能时写作”Figure 4, Panel B”，但正文 Figure 4 的面板标注为 (A) Chess Text、(B) Chess Openings、(C) Poker、(D) Werewolf，按图应为 Panel D；HTML 与 PDF 两版都是这一写法。

  • 同梯队内次序不可靠：棋类 o3（928–1107）与 GPT-5.2（849–1018）区间大幅重叠。
  • 扑克中游无法排序：Claude Opus 4.5 与 Claude Sonnet 4.5 的分布尾部交叠，作者明确写”点估计一致但差异不那么确定”；底层三个模型（DeepSeek V3.2、Gemini 3 Pro Preview、Grok 4.1 Fast Reasoning）分布互相部分重叠（§3.2）。

  • 论文自报的负面结果：启发式指标（KSR 约 0.5、IRP 约 0.65、VSS 接近 1.0、Margin/Speed of Win）几乎没有区分度，作者认为作为主指标会误导，因为”活到最后”不等于”对团队最优”，战略性自我牺牲有时是正解（附录 A.8、附录 Figure 9）；基于结对联盟（coalition）的合作分析也”太接近、无法得出有信心的结论”——28 个联盟中 48% 的成对比较频次为零，且迭代最大彩票只能分出 6 组（附录 A.6.1）。

4.3 机制证据

论文做到了”不只是说有效”，但程度不均匀。

支持”为什么有效”的直接证据有三处，质量不同：

  1. 样本量 → 排序唯一性（最硬的一条）：完整 31,472 局数据里锦标赛图完全无环；把样本缩到 1,000 局则平均出现 2.048 个环（附录 A.6、附录 Figure 7）。这直接支持了”样本不足会产生自相矛盾的排序”这一前提，也是本文对”统计严谨性”主张最有说服力的证据。
  2. 规则修改 → 胜率变化（变量隔离得最干净的一条）：附录 Table 2 逐配置给出村民胜率 0.734 → 0.724 → 0.606 → 0.567，能读出每条规则改动的方向与量级（附录 A.5）。
  3. 时间定位 → 差距来源：Stockfish 胜率轨迹显示开局阶段均衡、中局分叉（正文 Figure 3）；rethink（非法着法重试）频率与对手强度强相关——最强的 Gemini 平均每局少于 0.2 次，GPT-5.2 稳定在每局 1 次以内，中档模型约 0.5–1.7 次，而 DeepSeek V3.2 与 Claude Haiku 4.5 经常超过 5 次、常常超过 10 次；重试集中出现在后半盘（高频重试的模型开局段只占约 10–20%），常见失败模式是”被将军但没有解将”（§3.1、附录 A.2.2）。这两条相互印证，支持”差距来自中后盘决策质量”。

只有一致性/相关性、没有因果证据的部分：

  • duplicate poker 的降方差作用没有被隔离验证：论文报告了区间与配对胜率，但没有任何”去掉 hand-mirroring 后区间会变多宽”的对照。
  • GTE 优于 Elo/OpenSkill 的证据是看图：附录 Figure 6 表明三者排序趋势一致而 GTE 区间更紧，但没有给出区分度的量化指标（如相邻模型区间重叠比例、排序一致性的统计量）。

附录 Figure 6（Ratings of group Elo, OpenSkill, and Game Theoretic Eval (GTE)）。三幅柱状图用同一批 31,472 局数据、1,000 次 bootstrap 分别给出 group Elo、OpenSkill 与 GTE 的评分与 95% 区间，横轴按同一顺序排列八个模型（GPT-5 mini 到 Gemini 3 Pro Preview）。该图是”为什么在不完全信息多人博弈上不用传统评分”的主要证据，作者在图注中即如此声称（GTE exhibits tighter confidence intervals and greater discriminative power）：Elo 面板中 Gemini 3 Pro Preview、Gemini 3 Flash Preview 与 GPT-5.2 的区间大幅重叠，OpenSkill 面板更甚（顶部几个模型的误差棒几乎连成一片），而 GTE 面板的区间明显收窄、GPT-5 mini 明显低于其余模型。读者需要注意，三者的纵轴单位不同（Elo 为评分、OpenSkill 为技能参数、GTE 为相对 Net Rating），因此只能比较区间的相对宽度与重叠程度，不能比较数值本身。

  • “扑克差距主要来自翻后决策”是排除法推断，不是测量结果：作者用翻前风格否证了”翻前范围决定胜负”（GPT-5.2 +46.6 与 GPT-5 mini −94.9 都开池很宽，结果相差超过 140 BB/100；Grok 4 与 Grok 4.1 Fast Reasoning 按钮开牌率 95.0% 与 83.8%，结果却是 +27.1 与 −19.2），并据此写”preflop range selection is a necessary but insufficient determinant…suggesting that postflop decision-making may account for much of the variance”（附录 A.3.4）。注意作者用的是 suggesting/may，而且论文没有计算任何翻后质量指标（没有 bet sizing 质量、没有翻后 EV loss、没有对摊牌决策的评估），因此”翻后才是主因”目前是排除了一个替代解释后的推断，不是被直接验证的机制。
  • 未排除的替代解释：输出 token 预算与推理长度（论文正文未报告任何模型的平均输出 token 数，Figure 4 的成本只是其代理）、上下文长度上限、以及不同 harness 容错策略对模型的不对称影响。作者没有做这方面的对照。

结论：本文的机制证据足以支持”评测规模与对局设计会显著影响结论的可靠性”（这在狼人杀样本量实验里被直接演示），但不足以支持”某个模型强是因为某种具体战略能力”（例如”Gemini 更会传递私有信息”），后者是作者的解释性主张。

4.4 成本与适用范围

方法付出的代价（论文实际报告的）：

  • 训练成本：无。方法在模型侧完全 training-free，不微调、不加工具、不做检索（§2.5）。
  • 对局规模本身即主要成本：扑克 900,000 手（每对 20,000 手 × 45 对，每模型 180,000 手）、狼人杀 31,472 局、棋类每对 40 局；按论文报告的全循环结构推算，棋类每个模式约 45 × 40 = 1,800 局（这是分析者按原文数字的算术推算，论文未直接报告棋类总局数，也未报告两个模式合计）。
  • 推断成本：只以 Figure 4 横轴形式给出（棋与扑克按每回合、狼人杀按每局，单位为美元）。分析者按该图坐标轴近似读取：棋类每回合大致落在 0.005–0.38 美元的区间（Grok 4 最贵），扑克每回合约 0.007–0.117 美元，狼人杀每局约 0.075–0.105 美元。论文没有报告总花费、总 token 数或端到端时延——§2.5 只说 “Per-turn token counts and inference costs are reported alongside gameplay results”，这些数据在论文正文中并未以表格出现。
  • 人工成本：扑克的系统提示词需要职业扑克选手参与设计（§2.2、附录 B.2）；狼人杀规则平衡需要 4 个配置 × 500 局 = 2,000 局 self-play（附录 A.5）；游戏规则与状态表示的工程实现（声明式 JSON + Python 解释器、可视化层 TS/React/Canvas）也是持续投入（附录 A.1）。
  • 外部依赖与系统复杂度：全部评测对象都是闭源 API；其中两个是 Preview 版本（Gemini 3 Pro Preview、Gemini 3 Flash Preview），随时可能下线或被替换；结果绑定在 2026 年 2 月的快照与各家默认采样参数上，而论文没有报告如何声明与固定这些版本。数据层要把每步快照序列化为 JSON 并托管到 Kaggle，存储与工程复杂度都不可忽略（附录 A.1）。
  • 数据完整性上的小口子：正文 Table 2 的 Hands 列显示 Claude Opus 4.5 与 DeepSeek V3.2 各 179,936 手，其余八个模型均为 180,000 手，论文未解释这 64 手的差异。

哪些问题得到改善、哪些仍未解决。

得到改善的：同一环境内的模型排名有了可复核的置信区间与诊断维度（时间定位、rethink 可靠性、翻前风格、角色分解）；”样本不足会得出自相矛盾的排序”这一风险被直接演示并对冲（duplicate poker、大样本、bootstrap）；游戏规则平衡性被当作效度问题来处理；完整轨迹与 harness 开源，使第三方可以复核或接入新游戏。

仍未解决（§4 自述）：固定局数配对的调度不做自适应，算力分配不高效（势均力敌的对局应多下、悬殊的对局应少下）；模型频繁更替会打断纵向比较与对局图的连通性，尚无冷启动与图维护协议；跨异构游戏的统一 meta-rating 尚未建立（尤其多人博弈的贡献归因难题）；游戏套件只有三个，诊断性总结也需扩展。分析者补充：跨游戏结论与成本—性能结论目前都是”读图得出的定性结论”，没有统计检验，也没有跨运行的稳定性证据。

结论适用范围。 论文的结论适用于：这 10 个模型、2026 年 2 月的 API 快照、各家默认采样参数、无工具无检索、在 Chess/Poker/Werewolf 三个特定规则配置下的表现。不适用于：其他模型、其他时间点的同一模型（Preview 版本尤其）、启用工具或改变提示词后的配置，以及”战略能力”的一般性论断——论文自己说明”战略能力是多面的”，正是拒绝给出单一分数。

5. 最容易受到审稿人质疑的地方

质疑 1：结论缺少运行间稳定性证据，而评测对象是随时间漂移的闭源 API

  • 原文依据：§2.5 声明全部模型”通过公开 API、使用各家默认采样参数与生成长度”访问，且评测时点为 2026 年 2 月；其中 Gemini 3 Pro Preview 与 Gemini 3 Flash Preview 是 Preview 版本。全部 95% 置信区间来自对同一批已完成对局的 bootstrap 重采样（§2.4、附录 A.7），论文未报告任何一次重复运行，也未报告采样参数的具体取值。
  • 为什么重要：它直接影响结论的可复现性与外部效度。bootstrap 区间刻画的是”若从同一数据生成过程再抽一批对局会怎样”，不包含”同一模型在不同时间/不同后端重跑会差多少”。对推理型模型而言，后者可能与前者的量级相当。若把”分层”理解为模型固有属性，这一跳跃缺少支撑。
  • 当前能够得出的判断：论文报告的是单次运行框架内的统计不确定性，且这一部分做得比同类工作扎实；但”排序在重复运行下仍然稳定”属于论文未报告、当前材料无法确认的内容。
  • 如何验证或补强：选 2–3 对名次相邻的模型（如 o3 vs GPT-5.2、Claude Opus 4.5 vs Claude Sonnet 4.5、Grok 4 vs Grok 4.1 Fast Reasoning）在不同日期各重跑一次相同规模的循环，报告运行间方差与两次排序的一致性；并在论文中明确记录每次调用的模型版本字符串、采样参数与快照日期。
  • 严重程度：主要问题。

质疑 2：Werewolf 主指标（GTE equilibrium rating）的尺度与归一化定义不完整，且同一指标有三种叫法

  • 原文依据：附录 A.7 给出了经验胜率、三方效用与最大熵相关均衡的求解思路，但没有把最终排名标量写成显式公式，只描述为”模型 A 面对从 CE 抽出的 (模型 B, 角色) 对时的平均表现”；正文 Figure 6 的图注称”0 indicates the break-even rating”，但 0 相对什么参照系为零，正文与附录都未说明。指标名称在文中出现三种：附录 Table 1 的列名是 “Werewolf (Equilibrium rating)”，正文 Figure 6 图注用 “Net Rating”，而 §4 又写成 “balanced win rate for Werewolf”。结果是八个模型中七个为负、只有一个微量正值（+0.10%）。
  • 为什么重要：这是 Werewolf 的唯一主指标，也是全文”分层”结论的载体。指标尺度不明确会造成两类误读：一是把负值误读为”输多赢少”（按作者用法，它是相对 break-even 的差值）；二是读者无法判断 −5.23% 与 −6.78% 之间的差距意味着多大的实力差。此外，附录 A.7 把效用定义成成对胜率差 uA=v(aA,arole)−v(aB,arole)u_A=v(a_A,a_{\text{role}})-v(a_B,a_{\text{role}})uA​=v(aA​,arole​)−v(aB​,arole​)（这是一个零和量），而汇总后的 Net Rating 却呈现”七负一正”；这是分析者判断——如果该标量沿用了同一乘积结构，那么这个分布提示零点参照系与模型池的平均值不重合，需要作者给出解释。
  • 当前能够得出的判断：排序的相对次序在多种方法下一致（附录 Table 3：Elo、Copeland、Ranked Pairs 与 GTE 排序完全相同），因此”Gemini 两模型领先、GPT-5 mini 垫底”这一粗粒度结论可信；但该数值的绝对尺度与零点的含义属于当前材料无法确认，需要读 polarix 代码才能复现。
  • 如何验证或补强：在附录 A.7 补上从 CE 到标量评分的完整公式，明确零点的参照系（是否为 CE 分布下模型池的期望值），并给出一个把该尺度换算为更有直觉的量（如”面对均衡对手时的期望净胜率差”）的说明；同时统一正文与附录中的指标名称。
  • 严重程度：主要问题。

质疑 3：Werewolf 只覆盖 10 个模型中的 8 个，两个模型缺失且论文未解释

  • 原文依据：§2.5 声明评测对象是 10 个模型；正文 Table 1 写明 Werewolf 的评测规模为”约 31,500 局”。但正文 Figure 6 图注、附录 Table 1 的 Werewolf 段、附录 Figure 7 的锦标赛图、附录 Table 3、附录 Figure 8 与附录 Figure 9 都只出现 8 个模型，且 §3.3 的讨论也只涉及这 8 个。缺失的两个是 Claude Haiku 4.5 与 DeepSeek V3.2（二者在 Chess 与 Poker 中均被评测）。全文没有任何一句解释原因（论文未报告）。
  • 为什么重要：它影响结论范围与评测公平性。Werewolf 是本文宣称”覆盖不对称多人博弈”的唯一环境，而它恰恰是覆盖模型最少的；如果缺失是因为成本、接口稳定性或权重重置等技术原因，读者需要知道，否则会把”8 个模型的分层”误当成”10 个模型的分层”。此外在与 Chess/Poker 做跨游戏对照时，样本集合不同本身就是一个混杂因素。
  • 当前能够得出的判断：论文未报告缺失原因；当前的 Werewolf 结论只能限定在文中列出的 8 个模型上，不能按 §2.5 的 10 模型口径理解。
  • 如何验证或补强：补跑这两个模型的 Werewolf 对局，或在正文与附录表格中显式说明排除原因（例如预算、超时率过高、版本稳定性），并把 Table 1 中的规模口径改为”每环境的实际参赛模型数”。
  • 严重程度：主要问题。

质疑 4：成本—性能结论只有定性读图，且论文承诺的成本数据未真正出现在正文

  • 原文依据：§2.5 写 “Per-turn token counts and inference costs are reported alongside gameplay results to support cost-performance analysis”，但正文与附录没有任何 token 数、总花费或时延的表格。§3.3 与 §4 关于”前沿形状跨游戏相似/扑克重排前沿”的结论，唯一的证据是正文 Figure 4 的四面板散点图；该图的横轴口径在环境间不一致（棋与扑克按每回合、狼人杀按每局），而扑克一手包含多个决策点，因此”每回合成本”在两个游戏间的语义并不等价。§3.3 还把这幅图的面板引用错写为 “Panel B”（应为 Panel D）。
  • 为什么重要：它影响结论的可验证性与可复核性。”成本—性能前沿只有部分跨游戏共享”是论文的两条主结论之一，但目前既没有统计检验（例如前沿差异是否超过重采样噪声），也没有给出原始成本数据；横轴口径差异使”相似”与”重排”的判断更接近视觉印象。另外，缺少总成本数据让读者无法评估”复制这套评测需要多少钱”，而这是平台型工作的关键采纳门槛。
  • 当前能够得出的判断：论文未报告总成本、token 与时延；跨游戏成本结论目前是分析者按图可复核但无统计支撑的定性判断。作者在 Figure 4 图注中已明确说明各面板的口径不同，态度是坦白的，但结论强度仍被高估。
  • 如何验证或补强：补充一张每模型每环境的表（平均输出 token、平均每回合/每局成本、总对局成本、p95 时延），给出总开销量级；对”前沿形状相似”给出可量化定义（例如各环境 Pareto 有效集合的 Jaccard 相似度）并做 bootstrap 检验；把横轴统一为”每决策点成本”或分别归一后说明可比性。
  • 严重程度：主要问题。

质疑 5：关键设计缺少隔离实验，部分”为什么有效”只有一致性与作者解释

  • 原文依据：(a) duplicate poker（手牌镜像）是全文降方差的核心设计，但论文只报告了使用后的结果，没有任何 on/off 对照（§2.2、§2.4）；(b) GTE 相对 group Elo / OpenSkill 的优势以”置信区间更紧、区分度更高”的看图描述呈现（附录 Figure 6），没有量化指标；(c) 规则平衡性的 self-play 消融由单个模型（Gemini 3 Pro Preview）控制全部 8 名玩家，作者自己承认”baseline 胜率会随 self-play 所用模型或策略 profile 波动”，只提供”比较信号”（附录 A.5）；(d) “扑克差异主要来自翻后”依赖排除法，论文未计算任何翻后质量指标（附录 A.3.4）；(e) 论文内部还有若干交叉引用错误：§3.1 的 “Figure Figure 4”、§3.3 的 “Figure 4, Panel B”、附录 A.2.1 的 “Appendix 3.1”（本文无此小节）、附录 A.2.2 把 Grok 4.1 Fast Reasoning 写成 “Grok 4.1 Rapid Reasoning Edition”，这些在 HTML 与 PDF 两版中均存在。
  • 为什么重要：前四项影响”机制解释是否成立”这一层——目前论文能证明”这样做可以得到可信的排序”，但还不足以证明”是因为这个设计”。第五项影响可复核性与读者信任：错误的面板/小节引用会让核查者浪费精力，而模型名称不一致在复现时可能被误当作另一个模型。
  • 当前能够得出的判断：作者对 self-play 平衡分析的局限是坦诚的（明确写了 baseline 会波动），这一点应记在作者一方；但 duplicate poker 与 GTE 的增益缺少隔离实验属于证据不足，而不是作者的结论错误。”翻后为主因”应读作有理由的假设而非已验证的机制。
  • 如何验证或补强：在扑克上做 duplicate on/off 的对照（比较 CI 宽度与排序稳定性）；对 GTE/Elo/OpenSkill 报告可量化的区分度指标与排序一致性；用 2–3 个不同模型分别做 self-play 平衡分析，检验规则结论对 profile 的敏感性；增加翻后的 EV-loss 类指标来直接检验”翻后是主因”；并做一轮交叉引用与模型名称的校对。
  • 严重程度：次要问题（作为对机制证据强度的质疑则是中等；论文的主要结论不依赖这些隔离实验，因此不到主要问题的程度）。

6. 审稿式总评

作者发现静态基准饱和且易被污染、主观评委噪声大，而既有游戏评测又是一次性数据集、样本不足、难以持续，因此提出把评测做成一个开放、持续运行、可扩展的多游戏竞技平台 Game Arena，通过统一文本 harness、声明式环境规范、duplicate poker 与 bootstrap 等方差削减手段，以及面向不对称多人博弈的 GTE 角色分解评分实现。实验在 2026 年 2 月的 10 个前沿模型、默认 API 参数、无工具无检索的条件下表明：模型强度在同一游戏内分层明显（Chess 的 Elo 呈三个梯队、Poker 的 GPT-5.2 与 GPT-5 mini 分别孤立于两端、Werewolf 的 Gemini 两模型领先而 GPT-5 mini 全角色负贡献），且跨游戏排序不一致——其中大样本、置信区间与狼人杀的角色分解证据较强，规则平衡消融与”样本量决定排序唯一性”的演示是全文最扎实的两块；但结论的跨运行稳定性、GTE 评分的尺度定义、Werewolf 只覆盖 8/10 个模型，以及成本—性能结论的定性性质，都仍缺少充分支持。本文最有价值的部分是把一套可复用的评测基础设施、提示词、统计流程与完整轨迹公开出来，并诚实报告了负面结果（启发式指标失效、联盟分析无法得出结论），对做 LLM/Agent 评测的读者是直接的工程与统计参考；最大的审稿风险是”平台可持续、可纵向比较”这一核心主张目前只有框架与单次运行支撑，且主指标的数学定义没有写到可独立复现的程度。

  • 问题定义清晰度：强。问题、替代方案与边界（三个游戏、10 个模型、单环境排名而非统一分数）陈述明确，§4 主动列出未解决的四个方向，不含糊。
  • 创新性证据：中。工程量与覆盖范围是真实的增量（三游戏全循环 + 完整轨迹开源），但 duplicate poker、bootstrap、Bradley–Terry 均为已有实践，GTE 引自 Liu et al. (2025)，”首次用于 LLM 扑克评测”等首创性断言未做完整文献比较。
  • 方法可信度：中。harness 设计（反馈最小化、环境级强制信息不对称）、配对设计与统计流程都合理且有据可查；扣分项是 Werewolf 主指标的尺度定义不完整、闭源 Preview 模型带来的不可回滚性，以及若干交叉引用错误。
  • 实验支持力度：中。游戏内的分层与配对结论有大样本与区间支撑，样本量对排序唯一性的影响被直接演示；但跨游戏与成本—性能结论是定性读图，无运行间方差，无显著性检验，机制解释部分依赖排除法。
  • 可复现性：中。harness、提示词模板、环境实现、评测脚本与完整轨迹数据均公开，GTE 代码也给出仓库名，这是加分项；扣分项是所有被测模型都是闭源 API 且未报告版本字符串与采样参数快照，评测时点固定为 2026 年 2 月，第三方难以原样重跑。
  • 综合阅读价值：高。对做评测的读者，本文提供了可直接借鉴的协议设计、提示词与统计流程，并且诚实报告了失效的指标；对只想”看哪个模型更强”的读者，价值有限且有时效性——这正是论文自己主张”竞技平台要持续运行”的含义。
